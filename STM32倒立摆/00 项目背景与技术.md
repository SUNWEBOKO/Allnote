# 00 项目背景与技术

## 学习目标

- 界定 HAL 复刻版与原课程的差别。
- 识别各硬件模块占用的引脚与外设。
- 区分生成代码、官方库与用户驱动。
- 建立从配置到编译下载的工程流程。

## 1. 这套文档是什么

本系列以**江科大 STM32 倒立摆教程（标准库版）**为基础，将外设驱动迁移到 STM32F1 HAL 库。原课程的控制原理与实验思路保留，工程改用 CubeMX 生成初始化代码，通过 VS Code 的 STM32 官方扩展完成 CMake 构建和 ST-LINK 下载。基础驱动的原版基准是课程资料中的 `01-基础驱动代码`（标准库版），本项目沿用其引脚、外设参数和公开 API，HAL 版只把初始化搬到 CubeMX。

本项目承接 [[STM32HAL库入门教程/README|STM32 HAL 库入门教程]]：入门课程分别学习外设，本系列将外设组合成反馈控制系统。驱动适配关系见 [[03 基础驱动：CubeMX与HAL库实现#1.5 与入门教程共用驱动]]。

目前四篇覆盖项目约定、PID 原理、离散算法与基础驱动，**尚不构成完整的倒立摆控制程序**。算法改进、串级控制与起摆控制不在这四篇的实现范围内。

## 2. 复刻的边界

| 方面 | 原版 | HAL 复刻版 |
| --- | --- | --- |
| 原理与实验 | 标准库课程及配套课件 | 保留教学主线，明确结论的适用条件 |
| 芯片与套件 | STM32F103C8T6 + PID 板 | 沿用同类硬件与接线 |
| 外设库 | STM32 标准外设库 | STM32F1 HAL |
| 初始化 | 手工配置外设 | CubeMX 生成，用户逻辑放用户区或自建文件 |
| 构建 | Keil 工程 | CMake + Ninja + Arm GNU 工具链 |
| 驱动接口 | `LED_ON()`、`Motor_SetPWM()` 等 | 尽量沿用函数名，内部改为 HAL 调用 |

迁移时要保持接口含义，而不只是替换函数名。例如 `Motor_SetPWM()` 接收带符号的占空比指令，`Encoder_Get()` 返回相邻两次读取间的计数增量；增量如何在驱动内部取得，不应影响上层算法。

## 3. 硬件

主控为 STM32F103C8T6 最小系统板，配合 PID 实验板及以下模块：

| 模块 | 型号或作用 | 引脚与外设 |
| --- | --- | --- |
| 板载 LED | 低电平点亮 | PC13，GPIO 输出 |
| 按键 K1～K4 | 上拉输入，按下接地 | PB10、PB11、PA11、PA12 |
| 电位器 RP1～RP4 | 模拟量输入 | PA2～PA5，ADC2_IN2～IN5 |
| 直流减速电机 | TB6612FNG 驱动 | PA0/TIM2_CH1 输出 PWM，PB12/PB13 控方向 |
| 霍尔编码器 | A/B 正交信号 | PA6/PA7，TIM3 编码器接口 |
| OLED | SSD1306 四针模块 | PB8/PB9，软件 I2C |
| 串口 | 调试与波形输出 | PA9/PA10，USART1 |
| 下载器 | ST-LINK，SWD 接口 | PA13/PA14，另接 GND 及所需目标参考线 |

定时器资源统一分配：TIM1 提供 1 ms 按键节拍，TIM2 输出 20 kHz PWM，TIM3 计编码器脉冲；第 02 篇另加 TIM4，产生 10 ms 控制周期。现有基础工程尚未启用 TIM4。完整配置见 [[03 基础驱动：CubeMX与HAL库实现#1.4 本工程的引脚与外设总表]]。

电机电源 VM 与逻辑电源不是同一路信号。本文套件按 12 V 电机供电、3.3 V 逻辑电平讲解，实际接线须核对板卡标识。**不得把 12 V 接入 MCU 引脚，也不要并联两路 3.3 V 电源输出。** ST-LINK 的供电输出与目标电压参考输入不能混为一谈，接法见第 03 篇。

## 4. 工具链与构建

| 环节 | 工具或文件 |
| --- | --- |
| 外设配置 | STM32CubeMX，保存配置并生成代码 |
| 编辑与调试 | VS Code + STM32 官方扩展 |
| 编译 | `arm-none-eabi-gcc` |
| 构建 | CMake + Ninja |
| 工具链文件 | `cmake/gcc-arm-none-eabi.cmake` |
| 构建预设 | `CMakePresets.json` 中的 `Debug` / `Release` |
| 下载 | ST-LINK |
| 源码编码 | UTF-8 |

本地参考工程当前为 `E:\ProjectStm\PIDproject\01 PID`（本章写作时的副本）。后续章节通常按序号在上一版工程副本上继续修改，不一定重新复制原始工程；引用路径以当时实际工程为准。其配置记录为 CubeMX 6.18.1、STM32Cube FW_F1 V1.8.7；工具链版本随本机扩展安装情况变化，不是复现实验的固定要求。扩展托管的工具通常位于 `%LOCALAPPDATA%\stm32cube\bundles`，以实际安装目录为准。

基本流程是：**修改配置 → 生成代码 → 登记用户源文件 → 选择构建预设 → 编译 → 下载**。修改引脚、时钟或外设模式后，应重新生成并编译；仅修改驱动里的句柄或宏，不会自动改变 CubeMX 配置。

## 5. 工程目录

```text
PID 工程/
├─ PID.ioc              CubeMX 配置
├─ Core/
│  ├─ Src/              生成的初始化代码与用户驱动
│  └─ Inc/              对应头文件
├─ Drivers/             ST 官方 HAL 库与 CMSIS
├─ cmake/               CubeMX 构建配置与工具链文件
├─ CMakeLists.txt       根构建脚本，登记用户 .c 文件
├─ CMakePresets.json    构建预设
└─ build/               构建产物
```

三类代码分开管理：

- **生成代码**：外设参数在 CubeMX 中修改。用户逻辑写进 `USER CODE BEGIN/END` 区，并启用生成时保留用户代码；区外手改可能被覆盖。
- **官方库**：`Drivers/` 保持原样，避免将应用逻辑混入 HAL。
- **用户驱动**：`.c` 放在 `Core/Src/`，声明放在 `Core/Inc/`，并将新增 `.c` 登记到根 `CMakeLists.txt`。

头文件让编译器知道函数声明，构建登记让对应实现参与编译链接，二者不能互相替代。具体模板见 [[03 基础驱动：CubeMX与HAL库实现#1.1 三份代码，三种归属]]。

## 6. 驱动组织约定

- **先配置，再启动**：`MX_xxx_Init()` 设置引脚与外设参数；用户 `XX_Init()` 负责启动、校准或建立初始状态，不重复配置整套外设。
- **名称表达接口含义**：`Motor_SetPWM()` 设置开环驱动量，不承诺实际转速；`Encoder_Get()` 返回增量，不是绝对位置。
- **方向统一**：电机正指令应对应编码器正增量。闭环前先小占空比核对，不能只凭函数名认定方向正确。
- **事件与连续量分开**：`Key_GetNum()` 读取并消费按键事件；编码器计数用于速度或位置计算。共享数据的读改写需要考虑中断竞争，`volatile` 本身不提供原子性。
- **每类 HAL 回调只定义一份**：定时器更新回调按 `htim->Instance` 区分 TIM1 与 TIM4；串口接收回调由串口驱动统一处理。
- **示例与实测区分**：课件波形用于分析规律，不代表本次 HAL 工程已复现。本文硬件预期现象均待实测。
