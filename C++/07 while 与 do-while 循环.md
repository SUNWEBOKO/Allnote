## 学习目标

完成本章后，你应当能够：

1. 说明什么情况下该用 `while` 而不是 `for`。
2. 写出 `while` 循环，并说出条件检查发生在哪一步。
3. 写出 `do-while` 循环，并说出它与 `while` 在迭代次数上的差别。
4. 对同一个任务判断该用 `while` 还是 `do-while`。
5. 识别死循环的成因并在写循环时提前避免。

## 1 迭代次数已知与未知

第 06 章的 `for` 循环适合处理一类明确的问题："把这 5 个元素遍历一遍"、"累加 1 到 100"。循环的**次数或范围事先就写在代码里**，看一眼条件就知道要转几圈。

但很多场景里你事先根本不知道要转几圈：

- 从某个外部来源取任务来处理，**队列里还剩多少项要等运行起来才知道**，处理到队列为空为止。
- 读用户输入，读一次判断一次，**用户什么时候选择退出无法预知**。
- 用迭代法求解一个方程，**不知道多少轮才能达到可接受的精度**，只知道"还不够精确就继续算"。

这些问题的共同点是：**只知道"满足什么条件就继续"，不知道"要重复多少次"。** `for` 也能硬写，但把次数写死反而掩盖了真实意图。C++ 为这类需求提供了 `while` 循环，还有一个变体 `do-while`。

## 2 `while` 循环

### 2.1 结构

```cpp
int workItems = 10;

while (workItems > 0)
{
    std::cout << workItems << std::endl;
    --workItems;
}
```

结构只有两部分：`while` 关键字 + 一对小括号里的**条件**，后面接循环体。**没有 for 那样的初始化段和更新段**——因为循环次数未知，也就无法在循环头上把"从哪开始、怎么推进"一次写清楚。

于是这两件事必须自己安排：

| 职责 | for 里写在哪 | while 里写在哪 |
| --- | --- | --- |
| 准备初始状态 | 小括号第一段 | **循环之前**先定义并初始化好变量 |
| 判断能不能继续 | 小括号第二段 | 小括号里（唯一和 for 对应的部分） |
| 让状态向结束推进 | 小括号第三段 | **循环体内部**，通常放在最后 |

### 2.2 条件的检查时机：每轮之前

`while` 在**每一轮迭代开始之前**检查条件：为真就执行循环体，为假就结束循环、跳到循环后面的语句继续执行。

上面那段代码的轨迹：

| 轮次 | 进入前 `workItems` | 条件 `> 0` | 循环体打印 | 体末 `--workItems` 之后 |
| --- | --- | --- | --- | --- |
| 第 1 轮 | 10 | 真 | `10` | 9 |
| 第 2 轮 | 9 | 真 | `9` | 8 |
| … | … | 真 | … | … |
| 第 10 轮 | 1 | 真 | `1` | 0 |
| 结束 | 0 | **假** | —— | —— |

共打印 10 行，从 `10` 递减到 `1`。注意最后那一行是 `1` 而不是 `0`：打印发生在判断之前，`0` 这一轮已经进不来了。

### 2.3 可能一次都不执行

因为条件在**进入循环体之前**检查，所以如果一开始条件就是假，循环体**一次都不会执行**：

```cpp
int workItems = 0;

while (workItems > 0)     // 0 > 0 为假
{
    std::cout << workItems << std::endl;   // 永远不会执行
}
```

这个程序运行起来什么都不打印。这不是 bug，而是 `while` 的正常语义——**"次数可以是 0" 是 while 应有的性质**。在有些场景里这正是你想要的：任务队列本来就是空的，那就什么也不用做。

### 2.4 为什么 `while` 更容易写错

回到刚才那张职责分工表。`for` 把"初始化 / 条件 / 更新"三件事都集中在循环头上，一眼就能看全；`while` 把它们拆到了三个地方，于是有了一个典型的失败模式：**初始化写了、条件写了、循环体里却忘了更新状态**。

```cpp
int workItems = 10;

while (workItems > 0)
{
    std::cout << workItems << std::endl;
    // 这里少了一句 --workItems;
}
```

`workItems` 永远是 10，条件永远为真，程序会一直打印下去，直到被强行终止——这就是**死循环**。第 5 节专门讲它。

**写 while 循环时第一件要确认的事：循环体里有没有让条件趋向假的操作。** 没有，就要么补上，要么说明这里本来就该是无限循环。

## 3 `do-while` 循环

### 3.1 结构

```cpp
do
{
    std::cout << workItems << std::endl;
    --workItems;
}
while (workItems > 0);
```

关键字是 `do` 和 `while` 两个：`do` 后面直接接循环体，循环体之后才写 `while (条件)`。

有一个**纯语法上的坑**必须先记住：`while (条件)` 末尾那个**分号不能漏**。因为 `do-while` 的整条结构在这里结束，分号是这条语句的结束标记（对比普通 `while`，它的分号其实属于循环体那条语句，所以看起来像是没有）。

### 3.2 条件的检查时机：每轮之后

`do-while` 与普通 `while` 唯一的区别是**条件的检查时机**：它先执行一轮循环体，**执行完之后**再检查条件，为真就回去再来一轮。

由此得到 `do-while` 最重要的性质：**循环体至少执行一次，一次都不执行是不可能的。**

看一个刻意构造的例子：

```cpp
int workItems = 0;      // 注意：初始就是 0，条件一开始就是假的

do
{
    std::cout << workItems << std::endl;
    --workItems;        // workItems 变成 -1
}
while (workItems > 0);  // 检查 -1 > 0，为假，结束
```

运行结果是**打印一行 `0`**。

如果把它改写成普通 `while`：

```cpp
int workItems = 0;

while (workItems > 0)   // 条件一开始就是假
{
    std::cout << workItems << std::endl;   // 一行都不会打印
}
```

一行都不会输出。**同样的初值、同样的条件，只是循环形式不同，结果就从"打印一行"变成"什么都不打印"。** 这就是两者差别的全部：

| | 条件检查时机 | 最少执行次数 | 适用场景 |
| --- | --- | --- | --- |
| `while` | 每轮**之前** | 0 次 | 先判断、条件不成立就什么都不做 |
| `do-while` | 每轮**之后** | 1 次 | 必须先做一次，再看结果决定要不要继续 |

### 3.3 什么时候必须用 `do-while`

`do-while` 的典型场景是**"先做一次、再判断"**。最经典的是菜单或命令行界面：

程序启动后必须先显示一次菜单、读一次用户输入，然后才谈得上"判断用户是不是选了退出"。如果这一步用普通 `while`，就得把"显示菜单并读输入"的代码在循环外再写一遍——重复一份；而 `do-while` 天然表达了这个意思：**先做一次（显示菜单、读输入），然后检查条件（是否退出），没退出就再来一轮。**

反过来说，如果"一次都不做"是合法甚至更合理的（队列本来就是空的），那就该用 `while`。

## 4 死循环：`while` 特有的风险

**死循环**指循环条件永远为真，程序停不下来。常见的三种成因：

1. **忘了推进状态。** 循环体里没有修改条件涉及的变量（就是 2.4 节那个例子）。
2. **推进的方向错了。** 条件写的是 `workItems > 0`，循环体里却写成 `++workItems`（越来越大），永远到不了 0。
3. **条件本身恒真。** 例如 `while (true)` 或写错了字的常量条件。

**预防办法很简单：写完一个 `while` 或 `do-while`，回头找一下"哪一句会让条件最终变成假"**，确认它存在、方向正确、并且每一轮都会执行到（没有藏在某个 if 分支里）。

另外要说清楚：死循环不总是 bug。有些程序的**主循环本来就要一直跑**（等待事件的服务器、扫描按键的嵌入式程序），那时它会明确写成 `while (true)` 这种一眼能看出意图的形式，而不是因为忘了更新变量而"意外地"停不下来。区别在于**是刻意写的还是漏写的**。

程序真的卡死时怎么退出：在 VS Code 的终端里点终端面板的终止按钮，或在终端里按 `Ctrl+C` 中断当前进程。

## 5 动手实验

例程在 `E:\CPP_Code\CppFromScratch\ch07_while_loops\` 下，两个程序各占一个文件夹。

### 5.1 实验一：`while` 的递减轨迹

`ch07_while_loops\while\while.cpp` 里 `workItems` 初始为 10，循环条件 `workItems > 0`，循环体先打印再 `--workItems`。

```text
E:\msys64\ucrt64\bin\g++.exe -std=c++17 -Wall -g while.cpp -o while.exe
./while.exe
```

**预期现象**：输出 10 行，从 `10` 递减到 `1`：

```text
10
9
8
...
1
```

**验收标准**：正好 10 行，且**最后一行是 `1`，不是 `0`**。能解释为什么没有 `0`——打印发生在条件检查之后、变量递减之前，等到 `workItems` 变成 0 时这一轮已经进不来了。

把初值改成 `0` 重新编译，输出应变成**什么都没有**（循环体一次都不执行），改回 10 恢复原状。

### 5.2 实验二：`do-while` 至少执行一次

`ch07_while_loops\do_while\do_while.cpp` 里 `workItems` 初始为 0，用 `do { ... } while (workItems > 0);` 结构。

**预期现象**：只输出一行

```text
0
```

**验收标准**：能说清这一行是怎么来的——条件一开始就是假，但循环体在条件检查之前已经先执行了一轮，所以打印了 `0`，随后 `--workItems` 让它变成 -1，检查 `-1 > 0` 为假退出。

然后把这个例程**临时改成普通 `while`**（把 `do` 去掉、把 `while` 挪到循环体前面），重新编译运行应看到**一行都没有**。改回 `do-while` 结构。

### 5.3 实验三：亲手制造一次死循环并终止它

把 `ch07_while_loops\while\while.cpp` 循环体里的 `--workItems;` 那一行**注释掉**，重新编译运行。

**预期现象**：终端开始不停打印 `10`，永不停歇——`workItems` 永远是 10，条件永远为真。

**如何终止**：在终端面板里点击终止（垃圾桶）按钮，或按 `Ctrl+C`。

**验收标准**：亲手终止了它，并说清成因——循环体里没有任何一句能让 `workItems` 趋向 0。把注释还原，重新编译运行，确认输出恢复为 10 行。

## 6 常见错误与排查

| 报错或现象 | 原因 | 处理 |
| --- | --- | --- |
| 程序一直打印、停不下来 | 循环体里缺少让条件趋向假的操作 | 补上更新语句，或在写完后核对"哪一句会让条件变假" |
| 条件一开始为假，却以为循环体会执行一次 | 用的是 `while` 而不是 `do-while` | 需要至少执行一次就用 `do-while` |
| `error: expected ';' before 'return'`，指向 `do-while` 的 `while` | `do-while` 结尾漏了分号 | 在 `while (条件)` 后面补 `;` |
| `warning: suggest parentheses around assignment used as truth value` | 条件里把 `==` 写成了 `=`（例如 `while (x = 0)`） | 改成 `==`；这类错误下一章依然要注意 |
| 循环体执行次数比预期少一次 | `while` 的条件在进入前检查，最后一轮可能已经进不来 | 把打印语句的位置和条件的边界在纸上走一遍，确认哪一轮是最后一轮 |
| 循环变量在循环外使用报错 | 变量作用域只在循环结构内 | 需要在循环之后继续用的变量，要在循环之前定义 |
