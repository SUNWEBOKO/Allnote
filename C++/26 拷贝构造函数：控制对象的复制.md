## 学习目标

完成本章后，你应当能够：

1. 写出拷贝构造函数的签名，并说明参数为什么必须是引用、为什么通常是 `const` 引用。
2. 指出拷贝构造函数在哪些时刻会被调用。
3. 说明编译器隐式生成的拷贝构造函数做了什么。
4. 解释成员是裸指针时，默认的逐成员复制会带来什么后果。
5. 用 `= delete` 禁止一个类型的复制，并说出标准库中的实例。

## 1 从已有对象造出新对象

第 24 章的构造函数是"从参数造出对象"，第 25 章的析构函数是"对象消失时的收尾"。这一章处理第三种常见需求：**已经有一个对象，想照着它的样子再造一个。**

之前几章里我们已经不知不觉做过很多次了：函数按值传参时，形参是实参的一份副本（第 08 章）；函数按值返回一个对象时，也会产生一个新的对象。为了让"复制一个对象"这件事可以自己定义，C++ 提供了**拷贝构造函数**（copy constructor）。

先看它长什么样。例程 `E:\CPP_Code\CppFromScratch\ch26_copy_constructor\copy_constructor\copy_constructor.cpp` 里有一个最短的可用版本：

```cpp
struct point
{
    int x;
    int y;

    point(int new_x, int new_y) : x(new_x), y(new_y)
    {
    }

    point(const point& p) : x(p.x), y(p.y)
    {
        std::cout << "copy ctor: build (" << x << ", " << y << ") from (" << p.x << ", " << p.y << ")" << std::endl;
    }

    void print()
    {
        std::cout << "x = " << x << ", y = " << y << std::endl;
    }
};
```

对照第 24 章的规则看：**名字还是 `point`，也不写返回类型**——这两点和普通构造函数一模一样。差别在参数列表：普通构造函数这里放的是 `int new_x, int new_y`，拷贝构造函数放的是**一个本类型的引用** `const point& p`，`p` 就是"要照着复制的那个对象"。

## 2 签名里的两个决定：引用和 `const`

`point(const point& p)` 这一行有两个必须讲清的地方。

### 2.1 为什么参数必须是引用

假设按值写：

```cpp
point(const point p) : x(p.x), y(p.y) { }      // 错误写法
```

编译器会直接拒绝：

```text
error: invalid constructor; you probably meant 'point (const point&)'
```

原因是**按值传参本身就要先复制一次实参**，而复制需要调用拷贝构造函数——正是我们此刻正在定义的那个函数。这样就形成了"要调用自己才能调用自己"的无限递归。写成引用就没有这个问题：引用只是原有对象的一个别名（第 15 章），传引用不会创建新对象，也就不会触发又一次复制。编译器直接堵死按值的写法，就是为了防止这种无解的递归。

### 2.2 为什么通常加 `const`

拷贝的语义是"照着原对象的样子造一个新的"。这个过程中我们只会**读取**原对象的数据成员（`p.x`、`p.y`），不会去改它。加上 `const` 就是把这句话写进类型里：函数体内不能修改 `p`，编译期就会拦住任何写操作。

不加 `const` 也能编译，但会带来一个实际麻烦。看下面的例子：

```cpp
struct point
{
    int x, y;
    point(int new_x, int new_y) : x(new_x), y(new_y) { }
    point(point& p) : x(p.x), y(p.y) { }        // 没有 const
};

void take(const point& p)
{
    point copy = p;      // 编译失败
}
```

报错是：

```text
error: binding reference of type 'point&' to 'const point' discards qualifiers
```

因为 `p` 是 `const point&`，而拷贝构造函数的参数是 `point&`（非 const 引用），把常量对象交给一个"可能修改它"的引用是非法的。**结论：拷贝构造函数一律写 `const point&`。** 它同时也是"复制不会改动原对象"这一承诺的书面形式，而这条承诺正是后面所有讨论的基础。

## 3 拷贝构造函数在什么时候被调用

这是最容易模糊的一点。判断规则只有一句：

> **凡是"用一个已有对象去初始化一个正在创建的新对象"，调用的都是拷贝构造函数。**

例程一里演示了三种写法：

```cpp
point p2 = p1;      // 拷贝初始化
point p3(p1);       // 直接初始化
print_point(p1);    // 按值传参：形参 p 是新创建的对象
```

三种写法都调用了拷贝构造函数，运行结果里也都能看到那句 `copy ctor: ...` 的打印。其中前两种写法**看着不同，做的事完全相同**，选哪个只是风格问题。

### 3.1 拷贝构造与赋值是两回事

下面两行完全不一样：

```cpp
point p2 = p1;      // p2 是这一刻才诞生的，用 p1 初始化它 → 拷贝构造函数
p2 = p1;            // p2 早就存在了，把 p1 的值覆盖进去 → 赋值，不是拷贝构造
```

区别在于**等号左边的对象是否已经存在**。第二行调用的是"拷贝赋值运算符"，那是另一个函数，写法和运算符重载有关，第 27 章之后会看到它的形式。本章只需要记住这条判断依据：**看左边是不是新对象。**

### 3.2 按值传参也会复制

例程一里还有一个函数：

```cpp
void print_point(point p)
{
    std::cout << "inside the function: ";
    p.print();
}
```

调用 `print_point(p1);` 时，形参 `p` 是一个新创建的对象，用 `p1` 初始化，于是这里又发生了一次拷贝。这解释了第 08 章"形参是实参的副本"这句话的成本：**每一次按值传参都在复制整个对象。** 对 `point` 这种只有两个 `int` 的类型可以忽略；但对一个内部装着几万个元素的类型，这个复制的代价就很大了。第 16 章讲的按引用传参正是为了避免它，而第 28 章会给出另一种更进一步的方案。

例程运行完可以看到，三次拷贝之后 `p1` 的 `x`、`y` 仍然是 `10`、`20`——拷贝构造函数体里只读了 `p` 的成员，没有写。**复制一个对象不应该改变原对象**，这是拷贝构造函数必须守住的性质。

## 4 不写会怎样：编译器隐式生成的拷贝构造函数

例程 `E:\CPP_Code\CppFromScratch\ch26_copy_constructor\implicit_copy\implicit_copy.cpp` 里的 `point` 完全不写拷贝构造函数，但 `point p2 = p1;` 仍然能编译、能跑对。

原因是：**如果你没有声明拷贝构造函数，编译器会隐式声明一个**，它的行为是**逐个数据成员地复制**（memberwise copy）。本例的两个成员都是 `int`，于是 `p2.x` 被初始化为 `p1.x`、`p2.y` 被初始化为 `p1.y`，结果就是一个一模一样的点。

"逐个成员复制"带来的直接后果是**两个对象彼此独立**：例程里把 `p2.x` 改成 `30`、`p2.y` 改成 `40`，`p1` 依然打印 `x = 10, y = 20`。对只含值成员的类型来说，这正是我们想要的默认行为。

如果只是想明确写出"就用编译器给的那个版本"，可以写：

```cpp
point(const point& p) = default;
```

`= default` 的意思是"我声明它存在，但实现交给编译器生成"，效果与不写完全相同。**多数简单类型不需要写拷贝构造函数**，直接用隐式的就够；需要写自己的版本只有两个理由：复制时要多做点事（比如打印、计数），或者默认行为是错的——后者是下一节的内容。

## 5 默认复制什么时候会出错：成员是裸指针

第 25 章的 `manual_cleanup` 里有一个用手工管理内存的类型：

```cpp
struct int_array
{
    int* array;
    int_array(int size) { array = new int[size] {}; }
    ~int_array() { delete[] array; }
};
```

它的成员 `array` 是一个裸指针。**指针也是值**，所以逐成员复制会把指针里的地址原样抄一份。意思是复制之后：

- 原对象和新对象的 `array` **指向同一块内存**；
- 两个对象都认为自己负责释放那块内存，析构时就会各释放一次。

这不是"两个副本"，而是"两个对象共享一份资源却被各自当成独占"。同一个资源被 `delete[]` 两次叫**双释放**（double free），属于未定义行为。

在 `manual_cleanup.cpp` 上做一个小实验就能看到这一点：

```cpp
int_array a(10);
int_array b = a;                                     // 默认拷贝构造
std::cout << (a.array == b.array) << std::endl;      // 两个指针是不是同一个地址
```

实测（GCC 16.1.0 / UCRT 运行时）：这一行输出 `1`，说明两个指针确实相等；随后两个析构函数各打印一行 `dtor`，进程在退出时异常终止（本次实测退出码 127，没有任何编译警告）。**因为是未定义行为，换一个编译器或运行库表现可能不同**——它也可能安静地跑完，让人完全察觉不到问题所在。这类"看不出错但已经错了"的缺陷，正是拷贝构造函数需要自己掌控的原因。

需要注意的是，**问题的根源不是"默认拷贝构造有 bug"，而是这个类型不该被复制**。`int_array` 里那块内存的所有权是唯一的，复制对象时无法把内存也复制成两份，所以正确处理只有两条路：要么禁止复制（下一节），要么自己写一个"申请一块同样大小的新内存、再把数据逐个拷过去"的拷贝构造函数，也就是**深拷贝**。深拷贝的写法就是本章学的拷贝构造函数，只是函数体里的 `x(p.x)` 换成显式的内存申请与逐元素拷贝；本章的重点放在"识别出哪些类型不该被复制、以及怎么禁止它"。

由此可以得到一条实用的经验：**如果一个类需要自己写析构函数（说明它在手工管理某个资源），那它多半也需要自己定义复制行为。** 这条经验在 C++ 里叫"三法则"（Rule of Three）：析构函数、拷贝构造函数、拷贝赋值运算符，要么都不写，要么一起写。本章处理其中的拷贝构造函数，拷贝赋值运算符的写法要用到第 27 章的运算符重载知识。

## 6 禁止复制：`= delete`

有些类型的存在本身就意味着"世界上只能有一个"。例程 `E:\CPP_Code\CppFromScratch\ch26_copy_constructor\delete_copy\delete_copy.cpp` 里的 `owned_int` 就是这种：它独占一块动态分配的 `int`，允许复制必然导致双释放，所以干脆禁止复制。

```cpp
struct owned_int
{
    int* data;

    owned_int(int value) : data(new int(value))
    {
    }

    owned_int(const owned_int& other) = delete;

    ~owned_int()
    {
        delete data;
    }
};
```

`= delete` 写在函数声明后面，意思是"这个函数不允许被使用"。它带来的效果是双重的：

- 编译器**不再隐式生成**拷贝构造函数（因为我们已经声明了它，只是标成了删除）；
- 任何试图拷贝这个类型对象的代码**在编译期直接失败**。

例程里那行复制语句被留成了注释，取消注释后编译会报：

```text
error: use of deleted function 'owned_int::owned_int(const owned_int&)'
```

请注意失败的位置：**编译期**，而不是运行期。这正是 `= delete` 的价值——它把"这个类型不能被复制"变成编译器强制执行的规则，而不是一句只写在文档或注释里、靠人自觉的约定。

标准库里最有名的例子就是 `std::unique_ptr`：它独占自己管理的资源，所以内部把拷贝构造函数（以及拷贝赋值）标记为 `delete`，只保留可以转移所有权的操作。例程里同样创建了一个 `unique_ptr` 并用它，只是那行复制代码被注释掉——取消注释就会看到同一类 `use of deleted function` 报错，报错信息里提到的正是 `std::unique_ptr` 的拷贝构造函数。

### 6.1 一个容易踩的坑：删了拷贝构造，赋值还在

`= delete` 只作用于你删掉的那一个函数。本例删的是**拷贝构造函数**，而 `p2 = p1;` 那种形式调用的是**拷贝赋值运算符**，它并不会因为拷贝构造函数被删除而自动消失。所以下面这段代码**仍然能编译通过**：

```cpp
owned_int a(10);
owned_int b(0);
b = a;              // 编译通过：b.data 和 a.data 指向同一块内存
```

编译通过并不代表正确，它只是说明"复制还在，只是换了个入口"。要彻底堵住复制，两个函数都得处理，其中拷贝赋值运算符的写法要用到第 27 章的运算符重载。本章要建立的认识是：**禁止复制时，先想清楚有哪些入口会复制对象**——初始化、按值传参、赋值，一个都不能漏。

**必做实验**：把 `// owned_int b = a;` 的注释去掉，重新编译，确认得到上面的报错、**没有生成可执行文件**；再把注释还原。然后把 Demo C 里 `std::unique_ptr<int> other = ptr;` 那行注释的复制语句也放开，确认报错换成 `unique_ptr` 的拷贝构造函数被删除。两次都看完后记得还原。

```cpp

```

## 8 常见错误与排查

| 报错或现象 | 原因 | 处理 |
| --- | --- | --- |
| `error: invalid constructor; you probably meant 'point (const point&)'` | 拷贝构造函数的参数写成了按值 `point(const point p)` | 参数改成引用：`point(const point& p)` |
| `error: binding reference of type 'point&' to 'const point' discards qualifiers` | 拷贝构造函数的参数没写 `const`，却要复制一个常量对象 | 参数改成 `const point&` |
| `error: use of deleted function 'owned_int::owned_int(const owned_int&)'` | 类型用 `= delete` 禁止了复制，代码里却还在复制它 | 删掉复制语句；确实需要转移资源时改用后面章节讲的移动 |
| `error: 'point::point(const point&)' cannot be overloaded with 'point::point(const point&)'` | 同一个拷贝构造函数被定义了两次 | 只保留一份定义 |
| `error: no matching function for call to 'point::point()'` | 只写了带参数的构造函数，没有默认构造函数，却创建了不带参数的对象 | 创建时给出参数，或补一个默认构造函数 |
| `p2 = p1;` 编译通过，但 `point p3 = p1;` 报"删除的函数" | 两者是不同的函数：赋值调用拷贝赋值运算符，初始化才是拷贝构造函数 | 想禁止复制必须逐个入口处理，别只看拷贝构造函数 |
| 程序在退出时异常终止，析构打印出现两次 | 管理裸指针的类型被默认复制，两个对象释放同一块内存（双释放，未定义行为） | 用 `= delete` 禁止复制，或自己写申请新内存的拷贝构造函数（深拷贝） |
| 复制后修改新对象，原对象也跟着变了 | 默认逐成员复制只抄了指针的值（地址），两个对象共享同一份数据 | 这是浅拷贝的必然结果；需要独立性就写自己的拷贝构造函数 |

## 9 本章验收
