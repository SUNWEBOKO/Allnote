## 学习目标

完成本章后，你应当能够：

1. 用 `struct` 和 `class` 定义包含数据成员和成员函数的类型，创建对象并用点运算符访问成员。
2. 说出 `struct` 与 `class` 的唯一区别，以及 `public`、`private` 的作用范围和各自的默认值。
3. 用聚合初始化和空花括号创建对象，并说出 `Point p;`、`Point p {};`、`Point p {10, 20};` 三种写法的区别与风险。
4. 说明成员函数为什么能直接访问数据成员，以及同一类型的两个对象之间是什么关系。
5. 用"私有数据成员 + 公开成员函数"的写法给一个类写出带检查的 setter 与 getter，并说明封装比直接开放数据成员好在哪里。

## 1 为什么需要定义自己的类型

到这一章之前，我们用的类型都是现成的：`int`、`double` 来自语言本身，`std::array`、`std::vector` 来自标准库。这些类型覆盖了很大一类需求，但总会碰到它们不够用的时候。常见的三种情形是：

- **标准库容器不够用**。它们只负责"装东西"，装进去的东西之间的关系、对这些东西能做什么操作，容器一概不管。
- **已有的类型不合适**，需要一个按自己需求定制的类型（比如某处的数据要一直保持有序、或者要记录额外信息）。
- **语言里根本没有这个类型**，因为它只存在于你要解决的那个问题里。

第三种情形最容易理解，也最好举例。假设我们在写一个处理绘图或图表的程序，那么"平面上的一个坐标点"就是最基本的东西。用现成的类型怎么表示它？

```cpp
int x = 10;
int y = 20;
```

能用，但有个根本问题：**`x` 和 `y` 之间的"成对"关系只存在于我们的记忆里**。语言不知道这两个 `int` 是一组；如果程序中还有另一个点的坐标 `x2`、`y2`，函数签名里就会出现一堆看不出关系的整数参数，谁都可以把两个不同点的坐标混着用而编译器毫无反应。

我们希望有一个**类型**，它的名字就叫"点"，它自己就知道"我由两个整数坐标组成"。这就是自定义类型的意义：**把数据的结构和适用于这些数据的操作，一起变成一个可以命名、可以检查、可以传递的东西。** 在 C++ 里做这件事的两个关键字是 `struct` 和 `class`（本章都会讲到）。它们几乎相同，下面先专注结构体的基础与核心。

## 2 定义一个结构体

定义一个表示坐标点的类型，写法如下（取自例程 `E:\CPP_Code\CppFromScratch\ch22_structs\struct_point\struct_point.cpp`）：

```cpp
struct Point
{
    int x;
    int y;

    void print()
    {
        std::cout << "x = " << x << std::endl;
        std::cout << "y = " << y << std::endl;
    }
};
```

逐部分看：

- **`struct Point`**：`struct` 是关键字，`Point` 是新类型的名字。这一句是**类型定义**，不是变量定义——它只告诉编译器"以后有个类型叫 `Point`"。写到这一行为止，内存里还没有任何东西。
- **数据成员**：`int x;` 和 `int y;`。它们不是某个具体对象的坐标，而是"凡是用这个类型创建的对象，都各有这两个 `int` 成员"。习惯上把数据成员写在前面。
- **成员函数**：`void print()` 写在结构体内部，同样具备第 04 章讲的函数四要素（返回类型、名字、参数列表、函数体）。它的特别之处在于**参数列表是空的，却能打印 `x` 和 `y`**——因为它是 `Point` 的成员函数，调用它的那个对象就是它的数据来源。
- **结尾的分号**：`};` 这一行末尾的分号不能省。这是最容易漏、报错信息又最难看懂的一处，漏写时编译器通常报在**下一行**，而不是 `struct` 这一行。

**`struct` 与 `class` 的唯一区别（本章第 7 节展开）**：结构体的成员默认是公开可访问的，类的成员默认是私有的。到目前为止结构体例子里的成员都能在结构体外面直接使用。

## 3 创建对象并使用它

**定义好类型之后，创建变量的方式和 `int` 完全一样**：

```cpp
Point p1;      // 创建一个 Point 类型的对象，名字叫 p1
```

这里 `Point` 是类型名，`p1` 是这个类型的一个**对象**（也叫这个结构体的一个**实例**）。创建实例这件事，语法上和第 02 章 `int count;` 没有任何差别——自定义类型和内置类型在"怎么用"这一层是平等的。

**访问成员需要点运算符 `.`**：

```cpp
p1.x = 10;     // 把 p1 的 x 成员设为 10
p1.y = 20;     // 把 p1 的 y 成员设为 20
p1.print();    // 调用 p1 的成员函数
```

`.` 是**成员访问运算符**，`p1.x` 读作"`p1` 的 `x`"。它后面既可以跟数据成员，也可以跟成员函数——这个运算符其实我们早就在用了：第 07 章写过的 `myVector.push_back(5)`、`myVector.size()`，用的就是同一个运算符，只不过那些成员来自标准库的 `vector`。现在这些成员是我们自己定义的。

**成员函数最大的好处在这里体现出来**：`p1.print()` 的参数列表是空的，我们不需要把坐标作为参数传进去。原因是数据成员 `x`、`y` 本来就在对象内部，成员函数可以直接使用它们。对比第 04 章的 `printArray(std::array<int, 3> array)`——那个函数必须把要打印的数组当参数接收，因为它站在数组外面。**把数据和操作数据的函数放进同一个类型，从此"要打印一个点"和"要打印的数组长度"这类信息不用再靠参数来回传递。**

## 4 两个对象是彼此独立的两份数据

再创建一个对象，它的成员和第一个对象毫无关系：

```cpp
Point p2;
p2.x = 5;
p2.y = -5;
p2.print();
```

`p1` 和 `p2` 都是 `Point` 的实例，但它们是**两个不同的对象**：各自有自己的一份 `x` 和 `y`，在内存里落在不同的存储单元上。改 `p2` 不会影响 `p1`，因此例程 `struct_point` 的 Demo C 里再次打印 `p1`，拿到的仍然是 10 和 20。

这一点值得和已经学过的规则接上：**结构体是值类型**，和 `int`、`std::array` 一样。赋值时会逐成员复制出一份独立的数据，按值传参时也一样（第 04 章讲过按值传参是复制），函数里改的是副本、不会改到原件。例程 `struct_vector` 的 Demo C 就用一个按值接收 `Point` 的函数演示了这件事。

## 5 创建对象的几种写法

`Point p1;` 这条语句只是"创建对象"，**并没有给成员任何值**。此时 `p1.x`、`p1.y` 里是什么，没有任何保证——和第 02 章"未初始化的变量不能用"是同一条规则。想让成员一创建就有值，有两种写法。

**聚合初始化：按声明顺序一次给全成员赋初值。**

```cpp
Point p1 {10, 20};      // x = 10, y = 20
```

`Point` 这种"没有任何自定义构造方式、成员都是公开的"类型，属于**聚合类型**（aggregate），可以用一对花括号一次性初始化全部成员：**花括号里的值按位置对应成员的声明顺序**，第一个给 `x`，第二个给 `y`。判定聚合的条件其实更完整一些：一旦有用户提供的构造函数、有虚函数，或者有私有/保护的非静态数据成员，它就不再是聚合类型（第 12 章会用到这条）。这里要小心一件事：顺序写反了编译器不会拦，只会静悄悄地把两个值装反——`Point p1 {20, 10}` 是能编译的，但得到的是 `x = 20`、`y = 10`。

**空花括号：所有成员都用各自类型的零值。**

```cpp
Point origin {};        // x = 0, y = 0
```

空花括号是特殊语法，表示"全部成员取零值"，所以 `origin` 的坐标一定是 0，不会是随机数。两条写法的差别可以概括成一句话：**`Point p;` 让成员处于不确定状态，`Point p {};` 保证成员被清零。** 只要不在创建后马上给每个成员赋值，就应该写成空花括号的形式。

**花括号里少给几个值也可以**，剩下的成员按零值处理：

```cpp
Point half {1};         // x = 1, y = 0
```

这**不会**报错，也不需要警告——编译器认为这是有意的写法。值给多了才会报错（`too many initializers`）。所以"少给"和"给反"这两种错误编译器都帮不上忙，写聚合初始化时要自己核对顺序和个数。

## 6 自定义类型带来的连锁好处

一旦 `Point` 成了一个真正的类型，前面章节学到的东西几乎都能直接用在它身上：

```cpp
std::vector<Point> points {{1, 2}, {3, 4}, {5, 6}};   // 放进容器，每个花括号是一个 Point

for (Point p : points)                                // 范围 for 遍历
{
    p.print();
}
```

**自定义类型也可以当函数的返回类型和参数类型**：

```cpp
Point midPoint(Point a, Point b)
{
    return Point {(a.x + b.x) / 2, (a.y + b.y) / 2};
}
```

这个函数接收两个点、返回它们的中点。`Point {...}` 在 `return` 里照样是聚合初始化，结果直接在调用处构造出返回对象（C++17 起保证不复制，这就是受保证的复制省略）。`struct_vector` 这个例程把上面这些串在一起：三个点放进 `vector`、逐个打印、算出中点、再用一个按值传参的函数演示复制语义。

**这些能力不是为结构体专门开的后门，而是"它已经是一个类型了"的自然结果。** 这正是自定义类型的价值所在：把问题里的概念变成一个类型，之后所有处理类型的手段就都能用上。

## 7 从结构体到类：只差一个默认值

结构体的基础到这里已经齐了，现在换一个关键字，做同样的定义。前面几节我们用 `struct` 定义了自己的类型，并且两个对象可以各有各的数据、可以放进容器、可以当函数参数和返回值：

```cpp
struct Point
{
    int x;
    int y;
};

class Point
{
    int x;
    int y;
};
```

这两段定义几乎一模一样，**在 C++ 里它们唯一的区别只有一个默认值：如果不特别声明，成员的访问权限是什么。** 结构体里默认是公开可访问的，类里默认是私有的。除此之外没有别的差异，所以前面学到的所有东西——创建对象、点运算符、成员函数、值语义——下面一条都不用重学。

先看"访问权限"到底管什么。C++ 里有三个访问限定符：

| 限定符 | 谁能访问 |
| --- | --- |
| `public` | 任何人：类内部、类外部都能访问这些成员 |
| `private` | 只有这个类自己的成员函数能访问；类外部一律不行 |
| `protected` | 本类与派生类；它只在讲继承的时候才有意义，本章不涉及 |

限定符的**作用范围**是"从它出现的位置开始，直到下一个限定符或者类结束"：

```cpp
class Point
{
    int x;          // 前面没有限定符，所以按 class 的默认规则：private
    int y;          // 同上，private

public:             // 从这里开始改成 public
    void print();   // public
    int getX();     // public

private:            // 又可以改回 private
    int cached;     // private
};
```

也就是说，`public:`、`private:` 不是"给某一个成员贴的标签"，而是**一条分界线**：它切换后面一大段成员的权限，直到下一条分界线。一般来说，写类时习惯把 `public` 的接口放在前面，让读者先看到"这个类能做什么"，把 `private` 的实现细节放在后面；上面这个例子正好相反，把数据成员放在最前面，是为了直观演示 `class` 的默认权限就是 `private`。顺序只是风格，起决定作用的始终是最后生效的那条分界线。

## 8 默认私有意味着什么

在类的定义里什么都不写，那么所有成员都是私有的。此时下面这段代码无法编译：

```cpp
class Point
{
    int x;
    int y;

    void print()
    {
        std::cout << "x = " << x << std::endl;   // 合法：成员函数访问自己的成员
        std::cout << "y = " << y << std::endl;
    }
};

int main()
{
    Point p1;
    p1.x = 10;      // 编译错误：x 是私有的
    p1.print();     // 编译错误：print 也是私有的
}
```

两条语句都会失败，但失败的原因不同、处理方式也不同：

- `p1.x = 10;` 失败，是因为 `x` 是**数据成员**且默认私有。编译器给出的原文是：

  ```text
  error: 'int Point::x' is private within this context
  note: declared private here
  ```

  第二行 `note` 会指到类里声明 `x` 的那一行，方便你确认是谁把访问挡住了。
- `p1.print();` 失败，是因为**成员函数也会受访问限定符的约束**——默认私有的不只是数据，函数同样是私有成员：

  ```text
  error: 'void Point::print()' is private within this context
  ```

`print` 这个函数体本身是合法的：它是 `Point` 的成员函数，所以它访问 `x`、`y` 没有任何问题。访问权限约束的是“从类外面伸进去的手”，不是类自己内部的代码。这条规则的道理也在这里：一个类的成员函数之间可以随意协作，因为它们对同一份数据负责；而类外面的代码必须先得到许可，才能碰这些数据。

那么**为什么要把默认值定成这样**？因为这是给类型的作者一个"默认保守"的起点：写 `class` 时，你不写任何限定符，成员就是外人碰不到的，只有你主动写出 `public:` 时，某个成员才成为对外承诺的一部分。反过来，`struct` 的默认值是公开，正好适合前面结构体那种"只是把几个数据捆在一起"的简单类型，此时不需要任何封装。

## 9 把类变成"能用的"：写上 public

要让上面那段代码跑起来，最直接的做法就是像例程 `E:\CPP_Code\CppFromScratch\ch23_classes\class_access\class_access.cpp` 那样，在成员前面加一条 `public:`：

```cpp
class Point
{
public:
    int x;
    int y;

    void print()
    {
        std::cout << "x = " << x << std::endl;
        std::cout << "y = " << y << std::endl;
    }
};
```

这样 `p1.x = 10;`、`p1.y = 20;`、`p1.print();` 全部合法，运行结果和前面结构体版本一模一样。**把类里所有成员都标成 `public`，这个类就和一个结构体没有实质差别了**——它当然能跑，但也就放弃了类本来要提供的保护。

例程 `class_struct_default` 把两种写法摆在一起：`StructPoint` 什么都不写，`ClassPoint` 补一句 `public:`，两者从创建对象到调用成员函数的行为完全一致；再用一个函数模板接收这两个类型，进一步说明它们都只是普通类型，差别只在"默认谁能访问"。

## 10 封装：哪些成员该公开，哪些该私有

既然一句话就能把所有成员公开，为什么还要折腾访问权限？因为很多类型**自己有规则要守**。看例程 `class_encapsulation` 里的类（略去注释）：

```cpp
class Sensor
{
private:
    int value;

public:
    bool setValue(int newValue)
    {
        if (newValue < 0 || newValue > 100)
        {
            return false;
        }

        value = newValue;
        return true;
    }

    int getValue()
    {
        return value;
    }

    void print()
    {
        std::cout << "value = " << value << std::endl;
    }
};
```

这个类的规则是"`value` 只能落在 0 到 100 之间"。假如 `value` 是公开的，那么 `sensor.value = 999;` 就是一句合法代码，规则被绕过，而且**没有任何地方能拦住它**——等你发现数据不对，已经找不到是哪一行写坏的。把 `value` 变成私有之后：

- 唯一能改动 `value` 的入口是 `setValue`，检查只需要在**一个地方**做；
- 任何人想设值都得走 `setValue`，非法值**根本没机会**写进去；
- 将来范围规则要调整（比如上限改成 200），也只改那一个条件，外部代码不受影响。

这就是**封装**：把数据藏进类里，只对外暴露一组经过设计的操作。它带来的不是"安全"这种虚的好处，而是三条实打实的性质：**规则集中、入口唯一、内部可改**。

**setter 与 getter** 就是这组接口里最常见的两个名字：

- **setter**（也叫设置器）：接收新值、做检查、写进数据成员。命名习惯是 `setXxx`。上例的 `setValue` 返回 `bool`，表示这次设置是否被接受——这一点很重要：调用者需要知道自己的请求生效了没有，而不是设完才发现值没变。
- **getter**（也叫获取器）：把数据成员的值交给调用者。命名习惯是 `getXxx`。它不只是"把变量转手公开"：getter 里同样可以做检查或加工（求平均、换算单位、按需计算等），所以外部拿到的可以是一个"处理过的结果"而不是原始内存。

例程 `class_encapsulation` 的 `main` 里，对外部代码来说 `value` 这个成员根本不存在：设置走 `setValue`，读取走 `print` 和 `getValue`。Demo B 里那个 150 被接口挡下，`value` 仍然是 42——非法值一次都没有进过类的内部。

**但也要知道它的边界**：封装不等于"所有成员都必须配一对 setter/getter"。如果 `getXxx` 只是原样返回一个成员、`setXxx` 只是原样写入一个成员，那等于把数据成员换了个名字公开出去，规则照样可以被绕过——此时用 `struct` 反而更诚实。**判断标准是：这个成员有没有需要保护的规则、有没有外部不该看到的中间状态。** 有，就私有；没有，公开也无妨。

## 11 封装的边界

上面的 `Sensor` 有一个必须注意的地方：`value` 是私有成员，而且**没有初值**。所以这个类在第一次调用 `setValue` 之前，`value` 里的东西是不确定的，此时调用 `print` 或 `getValue` 就是在读一个无效值（第 02 章的老规矩：未初始化的值不能用）。例程里第一条语句就是 `sensor.setValue(42)`，正是为了避开这个坑。

这个别扭之处指向下一章要解决的问题：**能不能让对象在创建的那一刻就带着合法初值，而不是创建完再靠调用者记得去设置？** 这正是构造函数的用途。

### 12.6 实验六：默认访问权限的对照（`class_struct_default`）

`class_struct_default\class_struct_default.cpp` 里 `StructPoint` 不写任何限定符，`ClassPoint` 写 `public:`，两者用法对照；最后用一个函数模板接收这两种类型。
