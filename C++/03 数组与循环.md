## 学习目标

完成本章后，你应当能够：

1. 用"元素类型 + 元素个数"声明 `std::array`、用聚合初始化赋初值，并用 `at()`、`[]`、`front()`、`back()` 访问元素，区分 `at()` 与 `[]` 越界时的行为。
2. 用 `fill()` 重置数组、用 `size()` 查询元素个数，理解长度信息来自容器本身。
3. 写出 C 风格 `for` 循环的三部分并走一遍完整执行轨迹，避开差一错误。
4. 用范围 `for` 遍历容器，说出它为什么能从源头避免下标越界。
5. 写出 `while` / `do-while` 并区分两者的条件检查时机与最少执行次数，会识别死循环成因、在四种循环形式间做出合适选择。

## 1 为什么需要容器

假设要处理一年的温度数据：365 个测量值，每个都要参与后续计算。如果沿用第 02 章的办法，就得定义 365 个变量：

```cpp
double temperature1 = 23.5;
double temperature2 = 24.1;
// ... 还有 363 个
```

这条路走不通。不但写起来荒唐，更关键的是**没法用循环处理**——变量名各不相同，你无法写出一句"把第 i 个温度加起来"。数据必须能按下标访问，才谈得上批量处理。

解决办法是把一组**同类型**的值放进同一个变量里，这个变量内部有很多"格子"，每个格子放一个值，用下标就能定位到具体某一格。这样的结构叫**容器**，本章要学的第一种容器是**静态数组** `std::array`。

## 2 `std::array`：固定大小、类型统一

### 2.1 声明一个数组要给出两件事

```cpp
std::array<int, 3> myArray {4, 5, 3};
```

这行代码的意思是："我要一个能装 3 个 `int` 的数组，名字叫 `myArray`，初始内容是 4、5、3。"尖括号里的两个参数分别是：

- 第一个 `int`：**元素类型**，数组里每个格子装什么类型——这里统一装整数。
- 第二个 `3`：**元素个数**，数组里一共有几个格子。

"静态"和"固定大小"说的一回事：**元素个数在编译期就定死，程序运行期间不会变。** 所以元素个数必须是编译期就能算出来的常量，不能是运行期间才知道的值（比如用户输入的数目）。需要一个能随时增删元素、长度可变的容器，是后续课程的内容。

### 2.2 `std::array` 是模板，不是类型

这里要介绍的是数组部分新引入的唯一一个语言机制。`std::array` 本身**不是一个具体的类型**，而是一个**模板**（template），可以理解成一个"模具"：它描述了"固定大小的同类型数组"这件事的通用做法，但没说明装什么、装几个。

只有把参数填进尖括号，模具才浇出具体的类型：

```cpp
std::array<int, 3>      // 装 3 个 int 的类型
std::array<double, 100> // 装 100 个 double 的类型
std::array<float, 7>    // 装 7 个 float 的类型
```

元素类型和元素个数都能换，所以理论上存在无限多种 `std::array` 类型。**写模板类型时尖括号里的内容不能省**——只写 `std::array myArray;` 编译器无法知道你想要的到底是哪一种。

模板参数的写法要和变量定义区分开：尖括号里是"类型和数量"，变量名写在尖括号外面。

## 3 定义与聚合初始化

### 3.1 聚合初始化

定义数组时最好同时给出初值，写法是用一对花括号把值按顺序列出来：

```cpp
std::array<int, 3> myArray {4, 5, 3};     // 下标 0 是 4，下标 1 是 5，下标 2 是 3
```

这种"用花括号一次性把成员按顺序填满"的初始化方式叫**聚合初始化**。值和下标一一对应，按你书写的顺序放进 0、1、2。前面加等号也完全等价，只是多写一个字符：

```cpp
std::array<int, 3> myArray = {4, 5, 3};   // 和上面完全相同
```

### 3.2 只定义不初始化会留下隐患

```cpp
std::array<int, 3> myArray;    // 可以编译，但三个元素的值都不确定
```

这和第 02 章"不要留下未初始化的变量"是同一个道理：元素此刻装的是那块内存里的残留数据，读出来毫无意义。**定义数组时就把它填满**，或者至少像本章第 6 节那样用 `fill()` 立刻设成已知值。

## 4 访问元素：把某一格取出来

数组的价值在于能定位到单个元素。`std::array` 提供了四种常用方式。

### 4.1 零索引

所有下标从 **0** 开始：三个元素的下标依次是 0、1、2，**最后一个元素的下标是"元素个数 - 1"**。所以 `std::array<int, 3>` 的合法下标是 0、1、2，没有 3。这个约定在后面写循环时尤其关键。

### 4.2 `at()`：带边界检查的访问

```cpp
std::cout << myArray.at(0) << std::endl;    // 取出下标 0 的元素：4
```

`at()` 会先**检查下标是否在合法范围内**。越界时它不会悄悄给你一个错误的值，而是抛出一个 `std::out_of_range` 异常。本机实测，对只有 3 个元素的数组访问 `myArray.at(3)`，程序输出会是（首行 `before` 是为看清"越界发生前程序还在正常输出"而临时加的打印，例程 `array.cpp` 本身没有这句）：

```text
before
terminate called after throwing an instance of 'std::out_of_range'
  what():  array::at: __n (which is 3) >= _Nm (which is 3)
```

即：打印完越界之前的内容后**程序立刻终止**。这个"立刻停下来"的行为正是它的价值——错误暴露在出错的那一行，而不是让你带着一个错值继续算下去、几十行之后才发现结果不对。

### 4.3 `[]`：不做检查的访问

```cpp
std::cout << myArray[0] << std::endl;       // 同样是 4
```

方括号写法更短，但它**不做任何边界检查**。下标越界时的行为是**未定义**的：可能读到一个毫无意义的数，可能覆盖别的数据，也可能直接崩溃——具体会发生什么取决于那一刻的内存布局，而且同一个程序换一次编译或换一台机器表现都可能不同。

需要注意，这两种写法在"合法下标"下结果完全一样，区别只在越界时：

| 写法 | 是否检查边界 | 越界时的表现 | 什么时候用 |
| --- | --- | --- | --- |
| `myArray.at(i)` | 检查 | 抛异常，程序立刻终止并给出原因 | 下标是自己算出来的、没有十足把握时 |
| `myArray[i]` | 不检查 | 未定义行为，可能读到垃圾数据 | 下标确定合法，或需要极致的访问速度时 |

**推荐默认用 `at()`。** 一个多余的检查换来的是一次定位准确的报错，比一个查不出原因的错值划算得多。

### 4.4 `front()` 与 `back()`

```cpp
myArray.front();    // 第一个元素，等价于 myArray.at(0)
myArray.back();     // 最后一个元素，等价于 myArray.at(myArray.size() - 1)
```

取首尾元素时用它们，省得自己算下标——**少算一次就少一次算错的机会**，尤其是 `back()`，它替我们处理了"个数减一"这个容易写错的地方。

### 4.5 `data()`：访问底层内存

`data()` 返回指向数组内部第一块内存的指针。本章用不到它，知道有这么个成员即可；它是为后续需要与 C 风格接口打交道的场合准备的。

## 5 修改元素

数组里的元素是可以重新赋值的，用下标定位到具体位置，然后写入新值：

```cpp
myArray[0] = 10;    // 把下标 0 的元素从 4 改成 10
```

其余元素不受影响。这一点和第 02 章修改变量值是同一件事——**数组元素本质上是"带下标的变量"**，只是名字变成了"数组名 + 下标"。

## 6 `fill()`：整体重置

要把所有元素设成同一个值，逐个赋值太啰嗦，用 `fill()`：

```cpp
myArray.fill(5);    // 三个元素全部变成 5
```

它常用来把数组重置回一个已知状态（例如每轮计算开始前清零）。注意它**一次影响所有元素**，和单元素赋值的区别不要混淆。

## 7 `size()`：容器自己知道有多少元素

```cpp
std::cout << myArray.size() << std::endl;    // 3
```

单独打印一个 `3` 看着没什么，但它的意义在于：**这个数字来自容器本身，而不是我们另外拿一个变量去记。** 带来两个好处：

- 代码里不用再重复出现"3"这个字面量。想知道长度就查 `size()`，永远和数组实际大小一致。
- 以后把数组改成 `std::array<int, 5>`，所有依赖长度的代码自动跟着对，不需要再去找散落各处的 `3` 逐个修改。

这正是标准容器比**C 风格数组**省心的地方。C 风格数组（`int myArray[3];`）在 C++ 里仍然可用，但它在很多场合会"退化"成一个指针，把自己有多少个元素这件事丢掉，于是长度只能由程序员另外用变量记住——那个变量一旦和真实长度不一致，越界就来了。**新代码优先用 `std::array`。**

## 8 不能把整个数组送进输出流

很自然会想这样写：

```cpp
std::cout << myArray << std::endl;     // 编译错误
```

本机实测，编译器会给出很长一串错误，起始几行是：

```text
error: no match for 'operator<<' (operand types are 'std::ostream' {aka 'std::basic_ostream<char>'} and 'std::array<int, 3>')
• there are 33 candidates
```

原因在第 01 章已经埋下伏笔：**只有标准库为某个类型定义了 `<<`，这个类型才能被打印**。`int`、`double`、字符串都有对应的定义，而 `std::array` 没有——标准库不知道你想怎么打印一个数组，是用空格分隔、用逗号分隔，还是每个一行。所以打印数组内容必须自己一个元素一个元素地送进流里。

顺带记住这个现象的排查方法：**一旦开始使用模板类型，编译错误信息会变得又长又吓人**（这里就有 33 个候选重载）。不要从中间开始读，**只读最前面那一句** `error: no match for 'operator<<' (operand types are ... and ...)`，它已经说清了"类型不匹配"，而括号里标出的两个操作数类型，往往一眼就能看出问题。

## 9 重复的工作交给循环

前面几节把一组数据放进了数组，但访问元素还是手写下标：`myArray.at(0)`、`myArray.at(1)`、`myArray.at(2)`。元素一多，这种写法就没法用了——365 个温度值，你不可能手写 365 行。

程序里"把同一件事重复做若干遍"的需求到处都是：重复累加一批数字、把一批数据逐个输出、对矩阵的每一行和每一列做同一套运算（矩阵乘法就是一个典型：用循环遍历行和列，把元素相乘并累加中间结果）。**这类问题的共同解法是把重复的部分交给循环**，让程序自己一轮一轮地执行，每次只处理当前这一轮该处理的那一小块。

`for` 循环是其中最常用的一种，本章讲它的两种形式：从 C 语言继承来的 **C 风格 `for`**，以及 C++ 提供的 **范围 `for`**（range-based for）。

## 10 C 风格 `for`：把循环的三件事写在一行

### 10.1 结构

```cpp
for (int i = 0; i < 5; ++i)
{
    std::cout << "Iteration: " << i << std::endl;
}
```

`for` 后面的小括号里有三段，用**两个分号**隔开，顺序固定：**初始化; 条件; 更新**。

| 位置 | 这一段的代码 | 作用 | 执行时机 |
| --- | --- | --- | --- |
| 第一段 | `int i = 0` | 准备循环计数器 `i`，作为"现在数到第几个了"的记录 | 只在进入循环**之前**执行一次 |
| 第二段 | `i < 5` | 继续循环的条件，决定还能不能再转一圈 | 每轮迭代**开始之前**检查一次 |
| 第三段 | `++i` | 把计数器往前推一格 | 每轮迭代**结束之后**执行 |

花括号里是要重复执行的**循环体**——可以是一条语句，也可以是一整段代码。

### 10.2 执行顺序：走一遍完整的轨迹

把上面的代码在脑子里跑一遍，轨迹是这样的：

| 轮次 | 检查条件前 `i` 的值 | 条件 `i < 5` | 循环体打印 | 循环体后 `++i` |
| --- | --- | --- | --- | --- |
| 第 1 轮 | 0 | 真 | `Iteration: 0` | `i` 变成 1 |
| 第 2 轮 | 1 | 真 | `Iteration: 1` | `i` 变成 2 |
| 第 3 轮 | 2 | 真 | `Iteration: 2` | `i` 变成 3 |
| 第 4 轮 | 3 | 真 | `Iteration: 3` | `i` 变成 4 |
| 第 5 轮 | 4 | 真 | `Iteration: 4` | `i` 变成 5 |
| 循环结束 | 5 | **假** | —— | —— |

有两条规律值得记住：

- **更新表达式在循环体的最后执行**，所以循环体第 5 轮里 `i` 还是 4，打印完才变成 5。
- **正是那个让条件变成假的 5，终止了循环**。所以循环结束后 `i` 的值是 5，而不是 4。

### 10.3 想让循环跑几次，看条件怎么写

"跑 5 次"对应的是 `i < 5`，因为 `i` 取值 0、1、2、3、4 时条件成立，共 5 个值。写成 `i <= 5` 就会跑到 `i = 5` 那一轮，变成 6 次——这就是后面要讲的**差一错误**（off-by-one）。**默念一遍"从 0 开始、小于上限"，比事后排查省事得多。**

### 10.4 三部分都是可以改的

上面是最常见的写法，不是唯一写法：

```cpp
for (int i = 5; i > 0; --i)       // 从大往小倒数
for (int i = 0; i < 10; i += 2)   // 步长是 2，只处理偶数下标
```

只要能表达清楚"从哪开始、做到什么时候、每轮怎么推进"就行。三个部分甚至可以都省略（`for (;;)`），此时条件恒为真，就是一个死循环——只在你确实需要无限循环时才这么写。

### 10.5 循环变量的作用域

`i` 这个名字只在小括号和花括号之内有效，出了循环再用它编译会报错。这个限制是好事：它防止你在循环结束后误用一个已经"过期"的计数器（那个值通常也不是你想要的）。

命名的习惯用法是短名字：`i` 用于最外层、`j` 用于第二层、`k` 用于第三层；再深的层次就要用有意义的名字了，因为 `i`、`j`、`k` 太多也容易看混。

## 11 `++i` 与 `i++`

第三段里写的是 `++i`，第 02 章里你可能见过写作 `i++`。两者都表示"把 `i` 加 1"，差别在**自增发生的时刻**：

- `++i`（前置）：先把 `i` 加 1，然后用新的值参与外围运算。
- `i++`（后置）：先用 `i` 当前的值参与外围运算，然后再把它加 1。

单看结果：

```cpp
int a = 5;
int b = a++;    // b 得到 5（先取值），a 变成 6
int c = ++a;    // a 先变成 7，c 得到 7
```

**但是**：当 `++i` / `i++` 单独作为一条语句使用时（就像 for 循环第三段那样），没人关心"用了哪个值"，两者效果完全相同。所以本课程在 for 循环里统一写 `++i`——它不是必须的，只是一个明确的习惯。真正需要分辨前置和后置的场合，是它们的结果被拿去参与别的运算时。

## 12 范围 `for`：直接遍历容器

### 12.1 语法

```cpp
std::array<int, 5> myArray {4, 2, 12, 63, 13};

for (int value : myArray)
{
    std::cout << value << std::endl;
}
```

结构是 `for (元素类型 变量名 : 要遍历的容器) { 循环体 }`。冒号左边是每一轮从容器里取出来的元素，右边是要遍历的范围。每一轮都会取下一个元素、用它初始化 `value`，然后执行循环体——所以循环体里直接写 `value` 就行，**不需要下标，也不需要计数器**。

### 12.2 它为什么更安全

范围 `for` 最大的好处是**你根本没有机会写错下标**：

- 循环次数由容器决定，**容器自己知道有多少元素**（本章第 7 节的 `size()` 就是这件事的体现），不用你手写长度。
- 没有下标这个中间量，也就没有"多跑一轮"或"少跑一轮"的可能。

而下标越界恰恰是手写循环最常见的错误：长度是 5 却写了 `i <= 5`、长度后来改成 8 却忘了同步循环条件里的 `5`——这两种都会让程序去访问不存在的元素。用范围 `for` 时，这类错误从源头上不会出现。

### 12.3 与 C 风格循环的对照

上面那段范围 `for` 用 C 风格循环写出来是这样：

```cpp
for (int i = 0; i < 5; ++i)
{
    std::cout << myArray[i] << std::endl;
}
```

多出来的东西一眼可见：一个计数器 `i`、一次结束判断、一次自增，还有 `myArray[i]` 这次按下标取值。其中那个 `5` 是手写死的长度——它和数组的真实长度之间**没有任何机制保证一致**，改动一处忘了另一处就出错。范围 `for` 里没有这个数字。

所以范围 `for` 也属于第 02 章说过的**语法糖**：它和 C 风格循环做的是同一件事，但不需要你承担手写计数器的劳动和风险，代码的意图也更清楚——"遍历这个容器里的所有值"。

### 12.4 `value` 是元素的副本

`for (int value : myArray)` 里的 `value` 每一轮拿到的是元素的一份**副本**。所以在循环体里修改 `value`（例如 `value = 0;`）**不会改变数组本身**，`myArray` 里原来的值原封不动。读一读、打印一下完全没有副作用，本章的例子里都只做读取。

想通过范围 `for` 修改容器里的元素，需要换一种写法（用引用），那是后续课程的内容。

## 13 两种 `for` 怎么选

| 需求 | 选择 |
| --- | --- |
| 遍历整个容器里的每一个元素 | 范围 `for` |
| 需要用到下标本身（打印序号、访问另一个容器的对应位置、只处理部分元素） | C 风格 `for` |
| 循环次数在写代码时就确定，和容器无关 | C 风格 `for` |
| 迭代次数事先不知道，只看条件是否满足 | `while`（本章第 15 节） |

两者在真实代码里都经常出现。**没有"更好的那一个"，只有"更合适的那一个"**——判断依据就一句话：我关心的是元素，还是下标和次数？

## 14 迭代次数已知与未知

前两节的 `for` 循环适合处理一类明确的问题："把这 5 个元素遍历一遍"、"累加 1 到 100"。循环的**次数或范围事先就写在代码里**，看一眼条件就知道要转几圈。

但很多场景里你事先根本不知道要转几圈：

- 从某个外部来源取任务来处理，**队列里还剩多少项要等运行起来才知道**，处理到队列为空为止。
- 读用户输入，读一次判断一次，**用户什么时候选择退出无法预知**。
- 用迭代法求解一个方程，**不知道多少轮才能达到可接受的精度**，只知道"还不够精确就继续算"。

这些问题的共同点是：**只知道"满足什么条件就继续"，不知道"要重复多少次"。** `for` 也能硬写，但把次数写死反而掩盖了真实意图。C++ 为这类需求提供了 `while` 循环，还有一个变体 `do-while`。

## 15 `while` 循环

### 15.1 结构

```cpp
int workItems = 10;

while (workItems > 0)
{
    std::cout << workItems << std::endl;
    --workItems;
}
```

结构只有两部分：`while` 关键字 + 一对小括号里的**条件**，后面接循环体。**没有 for 那样的初始化段和更新段**——因为循环次数未知，也就无法在循环头上把"从哪开始、怎么推进"一次写清楚。

于是这两件事必须自己安排：

| 职责 | for 里写在哪 | while 里写在哪 |
| --- | --- | --- |
| 准备初始状态 | 小括号第一段 | **循环之前**先定义并初始化好变量 |
| 判断能不能继续 | 小括号第二段 | 小括号里（唯一和 for 对应的部分） |
| 让状态向结束推进 | 小括号第三段 | **循环体内部**，通常放在最后 |

### 15.2 条件的检查时机：每轮之前

`while` 在**每一轮迭代开始之前**检查条件：为真就执行循环体，为假就结束循环、跳到循环后面的语句继续执行。

上面那段代码的轨迹：

| 轮次 | 进入前 `workItems` | 条件 `> 0` | 循环体打印 | 体末 `--workItems` 之后 |
| --- | --- | --- | --- | --- |
| 第 1 轮 | 10 | 真 | `10` | 9 |
| 第 2 轮 | 9 | 真 | `9` | 8 |
| … | … | 真 | … | … |
| 第 10 轮 | 1 | 真 | `1` | 0 |
| 结束 | 0 | **假** | —— | —— |

共打印 10 行，从 `10` 递减到 `1`。注意最后那一行是 `1` 而不是 `0`：打印发生在判断之前，`0` 这一轮已经进不来了。

### 15.3 可能一次都不执行

因为条件在**进入循环体之前**检查，所以如果一开始条件就是假，循环体**一次都不会执行**：

```cpp
int workItems = 0;

while (workItems > 0)     // 0 > 0 为假
{
    std::cout << workItems << std::endl;   // 永远不会执行
}
```

这个程序运行起来什么都不打印。这不是 bug，而是 `while` 的正常语义——**"次数可以是 0" 是 while 应有的性质**。在有些场景里这正是你想要的：任务队列本来就是空的，那就什么也不用做。

### 15.4 为什么 `while` 更容易写错

回到刚才那张职责分工表。`for` 把"初始化 / 条件 / 更新"三件事都集中在循环头上，一眼就能看全；`while` 把它们拆到了三个地方，于是有了一个典型的失败模式：**初始化写了、条件写了、循环体里却忘了更新状态**。

```cpp
int workItems = 10;

while (workItems > 0)
{
    std::cout << workItems << std::endl;
    // 这里少了一句 --workItems;
}
```

`workItems` 永远是 10，条件永远为真，程序会一直打印下去，直到被强行终止——这就是**死循环**。本章第 17 节专门讲它。

**写 while 循环时第一件要确认的事：循环体里有没有让条件趋向假的操作。** 没有，就要么补上，要么说明这里本来就该是无限循环。

## 16 `do-while` 循环

### 16.1 结构

```cpp
do
{
    std::cout << workItems << std::endl;
    --workItems;
}
while (workItems > 0);
```

关键字是 `do` 和 `while` 两个：`do` 后面直接接循环体，循环体之后才写 `while (条件)`。

有一个**纯语法上的坑**必须先记住：`while (条件)` 末尾那个**分号不能漏**。因为 `do-while` 的整条结构在这里结束，分号是这条语句的结束标记（对比普通 `while`，它的分号其实属于循环体那条语句，所以看起来像是没有）。

### 16.2 条件的检查时机：每轮之后

`do-while` 与普通 `while` 唯一的区别是**条件的检查时机**：它先执行一轮循环体，**执行完之后**再检查条件，为真就回去再来一轮。

由此得到 `do-while` 最重要的性质：**循环体至少执行一次，一次都不执行是不可能的。**

看一个刻意构造的例子：

```cpp
int workItems = 0;      // 注意：初始就是 0，条件一开始就是假的

do
{
    std::cout << workItems << std::endl;
    --workItems;        // workItems 变成 -1
}
while (workItems > 0);  // 检查 -1 > 0，为假，结束
```

运行结果是**打印一行 `0`**。

如果把它改写成普通 `while`：

```cpp
int workItems = 0;

while (workItems > 0)   // 条件一开始就是假
{
    std::cout << workItems << std::endl;   // 一行都不会打印
}
```

一行都不会输出。**同样的初值、同样的条件，只是循环形式不同，结果就从"打印一行"变成"什么都不打印"。** 这就是两者差别的全部：

| | 条件检查时机 | 最少执行次数 | 适用场景 |
| --- | --- | --- | --- |
| `while` | 每轮**之前** | 0 次 | 先判断、条件不成立就什么都不做 |
| `do-while` | 每轮**之后** | 1 次 | 必须先做一次，再看结果决定要不要继续 |

### 16.3 什么时候必须用 `do-while`

`do-while` 的典型场景是**"先做一次、再判断"**。最经典的是菜单或命令行界面：

程序启动后必须先显示一次菜单、读一次用户输入，然后才谈得上"判断用户是不是选了退出"。如果这一步用普通 `while`，就得把"显示菜单并读输入"的代码在循环外再写一遍——重复一份；而 `do-while` 天然表达了这个意思：**先做一次（显示菜单、读输入），然后检查条件（是否退出），没退出就再来一轮。**

反过来说，如果"一次都不做"是合法甚至更合理的（队列本来就是空的），那就该用 `while`。

## 17 死循环：`while` 特有的风险

**死循环**指循环条件永远为真，程序停不下来。常见的三种成因：

1. **忘了推进状态。** 循环体里没有修改条件涉及的变量（就是本章第 15.4 节那个例子）。
2. **推进的方向错了。** 条件写的是 `workItems > 0`，循环体里却写成 `++workItems`（越来越大），永远到不了 0。
3. **条件本身恒真。** 例如 `while (true)` 或写错了字的常量条件。

**预防办法很简单：写完一个 `while` 或 `do-while`，回头找一下"哪一句会让条件最终变成假"**，确认它存在、方向正确、并且每一轮都会执行到（没有藏在某个 if 分支里）。

另外要说清楚：死循环不总是 bug。有些程序的**主循环本来就要一直跑**（等待事件的服务器、扫描按键的嵌入式程序），那时它会明确写成 `while (true)` 这种一眼能看出意图的形式，而不是因为忘了更新变量而"意外地"停不下来。区别在于**是刻意写的还是漏写的**。

程序真的卡死时怎么退出：在 VS Code 的终端里点终端面板的终止按钮，或在终端里按 `Ctrl+C` 中断当前进程。

### 实验六：让越界错误被抓住

把 `ch06_for_loops\range_for\range_for.cpp` 里的范围 `for` 临时替换成下面这种手写下标、并且**故意写错边界**的版本：

```cpp
for (int i = 0; i <= myArray.size(); ++i)     // 注意 <= 使得最后一轮越界
{
    std::cout << myArray.at(i) << std::endl;  // 用 at() 而不是 []
}
```

这里 `i` 是 `int`，而 `myArray.size()` 返回无符号的 `size_type`，用 `-Wall` 编译这段代码会出现符号比较警告：

```text
warning: comparison of integer expressions of different signedness: 'int' and 'std::array<int, 5>::size_type' {aka 'long long unsigned int'} [-Wsign-compare]
```

本章动手实验要求"`-Wall` 无警告"，这正是它针对的一类问题。正确写法是把计数器类型对齐为 `std::size_t`，即 `for (std::size_t i = 0; i < myArray.size(); ++i)`。本实验只是临时演示，看清 `at()` 抓越界的效果后改回范围 `for` 即可。

**预期现象**：前 5 个元素正常打印，最后一轮 `i` 等于 5 时 `at()` 检测到越界，抛出 `std::out_of_range`，程序立刻中止并打印 `what():  array::at: __n (which is 5) >= _Nm (which is 5)`。

**验收标准**：能指出报错里的 `__n (which is 5)` 就是那个越界下标，并说清它是被 `<=` 制造出来的。看完把代码改回范围 `for`。

> 顺带一句：这个实验里如果把 `at()` 换成 `[]`，程序**不会报错**，可能会打印一个垃圾值、也可能直接崩溃——因为 `[]` 不做边界检查。这就是本章第 4 节推荐默认使用 `at()` 的原因。
