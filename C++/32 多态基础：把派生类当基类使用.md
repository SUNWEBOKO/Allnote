# 32 多态基础：把派生类当基类使用

上一篇：[[31 继承与派生类：复用基类的成员]]
下一篇：[[33 虚函数：运行时的动态绑定]]

## 学习目标

完成本章后，你应当能够：

1. 说出多态在这里的确切含义：把派生类对象当作它的基类来使用。
2. 用基类的引用、指针和函数参数接收不同的派生类对象，并说明这一步为什么不需要任何转换代码。
3. 说出通过基类接口调用成员函数时，编译器在什么时候决定调用哪一个实现，以及这与"直接通过派生类对象调用"有什么不同。
4. 解释为什么 `std::vector<Dog>` 和 `std::vector<Cat>` 无法装在同一处，而 `std::vector<Animal*>` 可以。
5. 说出把派生类对象按值放进基类容器会发生什么，以及这种行为为什么常常不是想要的。

## 1 把不同派生类归为一类

第 31 章用继承解决了"公共成员写两遍"的问题：定义一个基类装公共部分，再让多个派生类从它扩展。但继承还带来一个更有意思的可能：既然这些派生类**都是**同一个基类（狗是一种动物，猫也是一种动物），那么能不能把它们当成同一种东西来处理？

能这样做的好处非常具体。只要"当成同一种东西"成立：

- 同一份代码可以接收任何一种派生类对象，不用为每种派生类各写一份；
- 同一个容器可以装下不同派生类的对象，不用 `std::vector<Dog>`、`std::vector<Cat>` 各管一摊。

这正是**多态**（polymorphism，字面意思是"多种形态"）在继承这个话题下的含义：**把不同类型的对象当作同一种类型看待。** 而本章讲的这一层，具体就是指**把派生类对象当作它的基类来使用**。

## 2 先看不用基类的写法

例程 `E:\CPP_Code\CppFromScratch\ch32_polymorphism\polymorphism_basic\polymorphism_basic.cpp` 用的是最经典的一组类型：

```cpp
struct Animal
{
    void speak()
    {
        std::cout << "default speak!" << std::endl;
    }
};

struct Dog : Animal
{
    void speak()
    {
        std::cout << "woof" << std::endl;
    }
};

struct Cat : Animal
{
    void speak()
    {
        std::cout << "meow" << std::endl;
    }
};
```

两个派生类各自写了一个 `speak()`，名字和参数列表与基类的那个完全相同。直接通过派生类对象调用时，用的当然是各自那一份：

```cpp
Dog d;
Cat c;
d.speak();    // woof
c.speak();    // meow
```

```text
=== Demo A: a Dog and a Cat use their own version of speak ===
woof
meow
=== Demo B: the base class keeps its own version ===
default speak!
```

### 2.1 这里发生的是"隐藏"，不是"重载"

有一个术语必须说准。派生类里写一个与基类同名的函数，**不叫重载**：重载（第 09 章）要求同名函数处在**同一个作用域**里，按参数列表区分；而这里的两个 `speak` 分别在 `Animal` 和 `Dog` 两个作用域里，它们是两个独立的函数。

标准给这件事的说法是**隐藏**（name hiding）：`Dog` 里声明了 `speak` 这个名字之后，**基类里所有同名的函数**在 `Dog` 的作用域里都被这个名字遮住了。既然两份实现都还在，就可以用作用域限定符 `::` 明确指定要调用哪一份：

```text
=== Demo C: Dog::speak hides Animal::speak, it does not replace it ===
woof
default speak!
```

第二行的 `d.Animal::speak();` 调用的就是基类那一份，说明**基类的实现并没有被"改写"或"覆盖"，它只是被遮住了**。这一点在下一章讲虚函数时会变得关键：`virtual` 带来的才是真正的"用派生类的实现替换基类的实现"，而单纯写一个同名函数只是隐藏。

## 3 把派生类对象当基类用

现在进入本章的正题。既然 `Dog` 继承了 `Animal`，那么一个 `Dog` 对象里就含有一份完整的 `Animal` 部分，于是可以这样做：

```cpp
Dog d;
Animal& ref = d;      // 用基类的引用去指派生类对象
```

这一步叫**上转型**（upcast）：把派生类类型的对象转换成基类类型来使用。它有三个特点：

- **不需要写任何转换代码**，编译器自动完成，因为"派生类对象里本来就有一个基类子对象"。
- **不会新建对象，也不会复制数据。**
- **调用成员函数的结果会变。** 明明 `d` 是狗，`ref.speak()` 打印的却是 `default speak!`。

第二条有直接的证据，例程 `E:\CPP_Code\CppFromScratch\ch32_polymorphism\upcast_reference\upcast_reference.cpp` 打印了地址比较：

```text
=== Demo B: the same object, now handled as an Animal ===
the reference points at the same object: true
default speak!
```

地址相同，说明 `ref` 只是 `d` 的另一个名字（第 15 章的引用），这一步没有任何数据被复制。

第三点就是本章的核心现象。原因不在运行时，而在编译期：**编译器只看着 `ref` 的类型（`Animal`）就决定了要调用 `Animal::speak`**，它在乎的是"这个引用是什么类型"，而不是"它实际绑定了哪个对象"。这种"编译期就把函数定下来"的机制叫**静态绑定**，对应的多态叫**静态多态**。

传参时的情形完全一样——形参写成基类的引用，实参可以是任何派生类对象：

```cpp
void speak_as_animal(Animal& animal)   // 形参是基类引用
{
    animal.speak();
}
```

```text
=== Demo C: it looks the same when the object is passed to a function ===
default speak!
```

函数内部的类型是 `Animal`，所以它调用的是 `Animal::speak`，哪怕传进来的是一只狗。**这既是上转型的方便之处（一种形参类型能接收一整族实参），也是它的局限（函数里拿不回派生类的那份实现）。**

`Cat` 那边走的是完全相同的一条路：

```text
=== Demo D: the Cat is upcast in exactly the same way ===
meow
default speak!
```

## 4 把不同派生类放进同一个容器

上转型最实用的价值出现在容器上。`std::vector` 只有一个模板参数，也就是只能有一种元素类型，所以：

```cpp
std::vector<Dog> dogs;    // 只能装狗
std::vector<Cat> cats;    // 只能装猫
```

狗和猫没法混在同一个 `std::vector` 里——这就是"需要归为一类"的动机。而把元素类型换成**指向基类的指针**，问题就解决了：`Dog*` 和 `Cat*` 都能上转型成 `Animal*`。

例程 `E:\CPP_Code\CppFromScratch\ch32_polymorphism\base_pointer_container\base_pointer_container.cpp` 把三种做法摆在一起：

```cpp
std::vector<Animal*> animals;     // 基类指针的容器：两种都能装
animals.push_back(&d);            // 容器里存的是地址，对象本身还在 main 里
animals.push_back(&c);

std::vector<Animal> zoo;          // 直接装基类对象：只能装下"基类那部分"
zoo.push_back(d);
zoo.push_back(c);
```

运行结果：

```text
=== Demo A: one vector holds exactly one element type ===
dogs.size() = 1, the element type is Dog
cats.size() = 1, the element type is Cat
=== Demo B: a vector of base class pointers holds both ===
animals.size() = 2
default speak!
default speak!
=== Demo C: a vector of base class values keeps only the base part ===
zoo.size() = 2
default speak!
default speak!
=== Demo D: the two original objects are untouched ===
woof
meow
```

Demo B 是"凑到一起"成功的样子：两个派生类对象住在同一个容器里，用同一段循环处理。注意容器里存的是**地址**，对象本身没有被复制，所以 `animals` 里的元素和 `main` 里的 `d`、`c` 是同一批对象。

但 Demo B 也把局限暴露得很清楚：**两次 `speak()` 打印的都是基类的默认实现**，尽管容器里明明一只狗、一只猫。原因和第 3 节说的一样：循环变量的类型是 `Animal*`，编译期就定下了 `Animal::speak`。

Demo C 换了一种装法：容器直接装基类对象。这里的 `push_back(d)` 需要把 `Dog` 变成 `Animal`，于是**只把狗身上的基类部分复制进容器，狗特有的那部分被丢掉了**——这个现象叫**对象切片**（object slicing）。本例的两个派生类都没有自己的数据成员，所以丢掉的只是"身份"；如果 `Dog` 带有自己的数据，那些数据在这一步就真没了。

Demo D 是收尾检查：前面几段代码都没有改动 `d` 和 `c`（容器里放的是地址或基类部分的副本），直接用派生类对象调用时，用的仍然是派生类自己的那份实现。

## 5 静态多态做到了什么，没做到什么

把本章的现象整理成一张表：

| 想做的事 | 静态多态（本章）能不能做到 | 说明 |
| --- | --- | --- |
| 用同一种形参类型接收不同派生类对象 | 能 | 形参写成基类的引用或指针即可，上转型自动完成 |
| 用一个容器装下不同派生类 | 能 | 元素类型用基类的指针（或引用包装） |
| 写一份循环处理所有派生类对象 | 能 | 前提是这些处理**只依赖基类的接口** |
| 让"同一个调用"在运行期根据实际对象给出不同行为 | **不能** | 通过基类接口调用到的永远是基类的实现 |
| 通过基类接口间接调用派生类特有的函数 | **不能** | 基类里没有那个名字，调用处就编译不过 |

表格最后两行是这条路的边界。它们不能被"写得更聪明一点"解决，因为**编译期做决定**这件事本身就排除了"看运行时是哪个对象再决定"的可能。

要突破这条边界需要另一种机制：让编译器**不**在编译期把函数定死，而是留到运行时、根据对象的真实类型去选择实现。那就要在基类的函数前加 `virtual`，也就是**虚函数**与**动态多态**——下一章的主题。所以本章的现象（通过基类调用得到基类的实现）不是"写错了"，而是"还没有让这个函数变成虚函数"。

顺带记住两个方向的安全性差别：

- **派生类 → 基类（上转型）：安全，隐式完成。** 派生类对象里确实含有一个完整的基类子对象，这个转换不会丢失信息。
- **基类 → 派生类（下转型）：不安全，需要显式写出来。** 一个 `Animal&` 背后可能是一只猫，也可能是一只狗，编译器无从判断，只能由写代码的人自己保证。

两个**兄弟**派生类之间的指针更是完全不能互转，编译时会直接报错：

```text
error: cannot convert 'Cat*' to 'Dog*' in initialization
```

## 6 动手实验

三个例程都在 `E:\CPP_Code\CppFromScratch\ch32_polymorphism\` 下，各占一个文件夹。

### 6.1 实验一：各自调用与隐藏（`polymorphism_basic`）

`polymorphism_basic\polymorphism_basic.cpp` 里 `Dog`、`Cat` 各自定义了 `speak()`，`main` 里既用派生类对象调用，也用 `d.Animal::speak()` 显式调用基类那一份。

```text
E:\msys64\ucrt64\bin\g++.exe -std=c++20 -Wall -g polymorphism_basic.cpp -o polymorphism_basic.exe
./polymorphism_basic.exe
```

**预期现象**：输出与 2 节的九行逐字符一致。

**验收标准**：`-Wall` 无警告；能说出 `Dog::speak` 与 `Animal::speak` 是两个独立的函数，并解释 `d.Animal::speak();` 为什么能调用到基类那份。

**改值实验**：给 `Animal` 增加一个带参数的版本，然后故意用派生类对象去调用它：

```cpp
struct Animal
{
    void speak() { /* ... */ }
    void speak(int times) { std::cout << "default speak x" << times << std::endl; }
};
```

在 Demo A 后面加上一行 `d.speak(3);`，先判断结果。预期是**编译失败**：

```text
error: no matching function for call to 'Dog::speak(int)'
```

编译器列出的候选只有一个 `void Dog::speak()`。这就是"隐藏"的确切含义：**派生类里声明了同名函数之后，基类里所有同名的重载版本一起被遮住**，不是只遮住参数相同的那一个。想让它们重新可见，需要在派生类里写一句 `using Animal::speak;`。看完把两处改动还原。

### 6.2 实验二：上转型（`upcast_reference`）

`upcast_reference\upcast_reference.cpp` 用基类引用、基类形参两种方式接收派生类对象，并打印地址比较证明"没有新建对象"。

```text
E:\msys64\ucrt64\bin\g++.exe -std=c++20 -Wall -g upcast_reference.cpp -o upcast_reference.exe
./upcast_reference.exe
```

**预期现象**：完整输出如下，共十行（地址比较为 `true`，两次通过基类调用都是 `default speak!`）：

```text
=== Demo A: the Dog uses its own version ===
woof
=== Demo B: the same object, now handled as an Animal ===
the reference points at the same object: true
default speak!
=== Demo C: it looks the same when the object is passed to a function ===
default speak!
=== Demo D: the Cat is upcast in exactly the same way ===
meow
default speak!
```

**验收标准**：`-Wall` 无警告；能说出 `(&ref == &d)` 是 `true` 说明了什么（上转型不复制对象）；能解释为什么经过 `Animal&` 调用就得不到 `woof`。

**改值实验**：把 Demo B 里的引用换成按值复制，再把地址比较换成新对象：

```cpp
Animal copy = d;                  // 按值复制：只复制基类部分
std::cout << "the reference points at the same object: "
          << std::boolalpha << (&copy == &d) << std::endl;
copy.speak();
```

先判断结果。预期是那一行变成 `false`（这次真的新建了一个对象），而下一行仍然是 `default speak!`。**对照着看这两行就能分清两件事**：`false` 说明按值接收会复制、会发生对象切片；`default speak!` 则说明"通过基类接口调用只能得到基类的实现"和复不复制无关——就算一个字节都不复制（上一节的引用），结果也一样。改完编译运行核对，然后还原。

### 6.3 实验三：容器里的多态（`base_pointer_container`）

`base_pointer_container\base_pointer_container.cpp` 对比"基类指针的容器"与"基类对象的容器"。

```text
E:\msys64\ucrt64\bin\g++.exe -std=c++20 -Wall -g base_pointer_container.cpp -o base_pointer_container.exe
./base_pointer_container.exe
```

**预期现象**：输出与 4 节的十四行逐字符一致（Demo B 与 Demo C 各两行 `default speak!`，Demo D 仍是 `woof`、`meow`）。

**验收标准**：`-Wall` 无警告；能说出 Demo B 与 Demo C 的输出为什么一模一样（两种装法都只能拿回基类的实现，区别在于容器里存的是地址还是副本）；能说出对象切片发生在 Demo C 的哪一行。

**改值实验**：把 Demo B 里的 `animals.push_back(&c);` 删掉，先判断输出。预期 `animals.size()` 变成 `1`，随后的循环只剩一行 `default speak!`；Demo C、D 完全不受影响——因为 `zoo` 装的是两个独立的基类副本，和 `animals` 里存谁的地址无关。

**边界实验**：给 `Dog` 加一个只属于它的成员函数（例如 `void fetch() { }`），再把 Demo B 循环里的 `animal->speak();` 改成 `animal->fetch();`，先判断结果。预期是**编译失败**：

```text
error: 'struct Animal' has no member named 'fetch'
```

循环变量的类型是 `Animal*`，编译器只能在 `Animal` 的成员里找这个名字，而它不存在。这正是第 5 节表格里"不能通过基类接口间接调用派生类特有函数"那一行的具体形态，也是下一章虚函数要解决的问题——注意虚函数能解决的只是"同一个名字给出不同实现"，**名字必须先在基类里存在**这一条永远成立。看完还原。

## 7 常见错误与排查

| 报错或现象 | 原因 | 处理 |
| --- | --- | --- |
| 明明装进去的是 `Dog`，通过基类的引用或指针调用却打印基类的实现 | 这个函数不是虚函数，编译器按引用/指针的静态类型在编译期就定下了调用哪一个 | 这是静态多态的预期行为；需要按实际对象决定时把基类的该函数声明为 `virtual`（第 33 章） |
| `error: no matching function for call to 'Dog::speak(int)'`（候选只有 `void Dog::speak()`） | 派生类里的同名函数把基类的**所有**同名重载一起隐藏了 | 在派生类里写 `using Animal::speak;` 让基类的重载重新可见，或换一个函数名 |
| `error: cannot convert 'Cat*' to 'Dog*' in initialization` | 两个派生类互为兄弟，即使继承同一个基类也不能互相转换 | 用共同基类的指针（`Animal*`）统一处理；确实要下转型必须显式写出来，并自己保证对象的真实类型 |
| `std::vector<Animal>` 装进派生类对象后，派生类特有的数据不见了 | 按值装进基类容器会发生对象切片，只复制了基类部分 | 容器元素类型用基类指针（或引用包装）而不是基类对象；存指针时注意对象的生命周期要长于容器 |
| 想让一个函数同时接收 `Dog` 和 `Cat`，于是写了两份重载 | 没有用上"它们都是 `Animal`"这个事实 | 形参写成基类的引用（`Animal&`）或指针，一份函数即可接收整族派生类型 |
| 通过基类指针 `delete` 派生类对象，派生类析构函数没有执行 | 基类析构函数不是虚函数，`delete` 只按指针的静态类型析构 | 基类析构函数声明为虚函数（第 33 章讲虚函数时一并补上） |
| `error: 'base' is an inaccessible base of 'derived'` | 派生类用的是私有继承（`class` 默认如此），上转型在类外不允许 | 把继承方式改成 `public`（第 31 章 5 节） |
