## 1 重复的工作交给循环

第 05 章把一组数据放进了数组，但访问元素还是手写下标：`myArray.at(0)`、`myArray.at(1)`、`myArray.at(2)`。元素一多，这种写法就没法用了——365 个温度值，你不可能手写 365 行。

程序里"把同一件事重复做若干遍"的需求到处都是：重复累加一批数字、把一批数据逐个输出、对矩阵的每一行和每一列做同一套运算（矩阵乘法就是一个典型：用循环遍历行和列，把元素相乘并累加中间结果）。**这类问题的共同解法是把重复的部分交给循环**，让程序自己一轮一轮地执行，每次只处理当前这一轮该处理的那一小块。

`for` 循环是其中最常用的一种，本章讲它的两种形式：从 C 语言继承来的 **C 风格 `for`**，以及 C++ 提供的 **范围 `for`**（range-based for）。

## 2 C 风格 `for`：把循环的三件事写在一行

### 2.1 结构

```cpp
for (int i = 0; i < 5; ++i)
{
    std::cout << "Iteration: " << i << std::endl;
}
```

`for` 后面的小括号里有三段，用**两个分号**隔开，顺序固定：**初始化; 条件; 更新**。

| 位置 | 这一段的代码 | 作用 | 执行时机 |
| --- | --- | --- | --- |
| 第一段 | `int i = 0` | 准备循环计数器 `i`，作为"现在数到第几个了"的记录 | 只在进入循环**之前**执行一次 |
| 第二段 | `i < 5` | 继续循环的条件，决定还能不能再转一圈 | 每轮迭代**开始之前**检查一次 |
| 第三段 | `++i` | 把计数器往前推一格 | 每轮迭代**结束之后**执行 |

花括号里是要重复执行的**循环体**——可以是一条语句，也可以是一整段代码。

### 2.2 执行顺序：走一遍完整的轨迹

把上面的代码在脑子里跑一遍，轨迹是这样的：

| 轮次 | 检查条件前 `i` 的值 | 条件 `i < 5` | 循环体打印 | 循环体后 `++i` |
| --- | --- | --- | --- | --- |
| 第 1 轮 | 0 | 真 | `Iteration: 0` | `i` 变成 1 |
| 第 2 轮 | 1 | 真 | `Iteration: 1` | `i` 变成 2 |
| 第 3 轮 | 2 | 真 | `Iteration: 2` | `i` 变成 3 |
| 第 4 轮 | 3 | 真 | `Iteration: 3` | `i` 变成 4 |
| 第 5 轮 | 4 | 真 | `Iteration: 4` | `i` 变成 5 |
| 循环结束 | 5 | **假** | —— | —— |

有两条规律值得记住：

- **更新表达式在循环体的最后执行**，所以循环体第 5 轮里 `i` 还是 4，打印完才变成 5。
- **正是那个让条件变成假的 5，终止了循环**。所以循环结束后 `i` 的值是 5，而不是 4。

### 2.3 想让循环跑几次，看条件怎么写

"跑 5 次"对应的是 `i < 5`，因为 `i` 取值 0、1、2、3、4 时条件成立，共 5 个值。写成 `i <= 5` 就会跑到 `i = 5` 那一轮，变成 6 次——这就是后面要讲的**差一错误**（off-by-one）。**默念一遍"从 0 开始、小于上限"，比事后排查省事得多。**

### 2.4 三部分都是可以改的

上面是最常见的写法，不是唯一写法：

```cpp
for (int i = 5; i > 0; --i)       // 从大往小倒数
for (int i = 0; i < 10; i += 2)   // 步长是 2，只处理偶数下标
```

只要能表达清楚"从哪开始、做到什么时候、每轮怎么推进"就行。三个部分甚至可以都省略（`for (;;)`），此时条件恒为真，就是一个死循环——只在你确实需要无限循环时才这么写。

### 2.5 循环变量的作用域

`i` 这个名字只在小括号和花括号之内有效，出了循环再用它编译会报错。这个限制是好事：它防止你在循环结束后误用一个已经"过期"的计数器（那个值通常也不是你想要的）。

命名的习惯用法是短名字：`i` 用于最外层、`j` 用于第二层、`k` 用于第三层；再深的层次就要用有意义的名字了，因为 `i`、`j`、`k` 太多也容易看混。

## 3 `++i` 与 `i++`

第三段里写的是 `++i`，第 03 章里你可能见过写作 `i++`。两者都表示"把 `i` 加 1"，差别在**自增发生的时刻**：

- `++i`（前置）：先把 `i` 加 1，然后用新的值参与外围运算。
- `i++`（后置）：先用 `i` 当前的值参与外围运算，然后再把它加 1。

单看结果：

```cpp
int a = 5;
int b = a++;    // b 得到 5（先取值），a 变成 6
int c = ++a;    // a 先变成 7，c 得到 7
```

**但是**：当 `++i` / `i++` 单独作为一条语句使用时（就像 for 循环第三段那样），没人关心"用了哪个值"，两者效果完全相同。所以本课程在 for 循环里统一写 `++i`——它不是必须的，只是一个明确的习惯。真正需要分辨前置和后置的场合，是它们的结果被拿去参与别的运算时。

## 4 范围 `for`：直接遍历容器

### 4.1 语法

```cpp
std::array<int, 5> myArray {4, 2, 12, 63, 13};

for (int value : myArray)
{
    std::cout << value << std::endl;
}
```

结构是 `for (元素类型 变量名 : 要遍历的容器) { 循环体 }`。冒号左边是每一轮从容器里取出来的元素，右边是要遍历的范围。每一轮都会取下一个元素、用它初始化 `value`，然后执行循环体——所以循环体里直接写 `value` 就行，**不需要下标，也不需要计数器**。

### 4.2 它为什么更安全

范围 `for` 最大的好处是**你根本没有机会写错下标**：

- 循环次数由容器决定，**容器自己知道有多少元素**（第 05 章的 `size()` 就是这件事的体现），不用你手写长度。
- 没有下标这个中间量，也就没有"多跑一轮"或"少跑一轮"的可能。

而下标越界恰恰是手写循环最常见的错误：长度是 5 却写了 `i <= 5`、长度后来改成 8 却忘了同步循环条件里的 `5`——这两种都会让程序去访问不存在的元素。用范围 `for` 时，这类错误从源头上不会出现。

### 4.3 与 C 风格循环的对照

上面那段范围 `for` 用 C 风格循环写出来是这样：

```cpp
for (int i = 0; i < 5; ++i)
{
    std::cout << myArray[i] << std::endl;
}
```

多出来的东西一眼可见：一个计数器 `i`、一次结束判断、一次自增，还有 `myArray[i]` 这次按下标取值。其中那个 `5` 是手写死的长度——它和数组的真实长度之间**没有任何机制保证一致**，改动一处忘了另一处就出错。范围 `for` 里没有这个数字。

所以范围 `for` 也属于第 03 章说过的**语法糖**：它和 C 风格循环做的是同一件事，但不需要你承担手写计数器的劳动和风险，代码的意图也更清楚——"遍历这个容器里的所有值"。

### 4.4 `value` 是元素的副本

`for (int value : myArray)` 里的 `value` 每一轮拿到的是元素的一份**副本**。所以在循环体里修改 `value`（例如 `value = 0;`）**不会改变数组本身**，`myArray` 里原来的值原封不动。读一读、打印一下完全没有副作用，本章和下一章的例子里都只做读取。

想通过范围 `for` 修改容器里的元素，需要换一种写法（用引用），那是后续课程的内容。

## 5 两种 `for` 怎么选

| 需求 | 选择 |
| --- | --- |
| 遍历整个容器里的每一个元素 | 范围 `for` |
| 需要用到下标本身（打印序号、访问另一个容器的对应位置、只处理部分元素） | C 风格 `for` |
| 循环次数在写代码时就确定，和容器无关 | C 风格 `for` |
| 迭代次数事先不知道，只看条件是否满足 | `while`（下一章） |

两者在真实代码里都经常出现。**没有"更好的那一个"，只有"更合适的那一个"**——判断依据就一句话：我关心的是元素，还是下标和次数？

## 6 动手实验

例程在 `E:\CPP_Code\CppFromScratch\ch06_for_loops\` 下，两个程序各占一个文件夹。

### 6.1 实验一：C 风格循环的迭代轨迹

`ch06_for_loops\for\for.cpp` 里的循环是 `for (int i = 0; i < 5; ++i)`，循环体打印 `Iteration: ` 和当前的 `i`。

**操作与预期现象**：

```text
E:\msys64\ucrt64\bin\g++.exe -std=c++17 -Wall -g for.cpp -o for.exe
./for.exe
```

输出五行：

```text
Iteration: 0
Iteration: 1
Iteration: 2
Iteration: 3
Iteration: 4
```

**验收标准**：输出正好五行（不是四行也不是六行），且从 `0` 开始、到 `4` 结束。把条件改成 `i <= 5` 再编译运行，应变成六行且最后一行是 `Iteration: 5`——亲手确认一次差一错误的后果，然后改回 `i < 5`。

### 6.2 实验二：范围 `for` 遍历数组

`ch06_for_loops\range_for\range_for.cpp` 里的数组是 `std::array<int, 5> myArray {4, 2, 12, 63, 13};`。

**预期现象**：输出五行，每行一个元素的值：

```text
4
2
12
63
13
```

**验收标准**：输出的元素个数和顺序与数组声明里的初值完全一致。接着把数组声明里的元素个数从 `5` 改成 `8` 并补上三个初值，**循环一行都不用改**，重新编译后输出会自动变成八行——这正是范围 `for` 不依赖手写长度的直接证据。看完改回原样。

### 6.3 实验三：让越界错误被抓住

把 `ch06_for_loops\range_for\range_for.cpp` 里的范围 `for` 临时替换成下面这种手写下标、并且**故意写错边界**的版本：

```cpp
for (int i = 0; i <= myArray.size(); ++i)     // 注意 <= 使得最后一轮越界
{
    std::cout << myArray.at(i) << std::endl;  // 用 at() 而不是 []
}
```

**预期现象**：前 5 个元素正常打印，最后一轮 `i` 等于 5 时 `at()` 检测到越界，抛出 `std::out_of_range`，程序立刻中止并打印 `what():  array::at: __n (which is 5) >= _Nm (which is 5)`。

**验收标准**：能指出报错里的 `__n (which is 5)` 就是那个越界下标，并说清它是被 `<=` 制造出来的。看完把代码改回范围 `for`。

> 顺带一句：这个实验里如果把 `at()` 换成 `[]`，程序**不会报错**，可能会打印一个垃圾值、也可能直接崩溃——因为 `[]` 不做边界检查。这就是第 05 章推荐默认使用 `at()` 的原因。

## 7 常见错误与排查

| 报错或现象 | 原因 | 处理 |
| --- | --- | --- |
| 循环多跑一轮，访问了不存在的元素 | 差一错误，把 `i < n` 写成 `i <= n` | 改成 `<`；遍历容器时优先用范围 `for` |
| `error: expected ';' before '<' token` | for 小括号里用逗号代替了分号 | 三段之间的分隔符必须是分号，报错里那个 `<` 就是紧跟在第一个逗号后面的内容 |
| `error: 'i' was not declared in this scope` | 在循环之外使用了循环变量 | `i` 只在小括号和花括号内有效；需要在外面用就先在循环外定义 |
| 程序长时间不结束 | 更新表达式漏写或写错，`i` 不变导致条件永远为真 | 检查第三段是否真的改变了条件涉及的量 |
| 循环次数和预期不符 | 循环体里另外修改了 `i` | 不要在循环体内改循环变量，让迭代次数只由 for 的三段决定 |
| 在范围 `for` 里改了 `value`，数组却没变 | `value` 是元素的副本，改它不影响容器 | 本章只读遍历；需要修改元素的写法见后续章节 |
| 循环体一条都没执行 | 初始化后条件立刻为假（例如 `i = 10` 却写 `i < 5`） | 检查初值和条件是否匹配 |
| 只执行了一次就结束 | for 行末多写了分号，如 `for (...);` | 删掉多余分号：它会变成"空循环体"，后面的花括号块成了只执行一次的普通代码块 |
