## 学习目标

完成本章后，你应当能够：

1. 说出复制一个对象在什么情况下代价很高，以及有些对象为什么根本不允许复制。
2. 用 `&` 声明一个引用，并说明它是已有对象的别名，而不是新变量。
3. 通过引用改动原对象，并说出这与"改动副本"的区别。
4. 说出引用的两条使用规则：定义时必须绑定、绑定之后不能改绑。
5. 用取地址运算符 `&` 判断两个名字是不是同一块内存。

## 1 复制并不总是免费的

第 08 章给函数定下的传参规则是**按值传递**：调用时把实参复制给形参。当时我们只讨论了一个后果——函数里改动形参不影响外面。现在看另一个后果：**这份复制本身是有开销的**。

复制一个 `int` 几乎不花钱：它只有 4 个字节。但复制一个有 10000 个整数的 `std::vector<int>` 完全是另一回事——它要在自由存储区**另外申请**一块 40 KB 的内存，然后把 10000 个元素**逐个拷贝**过去。如果这个复制只是为了让函数打印几行内容，那这笔钱花得毫无意义。

更麻烦的是，有些对象**根本不允许复制**。最典型的例子是"锁"：一个互斥锁代表某个资源的独占使用权，它的语义就是"同一时刻只能有一个持有者"。如果允许随意复制一把锁，就会出现两把锁各自都认为自己独占着同一个资源，这没有任何意义。这类对象在 C++ 里会被定义成"不可复制"的类型，你甚至写不出复制它的代码。

所以需要一种机制：**让另一个名字代表同一个对象，而不产生新对象、不发生复制**。这就是**引用**。

## 2 引用就是别名

声明引用的写法是在类型后面加一个 `&`：

```cpp
int a = 5;
int& b = a;     // b 是 a 的引用
```

`int&` 读作"`int` 的引用"。`int& b = a;` 的含义**不是**"把 a 的值复制给 b"，而是：

> b 从此刻起成为 a 的另一个名字。

换句话说，`a` 和 `b` 指的是**同一块内存**，同一个整数。没有第二块内存被申请，没有值被复制。目标是"给已经存在的对象或函数再取一个名字"——一个字面意思上的别名。

据此可以立即推出它的行为：**对 `b` 做的任何改动就是"对 a 的改动"**，因为那本来就是同一个对象。

引用有两条必须记住的规则：

1. **定义引用时必须立刻绑定。** `int& r;` 是编译错误：别名必须指着某个真实存在的对象，凭空一个"没有对象可指"的名字没有意义。
2. **绑定之后不能改绑。** 一旦写定 `int& b = a;`，b 就永远是 a 的别名。后面再写 `b = c;` 也不是"让 b 改成指 c"，而是"把 c 的值写进 a"（第 5 节会专门演示这个坑）。这一点是引用与指针最本质的区别：引用只负责"起名字"，不负责"换目标"。

顺带说清一个容易混淆的地方：`&` 这个符号有两种用途，看它出现在哪儿就能分清。

| 出现位置 | 名称 | 含义 | 例子 |
| --- | --- | --- | --- |
| 类型里 | 引用声明符 | 声明一个别名 | `int& b = a;` |
| 表达式里 | 取地址运算符 | 求这个对象的内存地址 | `&a` |

## 3 复制与别名：第一次对比

例程 `E:\CPP_Code\CppFromScratch\ch15_references\ref_copy_vs_alias\ref_copy_vs_alias.cpp` 把两种情况并排放：

```cpp
#include <iostream>

int main()
{
    std::cout << "=== A: a separate variable copies ===" << std::endl;

    int a = 5;
    int b = a;
    b += 1;

    std::cout << "a = " << a << ", b = " << b << std::endl;

    std::cout << "=== B: a reference is an alias ===" << std::endl;

    int c = 5;
    int& d = c;
    d += 1;

    std::cout << "c = " << c << ", d = " << d << std::endl;

    return 0;
}
```

输出：

```text
=== A: a separate variable copies ===
a = 5, b = 6
=== B: a reference is an alias ===
c = 6, d = 6
```

两段的差别只在一个字符（`int b = a;` 与 `int& d = c;`），结果却完全不同：

- A 段里 `int b = a;` 申请了第二块内存，把 5 复制过去；`b += 1` 改的是 b 那一块，所以 a 仍然是 5、b 变成 6。
- B 段里 `int& d = c;` 没有申请任何新内存，d 就是 c；`d += 1` 改的是它们共用的那一块，所以打印出来两个名字的值一起变成 6。

这也解释了为什么引用**不能是空的**：它一出生就必须绑在某个对象上。而"某个对象"必须在这一刻真实存在——你没法给一个还不存在的东西起别名。

## 4 用地址确认"同一块内存"

上面的话听起来还是有点抽象。想要拿到确凿证据，可以直接看这两个名字对应的内存地址：**如果地址完全相同，就说明只有一块内存。**

例程 `E:\CPP_Code\CppFromScratch\ch15_references\ref_address\ref_address.cpp`：

```cpp
#include <iostream>

int main()
{
    std::cout << std::boolalpha;  // 让 bool 打印成 true / false，而不是 1 / 0

    int a = 5;
    int b = a;      // 新变量：另有一块内存
    int& c = a;     // 引用：不新开内存，c 就是 a

    std::cout << "=== compare addresses ===" << std::endl;

    std::cout << "&b == &a : " << (&b == &a) << std::endl;
    std::cout << "&c == &a : " << (&c == &a) << std::endl;
    std::cout << "&c == &b : " << (&c == &b) << std::endl;

    return 0;
}
```

输出：

```text
=== compare addresses ===
&b == &a : false
&c == &a : true
&c == &b : false
```

三个结果正好把三件事说清楚：

- `&b == &a` 是 `false`：b 是一个**独立的变量**，地址和 a 不同（a 和 b 各占 4 个字节，两块内存相邻）。
- `&c == &a` 是 `true`：c 是**引用**，它和 a 是同一块内存，地址当然相同。
- `&c == &b` 是 `false`：c 绑定的是 a，和 b 没有关系。

**为什么不直接把地址打印出来看？** 因为地址的具体数值每次运行、每台机器上都不一样（和操作系统怎么给程序分配内存有关），打印出来没法核对。而"两个地址是否相等"是每次运行都稳定的结果，正好可以当作验证条件——这也是本课程里比较内存地址时的通用做法。

需要说明的是：取地址运算符、以及"地址"这个概念本身的完整用法属于第 17 章（指针）的内容。这里只是借用 `&` 来验证一件事——**引用没有新开内存**。

## 5 r = b 不是改绑

引用最容易被误读的一行，是给引用赋值的时候。例程 `E:\CPP_Code\CppFromScratch\ch15_references\ref_no_rebind\ref_no_rebind.cpp`：

```cpp
#include <iostream>

int main()
{
    std::cout << std::boolalpha;

    int a = 1;
    int b = 2;

    int& r = a;

    r = b;

    std::cout << "a = " << a << ", b = " << b << ", r = " << r << std::endl;

    std::cout << "&r == &a : " << (&r == &a) << std::endl;
    std::cout << "&r == &b : " << (&r == &b) << std::endl;

    return 0;
}
```

输出：

```text
a = 2, b = 2, r = 2
&r == &a : true
&r == &b : false
```

看到 `r = b;` 这一行，直觉容易读成"让 r 以后指 b"。但引用**不能改绑**，所以这一行的真实含义是：**把 b 的值（2）写进 r 所指的那块内存**，而 r 指的仍然是 a。结果就是 a 被改成了 2，b 自己没变，而 r 读到 2 只是因为它和 a 是同一个对象。地址比较给出了佐证：`&r == &a` 仍然是 `true`，`&r == &b` 仍然是 `false`。

这个坑的实用结论是：**看到一个引用，就要顺着它当初绑定的那个对象去理解**，不要被后面出现的赋值语句带偏。如果想表达"这个名字先后指向不同的对象"，要用的不是引用，而是**指针**——指针可以被重新赋值、改指向别的对象，第 17 章讲。

## 6 动手实验

### 6.1 实验一：复制还是别名

源码 `ref_copy_vs_alias\ref_copy_vs_alias.cpp`。

**预期输出**：

```text
=== A: a separate variable copies ===

=== B: a reference is an alias ===
c = 6, d = 6
```

**验收标准**：四行输出逐字符一致。能指着 `int b = a;` 和 `int& d = c;` 说出这两行各自的后果，并解释为什么 A 段打印出 5 和 6，B 段打印出两个 6。

**改值实验**：把 B 段的 `int& d = c;` 改成 `int d = c;`（只去掉一个 `&`），**先预测输出**再编译运行。预测的要点是：d 变成了新变量，`d += 1` 只改自己，所以 c 保持 5、d 变成 6。核对之后把 `&` 加回去。

### 6.2 实验二：地址比对

源码 `ref_address\ref_address.cpp`。

**预期输出**：

```text
=== compare addresses ===
&b == &a : false
&c == &a : true
&c == &b : false
```

**验收标准**：三行输出逐字符一致。能说出 `false`、`true`、`false` 分别对应"独立变量""引用""没有关系"这三种情况。

**改值实验**：在 `main` 末尾加一句 `int& e = b;`，再输出 `&e == &b` 和 `&e == &a`。预测：e 绑的是 b，所以第一项 `true`、第二项 `false`（b 和 a 本来就是两块内存）。运行核对后删掉这个实验变量。

### 6.3 实验三：赋值不等于改绑

源码 `ref_no_rebind\ref_no_rebind.cpp`。

**预期输出**：

```text
a = 2, b = 2, r = 2
&r == &a : true
&r == &b : false
```

**验收标准**：三行输出逐字符一致；能说清 `r = b;` 这一行到底改了谁，以及为什么 `a` 变成了 2。

**改值实验**：把 `int& r = a;` 改成 `int& r = b;`（初始改为绑定 b），其余不动。**先预测再运行**：`r = b;` 这一句变成了"把 b 的值写进 b"，什么也没改变，于是 a 还是 1、b 还是 2、r 也是 2；地址比较变成 `&r == &a : false`、`&r == &b : true`。核对后改回 `int& r = a;`。

## 7 常见错误与排查

| 报错或现象 | 原因 | 处理 |
| --- | --- | --- |
| `error: 'r' declared as reference but not initialized` | 写了 `int& r;`，引用必须绑定到某个对象，不能先声明后绑定 | 定义时就绑定：`int& r = a;` |
| `error: cannot bind non-const lvalue reference of type 'int&' to an rvalue of type 'int'` | 想给非 `const` 引用绑定一个字面量（如 `int& r = 5;`），字面量没有可改的内存 | 真需要一个临时对象时写成 `const int& r = 5;`（第 16 章讲），否则绑定到一个变量上 |
| `error: cannot bind non-const lvalue reference of type 'int&' to a value of type 'double'` | 引用的类型与被引用对象的类型不一致（这里 `double` 要先转换成 `int`，转换出的临时值绑不上非 `const` 引用） | 让引用类型与被绑定对象的类型完全一致 |
| `error: cannot declare reference to 'int&', which is not a typedef or a template type argument` | 写成 `int& & c = b;`，想给引用再加一个引用 | 不需要再套一层：`int& c = b;` 就已经是别名了 |
| 写了 `int b = a;` 却发现改 b 影响不到 a | 少写了 `&`，这里是复制而不是引用 | 确实要别名就写 `int& b = a;`；如果本来就想复制，那是正确行为 |
| 写 `r = b;` 以为能让 r 改指 b，结果 a 被改掉了 | 引用不能改绑，`r = b` 是"把 b 的值写进 r 所指的对象" | 顺着引用初始绑定的对象去理解它；需要改指向时用指针（第 17 章） |
| 引用仍然能编译，但指向的对象已经不存在，程序行为异常 | 被引用的对象先被销毁了（例如引用绑定到某个已经离开作用域的对象），此时引用变成悬垂引用 | 确认被引用对象的生命周期覆盖引用的整个使用期；不要返回指向局部变量的引用 |
| 打印出来的地址和书上、和别人机器上的地址不一样 | 地址的具体数值取决于运行时内存布局，每次运行都可能不同 | 只比较地址是否相等，不要依赖具体数值 |
