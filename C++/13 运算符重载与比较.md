## 1 编译器不认识"两个点相加"

前面几章我们一直在做一件事：用结构体和类定义自己的类型（第 11 章），再给它配上构造函数和析构函数（第 12 章）。有了这些，类型的"出生"和"死亡"都安排好了，剩下的问题是**日常使用**。

而日常使用里最顺手的东西是运算符。第 12 章的 `point` 已经被验证过：`p2 = p1;` 能用、按值传参能用，因为那些行为编译器能推导出来（隐式拷贝构造就是逐成员复制）。但如果你写：

```cpp
point p1(10, 20);
point p2(30, 40);
point p3 = p1 + p2;
```

会直接报错：

```text
error: no match for 'operator+' (operand types are 'point' and 'point')
```

原因很直白：**`+` 对 `int`、`double` 这些内置类型有明确定义，但那套定义完全建立在"数字"这个概念上。编译器不知道 `point` 的"相加"应该是两个坐标分别相加，还是取中点，还是别的什么。** 这个含义必须由定义类型的人写出来。

C++ 给出的办法是**运算符重载**（operator overloading）：把运算符也当成一个可以自己实现的函数。你去实现它，编译器以后看到这个运算符作用在你的类型上，就调用你写的那份实现。

## 2 给运算符写一个函数

例程 `E:\CPP_Code\CppFromScratch\ch27_operator_overloading\operator_plus\operator_plus.cpp` 里的实现：

```cpp
struct point
{
    int x;
    int y;

    point(int new_x, int new_y) : x(new_x), y(new_y) { }

    void print()
    {
        std::cout << "x = " << x << ", y = " << y << std::endl;
    }

    point operator+(const point& rhs)
    {
        return point(x + rhs.x, y + rhs.y);
    }
};
```

除名字之外，它就是一个普通的成员函数。下面把每一处选择讲清楚。

### 2.1 名字：`operator` 加运算符

运算符函数的命名规则是固定的：**关键字 `operator` 后面紧跟要重载的运算符**。重载 `+` 就写成 `operator+`，重载 `+=` 就写成 `operator+=`。这是编译器识别"这是一份运算符实现"的唯一记号，没有别的写法，也不能自己造新符号——把 `+` 换成 `**` 之类的写法会直接报错：

```text
error: declaration of 'operator*' as non-function
```

### 2.2 返回类型：两个点相加，得到一个新点

`operator+` 的返回类型是 `point`。理由是语义决定的：**`+` 不改变任何一个操作数，只是算出一个新的值。** 这和 `int` 的加法一致：`a + b` 算完之后 `a` 和 `b` 都没变，只是多了一个结果。既然结果是"一个新的 `point`"，返回类型就写 `point`。

返回值这一点还直接决定了链式写法能不能用：

```cpp
point p4 = p1 + p2 + p3;
```

`+` 是从左往右结合的，所以先算 `p1 + p2`，得到一个临时的 `point`；再拿这个临时点去加 `p3`。**如果 `operator+` 返回 `void`，右边这次相加就没有一个"新点"可用了。** 返回一个新的 `point` 值，是让 `+` 具备"可以连续相加"这一性质的前提。

### 2.3 参数：`const point& rhs`

参数列表里只有一个参数，写法和第 12 章的拷贝构造函数同一套逻辑：

- **用引用**，避免复制整个对象（第 08 章）。加法只是读两个坐标，把右侧操作数整个复制一份毫无必要。
- **加 `const`**，因为加法不会修改右侧操作数。`const` 把"只读"这件事写进类型，编译期就能拦住误写。

参数名用的是 `rhs`。它是 right-hand side（右侧操作数）的缩写：在 `p1 + p2` 里，`p1` 是左操作数，`p2` 从运算符右边传进来，就是这里的 `rhs`。函数体里：

- `x`、`y` 是**当前对象**（也就是左操作数 `p1`）的成员，成员函数里可以直接用名字访问，不需要写任何前缀；
- `rhs.x`、`rhs.y` 是**右操作数**的成员，必须通过参数名访问。

所以 `point(x + rhs.x, y + rhs.y)` 这行就是"左 x 加右 x、左 y 加右 y，用两个结果构造一个新点"。例程里 `p1(10, 20)` 与 `p2(30, 40)` 相加得到 `x = 40, y = 60`。

### 2.4 `p1 + p2` 实际调用的是 `p1.operator+(p2)`

这是理解成员形式的运算符最关键的一点。下面两种写法**完全等价**：

```cpp
point p3 = p1 + p2;
point p3 = p1.operator+(p2);      // 编译器背后真正生成的调用
```

由此可以推出三条结论：

1. **左操作数是调用者。** `p1 + p2` 里，`p1` 调用自己的 `operator+`，`p2` 作为实参传入。这就是为什么函数体里能直接用 `x`、`y`——它们就是 `p1` 的成员。
2. **左侧必须是本类型的对象。** 写成 `10 + p1` 会报：

   ```text
   error: no match for 'operator*' (operand types are 'int' and 'point')
   ```

   （以 `*` 为例；换回 `+` 也是同样的形状。）原因是 `10` 是 `int`，它没有名为 `operator+` 的成员函数可以接收 `point`。把运算符写成非成员函数可以解决这类"左操作数不是本类型"的情况，本章只用成员形式。
3. **参数个数只能是 0 或 1。** 成员形式的运算符，左操作数已经由调用者占掉了，所以二元运算符只能带 1 个参数、一元运算符只能带 0 个参数。写成两个参数会报：

   ```text
   error: 'point point::operator+(const point&, const point&)' must have either zero or one argument
   ```

## 3 就地修改的运算符：`operator+=`

并非所有运算符都产出新值。`+=` 的语义是**修改左边的对象**，例程 `E:\CPP_Code\CppFromScratch\ch27_operator_overloading\operator_plus_equal\operator_plus_equal.cpp` 里实现了它：

```cpp
point& operator+=(const point& rhs)
{
    x += rhs.x;
    y += rhs.y;
    return *this;
}
```

### 3.1 `p1 += p2` 该做什么

在心里把 `p1 += p2` 展开成 `p1 = p1 + p2`，就能看清它要完成的事：**用相加的结果替换掉 `p1` 原来的值**。但它和 `p1 = p1 + p2` 有一个实现上的区别——不必真的构造一个新点再覆盖回去，直接就地累加更直接，例程里用的就是后一种：

```cpp
x += rhs.x;
y += rhs.y;
```

这里的 `x += rhs.x` 是 `x = x + rhs.x` 的简写（第 04 章讲过这种复合赋值形式）：当前对象的 `x` 变大，`rhs` 的成员只被读取。例程中 `p1(10, 20)` 执行 `p1 += p2`（`p2` 为 `30, 40`）之后变成 `x = 40, y = 60`，而 `p2` 一点没变。

### 3.2 返回类型是引用，靠 `*this`

`operator+=` 的返回类型是 `point&`——**返回被修改的对象的引用**。这个选择有两个理由：

- **语义上**：`p1 += p2` 的结果就是 `p1` 本身。既然对象没有被复制，就不该返回一个副本。
- **实用上**：返回引用才能连着写：

  ```cpp
  (p1 += p3) += p3;
  ```

  先算 `p1 += p3`，得到 `p1` 的引用；再对这个引用做一次 `+= p3`，于是两次都把结果加在同一个 `p1` 上。例程里 `p1` 从 `(40, 60)` 经过两次 `+= p3`（`p3` 为 `1, 2`）变成 `(42, 64)`。

怎么写"返回自己"？靠关键字 `this`：

```cpp
return *this;
```

**`this` 是成员函数里的一个隐藏指针，指向"当前对象"**。调用 `p1 += p2` 时 `this` 就指向 `p1`。注意它的类型是指针，而我们需要交出的是对象本身，所以必须**解引用**：`*this` 才是 `p1` 这个对象。这一对关系要记牢：

| 写法 | 含义 | 类型 |
| --- | --- | --- |
| `this` | 指向当前对象的指针 | `point*` |
| `*this` | 当前对象本身 | `point` |

漏掉那个 `*` 会得到：

```text
error: invalid initialization of non-const reference of type 'point&' from an rvalue of type 'point*'
```

### 3.3 返回类型写错会怎样

| 返回类型 | 后果 |
| --- | --- |
| `point&`（正确） | `p1 += p2` 修改 `p1`，连续 `+=` 都作用在 `p1` 上 |
| `void` | `p1 += p2;` 单用没问题，但 `(p1 += p2) += p3;` 报 `error: no match for 'operator+=' (operand types are 'void' and 'point')` |
| `point`（值） | 能编译，`p1 += p2;` 也正确；但连续运算里的第二次 `+=` 作用在一个临时副本上，`p1` 只被加了一次——**编译不报错，结果错**，最难查 |

所以判断标准不是"能不能编译"，而是**"这个运算符的结果是不是左操作数本身"**。是，就返回 `*this` 的引用；不是（比如 `+` 产出的是一个新对象），就返回值。

## 4 设计运算符时的几条限制

运算符重载把一部分语言机制的钥匙交给了你，但并没有把全部钥匙都交出去。下面是必须知道的边界。

1. **不是所有运算符都能重载。** `::`（作用域解析）、`.`（成员访问）、`.*`（成员指针访问）、`?:`（三目条件运算符）、`sizeof` 这几类不能重载；`alignof`、`typeid` 也属于语言内建操作，同样不能重载；`=`、`[]`、`()`、`->` 只能是成员函数。剩下的绝大多数运算符（算术、比较、位运算、下标、函数调用等）都可以。本节只涉及算术类，后续会按需要补上其他运算符：比较与三向比较运算符见本章第 5 节，函数调用运算符 `()` 在第 18 章。
2. **不能改变运算符本身的"语法属性"**：操作数的个数、优先级、结合方向、以及它和内置类型之间的既有含义都改不了。你只是为"本类型 + 本类型"这类组合补充定义；`int` 之间的 `+` 永远还是加法。
3. **至少有一个操作数得是自定义类型。** 不能给 `int` 和 `int` 重新定义 `+`，否则整个语言的基础就动摇了。
4. **没有实现过的组合就用不了。** 只实现了 `operator+` 的话，`p1 += p2`、`p1 - p2`、`p1 == p2` 全都会报 `no match for 'operator...'`。每个运算符都要单独实现，这也意味着**只实现类型真正需要的那些**。
5. **实现要守约定。** `+` 应该"不改变操作数、产出新值"，`+=` 应该"修改左操作数"。把 `operator+` 写成修改 `p1`、或者让 `operator+=` 返回一个全新的对象，语法上都合法，但会违反所有读代码的人的预期，而且和标准库（如容器、算法）依赖的规则冲突。**运算符是给语义起的一个约定俗成的名字，不要用它做别的事。**

算术运算符写完之后，下一个自然的需求是比较：两个对象相等吗？谁大谁小？这类运算符同样要靠重载来提供，而手写它们比写 `operator+` 更枯燥，C++20 为此准备了一套更省事的方案。

## 5 手写比较运算符的麻烦

本章开头讲过运算符重载：想让自定义类型支持某个运算符，就得自己把这个运算符写出来。比如两个对象的相等比较：

```cpp
bool operator==(const point& rhs) const
{
    return x == rhs.x && y == rhs.y;
}
```

逻辑很简单，但它是纯粹的机械劳动，而且有两个麻烦：

- **成员一多就容易漏。** 加一个新数据成员，回头就得记着把这个函数改一遍；漏掉一个成员，两个本该不相等的对象就会判成相等——这种错误很难通过肉眼发现。
- **六个运算符之间的关系要保持一致。** 相等比较有 `==` 和 `!=`，大小比较有 `<`、`<=`、`>`、`>=`，一共六种。如果全部手写，我们不仅要写六遍，还得保证它们彼此不矛盾（比如 `a <= b` 和 `b >= a` 必须给出相同的结论）。这对写代码的人来说是很容易出错的负担。

C++20 提供了**默认比较**：和函数模板、类模板一样，把这类机械工作交给编译器。我们只声明"这个类型有比较运算符"，并在后面写 `= default`（第 12 章已讲过拷贝控制；第 14 章还会用移动语义优化这类返回），编译器就把实现填进去。

## 6 默认化的相等比较

### 6.1 写法

```cpp
struct s
{
    int a;
    int b;

    bool operator==(const s&) const = default;
};
```

三个细节和手写版本完全一样，只有函数体被换成了 `= default`：

- 返回类型是 `bool`；
- 参数是 `const s&`（第 8、12 章的理由：比较只读取，不该复制也不该修改）；
- 函数自己是 `const` 成员函数（比较不应该改动自己）。

**不写这一行就没有 `==` 可用。** 两个结构体长得一样，编译器并不会因此就认为它们能比较：

```text
error: no match for 'operator==' (operand types are 's' and 's')
```

### 6.2 比较规则：逐成员、按声明顺序

默认化版本做的事就是"把每个数据成员都比一遍"：按成员声明的顺序逐个比较，一旦发现某个成员不相等就立刻返回 `false`（不再看后面的成员），全部相等才返回 `true`。所以输出是 `0`（假）或 `1`（真）：

```cpp
s s1 {1, 2};
s s2 {1, 3};
std::cout << (s1 == s2) << std::endl;   // 输出 0：成员 b 不相等
```

`!=` 不需要额外声明。C++20 规定 `a != b` 会被自动当作 `!(a == b)` 处理，所以只默认化 `==` 就有两种比较可用。但要注意**这适用于 `!=`，不适用于 `<`、`<=`、`>`、`>=`**：只默认化 `==` 时写 `s1 < s2` 仍然编译失败（`no match for 'operator<'`），关系比较要等下一节的三向比较运算符来提供。

### 6.3 成员自身必须支持比较

默认化只是把工作交给编译器，它不能凭空创造比较能力。如果类里有一个成员的类型自身不支持 `==`，那么这个默认化的 `==` 会被定义为**删除的**（deleted），一使用就报错：

```text
error: use of deleted function 'constexpr bool s::operator==(const s&) const'
note: 'constexpr bool s::operator==(const s&) const' is implicitly deleted because the default definition would be ill-formed:
error: no match for 'operator==' (operand types are 'inner' and 'inner')
```

处理办法有两个：给那个成员类型补上比较运算符，或者自己手写外层的 `==` 并明确说明这种比较该怎么定义。

## 7 三向比较运算符

### 7.1 写法与目的

只默认化 `==` 还不够——我们还缺 `<`、`<=`、`>`、`>=`。一个一个默认化做不到（`operator<` 这类虽然也能写 `= default`，但默认定义会被定义为 deleted，一旦使用就编译失败），标准给出的方案是**三向比较运算符**，运算符符号写成 `<=>`（因为形状像飞碟，通常被叫作飞船运算符）：

```cpp
struct s
{
    int a;
    int b;

    auto operator<=>(const s&) const = default;
};
```

和上一节唯一的差别是：运算符名换成 `<=>`，返回类型写 `auto`。写了这一行之后，六种比较就都可以用了：

```cpp
std::cout << (s1 <  s2) << std::endl;   // 1
std::cout << (s1 <= s2) << std::endl;   // 1
std::cout << (s1 >  s2) << std::endl;   // 0
std::cout << (s1 >= s2) << std::endl;   // 0
std::cout << (s1 == s2) << std::endl;   // 0
std::cout << (s1 != s2) << std::endl;   // 1
```

### 7.2 关于 `==` 的一条关键区别

这一节的内容很容易记错，所以分开说清楚：

- **默认化的 `<=>`（写 `= default`）会连带声明一个对应的 `==`。**标准规定：如果一个类里没有自己声明 `operator==`，那么每个声明为默认化的 `operator<=>` 都会隐式声明一个对应的 `operator==`（返回类型改成 `bool`，其余属性照抄）。所以上面那一行代码就凑齐了全部六种比较运算符——这也是为什么例程 `spaceship_default` 里只写了 `<=>` 却能使用 `==` 和 `!=`。
- **自己手写的 `<=>`（不写 `= default`）不带这个附带效果。**这种情况下必须另外声明 `==`，通常就是再写一句 `bool operator==(const s&) const = default;`。少了它，代码里出现的 `==` 会直接报 `error: no match for 'operator==' (operand types are 's' and 's')`。

一句话的结论：**如果类里的比较运算符有一部分是手写的，就要自己确认 `==` 是否已经被声明出来。**这也是本章最容易踩的一个坑。

### 7.3 返回值不是一个 bool

`<=>` 的返回值不是 `true` / `false`，而是一个表示"大小关系"的对象（下一节讲它有几种）。这样设计的原因很直接：一次比较就能表达三种结果，而不是分三次调用才知道谁大谁小。

虽然它不是 `bool`，但用起来有两条简单规则：

- **和 0 比较**：`(a <=> b) < 0` 等价于 `a < b`，`(a <=> b) == 0` 等价于 `a == b`。所有重写出来的关系运算符（`<`、`<=`、`>`、`>=`）内部就是这么定义的。
- **不能直接打印**：`std::cout << (a <=> b)` 会报 `error: no match for 'operator<<' (operand types are 'std::ostream' {aka 'std::basic_ostream<char>'} and 'std::strong_ordering')`（实测原文，本机 GCC 16.1.0；换了编译器版本，`std::ostream {aka ...}` 这一段可能略有差别）。要看它是什么结果，可以跟 0 比较后输出 `bool`，或者像例程里那样写一个小函数把结果翻译成文字，也可以用标准库提供的 `std::is_lt`、`std::is_eq` 等判断函数。

## 8 比较的三种强度

比较结果有类型，而这个类型由**数据成员**决定。三种强度从强到弱是：

| 比较类别 | 结果取值 | 适用于 | 相等时打印出的词 |
| --- | --- | --- | --- |
| `std::strong_ordering` | `less` / `equal` / `greater` | 整数、指针等"相等就是真的相同"的类型 | `equal` |
| `std::weak_ordering` | `less` / `equivalent` / `greater` | 相等但未必相同的类型（例如忽略大小写的字符串） | `equivalent` |
| `std::partial_ordering` | `less` / `equivalent` / `greater` / `unordered` | 浮点数：NaN 无法和任何值比较 | `equivalent` |

三个要点：

- **默认化时写 `auto` 就是在让编译器去算这个类型。**全是 `int` 成员时得到 `std::strong_ordering`；只要有一个 `double` 成员，整体就退到 `std::partial_ordering`。取的是各成员里最弱的那个。
- **`partial` 比另外两种多一个取值 `unordered`（无法比较）。**它存在的唯一原因就是浮点数的 NaN：NaN 和任何值比大小都不成立。
- **`strong` 的"相等"叫 `equal`，另外两种叫 `equivalent`（等价）。**同一片信息在 `weak` 的语义下只是"等价"：比如忽略大小写时 `"ABC"` 和 `"abc"` 等价，但它们并不是同一个字符串。

`std::weak_ordering` 用得少，可以自己写一个来观察：下面的函数忽略大小写比较两个字符串，返回的就是 `std::weak_ordering`。

```cpp
std::string lower(std::string s)                  // 把字母统一转成小写
{
    for (char& c : s)
    {
        c = static_cast<char>(std::tolower(static_cast<unsigned char>(c)));
    }
    return s;
}

std::weak_ordering compare_ignore_case(const std::string& lhs, const std::string& rhs)
{
    return lower(lhs) <=> lower(rhs);             // 结果类型是 weak_ordering
}
```

用它比较两组字符串，实测（`-std=c++20 -Wall`）第一行输出 `true`、第二行输出 `true`：

```cpp
std::cout << std::boolalpha;
std::cout << (compare_ignore_case("ABC", "abc") == 0) << std::endl;   // true：等价
std::cout << (compare_ignore_case("ABC", "abd") <  0) << std::endl;   // true：ABC 更小
```

在这个语义下 `"ABC"` 和 `"abc"` 是 `equivalent`（等价）而不是 `equal`（相同），这正是 `weak_ordering` 与 `strong_ordering` 的差别。

NaN 的具体表现必须记住，实测（见例程 `ordering_categories`）在含 NaN 的比较里：

```text
nan <  1.0 -> 0
nan >  1.0 -> 0
nan <= 1.0 -> 0
nan == 1.0 -> 0
nan != 1.0 -> 1
```

六个比较里只有 `!=` 为真（因为它就是 `!(==)` 的结果），其他全部为假。所以把可能含 NaN 的值当作排序关键字，就违反严格弱序这一前置条件，此时标准库排序算法的行为是未定义（UB）——这也是"偏序"这个名字的含义：任意两个值不一定都能比出大小。

## 9 逐成员比较的规则：字典序

默认化的 `<=>` 和默认化的 `==` 一样，都按**成员声明顺序**逐个比较，而且一旦某个成员分出了大小就立刻有结论，后面的成员不再参与。这就是**字典序**（lexicographical order），和查字典时比较单词的规则完全相同。

看一组具体数据：

```cpp
s p1 {1, 30};
s p2 {10, 20};
std::cout << (p1 < p2) << std::endl;    // 输出 1
```

`p1` 的第二个成员（30）比 `p2` 的（20）大，但结论仍然是 `p1 < p2`——因为第一个成员 `1 < 10` 已经把胜负定下来了。**第一个不同的成员说了算。**

这条规则带来一个非常实用的推论：**成员声明的顺序就是排序关键字的优先级。**想让 `score` 当第一关键字，就把它声明在 `id` 前面，一行比较代码都不用改。例程 `sort_with_spaceship` 就是把这个推论用到 `std::sort` 上的例子：类型只多了一行 `= default`，就立刻可以排序、可以求最值。

## 10 该用哪一种

- **只需要判断相等**（例如作为 `std::map` 的键的辅助判断、查找重复项）：只默认化 `==`。
- **需要排序或比较大小**：默认化 `<=>`。它顺带会声明 `==`；如果你更希望把意图写明白，也可以把 `==` 那行显式写出来，两行一起写不会冲突。
- **需要自定义比较规则**（只看某几个成员、或者按某种特别的顺序）：自己手写 `<=>`，并且**用同样的规则写 `==`**。标准约定（也是推荐做法）这两个运算符的结论要一致，否则同一对对象会得出互相矛盾的答案；这条约定并没有强制的编译期诊断，编译器不会替你检查。
- **标准与编译器**：默认比较与三向比较运算符属于 C++20。本课程所有例程统一用 `-std=c++20`（GCC 10 及以后支持）。忘了加这个参数时会看到 `<=>` 被拆成 `operator<=` 和 `>` 去解析所引发的一串报错，例如：

```text
error: declaration of 'operator<=' as non-function
error: expected ';' at end of member declaration
```

=== Demo E: p1.operator+(p2) is the same call ===
x = -20, y = -20

Demo C 为什么是 `(0, 0)`？因为 `p3` 自己也是用这个（被改坏的）运算符算出来的：`p3 = p1 - p2` 得到 `(-20, -20)`，于是 `p4 = (p1 - p2) - p3 = (-20, -20) - (-20, -20) = (0, 0)`。这个实验说明：**运算符的含义完全由我们写的函数体决定**，改了实现，所有使用它的地方都会跟着变。看完把函数体还原。
