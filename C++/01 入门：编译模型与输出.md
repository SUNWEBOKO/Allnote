## 1 从一句话认识 C++

要描述 C++，一句话就够了：**C++ 是一种静态类型的编译语言**。

这句话很短，但它定下了后面所有内容的基调。程序里写的每一行代码最终都要变成处理器能执行的指令，而"编译"和"静态类型"分别规定了这件事在什么时候、以什么方式发生：编译决定了**你的源码必须先被翻译成可执行文件才能运行**；静态类型决定了**每个值的类型必须在翻译完成之前就确定下来**。本章把这两个词拆开讲清楚，然后写出、编译、运行第一个 C++ 程序。

配套例程在 `E:\CPP_Code\CppFromScratch\ch01_what_is_cpp\`

## 2 编译语言：源码不是可以直接运行的东西

### 2.1 编译语言与解释语言的区别

在 Python 这类语言里，你写完 `print("hi")` 保存成 `.py`，直接用 Python 解释器运行它，解释器一边读一边执行，源码本身就是要运行的东西。

C++ 不是这样。你写出来的 `.cpp` 文件只是**给人看的文本**，处理器不认识它，操作系统也不认识它。要让它跑起来，必须先交给一个叫**编译器**（compiler）的程序，把它翻译成机器能执行的**可执行文件**。翻译发生在运行之前，是一次性的；一旦可执行文件生成好了，再运行它就不需要编译器参与了。

这个差别带来两个直接后果，后面会反复用到：

- **运行之前就能发现一部分错误。** 语法错误、类型不匹配这类问题在翻译阶段就会被编译器挡下来，程序根本不会开始运行。
- **改了源码不会自动生效。** 因为可执行文件是上一次翻译的结果，源码改了必须重新翻译一遍。这是本章第 5 节要专门讲的一个高频困惑。

### 2.2 从源码到可执行文件要经过四步

编译器驱动（我们是 `g++`）把源码变成可执行文件，中间经过四个阶段：

| 阶段 | 做什么 | 产物 |
| --- | --- | --- |
| 预处理 | 展开 `#include`、处理宏和条件编译指令 | 展开后的完整源码 |
| 编译 | 把 C++ 代码翻译成汇编代码，并做语法和类型检查 | 汇编代码 |
| 汇编 | 把汇编代码翻译成机器指令 | 目标文件（`.o` / `.obj`） |
| 链接 | 把若干目标文件和标准库拼成一个完整的可执行文件 | 可执行文件（`.exe`） |

平时的报错主要来自中间两步，而"某个名字找不到"这类错误往往发生在链接阶段。

要提醒的是，`g++` 只是一个**驱动**：它按顺序调用预处理器、编译器本体、汇编器和链接器，把四步串起来。你只敲一条命令，四步都在后台完成了。

### 2.3 编译器与标准库的分工

编译器只负责翻译你的代码，语言本身还带一个**标准库**：容器、算法、输入输出等常用功能都已经写好，你直接用即可。本课程后面用到的 `std::cout`、`std::array` 都来自标准库，用法是"包含对应头文件 + 调用其中的设施"。

## 3 静态类型：每个值都有类型

### 3.1 类型说明这个值是什么

程序里到处是值：`0` 是值，`3.14` 是值，一段文字也是值。在 C++ 里，**每一个值都属于某个类型**，类型告诉你这个值在表示什么——是整数，是带小数的浮点数，是"真/假"，还是一段字符。

### 3.2 类型决定能对值做哪些运算

类型不只是标签，它还决定了这个值能参与哪些运算、这些运算又是什么意思。例如两个整数可以相加、取余。**类型不对，运算就写不出来**——`"abc" * 2` 这种写法编译器会直接拒绝，因为字符串类型上根本没有"乘法"这个约定。还要留意：字符串字面量本质是 `const char*`，所以 `+`、`-` 在这里是指针算术，不是字符串运算——`"abc" - 1` 这类写法反而能通过编译。

这也是本课程后面反复出现的一种思维方式：看到一个值，先问"它是什么类型"，能做的操作、结果的类型、输出的形式就都跟着确定了。

### 3.3 静态：类型在编译期就固定下来

"静态"指的是时机。**类型必须在编译期确定，并且确定之后不能在运行期改变。** 一个变量被定义成整数，它在整个程序运行过程中就一直是整数，不会变成浮点数，也不会变成字符串。

这带来两个好处：

- **编译器能生成正确的机器指令。** 整数加法和浮点数加法在处理器上是不同的指令。编译器必须在编译期就知道是哪种，才能挑对指令。
- **错误能提前暴露。** 把字符串和整数直接相加这类错误在编译期就被发现，而不是等到运行到那一行才出问题。

整型、浮点、布尔、字符这些内置类型统称为**基础类型**，第 02 章会系统梳理它们；本章只需要记住"每个值都有类型、类型在编译期定死"。

## 4 最简的 C++ 程序：main 函数

`E:\CPP_Code\CppFromScratch\ch01_what_is_cpp\main\main.cpp` 是能写出来的最短的 C++ 程序（去掉注释后只有三行）：

```cpp
int main()
{
    return 0;
}
```

这短短三行里包含了一个函数的全部组成部分，逐块拆开看：

| 成分 | 作用 |
| --- | --- |
| `int` | **返回类型**。这个函数执行完之后要交回一个整数。 |
| `main` | **函数名**。函数是"给一串代码起的名字"，调用这个名字就会执行函数体里的语句。 |
| `()` | **参数列表**。括号里是函数需要的输入；这里是空的，表示这个函数不接收任何输入。 |
| `{ }` | **函数体**。花括号里的语句就是调用这个函数时会真正执行的内容。 |
| `return 0;` | **返回语句**。`return` 是 C++ 的关键字，表示"结束函数并把后面的值交回去"；语句末尾的分号是 C++ 语句的结束标记，不能漏。 |

这里的 `main` 有一个特殊身份：**它是整个程序的执行起点**。可执行文件被加载运行时，操作系统会找到名为 `main` 的那个函数，从它函数体的第一条语句开始执行。所以不管 `main` 写在哪个源文件里、写在文件的哪个位置，程序都从它开始跑。一个程序必须有且只有一个 `main`，否则链接阶段会报错。

### 4.1 关键字与标识符

`int`、`return` 这类词是语言保留的**关键字**，有固定含义，不能拿来当变量名或函数名。反过来，`main`、`var_one` 这类你自己起的名字叫**标识符**，命名时要用能说明用途的英文，别用 `a1`、`x2` 这种过几天自己都看不懂的名字。

### 4.2 平台差异：可执行权限

课程视频在 Linux 下演示，`ls -l` 会看到可执行文件比源码多了一个执行权限位，运行时写 `./main`。**Windows 上没有这种权限位**，可执行文件以 `.exe` 结尾，运行时写上文件名即可。这是两个平台在"怎么运行"上的差别，不影响 C++ 代码本身。

## 5 编译型语言的直接后果：改源码必须重新编译

现在回到本章第 2 节留下的那个问题。假设你打开 `main.cpp`，把 `return 0;` 改成 `return 12;` 保存，然后**直接再运行一次 `main.exe`**——得到的退出码仍然是 `0`。

原因很直白：`.exe` 是上一次编译的产物，它里面记的是上一次那份代码。你新写的源码对已经生成的 `.exe` 没有任何影响。必须重新执行一次编译命令，让编译器按新的源码生成新的 `.exe`。

这就是"编译型语言"最日常的后果，也是初学者最常见的困惑之一——**"我明明改了啊，怎么没反应"，十有八九是忘了重新编译**。VS Code 里的 `F5` 和"编译并运行"任务都带了"先编译"这一步，用它们就不会踩这个坑。

到这里，"怎么编译、怎么运行"已经解决了，但程序的结果还只能通过退出码传出一个整数。下一步就是让程序把真正的信息打到屏幕上。

## 6 为什么程序需要输出

到目前为止，我们写的程序运行之后什么都不显示——它的结果只能通过退出码传出去一个整数。这显然不够用：程序在做什么、中间算出了什么值，都需要能看到。

把信息打到屏幕上，是程序最基本的对外通道。有两个场景几乎每天都会用到：

- **记录与观测。** 程序跑出意外结果时，先把关键变量的值打出来，能最快定位问题出在哪一步。这是最原始的调试手段，也是最可靠的手段。
- **给用户看结果。** 命令行工具、控制台程序的计算结果，最终都要以文本形式呈现给用户。

## 7 `#include`：把别人的代码搬进自己的文件

### 7.1 输出流对象从哪来

要在屏幕上输出内容，本来需要自己写一堆和操作系统打交道的代码。好在这件事已经被标准库解决了：标准库提供了**输入输出设施**，也就是各种**流**（stream）对象——屏幕是一根流，文件是另一根流，往流里送数据，数据就流向了对应的目的地。

本章只用其中的**标准输出流**，名字是 `std::cout`。`cout` 是 "character output" 的缩写，它的类型是 `std::ostream`（output stream）。这个类型定义在头文件 `<iostream>` 里（`i` 是 input，`o` 是 output）。

### 7.2 使用之前必须先知道它是什么

编译器在处理你的源文件时，是按顺序往下读的。读到 `std::cout` 这一刻，它需要知道"`cout` 是标准库里的一个输出流对象"，否则只能报错。这份"说明"从哪来？答案就是头文件。

所以使用任何标准库设施之前，都要先用 `#include` 把它所在头文件包含进来：

```cpp
#include <iostream>
```

`#include` 是一个**预处理指令**，不是普通的 C++ 语句（所以它末尾不写分号）。本章第 2 节讲过编译要经过预处理、编译、汇编、链接四个阶段，`#include` 的处理发生在第一个阶段：**预处理器把 `<iostream>` 这个文件的全部内容，原样复制到 `#include` 这一行的位置上**，等价于手工把几万行头文件代码粘贴进来。复制完成之后，`cout` 的定义就已经出现在你的源文件里了，编译器自然认识它。

### 7.3 亲眼看到展开的结果

这件事不用只靠想象，可以让编译器把预处理的结果留下来。`-E` 参数表示"只做预处理，做完就停"：

```text
E:\msys64\ucrt64\bin\g++.exe -E print.cpp -o print.ii
```

生成的 `print.ii` 就是展开后的完整源码。本机实测：`E:\CPP_Code\CppFromScratch\ch02_print\print\print.cpp` 里我们自己写的代码只有 30 行左右，展开后的 `print.ii` 却有 **44137 行**。翻到文件底部，能看到自己那几行代码；往上翻，全都是被搬进来的头文件内容，其中夹杂着形如 `# 1 "..."` 的行标记，表示"接下来这段来自哪个文件"。

在 `print.ii` 里搜索 `cout`，可以找到它的声明：

```cpp
extern ostream cout;
```

**这就是 `#include` 全部的秘密：它不是"链接"、不是"引用"，而是复制粘贴。** 理解了这一点，后面所有"为什么用这个东西之前要先 include"的问题都能自己回答。

### 7.4 尖括号与引号的区别

包含头文件有两种写法：`<iostream>` 和 `"myheader.h"`。尖括号用于**标准库和系统提供的头文件**，编译器会去标准的位置找；双引号用于**你自己写的头文件**，编译器先在你当前目录找。本课程目前只用到标准库头文件，统一用尖括号。

### 7.5 `std::` 是什么

`cout` 的名字其实不叫 `cout`，而是 `std::cout`。`std` 是**命名空间**（namespace），标准库里的所有设施都放在这个命名空间里；`::` 是**作用域解析运算符**，`std::cout` 读作"`std` 命名空间里的 `cout`"。

命名空间的作用是避免重名冲突：标准库里有 `cout`，你自己的代码里也可能有一个叫 `cout` 的东西，用命名空间一隔开，两者互不干扰。**代码里看到 `std::` 开头，就知道它来自标准库**。命名空间的完整规则会在后续章节展开，现在只要会照写 `std::cout` 就行。

## 8 `std::cout` 与 `<<`

### 8.1 往流里送数据

准备好 `std::cout` 之后，输出一行文字只需要一句：

```cpp
std::cout << "Hello World" << std::endl;
```

这行代码里出现了两个符号，都要说清楚。

### 8.2 `<<` 在流对象上是"插入"

`<<` 这个符号在 C++ 里**有两种完全不同的含义**，靠操作数的类型来区分：

- 当两边都是整数时，它是**左移运算符**：`1 << 3` 表示把 1 的二进制位向左移 3 位，结果是 8。
- 当左边是输出流对象时，它是**流插入运算符**：含义变成"把右边的东西送进左边这个流"。

同一个符号在不同类型上有不同含义，这一点是对的：本章第 3 节讲过类型决定可用的运算符及其含义。标准库为输出流定义了 `<<`，所以我们才能用这个符号来做输出。反过来说，**一个类型能不能用 `<<` 打印，取决于标准库或这个类型的作者有没有为它定义 `<<`**——第 03 章的 `std::array` 就恰恰没有定义，不能整体打印，那时会再回到这一点。

注意 `<<` 的方向：数据从右边**流进**左边的流对象，所以箭头指向 `cout` 一侧。写反成 `>>` 不会达到你想要的效果。

### 8.3 字符串用双引号

`"Hello World"` 是**字符串字面量**，用双引号；单引号 `'a'` 表示**单个字符字面量**，两者是不同的东西，不能混用。写成单引号的 `'Hello World'` 是另一类语法结构（多字符字面量），屏幕上不会打印出这段文字，只会得到一个整数，而且编译器会警告。**要输出一段文字，就用双引号。**

### 8.4 `std::endl` 与 `'\n'`

`std::endl` 的作用是**换行并刷新缓冲区**。所谓缓冲区，是一块攒着输出内容的临时内存：程序输出时不会每写一个字符就马上发给终端，而是先攒在缓冲区里，攒够了或需要时再一次性送出去，这样效率更高。`std::endl` 做两件事——先写入一个换行符，再强制把缓冲区的内容立刻送到终端。

只换行不刷新，可以写 `'\n'`：

```cpp
std::cout << "Hello World\n";   // 换行，但不强制刷新
```

日常小程序里两者看不出差别，本课程的例程统一使用 `std::endl`：程序异常中断时，已经用 `std::endl` 刷新的内容更容易被看到，排查问题时才不会出现"明明打印了却没显示"的错觉。

## 9 把多个内容串在一起输出

一次 `<<` 只能送一样东西进流，但可以连着写很多个 `<<`。`print_chain.cpp` 里的一行：

```cpp
std::cout << "Hello" << "," << " World" << std::endl;
```

它等价于下面四步依次执行，只是紧凑地写在一行里：

```cpp
std::cout << "Hello";
std::cout << ",";
std::cout << " World";
std::cout << std::endl;
```

它之所以能一直写下去，是因为**每次 `<<` 做完之后返回的就是左边那个流对象本身**（还是 `std::cout`），于是它可以继续作为下一个 `<<` 的左操作数。这一串按从左到右的顺序执行，所以屏幕上的顺序和我们书写的顺序完全一致。

拼接时**没有自动的空格**：上面输出的是 `Hello, World`，中间那个空格是 `" World"` 这个字符串自己带的。想要分隔就自己写进字符串里。

同一个流里可以混排不同类型，例如：

```cpp
std::cout << "1 " << 42 << " World" << std::endl;   // 输出：1 42 World
std::cout << "6 * 7 = " << 6 * 7 << std::endl;       // 输出：6 * 7 = 42
```

整数 `42` 会被自动转成它的十进制文本形式再送出。这也是为什么第 02 章里把变量类型从 `int` 改成 `double` 时打印语句一行都不用改——**流的输出形式由送进去的值的类型决定**。

### 实验一：编译并运行最简程序

**材料与设置**：VS Code 打开文件夹 `E:\CPP_Code`（注意打开的是文件夹，不是单个文件，否则 `.vscode` 里的配置不生效）；打开 `E:\CPP_Code\CppFromScratch\ch01_what_is_cpp\main\main.cpp`。

**操作步骤与预期现象**，两种方式任选：

方式一（VS Code）：

1. 按 `Ctrl+Shift+B` 会直接运行默认生成任务 `C/C++: g++.exe 生成活动文件`；若要运行 `C++: 编译当前文件 (MSYS2 UCRT64)`，需从命令面板（`Ctrl+Shift+P`）执行 `Tasks: Run Build Task` 再选中它。
2. 终端只有编译命令，**没有任何报错输出**，说明编译通过，同目录下出现 `main.exe`。
3. 按 `F5`（或选任务 `C++: 编译并运行当前文件`）运行它。

方式二（终端，在 Git Bash 或 PowerShell 里执行）：

```text
E:\msys64\ucrt64\bin\g++.exe -std=c++20 -Wall -g main.cpp -o main.exe
./main.exe
```

这时**屏幕上什么都不会出现**。这不是程序没跑起来，而是因为 `main` 里只有一句 `return 0;`——它除了结束程序，没有做任何输出。要确认它真的正常结束了，看退出码：

| 终端 | 查看上一条命令退出码 |
| --- | --- |
| cmd（命令提示符） | `echo %ERRORLEVEL%` |
| PowerShell | `echo $LASTEXITCODE` |
| Git Bash | `echo $?` |

看到 `0` 就表示程序正常结束。

**验收标准**：`main.exe` 生成成功；运行后无输出；退出码为 `0`。

### 实验二：把退出码改成 12

打开 `E:\CPP_Code\CppFromScratch\ch01_what_is_cpp\exit_code\exit_code.cpp`，它与实验一的唯一区别是把 `return 0;` 换成了 `return 12;`。

按同样的方式编译运行，然后查看退出码，这次得到的应该是 `12`。屏幕上依然什么都没有——**这个程序"说"的话不在屏幕上，而在退出码里**。

**验收标准**：退出码为 `12`，且屏幕无输出。

### 退出码是什么

前面两个实验反复提到的"退出码"就是 `main` 返回值的去向。函数返回值交给操作系统之后，成为这个进程的**退出码**（exit code）：

- `0` 是约定俗成的"一切正常"；
- 非 `0` 表示出现了某种异常，具体含义由程序自己规定。

这就是为什么 `main` 的返回类型必须是 `int`：它需要一个整数把"这次运行的结果如何"汇报出去。批处理脚本、构建系统、自动化测试都是靠读取退出码来判断上一步是否成功，而不是靠屏幕输出——因为屏幕输出要人工看，退出码可以自动判断。
