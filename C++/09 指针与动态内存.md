## 学习目标

完成本章后，你应当能够：

1. 说出指针变量里存的是什么，用取地址运算符 `&` 把地址存进指针、用解引用运算符 `*` 通过指针读写原变量，并说明指针和引用的区别。
2. 写出空指针并说明为什么解引用之前必须先判空，说出 `int*`、`double*`、`int**`、`void*` 各自能指向什么、不能做什么。
3. 说明为什么有些内存必须在运行时才申请，并用 `new` 表达式申请内存、用指针接住它返回的地址。
4. 用 `delete` 和 `delete[]` 释放自己申请的内存，说出两者的区别以及写错时的现象。
5. 说出不释放内存的后果与使用 `new`/`delete` 必须遵守的纪律，理解为什么实际代码优先用容器和智能指针。

## 1 一个还没回答的问题：地址能不能存下来

第 08 章讲引用时提到过一个运算符：`&`。写 `int& b = a;` 之后 `b` 就是 `a` 的别名，改 `b` 就是改 `a`，因为两者是同一块内存的两个名字。当时还有一条附带结论——`&a` 能取出变量 `a` 的地址，也就是它在内存里的位置。

到了第 08 章后半部分，我们用 `&` 把变量按引用传进函数，避免了复制。

但这里一直悬着一个问题：**取出来的这个地址，能不能像普通的数一样存进一个变量里？**

能。专门用来存地址的变量类型就叫做**指针**（pointer）。第 06 章讲过"迭代器记录的是位置"，并留下一个线索：`std::array` 的迭代器在 libstdc++ 里其实就是裸指针。更准确的说法是——**迭代器是对指针的泛化**：连续容器（如 `std::array`、`std::vector`）的迭代器往往就是指针，其他容器的迭代器则是更复杂的对象；而所有迭代器共有的"用 `*it` 取元素"这套用法，正是从指针的解引用借用来的。

本章先把指针本身讲清楚：怎么声明、怎么取地址、怎么通过它访问原变量、怎么保证不出错。至于"自己申请和释放内存"这种必须用到指针的场合，是本章第 9 节的事。

## 2 指针的声明：星号是类型的一部分

指针变量的声明形式，是在类型名后面加一个星号：

```cpp
int a = 5;
int* b = &a;      // b 是"指向 int 的指针"，初值是 a 的地址
```

这一行可以做三处拆解：

| 部分 | 内容 | 说明 |
| --- | --- | --- |
| 类型 | `int*` | 读作"指向 `int` 的指针"。它表示这个变量里存的是"一个 `int` 所在的内存地址"，而不是一个整数 |
| 名字 | `b` | 只是个变量名，叫什么都可以 |
| 初值 | `&a` | 取 `a` 的地址，把地址存进 `b` |

**星号是类型的一部分，不是"取值"的意思。** 这一点必须分清楚，因为同一个符号 `*` 在 C++ 里有两个完全不同的角色：

| 符号 | 出现在哪里 | 含义 |
| --- | --- | --- |
| `*` | 声明语句的类型部分，如 `int* b;` | 类型标记，表示"b 是保存 `int` 地址的变量" |
| `*` | 表达式里，如 `*b = 42;` | 解引用运算符，表示"沿着这个地址找到那块内存，把它当成 `int` 用" |
| `&` | 表达式里，如 `b = &a;` | 取地址运算符，交出这个变量的内存地址 |

所以 `int* b = &a;` 里的那个 `*` 只是类型写法，`=` 右边没有任何"取值"动作；而下一节 `*b` 里的 `*` 才是真正的动作。

另外注意类型和名字的结合方式：`int* b` 和 `int *b` 完全等价，编译器不在乎空格。但一个常见的写法陷阱是 `int* p, q;`——这里的 `p` 是 `int*`，而 `q` 是 `int`，星号只作用于紧挨着它的那个名字。想声明两个指针就写两行，或者写成 `int* p; int* q;`。

## 3 打印出来看看：`a` 和 `b` 打印的不是一类东西

把两个变量都打印出来，差别会很直观：

```cpp
std::cout << a << std::endl;      // 5      —— a 是 int，打印整数
std::cout << b << std::endl;      // 0x7ffd... 或类似形式 —— b 是 int*，打印地址
```

`a` 是整数，输出 `5`。`b` 的类型是"指向 `int` 的指针"，`std::cout` 遇到指针会把它按十六进制地址打印出来，形如 `0x7ffcd9e8c1ac`。

这里有一个重要的实践问题：**地址的具体数字每次运行都可能不同**。程序每次被加载到内存里的位置不保证一样，操作系统还会做地址随机化，所以同一份程序连着跑两次，打印出的地址很可能不一样。这意味着"打印地址"没法作为稳定的校验手段。所以在例程 `pointer_basic.cpp` 里我们不打印地址的值，而是打印判断结果：

```cpp
std::cout << "b holds the same address as &a: " << (b == &a) << std::endl;   // 输出 1
```

`b == &a` 是在比较两个地址是否相同，结果是 `bool`，打印出来是 `1`（真）。这个结果与内存布局无关，每次运行都相同——它同时证明了 `b` 里装的确实是 `a` 的地址。

## 4 解引用：通过指针读写原变量

把星号放在一个**已经声明的**指针变量前面，就是解引用（dereference）：沿着 `b` 里存的地址找到那块内存，把它当作 `int` 使用。

```cpp
std::cout << *b << std::endl;    // 5，因为 *b 就是 a
*b = 42;                         // 通过 b 修改 a 所在内存里的整数
std::cout << a << std::endl;     // 42
```

关键理解是：`*b` 和 `a` 是同一块内存的两种写法。读 `*b` 就是读 `a`，给 `*b` 赋值就是给 `a` 赋值。执行 `*b = 42;` 之后，`b` 自己（那个地址）一个字节都没变，变的是 `b` 指向的那块内存的内容。用地址去间接操作一个变量，这个过程叫**间接访问**，指针的价值就在这里。

写 `*b = 42;` 之后 `a` 变成 42，这说明**指针提供了和引用一样的"透过别名改原变量"的能力**。两者的区别不在能不能改原变量，而在下面第 5 节要说的事情。

解引用操作有两个前提，缺一个都是未定义行为：

- `b` 里必须是一个**有效地址**，也就是确实指向一块属于本程序、且类型匹配的内存；
- 那块内存**必须还活着**（没有被销毁、没有被释放）。

## 5 指针是变量，引用是别名

第 08 章强调过引用是"别名"：引用一旦绑定到某个变量，就永远是那个变量的另一个名字，没有"改成别的变量的引用"这种操作。指针不同——**指针本身就是一个普通变量，它的值（也就是"指向谁"）随时可以被改写**：

```cpp
int x = 1;
int y = 2;
int* p = &x;

*p = 10;      // 写的是 x
p = &y;       // p 改指向 y；这只是改了 p 自己的值，x 里的 10 还在
*p = 20;      // 这次写的是 y
```

执行完这三句，`x` 是 10，`y` 是 20。这个能力引用没有：引用更安全（不可能突然指向别处），指针更灵活（可以中途换目标）。

| 对比项 | 引用 `int&` | 指针 `int*` |
| --- | --- | --- |
| 本质 | 已有变量的别名 | 一个保存地址的变量 |
| 能否改指向 | 不能，绑定后就固定 | 能，随时赋新的地址 |
| 能否表示"不指向任何东西" | 不能，必须绑定一个对象 | 能，写成 `nullptr` |
| 声明时是否必须初始化 | 必须 | 不必须，但强烈建议初始化 |
| 解引用/使用 | 直接用，不需要符号 | 需要 `*p` 取到目标 |
| 用途倾向 | "这里就是要操作那个变量" | "地址需要被保存、传递、比较、中途更换" |

选择规则很简单：能用引用就用引用，因为引用不会为空、不会指向别处，出错的机会少得多。只有确实需要"保存地址""中途改指向""表示空"这几件事时，才用指针。

## 6 空指针与判空

指针可以合法地表示"现在什么都不指向"，这个值写 `nullptr`：

```cpp
int* p = nullptr;      // 空指针：合法的值，但不能解引用
```

`nullptr` 是 C++ 里专门的空指针字面量，任何类型的指针都可以用它初始化。它存在的理由是：**解引用一个无效地址是未定义行为，通常会直接让程序崩溃**。在例程里可以验证这一点——把 `int* p = nullptr; p` 解引用（写 `*p`），程序会在那一行直接异常退出，Windows 上退出码是 `0xC0000005`（访问冲突），Linux 上是 `Segmentation fault`。这类崩溃没有可读的提示，只能靠代码纪律避免。

所以"这个指针现在有没有指向东西"必须能被检查。指针在条件里会按"是否为空"判断真假：

```cpp
if (p != nullptr)
{
    std::cout << *p << std::endl;   // 确认有效之后再解引用
}
```

`if (p)` 和 `if (p != nullptr)` 等价，本课程统一用后一种，读起来更明确。

还要避开另一种更隐蔽的情况——**声明了但没初始化**：

```cpp
int* p;              // 危险：p 里是一个不确定的值
std::cout << *p;     // 访问一块随机地址，行为不可预测
```

GCC 在 `-Wall` 下会对这种写法给出 `warning: 'p' is used uninitialized [-Wuninitialized]`。养成习惯：**声明指针时就给初值**，暂时不知道指向哪里就写 `= nullptr`。

## 7 指针的类型信息在管什么

指针类型由"它指向什么"决定：指向 `int` 的是 `int*`，指向 `double` 的是 `double*`，指向 `std::vector<int>` 的是 `std::vector<int>*`。这个类型信息不是装饰，它在管三件事：

1. **解引用时怎么解释那块内存。** `*dp` 按 `double` 的方式读 8 个字节，`*ip` 按 `int` 的方式读 4 个字节。同一个地址用不同的指针类型去解释，得到的东西完全不同。
2. **指针算术的步长。** `p + 1` 不是"地址加 1 个字节"，而是"跳到下一个同类型对象"，`int*` 前进一个 `int` 的距离，`double*` 前进一个 `double` 的距离。本章第 13 节用 `new int[10]` 分配数组时会用到这条规则（顺便说：数组下标 `data[i]` 就是 `*(data + i)` 的简写）。
3. **编译期拦截类型错误。** `double` 的地址交给 `int*` 编译器直接报错，不会让你在运行时才发现读错了内存。

指针还可以指向指针。指针自己也是变量，也有地址，所以可以再取它的地址存进另一个指针：

```cpp
int a = 7;
int* p = &a;
int** pp = &p;      // 指向"指向 int 的指针"，类型是 int**
```

`pp` 的类型是 `int**`，读作"指向 `int*` 的指针"。解引用一次得到 `p`（一个 `int*`），解引用两次 `**pp` 才落到 `a` 这个 `int` 上。层级再往上写 `int***` 也合法，但三层以上几乎只在讲语法时出现，实际代码里极少见。

最后一种特殊类型是 `void*`：

```cpp
void* vp = &a;                                    // 任何对象指针都能隐式转成 void*
std::cout << *static_cast<int*>(vp) << std::endl; // 用的时候必须转回具体类型
```

`void*` 表示"指向某种东西的地址，但不说明是什么类型"。它丢掉了类型信息，所以既能接受任何对象指针，也**不能直接解引用**（`*vp` 编译不过）、不能做指针算术。要用它必须先用 `static_cast` 明确转回原来的类型。它存在的意义是在确实需要"只传地址、不关心类型"的接口里做中转。

指针能指向的东西就是"任何有地址的东西"：整数、浮点数、`std::vector` 这类对象、数组元素，以及指针自己。还有一类特殊的存在——**函数指针**（指向函数的指针，例如 `int (*fp)(int);`），它能指向函数而不是数据。本章讲的取地址、解引用、类型匹配这些规则对它是同样的道理，但用法属于另一个话题，知道它存在即可。

## 8 为什么现代 C++ 不鼓励使用原始指针

上面这种能直接声明、能算术、能随意赋值的指针叫做**原始指针**（raw pointer）。它是理解内存的基础，但现代 C++ 的日常代码里通常不鼓励直接使用它，原因有两条：

- **表达力不够。** `int*` 只说明"指向某个 `int`"，看不出它指向的是**一个** `int` 还是**一批** `int` 的第一个。`int* p = new int;` 和 `int* p = new int[10];` 的静态类型完全相同，用错释放方式（该写 `delete[]` 却写 `delete`）编译器不一定能拦住你。
- **释放不安全。** 用原始指针管理动态分配的内存时，释放完全靠人记得写 `delete`。中途提前 `return`、抛异常、或者某个分支漏写，内存就泄漏了；忘记 `delete` 还可以靠经验发现，写成两次 `delete` 则直接是未定义行为，程序可能在任何时候崩溃。

C++ 对此有几类解决办法，正好是后面几章的主线：

| 方案 | 解决什么 | 在哪一章 |
| --- | --- | --- |
| STL 容器（`std::vector` 等） | 分配、扩容、释放全由容器负责，不用碰指针 | 第 07 章已讲 |
| `std::unique_ptr` | 独占所有权：把"谁负责释放"写进类型，离开作用域自动释放 | 第 10 章 |
| `std::shared_ptr` | 共享所有权：多个持有者共同管理，计数归零才释放 | 第 10 章 |
| `std::span` | 传递"一批连续数据"时携带长度，不参与所有权 | 第 10 章 |

所以本章不是要让你以后到处写指针，而是要让你先掌握这个概念：**智能指针和 `span` 都是在原始指针之上包了一层的东西**，不知道底层存的是什么、解引用意味着什么，就没法理解它们为什么能保证安全。本章第 9 节先讲原始指针唯一真正无法回避的场合——自己申请和释放内存。

## 9 为什么需要"运行时才申请内存"

指针的基本用法到这里讲完了，还剩一块必须用到指针的拼图：内存从哪里来。到目前为止，我们用过的内存都来自两种"自动"的方式：

- **局部变量**：进入作用域时产生，离开作用域自动消失。长度在编译期就固定了（`int a;`、`std::array<int, 3> arr;`）。
- **标准库容器**：`std::vector` 在需要更多空间时自己去申请新内存、把元素搬过去、释放旧内存，我们只管 `push_back`；容器销毁时它自己把内存还回去（第 07 章）。

这两种方式都有一个共同前提：**什么时候分配、什么时候释放，都由别人决定**。局部变量由作用域决定，容器由它自己的生命周期决定。

有些场合不满足这个前提。例如：一块缓存要一直留到程序结束；一处代码申请的内存，要交给另一段很远的代码去用，谁都不知道最后是哪个分支先退出；或者要按运行时才知道的大小申请一批数据。这些情况都属于同一类需求——**现在给我一块内存，什么时候还由我说了算**。

理解这件事还有第二个理由：`std::vector` 内部就是靠这套机制工作的。知道 `new` 和 `delete` 怎么做，才知道容器替我们省掉了什么，也才能理解第 10 章智能指针包住的到底是什么。

## 10 `new` 表达式：申请一块内存

`new` 表达式向运行时申请内存，并且返回这块内存的地址。所以**它的结果必须用指针接住**：

```cpp
int* ptr = new int;
```

这一句做了三件事：

1. 申请一块"装得下一个 `int`"的内存；
2. 在这块内存上构造一个 `int`（本例没有提供初值，所以这块内存里此刻的值是不确定的）；
3. 返回这块内存的地址，类型是 `int*`。

第 3 步决定了接收方的类型：既然交回的是地址，就得用指针变量装，`int x = new int;` 是编译不过的（类型不匹配）。

拿到之后，这块内存的用法和平时的 `int` 完全一样，只是只能通过 `ptr` 访问：

```cpp
*ptr = 242;                              // 先写
std::cout << *ptr << std::endl;          // 读出来是 242
```

注意这里的顺序：`new int` 不初始化，**里面是什么值不确定**，所以不能先读后写。要让它一开始就是 0，标准写法是 `new int()`（带一对空圆括号），这是值初始化。

关于失败的处理也值得记一句：`new` 拿不到内存时不是返回空指针，而是抛出 `std::bad_alloc` 异常，正常路径就此中断。所以 `int* p = new int;` 之后**永远不需要判空**——它要么是一个有效地址，要么根本走不到下一句。

## 11 `delete` 表达式：把内存还回去

自己申请的内存不会自动回收，用完之后必须用 `delete` 表达式交还：

```cpp
delete ptr;      // 释放 ptr 指向的那块内存
```

`delete` 做两件事：销毁这块内存上的对象，然后把内存还给运行时。写法上有一个必须记清的点：**直接把指针交给它，不要写星号**。

```cpp
delete ptr;      // 对：ptr 是地址
delete *ptr;     // 错：*ptr 是 int（一个整数值），不是地址
```

释放之后，指针变量里那个地址值并不会被清掉，它成了**悬垂指针**：指向的内存已经不属于你，再解引用就是未定义行为。所以释放之后要立刻把它置空：

```cpp
delete ptr;
ptr = nullptr;   // 这样至少能靠 ptr == nullptr 判断出它已经失效
```

## 12 不释放会发生什么

如果一块内存在程序运行期间反复申请、从不释放，程序占用的内存就会持续增长，最终申请不到内存、以失败告终。这类问题叫**内存泄漏**（leak），而且它有几个不好对付的特点：

- 编译期、运行期都不会有任何提示，`-Wall` 也管不了它——**它不违反语言规则，只是浪费资源**；
- 症状是"跑得越久越慢、最后挂掉"，和逻辑错误混在一起时很难定位；
- 泄漏的量小的时候，程序照样跑完，测试根本发现不了。

这也正是标准库容器值得优先使用的原因：`std::vector` 的分配和释放都由它自己负责，我们不需要写 `delete`，也就不可能漏写。

## 13 `new[]`：一次申请一批对象

需要十个 `int` 时不必分配十次，在 `new` 后面加方括号写元素个数即可：

```cpp
int* data = new int[10];
```

返回类型仍然是 `int*`，但含义变了：**它指向这 10 个 `int` 中第一个的地址**，剩下 9 个紧跟在后面排在同一块连续内存里。这和在栈上声明 `std::array<int, 10>` 的元素布局是类似的，区别只在这块内存的存活时间由 `delete[]` 决定，而不是由作用域决定。

还需要特别留意一点：**`data` 的类型不携带元素个数，个数只存在于你的代码里**。`data` 的类型就是 `int*`，和本章第 2 节那种指向单个 `int` 的指针在类型上完全一样，这是原始指针表达力不足的典型表现。

因为内存是连续的，拿到首元素地址之后就能像数组一样用下标访问：

```cpp
for (int i = 0; i < 10; ++i)
{
    data[i] = i * i;
}
```

下标与解引用是同一件事的两种写法：

- `data[0]` 等价于 `*(data + 0)`，也就是 `*data`；
- `data[i]` 等价于 `*(data + i)`，含义是"从 `data` 指向的位置往后数第 `i` 个 `int`"。

所以 `*data = 242;` 和 `data[0] = 242;` 完全等效，都改的是第一个元素。

这里顺便解释了本章第 7 节提过的那条规则：`data + 3` 不是"地址加 3 个字节"，而是"加 3 个 `int` 的距离"，步长由指针指向的类型决定。两个指向同一块内存的指针相减，得到的是"相隔几个元素"，类型是 `ptrdiff_t`：

```cpp
std::cout << (&data[3] - data) << std::endl;   // 3
```

## 14 `delete` 与 `delete[]` 必须和分配方式对应

释放时的语法取决于当初怎么分配的：

| 分配 | 释放 | 说明 |
| --- | --- | --- |
| `new int` | `delete p;` | 销毁一个对象 |
| `new int[10]` | `delete[] p;` | 销毁一批对象 |

如果 `new` 用了方括号而 `delete` 没用，`delete` 只会按**单个对象**去析构并归还内存，与当初 `new[]` 的分配方式不匹配，属于未定义行为。GCC 在 `-Wall` 下会对这种明显不匹配的写法给出提示：

```text
warning: 'void operator delete(void*, std::size_t)' called on pointer returned from a mismatched allocation function [-Wmismatched-new-delete]
```

这类警告必须当成错误来对待：它指出的不是风格问题，而是一处会让程序在别处崩掉的内存错误。

## 15 一套必须遵守的使用纪律

`new` / `delete` 是把内存管理责任完全交给人的做法，规则不多，但每一条都是硬要求：

1. **成对。** 每一个 `new` 都要有对应的 `delete`，每一个 `new[]` 都要有对应的 `delete[]`。
2. **只释放一次。** 同一块内存 `delete` 两次是未定义行为。实测现象：程序会在第二次 `delete` 处直接异常退出（Windows 上退出码 `0xC0000374`，堆损坏；Linux 上会打印 `free(): double free detected`）。所以释放后立刻把指针置空，也能顺手避免重复释放时手滑。
3. **只释放 `new` 来的内存。** `delete &a;`（`a` 是局部变量）、`delete someArray.data();` 都是错误的：那块内存不归 `new` 管。
4. **不要越过末尾访问。** `data[10]`（合法下标是 0–9）不会报编译错误，运行时也不会立刻报错，这类越界是未定义行为，往往在很远的地方才表现出症状。

只要有一条做不到，就说明这段代码不该用原始指针管理内存，应该改用容器或第 10 章的智能指针。

## 16 什么时候还是应该用 `vector`

本章的例程是为了看清底层机制，实际写代码时选择的顺序应该反过来：

- **默认优先用 `std::vector`**：需要在运行时决定元素个数、需要增删元素、需要自动释放，它全包了，而且不会漏写 `delete`。
- 元素个数在编译期就固定，用 `std::array`（第 03 章）。
- 只有在需要**确切的、单个对象的动态生命周期**，或者要接一个只接受指针的接口时，才轮到手动分配。而即使是这些场合，第 10 章的 `std::unique_ptr`、`std::shared_ptr` 也能把"释放"这一步重新交给类型系统，不必手写 `delete`。

换句话说，本章的落点是：知道 `new`/`delete` 是什么、为什么会出错，然后**尽量不直接用它们**。

### 实验一：地址、解引用与改指向

例程在 `E:\CPP_Code\CppFromScratch\ch17_pointers\` 下，两个程序各占一个文件夹。

**预期输出**（逐字符一致）：

**结果解释**：`b holds the same address as &a: 1` 说明 `b` 存的确实是 `a` 的地址；`after *b = 42` 之后 `a = 42`，说明解引用写的是 `a` 本身。第 3 行和第 9 行都是"地址是否相等"的判定、都输出 `1`，分别对应 `b` 存的是 `a` 的地址、`p` 存的是 `y` 的地址；而第 5、6 行演示改 `b` 指向的内容，第 8、10 行演示改 `p` 的指向，正好说明"改指向"和"改指向的内容"是两件独立的事。

**改值实验**：把 `int a = 5;` 改成 `int a = 100;`，并删掉 `*b = 42;` 那一行（只删赋值语句，`std::cout << "after *b = 42"` 这行保留）。重新编译运行**之前**先预测 Demo A 的输出，再对照实测：

```text
a = 100
b holds the same address as &a: 1
*b = 100
after *b = 42
a = 100
```

跟着初值变的是两个真正被打印的值（`a` 和 `*b` 都变成 100），而最后一行 `a` 不再变成 42——因为那条赋值语句被删掉了。另外要留意 `after *b = 42` 这一行仍然原样输出：它只是一段固定字符串，和变量当前的值没有关系，这类"提示文字没跟着值一起改"是在输出里辨认信息时最常见的误判来源。

### 实验四：分配一批 `int` 并正确释放

`E:\CPP_Code\CppFromScratch\ch18_dynamic_memory\new_array\new_array.cpp` 演示 `new int[10]` 返回首元素地址、下标的连续性、下标与解引用等价、指针相减，以及 `delete[]`。

**预期输出**（逐字符一致）：

