## 学习目标

完成本章后，你应当能够：

1. 说出 `struct` 与 `class` 的唯一区别。
2. 说出 `public`、`private` 各自的作用范围，以及它们默认出现在哪一种类型里。
3. 解释 `p1.x = 10;` 在类外面为什么可能编译失败。
4. 用"私有数据成员 + 公开成员函数"的写法给一个类写出 setter 与 getter。
5. 说明把检查和规则放进 setter 之后，比直接开放数据成员好在哪里。

## 1 从结构体到类：只差一个默认值

第 22 章我们用 `struct` 定义了自己的类型，并且两个对象可以各有各的数据、可以放进容器、可以当函数参数和返回值。现在换一个关键字，做同样的定义：

```cpp
struct Point
{
    int x;
    int y;
};

class Point
{
    int x;
    int y;
};
```

这两段定义几乎一模一样，**在 C++ 里它们唯一的区别只有一个默认值：如果不特别声明，成员的访问权限是什么。** 结构体里默认是公开可访问的，类里默认是私有的。除此之外没有别的差异，所以上一章学到的所有东西——创建对象、点运算符、成员函数、值语义——本章一条都不用重学。

先看"访问权限"到底管什么。C++ 里有三个访问限定符：

| 限定符 | 谁能访问 |
| --- | --- |
| `public` | 任何人：类内部、类外部都能访问这些成员 |
| `private` | 只有这个类自己的成员函数能访问；类外部一律不行 |
| `protected` | 本类与派生类；它只在讲继承的时候才有意义，本章不涉及 |

限定符的**作用范围**是"从它出现的位置开始，直到下一个限定符或者类结束"：

```cpp
class Point
{
    int x;          // 前面没有限定符，所以按 class 的默认规则：private
    int y;          // 同上，private

public:             // 从这里开始改成 public
    void print();   // public
    int getX();     // public

private:            // 又可以改回 private
    int cached;     // private
};
```

也就是说，`public:`、`private:` 不是"给某一个成员贴的标签"，而是**一条分界线**：它切换后面一大段成员的权限，直到下一条分界线。写类的时候习惯把 `public` 的接口放在前面让读者先看到"这个类能做什么"，把 `private` 的实现细节放在后面。

## 2 默认私有意味着什么

在类的定义里什么都不写，那么所有成员都是私有的。此时下面这段代码无法编译：

```cpp
class Point
{
    int x;
    int y;

public:
    void print()
    {
        std::cout << "x = " << x << std::endl;   // 合法：成员函数访问自己的成员
        std::cout << "y = " << y << std::endl;
    }
};

int main()
{
    Point p1;
    p1.x = 10;      // 编译错误：x 是私有的
    p1.print();     // 编译错误：print 也是私有的
}
```

两条语句都会失败，但失败的原因不同、处理方式也不同：

- `p1.x = 10;` 失败，是因为 `x` 是**数据成员**且默认私有。编译器给出的原文是：

  ```text
  error: 'int Point::x' is private within this context
  note: declared private here
  ```

  第二行 `note` 会指到类里声明 `x` 的那一行，方便你确认是谁把访问挡住了。
- `p1.print();` 失败，是因为**成员函数也会受访问限定符的约束**——默认私有的不只是数据，函数同样是私有成员：

  ```text
  error: 'void Point::print()' is private within this context
  ```

**注意 `print` 这个函数体本身是合法的**：它是 `Point` 的成员函数，所以它访问 `x`、`y` 没有任何问题。访问权限约束的是"从类外面伸进去的手"，不是类自己内部的代码。这条规则的道理也在这里：一个类的成员函数之间可以随意协作，因为它们对同一份数据负责；而类外面的代码必须先得到许可，才能碰这些数据。

那么**为什么要把默认值定成这样**？因为这是给类型的作者一个"默认保守"的起点：写 `class` 时，你不写任何限定符，成员就是外人碰不到的，只有你主动写出 `public:` 时，某个成员才成为对外承诺的一部分。反过来，`struct` 的默认值是公开，正好适合第 22 章那种"只是把几个数据捆在一起"的简单类型，此时不需要任何封装。

## 3 把类变成"能用的"：写上 public

要让上面那段代码跑起来，最直接的做法就是像例程 `E:\CPP_Code\CppFromScratch\ch23_classes\class_access\class_access.cpp` 那样，在成员前面加一条 `public:`：

```cpp
class Point
{
public:
    int x;
    int y;

    void print()
    {
        std::cout << "x = " << x << std::endl;
        std::cout << "y = " << y << std::endl;
    }
};
```

这样 `p1.x = 10;`、`p1.y = 20;`、`p1.print();` 全部合法，运行结果和第 22 章的结构体版本一模一样。**把类里所有成员都标成 `public`，这个类就和一个结构体没有实质差别了**——它当然能跑，但也就放弃了类本来要提供的保护。

例程 `class_struct_default` 把两种写法摆在一起：`StructPoint` 什么都不写，`ClassPoint` 补一句 `public:`，两者从创建对象到调用成员函数的行为完全一致；再用一个函数模板接收这两个类型，进一步说明它们都只是普通类型，差别只在"默认谁能访问"。

## 4 封装：哪些成员该公开，哪些该私有

既然一句话就能把所有成员公开，为什么还要折腾访问权限？因为很多类型**自己有规则要守**。看例程 `class_encapsulation` 里的类（略去注释）：

```cpp
class Sensor
{
private:
    int value;

public:
    bool setValue(int newValue)
    {
        if (newValue < 0 || newValue > 100)
        {
            return false;
        }

        value = newValue;
        return true;
    }

    int getValue()
    {
        return value;
    }

    void print()
    {
        std::cout << "value = " << value << std::endl;
    }
};
```

这个类的规则是"`value` 只能落在 0 到 100 之间"。假如 `value` 是公开的，那么 `sensor.value = 999;` 就是一句合法代码，规则被绕过，而且**没有任何地方能拦住它**——等你发现数据不对，已经找不到是哪一行写坏的。把 `value` 变成私有之后：

- 唯一能改动 `value` 的入口是 `setValue`，检查只需要在**一个地方**做；
- 任何人想设值都得走 `setValue`，非法值**根本没机会**写进去；
- 将来范围规则要调整（比如上限改成 200），也只改那一个条件，外部代码不受影响。

这就是**封装**：把数据藏进类里，只对外暴露一组经过设计的操作。它带来的不是"安全"这种虚的好处，而是三条实打实的性质：**规则集中、入口唯一、内部可改**。

**setter 与 getter** 就是这组接口里最常见的两个名字：

- **setter**（也叫设置器）：接收新值、做检查、写进数据成员。命名习惯是 `setXxx`。上例的 `setValue` 返回 `bool`，表示这次设置是否被接受——这一点很重要：调用者需要知道自己的请求生效了没有，而不是设完才发现值没变。
- **getter**（也叫获取器）：把数据成员的值交给调用者。命名习惯是 `getXxx`。它不只是"把变量转手公开"：getter 里同样可以做检查或加工（求平均、换算单位、按需计算等），所以外部拿到的可以是一个"处理过的结果"而不是原始内存。

例程 `class_encapsulation` 的 `main` 里，对外部代码来说 `value` 这个成员根本不存在：设置走 `setValue`，读取走 `print` 和 `getValue`。Demo B 里那个 150 被接口挡下，`value` 仍然是 42——非法值一次都没有进过类的内部。

**但也要知道它的边界**：封装不等于"所有成员都必须配一对 setter/getter"。如果 `getXxx` 只是原样返回一个成员、`setXxx` 只是原样写入一个成员，那等于把数据成员换了个名字公开出去，规则照样可以被绕过——此时用 `struct` 反而更诚实。**判断标准是：这个成员有没有需要保护的规则、有没有外部不该看到的中间状态。** 有，就私有；没有，公开也无妨。

## 5 本章的边界

本章的 `Sensor` 有一个必须注意的地方：`value` 是私有成员，而且**没有初值**。所以这个类在第一次调用 `setValue` 之前，`value` 里的东西是不确定的，此时调用 `print` 或 `getValue` 就是在读一个无效值（第 03 章的老规矩：未初始化的值不能用）。例程里第一条语句就是 `sensor.setValue(42)`，正是为了避开这个坑。

这个别扭之处指向下一章要解决的问题：**能不能让对象在创建的那一刻就带着合法初值，而不是创建完再靠调用者记得去设置？** 这正是构造函数的用途。

### 6.1 实验一：把类用起来（`class_access`）

`class_access\class_access.cpp` 里定义了带 `public:` 的 `class Point`，`main` 创建两个对象、设置成员、调用成员函数。

```text
cd "E:/CPP_Code/CppFromScratch/ch23_classes/class_access"
"E:/msys64/ucrt64/bin/g++.exe" -std=c++20 -Wall -g class_access.cpp -o class_access.exe
./class_access.exe
```

**预期输出**：

```text
=== Demo A: 类里写了 public: 之后，用法和结构体一样 ===
x = 10
y = 20
=== Demo B: 第二个对象同样可以自由设置 ===
x = 5
y = -5
```

**验收标准**：输出逐字符一致，编译 `-Wall` 无警告。

**改值实验（本章最重要的一次）**：把 `class_access.cpp` 里的 `public:` 这一行**删掉或改成 `private:`**，重新编译。

**预判**：编译失败，`main` 里六条访问语句会各自报一次错，依次是：

```text
error: 'int Point::x' is private within this context
error: 'int Point::y' is private within this context
error: 'void Point::print()' is private within this context
error: 'int Point::x' is private within this context
error: 'int Point::y' is private within this context
error: 'void Point::print()' is private within this context
```

前三条来自 `p1`，后三条来自 `p2`。可以看到**数据成员和成员函数一样受约束**：`print` 也是私有成员，从 `main` 里调不到。再往上翻还能看到 `note: declared private here` 指回类定义里 `int x;` 的位置。看完把 `public:` 还原，重新编译通过。这次实验说明：**类里能不能从外面访问成员，完全由限定符决定；默认值就是 `private`。**

### 6.2 实验二：私有数据 + 公开接口（`class_encapsulation`）

`class_encapsulation\class_encapsulation.cpp` 里 `value` 是私有成员，外部只能通过 `setValue`、`getValue`、`print` 接触它；`setValue` 拒绝 0..100 之外的值。

```text
cd "E:/CPP_Code/CppFromScratch/ch23_classes/class_encapsulation"
"E:/msys64/ucrt64/bin/g++.exe" -std=c++20 -Wall -g class_encapsulation.cpp -o class_encapsulation.exe
./class_encapsulation.exe
```

**预期输出**：

```text
=== Demo A: 设置一个合法值 ===
设置 42 成功
value = 42
=== Demo B: 超出范围的值被接口挡下 ===
设置 150 被拒绝
value = 42
=== Demo C: 再用 getter 读取一次 ===
设置 77 成功
value = 77
```

**验收标准**：输出逐字符一致，编译 `-Wall` 无警告。Demo B 的两行输出（被拒绝 + 值仍是 42）说明非法值没有穿过接口。

**改值实验一**：在 `main` 末尾加一行 `sensor.value = 999;`，重新编译。**预判**：编译失败，报错为 `error: 'int Sensor::value' is private within this context`。这正说明"封装的规则由编译器强制执行"，不是靠约定。

**改值实验二**：把 `setValue` 里的条件从 `newValue < 0 || newValue > 100` 改成 `newValue < 0 || newValue > 200`，重新编译运行。**预判**：Demo B 变成 `设置 150 成功`，随后的 `value = 150`。范围规则只改了一处，外部代码（Demo A、C 的调用）一个字都不用动——这就是"规则集中"的价值。看完把改动还原。

**改值实验三**：把 `setValue` 末尾那句 `return true;` 删掉，重新编译。**预判**：出现警告

```text
warning: control reaches end of non-void function [-Wreturn-type]
```

函数仍然能编译，但返回值不确定（第 08 章讲过的同一类问题）。看完补回去——这也提醒我们 `-Wall` 的警告必须逐条看完。

`class_struct_default\class_struct_default.cpp` 里 `StructPoint` 不写任何限定符，`ClassPoint` 写 `public:`，两者用法对照；最后用一个函数模板接收这两种类型。

**预期输出**：

**验收标准**：输出逐字符一致，编译 `-Wall` 无警告。Demo C 里同一个模板函数对两种类型都工作，说明它们都只是普通类型。

## 7 常见错误与排查

| 报错或现象 | 原因 | 处理 |
| --- | --- | --- |
| `error: 'int Point::x' is private within this context`（并附 `note: declared private here`） | `class` 的成员默认私有，从类外面用点运算符直接访问了它 | 如果这个成员本来就该公开，加 `public:`；否则改为通过公开的成员函数读写 |
| `error: 'void Point::print()' is private within this context` | 成员函数也受访问限定符约束，默认私有的 `print` 不能在类外调用 | 把成员函数放进 `public` 段；注意报错只出现在写代码的地方，函数体本身没问题 |
| `warning: control reaches end of non-void function [-Wreturn-type]` | `setValue` 声明返回 `bool`，但某条路径上没有 `return` | 每条路径都返回；这类警告意味着调用处拿到的结果不可信 |
| `sensor.value = 999;` 编译不过，但把成员改成 `public` 之后就"修好"了 | 绕开接口去改数据，规则被跳过 | 不要为了让它编译过去而开放数据成员；用 setter 表达"我想改这个值"的意图 |
| `setValue(150)` 返回 `false`，但值没变被当成 bug | 调用处忽略了 setter 的返回值，以为设置已经生效 | 用 `if` 接住返回值并在失败时给出反馈，或者让非法值有明确的处理方式 |
| 所有成员都写成 `public`，类里定好的检查形同虚设 | 只写了检查却不限制访问入口，任何人都能直接改数据 | 把数据成员移到 `private`，只保留必要的公开接口 |
| 创建对象后忘了先设置私有的数据成员，直接打印得到怪值 | 私有成员没有初值，读它就是读一个未初始化的变量 | 使用前先通过接口赋值；更彻底的办法是让对象在创建时就带初值——这正是下一章构造函数要解决的 |
| 接口里给每个成员都配了原样进出的 `setXxx` / `getXxx` | 把成员"换了名字"公开出去，并没有真正封装 | 只在确有规则需要保护时提供接口；没有规则可守时，用 `struct` 更直接 |
