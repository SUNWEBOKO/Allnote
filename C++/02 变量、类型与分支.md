## 学习目标

完成本章后，你应当能够：

1. 用"类型 名字 = 初值;"的写法定义并初始化变量。
2. 用 `auto` 把类型推断交给编译器。
3. 用关系运算符写出结果为真或假的条件，不把 `=` 误写成 `==`。
4. 用 `if`、`if / else` 和 `if / else if / else` 链让程序按条件选择执行路径。
5. 用花括号写清每个 `if` / `else` 的归属，避开悬挂 `else`、条件后多写分号这类结构陷阱。

## 1 变量：给值起名字

程序里到处都是值：`10`、`20.7`、`true` 都是值。但直接把值写在代码里有两个麻烦。

一是**不可读**。`3.14159265` 出现在公式中间，读者得自己猜这是圆周率还是某个测得的数据。二是**不可维护**。同一个值在十几个地方用到，要改就得改十几处，漏一处就出现前后不一致。

解决方法是给值起名字：

```cpp
int var_one = 10;
```

这行代码之后，`var_one` 就是 `10` 的名字。凡是用到 `var_one` 的地方，都是在使用那个值；要改这个值，改定义的那一行就行。

**变量就是"一块内存 + 一个名字 + 一个类型"。** 名字让你能引用它，类型告诉编译器这块内存该按什么规则来解释，内存里放的就是当前的值。

## 2 类型是变量定义的一部分

第 01 章说过：程序里的每一个值都属于某个类型，类型决定这个值能参与哪些运算。变量是值的名字，所以**变量也必须带类型**——否则编译器无法知道这块内存该怎么解释、能存什么、能做什么运算。

所以变量定义的第一件事就是写类型，第二件事才是写名字。

### 2.1 基础类型一览

| 类型 | 表示什么 | 说明 |
| --- | --- | --- |
| `bool` | 真 / 假 | 取值只有 `true` 和 `false`，本章第 8 节的条件判断就靠它 |
| `char` | 单个字符 | 例如 `'A'`、`'7'`，用单引号写 |
| `int` | 正负整数 | 最常用的整数类型，本机是 4 字节，范围约 $\pm 2.1\times 10^{9}$ |
| `unsigned int` | 非负整数 | 不能表示负数，因此正数上限约是 `int` 的两倍 |
| `short` / `long` / `long long` | 宽度不同的整数 | 用于表示比 `int` 更小或更大的整数范围 |
| `float` | 单精度浮点数 | IEEE-754 格式，约 7 位十进制有效数字 |
| `double` | 双精度浮点数 | 同样遵循 IEEE-754，精度约 15～16 位十进制有效数字 |

两点提醒：

- **整数类型分有符号和无符号。** 默认的 `int` 是有符号的，能表示负数；`unsigned int` 只能表示非负数。本课程绝大多数场合直接用 `int`，不做位运算或只关心非负计数时才考虑 `unsigned`。
- **具体宽度由平台决定，标准只给了下限。** 想知道本机上某个类型占几个字节，可以用 `sizeof` 观察，例如打印 `sizeof(int)`。**不要凭猜测假设某个类型一定是几字节**，尤其在跨平台时。

### 2.2 浮点类型用来表示小数

`float` 和 `double` 用来处理带小数点的数值，遵循 IEEE-754 标准的二进制浮点格式：在遵循 IEEE-754 的主流平台上，`float` 占 4 字节，`double` 占 8 字节。精度的差别决定了两者的使用场合——本课程默认用 `double`，它在需要小数的计算里精度更充足。

## 3 定义与初始化

### 3.1 定义的语法

```cpp
int var_one = 10;
```

拆开看：`int` 是类型，`var_one` 是变量名，`=` 后面的 `10` 是初值，行末的分号结束这条语句。

这里的 `=` **不是数学里的"等于"**，而是"初始化"：把右边的值放进左边这块内存。数学里的"等于"在 C++ 里是 `==`（本章第 8 节会用到），两个符号千万不要混淆。

变量名自己起，规则是：字母、数字、下划线组成，不能以数字开头，不能是关键字（`int`、`return` 这类）。命名要有意义，`var_one`、`temperature` 这类名字过一个月再看还能看懂。

### 3.2 定义和初始化写在同一行

下面这种写法能编译通过，但不推荐：

```cpp
int x;      // 只要了一块内存，没有初始化
x = 10;     // 到这一行才把 10 放进去
```

问题出在中间那段"还没有值"的窗口里：`x` 的内容是不确定的（那块内存上一次被谁用过、留下什么数据都有可能）。如果在 `x = 10` 之前就读了 `x`，程序会拿到一个毫无意义的数，而且**编译器通常不会为此报错**——它只是"不确定值"，不是语法错误。这类错误排查起来非常费劲：程序有时候正常、有时候乱算，换个环境重现不了。

正确做法是把定义和初始化写在一起：

```cpp
int var_one = 10;
int var_two = 20;

// 右边可以是表达式：先把两个变量的值取出来相加，结果再存进 var_three
int var_three = var_one + var_two;
```

**结论：定义变量的同时就给它一个初值，不留"未初始化"的时间窗口。**

### 3.3 变量存的是值，不是公式

`var_three = var_one + var_two` 执行完之后，`var_three` 里存的是 `30` 这个**数值本身**。之后再修改 `var_one`，`var_three` 不会跟着变——它只是当初被赋了一个值，和另外两个变量之间没有持续的联系。这一点看起来显而易见，但初学者经常把变量当成代数里的符号关系来理解，进而在改了一个变量后奇怪为什么另一个没变。

### 3.4 用变量名代替字面量

`var_three` 也可以写成：

```cpp
int var_three = 10 + 20;    // 和上面等价，但意义不明
```

能跑，但失去了全部好处：读代码的人不知道 `10` 和 `20` 是什么，以后想把两个数都加倍还得改两处。**用变量名代替散落的字面量**，是让代码可读、可改的第一步。

## 4 变量参与运算

变量就是它所代表的那个值，所以整数变量可以参与整数能做的所有运算，和直接写数字没有区别：

```cpp
int a = 7;
int b = 2;

int sum = a + b;    // 9
int diff = a - b;   // 5
int prod = a * b;   // 14
int quo = a / b;    // 3 —— 两个整数相除，结果还是整数，小数部分被丢掉
int rem = a % b;    // 1 —— 取余
```

这里只提一个容易踩的坑：`a / b` 写出来是 `7 / 2`，结果是 `3` 而不是 `3.5`，因为**两个整数相除，结果仍然是整数，小数部分直接被舍去**。想要得到小数结果，至少要让其中一个操作数是浮点类型（例如 `double(7) / 2`）。这是整数类型带来的行为，和第 01 章讲的"类型决定运算的含义"完全一致。

## 5 打印变量

变量可以直接送进 `std::cout`，用法和第 01 章打印字面量一样：

```cpp
std::cout << var_three << std::endl;    // 输出 30
```

真正值得记住的是：**输出格式由变量的类型决定**。把三个变量都改成 `double`：

```cpp
double var_one = 10.5;
double var_two = 20.7;
double var_three = var_one + var_two;

std::cout << var_three << std::endl;    // 输出 31.2
```

打印语句**一行都不用改**，因为它不关心变量的类型是什么，只负责把值按该类型对应的文本形式送出去。整数按十进制打印，浮点按小数形式打印，这件事由流的实现和值的类型共同决定。

## 6 auto：把类型推断交给编译器

### 6.1 重复的信息

上面这段代码里有一处冗余：

```cpp
double var_one = 10.5;
double var_two = 20.7;
double var_three = var_one + var_two;
```

`var_one = 10.5` 已经说明了它是浮点数，我们又特意写了 `double`；`var_three` 更是如此——两个 `double` 相加，结果必然是 `double`。**类型信息其实重复了两遍。** 既然编译器本来就能从初值算出来，让我们每次再手写一遍就是白做工。

### 6.2 用 auto 让编译器推断

把类型位置写成关键字 `auto`，意思是"类型由你（编译器）来推断"：

```cpp
auto var_one = 10;              // 初值是整数字面量 -> var_one 是 int
auto var_two = 20;              // -> int
auto var_three = var_one + var_two;   // int + int 仍是 int -> int
```

推断规则很直接：**看初始化表达式右边是什么类型，左边的变量就是什么类型**；推断结果还能顺着表达式往下传递。把初值改成 `10.5`、`20.7`，三个变量就都变成 `double`，程序行为和手写 `double` 完全一样。

`auto` 不改变程序运行时的任何行为，它只是让我们少写一遍类型名——这种"让代码更简洁但不改变语义"的写法叫**语法糖**。

### 6.3 auto 必须同时初始化

这一点和本章第 3 节讲的"定义即初始化"正好呼应，而且这次是编译器**强制**的：

```cpp
auto var;      // 编译错误
```

编译器会给出：

```text
error: declaration of 'auto var' has no initializer
```

原因很直白：`auto` 的类型完全来自初始化器。编译器必须"看到"右边是 `10` 还是 `10.5`，才知道该给这个变量分配多大内存、按什么类型解释它。只写 `auto` 和名字、后面没有初值，编译器没有任何线索可推，只能报错。

顺便说，这也解释了为什么普通类型可以不初始化而 `auto` 不行：写 `int x;` 时你明确告诉了编译器类型，它照办即可；写 `auto x;` 时你把类型也交出去了，那就必须给出推断的依据。

### 6.4 什么时候该用 auto

`int`、`double` 这种又短又清楚的类型名，**手写反而更好读**——用 `auto var_one = 10;` 会让读者少看到一条信息，收益为零。`auto` 的价值在类型名很长、很难写的时候才体现出来，例如后续会遇到的迭代器类型：

```cpp
std::vector<int>::iterator it = myVector.begin();   // 手写一长串
auto it = myVector.begin();                         // 让编译器替我们写
```

另外，用 `auto` 还有一个附带好处：如果以后右边的表达式类型变了，用 `auto` 的地方不用跟着改，需要修改的地方更少。

**取舍原则**：类型短而明确就写出来，类型长而啰嗦就用 `auto`。

变量和类型都准备好了，但目前的程序仍然只会从头到尾顺序执行。接下来让程序学会根据条件的真假走不同的路。

## 7 让程序做决定

前面几章的程序都是从上到下把每条语句执行一遍，一条不落。但真实需求里，很多代码只在特定情况下才该执行：余额足够才扣款，输入合法才继续处理，温度超限才报警。

C++ 用**条件语句**来表达这种"看情况执行"。最基础的两个关键字是 `if` 和 `else`：如果某个条件成立就执行一段代码，否则执行另一段，或者干脆什么都不做。

本章第 2 节提到 `bool` 类型只有"真 / 假"两个取值。条件语句正是围绕这个类型工作的——先算出一个真/假，再根据它决定走向。

## 8 条件：结果为真或假的表达式

### 8.1 关系运算符

判断两个值的大小关系，用**关系运算符**：

| 运算符 | 含义 | 例子 | 结果 |
| --- | --- | --- | --- |
| `<` | 小于 | `5 < 10` | 真 |
| `<=` | 小于或等于 | `10 <= 10` | 真 |
| `>` | 大于 | `5 > 10` | 假 |
| `>=` | 大于或等于 | `5 >= 10` | 假 |
| `==` | 等于 | `10 == 10` | 真 |
| `!=` | 不等于 | `5 != 10` | 真 |

这些都是**双目运算符**：左右各要一个操作数，写出来就是"a 与 b 的关系是否成立"。

### 8.2 条件的结果是 bool

关系表达式的求值结果是一个 `bool` 值：**成立就是 `true`（真），不成立就是 `false`（假）**。也就是说

```cpp
a < b     // 这里不是问"a 是不是小于 b"，而是算出"a 小于 b 这件事"的真假值
```

`a` 是 5、`b` 是 10 时，这个表达式算出来的就是 `true`。`if` 语句做的事情，就是把这个真假值拿来用。

### 8.3 `=` 与 `==` 的分工

这里必须停一下，因为它是最容易出错的一处：

- `=` 是**赋值**：把右边的值写进左边的变量。`a = 10;` 的结果是 `a` 变成了 10。
- `==` 是**比较**：判断两边的值是否相等，结果是一个 `bool`。`a == 10` 不改变任何变量，只是算出一个真假值。

补充一点：`if` 的条件并不要求一定是 `bool`——非 `bool` 值（如 `int`、指针）会被隐式转换成 `bool`，**0 为假、非 0 为真**。下面那个错误能编译通过，正是因为这个转换。

在条件里写错成 `if (a = b)` 时，含义从"比较 a 和 b 是否相等"变成了"把 b 的值赋给 a，然后用这个值当条件"——赋值是有结果的（结果就是赋进去的那个值），所以它能编译通过，但逻辑完全变了，而且往往是"看起来正常"地跑出错误结果。**好在这个错误编译器一般会警告**，报错信息里通常含有 `suggest parentheses around assignment used as truth value` 这样的字样，看到就立刻检查是不是把 `==` 写成了 `=`。

## 9 `if` 语句：条件为真才执行

```cpp
int a = 5;
int b = 10;

if (a < b)
{
    std::cout << "a is less than b" << std::endl;
}
```

结构是 `if` 关键字 + 一对小括号 + 一个代码块：

- 小括号里放的是**要检查的条件**，也就是一个能算出真/假值的表达式；
- 后面那对花括号划出一个**代码块**，是条件为真时才会执行的语句。

执行流程是：先求 `a < b` 的值；为真就执行花括号里的所有语句；为假就**整块跳过**，直接执行这一整段 if 之后的下一条语句。

这里有个初学者常常误判的地方：**条件为假不代表出错了**。跳过就是 if 的正常行为之一，程序安静地继续往下走。所以屏幕上什么都没打印，很可能只是走到的分支里没有输出语句而已。

## 10 `if / else`：两条路选一条

很多时候条件为假也需要做点事。这时在 if 后面接一个 `else` 分支：

```cpp
if (a < b)
{
    std::cout << "a is less than b" << std::endl;
}
else
{
    std::cout << "a is not less than b" << std::endl;
}
```

`else` 后面**不写条件**，因为它唯一的进入条件就是"上面那个 if 的条件不成立"。它负责的是条件的假分支，不需要你重写一遍条件表达式。

这一段最重要的性质是**互斥**：`if` 和 `else` 是一对分支，**最多只会执行其中一个，永远不可能两个都执行**。走哪条路只取决于运行到这里时 `a` 和 `b` 的实际值。理解这一点，才能预判程序会打印什么——先把值代入条件算真假，再看哪一块会被执行。

## 11 `if / else if / else` 链：三种以上情况

需要区分"小于""等于""大于"三种情况时，在 else 后面再挂一个 `if`，形成链式结构：

```cpp
if (a < b)
{
    std::cout << "a is less than b" << std::endl;
}
else if (a == b)
{
    std::cout << "a equals b" << std::endl;
}
else
{
    std::cout << "a is greater than b" << std::endl;
}
```

执行规则是**从上往下逐个测试条件，命中一个就执行它的代码块，然后整条链剩下的部分全部跳过**。所以一条链跑一次只会命中一条分支。

链最后那个 `else` 不需要写条件，因为逻辑上已经穷尽了：如果 a 既不小于 b 也不等于 b，那么 a 必然大于 b。**省略最后一个条件，同时也省掉了一次多余的比较。**

反过来说，如果条件之间没有穷尽关系（比如只关心"是负数"和"是零"，其余情况不做处理），就不要写最后的 `else`，让它自然跳过即可。

## 12 嵌套

代码块里可以再写完整的条件语句，层数没有限制：

```cpp
else
{
    std::cout << "a is greater than b" << std::endl;

    if (a == 15)
    {
        std::cout << "a equals 15" << std::endl;
    }
}
```

这段的含义是：先按外层条件走，走到 else 分支后**再做一次更细的判断**。外层 if 的条件为假时，内层根本不会被求值。

嵌套带来一个必须留意的规则：**`else` 只和最近的那个还没有 else 的 `if` 配对**。因此像下面这样写是很危险的：

```cpp
if (a < b)
    if (a > 0)
        std::cout << "ok" << std::endl;
else
    std::cout << "not ok" << std::endl;   // 这个 else 属于内层 if，不是外层
```

看起来像是给外层 if 配的 else，实际上按规则它属于内层那个 `if`。**避免这种误读最省事的办法，就是无论代码块里有几条语句都写花括号**，让每个 `if` / `else` 的归属一眼可见。

### 实验四：条件语句例程

**例程的组织方式**：这一个程序把本章三件事各演示了一遍，用三行分隔文字标明在演示哪一部分，每段各自用一对花括号包成一个独立的代码块：

```cpp
{
    // 这一段里定义的 a、b 只在这里有效
}
```

之所以这样安排，是为了让三段演示里的 `a`、`b` 各自独立、互不干扰，同一个名字可以在每一段里重新定义和取值。这也是花括号的另一种用途：**它划出的不只是"要不要执行"，还有"这个名字在哪里有效"**。

**预期现象**：运行后应输出九行：

```text
=== Demo A: single if ===
a is less than b
=== Demo B: if / else ===
a is not less than b
=== Demo C: if / else if / else ===
a is less than b
a equals b
a is greater than b
a equals 15
```

对照阅读：

- **Demo A** 里 `a = 5`、`b = 10`，`a < b` 成立，所以打印了那一行。
- **Demo B** 里 `a = 10`、`b = 5`，`a < b` **不成立**，走 else 分支，因此打印的是 `a is not less than b`。
- **Demo C** 用三组不同的值各跑了一遍同一条链（中间那一层用 `a == b` 判断），所以三条分支各出现一次；最后一轮 `a = 15 > b = 10` 落进 else，并在 else 内部命中了嵌套的 `if (a == 15)`，于是多打印一行 `a equals 15`。

**验收标准**：

1. 输出九行，内容与上面逐字符一致（分隔行用英文，是为了避开 Windows 控制台的编码问题）。
2. 编译过程 `-Wall` 无警告——特别不该出现赋值误用为条件的警告。
3. 改值实验：把 Demo C 第一轮的 `a` 依次改成 `10`、`20` 并重新编译，能预判并验证输出如何变化——`a = 10` 时命中中间一层打印 `a equals b`；`a = 20` 时落进 else 但嵌套条件不成立，只打印 `a is greater than b`。
