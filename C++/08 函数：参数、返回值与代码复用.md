## 学习目标

完成本章后，你应当能够：

1. 说出一个函数由哪四个部分组成。
2. 定义并调用一个不返回值的函数。
3. 定义并调用一个带返回值的函数，并在调用处接住返回值。
4. 说明形参与实参的关系，以及函数内改动形参为什么不影响外面。
5. 说出把重复代码提取成函数之后，代码好在哪里。

## 1 为什么需要函数

到这里，我们已经掌握了三种控制流：

- **条件语句**让代码**有选择地执行**（第 04 章）；
- **循环**让代码**重复执行**（第 06、07 章）；
- **函数**是第三种：它给一段语句序列**起一个名字**，之后用这个名字就能把那段语句执行一遍。

为什么需要它？因为有一类重复**不适合用循环解决**。假设你要打印数组，第 05 章的做法是写一段范围 `for` 加一句换行：

```cpp
for (int value : myArray1)
{
    std::cout << value << " ";
}
std::cout << std::endl;
```

只用一次没问题。但如果程序要先打印 `myArray1`、中间做别的事、再打印 `myArray2`、最后还要再打印一次 `myArray1` 呢？这四行会被复制三份。这时**不能用循环**——这几次调用不是连续发生的，中间隔着别的操作，而且每次处理的数组还不一样。你也不想在程序里留下三份一模一样、将来改格式要改三处的代码。

解决办法就是把这段代码**提取出来、起个名字**，以后需要时就写这个名字。这个"有名字的语句块"就是函数。前面七章里我们一直在用函数，只是写的一直是最特殊的那一个：`main`。

## 2 函数的四个组成部分

回忆第 01 章拆解过的 `main`：

```cpp
int main()
{
    return 0;
}
```

它由四部分组成，**任何函数都是这四部分**：

| 组成 | 在 `main` 里 | 作用 |
| --- | --- | --- |
| 返回类型 | `int` | 函数执行完之后交回什么类型的值；不交回任何值就写 `void` |
| 函数名 | `main` | 调用时使用的名字 |
| 参数列表 | `()` | 调用这个函数时必须提供哪些输入；不接收输入就留空 |
| 函数体 | `{ return 0; }` | 调用时真正执行的那些语句 |

`main` 的特殊之处只有一点：它是程序执行的起点。**除此之外，它的结构和我们接下来要自己写的函数完全一样。**

## 3 定义并调用一个不返回值的函数

例程 `E:\CPP_Code\CppFromScratch\ch08_functions\print_array\print_array.cpp` 里把打印数组的工作提成了一个函数：

```cpp
void printArray(std::array<int, 3> array)
{
    for (int value : array)
    {
        std::cout << value << " ";
    }
    std::cout << std::endl;
}
```

逐部分看：

- **返回类型 `void`**：`void` 的意思是"没有值"。这个函数只负责把数组打到屏幕上，算不出也不需要交回任何结果，所以返回类型是 `void`，函数体里也**没有、不需要 `return` 语句**。
- **名字 `printArray`**：见名知意——读者看到调用处写 `printArray(...)`，不用再去看函数体就知道这里在做什么。**给函数起一个能说明动作的名字，是函数能不能提升可读性的关键。**
- **参数列表 `(std::array<int, 3> array)`**：这是函数的输入清单。这里声明"我需要一个能装 3 个 `int` 的数组"，前半段是**类型**，后半段的 `array` 是这个输入在函数体内的**名字**（第 5 节会讲这个名字的性质）。
- **函数体**：真正执行的语句，这里是第 05、06 章学过的元素访问和范围 `for`。

**定义好之后，调用就只是写一行名字加实参**：

```cpp
int main()
{
    std::array<int, 3> myArray1 {1, 2, 3};
    std::array<int, 3> myArray2 {4, 5, 6};

    printArray(myArray1);
    printArray(myArray2);

    return 0;
}
```

### 3.1 调用时发生了什么

调用 `printArray(myArray1);` 这一句时，控制流是这样的：**程序跳到 `printArray` 的函数体，从第一条语句开始执行，把整个函数体跑完，然后回到调用处，继续执行下一句。** 所以上面 `main` 的执行顺序是：创建两个数组 → 打印第一个 → 打印第二个 → `return 0`。

函数体里那段范围 `for` 加换行的代码只写了一份，却运行了两次，每次处理的是不同的数组。

### 3.2 一个函数只做一件事

`printArray` 只做打印。这不是偶然的——**把功能拆成"只做一件事"的小函数**，好处是这个函数容易看懂、容易测试、容易被别处复用。反过来，如果写一个函数既打印又求和又修改数组，它的名字就没法起得准确，调用它的人也无法预料副作用。

## 4 带返回值的函数

`void` 函数只做事、不交结果。如果函数要**算出一个结果交回调用处**，返回类型就写成结果的类型，并在函数体里用 `return` 把值交出去。

`ch08_functions\return_value\return_value.cpp` 里的求和函数：

```cpp
int sum(std::array<int, 3> array)
{
    int total = 0;

    for (int value : array)
    {
        total += value;
    }

    return total;
}
```

四点要注意：

- **返回类型是 `int`**：这个函数做的事是把若干整数加起来，整数相加的结果仍是整数（第 03 章讲的类型规则），所以用 `int` 装结果正合适。
- **累加器必须初始化。** `int total = 0;` 这一句不能省：如果只写 `int total;`，它里面是什么值没有保证，从这个不确定值往上加，结果自然也是错的。这和第 03 章"不要留下未初始化的变量"是同一条规则。
- **`total += value;`** 是 `total = total + value;` 的简写：先算右边的新总和，再存回 `total`，于是它一轮一轮地变大。
- **`return total;`** 做两件事：**立刻结束这个函数的执行**（函数体里 `return` 之后的语句都不会再执行），并把 `total` 的值交回调用处。

### 4.1 在调用处接住返回值

函数交回的值需要有地方存放：

```cpp
int result = sum(myArray);      // 用变量接住
std::cout << result << std::endl;
```

也可以让编译器推断类型：

```cpp
auto result = sum(myArray);     // result 被推断成 int，因为 sum 的返回类型是 int
```

之所以可以这样写，是因为 `sum` 的**返回类型已经明确写了 `int`**——推断的依据是现成的，用 `auto` 只是省掉我们重复写一遍类型名（第 03 章 7.4 节的原则：类型短而明确就写出来）。

返回值不接住也能编译（比如直接写 `sum(myArray);`），但那个结果就被丢掉了，这个调用等于白做——**除非你调用它的目的就是它内部的副作用**（例如 `printArray` 那种只打印的 `void` 函数）。

### 4.2 返回类型不是 `void` 时必须 `return`

漏写 `return` 时，编译器会给出警告：

```text
warning: no return statement in function returning non-void [-Wreturn-type]
```

注意这**只是警告，不是错误**——程序照样能编译出可执行文件，但调用处拿到的返回值是不确定的（未定义行为）。这类"能编译、结果乱"的问题最难查，所以 `-Wall` 打开的警告必须逐条看完。本课程的编译任务都带了 `-Wall`，就是为了让这类问题第一时间暴露。

## 5 形参与实参：一份副本

函数定义里 `(std::array<int, 3> array)` 中的 `array` 叫**形参**（形式参数），调用时传进去的 `myArray1` 叫**实参**（实际参数）。两者是"一份副本"的关系：

- 形参 `array` 是实参 `myArray1` 的一份**拷贝**。函数内部操作的是这份拷贝。
- 因此**在函数里改动 `array` 不会影响外面的 `myArray1`**。这个性质在"函数只读取数据、不修改原数据"时正好合适，`printArray` 和 `sum` 都属于这种情况。
- 名字也不必相同：调用时写 `printArray(myArray1)`，函数内部用的名字仍然是 `array`。函数内部只认自己的形参名。

**这里要明确一个边界**：按值传参意味着**每次调用都会复制整个数组**，元素很多时会有额外的时间和内存开销。更高效的传参方式（按引用传参、以及"只读引用"）会在后续课程里讲，本章先用最直观的副本形式把函数的基本结构立起来。

## 6 用函数换来了什么

回到第 1 节那段被复制三份的打印代码，现在它变成了三次一行调用。三个好处：

1. **不再有重复代码。** 打印逻辑只有一份。
2. **调用处一眼可见意图。** `printArray(myArray2);` 摆在那里，读者不需要逐行辨认一段循环到底在做什么。
3. **修改只在一处生效。** 将来想把输出格式从"空格分隔"改成"逗号分隔"，只改函数体里的那一处，所有调用自动跟着变；而复制三份的写法要改三处，漏一处就出现行为不一致。

还有一条容易被忽略的好处：**函数可以在程序的任何位置被调用**。前面几章的处理逻辑都得挤在 `main` 里按顺序写下来，一旦某段逻辑需要在开头、中间、结尾各用一次，就只能复制。有了函数，这段逻辑从 `main` 里搬出去、起了名字，需要时调用一次即可——`main` 也变得短了，读起来像一份提纲：创建数据、调用函数、输出结果。

## 7 动手实验

例程在 `E:\CPP_Code\CppFromScratch\ch08_functions\` 下，两个程序各占一个文件夹。

### 7.1 实验一：`void` 函数与复用

`print_array\print_array.cpp` 里定义了 `void printArray(std::array<int, 3> array)`，`main` 里对两个数组各调用一次。

```text
E:\msys64\ucrt64\bin\g++.exe -std=c++17 -Wall -g print_array.cpp -o print_array.exe
./print_array.exe
```

**预期现象**：输出两行，注意每个数字后面跟一个空格，所以行末也各有一个空格：

```text
1 2 3 
4 5 6 
```

**验收标准**：两行内容为 `1 2 3 ` 与 `4 5 6 `（含行末空格），编译 `-Wall` 无警告。

**复用验证**：在 `main` 里再加一个 `std::array<int, 3> myArray3 {7, 8, 9};` 并调用 `printArray(myArray3);`，**不对 `printArray` 做任何修改**，重新编译运行应该多输出一行 `7 8 9 `。这直接说明函数一次写好就能服务任意多个数据。

### 7.2 实验二：带返回值的函数

`return_value\return_value.cpp` 里定义了 `int sum(std::array<int, 3> array)`，`main` 里创建 `{1, 2, 3}` 并打印求和结果。

**预期现象**：输出一行

```text
6
```

**验收标准**：输出为 `6`（即 1 + 2 + 3）。把数组初值改成 `{5, 5, 5}` 后重新编译运行，应输出 `15`——函数体同样一行都不用改。

**边界验证**：把 `sum` 里的 `return total;` 注释掉再编译，应看到 `warning: no return statement in function returning non-void [-Wreturn-type]`。确认这只是警告、程序仍然能生成（但结果不可信），看完还原。

### 7.3 实验三：把定义挪到调用之后

把整个 `printArray` 函数**剪切到 `main` 之后**，重新编译。

**预期现象**：编译失败：

```text
error: 'printArray' was not declared in this scope
```

**原因**：编译器是从上往下读源文件的。读到 `main` 里那句调用时，它还没见过 `printArray` 这个名字，于是无从判断该怎么调用。**函数必须先被声明（通常就是先定义），才能被调用。**

**验收标准**：能说清报错的原因。看完把函数挪回 `main` 之前，重新编译通过。更一般的做法（先声明、后定义，从而不受顺序限制）属于后续内容，本章的规则是**先定义、后使用**。

## 8 常见错误与排查

| 报错或现象 | 原因 | 处理 |
| --- | --- | --- |
| `error: 'printArray' was not declared in this scope` | 函数定义写在了调用它的代码之后 | 把定义挪到前面（本章规则：先定义后使用） |
| `warning: no return statement in function returning non-void` | 返回类型不是 `void`，函数体里却漏了 `return` | 补上 `return 值;`；注意这只是警告，程序能编译但结果不可信 |
| `error: return-statement with no value, in function returning 'int'` | 写了 `return;` 但返回类型不是 `void` | 要么 `return 值;`，要么把返回类型改成 `void` |
| `error: invalid conversion from 'const char*' to 'int'` | `return` 后面的值类型和返回类型不匹配 | 让返回的表达式类型与返回类型一致 |
| `error: could not convert 'b' from 'array<[...],5>' to 'array<[...],3>'` | 调用时给的实参类型和形参类型不一致（元素个数不同也算不同类型） | 核对两边的类型，尤其是 `std::array` 尖括号里的元素类型和个数 |
| `error: too few arguments to function` | 调用时参数个数少于函数要求的 | 按参数列表补全实参 |
| 调用函数后，外面的数组没被修改 | 形参是实参的**副本**，函数内改的是副本 | 这是按值传参的正常行为；需要修改原数据的方式见后续章节 |
| 函数的返回值被丢掉了没用上 | 调用时没写变量去接 | 用变量接住（`int result = sum(...);`），或明确这个调用只要副作用 |
