# 31 继承与派生类：复用基类的成员

## 学习目标

完成本章后，你应当能够：

1. 用 `struct 派生类名 : 基类名` 定义一个派生类，并说出这行声明表达了什么关系。
2. 在派生类的构造函数里用成员初始化列表调用基类的构造函数，并说明为什么不能改在函数体里做。
3. 说出派生类对象构造与析构的完整顺序，并解释这个顺序为什么只能是这样。
4. 用一个基类服务多个派生类，并说明派生类如何自己决定基类部分的初值。
5. 说出 `public` / `protected` / `private` 三种继承方式的区别，以及 `struct` 与 `class` 在默认继承方式上的差异。

## 1 独立定义的类型会重复自己

到第 30 章为止，我们定义的每个结构体和类都是**各自独立**的：`point` 有自己的 `x`、`y`，`int_buffer` 有自己的指针和长度，它们之间没有任何关系。这在类型不多的时候没问题，但只要类型的用途是"同一类东西的不同版本"，重复就会出现。

假设程序里需要两种传感器：一种测温度，一种测压力。两者都有编号、采样间隔，都要打印自己的信息；区别只是测的量不同。如果各写一个类，那么编号、间隔、打印实现都要写两遍——**数据结构上的重叠和实现上的重叠同时出现了**。

消除这种重复的办法是**继承**（inheritance）：把公共的数据成员和成员函数提取到一个**基类**（base class）里，再让需要这些成员的类型从基类**派生**出来。这些类型叫**派生类**（derived class）。

这样安排的好处不只是"少写一遍代码"，更重要的是**基类成了公共部分的唯一一处定义**：以后要改公共行为，只改基类一处，所有派生类一起生效——这正是第 08 章讲函数复用时的那个道理，只不过这次复用的是"一整套数据和操作"。

继承同时表达了一种关系：**派生类"是一种"基类**。狗是一种动物，温度传感器是一种传感器。后面第 32 章要做的"把派生类当基类用"，依据就是这层关系。本章先把语法和构造规则立清楚。

## 2 定义基类与派生类

例程 `E:\CPP_Code\CppFromScratch\ch31_inheritance\inheritance_basic\inheritance_basic.cpp` 里的基类和派生类（节选，注释略）：

```cpp
struct base
{
    int x = 0;
    int y = 0;

    base(int new_x, int new_y) : x(new_x), y(new_y) { }

    void print_xy()
    {
        std::cout << "x = " << x << std::endl;
        std::cout << "y = " << y << std::endl;
    }
};

struct derived_one : base          // 冒号后面写"从谁继承"
{
    int z = 0;

    derived_one(int new_x, int new_y, int new_z) : base(new_x, new_y), z(new_z) { }

    void print_z()
    {
        std::cout << "z = " << z << std::endl;
    }
};
```

两点要先看清：

- **基类的写法没有任何特殊之处。** `base` 就是一个普通的类型：有自己的数据成员、构造函数和成员函数。它和前面几章的类没有区别，照样可以单独创建对象使用（例程 `derived_two` 的最后一段就在演示这件事）。
- **派生类的定义只多了一段 `: base`。** 含义是"我想要 `base` 的数据和方法，同时还要在此基础上扩展，而不是去修改 `base`"。加派生类不需要改动基类一行代码——这是继承最实用的性质。

派生类对象里**自带一份完整的基类部分**，所以下面这些写法全都成立：

```cpp
derived_one d_one(1, 2, 3);
d_one.print_xy();    // 调用的是基类实现，操作的是 d_one 里那份基类部分
d_one.print_z();     // 派生类自己加的方法
d_one.x = 100;       // 直接读写继承来的数据成员，不需要额外写法
```

运行结果：

```text
=== Demo A: the derived object uses the function written in the base class ===
x = 1
y = 2
=== Demo B: and it also has its own function ===
z = 3
=== Demo C: the inherited data members belong to the derived object ===
x = 100
y = 200
z = 3
=== Demo D: the same object seen through the base name still works ===
x = 100
y = 200
```

Demo D 里写的是 `base& ref = d_one;`：因为派生类对象含有完整的基类部分，基类的引用可以直接指向它。这条性质本章只需要知道它成立（它的用法是第 32 章的主题）。

## 3 派生类怎么初始化基类部分

`derived_one` 的构造函数里有本章最关键的一行：

```cpp
derived_one(int new_x, int new_y, int new_z) : base(new_x, new_y), z(new_z) { }
```

冒号后面的这一段叫**成员初始化列表**（第 24 章），它在这里初始化了两样东西：

- **`base(new_x, new_y)`**：调用**基类的构造函数**，把继承来的那部分数据初始化好。这就是"派生类建立在基类之上"的具体动作。
- **`z(new_z)`**：初始化派生类自己加的数据成员。

### 3.1 为什么基类的初始化只能写在初始化列表里

原因和时间顺序有关。一个派生类对象是这样搭起来的：

1. **基类部分**先用基类的构造函数构造好；
2. 然后是**派生类自己的数据成员**，按它们在类里的声明顺序初始化；
3. 最后才执行**派生类构造函数的函数体**。

所以在函数体开始执行的那一刻，`x`、`y`、`z` 全都已经初始化完成了。反过来说，**你不可能在函数体里"先把基类初始化出来"**——基类部分在函数体之前就已经建好了。下面这种写法是错的：

```cpp
// 错误示范：基类没有默认构造函数时，这个构造函数根本无法通过编译
derived_one(int new_x, int new_y, int new_z) : z(new_z)
{
    x = new_x;      // 这不是初始化，而是"先默认初始化再赋值"
    y = new_y;
}
```

例程 `derived_one` 的基类只提供了 `base(int, int)`，没有默认构造函数，于是编译器会直接报：

```text
error: no matching function for call to 'base::base()'
```

这句话的意思是"我已经不知道该用哪个构造函数来造基类部分了"。**如果基类恰好有一个默认构造函数，上面的写法反而能编译通过**，但那意味着基类部分先被默认构造了一次、随后又被赋值一次，多做了一遍无用功，而且遇到 `const` 成员或无默认构造的成员时迟早出错。**初始化就写在初始化列表里，这是稳定的写法。**

顺带说明初始化顺序的一个细节：初始化列表里书写的先后**不决定**实际顺序，实际顺序永远按"基类 → 成员（按声明顺序）→ 函数体"来。这一点在第 24 章讲过成员的情况，继承只是把"基类"插在了最前面。

### 3.2 析构顺序完全相反

销毁一个派生类对象时，顺序倒过来：**先执行派生类的析构函数体，再销毁派生类自己的数据成员，最后销毁基类部分**。理由是同一个：谁后建的谁先拆，这样拆到某一层时，下面那部分一定还是完好的。

例程 `E:\CPP_Code\CppFromScratch\ch31_inheritance\construction_order\construction_order.cpp` 用三个类型把六步各打印一行：

```cpp
struct base { explicit base(int new_id); ~base(); };          // 打印 "1." 和 "6."
struct part { explicit part(int new_value); ~part(); };        // 打印 "2." 和 "5."
struct derived : base
{
    part p;
    explicit derived(int new_id) : base(new_id), p(new_id * 10)
    {
        std::cout << "3. derived constructor body, ..." << std::endl;
    }
    ~derived() { std::cout << "4. derived destructor body" << std::endl; }
};
```

运行结果：

```text
=== Demo A: building a derived object, step by step ===
1. base constructor, id = 7
2. member constructor, value = 70
3. derived constructor body, base id = 7, member value = 70
=== Demo B: the two objects are independent ===
1. base constructor, id = 1
2. member constructor, value = 10
3. derived constructor body, base id = 1, member value = 10
4. derived destructor body
5. member destructor, value = 10
6. base destructor, id = 1
4. derived destructor body
5. member destructor, value = 70
6. base destructor, id = 7
```

Demo A 里只有 1、2、3 三行，是因为那个对象是在 `main` 里创建的，要等到 `main` 结束才销毁；最后三行（销毁 `id = 7` 的那个）就是它的。Demo B 里的 `d2` 被一对花括号限制在内部作用域里，一出作用域立刻走完 4、5、6 三步。两组 4、5、6 分属两个不同的对象，这也是"每个对象都有自己独立的一份基类部分"的证据。

## 4 一个基类，多个派生类

基类的意义在于**被多个派生类共用**。例程 `E:\CPP_Code\CppFromScratch\ch31_inheritance\derived_two\derived_two.cpp` 里，同一个 `base` 下面挂了两个扩展方向完全不同的派生类：

```cpp
struct derived_one : base                 // 加一个 int
{
    int z = 0;
    derived_one(int new_x, int new_y, int new_z) : base(new_x, new_y), z(new_z) { }
    void print_z() { /* ... */ }
};

struct derived_two : base                 // 加一个 double
{
    double w = 0.0;
    explicit derived_two(double new_w) : base(10, 20), w(new_w) { }
    void print_w() { /* ... */ }
};
```

```text
=== Demo A: derived_one adds its own data member ===
x = 1
y = 2
z = 3
=== Demo B: derived_two adds a different one, on the same base ===
x = 10
y = 20
w = 1.5
=== Demo C: the base class was never modified and still works alone ===
x = 7
y = 8
```

`derived_two` 的构造函数值得多看一眼：

```cpp
explicit derived_two(double new_w) : base(10, 20), w(new_w) { }
```

它只接收一个 `double`，却用**常量** 10 和 20 去初始化基类部分。这说明一件重要的事：**基类只要求"给我两个 `int`"，至于这两个值从哪里来，是派生类自己的事。** 可以像 `derived_one` 那样把参数往下传，也可以用固定值，甚至可以先算一遍再传。同一个基类因此能适应各种不同的派生需求。

Demo C 则说明基类仍然是普通类型：它没有被"抽象化"，照样可以自己创建对象、自己调用自己的成员函数。

## 5 继承方式与访问权限

派生类的定义里，冒号后面除了基类名，还可以写一个访问限定符：

```cpp
struct derived_public : public base { };      // 公有继承
struct derived_protected : protected base { }; // 保护继承
struct derived_private : private base { };    // 私有继承
```

**省略时用的是默认值，而 `struct` 与 `class` 的默认值不同：**

| 写法 | 默认继承方式 | 默认成员访问权限 |
| --- | --- | --- |
| `struct A : base` | `public` 继承 | `public` |
| `class A : base` | `private` 继承 | `private` |

这和这两条规则的结构是一致的：第 23 章讲过 `struct` 与 `class` 的唯一区别就是默认访问权限，继承方式沿用了同一个默认规则。

三种继承方式的区别在于**基类的成员在派生类里"对外是什么身份"**：

| 基类中该成员的访问级别 | `public` 继承后 | `protected` 继承后 | `private` 继承后 |
| --- | --- | --- | --- |
| `public` | `public` | `protected` | `private` |
| `protected` | `protected` | `protected` | `private` |
| `private` | 派生类不可访问 | 派生类不可访问 | 派生类不可访问 |

三条结论值得记住：

- **`private` 成员在任何继承方式下都不可被派生类直接访问。** 基类私有成员只有基类自己（以及它的友元）能碰。派生类要使用它们，只能通过基类提供的公开接口——这和第 23 章"外部只能走接口"是同一件事，只是换成了派生类的视角。
- **`protected` 是给"派生类"这一层准备的**：它对类外面不可见，但对派生类可见。
- **只有 `public` 继承表达了"派生类是一种基类"。** 这也是绝大多数场景该用的方式（本课程后面各章的例程都写 `struct X : base`，在 `struct` 里默认就是公有继承）。`private` 继承的含义是"用基类的实现，但不对外承认这层关系"，属于设计层面的取舍，`protected` 继承更少见。

> 一条施工提醒：如果打算通过**基类的指针**来删除派生类对象（`Animal* p = new Dog; delete p;`），基类的析构函数必须是虚函数，否则派生类的析构函数不会被执行。虚函数是第 33 章的主题，这里先记住这条要求，等到能写虚函数时再回头补上。

## 6 动手实验

三个例程都在 `E:\CPP_Code\CppFromScratch\ch31_inheritance\` 下，各占一个文件夹。

### 6.1 实验一：基类与派生类的基本用法（`inheritance_basic`）

`inheritance_basic\inheritance_basic.cpp` 里 `derived_one` 继承 `base` 并自己加了 `z`，`main` 依次调用基类方法、派生类方法，并直接修改继承来的数据成员。

```text
E:\msys64\ucrt64\bin\g++.exe -std=c++20 -Wall -g inheritance_basic.cpp -o inheritance_basic.exe
./inheritance_basic.exe
```

**预期现象**：输出与 2 节的十二行逐字符一致（Demo A 的两行来自基类的 `print_xy`，Demo C 证明继承来的成员可以直接读写）。

**验收标准**：`-Wall` 无警告；能指出 `d_one.print_xy()` 用的是哪个类里实现的函数、操作的是哪个对象的哪部分数据；能解释 Demo D 为什么合法。

**改值实验**：把 `derived_one d_one(1, 2, 3);` 改成 `derived_one d_one(11, 22, 33);`，先判断输出。预期 Demo A 变成 `x = 11`、`y = 22`，Demo B 变成 `z = 33`，Demo C、D 变成 `x = 100`、`y = 200`、`z = 33`——只有实参在变，其余逻辑一行不动。

**必做实验**：把 `derived_one` 的构造函数改成下面两种写法各试一次，看编译器分别给什么：

```cpp
// 写法一：初始化列表里只写 z，x、y 改在函数体里赋值
derived_one(int new_x, int new_y, int new_z) : z(new_z) { x = new_x; y = new_y; }

// 写法二：连 z 也放到函数体里赋值
derived_one(int new_x, int new_y, int new_z) { x = new_x; y = new_y; z = new_z; }
```

**预判**：两种写法都编译失败，报错都是 `error: no matching function for call to 'base::base()'`，并且编译器会列出 `base` 的候选构造函数告诉你"`base::base(int, int)` 需要 2 个参数、这里给了 0 个"。原因是**基类的构造函数调用只能出现在成员初始化列表里，而这里没有写**。看完还原。

### 6.2 实验二：一个基类服务两个派生类（`derived_two`）

`derived_two\derived_two.cpp` 里 `derived_two` 用常量 `base(10, 20)` 初始化基类部分，与 `derived_one` 的参数透传形成对照。

```text
E:\msys64\ucrt64\bin\g++.exe -std=c++20 -Wall -g derived_two.cpp -o derived_two.exe
./derived_two.exe
```

**预期现象**：输出与 4 节的十一行逐字符一致。

**验收标准**：`-Wall` 无警告；能说出 `derived_two` 的构造函数收到的 `double` 参数为什么可以用常量去初始化基类部分；能解释 Demo B 里 `x = 10`、`y = 20` 的来源。

**改值实验**：把 `base(10, 20)` 改成 `base(30, 40)`，先判断输出。预期只有 Demo B 的 `x`、`y` 变成 `30`、`40`，其余全部不变——`derived_one` 的基类部分初值来自它自己的参数，和这里无关。

### 6.3 实验三：构造与析构的顺序（`construction_order`）

`construction_order\construction_order.cpp` 让基类、派生类的数据成员、派生类构造函数体各打印一行，把三步顺序变成可核对的输出。

```text
E:\msys64\ucrt64\bin\g++.exe -std=c++20 -Wall -g construction_order.cpp -o construction_order.exe
./construction_order.exe
```

**预期现象**：输出与 3.2 节的十四行逐字符一致（构造 1→2→3，析构 4→5→6，且两组 4、5、6 属于两个对象）。

**验收标准**：`-Wall` 无警告；能说出为什么 Demo A 里看不到 4、5、6 三行；能解释 `id = 70` 的那个 `part` 为什么在 `id = 7` 的对象销毁时被销毁。

**改值实验**：交换初始化列表里两项的书写顺序：

```cpp
explicit derived(int new_id) : p(new_id * 10), base(new_id) { ... }
```

先判断输出会不会变。预期是**运行结果完全不变**（仍然是 1、2、3 的顺序）——因为初始化顺序由"基类 → 成员 → 函数体"这个固定规则决定，和书写顺序无关。但编译时**不再是零警告**了，会看到三条 `-Wreorder` 警告：

```text
warning: 'derived::p' will be initialized after [-Wreorder]
warning:   base 'base' [-Wreorder]
warning:   when initialized here [-Wreorder]
```

这条实验一次说明两件事：初始化顺序不可改，而把顺序写错只会让读到代码的人误解。看完把顺序改回来，重新确认零警告。

## 7 常见错误与排查

| 报错或现象 | 原因 | 处理 |
| --- | --- | --- |
| `error: no matching function for call to 'base::base()'`（附注 `candidate expects 2 arguments, 0 provided`） | 派生类的构造函数没有在成员初始化列表里调用基类的构造函数，而基类又没有默认构造函数 | 在初始化列表里补上 `: base(new_x, new_y)`；初始化只能写在那里 |
| `error: 'int base::x' is private within this context`（附注 `declared private here`） | 基类把该成员设成了 `private`，派生类不能直接访问 | 让基类提供公开接口间接读写；确认确实要给派生类用时再考虑 `protected`（第 23 章的封装原则同样适用） |
| `warning: 'derived::p' will be initialized after [-Wreorder]` | 初始化列表里书写的顺序与真实的初始化顺序（基类先、成员按声明顺序）不一致 | 按真实顺序书写，保持零警告（顺序本身不会因此改变） |
| 在派生类构造函数体里写 `x = new_x;` 也能编译，但基类部分像是被初始化了两次 | 基类部分在函数体之前已经构造完成，函数体里的赋值是"再改一次" | 把初值移到成员初始化列表；基类没有默认构造函数时这个写法根本无法编译，问题会更早暴露 |
| `error: 'base' is an inaccessible base of 'derived'` | 用 `class` 定义派生类时默认是**私有继承**，从外面把派生类对象当作基类看待是不允许的 | 写成 `class derived : public base`；用 `struct` 定义时默认就是公有继承 |
| `error: 'int base::x' is inaccessible within this context`（附注 `declared here`） | 私有继承把基类的公开成员在派生类里降成了私有，外部访问不到 | 需要"派生类是一种基类"这层关系时就用公有继承；`protected` 成员则对外不可见、对派生类可见 |
| `error: expected class-name before '{' token` | 冒号后面写的基类此时还没有被声明（写在了派生类后面，或两个类互相继承） | 把基类定义放到派生类之前；继承关系不能成环 |
| 通过基类指针 `delete` 派生类对象，派生类的析构函数没有执行 | 基类的析构函数不是虚函数，`delete` 只照着指针的静态类型去析构 | 让基类的析构函数成为虚函数（第 33 章讲虚函数时补上这一步） |
| 派生类明明没有写某个成员，却报"重复定义"或行为怪异的错 | 派生类里声明了与基类同名的数据成员，它把基类的那个成员遮住了 | 换个名字；同名成员会让代码里每一次访问都变成"到底指哪一个"的猜谜 |

## 8 本章验收

1. 三个例程都编译通过，`-Wall` 无警告，输出与 2、3.2、4 节的预期现象逐字符一致。
