## 学习目标

完成本章后，你应当能够：

1. 说出什么时候需要定义自己的类型。
2. 用 `struct` 定义一个同时包含数据成员和成员函数的类型。

4. 说明同一类型的两个对象之间是什么关系。
5. 用聚合初始化和空花括号创建对象，并说出两者的区别。

## 1 为什么需要定义自己的类型

到这一章之前，我们用的类型都是现成的：`int`、`double` 来自语言本身，`std::array`、`std::vector` 来自标准库。这些类型覆盖了很大一类需求，但总会碰到它们不够用的时候。常见的三种情形是：

- **标准库容器不够用**。它们只负责"装东西"，装进去的东西之间的关系、对这些东西能做什么操作，容器一概不管。
- **已有的类型不合适**，需要一个按自己需求定制的类型（比如某处的数据要一直保持有序、或者要记录额外信息）。
- **语言里根本没有这个类型**，因为它只存在于你要解决的那个问题里。

第三种情形最容易理解，也最好举例。假设我们在写一个处理绘图或图表的程序，那么"平面上的一个坐标点"就是最基本的东西。用现成的类型怎么表示它？

```cpp
int x = 10;
int y = 20;
```

能用，但有个根本问题：**`x` 和 `y` 之间的"成对"关系只存在于我们的记忆里**。语言不知道这两个 `int` 是一组；如果程序中还有另一个点的坐标 `x2`、`y2`，函数签名里就会出现一堆看不出关系的整数参数，谁都可以把两个不同点的坐标混着用而编译器毫无反应。

我们希望有一个**类型**，它的名字就叫"点"，它自己就知道"我由两个整数坐标组成"。这就是自定义类型的意义：**把数据的结构和适用于这些数据的操作，一起变成一个可以命名、可以检查、可以传递的东西。** 在 C++ 里做这件事的两个关键字是 `struct`（本章）和 `class`（下一章）。它们几乎相同，本章先专注结构体的基础与核心。

## 2 定义一个结构体

定义一个表示坐标点的类型，写法如下（取自例程 `E:\CPP_Code\CppFromScratch\ch22_structs\struct_point\struct_point.cpp`）：

```cpp
struct Point
{
    int x;
    int y;

    void print()
    {
        std::cout << "x = " << x << std::endl;
        std::cout << "y = " << y << std::endl;
    }
};
```

逐部分看：

- **`struct Point`**：`struct` 是关键字，`Point` 是新类型的名字。这一句是**类型定义**，不是变量定义——它只告诉编译器"以后有个类型叫 `Point`"。写到这一行为止，内存里还没有任何东西。
- **数据成员**：`int x;` 和 `int y;`。它们不是某个具体对象的坐标，而是"凡是用这个类型创建的对象，都各有这两个 `int` 成员"。习惯上把数据成员写在前面。
- **成员函数**：`void print()` 写在结构体内部，同样具备第 08 章讲的函数四要素（返回类型、名字、参数列表、函数体）。它的特别之处在于**参数列表是空的，却能打印 `x` 和 `y`**——因为它是 `Point` 的成员函数，调用它的那个对象就是它的数据来源。
- **结尾的分号**：`};` 这一行末尾的分号不能省。这是最容易漏、报错信息又最难看懂的一处，第 9 节会给出它的报错原文。

**`struct` 与 `class` 的唯一区别（下一章展开）**：结构体的成员默认是公开可访问的，类的成员默认是私有的。本章所有成员都能在结构体外面直接使用。

## 3 创建对象并使用它

**定义好类型之后，创建变量的方式和 `int` 完全一样**：

```cpp
Point p1;      // 创建一个 Point 类型的对象，名字叫 p1
```

这里 `Point` 是类型名，`p1` 是这个类型的一个**对象**（也叫这个结构体的一个**实例**）。创建实例这件事，语法上和第 03 章 `int count;` 没有任何差别——自定义类型和内置类型在"怎么用"这一层是平等的。

**访问成员需要点运算符 `.`**：

```cpp
p1.x = 10;     // 把 p1 的 x 成员设为 10
p1.y = 20;     // 把 p1 的 y 成员设为 20
p1.print();    // 调用 p1 的成员函数
```

`.` 是**成员访问运算符**，`p1.x` 读作"`p1` 的 `x`"。它后面既可以跟数据成员，也可以跟成员函数——这个运算符其实我们早就在用了：第 14 章写过的 `myVector.push_back(5)`、`myVector.size()`，用的就是同一个运算符，只不过那些成员来自标准库的 `vector`。现在这些成员是我们自己定义的。

**成员函数最大的好处在这里体现出来**：`p1.print()` 的参数列表是空的，我们不需要把坐标作为参数传进去。原因是数据成员 `x`、`y` 本来就在对象内部，成员函数可以直接使用它们。对比第 08 章的 `printArray(std::array<int, 3> array)`——那个函数必须把要打印的数组当参数接收，因为它站在数组外面。**把数据和操作数据的函数放进同一个类型，从此"要打印一个点"和"要打印的数组长度"这类信息不用再靠参数来回传递。**

## 4 两个对象是彼此独立的两份数据

再创建一个对象，它的成员和第一个对象毫无关系：

```cpp
Point p2;
p2.x = 5;
p2.y = -5;
p2.print();
```

`p1` 和 `p2` 都是 `Point` 的实例，但它们是**两个不同的对象**：各自有自己的一份 `x` 和 `y`，在内存里落在不同的存储单元上。改 `p2` 不会影响 `p1`，因此例程 `struct_point` 的 Demo C 里再次打印 `p1`，拿到的仍然是 10 和 20。

这一点值得和已经学过的规则接上：**结构体是值类型**，和 `int`、`std::array` 一样。赋值时会逐成员复制出一份独立的数据，按值传参时也一样（第 08 章讲过按值传参是复制），函数里改的是副本、不会改到原件。例程 `struct_vector` 的 Demo C 就用一个按值接收 `Point` 的函数演示了这件事。

## 5 创建对象的几种写法

`Point p1;` 这条语句只是"创建对象"，**并没有给成员任何值**。此时 `p1.x`、`p1.y` 里是什么，没有任何保证——和第 03 章"未初始化的变量不能用"是同一条规则。想让成员一创建就有值，有两种写法。

**聚合初始化：按声明顺序一次给全成员赋初值。**

```cpp
Point p1 {10, 20};      // x = 10, y = 20
```

`Point` 这种"没有任何自定义构造方式、成员都是公开的"类型，属于**聚合类型**（aggregate），可以用一对花括号一次性初始化全部成员：**花括号里的值按位置对应成员的声明顺序**，第一个给 `x`，第二个给 `y`。这里要小心一件事：顺序写反了编译器不会拦，只会静悄悄地把两个值装反——`Point p1 {20, 10}` 是能编译的，但得到的是 `x = 20`、`y = 10`。

**空花括号：所有成员都用各自类型的零值。**

```cpp
Point origin {};        // x = 0, y = 0
```

空花括号是特殊语法，表示"全部成员取零值"，所以 `origin` 的坐标一定是 0，不会是随机数。两条写法的差别可以概括成一句话：**`Point p;` 让成员处于不确定状态，`Point p {};` 保证成员被清零。** 只要不在创建后马上给每个成员赋值，就应该写成空花括号的形式。

**花括号里少给几个值也可以**，剩下的成员按零值处理：

```cpp
Point half {1};         // x = 1, y = 0
```

这**不会**报错，也不需要警告——编译器认为这是有意的写法。值给多了才会报错（`too many initializers`，见第 9 节）。所以"少给"和"给反"这两种错误编译器都帮不上忙，写聚合初始化时要自己核对顺序和个数。

## 6 自定义类型带来的连锁好处

一旦 `Point` 成了一个真正的类型，前面章节学到的东西几乎都能直接用在它身上：

```cpp
std::vector<Point> points {{1, 2}, {3, 4}, {5, 6}};   // 放进容器，每个花括号是一个 Point

for (Point p : points)                                // 范围 for 遍历
{
    p.print();
}
```

**自定义类型也可以当函数的返回类型和参数类型**：

```cpp
Point midPoint(Point a, Point b)
{
    return Point {(a.x + b.x) / 2, (a.y + b.y) / 2};
}
```

这个函数接收两个点、返回它们的中点。`Point {...}` 在 `return` 里照样是聚合初始化，花括号构造出的对象被复制一份交给调用处。`struct_vector` 这个例程把上面这些串在一起：三个点放进 `vector`、逐个打印、算出中点、再用一个按值传参的函数演示复制语义。

**这些能力不是为结构体专门开的后门，而是"它已经是一个类型了"的自然结果。** 这正是自定义类型的价值所在：把问题里的概念变成一个类型，之后所有处理类型的手段就都能用上。

### 7.1 实验一：结构体的基本组成（`struct_point`）

`struct_point\struct_point.cpp` 里定义了 `struct Point`，包含数据成员 `x`、`y` 和成员函数 `print()`。`main` 里创建 `p1` 并设置 10、20，创建 `p2` 并设置 5、-5，最后再打印一次 `p1`。

```text
cd "E:/CPP_Code/CppFromScratch/ch22_structs/struct_point"
"E:/msys64/ucrt64/bin/g++.exe" -std=c++20 -Wall -g struct_point.cpp -o struct_point.exe

```

**预期输出**：

```text

y = 20
=== Demo B: p2 是另一个独立的对象 ===

y = -5
=== Demo C: 再打印一次 p1，它没有被 p2 影响 ===

y = 20
```

**验收标准**：三段输出逐字符一致，编译 `-Wall` 无警告。Demo C 的 10、20 是"两个对象互不影响"的直接证据。

**改值实验**：把 `p2.x = 5;` 改成 `p2.x = -5;`，把 `p1.y = 20;` 改成 `p1.y = 200;`，重新编译运行。**先预判**：Demo A 会输出 `x = 10` 和 `y = 200`，Demo B 会输出 `x = -5` 和 `y = -5`，Demo C 与 Demo A 相同。再核对一遍——这能确认每一条赋值只落在它自己那个对象的成员上。

## 8 常见错误与排查

| 报错或现象 | 原因 | 处理 |
| --- | --- | --- |
| `error: expected ';' after struct definition` | 结构体定义结尾漏了分号（`}` 后面必须是 `};`） | 在右花括号后补分号 |
| `error: expected unqualified-id before '.' token` | 忘了创建对象，直接用类型名访问成员（写成 `Point.x = 10;`） | 先创建对象：`Point p1;` 再 `p1.x = 10;` |
| `error: 'struct Point' has no member named 'z'` | 访问了结构体里没有的成员名（拼错或没定义） | 核对结构体内的成员清单，改对名字或补上该成员 |
| `error: too many initializers for 'Point'` | 聚合初始化给的初值个数多于成员个数 | 初值个数不超过成员个数；少给的值会被置零，多给直接报错 |
| 打印出来是奇怪的数，每次运行还可能不同 | 只写了 `Point p;`，成员没有初始值就拿来用 | 改成 `Point p {};` 或 `Point p {10, 20};`，也可以创建后立刻逐个赋值 |
| `Point p {10, 20}` 编译通过，但两个值装反了 | 聚合初始化按成员声明顺序对应，顺序写错编译器不会拦 | 核对声明顺序与初值顺序是否一致 |
| `error: no match for 'operator<<' (operand types are 'std::ostream' {...} and 'Point')` | 想直接 `std::cout << p1;` 打印整个对象，但标准库不知道怎么打印自定义类型 | 调用成员函数打印（`p1.print()`）；让 `<<` 直接支持自定义类型属于运算符重载的内容，在后面章节 |
| `error: 'print' was not declared in this scope; did you mean 'printf'?` | 把成员函数当自由函数调用（写成 `print(p1);`），成员函数只能通过对象访问 | 改成 `p1.print();` |
