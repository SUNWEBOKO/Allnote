# 10 函数模板：让编译器生成函数版本

## 学习目标

完成本章后，你应当能够：

1. 说出第 09 章的重载遗留了哪部分重复代码，并说明模板如何消除它。
2. 用 `template <typename T>` 声明一个函数模板，在函数体里使用类型参数 `T`。
3. 分别用显式模板实参、模板实参推导两种方式调用同一个模板，并说出各自的适用场景。

## 1 重载解决了名字，但留下了重复的函数体

第 09 章把 `printIntArray` 和 `printFloatArray` 收成了一个名字 `printArray`，接口干净了，可是打开函数看：

```cpp
void printArray(std::array<int, 3> array)
{
    for (auto value : array)
    {
        std::cout << value << " ";
    }

    std::cout << std::endl;
}

void printArray(std::array<float, 3> array)
{
    for (auto value : array)
    {
        std::cout << value << " ";
    }

    std::cout << std::endl;
}
```

**两份函数体一字不差，唯一的区别是参数类型。** 这是第 08 章讲过的那种重复：将来要改打印格式（比如加分号、改成逗号分隔），必须记得每个版本都改一遍，漏一个就行为不一致。而且每多支持一种元素类型，就要再抄一份。

回忆第 08 章消除重复的办法：把重复的**语句**提取出来起个名字。可这次重复的不是"哪几句语句"，而是"**类型**"——`int` 版和 `float` 版的语句结构完全一样，只有类型不同。所以这次要提取的，是**类型本身**：把参数类型写成一个还没定下来的占位符，再告诉编译器"这个函数是"给我一个类型"的"。

## 2 函数模板：把类型变成参数

例程 `E:\CPP_Code\CppFromScratch\ch10_function_templates\template_basic\template_basic.cpp`：

```cpp
template <typename T>
void printArray(T array)
{
    for (auto value : array)
    {
        std::cout << value << " ";
    }

    std::cout << std::endl;
}
```

和普通函数相比，只多了上面一行 `template <typename T>`，并把参数类型从 `std::array<int, 3>` 换成了 `T`。这四处的含义如下。

- **`template <typename T>` 是模板头**，它说明"接下来的这个函数带一个类型参数"。这一行不是函数的一部分，函数名仍然是 `printArray`，返回值仍然是 `void`。
- **`T` 是类型参数名**，与形参名一样只是名字，取 `T`、`U`、`ValueType` 都行；叫 `T` 是惯例。`typename` 也可以写成 `class`（`template <class T>`），两者在这里完全等价。
- **`T` 出现在参数列表里**：`T array` 表示"参数类型由 `T` 决定"。函数体里也可以继续用 `T` 声明同类型的变量。
- **函数体里没有任何地方提到具体类型**：元素用 `auto` 接住、打印交给 `<<`。正因为这样，这段代码对任何"能用范围 for 遍历、元素能用 `<<` 输出"的类型都成立。

`main` 里可以显式给出模板实参：

```cpp
printArray<std::array<int, 3>>(myIntArray);
printArray<std::array<float, 3>>(myFloatArray);
```

尖括号里的 `std::array<int, 3>` 就是**模板实参**，意思是"这次把 `T` 填成它"。

```text
=== Demo A: explicit template argument ===
1 2 3 
1.1 2.2 3.3 
```

### 2.1 模板不是函数，实例化才产生函数

`template <typename T> void printArray(T array);` 这一段声明**本身不生成任何代码**。编译器读完它，只是记住"有这么一族函数，参数类型待定"。

真正生成函数发生在**实例化**（instantiation）：某处用具体类型调用了它，编译器就拿这个类型把 `T` 全部替换掉，得到一份参数类型确定的普通函数，然后调用它。上面两行调用会让编译器生成两份函数：

| 调用 | `T` 被替换为 | 实际生成的函数 |
| --- | --- | --- |
| `printArray<std::array<int, 3>>(myIntArray)` | `std::array<int, 3>` | `void printArray(std::array<int, 3> array)` |
| `printArray<std::array<float, 3>>(myFloatArray)` | `std::array<float, 3>` | `void printArray(std::array<float, 3> array)` |

**这两份函数是两个不同的函数**（编译后的符号名不同，地址也不同），只不过它们的函数体来自同一段模板。所以"用模板消除了重复"准确地说，是**在源码层面上消除了重复**：你在源文件里只维护一份函数体，重复出来的那些版本由编译器替你生成。第 09 章需要手抄的那两段函数体现在只需要一段。

## 3 让编译器反推模板实参

大多数情况下不需要写尖括号——编译器能从实参的类型推出 `T`。例程 `ch10_function_templates\template_deduce\template_deduce.cpp` 就是去掉尖括号之后的写法：

```cpp
printArray(myIntArray);
printArray(myFloatArray);
printArray(myDoubleArray);
printArray(myCharArray);
```

```text
=== Demo B: template argument deduction ===
1 2 3 
1.1 2.2 3.3 
10 20 30 40 
a b c d e 
```

这个过程叫**模板实参推导**（template argument deduction），规则对本例来说非常直接：形参是 `T`、实参是 `std::array<int, 3>`，于是 `T` 就是 `std::array<int, 3>`。这和 `auto` 的角色是同一件事——都是**由已有的信息推出没写出来的类型**，区别只是 `auto` 推的是变量类型，这里推的是模板参数。

四次调用得到四个不同的 `T`：

| 调用 | 推导出的 `T` |
| --- | --- |
| `printArray(myIntArray)` | `std::array<int, 3>` |
| `printArray(myFloatArray)` | `std::array<float, 3>` |
| `printArray(myDoubleArray)` | `std::array<double, 4>` |
| `printArray(myCharArray)` | `std::array<char, 5>` |

后两个值得注意：元素类型不同、**元素个数也不同**。在 C++ 里 `std::array<int, 3>` 和 `std::array<int, 4>` 是两个毫不相干的类型（第 05 章就强调过长度是类型的一部分），但对模板来说这不过是"又换了一次 `T`"，一份模板代码全都覆盖。

**什么时候该写尖括号？** 推导只在"能从实参推出来"时可用。如果类型无法从实参推出（例如 `T` 只出现在返回类型里），就必须显式给出。反过来，如果实参已经写明了类型，两个都行、尖括号是多余的：跟第 09 章"重载不必写类型"的结论一样，**让编译器做的事就别自己再写一遍**，只有需要明确表达"我就要这个版本"时，显式写法才更有表达力。

## 4 C++20 的缩写函数模板

既然参数列表里的类型可以由实参推出，那连 `template <typename T>` 这行也可以省掉。C++20 起，**参数列表里出现 `auto` 的函数声明会自动被当作函数模板**，每个 `auto` 对应一个编译器"凭空发明"的类型参数。例程 `ch10_function_templates\template_abbreviated\template_abbreviated.cpp`：

```cpp
void printArray(auto array)
{
    for (auto value : array)
    {
        std::cout << value << " ";
    }

    std::cout << std::endl;
}
```

上面这一行等价于 `template <typename T> void printArray(T array)`。调用方式与普通函数完全一致：

```cpp
printArray(myIntArray);
printArray(myFloatArray);
```

```text
=== Demo C: abbreviated function template (C++20) ===
1 2 3 
1.1 2.2 3.3 
```

这种写法叫**缩写函数模板**（abbreviated function template）。它的好处是函数长得就像普通函数，模板头不见了，读起来更轻。代价是**类型参数彻底不可见**：

- 需要显式写 `printArray<std::array<int, 3>>(...)` 时，你没有任何名字可以引用，只能靠推导；
- 函数体里若需要提到这个类型（比如写一个同类型的局部变量并用它做别的判断），只能改用 `auto` 绕，或者干脆换回命名参数的写法。

**对编译标准的要求**是本节的另一个重点。`auto` 参数是 C++20 的特性，在更早的标准下编译器会明确提示：

```text
warning: use of 'auto' in parameter declaration only available with '-std=c++20' or '-fconcepts'
```

这只是警告，程序仍会按"扩展语法"编译，但它提醒你：**这份代码换到只支持 C++17 的编译器（例如 GCC 4.8、7、9 之类）上会直接编译失败。** 本课程从第 09 章起统一使用 `-std=c++20`，因此这两种写法都能用；如果哪天在别人的工程里看到这个警告，加 `-std=c++20` 即可消除，前提是编译器真的支持。

## 5 模板的工作方式，以及它的边界

理解下面三件事，模板就不再神秘。

**第一，模板的"检查"发生在实例化时。** 编译到模板定义本身时，编译器并不检查函数体是不是对所有类型都成立——它连 `T` 是什么都不知道。真正的检查推迟到实例化那一刻：先确定 `T`，再把 `T` 代进函数体逐句编译。因此**报错信息里会同时出现"哪个调用要求实例化"和"实例化之后哪一行不对"**。例如对 `printArray(42)` 实例化 `T = int` 之后，函数体里的范围 for 就没有意义了：

```text
In instantiation of 'void printArray(T) [with T = int]':
    required from here
error: 'begin' was not declared in this scope
```

**第二，模板的定义必须出现在使用它的位置之前**，理由和普通函数一样（第 08 章）——而且对模板更严格：编译器在实例化时要能看到完整的函数体。所以本课程把模板定义写在 `main` 之前的同一个文件里。把模板声明和定义分开放进 `.h` 与 `.cpp` 是后续工程化的内容，本章不加区分。

**第三，每实例化一次就多一份函数。** 一份模板被 4 个类型使用，目标文件里就有 4 份函数代码。这就是模板的代价——**代码膨胀**。对本例这种小函数完全无所谓；只有当模板函数体很大、又被很多类型用时才需要留意。作为回报，你维护的源码只有一份。

**最后要说清模板解决不了什么。** 模板能覆盖的是"**所有类型的处理方式都相同**"的情形。假如有某个类型需要**略微不同**的处理（比如打印 `std::array<int, 3>` 时想换成另一种格式），模板本身没有"如果 `T` 是某某类型就换一套逻辑"的能力，硬凑的写法（在函数体里写 `if` 判断类型）在 C++ 里通常既写不出来也不该写。这就是下一章模板特化要解决的问题。

## 6 动手实验

例程都在 `E:\CPP_Code\CppFromScratch\ch10_function_templates\` 下，三个程序各占一个文件夹，每个 `.cpp` 都是自包含的单文件。

### 6.1 实验一：模板与显式模板实参

`template_basic\template_basic.cpp`：一份 `template <typename T> void printArray(T array)`，`main` 里用尖括号显式给出 `T` 调用两次。

```text
cd "E:/CPP_Code/CppFromScratch/ch10_function_templates/template_basic"
"E:/msys64/ucrt64/bin/g++.exe" -std=c++20 -Wall -g template_basic.cpp -o template_basic.exe
./template_basic.exe
```

**预期输出**（每行末尾有一个空格）：

```text
=== Demo A: explicit template argument ===
1 2 3 
1.1 2.2 3.3 
```

**验收标准**：输出与上面逐字符一致，编译 `-Wall` 无警告。

**改值实验**：把 `myIntArray` 的初值由 `{1, 2, 3}` 改成 `{7, 8, 9}`，第二行（float 那行）不受影响，第一行变为 `7 8 9 `。再试着把第二行调用写成 `printArray<std::array<int, 3>>(myFloatArray);`——显式指定的类型和实参不匹配，编译会失败：

```text
error: could not convert 'myFloatArray' from 'array<float,[...]>' to 'array<int,[...]>'
```

**尖括号里的类型是硬性要求，不是建议**，编译器不会替你修正。

### 6.2 实验二：让编译器推导

`template_deduce\template_deduce.cpp`：同一份模板被四种类型使用，`main` 里一个尖括号都不写。

```text
cd "E:/CPP_Code/CppFromScratch/ch10_function_templates/template_deduce"
"E:/msys64/ucrt64/bin/g++.exe" -std=c++20 -Wall -g template_deduce.cpp -o template_deduce.exe
./template_deduce.exe
```

**预期输出**（每行末尾有一个空格）：

```text
=== Demo B: template argument deduction ===
1 2 3 
1.1 2.2 3.3 
10 20 30 40 
a b c d e 
```

**验收标准**：四行内容与上面一致，`-Wall` 无警告。

**改值实验**：把 `myDoubleArray` 改成 `std::array<double, 3> myDoubleArray {10.0, 20.0, 30.0};`，重新编译运行，第三行应变成 `10 20 30 `。**这一改动的意义不在输出，而在类型**：`T` 从 `std::array<double, 4>` 变成了 `std::array<double, 3>`，编译器为此重新实例化了一份函数——元素个数是类型的一部分，"少打印一个数"在编译期就是另一个类型了。再故意写一句 `printArray(42);` 编译看看，会看到 `In instantiation of 'void printArray(T) [with T = int]'` 后面跟着 `error: 'begin' was not declared in this scope`：**错误是实例化时才发现的，而且报错位置在函数体那一行，不在调用那一行**。看完删掉这一句。

`template_abbreviated\template_abbreviated.cpp`：主模板写成 `void printArray(auto array)`。


**预期输出**：

**验收标准**：输出与实验一的第三行结构一致，`-Wall` 无警告。

**标准实验**：把编译命令里的 `-std=c++20` 换成 `-std=c++17` 重新编译：

这说明这份代码依赖 C++20。看完把标准换回 `-std=c++20`，警告消失——**这也是本课程从第 09 章起统一加 `-std=c++20` 的原因**。

### 6.4 实验四：一份模板到底生成了几份函数

在 `template_deduce.cpp` 里数一数：`main` 中一共 4 次调用、涉及 4 种不同的 `T`，因此编译器生成了 4 份函数。现在把 `printArray(myFloatArray);` 与 `printArray(myDoubleArray);` 两行注释掉，重新编译运行：

```text
=== Demo B: template argument deduction ===
1 2 3 
a b c d e 
```

输出少了两行，同时**少了两份实例化出来的函数**。源码里那份模板一个字都没改，变的只是"有哪些类型用了它"。这就是模板的基本账：**源码一份，目标代码按用到的类型数各一份。**

## 7 常见错误与排查

| 报错或现象 | 原因 | 处理 |
| --- | --- | --- |
| `error: 'T' was not declared in this scope`（常常还伴随 `error: variable or field 'printArray' declared void`） | 漏写了 `template <typename T>` 这一行，`T` 对编译器来说是未声明的名字 | 在函数定义上方补上模板头 `template <typename T>` |
| `warning: use of 'auto' in parameter declaration only available with '-std=c++20' or '-fconcepts'` | 缩写函数模板（`auto` 参数）需要 C++20 | 编译时加 `-std=c++20`；换到不支持 C++20 的编译器则要改回 `template <typename T>` 的写法 |
| `error: cannot convert 'std::array<int, 3>' to 'int'`，并提示 `initializing argument 1 of 'void printArray(T) [with T = int]'` | 尖括号里显式给的模板实参写错了，`T` 不是实参的类型 | 核对尖括号与实参：要么改成真正的类型，要么去掉尖括号交给推导 |
| `error: no matching function for call to 'print2(int, double)'`，并提示 `deduced conflicting types for parameter 'T' ('int' and 'double')` | 同一个 `T` 出现在多个形参上，而几个实参的类型不一致，推不出唯一的 `T` | 让几个实参类型一致；或改用两个类型参数 `template <typename T, typename U>` |
| `error: 'begin' was not declared in this scope`，前面还有 `In instantiation of 'void printArray(T) [with T = int]'` | 传给模板的类型不满足函数体的要求（这里用了范围 for，而 `int` 不是容器） | 看 `In instantiation of` 那一行确认 `T` 被推成了什么，再决定是换个实参还是放宽函数体 |
| `error: 'printArray' was not declared in this scope` | 模板定义写在使用它的代码之后（与普通函数同一条规则） | 把模板定义挪到前面 |
| 输出缺少某几行、且删掉调用后代码"变短"了 | 不是错误：没有被任何类型使用的模板不会被实例化，也就不会有对应代码 | 这是模板的正常行为，按调用点核对实例化了几份 |
| 编译时间明显变长、目标文件变大 | 模板是"每个用到的类型各生成一份"，重复实例化会放大这一点 | 确认函数体是否过大、类型是否太多；本章的小函数不必处理 |

## 8 本章验收

1. 三个例程编译通过、`-Wall` 无警告，输出与 6.1、6.2、6.3 节的预期逐字符一致。
2. 能对着 `template <typename T> void printArray(T array)` 逐部分说明：模板头、类型参数 `T`、参数列表里的 `T` 各自是什么，以及为什么函数体里可以完全不提具体类型。
3. 能说出模板与"编译器生成的函数"的关系：模板本身不生成代码，实例化时按 `T` 替换生成一份函数，`T` 不同就是不同的函数。
4. 用 `template_deduce.cpp` 的例子说明"一份模板被四个类型使用"会产生几份函数，并说出改动元素个数（`std::array<double, 4>` 改成 `std::array<double, 3>`）为什么会重新实例化。
5. 能说出缩写函数模板的写法与它的两个代价：类型参数不可见、必须 C++20。
6. 完成过 6.4 节实验，能解释注释掉两行调用后输出与生成代码的变化。
