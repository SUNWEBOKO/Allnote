# 27 运算符重载：让自定义类型支持运算符

## 学习目标

完成本章后，你应当能够：

1. 说明自定义类型为什么默认不能直接使用运算符。
2. 为自定义类型写出 `operator+`，并说明返回类型和参数类型为什么这样选。
3. 说出 `p1 + p2` 与 `p1.operator+(p2)` 的等价关系。
4. 写出 `operator+=`，用 `*this` 返回当前对象的引用，并说明返回引用与返回值在连续运算中的差别。
5. 说出设计运算符时必须遵守的几条限制。

## 1 编译器不认识"两个点相加"

前面几章我们一直在做一件事：用结构体和类定义自己的类型（第 22、23 章），再给它配上构造函数和析构函数（第 24、25 章）。有了这些，类型的"出生"和"死亡"都安排好了，剩下的问题是**日常使用**。

而日常使用里最顺手的东西是运算符。第 26 章的 `point` 已经被验证过：`p2 = p1;` 能用、按值传参能用，因为那些行为编译器能推导出来（隐式拷贝构造就是逐成员复制）。但如果你写：

```cpp
point p1(10, 20);
point p2(30, 40);
point p3 = p1 + p2;
```

会直接报错：

```text
error: no match for 'operator+' (operand types are 'point' and 'point')
```

原因很直白：**`+` 对 `int`、`double` 这些内置类型有明确定义，但那套定义完全建立在"数字"这个概念上。编译器不知道 `point` 的"相加"应该是两个坐标分别相加，还是取中点，还是别的什么。** 这个含义必须由定义类型的人写出来。

C++ 给出的办法是**运算符重载**（operator overloading）：把运算符也当成一个可以自己实现的函数。你去实现它，编译器以后看到这个运算符作用在你的类型上，就调用你写的那份实现。

## 2 给运算符写一个函数

例程 `E:\CPP_Code\CppFromScratch\ch27_operator_overloading\operator_plus\operator_plus.cpp` 里的实现：

```cpp
struct point
{
    int x;
    int y;

    point(int new_x, int new_y) : x(new_x), y(new_y) { }

    void print()
    {
        std::cout << "x = " << x << ", y = " << y << std::endl;
    }

    point operator+(const point& rhs)
    {
        return point(x + rhs.x, y + rhs.y);
    }
};
```

除名字之外，它就是一个普通的成员函数。下面把每一处选择讲清楚。

### 2.1 名字：`operator` 加运算符

运算符函数的命名规则是固定的：**关键字 `operator` 后面紧跟要重载的运算符**。重载 `+` 就写成 `operator+`，重载 `+=` 就写成 `operator+=`。这是编译器识别"这是一份运算符实现"的唯一记号，没有别的写法，也不能自己造新符号——把 `+` 换成 `**` 之类的写法会直接报错：

```text
error: declaration of 'operator*' as non-function
```

### 2.2 返回类型：两个点相加，得到一个新点

`operator+` 的返回类型是 `point`。理由是语义决定的：**`+` 不改变任何一个操作数，只是算出一个新的值。** 这和 `int` 的加法一致：`a + b` 算完之后 `a` 和 `b` 都没变，只是多了一个结果。既然结果是"一个新的 `point`"，返回类型就写 `point`。

返回值这一点还直接决定了链式写法能不能用：

```cpp
point p4 = p1 + p2 + p3;
```

`+` 是从左往右结合的，所以先算 `p1 + p2`，得到一个临时的 `point`；再拿这个临时点去加 `p3`。**如果 `operator+` 返回的是引用或 `void`，右边这次相加就没有一个"新点"可用了。** 返回一个新的 `point` 值，是让 `+` 具备"可以连续相加"这一性质的前提。

### 2.3 参数：`const point& rhs`

参数列表里只有一个参数，写法和第 26 章的拷贝构造函数同一套逻辑：

- **用引用**，避免复制整个对象（第 16 章）。加法只是读两个坐标，把右侧操作数整个复制一份毫无必要。
- **加 `const`**，因为加法不会修改右侧操作数。`const` 把"只读"这件事写进类型，编译期就能拦住误写。

参数名用的是 `rhs`。它是 right-hand side（右侧操作数）的缩写：在 `p1 + p2` 里，`p1` 是左操作数，`p2` 从运算符右边传进来，就是这里的 `rhs`。函数体里：

- `x`、`y` 是**当前对象**（也就是左操作数 `p1`）的成员，成员函数里可以直接用名字访问，不需要写任何前缀；
- `rhs.x`、`rhs.y` 是**右操作数**的成员，必须通过参数名访问。

所以 `point(x + rhs.x, y + rhs.y)` 这行就是"左 x 加右 x、左 y 加右 y，用两个结果构造一个新点"。例程里 `p1(10, 20)` 与 `p2(30, 40)` 相加得到 `x = 40, y = 60`。

### 2.4 `p1 + p2` 实际调用的是 `p1.operator+(p2)`

这是理解成员形式的运算符最关键的一点。下面两种写法**完全等价**：

```cpp
point p3 = p1 + p2;
point p3 = p1.operator+(p2);      // 编译器背后真正生成的调用
```

由此可以推出三条结论：

1. **左操作数是调用者。** `p1 + p2` 里，`p1` 调用自己的 `operator+`，`p2` 作为实参传入。这就是为什么函数体里能直接用 `x`、`y`——它们就是 `p1` 的成员。
2. **左侧必须是本类型的对象。** 写成 `10 + p1` 会报：

   ```text
   error: no match for 'operator*' (operand types are 'int' and 'point')
   ```

   （以 `*` 为例；换回 `+` 也是同样的形状。）原因是 `10` 是 `int`，它没有名为 `operator+` 的成员函数可以接收 `point`。把运算符写成非成员函数可以解决这类"左操作数不是本类型"的情况，本章只用成员形式。
3. **参数个数只能是 0 或 1。** 成员形式的运算符，左操作数已经由调用者占掉了，所以二元运算符只能带 1 个参数、一元运算符只能带 0 个参数。写成两个参数会报：

   ```text
   error: 'point point::operator+(const point&, const point&)' must have either zero or one argument
   ```

## 3 就地修改的运算符：`operator+=`

并非所有运算符都产出新值。`+=` 的语义是**修改左边的对象**，例程 `E:\CPP_Code\CppFromScratch\ch27_operator_overloading\operator_plus_equal\operator_plus_equal.cpp` 里实现了它：

```cpp
point& operator+=(const point& rhs)
{
    x += rhs.x;
    y += rhs.y;
    return *this;
}
```

### 3.1 `p1 += p2` 该做什么

在心里把 `p1 += p2` 展开成 `p1 = p1 + p2`，就能看清它要完成的事：**用相加的结果替换掉 `p1` 原来的值**。但它和 `p1 = p1 + p2` 有一个实现上的区别——不必真的构造一个新点再覆盖回去，直接就地累加更直接，例程里用的就是后一种：

```cpp
x += rhs.x;
y += rhs.y;
```

这里的 `x += rhs.x` 是 `x = x + rhs.x` 的简写（第 08 章讲过这种复合赋值形式）：当前对象的 `x` 变大，`rhs` 的成员只被读取。例程中 `p1(10, 20)` 执行 `p1 += p2`（`p2` 为 `30, 40`）之后变成 `x = 40, y = 60`，而 `p2` 一点没变。

### 3.2 返回类型是引用，靠 `*this`

`operator+=` 的返回类型是 `point&`——**返回被修改的对象的引用**。这个选择有两个理由：

- **语义上**：`p1 += p2` 的结果就是 `p1` 本身。既然对象没有被复制，就不该返回一个副本。
- **实用上**：返回引用才能连着写：

  ```cpp
  (p1 += p3) += p3;
  ```

  先算 `p1 += p3`，得到 `p1` 的引用；再对这个引用做一次 `+= p3`，于是两次都把结果加在同一个 `p1` 上。例程里 `p1` 从 `(40, 60)` 经过两次 `+= p3`（`p3` 为 `1, 2`）变成 `(42, 64)`。

怎么写"返回自己"？靠关键字 `this`：

```cpp
return *this;
```

**`this` 是成员函数里的一个隐藏指针，指向"当前对象"**。调用 `p1 += p2` 时 `this` 就指向 `p1`。注意它的类型是指针，而我们需要交出的是对象本身，所以必须**解引用**：`*this` 才是 `p1` 这个对象。这一对关系要记牢：

| 写法 | 含义 | 类型 |
| --- | --- | --- |
| `this` | 指向当前对象的指针 | `point*` |
| `*this` | 当前对象本身 | `point` |

漏掉那个 `*` 会得到：

```text
error: invalid initialization of non-const reference of type 'point&' from an rvalue of type 'point*'
```

### 3.3 返回类型写错会怎样

| 返回类型 | 后果 |
| --- | --- |
| `point&`（正确） | `p1 += p2` 修改 `p1`，连续 `+=` 都作用在 `p1` 上 |
| `void` | `p1 += p2;` 单用没问题，但 `(p1 += p2) += p3;` 报 `error: no match for 'operator+=' (operand types are 'void' and 'point')` |
| `point`（值） | 能编译，`p1 += p2;` 也正确；但连续运算里的第二次 `+=` 作用在一个临时副本上，`p1` 只被加了一次——**编译不报错，结果错**，最难查 |

所以判断标准不是"能不能编译"，而是**"这个运算符的结果是不是左操作数本身"**。是，就返回 `*this` 的引用；不是（比如 `+` 产出的是一个新对象），就返回值。

## 4 设计运算符时的几条限制

运算符重载把一部分语言机制的钥匙交给了你，但并没有把全部钥匙都交出去。下面是必须知道的边界。

1. **不是所有运算符都能重载。** `::`（作用域解析）、`.`（成员访问）、`.*`（成员指针访问）、`?:`（三目条件运算符）、`sizeof` 这几类不能重载；`=`、`[]`、`()`、`->` 只能是成员函数。剩下的绝大多数运算符（算术、比较、位运算、下标、函数调用等）都可以。本章只涉及算术类，后续章节会按需要补上其他运算符：比较与三向比较运算符在第 36 章，函数调用运算符 `()` 在第 38 章。
2. **不能改变运算符本身的"语法属性"**：操作数的个数、优先级、结合方向、以及它和内置类型之间的既有含义都改不了。你只是为"本类型 + 本类型"这类组合补充定义；`int` 之间的 `+` 永远还是加法。
3. **至少有一个操作数得是自定义类型。** 不能给 `int` 和 `int` 重新定义 `+`，否则整个语言的基础就动摇了。
4. **没有实现过的组合就用不了。** 只实现了 `operator+` 的话，`p1 += p2`、`p1 - p2`、`p1 == p2` 全都会报 `no match for 'operator...'`。每个运算符都要单独实现，这也意味着**只实现类型真正需要的那些**。
5. **实现要守约定。** `+` 应该"不改变操作数、产出新值"，`+=` 应该"修改左操作数"。把 `operator+` 写成修改 `p1`、或者让 `operator+=` 返回一个全新的对象，语法上都合法，但会违反所有读代码的人的预期，而且和标准库（如容器、算法）依赖的规则冲突。**运算符是给语义起的一个约定俗成的名字，不要用它做别的事。**

## 5 动手实验

两个例程都在 `E:\CPP_Code\CppFromScratch\ch27_operator_overloading\` 下，各占一个文件夹。

### 5.1 实验一：`operator+`

`operator_plus\operator_plus.cpp`

```text
E:\msys64\ucrt64\bin\g++.exe -std=c++20 -Wall -g operator_plus.cpp -o operator_plus.exe
./operator_plus.exe
```

**预期现象**：

```text
=== Demo A: p1 and p2 ===
x = 10, y = 20
x = 30, y = 40
=== Demo B: p3 = p1 + p2 ===
x = 40, y = 60
=== Demo C: p1 + p2 + p3 chains ===
x = 80, y = 120
=== Demo D: p1 and p2 are unchanged ===
x = 10, y = 20
x = 30, y = 40
=== Demo E: p1.operator+(p2) is the same call ===
x = 40, y = 60
```

**验收标准**：`-Wall` 无警告；能算出 Demo C 的 `x = 80, y = 120` 是怎么来的（10+30+40 与 20+40+60），也就是"先 `p1 + p2` 得到 `(40, 60)`，再加 `p3(40, 60)`"；能说出 Demo D 为什么证明了 `operator+` 没有修改操作数。

**改值实验**：把 Demo C 的 `point p4 = p1 + p2 + p3;` 改成 `point p4 = p1 + (p2 + p3);`，先判断 `x`、`y` 是否改变。预期**结果不变**（相加的顺序变了，但加法满足结合律）；再把 `operator+` 的函数体改成 `return point(x - rhs.x, y - rhs.y);`，重新编译运行，预期只有用到 `operator+` 的三处变化：

```text
=== Demo B: p3 = p1 + p2 ===
x = -20, y = -20
=== Demo C: p1 + p2 + p3 chains ===
x = 0, y = 0
=== Demo E: p1.operator+(p2) is the same call ===
x = -20, y = -20
```

Demo C 为什么是 `(0, 0)`？因为 `p3` 自己也是用这个（被改坏的）运算符算出来的：`p3 = p1 - p2` 得到 `(-20, -20)`，于是 `p4 = (p1 - p2) - p3 = (-20, -20) - (-20, -20) = (0, 0)`。这个实验说明：**运算符的含义完全由我们写的函数体决定**，改了实现，所有使用它的地方都会跟着变。看完把函数体还原。

### 5.2 实验二：`operator+=`

`operator_plus_equal\operator_plus_equal.cpp`

```text
E:\msys64\ucrt64\bin\g++.exe -std=c++20 -Wall -g operator_plus_equal.cpp -o operator_plus_equal.exe
./operator_plus_equal.exe
```

**预期现象**：

```text
=== Demo A: before ===
x = 10, y = 20
=== Demo B: p1 += p2 ===
x = 40, y = 60
=== Demo C: (p1 += p3) += p3 needs the returned reference ===
x = 42, y = 64
=== Demo D: p2 and p3 are unchanged ===
x = 30, y = 40
x = 1, y = 2
```

**验收标准**：`-Wall` 无警告；能解释 Demo C 的 `(42, 64)`（`(40,60) + (1,2) + (1,2)`）；能说出 Demo B 为什么改的是 `p1` 而不是 `p2`。

**必做实验（观察返回类型的影响）**：把 `operator+=` 的返回类型从 `point&` 改成 `void`（函数体末尾的 `return *this;` 一起删掉），重新编译。预期编译报错：

```text
error: no match for 'operator+=' (operand types are 'void' and 'point')
```

报错来自 Demo C 的连续运算——`void` 没法再当左操作数。把这个实验做完后还原。

**改值实验**：把返回类型改成 `point`（值，保留 `return *this;`），重新编译运行。预期**能编译、Demo A、B、D 都不变，但 Demo C 变成 `x = 41, y = 62`**：

```text
=== Demo B: p1 += p2 ===
x = 40, y = 60
=== Demo C: (p1 += p3) += p3 needs the returned reference ===
x = 41, y = 62
```

原因：第一次 `+=` 正常改到了 `p1`（变成 `41, 62`），但它返回的是一份**副本**；第二次 `+=` 作用在那份副本上，`p1` 就少加了一次。注意这个错误没有任何编译提示，只能靠输出发现。看完还原成 `point&`。

## 6 常见错误与排查

| 报错或现象 | 原因 | 处理 |
| --- | --- | --- |
| `error: no match for 'operator+' (operand types are 'point' and 'point')` | 没有为这个类型实现 `operator+` | 在结构体里补上 `point operator+(const point& rhs)` |
| `error: no match for 'operator+=' (operand types are 'point' and 'point')` | 实现了 `operator+` 但没实现 `operator+=`，两者是各自独立的函数 | 需要哪个就实现哪个：`point& operator+=(const point& rhs)` |
| `error: 'point point::operator+(const point&, const point&)' must have either zero or one argument` | 成员形式的二元运算符写了两个参数（左操作数已经由调用者占掉） | 只保留一个参数，左操作数用 `this`（`*this`）或直接访问成员 |
| `error: invalid initialization of non-const reference of type 'point&' from an rvalue of type 'point*'` | `return this;` 少了 `*`，返回的是指针而不是对象 | 写成 `return *this;` |
| `error: no match for 'operator+=' (operand types are 'void' and 'point')` | `operator+=` 的返回类型写成了 `void`，无法参与连续运算 | 返回类型改成 `point&`，并 `return *this;` |
| `error: no match for 'operator*' (operand types are 'int' and 'point')` | 左操作数不是本类型的对象（如 `2 * p1`），成员形式的运算符无从调用 | 让本类型的对象出现在运算符左边；确实需要反过来时把运算符写成非成员函数 |
| 连续 `+=` 之后对象只被改了一次 | `operator+=` 返回了 `point`（值）而不是引用，第二次运算作用在副本上 | 返回类型改成 `point&`；这类错误编译器不报，只能靠输出核对 |
| `error: declaration of 'operator*' as non-function` | 试图重载一个不存在的运算符名（如把 `+` 写成 `**`） | 只能使用语言已有的运算符符号 |
