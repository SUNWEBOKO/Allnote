# 15 继承与多态基础

## 学习目标

完成本章后，你应当能够：

1. 用 `struct 派生类名 : 基类名` 定义派生类，在派生类构造函数的成员初始化列表里调用基类构造函数，并按顺序说出派生类对象构造与析构的完整顺序。
2. 说出 `public` / `protected` / `private` 三种继承方式的区别，以及 `struct` 与 `class` 在默认继承方式上的差异。
3. 用基类的引用、指针和函数参数接收不同的派生类对象（上转型），并说出编译器在什么时候决定调用哪一份实现。
4. 说出派生类里定义同名函数是隐藏而不是重载，解释对象切片为什么发生，以及 `std::vector<Animal*>` 能装下不同派生类而按值容器不能的原因。
5. 在基类成员函数前加上 `virtual` 实现运行时的动态绑定，用 `override` 让编译器核对重写，并判断一个成员函数该不该写成虚函数。

## 1 独立定义的类型会重复自己

到目前这几章为止，我们定义的每个结构体和类都是**各自独立**的：`point`（第 11、12 章）有自己的 `x`、`y`，`int_buffer`（第 14 章）有自己的指针和长度，它们之间没有任何关系。这在类型不多的时候没问题，但只要类型的用途是"同一类东西的不同版本"，重复就会出现。

假设程序里需要两种传感器：一种测温度，一种测压力。两者都有编号、采样间隔，都要打印自己的信息；区别只是测的量不同。如果各写一个类，那么编号、间隔、打印实现都要写两遍——**数据结构上的重叠和实现上的重叠同时出现了**。

消除这种重复的办法是**继承**（inheritance）：把公共的数据成员和成员函数提取到一个**基类**（base class）里，再让需要这些成员的类型从基类**派生**出来。这些类型叫**派生类**（derived class）。

这样安排的好处不只是"少写一遍代码"，更重要的是**基类成了公共部分的唯一一处定义**：以后要改公共行为，只改基类一处，所有派生类一起生效——这正是第 04 章讲函数复用时的那个道理，只不过这次复用的是"一整套数据和操作"。

继承同时表达了一种关系：**派生类"是一种"基类**。狗是一种动物，温度传感器是一种传感器。后面本章第 6 节要做的"把派生类当基类用"，依据就是这层关系。本节先把语法和构造规则立清楚。

## 2 定义基类与派生类

例程 `E:\CPP_Code\CppFromScratch\ch31_inheritance\inheritance_basic\inheritance_basic.cpp` 里的基类和派生类（节选，注释略）：

```cpp
struct base
{
    int x = 0;
    int y = 0;

    base(int new_x, int new_y) : x(new_x), y(new_y) { }

    void print_xy()
    {
        std::cout << "x = " << x << std::endl;
        std::cout << "y = " << y << std::endl;
    }
};

struct derived_one : base          // 冒号后面写"从谁继承"
{
    int z = 0;

    derived_one(int new_x, int new_y, int new_z) : base(new_x, new_y), z(new_z) { }

    void print_z()
    {
        std::cout << "z = " << z << std::endl;
    }
};
```

两点要先看清：

- **基类的写法没有任何特殊之处。** `base` 就是一个普通的类型：有自己的数据成员、构造函数和成员函数。它和前面几章的类没有区别，照样可以单独创建对象使用（例程 `derived_two` 的最后一段就在演示这件事）。
- **派生类的定义只多了一段 `: base`。** 含义是"我想要 `base` 的数据和方法，同时还要在此基础上扩展，而不是去修改 `base`"。加派生类不需要改动基类一行代码——这是继承最实用的性质。

派生类对象里**自带一份完整的基类部分**，所以下面这些写法全都成立：

```cpp
derived_one d_one(1, 2, 3);
d_one.print_xy();    // 调用的是基类实现，操作的是 d_one 里那份基类部分
d_one.print_z();     // 派生类自己加的方法
d_one.x = 100;       // 直接读写继承来的数据成员，不需要额外写法
```

运行结果：

```text
=== Demo A: the derived object uses the function written in the base class ===
x = 1
y = 2
=== Demo B: and it also has its own function ===
z = 3
=== Demo C: the inherited data members belong to the derived object ===
x = 100
y = 200
z = 3
=== Demo D: the same object seen through the base name still works ===
x = 100
y = 200
```

Demo D 里写的是 `base& ref = d_one;`：因为派生类对象含有完整的基类部分，基类的引用可以直接指向它。这条性质本章只需要知道它成立（它的用法是本章第 8 节的主题）。

## 3 派生类怎么初始化基类部分

`derived_one` 的构造函数里有本章最关键的一行：

```cpp
derived_one(int new_x, int new_y, int new_z) : base(new_x, new_y), z(new_z) { }
```

冒号后面的这一段叫**成员初始化列表**（第 12 章），它在这里初始化了两样东西：

- **`base(new_x, new_y)`**：调用**基类的构造函数**，把继承来的那部分数据初始化好。这就是"派生类建立在基类之上"的具体动作。
- **`z(new_z)`**：初始化派生类自己加的数据成员。

### 3.1 为什么基类的初始化只能写在初始化列表里

原因和时间顺序有关。一个派生类对象是这样搭起来的：

1. **基类部分**先用基类的构造函数构造好；
2. 然后是**派生类自己的数据成员**，按它们在类里的声明顺序初始化；
3. 最后才执行**派生类构造函数的函数体**。

所以在函数体开始执行的那一刻，`x`、`y`、`z` 全都已经初始化完成了。反过来说，**你不可能在函数体里"先把基类初始化出来"**——基类部分在函数体之前就已经建好了。下面这种写法是错的：

```cpp
// 错误示范：基类没有默认构造函数时，这个构造函数根本无法通过编译
derived_one(int new_x, int new_y, int new_z) : z(new_z)
{
    x = new_x;      // 这不是初始化，而是"先默认初始化再赋值"
    y = new_y;
}
```

例程 `derived_one` 的基类只提供了 `base(int, int)`，没有默认构造函数，于是编译器会直接报：

```text
error: no matching function for call to 'base::base()'
```

这句话的意思是"我已经不知道该用哪个构造函数来造基类部分了"。**如果基类恰好有一个默认构造函数，上面的写法反而能编译通过**，但那意味着基类部分先被默认构造了一次、随后又被赋值一次，多做了一遍无用功，而且遇到 `const` 成员或无默认构造的成员时迟早出错。**初始化就写在初始化列表里，这是稳定的写法。**

顺带说明初始化顺序的一个细节：初始化列表里书写的先后**不决定**实际顺序，实际顺序永远按"基类 → 成员（按声明顺序）→ 函数体"来。这一点在第 12 章讲过成员的情况，继承只是把"基类"插在了最前面。

### 3.2 析构顺序完全相反

销毁一个派生类对象时，顺序倒过来：**先执行派生类的析构函数体，再销毁派生类自己的数据成员，最后销毁基类部分**。理由是同一个：谁后建的谁先拆，这样拆到某一层时，下面那部分一定还是完好的。

例程 `E:\CPP_Code\CppFromScratch\ch31_inheritance\construction_order\construction_order.cpp` 用三个类型把六步各打印一行：

```cpp
struct base { explicit base(int new_id); ~base(); };          // 打印 "1." 和 "6."
struct part { explicit part(int new_value); ~part(); };        // 打印 "2." 和 "5."
struct derived : base
{
    part p;
    explicit derived(int new_id) : base(new_id), p(new_id * 10)
    {
        std::cout << "3. derived constructor body, ..." << std::endl;
    }
    ~derived() { std::cout << "4. derived destructor body" << std::endl; }
};
```

运行结果：

```text
=== Demo A: building a derived object, step by step ===
1. base constructor, id = 7
2. member constructor, value = 70
3. derived constructor body, base id = 7, member value = 70
=== Demo B: the two objects are independent ===
1. base constructor, id = 1
2. member constructor, value = 10
3. derived constructor body, base id = 1, member value = 10
4. derived destructor body
5. member destructor, value = 10
6. base destructor, id = 1
4. derived destructor body
5. member destructor, value = 70
6. base destructor, id = 7
```

Demo A 里只有 1、2、3 三行，是因为那个对象是在 `main` 里创建的，要等到 `main` 结束才销毁；最后三行（销毁 `id = 7` 的那个）就是它的。Demo B 里的 `d2` 被一对花括号限制在内部作用域里，一出作用域立刻走完 4、5、6 三步。两组 4、5、6 分属两个不同的对象，这也是"每个对象都有自己独立的一份基类部分"的证据。

## 4 一个基类，多个派生类

基类的意义在于**被多个派生类共用**。例程 `E:\CPP_Code\CppFromScratch\ch31_inheritance\derived_two\derived_two.cpp` 里，同一个 `base` 下面挂了两个扩展方向完全不同的派生类：

```cpp
struct derived_one : base                 // 加一个 int
{
    int z = 0;
    derived_one(int new_x, int new_y, int new_z) : base(new_x, new_y), z(new_z) { }
    void print_z() { /* ... */ }
};

struct derived_two : base                 // 加一个 double
{
    double w = 0.0;
    explicit derived_two(double new_w) : base(10, 20), w(new_w) { }
    void print_w() { /* ... */ }
};
```

```text
=== Demo A: derived_one adds its own data member ===
x = 1
y = 2
z = 3
=== Demo B: derived_two adds a different one, on the same base ===
x = 10
y = 20
w = 1.5
=== Demo C: the base class was never modified and still works alone ===
x = 7
y = 8
```

`derived_two` 的构造函数值得多看一眼：

```cpp
explicit derived_two(double new_w) : base(10, 20), w(new_w) { }
```

它只接收一个 `double`，却用**常量** 10 和 20 去初始化基类部分。这说明一件重要的事：**基类只要求"给我两个 `int`"，至于这两个值从哪里来，是派生类自己的事。** 可以像 `derived_one` 那样把参数往下传，也可以用固定值，甚至可以先算一遍再传。同一个基类因此能适应各种不同的派生需求。

Demo C 则说明基类仍然是普通类型：它没有被"抽象化"，照样可以自己创建对象、自己调用自己的成员函数。

## 5 继承方式与访问权限

派生类的定义里，冒号后面除了基类名，还可以写一个访问限定符：

```cpp
struct derived_public : public base { };      // 公有继承
struct derived_protected : protected base { }; // 保护继承
struct derived_private : private base { };    // 私有继承
```

**省略时用的是默认值，而 `struct` 与 `class` 的默认值不同：**

| 写法 | 默认继承方式 | 默认成员访问权限 |
| --- | --- | --- |
| `struct A : base` | `public` 继承 | `public` |
| `class A : base` | `private` 继承 | `private` |

这和这两条规则的结构是一致的：第 11 章讲过 `struct` 与 `class` 的唯一区别就是默认访问权限，继承方式沿用了同一个默认规则。

三种继承方式的区别在于**基类的成员在派生类里"对外是什么身份"**：

| 基类中该成员的访问级别 | `public` 继承后 | `protected` 继承后 | `private` 继承后 |
| --- | --- | --- | --- |
| `public` | `public` | `protected` | `private` |
| `protected` | `protected` | `protected` | `private` |
| `private` | 派生类不可访问 | 派生类不可访问 | 派生类不可访问 |

三条结论值得记住：

- **`private` 成员在任何继承方式下都不可被派生类直接访问。** 基类私有成员只有基类自己（以及它的友元）能碰。派生类要使用它们，只能通过基类提供的公开接口——这和第 11 章"外部只能走接口"是同一件事，只是换成了派生类的视角。
- **`protected` 是给"派生类"这一层准备的**：它对类外面不可见，但对派生类可见。
- **只有 `public` 继承表达了"派生类是一种基类"。** 这也是绝大多数场景该用的方式（本课程后面各章的例程都写 `struct X : base`，在 `struct` 里默认就是公有继承）。`private` 继承的含义是"用基类的实现，但不对外承认这层关系"，属于设计层面的取舍，`protected` 继承更少见。

> 一条施工提醒：如果打算通过**基类的指针**来删除派生类对象（`Animal* p = new Dog; delete p;`），基类的析构函数必须是虚函数，否则派生类的析构函数不会执行、派生类那部分资源不会被释放，而且这是未定义行为。虚析构函数的写法和后果见本章第 12.6 节，这里先记住这条要求。

继承立好了"派生类是一种基类"这层关系，这层关系马上就能派上用场：既然狗是一种动物、猫也是一种动物，能不能把它们当成同一种东西来统一处理？这就进入了多态的话题。

## 6 把不同派生类归为一类

本章前几节用继承解决了"公共成员写两遍"的问题：定义一个基类装公共部分，再让多个派生类从它扩展。但继承还带来一个更有意思的可能：既然这些派生类**都是**同一个基类（狗是一种动物，猫也是一种动物），那么能不能把它们当成同一种东西来处理？

能这样做的好处非常具体。只要"当成同一种东西"成立：

- 同一份代码可以接收任何一种派生类对象，不用为每种派生类各写一份；
- 同一个容器可以装下不同派生类的对象，不用 `std::vector<Dog>`、`std::vector<Cat>` 各管一摊。

这正是**多态**（polymorphism，字面意思是"多种形态"）在继承这个话题下的含义：**把不同类型的对象当作同一种类型看待。** 而本节讲的这一层，具体就是指**把派生类对象当作它的基类来使用**。

## 7 先看不用基类的写法

例程 `E:\CPP_Code\CppFromScratch\ch32_polymorphism\polymorphism_basic\polymorphism_basic.cpp` 用的是最经典的一组类型：

```cpp
struct Animal
{
    void speak()
    {
        std::cout << "default speak!" << std::endl;
    }
};

struct Dog : Animal
{
    void speak()
    {
        std::cout << "woof" << std::endl;
    }
};

struct Cat : Animal
{
    void speak()
    {
        std::cout << "meow" << std::endl;
    }
};
```

两个派生类各自写了一个 `speak()`，名字和参数列表与基类的那个完全相同。直接通过派生类对象调用时，用的当然是各自那一份：

```cpp
Dog d;
Cat c;
d.speak();    // woof
c.speak();    // meow
```

```text
=== Demo A: a Dog and a Cat use their own version of speak ===
woof
meow
=== Demo B: the base class keeps its own version ===
default speak!
```

### 7.1 这里发生的是"隐藏"，不是"重载"

有一个术语必须说准。派生类里写一个与基类同名的函数，**不叫重载**：重载（第 04 章）要求同名函数处在**同一个作用域**里，按参数列表区分；而这里的两个 `speak` 分别在 `Animal` 和 `Dog` 两个作用域里，它们是两个独立的函数。

标准给这件事的说法是**隐藏**（name hiding）：`Dog` 里声明了 `speak` 这个名字之后，**基类里所有同名的函数**在 `Dog` 的作用域里都被这个名字遮住了。既然两份实现都还在，就可以用作用域限定符 `::` 明确指定要调用哪一份：

```text
=== Demo C: Dog::speak hides Animal::speak, it does not replace it ===
woof
default speak!
```

第二行的 `d.Animal::speak();` 调用的就是基类那一份，说明**基类的实现并没有被"改写"或"覆盖"，它只是被遮住了**。这一点在本章第 12 节讲虚函数时会变得关键：`virtual` 带来的才是真正的"用派生类的实现替换基类的实现"，而单纯写一个同名函数只是隐藏。

## 8 把派生类对象当基类用

现在进入本节的正题。既然 `Dog` 继承了 `Animal`，那么一个 `Dog` 对象里就含有一份完整的 `Animal` 部分，于是可以这样做：

```cpp
Dog d;
Animal& ref = d;      // 用基类的引用去指派生类对象
```

这一步叫**上转型**（upcast）：把派生类类型的对象转换成基类类型来使用。它有三个特点：

- **不需要写任何转换代码**，编译器自动完成，因为"派生类对象里本来就有一个基类子对象"。
- **不会新建对象，也不会复制数据。**
- **调用成员函数的结果可能不同**，取决于被调用的函数是不是虚函数。明明 `d` 是狗，`ref.speak()` 打印的却是 `default speak!`——因为 `Animal::speak` 不是虚函数；本章第 12 节会看到，在基类的 `speak` 前加上 `virtual` 之后，这一行就变成 `woof` 了。

第二条有直接的证据，例程 `E:\CPP_Code\CppFromScratch\ch32_polymorphism\upcast_reference\upcast_reference.cpp` 打印了地址比较：

```text
=== Demo B: the same object, now handled as an Animal ===
the reference points at the same object: true
default speak!
```

地址相同，说明 `ref` 只是 `d` 的另一个名字（第 08 章的引用），这一步没有任何数据被复制。

第三点就是本节的核心现象。原因不在运行时，而在编译期：**编译器只看着 `ref` 的类型（`Animal`）就决定了要调用 `Animal::speak`**，它在乎的是"这个引用是什么类型"，而不是"它实际绑定了哪个对象"。这种"编译期就把函数定下来"的机制叫**静态绑定**，对应的多态叫**静态多态**。

传参时的情形完全一样——形参写成基类的引用，实参可以是任何派生类对象：

```cpp
void speak_as_animal(Animal& animal)   // 形参是基类引用
{
    animal.speak();
}
```

```text
=== Demo C: it looks the same when the object is passed to a function ===
default speak!
```

函数内部的类型是 `Animal`，所以它调用的是 `Animal::speak`，哪怕传进来的是一只狗。**这既是上转型的方便之处（一种形参类型能接收一整族实参），也是它的局限（函数里拿不回派生类的那份实现）。**

`Cat` 那边走的是完全相同的一条路：

```text
=== Demo D: the Cat is upcast in exactly the same way ===
meow
default speak!
```

## 9 把不同派生类放进同一个容器

上转型最实用的价值出现在容器上。`std::vector` 只有一个模板参数，也就是只能有一种元素类型，所以：

```cpp
std::vector<Dog> dogs;    // 只能装狗
std::vector<Cat> cats;    // 只能装猫
```

狗和猫没法混在同一个 `std::vector` 里——这就是"需要归为一类"的动机。而把元素类型换成**指向基类的指针**，问题就解决了：`Dog*` 和 `Cat*` 都能上转型成 `Animal*`。

例程 `E:\CPP_Code\CppFromScratch\ch32_polymorphism\base_pointer_container\base_pointer_container.cpp` 把三种做法摆在一起：

```cpp
std::vector<Animal*> animals;     // 基类指针的容器：两种都能装
animals.push_back(&d);            // 容器里存的是地址，对象本身还在 main 里
animals.push_back(&c);

std::vector<Animal> zoo;          // 直接装基类对象：只能装下"基类那部分"
zoo.push_back(d);
zoo.push_back(c);
```

运行结果：

```text
=== Demo A: one vector holds exactly one element type ===
dogs.size() = 1, the element type is Dog
cats.size() = 1, the element type is Cat
=== Demo B: a vector of base class pointers holds both ===
animals.size() = 2
default speak!
default speak!
=== Demo C: a vector of base class values keeps only the base part ===
zoo.size() = 2
default speak!
default speak!
=== Demo D: the two original objects are untouched ===
woof
meow
```

Demo B 是"凑到一起"成功的样子：两个派生类对象住在同一个容器里，用同一段循环处理。注意容器里存的是**地址**，对象本身没有被复制，所以 `animals` 里的元素和 `main` 里的 `d`、`c` 是同一批对象。

但 Demo B 也把局限暴露得很清楚：**两次 `speak()` 打印的都是基类的默认实现**，尽管容器里明明一只狗、一只猫。原因和本章第 8 节说的一样：循环变量的类型是 `Animal*`，编译期就定下了 `Animal::speak`。

Demo C 换了一种装法：容器直接装基类对象。这里的 `push_back(d)` 需要把 `Dog` 变成 `Animal`，于是**只把狗身上的基类部分复制进容器，狗特有的那部分被丢掉了**——这个现象叫**对象切片**（object slicing）。本例的两个派生类都没有自己的数据成员，所以丢掉的只是"身份"；如果 `Dog` 带有自己的数据，那些数据在这一步就真没了。

Demo D 是收尾检查：前面几段代码都没有改动 `d` 和 `c`（容器里放的是地址或基类部分的副本），直接用派生类对象调用时，用的仍然是派生类自己的那份实现。

## 10 静态多态做到了什么，没做到什么

本节只回答一个问题：**在还没写 `virtual` 的前提下，静态绑定能做什么、不能做什么。** 把本章的现象整理成一张表：

| 想做的事 | 静态多态（本节之前）能不能做到 | 说明 |
| --- | --- | --- |
| 用同一种形参类型接收不同派生类对象 | 能 | 形参写成基类的引用或指针即可，上转型自动完成 |
| 用一个容器装下不同派生类 | 能 | 元素类型用基类的指针（或引用包装） |
| 写一份循环处理所有派生类对象 | 能 | 前提是这些处理**只依赖基类的接口** |
| 让"同一个调用"在运行期根据实际对象给出不同行为 | **不能** | 通过基类接口调用到的永远是基类的实现 |
| 通过基类接口间接调用派生类特有的函数 | **不能** | 基类里没有那个名字，调用处就编译不过 |

表格最后两行是这条路的边界。它们不能被"写得更聪明一点"解决，因为**编译期做决定**这件事本身就排除了"看运行时是哪个对象再决定"的可能。

要突破这条边界需要另一种机制：让编译器**不**在编译期把函数定死，而是留到运行时、根据对象的真实类型去选择实现。那就要在基类的函数前加 `virtual`，也就是**虚函数**与**动态多态**——本章第 11 节起的内容。所以本章的现象（通过基类调用得到基类的实现）不是"写错了"，而是"还没有让这个函数变成虚函数"。

顺带记住两个方向的安全性差别：

- **派生类 → 基类（上转型）：安全，隐式完成。** 派生类对象里确实含有一个完整的基类子对象，这个转换不会丢失信息。
- **基类 → 派生类（下转型）：不安全，必须显式写出来。** 常用的是 `static_cast`（编译期直接转换，不做任何检查）和 `dynamic_cast`（要求基类是多态类型，在运行时检查，失败时对指针返回空指针、对引用抛异常，见本章第 12 节）。一个 `Animal&` 背后可能是一只猫，也可能是一只狗，`static_cast` 无从判断，只能由写代码的人自己保证。

两个**兄弟**派生类之间的指针更是完全不能互转，编译时会直接报错：

```text
error: cannot convert 'Cat*' to 'Dog*' in initialization
```

表里那两行"不能"，就是本节划出的边界；下一节只讨论一个问题：什么情况下必须改用虚函数。

## 11 什么时候需要虚函数

第 10 节的表格已经列出了静态绑定的边界；本节只回答剩下那个问题——什么情况下必须改用虚函数，并在这里引入后面各节一直使用的 `animal` / `dog` 例子。

本章第 8 节做了一件事：把一个派生类对象交给基类的引用或指针，于是"狗"在代码里变成了"动物"。这个动作（向上转型）本身不复制任何数据，只是换了一种看待对象的方式。

后面各节一直使用的例子，是下面这个结构：

```cpp
struct animal
{
    void speak()
    {
        std::cout << "animal says something" << std::endl;
    }
};

struct dog : animal
{
    void speak()
    {
        std::cout << "dog says woof" << std::endl;
    }
};
```

`dog` 里写了同名的 `speak`，直接对 `dog` 对象调用时输出的是 `dog says woof`；但一旦写成 `animal& a = d; a.speak();`，输出就变回了基类的文字。原因在编译器身上：它读到你写的 `a.speak()` 时，只看到 `a` 的类型是 `animal&`，于是就把这次调用固定到 `animal::speak` 上。所有和类型有关的信息在编译期都是已知的，这种"编译时就把函数选好"的机制也叫**静态多态**。

静态多态有一个它解决不了的场景。我们把派生类对象向上转型，通常不是为了"抹掉"它们的行为，恰恰相反——是为了**把不同派生类的对象放在一起统一处理**，同时让每个对象保留自己的行为：一群动物各自叫各自的，而处理它们的代码只认识"动物"这一个类型。可是编译器在编译期并不知道引用背后到底是什么对象。它需要的信息只有运行时才有：`a` 在运行时绑定的到底是一只狗、一只猫，还是别的什么。所以我们需要一种机制，把"调用哪个函数"这个决定**推迟到运行时**再做出——这就是虚函数。

## 12 虚函数

### 12.1 写法

把 `virtual` 写在成员函数的返回类型前面：

```cpp
struct animal
{
    virtual void speak()
    {
        std::cout << "animal says something" << std::endl;
    }
};
```

除了多出这一个关键字，函数本身没有任何变化：照样有返回类型、参数列表和函数体。派生类里也照旧写同名、同参数、同返回类型的函数：

```cpp
struct dog : animal
{
    void speak() override
    {
        std::cout << "dog says woof" << std::endl;
    }
};
```

这里的 `override` 是本章第 13 节的内容，先记住它的位置：跟在函数头的末尾。派生类中这个函数叫**重写**（override）了基类的虚函数；注意不要和第 04 章的**重载**（overload，同一个作用域里同名不同参数的多个函数）混淆，两者是完全不同的机制。

### 12.2 动态绑定

加上 `virtual` 之后，`animal& a = d; a.speak();` 输出的就是 `dog says woof` 了。编译器不再把这次调用钉死在 `animal::speak` 上，而是生成一段"运行时再决定"的代码：程序执行到这一行时，先看引用实际绑定了哪一个对象，再调用那个对象所属类型的 `speak`。这个选择过程叫**动态绑定**，这样发生的调用叫**虚调用**。

可以把这件事理解成两种信息的分离：

- **引用或指针的类型**决定"你能看见哪些接口"。`animal&` 只能看见 `animal` 里声明过的成员，`.walk()` 之类的派生类成员根本不在视野内（编译期就会报 `'struct animal' has no member named 'walk'`）。
- **对象的实际类型**决定"调用哪一份实现"。这正是虚函数接管的部分。

实现上，编译器通常会为每个带虚函数的对象准备一份"这个类型该用哪些函数"的信息，虚调用时据此查找。具体机制属于进阶内容，本章只需要知道两件事：它发生在运行时，因此比普通函数调用**多一层开销**；而对同一个虚函数的反复调用，开销换来的是"用一份代码处理一族对象"的能力。

### 12.3 虚函数只在通过引用或指针调用时才起作用

这一点必须强调，因为它是虚函数最常见的失效原因。虚函数的动态绑定发生在**通过引用或指针调用**的时候：

```cpp
dog d;
animal& a = d;      // 引用：虚调用生效，输出 dog says woof
a.speak();

animal copy = d;    // 按值：对象被切片，只剩 animal 那一部分（本章第 9 节）
copy.speak();       // 这里调用的一定是 animal::speak
```

把派生类对象**按值**赋给基类对象或按值传给基类形参，派生类多出来的成员会被切掉，得到的只是一个真正的 `animal` 对象——它里面已经没有"我曾经是狗"的信息了，虚函数自然也无从选择。**想用多态，就传引用或指针。**

### 12.4 基类的版本并没有消失

虚函数只是让"通过基类引用调用时选到派生类版本"，基类那一份实现仍然存在，也仍然可以调用：

```cpp
animal a;
a.speak();          // 一个普通的 animal 对象：走基类版本

dog d;
d.animal::speak();  // 用"类名::函数名"显式指定：绕过动态绑定，强制走基类版本
```

第二行的写法叫限定调用（静态调用）。它跳过虚调用机制，因此能在派生类对象上直接取用基类的实现——派生类重写时想在基类版本的基础上再补充点东西，就会用到它。

### 12.5 什么该写成虚函数

判断标准很简单：**这个函数的行为是否依赖"到底是哪一种派生类"**。依赖就写 `virtual`，不依赖就别加。

- 基类给出一个可以用、但派生类很可能想改掉的行为，例如"动物叫"，适合写成虚函数。
- 纯数据访问、和类型无关的工具函数不该是虚函数：白付运行时的开销，语义上也没有意义。

另外两条惯例：

- `virtual` 只需要写在基类。派生类里同名同签名的函数**自动就是虚函数**，写不写 `virtual` 都一样；但派生类里应当写 `override`（下一节）。
- 不要"以防万一"地给所有成员函数都加 `virtual`。虚调用本身有运行时开销；给类加上虚函数还会引入虚函数表、增大对象体积，并使拷贝、比较、序列化这些操作不再"平凡"（不再是能直接按字节搬动的简单数据）。

如果基类的某个函数连一份合理的默认实现都给不出来（"动物叫"就是这种：不存在一种通用动物叫声），那它应当写成**纯虚函数**，基类也随之变成抽象类——这是第 16 章的内容。

### 12.6 虚析构函数

前面五节都在讲"通过基类引用调用时选哪份实现"。析构函数也有同一个问题：**通过基类的指针 `delete` 派生类对象时，基类的析构函数必须是虚函数。**

```cpp
struct base
{
    virtual ~base() { }      // 虚析构函数
};

struct derived : base
{
    ~derived() { }
};

base* p = new derived;
delete p;                    // 先执行 ~derived()，再执行 ~base()
```

道理和普通虚函数一样：`p` 的静态类型是 `base*`，如果 `base::~base` 不是虚函数，`delete p` 只会照着 `base` 去调用析构函数，`derived::~derived` 根本不会执行——派生类自己申请的资源就释放不掉。更严重的是，标准把这种删除定义为**未定义行为**：它可能看起来"正常"，也可能当场崩溃。

一个最小实验就能看出区别。让两个析构函数各打印一行，先不给基类的析构函数加 `virtual`：

```cpp
struct base
{
    ~base() { std::cout << "base destructor" << std::endl; }
};

struct derived : base
{
    ~derived() { std::cout << "derived destructor" << std::endl; }
};

int main()
{
    base* p = new derived;
    delete p;
}
```

实测输出（`-std=c++20 -Wall`）：

```text
base destructor
```

`derived destructor` 那一行没有出现——派生类的析构函数根本没有被调用。把 `base` 的析构函数改成 `virtual ~base()` 再编译运行：

```text
derived destructor
base destructor
```

两行齐全，顺序也符合"先派生、再基类"的析构规则（本章第 3.2 节）。

如果基类里本来就有别的虚函数（比如本章实验里的 `animal`），`-Wall` 还会在 `delete p;` 这一行给出提醒：

```text
warning: deleting object of polymorphic class type 'animal' which has non-virtual destructor might cause undefined behavior [-Wdelete-non-virtual-dtor]
```

但基类没有任何别的虚函数时，连这条提醒也没有：程序可能一直"跑得好好的"，只是每次销毁都少执行一段清理代码。所以结论要记成硬规则：**只要一个类打算被当成基类用（尤其是会被基类指针删除），它的析构函数就该声明为虚函数。** 反过来，不打算被继承的类不必加虚析构函数，那只会白白增加一个虚函数表指针。

## 13 override 限定符

### 13.1 不写 override 时会静默出错

假设你在派生类里把 `speak` 拼错了一个字母：

```cpp
struct dog : animal
{
    void spec()      // 正确名字应该是 speak
    {
        std::cout << "dog says woof" << std::endl;
    }
};
```

编译器**不会报错**，因为从它的角度看这件事完全合法：你只是给 `dog` 新加了一个名叫 `spec` 的成员函数。派生类里没有名为 `speak` 的成员，通过派生类对象名查找时找不到基类的 `speak`，于是 `d.speak()` 仍然按基类实现解释。程序照常编译通过，运行时所有狗叫都变成了 `animal says something`——一个没有任何报错、却和意图完全不符的行为。

### 13.2 override 让编译器替我们核对

在函数头末尾写上 `override`（C++11 起可用），就等于告诉编译器："这个函数是用来重写基类的某个虚函数的，请帮我核对。"

```cpp
struct dog : animal
{
    void spec() override     // 名字拼错了
    {
        std::cout << "dog says woof" << std::endl;
    }
};
```

编译器会去基类里找一个签名完全匹配的虚函数，找不到就直接报错：

```text
error: 'void dog::spec()' marked 'override', but does not override
```

同一个报错也会在**签名不一致**时出现。例如基类写的是 `virtual void speak() const`，派生类漏了 `const`：

```text
error: 'void dog::speak()' marked 'override', but does not override
warning: 'virtual void animal::speak() const' was hidden [-Woverloaded-virtual=]
```

两行信息指向同一个问题：`dog::speak()` 和 `animal::speak() const` 不是同一个函数，重写失败，基类版本被隐藏。

`override` 不改变函数的功能，它只是一条**给自己上的保险**。既然代价这么小，规则就是：凡是重写虚函数，一律写上 `override`。

```text

warning:   base 'base' [-Wreorder]
warning:   when initialized here [-Wreorder]
```

这条实验一次说明两件事：初始化顺序不可改，而把顺序写错只会让读到代码的人误解。看完把顺序改回来，重新确认零警告。

### 实验四：各自调用与隐藏（`polymorphism_basic`）

`polymorphism_basic\polymorphism_basic.cpp` 里 `Dog`、`Cat` 各自定义了 `speak()`，`main` 里既用派生类对象调用，也用 `d.Animal::speak()` 显式调用基类那一份。

```text

```

**预期现象**：完整输出共十一行，与本章第 7 节展示的各段逐字符一致（Demo A 两行派生类行为、Demo B 基类行为、Demo C 显式调用基类那一份、Demo D 与 Demo A/C 对称）。

**验收标准**：`-Wall` 无警告；能说出 `Dog::speak` 与 `Animal::speak` 是两个独立的函数，并解释 `d.Animal::speak();` 为什么能调用到基类那份。

**改值实验**：给 `Animal` 增加一个带参数的版本，然后故意用派生类对象去调用它：

```cpp
struct Animal
{
    void speak() { /* ... */ }
    void speak(int times) { std::cout << "default speak x" << times << std::endl; }
};
```

在 Demo A 后面加上一行 `d.speak(3);`，先判断结果。预期是**编译失败**：

```text
error: no matching function for call to 'Dog::speak(int)'
```

编译器列出的候选只有一个 `void Dog::speak()`。这就是"隐藏"的确切含义：**派生类里声明了同名函数之后，基类里所有同名的重载版本一起被遮住**，不是只遮住参数相同的那一个。想让它们重新可见，需要在派生类里写一句 `using Animal::speak;`。看完把两处改动还原。

### 实验五：上转型（`upcast_reference`）

`upcast_reference\upcast_reference.cpp` 用基类引用、基类形参两种方式接收派生类对象，并打印地址比较证明"没有新建对象"。

```text
E:\msys64\ucrt64\bin\g++.exe -std=c++20 -Wall -g upcast_reference.cpp -o upcast_reference.exe
./upcast_reference.exe
```

**预期现象**：完整输出如下，共十行（地址比较为 `true`，两次通过基类调用都是 `default speak!`）：

```text
=== Demo A: the Dog uses its own version ===
woof
=== Demo B: the same object, now handled as an Animal ===
the reference points at the same object: true
default speak!
=== Demo C: it looks the same when the object is passed to a function ===
default speak!
=== Demo D: the Cat is upcast in exactly the same way ===
meow
default speak!
```

**验收标准**：`-Wall` 无警告；能说出 `(&ref == &d)` 是 `true` 说明了什么（上转型不复制对象）；能解释为什么经过 `Animal&` 调用就得不到 `woof`。

**改值实验**：把 Demo B 里的引用换成按值复制，再把地址比较换成新对象：

```cpp
Animal copy = d;                  // 按值复制：只复制基类部分
std::cout << "the reference points at the same object: "
          << std::boolalpha << (&copy == &d) << std::endl;
copy.speak();
```

先判断结果。预期是那一行变成 `false`（这次真的新建了一个对象），而下一行仍然是 `default speak!`。**对照着看这两行就能分清两件事**：`false` 说明按值接收会复制、会发生对象切片；`default speak!` 则说明"通过基类接口调用只能得到基类的实现"和复不复制无关——就算一个字节都不复制（本章第 8 节的引用），结果也一样。改完编译运行核对，然后还原。
