# 11 模板特化：为特定类型定制实现

上一篇：[[10 函数模板：让编译器生成函数版本]]

## 学习目标

完成本章后，你应当能够：

1. 说出"一份模板服务所有类型"这一前提在什么情况下不成立。
2. 用 `template <>` 为某个具体类型写出函数模板的显式特化，并说明那一行 `template <>` 的作用。
3. 解释特化为什么按完整类型精确匹配，例如 `std::array<int, 4>` 不会命中 `std::array<int, 3>` 的特化。
4. 说出显式特化的两条位置要求：主模板必须先声明、特化必须写在首次使用的调用之前。
5. 区分三种写法在行为上的差别：显式特化、漏写 `template <>` 的普通函数、更专门的模板重载。

## 1 模板覆盖不了的情况

第 10 章的 `printArray` 有一个隐含前提：**所有类型的处理方式都一样**。元素用空格分开、循环结束换行，对 `int` 数组、`float` 数组、`char` 数组都合适，所以一份模板就够了。

现在换一个需求：打印 `std::array<int, 3>` 时希望格式不同——比如不带尾随空格、用逗号分隔、前面加一个标记。这时"一份函数体服务所有类型"就不够用了。

自然的想法是在函数体里判断"`T` 是不是 `std::array<int, 3>`"，然后走不同的分支。这个想法在 C++ 里行不通：模板参数 `T` 是**类型**而不是值，没有可以用来比较的表达式，语言也没有提供"按类型分支"的语句。硬凑的写法要么编译不过，要么把代码写得既慢又难读；而且从设计上看这么写也不对——**"某几个类型要特殊处理"是签名的差异，不是运行期的分支**。

C++ 给出的机制是**模板特化**（template specialization）：**对某个具体类型，另外给一份实现**；其余类型继续使用原来那份通用实现。原来那份通用实现叫**主模板**（primary template），专门为某类型写的那一份叫**显式特化**（explicit specialization）。

## 2 显式特化的写法

例程 `E:\CPP_Code\CppFromScratch\ch11_template_specialization\specialization_basic\specialization_basic.cpp`：

```cpp
// 主模板：所有类型默认走这里
template <typename T>
void printArray(T array)
{
    std::cout << "baseline -> ";

    for (auto value : array)
    {
        std::cout << value << " ";
    }

    std::cout << std::endl;
}

// 显式特化：只针对 T = std::array<int, 3> 这一个类型
template <>
void printArray(std::array<int, 3> array)
{
    std::cout << "specialization -> ";

    bool first = true;

    for (auto value : array)
    {
        if (!first)
        {
            std::cout << ", ";
        }

        std::cout << value;
        first = false;
    }

    std::cout << std::endl;
}
```

`main` 里的调用完全不用改：

```cpp
printArray(myIntArray);      // 走特化
printArray(myFloatArray);    // 回落到主模板
```

```text
=== Demo A: primary template vs specialization ===
specialization -> 1, 2, 3
baseline -> 1.1 2.2 3.3 
```

（第二行末尾有一个空格，那是主模板"元素 + 空格"的写法留下的；特化版本用逗号分隔、最后一个元素后不加分隔符，所以第一行末尾没有空格。）

### 2.1 逐部分看特化的写法

- **`template <>`**：空尖括号的意思是"类型参数已经没有需要推导的了，全部写死了"。它同时向编译器声明"**下面这个不是新函数，而是前面那个模板在这个具体类型上的一个特例**"。这一行不能省，也不能写成 `template <typename T>`（见第 4 节）。
- **`void printArray(std::array<int, 3> array)`**：函数名和参数列表看起来和主模板实例化出来的那份函数一样，但它的身份是"特化"——属于那个模板，而不是一个独立函数。
- **特化只处理它写明的那个类型**，其余类型不受影响。所以 `float` 数组照旧走主模板。

### 2.2 两条位置要求

**第一，主模板必须先声明。** 特化是"某个模板的特例"，先得有那个模板。若一个 `template <>` 后面跟着的函数在作用域里根本找不到对应的主模板，GCC 报：

```text
error: 'printArray' is not a template function
```

**第二，特化必须写在任何会导致该类型被实例化的调用之前。** 编译器是按顺序处理的：如果在特化出现之前，某处已经用 `std::array<int, 3>` 调用过主模板，编译器那时就已经照主模板生成好了函数，后面再写特化也来不及了，于是报：

```text
error: specialization of 'void printArray(T) [with T = std::array<int, 3>]' after instantiation
```

这两条合起来，就是本章所有例程都把特化写在 `main` 之前的原因。在实际工程里，特化通常和主模板放在同一个头文件中、紧接着主模板写，就是为了保证"任何使用点都晚于它"。

## 3 特化按"完整类型"精确匹配

例程 `ch11_template_specialization\specialization_exact_type\specialization_exact_type.cpp` 准备了两份特化（`std::array<int, 3>` 与 `std::array<double, 3>`）和四种实参：

```cpp
std::array<int, 3> myIntArray3 {1, 2, 3};
std::array<int, 4> myIntArray4 {1, 2, 3, 4};
std::array<double, 3> myDoubleArray {1.5, 2.5, 3.5};
std::array<float, 3> myFloatArray {1.1f, 2.2f, 3.3f};
```

```text
=== Demo B: specialization matches the exact type only ===
array<int, 3>    : specialization int -> [1, 2, 3]
array<int, 4>    : baseline -> 1 2 3 4 
array<double, 3> : specialization double -> 1.5|2.5|3.5
array<float, 3>  : baseline -> 1.1 2.2 3.3 
```

匹配规则可以用一张表说清：

| 实参类型 | 与特化 `std::array<int, 3>` 是否同一类型 | 使用哪份实现 |
| --- | --- | --- |
| `std::array<int, 3>` | 是 | 特化 |
| `std::array<int, 4>` | 否（**元素个数是类型的一部分**） | 主模板 |
| `std::array<double, 3>` | 否（元素类型不同） | 另一份特化 |
| `std::array<float, 3>` | 否 | 主模板 |

**"元素个数不同就不算命中"是最容易踩的坑**，因为它和第 10 章的模板用法形成了对比：主模板不关心元素个数（`T` 整体被替换，`3` 还是 `4` 都无所谓），而特化是"给某个完整类型开小灶"，类型一个字都不能差。这也正是第 05 章那句"`std::array` 的长度是类型的一部分"在这里的具体后果：`std::array<int, 3>` 和 `std::array<int, 4>` 是两个毫不相干的类型。

## 4 三种容易混淆的写法

想给某类型定制实现时，一共有三种看上去差不多、行为却不一样的写法。分清它们，特化就算学明白了。

### 4.1 漏写 `template <>`：那是普通函数，不是特化

例程 `ch11_template_specialization\specialization_vs_overload\specialization_vs_overload.cpp` 里，第二个 `printArray` 和主模板的参数类型写得一模一样，唯一差别是**没有** `template <>`：

```cpp
template <typename T>
void printArray(T array)
{
    std::cout << "primary template" << std::endl;
}

void printArray(std::array<int, 3> array)     // 注意：不是特化
{
    std::cout << "plain non-template function" << std::endl;
}
```

```text
=== Demo D: a plain function is not a specialization ===
direct call        -> plain non-template function
explicit arg call  -> primary template
```

两个调用的实参相同、函数名相同，结局却相反：

- `printArray(myIntArray);` 时，普通函数与"主模板实例化出来的那份函数"都精确匹配，重载解析的规则里**普通函数优先于模板**，所以选中了普通函数。
- `printArray<std::array<int, 3>>(myIntArray);` 里尖括号是模板专属语法，**一旦写出尖括号，候选里就只剩模板**，普通函数连参与比较的资格都没有，于是实例化主模板并调用。

而第 2 节的显式特化是模板的一部分，两种调用方式都会走同一份特化实现。**这正是 `template <>` 必须写的原因**：它决定了这份实现是"模板的特例"，还是"另一个碰巧同名的普通函数"。漏写时程序照样能编译通过（`-Wall` 也不会提示），只是特化悄悄没有生效——这类"不报错但不符合预期"的问题最难发现，所以写完特化后最好用显式模板实参的调用方式验证一次。

### 4.2 特化的参数列表必须落在主模板的范围内

特化的参数类型必须是主模板"能够变成的形状"。主模板是 `template <typename T> void printArray(T array)`（一个类型参数），所以 `std::array<int, 3>` 是可以的（它就是某个 `T`）；但如果把参数写成主模板根本产生不出来的形式，例如两个参数：

```cpp
template <>
void printArray(int first, int second);   // 主模板只有一个参数，这不是它的特化
```

GCC 报：

```text
error: template-id 'printArray<>' for 'void printArray(int, int)' does not match any template declaration
```

遇到这条错误，就回去把特化的参数列表和主模板的参数列表对齐。

### 4.3 函数模板没有"偏特化"，需要的可以重载一个更专门的模板

如果想要的不是"某一个类型"，而是"某一类类型"——比如"元素类型任意、但只要长度为 3 的 `std::array`"——显式特化做不到，因为 `template <>` 要求把类型写全。类模板有**偏特化**（partial specialization，只写一部分参数），但**函数模板不支持偏特化**，写出来会被当成别的意思（下一段的实验会看到其中一种）。

可行的替代办法是**重载一个更专门的函数模板**，让它的参数把想固定的部分固定、想保留的部分继续当模板参数：

```cpp
template <typename T>
void printArray(std::array<T, 3> array)   // 适用于所有长度为 3 的 std::array
{
    // ... 另一套格式 ...
}
```

主模板与它同时存在时，调用 `std::array<int, 3>` 会选中这个更专门的版本，而 `std::array<int, 4>` 仍然落到主模板——一次覆盖了一整类类型，比逐类型写显式特化省事。第 6.4 节会把这段代码亲手跑一遍。

## 5 主模板写成缩写形式时的特化

第 10 章讲过 C++20 的缩写函数模板（参数列表里写 `auto`）。主模板用这种写法时，特化语法完全不变。例程 `ch11_template_specialization\specialization_auto\specialization_auto.cpp`：

```cpp
void printArray(auto array)              // 主模板：等价于 template <typename T>
{
    std::cout << "baseline(auto template) -> ";

    for (auto value : array)
    {
        std::cout << value << " ";
    }

    std::cout << std::endl;
}

template <>                              // 特化写法与前一节一样
void printArray(std::array<int, 3> array)
{
    // ...
}
```

```text
=== Demo C: specializing an abbreviated template ===
specialization -> 1, 2, 3
baseline(auto template) -> 1.1 2.2 3.3 
```

缩写函数模板和普通函数模板一样可以被特化（标准里对这点有明确说明，本课程的 GCC 16 实测通过，调用时确实走特化）。**但工程上更推荐给类型参数起名的写法**：`T` 有名字，函数体里需要提到这个类型时能直接写出来，特化和错误信息也更可读；缩写形式适合那些"类型只出现在参数列表里、函数体完全不提它"的简单函数。

**第二处（4.3 节那条替代方案的验证）**：打开 `specialization_basic.cpp`，把特化那一段改成下面这样（`template <>` 换成 `template <typename T>`，参数改成带 `T` 的 `std::array<T, 3>`），函数体不变：

```cpp
template <typename T>
void printArray(std::array<T, 3> array)
{
    std::cout << "overload for array<T, 3> -> ";
    // ... 其余保持不变 ...
}
```

重新编译运行，**预期输出**（两行末尾都没有空格，因为逗号分隔的版本最后一个元素后不加分隔符）：

```text

overload for array<T, 3> -> 1.1, 2.2, 3.3
```

两行都用了新格式——**这个版本不只是覆盖 `int`，而是把所有长度为 3 的 `std::array` 一网打尽**，包括原来的 `float` 版本。这就是"重载一个更专门的模板"与"显式特化"的差别：特化一次只锁定一个完整类型，重载模板可以锁定一整类。看完把这些改动还原成原来的特化写法。

## 7 常见错误与排查

| 报错或现象 | 原因 | 处理 |
| --- | --- | --- |
| `error: specialization of 'void printArray(T) [with T = std::array<int, 3>]' after instantiation` | 特化写在"首次用该类型调用"的代码之后，编译器已经照主模板实例化过了 | 把特化移到所有使用点之前（通常就紧挨主模板写） |
| `error: 'printArray' is not a template function` | 写了 `template <>`，但作用域里没有对应的主模板（名字写错、主模板漏掉或写在后面） | 先声明主模板，再写特化；核对两者名字完全一致 |
| `error: template-id 'printArray<>' for 'void printArray(int, int)' does not match any template declaration` | 特化的参数列表和主模板对不上（个数、类型都不能凭空多出来） | 让特化的参数列表是主模板参数列表在某个具体类型下的形态 |
| 写了"特化"但输出看不出任何变化，编译也没有报错 | 漏写了 `template <>`，它成了一个普通的非模板重载；或者特化针对的类型和实际传的类型不完全一样 | 补上 `template <>`；并用显式模板实参调用 `printArray<std::array<int, 3>>(x)` 验证特化确实生效 |
| `std::array<int, 4>` 没有走针对 `std::array<int, 3>` 的特化 | 元素个数是类型的一部分，两者是不同的类型，特化不匹配 | 这是正常行为；真要覆盖就用 4.3 节"更专门的模板重载"，或者为该类型再写一份特化 |
| `error: redefinition of 'void printArray(std::array<int, 3>)'` | 同一类型上既有显式特化、又有一个同签名的普通函数 | 只保留一种写法；想让它属于模板就用 `template <>` |
| `warning: use of 'auto' in parameter declaration only available with '-std=c++20' or '-fconcepts'` | 主模板用了缩写形式（`auto` 参数），需要 C++20 | 加 `-std=c++20`；或把主模板改成 `template <typename T>` 的写法 |
| 特化版本里的形参没被使用，担心报错 | 未使用的形参不在 `-Wall` 的检查范围内 | 不用处理；如果确实要写"只用一份实现来标记身份"的函数，属正常写法 |
