# 33 虚函数：运行时的动态绑定

## 学习目标

完成本章后，你应当能够：

1. 说出为什么把派生类对象交给基类引用之后，行为会"退化"成基类版本。
2. 在基类的成员函数前加上 `virtual`，让派生类的实现重新生效。
3. 解释"静态绑定"和"动态绑定"的区别，并说出虚函数必须通过引用或指针调用的原因。
4. 在每个重写函数后面写 `override`，并说出它挡住了哪一类错误。
5. 判断一个成员函数该不该写成虚函数。

## 1 静态多态留下的问题

第 32 章做了一件事：把一个派生类对象交给基类的引用或指针，于是"狗"在代码里变成了"动物"。这个动作（向上转型）本身不复制任何数据，只是换了一种看待对象的方式。

那一章用的例子是这样的结构：

```cpp
struct animal
{
    void speak()
    {
        std::cout << "animal says something" << std::endl;
    }
};

struct dog : animal
{
    void speak()
    {
        std::cout << "dog says woof" << std::endl;
    }
};
```

`dog` 里写了同名的 `speak`，直接对 `dog` 对象调用时输出的是 `dog says woof`；但一旦写成 `animal& a = d; a.speak();`，输出就变回了基类的文字。原因在编译器身上：它读到你写的 `a.speak()` 时，只看到 `a` 的类型是 `animal&`，于是就把这次调用固定到 `animal::speak` 上。所有和类型有关的信息在编译期都是已知的，这种"编译时就把函数选好"的机制也叫**静态多态**。

静态多态有一个它解决不了的场景。我们把派生类对象向上转型，通常不是为了"抹掉"它们的行为，恰恰相反——是为了**把不同派生类的对象放在一起统一处理**，同时让每个对象保留自己的行为：一群动物各自叫各自的，而处理它们的代码只认识"动物"这一个类型。

可是编译器在编译期并不知道引用背后到底是什么对象。它需要的信息只有运行时才有：`a` 在运行时绑定的到底是一只狗、一只猫，还是别的什么。所以我们需要一种机制，把"调用哪个函数"这个决定**推迟到运行时**再做出——这就是虚函数。

## 2 虚函数

### 2.1 写法

把 `virtual` 写在成员函数的返回类型前面：

```cpp
struct animal
{
    virtual void speak()
    {
        std::cout << "animal says something" << std::endl;
    }
};
```

除了多出这一个关键字，函数本身没有任何变化：照样有返回类型、参数列表和函数体。派生类里也照旧写同名、同参数、同返回类型的函数：

```cpp
struct dog : animal
{
    void speak() override
    {
        std::cout << "dog says woof" << std::endl;
    }
};
```

这里的 `override` 是第 3 节的内容，先记住它的位置：跟在函数头的末尾。派生类中这个函数叫**重写**（override）了基类的虚函数；注意不要和第 09 章的**重载**（overload，同一个作用域里同名不同参数的多个函数）混淆，两者是完全不同的机制。

### 2.2 动态绑定

加上 `virtual` 之后，`animal& a = d; a.speak();` 输出的就是 `dog says woof` 了。编译器不再把这次调用钉死在 `animal::speak` 上，而是生成一段"运行时再决定"的代码：程序执行到这一行时，先看引用实际绑定了哪一个对象，再调用那个对象所属类型的 `speak`。这个选择过程叫**动态绑定**，这样发生的调用叫**虚调用**。

可以把这件事理解成两种信息的分离：

- **引用或指针的类型**决定"你能看见哪些接口"。`animal&` 只能看见 `animal` 里声明过的成员，`.walk()` 之类的派生类成员根本不在视野内（编译期就会报 `'struct animal' has no member named 'walk'`）。
- **对象的实际类型**决定"调用哪一份实现"。这正是虚函数接管的部分。

实现上，编译器通常会为每个带虚函数的对象准备一份"这个类型该用哪些函数"的信息，虚调用时据此查找。具体机制属于进阶内容，本章只需要知道两件事：它发生在运行时，因此比普通函数调用**多一层开销**；而对同一个虚函数的反复调用，开销换来的是"用一份代码处理一族对象"的能力。

### 2.3 虚函数只在通过引用或指针调用时才起作用

这一点必须强调，因为它是虚函数最常见的失效原因。虚函数的动态绑定发生在**通过引用或指针调用**的时候：

```cpp
dog d;
animal& a = d;      // 引用：虚调用生效，输出 dog says woof
a.speak();

animal copy = d;    // 按值：对象被切片，只剩 animal 那一部分（第 32 章）
copy.speak();       // 这里调用的一定是 animal::speak
```

把派生类对象**按值**赋给基类对象或按值传给基类形参，派生类多出来的成员会被切掉，得到的只是一个真正的 `animal` 对象——它里面已经没有"我曾经是狗"的信息了，虚函数自然也无从选择。**想用多态，就传引用或指针。**

### 2.4 基类的版本并没有消失

虚函数只是让"通过基类引用调用时选到派生类版本"，基类那一份实现仍然存在，也仍然可以调用：

```cpp
animal a;
a.speak();          // 一个普通的 animal 对象：走基类版本

dog d;
d.animal::speak();  // 用"类名::函数名"显式指定：绕过动态绑定，强制走基类版本
```

第二行的写法叫限定调用（静态调用）。它跳过虚调用机制，因此能在派生类对象上直接取用基类的实现——派生类重写时想在基类版本的基础上再补充点东西，就会用到它。

### 2.5 什么该写成虚函数

判断标准很简单：**这个函数的行为是否依赖"到底是哪一种派生类"**。依赖就写 `virtual`，不依赖就别加。

- 基类给出一个可以用、但派生类很可能想改掉的行为，例如"动物叫"，适合写成虚函数。
- 纯数据访问、和类型无关的工具函数不该是虚函数：白付运行时的开销，语义上也没有意义。

另外两条惯例：

- `virtual` 只需要写在基类。派生类里同名同签名的函数**自动就是虚函数**，写不写 `virtual` 都一样；但派生类里应当写 `override`（下一节）。
- 不要"以防万一"地给所有成员函数都加 `virtual`。虚调用有运行时开销，也会让类失去按值复制时那份简单的语义。

如果基类的某个函数连一份合理的默认实现都给不出来（"动物叫"就是这种：不存在一种通用动物叫声），那它应当写成**纯虚函数**，基类也随之变成抽象类——这是第 34 章的内容。

## 3 override 限定符

### 3.1 不写 override 时会静默出错

假设你在派生类里把 `speak` 拼错了一个字母：

```cpp
struct dog : animal
{
    void spec()      // 正确名字应该是 speak
    {
        std::cout << "dog says woof" << std::endl;
    }
};
```

编译器**不会报错**，因为从它的角度看这件事完全合法：你只是给 `dog` 新加了一个名叫 `spec` 的成员函数。基类的 `speak` 并没有被重写，它只是被 `spec` 这个新名字遮住了。于是程序照常编译通过，运行时 `d.speak()` 调用的是基类版本，所有狗叫都变成了 `animal says something`——一个没有任何报错、却和意图完全不符的行为。

### 3.2 override 让编译器替我们核对

在函数头末尾写上 `override`（C++11 起可用），就等于告诉编译器："这个函数是用来重写基类的某个虚函数的，请帮我核对。"

```cpp
struct dog : animal
{
    void spec() override     // 名字拼错了
    {
        std::cout << "dog says woof" << std::endl;
    }
};
```

编译器会去基类里找一个签名完全匹配的虚函数，找不到就直接报错：

```text
error: 'void dog::spec()' marked 'override', but does not override
```

同一个报错也会在**签名不一致**时出现。例如基类写的是 `virtual void speak() const`，派生类漏了 `const`：

```text
error: 'void dog::speak()' marked 'override', but does not override
warning: 'virtual void animal::speak() const' was hidden [-Woverloaded-virtual=]
```

两行信息指向同一个问题：`dog::speak()` 和 `animal::speak() const` 不是同一个函数，重写失败，基类版本被隐藏。

`override` 不改变函数的功能，它只是一条**给自己上的保险**。既然代价这么小，规则就是：凡是重写虚函数，一律写上 `override`。

## 4 动手实验

三个例程都在 `E:\CPP_Code\CppFromScratch\ch33_virtual_functions\` 下，每个单独一个文件夹。编译命令模板如下（把 `<例程名>` 替换成实际名字，`cd` 到对应文件夹）：

```text
cd "E:/CPP_Code/CppFromScratch/ch33_virtual_functions/<例程名>"
"E:/msys64/ucrt64/bin/g++.exe" -std=c++20 -Wall -g <例程名>.cpp -o <例程名>.exe
./<例程名>.exe
```

### 4.1 实验一：非虚函数的静态绑定

`E:\CPP_Code\CppFromScratch\ch33_virtual_functions\static_binding\static_binding.cpp` 里的 `animal::speak` **没有** `virtual`，派生类 `dog`、`cat` 各写了同名函数，`main` 里先直接调用，再通过 `animal&` 和 `animal*` 调用。

**预期输出**：

```text
=== Demo A: call the derived objects directly ===
dog says woof
cat says meow
=== Demo B: upcast to animal& and call speak ===
animal says something
animal says something
=== Demo C: the same thing happens through a base pointer ===
animal says something
animal says something
```

**验收标准**：Demo A 输出派生类行为，Demo B 和 Demo C 都输出基类行为；编译 `-Wall` 无警告。

**改值实验**：只改一个关键字——给 `animal::speak` 加上 `virtual`（派生类一个字都不用动），重新编译运行。此时 Demo B、Demo C 的每一行都应变成 `dog says woof` 与 `cat says meow`。看完把 `virtual` 删回去，确认输出恢复原样。这个对照实验说明：**行为差别只来自那一个关键字。**

### 4.2 实验二：虚函数与 override

`E:\CPP_Code\CppFromScratch\ch33_virtual_functions\virtual_override\virtual_override.cpp` 里 `animal::speak` 是虚函数，`dog`、`cat` 的重写函数都带了 `override`，`main` 里除了直接调用和向上转型调用之外，还演示了基类版本仍然可用。

**预期输出**：

```text
=== Demo A: direct calls on derived objects ===
dog says woof
cat says meow
=== Demo B: through animal&, the derived behavior is kept ===
dog says woof
cat says meow
=== Demo C: through animal*, the same ===
dog says woof
cat says meow
=== Demo D: the base version is still there ===
animal says something
animal says something
```

**验收标准**：Demo B、Demo C 输出派生类行为（这正是向上转型之后仍保留自身行为的证据）；Demo D 的两行都是基类版本，其中第二行来自 `d.animal::speak()` 这种限定调用；编译 `-Wall` 无警告。

**边界实验**：把 `dog` 里 `void speak() override` 的 `override` 删掉，再把函数名改成 `spec`，重新编译。程序能正常编译运行，但 Demo A 和 Demo B 的第一行都会变成 `animal says something`——行为悄悄改掉了，编译器一句话都不说。看完把名字和 `override` 都改回来。这是本实验最重要的验证：**没有 `override`，重写失败是静默的。**

### 4.3 实验三：把一族对象分组处理

`E:\CPP_Code\CppFromScratch\ch33_virtual_functions\virtual_grouping\virtual_grouping.cpp` 里多了第三个派生类 `cow`，`main` 把三种动物的地址放进同一个 `std::vector<animal*>`（第 14 章讲过 `vector`），再用循环调用；另有一个只认识 `animal&` 的函数 `makeItSpeak`。

**预期输出**：

```text
=== Demo A: a group of animals behind animal* ===
dog says woof
cat says meow
cow says moo
=== Demo B: a function that only knows animal ===
dog says woof
cat says meow
cow says moo
```

**验收标准**：两个 Demo 都按 `dog / cat / cow` 的顺序输出各自的声音；循环体和 `makeItSpeak` 都只出现 `animal`，没有一处判断"这个对象是狗还是猫"；编译 `-Wall` 无警告。

**改值实验**：给 `cow::speak` 换一句输出文字（例如 `cow says mooooo`），重新编译运行，只有第三行变化，其余两行和 `makeItSpeak`、循环体都不需要改。这说明新增一种动物时，处理代码一行都不用动——需要改的只有新增的派生类自己。

## 5 常见错误与排查

| 报错或现象 | 原因 | 处理 |
| --- | --- | --- |
| `error: 'void dog::spec()' marked 'override', but does not override` | 写了 `override`，但基类里没有签名匹配的虚函数（名字拼错、参数或 `const` 不一致） | 逐字核对基类虚函数的完整签名，改成完全一致 |
| `warning: 'virtual void animal::speak() const' was hidden [-Woverloaded-virtual=]` | 派生类同名函数签名与基类虚函数不一致（常见是漏了 `const`），基类版本被隐藏 | 补齐签名；确认自己确实是要重写而不是新增函数 |
| 编译通过、运行结果却是基类行为，且没有任何警告 | 派生类函数名字拼错，又没有写 `override`，成了新函数 | 给所有重写函数加 `override`，让编译器在编译期拦住 |
| `error: 'virtual' outside class declaration` | 把 `virtual` 用在了非成员函数（自由函数）上 | `virtual` 只能用于类的成员函数；检查函数是否写在了类外或类内位置不对 |
| `error: 'struct animal' has no member named 'walk'` | 通过基类引用或指针调用派生类才有的成员 | 引用/指针只能看见基类声明过的成员；把需要的接口提到基类里，而不是在派生类里藏着 |
| 通过基类引用调用仍然是基类行为 | 对象是按值传进来或按值赋给基类对象的，派生类部分已被切片（第 32 章） | 参数写成基类的引用或指针，避免按值传递 |
| `error: 'void dog::speak()' marked 'override', but does not override` | 基类那一份忘了写 `virtual`，派生类却写了 `override` | 给基类的成员函数加上 `virtual`；只有虚函数才能被重写 |
| 给所有成员函数都加了 `virtual`，程序变慢 | 虚调用需要在运行时确定目标，比普通调用多一层开销 | 只把"行为依赖具体派生类型"的函数写成虚函数 |
