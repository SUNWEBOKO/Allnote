## 1 手写比较运算符的麻烦

第 27 章讲过运算符重载：想让自定义类型支持某个运算符，就得自己把这个运算符写出来。比如两个对象的相等比较：

```cpp
bool operator==(const point& rhs) const
{
    return x == rhs.x && y == rhs.y;
}
```

逻辑很简单，但它是纯粹的机械劳动，而且有两个麻烦：

- **成员一多就容易漏。** 加一个新数据成员，回头就得记着把这个函数改一遍；漏掉一个成员，两个本该不相等的对象就会判成相等——这种错误很难通过肉眼发现。
- **六个运算符之间的关系要保持一致。** 相等比较有 `==` 和 `!=`，大小比较有 `<`、`<=`、`>`、`>=`，一共六种。如果全部手写，我们不仅要写六遍，还得保证它们彼此不矛盾（比如 `a <= b` 和 `b >= a` 必须给出相同的结论）。这对写代码的人来说是很容易出错的负担。

C++20 提供了**默认比较**：和函数模板、类模板一样，把这类机械工作交给编译器。我们只声明"这个类型有比较运算符"，并在后面写 `= default`（第 26、28 章用这个写法默认化过拷贝与移动构造函数），编译器就把实现填进去。

## 2 默认化的相等比较

### 2.1 写法

```cpp
struct s
{
    int a;
    int b;

    bool operator==(const s&) const = default;
};
```

三个细节和手写版本完全一样，只有函数体被换成了 `= default`：

- 返回类型是 `bool`；
- 参数是 `const s&`（第 16、26 章的理由：比较只读取，不该复制也不该修改）；
- 函数自己是 `const` 成员函数（比较不应该改动自己）。

**不写这一行就没有 `==` 可用。** 两个结构体长得一样，编译器并不会因此就认为它们能比较：

```text
error: no match for 'operator==' (operand types are 's' and 's')
```

### 2.2 比较规则：逐成员、按声明顺序

默认化版本做的事就是"把每个数据成员都比一遍"：按成员声明的顺序逐个比较，一旦发现某个成员不相等就立刻返回 `false`（不再看后面的成员），全部相等才返回 `true`。所以输出是 `0`（假）或 `1`（真）：

```cpp
s s1 {1, 2};
s s2 {1, 3};
std::cout << (s1 == s2) << std::endl;   // 输出 0：成员 b 不相等
```

`!=` 不需要额外声明。C++20 规定 `a != b` 会被自动当作 `!(a == b)` 处理，所以只默认化 `==` 就有两种比较可用。但要注意**这适用于 `!=`，不适用于 `<`、`<=`、`>`、`>=`**：只默认化 `==` 时写 `s1 < s2` 仍然编译失败（`no match for 'operator<'`），关系比较要等下一节的三向比较运算符来提供。

### 2.3 成员自身必须支持比较

默认化只是把工作交给编译器，它不能凭空创造比较能力。如果类里有一个成员的类型自身不支持 `==`，那么这个默认化的 `==` 会被定义为**删除的**（deleted），一使用就报错：

```text
error: use of deleted function 'constexpr bool s::operator==(const s&) const'
note: 'constexpr bool s::operator==(const s&) const' is implicitly deleted because the default definition would be ill-formed:
error: no match for 'operator==' (operand types are 'inner' and 'inner')
```

处理办法有两个：给那个成员类型补上比较运算符，或者自己手写外层的 `==` 并明确说明这种比较该怎么定义。

## 3 三向比较运算符

### 3.1 写法与目的

只默认化 `==` 还不够——我们还缺 `<`、`<=`、`>`、`>=`。一个一个默认化做不到（`operator<` 这类不能默认化），标准给出的方案是**三向比较运算符**，运算符符号写成 `<=>`（因为形状像飞碟，通常被叫作飞船运算符）：

```cpp
struct s
{
    int a;
    int b;

    auto operator<=>(const s&) const = default;
};
```

和上一节唯一的差别是：运算符名换成 `<=>`，返回类型写 `auto`。写了这一行之后，六种比较就都可以用了：

```cpp
std::cout << (s1 <  s2) << std::endl;   // 1
std::cout << (s1 <= s2) << std::endl;   // 1
std::cout << (s1 >  s2) << std::endl;   // 0
std::cout << (s1 >= s2) << std::endl;   // 0
std::cout << (s1 == s2) << std::endl;   // 0
std::cout << (s1 != s2) << std::endl;   // 1
```

### 3.2 关于 `==` 的一条关键区别

这一节的内容很容易记错，所以分开说清楚：

- **默认化的 `<=>`（写 `= default`）会连带声明一个对应的 `==`。**标准规定：如果一个类里没有自己声明 `operator==`，那么每个声明为默认化的 `operator<=>` 都会隐式声明一个对应的 `operator==`（返回类型改成 `bool`，其余属性照抄）。所以上面那一行代码就凑齐了全部六种比较运算符——这也是为什么例程 `spaceship_default` 里只写了 `<=>` 却能使用 `==` 和 `!=`。
- **自己手写的 `<=>`（不写 `= default`）不带这个附带效果。**这种情况下必须另外声明 `==`，通常就是再写一句 `bool operator==(const s&) const = default;`。少了它，代码里出现的 `==` 会直接报 `error: no match for 'operator==' (operand types are 's' and 's')`。

一句话的结论：**如果类里的比较运算符有一部分是手写的，就要自己确认 `==` 是否已经被声明出来。**这也是本章最容易踩的一个坑。

### 3.3 返回值不是一个 bool

`<=>` 的返回值不是 `true` / `false`，而是一个表示"大小关系"的对象（下一节讲它有几种）。这样设计的原因很直接：一次比较就能表达三种结果，而不是分三次调用才知道谁大谁小。

虽然它不是 `bool`，但用起来有两条简单规则：

- **和 0 比较**：`(a <=> b) < 0` 等价于 `a < b`，`(a <=> b) == 0` 等价于 `a == b`。所有重写出来的关系运算符（`<`、`<=`、`>`、`>=`）内部就是这么定义的。
- **不能直接打印**：`std::cout << (a <=> b)` 会报 `no match for 'operator<<' (operand types are 'std::basic_ostream<char>' and 'std::strong_ordering')`。要看它是什么结果，可以跟 0 比较后输出 `bool`，或者像例程里那样写一个小函数把结果翻译成文字，也可以用标准库提供的 `std::is_lt`、`std::is_eq` 等判断函数。

## 4 比较的三种强度

比较结果有类型，而这个类型由**数据成员**决定。三种强度从强到弱是：

| 比较类别 | 结果取值 | 适用于 | 相等时打印出的词 |
| --- | --- | --- | --- |
| `std::strong_ordering` | `less` / `equal` / `greater` | 整数、指针等"相等就是真的相同"的类型 | `equal` |
| `std::weak_ordering` | `less` / `equivalent` / `greater` | 相等但未必相同的类型（例如忽略大小写的字符串） | `equivalent` |
| `std::partial_ordering` | `less` / `equivalent` / `greater` / `unordered` | 浮点数：NaN 无法和任何值比较 | `equivalent` |

三个要点：

- **默认化时写 `auto` 就是在让编译器去算这个类型。**全是 `int` 成员时得到 `std::strong_ordering`；只要有一个 `double` 成员，整体就退到 `std::partial_ordering`。取的是各成员里最弱的那个。
- **`partial` 比另外两种多一个取值 `unordered`（无法比较）。**它存在的唯一原因就是浮点数的 NaN：NaN 和任何值比大小都不成立。
- **`strong` 的"相等"叫 `equal`，另外两种叫 `equivalent`（等价）。**同一片信息在 `weak` 的语义下只是"等价"：比如忽略大小写时 `"ABC"` 和 `"abc"` 等价，但它们并不是同一个字符串。

NaN 的具体表现必须记住，实测（见例程 `ordering_categories`）在含 NaN 的比较里：

```text
nan <  1.0 -> 0
nan >  1.0 -> 0
nan <= 1.0 -> 0
nan == 1.0 -> 0
nan != 1.0 -> 1
```

六个比较里只有 `!=` 为真（因为它就是 `!(==)` 的结果），其他全部为假。所以把可能含 NaN 的值当作排序关键字，排序的行为是不可靠的——这也是"偏序"这个名字的含义：任意两个值不一定都能比出大小。

## 5 逐成员比较的规则：字典序

默认化的 `<=>` 和默认化的 `==` 一样，都按**成员声明顺序**逐个比较，而且一旦某个成员分出了大小就立刻有结论，后面的成员不再参与。这就是**字典序**（lexicographical order），和查字典时比较单词的规则完全相同。

看一组具体数据：

```cpp
s p1 {1, 30};
s p2 {10, 20};
std::cout << (p1 < p2) << std::endl;    // 输出 1
```

`p1` 的第二个成员（30）比 `p2` 的（20）大，但结论仍然是 `p1 < p2`——因为第一个成员 `1 < 10` 已经把胜负定下来了。**第一个不同的成员说了算。**

这条规则带来一个非常实用的推论：**成员声明的顺序就是排序关键字的优先级。**想让 `score` 当第一关键字，就把它声明在 `id` 前面，一行比较代码都不用改。例程 `sort_with_spaceship` 就是把这个推论用到 `std::sort` 上的例子：类型只多了一行 `= default`，就立刻可以排序、可以求最值。

## 6 该用哪一种

- **只需要判断相等**（例如作为 `std::map` 的键的辅助判断、查找重复项）：只默认化 `==`。
- **需要排序或比较大小**：默认化 `<=>`。它顺带会声明 `==`；如果你更希望把意图写明白，也可以把 `==` 那行显式写出来，两行一起写不会冲突。
- **需要自定义比较规则**（只看某几个成员、或者按某种特别的顺序）：自己手写 `<=>`，并且**用同样的规则写 `==`**。C++20 要求这两个运算符的结论一致，否则同一对对象会得出互相矛盾的答案。
- **标准与编译器**：默认比较与三向比较运算符属于 C++20。本课程所有例程统一用 `-std=c++20`（GCC 10 及以后支持）。忘了加这个参数时会看到 `<=>` 被拆成 `operator<=` 和 `>` 去解析所引发的一串报错，例如：

```text
error: declaration of 'operator<=' as non-function
error: expected ';' at end of member declaration
```

### 7.2 实验二：默认化的三向比较运算符

`E:\CPP_Code\CppFromScratch\ch36_three_way_comparison\spaceship_default\spaceship_default.cpp` 里只有一个类型，只写了一句 `auto operator<=>(const s&) const = default;`（没有单独写 `==`），`main` 里把六种比较全部用了一遍，并单独考察了 Demo B 的字典序结论。

```cpp
std::strong_ordering operator<=>(const s& rhs) const
{
    if (a != rhs.a)
    {
        return a <=> rhs.a;
    }

    return b <=> rhs.b;
}
```

此时六种比较里的 `==` 与 `!=` 会编译失败，报 `error: no match for 'operator==' (operand types are 's' and 's')`：**手写的 `<=>` 不会附带 `==`**。补上一句 `bool operator==(const s&) const = default;` 之后，六种比较又全部可用。看完把类型改回 `= default` 的版本。

### 7.3 实验三：比较的三种强度与 NaN

`E:\CPP_Code\CppFromScratch\ch36_three_way_comparison\ordering_categories\ordering_categories.cpp` 里有三个类型：`strong_pair`（全是 `int`）、`partial_pair`（一个 `double`）、`magnitude`（手写 `<=>` 与 `==` 的自定义规则）。

### 7.4 实验四：把默认比较用到标准库算法上

`E:\CPP_Code\CppFromScratch\ch36_three_way_comparison\sort_with_spaceship\sort_with_spaceship.cpp` 里 `record` 只有两个 `int` 成员和一行 `auto operator<=>(const record&) const = default;`，`main` 用 `std::sort`（第 13 章）排序，并用 `std::min_element`、`std::max_element` 取最值。

**验收标准**：Demo B 的顺序是先按 `id` 升序、`id` 相同时按 `score` 升序（这就是"成员声明顺序即关键字优先级"）；Demo C 的 min 与 max 和排序结果的首尾一致；`std::sort` 调用时没有传任何比较函数；编译 `-Wall` 无警告。

```text
=== Demo B: after std::sort ===

id = 1, score = 90
id = 2, score = 100
id = 3, score = 80
=== Demo C: min and max are chosen by the same rule ===
min -> id = 1, score = 70
max -> id = 3, score = 80
```

新记录排在 `id = 1` 的两条之后、`id = 3` 的那条之前——它的 `score` 最大也没用，因为 `id` 是第一关键字；`max` 仍然是 `id = 3, score = 80`，原因相同。这直接说明了"成员声明顺序就是关键字优先级"。（如果把 `record` 里两行成员声明交换位置，输出同样会变，但两个 `push_back` 里的初值也会按新的声明顺序被填进去，数字看起来会很乱，所以观察优先级用上面这种加一条记录的方式更清楚。）

## 8 常见错误与排查

| 报错或现象 | 原因 | 处理 |
| --- | --- | --- |
| `error: no match for 'operator==' (operand types are 's' and 's')` | 类型没有可用的 `==`：既没默认化也没手写；或者 `<=>` 是自己手写的（手写版本不会附带 `==`） | 加上 `bool operator==(const s&) const = default;` |
| `error: no match for 'operator<' (operand types are 's' and 's')` | 只默认化了 `==`；`==` 只让 `!=` 也可以用，不提供关系比较 | 默认化 `<=>`，或自己写出需要的 `<` |
| `error: no match for 'operator<<' (operand types are 'std::basic_ostream<char>' and 'std::strong_ordering')` | 想把 `<=>` 的结果直接打印出来 | 结果与 0 比较后打印 `bool`，或用 `std::is_lt` / `std::is_eq` 等函数判断，或自己写一个翻译函数 |
| `error: use of deleted function 'constexpr bool s::operator==(const s&) const'`，note 里写 `implicitly deleted because the default definition would be ill-formed` | 某个数据成员的类型自身不支持 `==`（同一段错误里还会给出 `no match for 'operator==' (operand types are 'inner' and 'inner')`） | 给该成员类型补上比较运算符，或手写外层的 `==` |
| `error: expected ';' at end of member declaration`（报在 `<=>` 那一行） | 用 C++17 或更早的标准编译，`<=>` 被拆成 `operator<=` 和 `>` 解析 | 编译命令里加 `-std=c++20` |
| `error: could not convert '(left <=> right)' from 'std::partial_ordering' to 'std::strong_ordering'` | 手写的 `<=>` 声明的返回类型比成员实际给的类别强（例如用 `double` 成员却声明返回 `std::strong_ordering`） | 把返回类型改成 `std::partial_ordering`，或干脆写 `auto` 交给编译器 |
| 排序或取最值的结果不符合预期 | 默认比较按成员声明顺序，第一个成员就是主关键字 | 调整数据成员的声明顺序，而不是去改比较函数 |
| 手写的 `<=>` 只看部分成员，而 `==` 用的是逐成员默认版本，两者结论互相矛盾 | `==` 与 `<=>` 必须按同一规则定义 | 手写 `==` 并让它与 `<=>` 保持一致 |
