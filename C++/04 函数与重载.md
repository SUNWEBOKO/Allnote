# 04 函数与重载

## 学习目标

完成本章后，你应当能够：

1. 说出一个函数由哪四个部分组成，定义并调用带参数与返回值的函数，并在调用处接住返回值。
2. 说明形参与实参的"一份副本"关系，以及把重复代码提取成函数之后代码好在哪里。
3. 写出两个同名重载函数，说出编译器依据哪些信息区分它们。
4. 按精确匹配、类型提升、类型转换的优先顺序预判一个调用会选中哪个重载。
5. 看懂"无法转换""调用有歧义""重定义""漏 `return`"这几类与函数和重载相关的报错。

## 1 为什么需要函数

到这里，我们已经掌握了三种控制流：

- **条件语句**让代码**有选择地执行**（第 02 章）；
- **循环**让代码**重复执行**（第 03 章）；
- **函数**是第三种：它给一段语句序列**起一个名字**，之后用这个名字就能把那段语句执行一遍。

为什么需要它？因为有一类重复**不适合用循环解决**。假设你要打印数组，第 03 章的做法是写一段范围 `for` 加一句换行：

```cpp
for (int value : myArray1)
{
    std::cout << value << " ";
}
std::cout << std::endl;
```

只用一次没问题。但如果程序要先打印 `myArray1`、中间做别的事、再打印 `myArray2`、最后还要再打印一次 `myArray1` 呢？这四行会被复制三份。这时**不能用循环**——这几次调用不是连续发生的，中间隔着别的操作，而且每次处理的数组还不一样。你也不想在程序里留下三份一模一样、将来改格式要改三处的代码。

解决办法就是把这段代码**提取出来、起个名字**，以后需要时就写这个名字。这个"有名字的语句块"就是函数。前面的章节里我们一直在用函数，只是写的一直是最特殊的那一个：`main`。

## 2 函数的四个组成部分

回忆第 01 章拆解过的 `main`：

```cpp
int main()
{
    return 0;
}
```

它由四部分组成，**任何函数都是这四部分**：

| 组成 | 在 `main` 里 | 作用 |
| --- | --- | --- |
| 返回类型 | `int` | 函数执行完之后交回什么类型的值；不交回任何值就写 `void` |
| 函数名 | `main` | 调用时使用的名字 |
| 参数列表 | `()` | 调用这个函数时必须提供哪些输入；不接收输入就留空 |
| 函数体 | `{ return 0; }` | 调用时真正执行的那些语句 |

`main` 的特殊之处只有一点：它是程序执行的起点。**除此之外，它的结构和我们接下来要自己写的函数完全一样。**

## 3 定义并调用一个不返回值的函数

例程 `E:\CPP_Code\CppFromScratch\ch08_functions\print_array\print_array.cpp` 里把打印数组的工作提成了一个函数：

```cpp
void printArray(std::array<int, 3> array)
{
    for (int value : array)
    {
        std::cout << value << " ";
    }
    std::cout << std::endl;
}
```

逐部分看：

- **返回类型 `void`**：`void` 的意思是"没有值"。这个函数只负责把数组打到屏幕上，算不出也不需要交回任何结果，所以返回类型是 `void`，函数体里也**没有、不需要 `return` 语句**。
- **名字 `printArray`**：见名知意——读者看到调用处写 `printArray(...)`，不用再去看函数体就知道这里在做什么。**给函数起一个能说明动作的名字，是函数能不能提升可读性的关键。**
- **参数列表 `(std::array<int, 3> array)`**：这是函数的输入清单。这里声明"我需要一个能装 3 个 `int` 的数组"，前半段是**类型**，后半段的 `array` 是这个输入在函数体内的**名字**（本章第 5 节会讲这个名字的性质）。
- **函数体**：真正执行的语句，这里是第 03 章学过的元素访问和范围 `for`。

**定义好之后，调用就只是写一行名字加实参**：

```cpp
int main()
{
    std::array<int, 3> myArray1 {1, 2, 3};
    std::array<int, 3> myArray2 {4, 5, 6};

    printArray(myArray1);
    printArray(myArray2);

    return 0;
}
```

### 3.1 调用时发生了什么

调用 `printArray(myArray1);` 这一句时，控制流是这样的：**程序跳到 `printArray` 的函数体，从第一条语句开始执行，把整个函数体跑完，然后回到调用处，继续执行下一句。** 所以上面 `main` 的执行顺序是：创建两个数组 → 打印第一个 → 打印第二个 → `return 0`。

函数体里那段范围 `for` 加换行的代码只写了一份，却运行了两次，每次处理的是不同的数组。

### 3.2 一个函数只做一件事

`printArray` 只做打印。这不是偶然的——**把功能拆成"只做一件事"的小函数**，好处是这个函数容易看懂、容易测试、容易被别处复用。反过来，如果写一个函数既打印又求和又修改数组，它的名字就没法起得准确，调用它的人也无法预料副作用。

## 4 带返回值的函数

`void` 函数只做事、不交结果。如果函数要**算出一个结果交回调用处**，返回类型就写成结果的类型，并在函数体里用 `return` 把值交出去。

`ch08_functions\return_value\return_value.cpp` 里的求和函数：

```cpp
int sum(std::array<int, 3> array)
{
    int total = 0;

    for (int value : array)
    {
        total += value;
    }

    return total;
}
```

四点要注意：

- **返回类型是 `int`**：这个函数做的事是把若干整数加起来，整数相加的结果仍是整数（第 02 章讲的类型规则），所以用 `int` 装结果正合适。
- **累加器必须初始化。** `int total = 0;` 这一句不能省：如果只写 `int total;`，它里面是什么值没有保证，从这个不确定值往上加，结果自然也是错的。这和第 02 章"不要留下未初始化的变量"是同一条规则。
- **`total += value;`** 是 `total = total + value;` 的简写：先算右边的新总和，再存回 `total`，于是它一轮一轮地变大。
- **`return total;`** 做两件事：**立刻结束这个函数的执行**（函数体里 `return` 之后的语句都不会再执行），并把 `total` 的值交回调用处。

### 4.1 在调用处接住返回值

函数交回的值需要有地方存放：

```cpp
int result = sum(myArray);      // 用变量接住
std::cout << result << std::endl;
```

也可以让编译器推断类型：

```cpp
auto result = sum(myArray);     // result 被推断成 int，因为 sum 的返回类型是 int
```

之所以可以这样写，是因为 `sum` 的**返回类型已经明确写了 `int`**——推断的依据是现成的，用 `auto` 只是省掉我们重复写一遍类型名（第 02 章 6.4 节的原则：类型短而明确就写出来）。

返回值不接住也能编译（比如直接写 `sum(myArray);`），但那个结果就被丢掉了，这个调用等于白做——**除非你调用它的目的就是它内部的副作用**（例如 `printArray` 那种只打印的 `void` 函数）。

### 4.2 返回类型不是 `void` 时必须 `return`

漏写 `return` 时，编译器会给出警告：

```text
warning: no return statement in function returning non-void [-Wreturn-type]
```

注意这**只是警告，不是错误**——程序照样能编译出可执行文件，但调用处拿到的返回值是不确定的（未定义行为）。这类"能编译、结果乱"的问题最难查，所以这条警告必须逐条看完——`-Wreturn-type` 在 GCC 上**默认就开**，不依赖 `-Wall`。本课程的编译任务仍统一带 `-Wall`，是为了连同其他警告一起暴露出来。

## 5 形参与实参：一份副本

函数定义里 `(std::array<int, 3> array)` 中的 `array` 叫**形参**（形式参数），调用时传进去的 `myArray1` 叫**实参**（实际参数）。两者是"一份副本"的关系：

- 形参 `array` 是实参 `myArray1` 的一份**拷贝**。函数内部操作的是这份拷贝。
- 因此**在函数里改动 `array` 不会影响外面的 `myArray1`**。这个性质在"函数只读取数据、不修改原数据"时正好合适，`printArray` 和 `sum` 都属于这种情况。
- 名字也不必相同：调用时写 `printArray(myArray1)`，函数内部用的名字仍然是 `array`。函数内部只认自己的形参名。

**这里要明确一个边界**：按值传参意味着**每次调用都会复制整个数组**，元素很多时会有额外的时间和内存开销。更高效的传参方式（按引用传参、以及"只读引用"）会在后续课程里讲，本章先用最直观的副本形式把函数的基本结构立起来。

## 6 用函数换来了什么

回到本章第 1 节那段被复制三份的打印代码，现在它变成了三次一行调用。三个好处：

1. **不再有重复代码。** 打印逻辑只有一份。
2. **调用处一眼可见意图。** `printArray(myArray2);` 摆在那里，读者不需要逐行辨认一段循环到底在做什么。
3. **修改只在一处生效。** 将来想把输出格式从"空格分隔"改成"逗号分隔"，只改函数体里的那一处，所有调用自动跟着变；而复制三份的写法要改三处，漏一处就出现行为不一致。

还有一条容易被忽略的好处：**函数可以在程序的任何位置被调用**。前面几章的处理逻辑都得挤在 `main` 里按顺序写下来，一旦某段逻辑需要在开头、中间、结尾各用一次，就只能复制。有了函数，这段逻辑从 `main` 里搬出去、起了名字，需要时调用一次即可——`main` 也变得短了，读起来像一份提纲：创建数据、调用函数、输出结果。

## 7 名字应该描述"做什么"，而不是"处理哪种类型"

本章第 3 节的 `printArray` 只能打印 `std::array<int, 3>`。现在多一个需求：把 `std::array<float, 3>` 也打印出来。

最直接的做法是复制一份、改掉参数类型：

```cpp
void printIntArray(std::array<int, 3> array);
void printFloatArray(std::array<float, 3> array);
```

这样写能跑通，语法上没有任何问题。**代价不在代码里，而在使用者的脑子里**：调用的人必须记住"打印 int 数组要用哪个名字、打印 float 数组要用哪个名字"。而且需求会继续膨胀——今天加 `float`，明天加 `double`、加 `char`，名字就变成 `printIntArray`、`printFloatArray`、`printDoubleArray`……一套功能拖着四个名字。

问题的根源在于：**我们把"类型"编进了名字里**。而类型信息本来就写在实参上，不需要再复制到函数名里：

```cpp
std::array<float, 3> myFloatArray {1.1f, 2.2f, 3.3f};
printFloatArray(myFloatArray);   // 类型在实参里已经说清楚了，函数名里又重复一遍
```

C++ 给出的方案是：**允许几个函数共用同一个名字，由编译器根据实参去挑该调用哪一个。** 这个机制叫**函数重载**（function overloading），编译器挑版本的过程叫**重载解析**（overload resolution）。于是函数名回到它该有的样子——只描述做什么：

```cpp
std::array<int, 3> myIntArray {1, 2, 3};
std::array<float, 3> myFloatArray {1.1f, 2.2f, 3.3f};

printArray(myIntArray);      // 编译器选中处理 int 数组的那一份
printArray(myFloatArray);    // 编译器选中处理 float 数组的那一份
```

这也是本章第 1 节"把重复代码提取成函数"的延续：那一次消除的是**语句的重复**，这一次消除的是**名字的重复**。

## 8 用同一个名字写两个函数

例程 `E:\CPP_Code\CppFromScratch\ch09_overloading\overload_basic\overload_basic.cpp` 把上一节的设想写了出来：

```cpp
void printArray(std::array<int, 3> array)
{
    for (auto value : array)
    {
        std::cout << value << " ";
    }

    std::cout << std::endl;
}

void printArray(std::array<float, 3> array)
{
    for (auto value : array)
    {
        std::cout << value << " ";
    }

    std::cout << std::endl;
}
```

两个函数同名 `printArray`，参数列表里的类型一个是 `std::array<int, 3>`、一个是 `std::array<float, 3>`。编译、链接、运行都没有问题，`main` 里只需照常调用：

```cpp
std::cout << "=== Demo A: one name, two overloads ===" << std::endl;

printArray(myIntArray);
printArray(myFloatArray);
```

```text
=== Demo A: one name, two overloads ===
1 2 3 
1.1 2.2 3.3 
```

（两行数字后面各有一个空格，因为函数体是"元素 + 空格"逐个数打印的，最后一个元素后面也带一个空格。）

**怎么确认编译器真的调用了两个不同的函数，而不是碰巧把两行都打印成了同一个结果？** 把两个函数体改成截然不同的内容，比如让第二个函数打印别的字，重新编译运行，两行输出就会明显不同。更彻底的验证是**删掉其中一个函数**再编译——`printArray(myFloatArray)` 立刻报错，这说明那一行确实依赖着被删掉的那个版本，两个调用走的是两份不同的代码（动手实验 12.7 就是做这件事）。

## 9 函数签名：编译器靠什么区分两个同名函数

编译器判断"这两个同名函数是不是同一个"依据的是**函数签名**（function signature）。对普通函数来说，签名由三部分构成：

| 是否参与签名 | 内容 | 说明 |
| --- | --- | --- |
| 参与 | 函数名 | 名字不同就是两个函数，与重载无关 |
| 参与 | 参数的**个数** | `f(int)` 与 `f(int, int)` 是两个函数 |
| 参与 | 参数的**类型**（含顺序） | `f(int, double)` 与 `f(double, int)` 是两个函数 |
| **不参与** | 返回值类型 | 只有返回值类型不同 → 编译错误 |
| **不参与** | 参数名 | `f(int a)` 与 `f(int b)` 是同一个函数 |
| **不参与** | 函数体 | 函数体写得完全一样，也是同一个签名 |

**返回值类型不参与签名**这一条最容易记反。它的理由很实际：**调用处通常用不上返回类型来消歧**。看这两行：

```cpp
printArray(myIntArray);   // 返回值被丢掉，这里根本没有"要什么类型"的信息
auto value = pick();      // 如果 pick() 有两个只差返回类型的版本，这里该选哪个？
```

第一行里返回值压根没被使用，第二行里 `auto` 的含义恰恰是"由函数决定"。如果允许返回类型参与重载，编译器在大多数调用点上都找不到任何依据来选版本，所以标准直接规定：**两个函数声明如果只差返回类型，不能构成重载**。在 GCC 下这会产生这样一条错误：

```text
error: ambiguating new declaration of 'double area(int)'
note: old declaration 'int area(int)'
```

（`ambiguating` 的意思是"造成歧义"，是 GCC 对"同名同参、只差返回类型"这种情况的固定说法。）

顺带一提，函数体不参与签名意味着：**函数体的重复并不构成重载的理由**。上一节的 `printArray` 两个版本函数体一模一样，那是重复代码，第 05 章会用函数模板把它合并成一份；这里之所以能写成两个函数，仅仅因为参数类型不同。

### 9.1 参数个数与顺序不同也算不同签名

例程 `ch09_overloading\overload_signature\overload_signature.cpp` 演示另外两种签名差异：

```cpp
// 参数个数不同：一个参数算正方形面积，两个参数算矩形面积
int area(int side)
{
    return side * side;
}

int area(int width, int height)
{
    return width * height;
}

// 参数个数与类型集合都相同，只是顺序相反
void combine(int first, double second)
{
    std::cout << "combine(int, double): " << first << " " << second << std::endl;
}

void combine(double first, int second)
{
    std::cout << "combine(double, int): " << first << " " << second << std::endl;
}
```

```text
=== Demo B: overloads differing in parameter count ===
area(4) = 16
area(3, 5) = 15
=== Demo C: overloads differing in parameter order ===
combine(int, double): 2 3.5
combine(double, int): 2.5 3
```

这里要提醒一句**能用不等于该用**：`combine(2, 3.5)` 与 `combine(2.5, 3)` 之间只差两个实参的先后，读代码的人极容易看错。参数顺序不同可以用来"区分"，但它**表达不了任何含义**；真正需要按含义区分的两个功能，应该给它们不同的名字，或者用不同的类型把含义写进签名里（后续章节的类型系统正是干这个的）。

## 10 重载解析：编译器怎么挑

当几个候选函数的参数类型都"差不多能接受"同一个实参时，编译器不会随便挑，而是给每个实参到形参的转换打一个等级，等级高的胜出。等级从高到低是：

1. **精确匹配**（exact match）：实参类型与形参类型一致。`int` 到 `int`、`double` 到 `double` 都属于这一级；可以忽略的顶层 `const` 之类的小差别也算精确匹配。
2. **类型提升**（promotion）：不丢有效位的"加宽"，例如 `char`、`short` 到 `int`，`float` 到 `double`。规则上它比第 3 级"更好"。
3. **类型转换**（conversion）：其余能编译通过的类型转换，例如 `int` 到 `double`、`double` 到 `int`——**可能丢信息**，是三级里最低的。

例程 `ch09_overloading\overload_resolution\overload_resolution.cpp` 只有 `show(int)` 与 `show(double)` 两个版本，但每个调用都能明确落在某一级上，于是"选谁"完全由规则决定：

```cpp
show(7);       // 精确匹配 show(int)
show(7.5);     // 精确匹配 show(double)
show('A');     // char -> int 是提升，char -> double 是转换，选 show(int)
show(2.5f);    // float -> double 是提升，float -> int 是转换，选 show(double)
show(small);   // small 是 short：short -> int 是提升，选 show(int)
```

```text
=== Demo D: exact match wins ===
show(int) <- 7
show(double) <- 7.5
=== Demo E: promotion beats conversion ===
show(int) <- 65
show(double) <- 2.5
show(int) <- 4
```

两处值得停下来看：

- `show('A')` 打印的是 `65`：`'A'` 走的是整型提升变成 `int`（`char` 的编码值就是 65），**没有**被当成浮点数。
- `show(2.5f)` 打印的是 `2.5`：`float` 走的是浮点提升变成 `double`，**没有**被截成整数。许多人凭直觉以为"`2.5f` 是 float，`show(int)` 也是数字，可能选 int"，实际上"提升优于转换"这条规则把它稳稳地送到了 `show(double)`。

**只有当没有任何一个候选比其他候选更好（或者几个候选打平）时**，编译器才报"调用有歧义"并拒绝编译。这也是重载设计的一条实用准则：**让各个版本在实参上互相"不亲近"**。如果两个版本都只能靠隐式转换接受同一个实参，就很容易踩到歧义，或者更糟——猜错版本。

## 11 让重载可用的两条前提

**前提一：参与选择的候选必须是"在调用点已经看见的"。** 编译器是从上往下读源文件的，如果某个重载写在调用点之后，它在那个位置还不存在。本章实验三验证过"先定义、后使用"，重载的情形会更迷惑人：函数名已经能在上文找到，编译器于是只用看得见的那个版本去匹配实参，报出来的错是"转换不了"，而不是"没有这个函数"：

```text
error: could not convert 'myFloatArray' from 'array<float,[...]>' to 'array<int,[...]>'
```

**前提二：不要指望隐式转换替你找版本。** 隐式转换会让"看起来不匹配"的调用也能编过，从而悄悄选到一个你不想要的版本。例如只有 `show(int)` 与 `show(double)` 时写 `show(3u)`（`unsigned int`）：`unsigned int` 到 `int` 和到 `double` 都是普通转换，等级相同，于是编译器报歧义：

```text
error: call of overloaded 'show(unsigned int)' is ambiguous
```

歧义不是"编译器不够聪明"，而是在说：**代码的意图不明确**。这类错误必须靠改代码消除（加显式类型转换、或者给这个类型专门写一个重载），而不是靠调整参数顺序去绕过。

到这里，系列的第一段路走完了。回头看这条链：第 01 章立下"C++ 是静态类型的编译语言"这个前提，并解决"怎么看到结果"；第 02 章引入带类型的变量与分支；第 03 章引入第一个标准库容器 `std::array` 与 `for`、`while` 两种循环；本章再用函数把前面的东西组织起来。

这一段的边界是刻意留的，接下来会逐个补上：`std::array` 的长度固定，长度可变的容器是第 07 章的 `std::vector`；函数按值传参会复制数据，更好的传参方式是第 08 章的引用与按引用传递；本章的重载解决了"函数名不够用"，函数体的重复则留给第 05 章的函数模板；数据在内存里的位置与生命周期是第 09、10 章的指针、动态内存、智能指针与 `std::span`；再往后是用结构体和类定义自己的类型（第 11–14 章）、继承与多态（第 15–16 章）、泛型与 Lambda（第 17、18 章）、并发（第 19 章，并行 STL 算法则将在第 06 章展开），最后以命名空间、随机数、文件、编译时编程和概念收尾。

## 12 动手实验

### 12.1 实验一：`void` 函数与复用

例程在 `E:\CPP_Code\CppFromScratch\ch08_functions\` 下，两个程序各占一个文件夹。`print_array\print_array.cpp` 里定义了 `void printArray(std::array<int, 3> array)`，`main` 里对两个数组各调用一次。

```text
E:\msys64\ucrt64\bin\g++.exe -std=c++20 -Wall -g print_array.cpp -o print_array.exe
./print_array.exe
```

**预期现象**：输出两行，注意每个数字后面跟一个空格，所以行末也各有一个空格：

```text
1 2 3 
4 5 6 
```

**验收标准**：两行内容为 `1 2 3 ` 与 `4 5 6 `（含行末空格），编译 `-Wall` 无警告。

**复用验证**：在 `main` 里再加一个 `std::array<int, 3> myArray3 {7, 8, 9};` 并调用 `printArray(myArray3);`，**不对 `printArray` 做任何修改**，重新编译运行应该多输出一行 `7 8 9 `。这直接说明函数一次写好就能服务任意多个数据。

### 12.2 实验二：带返回值的函数

`return_value\return_value.cpp` 里定义了 `int sum(std::array<int, 3> array)`，`main` 里创建 `{1, 2, 3}` 并打印求和结果。

**预期现象**：输出一行

```text
6
```

**验收标准**：输出为 `6`（即 1 + 2 + 3）。把数组初值改成 `{5, 5, 5}` 后重新编译运行，应输出 `15`——函数体同样一行都不用改。

**边界验证**：把 `sum` 里的 `return total;` 注释掉再编译，应看到 `warning: no return statement in function returning non-void [-Wreturn-type]`（这条警告默认就开，不带 `-Wall` 也会出现）。确认这只是警告、程序仍然能生成（但结果不可信），看完还原。

### 12.3 实验三：把定义挪到调用之后

把整个 `printArray` 函数**剪切到 `main` 之后**，重新编译。

**预期现象**：编译失败：

```text
error: 'printArray' was not declared in this scope
```

**原因**：编译器是从上往下读源文件的。读到 `main` 里那句调用时，它还没见过 `printArray` 这个名字，于是无从判断该怎么调用。**函数必须先被声明（通常就是先定义），才能被调用。**

**验收标准**：能说清报错的原因。看完把函数挪回 `main` 之前，重新编译通过。更一般的做法（先声明、后定义，从而不受顺序限制）属于后续内容，本章的规则是**先定义、后使用**。

### 12.4 实验四：重载的基本形态

例程都在 `E:\CPP_Code\CppFromScratch\ch09_overloading\` 下，三个程序各占一个文件夹，每个 `.cpp` 都是自包含的单文件。`overload_basic\overload_basic.cpp`：两个同名 `printArray`，`main` 里对 int 数组与 float 数组各调用一次。

```text
cd "E:/CPP_Code/CppFromScratch/ch09_overloading/overload_basic"
"E:/msys64/ucrt64/bin/g++.exe" -std=c++20 -Wall -g overload_basic.cpp -o overload_basic.exe

```

**预期输出**（注意每行末尾都有一个空格）：

```text

```

**验收标准**：两行数据分别是 `1 2 3 ` 和 `1.1 2.2 3.3 `（含行末空格），编译 `-Wall` 无警告。

**改值实验**：把 `myFloatArray` 的初值改成 `{4.5f, 5.5f, 6.5f}`，先自己预测第二行输出，再重新编译运行，应得到：

第一行完全不受影响——因为两份函数的函数体各自独立，改动只落在被改的那个实参上。

### 12.5 实验五：参数个数与参数顺序

`overload_signature\overload_signature.cpp`：`area` 有 1 参数和 2 参数两个版本，`combine` 有参数顺序相反的两个版本。

```text
cd "E:/CPP_Code/CppFromScratch/ch09_overloading/overload_signature"
"E:/msys64/ucrt64/bin/g++.exe" -std=c++20 -Wall -g overload_signature.cpp -o overload_signature.exe
./overload_signature.exe
```

**预期输出**：

```text
=== Demo B: overloads differing in parameter count ===
area(4) = 16
area(3, 5) = 15
=== Demo C: overloads differing in parameter order ===
combine(int, double): 2 3.5
combine(double, int): 2.5 3
```

**验收标准**：输出与上面逐行一致，`-Wall` 无警告。**改值实验**：把 `area(4)` 改成 `area(6)`，应输出 `area(6) = 36`；把 `combine(2, 3.5)` 改成 `combine(2.0, 3.5)` 后重新编译，两个实参都成了 `double`，第一个版本要把 `2.0` 转成 `int`、第二个版本要把 `3.5` 转成 `int`，两个候选打平，于是编译失败：

```text
error: call of overloaded 'combine(double, double)' is ambiguous
```

这也是"参数顺序相反"这种重载的真实风险：一旦调用处的实参类型和签名差一点，它就从"能编过"直接掉进"歧义"。看完把这一行还原。

### 12.6 实验六：重载解析的取舍顺序

`overload_resolution\overload_resolution.cpp`：只有 `show(int)`、`show(double)`，靠实参的类型落在不同的转换等级上来决定选中谁。

```text
cd "E:/CPP_Code/CppFromScratch/ch09_overloading/overload_resolution"
"E:/msys64/ucrt64/bin/g++.exe" -std=c++20 -Wall -g overload_resolution.cpp -o overload_resolution.exe
./overload_resolution.exe
```

**预期输出**：

```text
=== Demo D: exact match wins ===
show(int) <- 7
show(double) <- 7.5
=== Demo E: promotion beats conversion ===
show(int) <- 65
show(double) <- 2.5
show(int) <- 4
```

**验收标准**：五行调用分别落在 `show(int)`、`show(double)`、`show(int)`、`show(double)`、`show(int)` 上，与预期输出一致。

**改值实验**：把 `show(7);` 改成 `show(7.0);`，其余不动。`7.0` 是 `double`，精确匹配 `show(double)`，因此第一行会变成 `show(double) <- 7`。再把 `show(2.5f);` 改成 `show(2.5);`，输出仍是 `show(double) <- 2.5`：前者靠浮点提升、后者精确匹配，**路径不同但都落在 `show(double)` 上**。这说明"选中哪个版本"与"做了哪种转换"是两件事——输出看起来没变，不代表编译器走的还是原来那条路。

### 12.7 实验七：三类失败现场

三处改动各自独立，做完一处看到报错就还原，再试下一处。

1. **删掉 float 那个重载**（把第二个 `printArray` 整个删掉），重新编译 `overload_basic.cpp`，应看到：

```text
error: could not convert 'myFloatArray' from 'array<float,[...]>' to 'array<int,[...]>'
```

   这正好证明 `printArray(myFloatArray)` 原本调用的就是被删掉的那一份，而不是 int 版本。看完还原。

2. **把 int 那个重载原样复制一份、只改函数体**（例如让第二份打印 `hello world`），重新编译，应看到：

```text
error: redefinition of 'void printArray(std::array<int, 3>)'
note: 'void printArray(std::array<int, 3>)' previously defined here
```

   **函数体不同也救不了重复的签名**：编译器在参数列表这一层就分不出该调用哪一个，于是直接判定为同一个函数的重复定义。看完还原。

3. **在 `overload_resolution.cpp` 的末尾加一句 `show(3u);`**，重新编译，应看到：

```text
error: call of overloaded 'show(unsigned int)' is ambiguous
```

   看完删掉这一句。亲手见一次歧义报错，将来看到它就知道该去找"哪个实参有两个同样好的候选"，而不是去怀疑编译器。
