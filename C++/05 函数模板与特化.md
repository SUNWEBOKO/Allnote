## 学习目标

完成本章后，你应当能够：

1. 用 `template <typename T>` 声明函数模板，并分别用显式模板实参、模板实参推导两种方式调用它。
2. 用 C++20 的缩写语法（参数列表里写 `auto`）声明函数模板。
3. 解释"模板不是函数、实例化才产生函数"。
4. 用 `template <>` 为某个具体类型写出函数模板的显式特化，说出它的两条位置要求。
5. 区分三种写法在行为上的差别：显式特化、漏写 `template <>` 的普通函数、更专门的模板重载。

## 1 重载解决了名字，但留下了重复的函数体

第 04 章把 `printIntArray` 和 `printFloatArray` 收成了一个名字 `printArray`，接口干净了，可是打开函数看：

```cpp
void printArray(std::array<int, 3> array)
{
    for (auto value : array)
    {
        std::cout << value << " ";
    }

    std::cout << std::endl;
}

void printArray(std::array<float, 3> array)
{
    for (auto value : array)
    {
        std::cout << value << " ";
    }

    std::cout << std::endl;
}
```

**两份函数体一字不差，唯一的区别是参数类型。** 这是第 04 章讲过的那种重复：将来要改打印格式（比如加分号、改成逗号分隔），必须记得每个版本都改一遍，漏一个就行为不一致。而且每多支持一种元素类型，就要再抄一份。

回忆第 04 章消除重复的办法：把重复的**语句**提取出来起个名字。可这次重复的不是"哪几句语句"，而是"**类型**"——`int` 版和 `float` 版的语句结构完全一样，只有类型不同。所以这次要提取的，是**类型本身**：把参数类型写成一个还没定下来的占位符，再告诉编译器"这个函数是"给我一个类型"的"。

## 2 函数模板：把类型变成参数

例程 `E:\CPP_Code\CppFromScratch\ch10_function_templates\template_basic\template_basic.cpp`：

```cpp
template <typename T>
void printArray(T array)
{
    for (auto value : array)
    {
        std::cout << value << " ";
    }

    std::cout << std::endl;
}
```

和普通函数相比，只多了上面一行 `template <typename T>`，并把参数类型从 `std::array<int, 3>` 换成了 `T`。这四处的含义如下。

- **`template <typename T>` 是模板头**，它说明"接下来的这个函数带一个类型参数"。这一行不是函数的一部分，函数名仍然是 `printArray`，返回值仍然是 `void`。
- **`T` 是类型参数名**，与形参名一样只是名字，取 `T`、`U`、`ValueType` 都行；叫 `T` 是惯例。`typename` 也可以写成 `class`（`template <class T>`），两者在这里完全等价。
- **`T` 出现在参数列表里**：`T array` 表示"参数类型由 `T` 决定"。函数体里也可以继续用 `T` 声明同类型的变量。
- **函数体里没有任何地方提到具体类型**：元素用 `auto` 接住、打印交给 `<<`。正因为这样，这段代码对任何"能用范围 for 遍历、元素能用 `<<` 输出"的类型都成立。

`main` 里可以显式给出模板实参：

```cpp
printArray<std::array<int, 3>>(myIntArray);
printArray<std::array<float, 3>>(myFloatArray);
```

尖括号里的 `std::array<int, 3>` 就是**模板实参**，意思是"这次把 `T` 填成它"。

```text
=== Demo A: explicit template argument ===
1 2 3 
1.1 2.2 3.3 
```

### 2.1 模板不是函数，实例化才产生函数

`template <typename T> void printArray(T array);` 这一段声明**本身不生成任何代码**。编译器读完它，只是记住"有这么一族函数，参数类型待定"。

真正生成函数发生在**实例化**（instantiation）：某处用具体类型调用了它，编译器就拿这个类型把 `T` 全部替换掉，得到一份参数类型确定的普通函数，然后调用它。上面两行调用会让编译器生成两份函数：

| 调用 | `T` 被替换为 | 实际生成的函数 |
| --- | --- | --- |
| `printArray<std::array<int, 3>>(myIntArray)` | `std::array<int, 3>` | `void printArray(std::array<int, 3> array)` |
| `printArray<std::array<float, 3>>(myFloatArray)` | `std::array<float, 3>` | `void printArray(std::array<float, 3> array)` |

**这两份函数是两个不同的函数**（编译后的符号名不同，地址也不同），只不过它们的函数体来自同一段模板。所以"用模板消除了重复"准确地说，是**在源码层面上消除了重复**：你在源文件里只维护一份函数体，重复出来的那些版本由编译器替你生成。第 04 章需要手抄的那两段函数体现在只需要一段。

## 3 让编译器反推模板实参

大多数情况下不需要写尖括号——编译器能从实参的类型推出 `T`。例程 `ch10_function_templates\template_deduce\template_deduce.cpp` 就是去掉尖括号之后的写法：

```cpp
printArray(myIntArray);
printArray(myFloatArray);
printArray(myDoubleArray);
printArray(myCharArray);
```

```text
=== Demo B: template argument deduction ===
1 2 3 
1.1 2.2 3.3 
10 20 30 40 
a b c d e 
```

这个过程叫**模板实参推导**（template argument deduction），规则对本例来说非常直接：形参是 `T`、实参是 `std::array<int, 3>`，于是 `T` 就是 `std::array<int, 3>`。这和 `auto` 的角色是同一件事——都是**由已有的信息推出没写出来的类型**，区别只是 `auto` 推的是变量类型，这里推的是模板参数。

四次调用得到四个不同的 `T`：

| 调用 | 推导出的 `T` |
| --- | --- |
| `printArray(myIntArray)` | `std::array<int, 3>` |
| `printArray(myFloatArray)` | `std::array<float, 3>` |
| `printArray(myDoubleArray)` | `std::array<double, 4>` |
| `printArray(myCharArray)` | `std::array<char, 5>` |

后两个值得注意：元素类型不同、**元素个数也不同**。在 C++ 里 `std::array<int, 3>` 和 `std::array<int, 4>` 是两个毫不相干的类型（第 03 章就强调过长度是类型的一部分），但对模板来说这不过是"又换了一次 `T`"，一份模板代码全都覆盖。

**什么时候该写尖括号？** 推导只在"能从实参推出来"时可用。如果类型无法从实参推出（例如 `T` 只出现在返回类型里），就必须显式给出：

```cpp
template <typename T>
T zero();          // T 只出现在返回类型里，无法从实参推出

zero<int>();       // 必须写成 zero<int>()：写成 zero() 会因推不出 T 而编译失败
```

反过来，如果实参已经写明了类型，两个都行、尖括号是多余的：跟第 04 章"重载不必写类型"的结论一样，**让编译器做的事就别自己再写一遍**，只有需要明确表达"我就要这个版本"时，显式写法才更有表达力。

## 4 C++20 的缩写函数模板

既然参数列表里的类型可以由实参推出，那连 `template <typename T>` 这行也可以省掉。C++20 起，**参数列表里出现 `auto` 的函数声明会自动被当作函数模板**，每个 `auto` 对应一个编译器"凭空发明"的类型参数。例程 `ch10_function_templates\template_abbreviated\template_abbreviated.cpp`：

```cpp
void printArray(auto array)
{
    for (auto value : array)
    {
        std::cout << value << " ";
    }

    std::cout << std::endl;
}
```

上面这一行等价于 `template <typename T> void printArray(T array)`。调用方式与普通函数完全一致：

```cpp
printArray(myIntArray);
printArray(myFloatArray);
```

```text
=== Demo C: abbreviated function template (C++20) ===
1 2 3 
1.1 2.2 3.3 
```

这种写法叫**缩写函数模板**（abbreviated function template）。它的好处是函数长得就像普通函数，模板头不见了，读起来更轻。代价是**类型参数彻底不可见**：

- 需要显式写 `printArray<std::array<int, 3>>(...)` 时，你没有任何名字可以引用，只能靠推导；
- 函数体里若需要提到这个类型（比如写一个同类型的局部变量并用它做别的判断），只能改用 `auto` 绕，或者干脆换回命名参数的写法。

**对编译标准的要求**是本节的另一个重点。`auto` 参数是 C++20 的特性，在更早的标准下编译器会明确提示：

```text
warning: use of 'auto' in parameter declaration only available with '-std=c++20' or '-fconcepts'
```

这只是警告，程序仍会按"扩展语法"编译，但它说明**这份代码依赖 C++20**：换到不支持 C++20 的旧编译器上，就得改回 `template <typename T>` 的写法才能编译。本课程从第 04 章起统一使用 `-std=c++20`，因此这两种写法都能用；如果哪天在别人的工程里看到这个警告，加 `-std=c++20` 即可消除，前提是编译器真的支持。

## 5 模板的工作方式，以及它的边界

理解下面三件事，模板就不再神秘。

**第一，模板的"检查"发生在实例化时。** 编译到模板定义本身时，编译器并不检查函数体是不是对所有类型都成立——它连 `T` 是什么都不知道。真正的检查推迟到实例化那一刻：先确定 `T`，再把 `T` 代进函数体逐句编译。因此**报错信息里会同时出现"哪个调用要求实例化"和"实例化之后哪一行不对"**。例如对 `printArray(42)` 实例化 `T = int` 之后，函数体里的范围 for 就没有意义了：

```text
In instantiation of 'void printArray(T) [with T = int]':
    required from here
error: 'begin' was not declared in this scope
```

**第二，模板的定义必须出现在使用它的位置之前**，理由和普通函数一样（第 04 章）——而且对模板更严格：编译器在实例化时要能看到完整的函数体。所以本课程把模板定义写在 `main` 之前的同一个文件里。把模板声明和定义分开放进 `.h` 与 `.cpp` 是后续工程化的内容，本章不加区分。

**第三，每实例化一次就多一份函数。** 一份模板被 4 个类型使用，目标文件里就有 4 份函数代码。这就是模板的代价——**代码膨胀**。对本例这种小函数完全无所谓；只有当模板函数体很大、又被很多类型用时才需要留意。作为回报，你维护的源码只有一份。

**最后要说清模板解决不了什么。** 模板能覆盖的是"**所有类型的处理方式都相同**"的情形。假如有某个类型需要**略微不同**的处理（比如打印 `std::array<int, 3>` 时想换成另一种格式），模板本身没有"如果 `T` 是某某类型就换一套逻辑"的能力，硬凑的写法（在函数体里写 `if` 判断类型）在 C++ 里通常既写不出来也不该写。这正是本章第 6 节要讲的模板特化要解决的问题。

## 6 模板覆盖不了的情况

第 2 节的 `printArray` 有一个隐含前提：**所有类型的处理方式都一样**。元素用空格分开、循环结束换行，对 `int` 数组、`float` 数组、`char` 数组都合适，所以一份模板就够了。

现在换一个需求：打印 `std::array<int, 3>` 时希望格式不同——比如不带尾随空格、用逗号分隔、前面加一个标记。这时"一份函数体服务所有类型"就不够用了。

自然的想法是在函数体里判断"`T` 是不是 `std::array<int, 3>`"，然后走不同的分支。这个想法在 C++ 里行不通：模板参数 `T` 是**类型**而不是值，没有可以用来比较的表达式，语言也没有提供"按类型分支"的语句。硬凑的写法要么编译不过，要么把代码写得既慢又难读；而且从设计上看这么写也不对——**"某几个类型要特殊处理"是签名的差异，不是运行期的分支**。

C++ 给出的机制是**模板特化**（template specialization）：**对某个具体类型，另外给一份实现**；其余类型继续使用原来那份通用实现。原来那份通用实现叫**主模板**（primary template），专门为某类型写的那一份叫**显式特化**（explicit specialization）。

## 7 显式特化的写法

例程 `E:\CPP_Code\CppFromScratch\ch11_template_specialization\specialization_basic\specialization_basic.cpp`：

```cpp
// 主模板：所有类型默认走这里
template <typename T>
void printArray(T array)
{
    std::cout << "baseline -> ";

    for (auto value : array)
    {
        std::cout << value << " ";
    }

    std::cout << std::endl;
}

// 显式特化：只针对 T = std::array<int, 3> 这一个类型
template <>
void printArray(std::array<int, 3> array)
{
    std::cout << "specialization -> ";

    bool first = true;

    for (auto value : array)
    {
        if (!first)
        {
            std::cout << ", ";
        }

        std::cout << value;
        first = false;
    }

    std::cout << std::endl;
}
```

`main` 里的调用完全不用改：

```cpp
printArray(myIntArray);      // 走特化
printArray(myFloatArray);    // 回落到主模板
```

```text
=== Demo A: primary template vs specialization ===
specialization -> 1, 2, 3
baseline -> 1.1 2.2 3.3 
```

（第二行末尾有一个空格，那是主模板"元素 + 空格"的写法留下的；特化版本用逗号分隔、最后一个元素后不加分隔符，所以第一行末尾没有空格。）

### 7.1 逐部分看特化的写法

- **`template <>`**：空尖括号的意思是"类型参数已经没有需要推导的了，全部写死了"。它同时向编译器声明"**下面这个不是新函数，而是前面那个模板在这个具体类型上的一个特例**"。这一行不能省，也不能写成 `template <typename T>`（见本章第 9 节）。
- **`void printArray(std::array<int, 3> array)`**：函数名和参数列表看起来和主模板实例化出来的那份函数一样，但它的身份是"特化"——属于那个模板，而不是一个独立函数。
- **特化只处理它写明的那个类型**，其余类型不受影响。所以 `float` 数组照旧走主模板。

### 7.2 两条位置要求

**第一，主模板必须先声明。** 特化是"某个模板的特例"，先得有那个模板。若一个 `template <>` 后面跟着的函数在作用域里根本找不到对应的主模板，GCC 报：

```text
error: 'printArray' is not a template function
```

**第二，特化必须写在任何会导致该类型被实例化的调用之前。** 编译器是按顺序处理的：如果在特化出现之前，某处已经用 `std::array<int, 3>` 调用过主模板，编译器那时就已经照主模板生成好了函数，后面再写特化也来不及了，于是报：

```text
error: specialization of 'void printArray(T) [with T = std::array<int, 3>]' after instantiation
```

这两条合起来，就是本章所有例程都把特化写在 `main` 之前的原因。在实际工程里，特化通常和主模板放在同一个头文件中、紧接着主模板写，就是为了保证"任何使用点都晚于它"。

## 8 特化按"完整类型"精确匹配

例程 `ch11_template_specialization\specialization_exact_type\specialization_exact_type.cpp` 准备了两份特化（`std::array<int, 3>` 与 `std::array<double, 3>`）和四种实参：

```cpp
std::array<int, 3> myIntArray3 {1, 2, 3};
std::array<int, 4> myIntArray4 {1, 2, 3, 4};
std::array<double, 3> myDoubleArray {1.5, 2.5, 3.5};
std::array<float, 3> myFloatArray {1.1f, 2.2f, 3.3f};
```

```text
=== Demo B: specialization matches the exact type only ===
array<int, 3>    : specialization int -> [1, 2, 3]
array<int, 4>    : baseline -> 1 2 3 4 
array<double, 3> : specialization double -> 1.5|2.5|3.5
array<float, 3>  : baseline -> 1.1 2.2 3.3 
```

匹配规则可以用一张表说清：

| 实参类型 | 与特化 `std::array<int, 3>` 是否同一类型 | 使用哪份实现 |
| --- | --- | --- |
| `std::array<int, 3>` | 是 | 特化 |
| `std::array<int, 4>` | 否（**元素个数是类型的一部分**） | 主模板 |
| `std::array<double, 3>` | 否（元素类型不同） | 另一份特化 |
| `std::array<float, 3>` | 否 | 主模板 |

**"元素个数不同就不算命中"是最容易踩的坑**，因为它和本章第 3 节的模板用法形成了对比：主模板不关心元素个数（`T` 整体被替换，`3` 还是 `4` 都无所谓），而特化是"给某个完整类型开小灶"，类型一个字都不能差。这也正是第 03 章那句"`std::array` 的长度是类型的一部分"在这里的具体后果：`std::array<int, 3>` 和 `std::array<int, 4>` 是两个毫不相干的类型。

## 9 三种容易混淆的写法

想给某类型定制实现时，一共有三种看上去差不多、行为却不一样的写法。分清它们，特化就算学明白了。

### 9.1 漏写 `template <>`：那是普通函数，不是特化

例程 `ch11_template_specialization\specialization_vs_overload\specialization_vs_overload.cpp` 里，第二个 `printArray` 和主模板的参数类型写得一模一样，唯一差别是**没有** `template <>`：

```cpp
template <typename T>
void printArray(T array)
{
    std::cout << "primary template" << std::endl;
}

void printArray(std::array<int, 3> array)     // 注意：不是特化
{
    std::cout << "plain non-template function" << std::endl;
}
```

```text
=== Demo D: a plain function is not a specialization ===
direct call        -> plain non-template function
explicit arg call  -> primary template
```

两个调用的实参相同、函数名相同，结局却相反：

- `printArray(myIntArray);` 时，普通函数与"主模板实例化出来的那份函数"都精确匹配，重载解析的规则里**普通函数优先于模板**，所以选中了普通函数。
- `printArray<std::array<int, 3>>(myIntArray);` 里尖括号是模板专属语法，**一旦写出尖括号，候选里就只剩模板**，普通函数连参与比较的资格都没有，于是实例化主模板并调用。

而本章第 7 节的显式特化是模板的一部分，两种调用方式都会走同一份特化实现。**这正是 `template <>` 必须写的原因**：它决定了这份实现是"模板的特例"，还是"另一个碰巧同名的普通函数"。漏写时程序照样能编译通过（`-Wall` 也不会提示），只是特化悄悄没有生效——这类"不报错但不符合预期"的问题最难发现，所以写完特化后最好用显式模板实参的调用方式验证一次。

### 9.2 特化的参数列表必须落在主模板的范围内

特化的参数类型必须是主模板"能够变成的形状"。主模板是 `template <typename T> void printArray(T array)`（一个类型参数），所以 `std::array<int, 3>` 是可以的（它就是某个 `T`）；但如果把参数写成主模板根本产生不出来的形式，例如两个参数：

```cpp
template <>
void printArray(int first, int second);   // 主模板只有一个参数，这不是它的特化
```

GCC 报：

```text
error: template-id 'printArray<>' for 'void printArray(int, int)' does not match any template declaration
```

遇到这条错误，就回去把特化的参数列表和主模板的参数列表对齐。

### 9.3 函数模板没有"偏特化"，需要的可以重载一个更专门的模板

如果想要的不是"某一个类型"，而是"某一类类型"——比如"元素类型任意、但只要长度为 3 的 `std::array`"——显式特化做不到，因为 `template <>` 要求把类型写全。类模板有**偏特化**（partial specialization，只写一部分参数），但**函数模板不支持偏特化**，写出来会被当成别的意思（下一段的实验会看到其中一种）。

可行的替代办法是**重载一个更专门的函数模板**，让它的参数把想固定的部分固定、想保留的部分继续当模板参数：

```cpp
template <typename T>
void printArray(std::array<T, 3> array)   // 适用于所有长度为 3 的 std::array
{
    std::cout << "overload for array<T, 3> -> ";

    bool first = true;

    for (auto value : array)
    {
        if (!first)
        {
            std::cout << ", ";
        }

        std::cout << value;
        first = false;
    }

    std::cout << std::endl;
}
```

主模板与它同时存在时，调用 `std::array<int, 3>` 会选中这个更专门的版本，而 `std::array<int, 4>` 仍然落到主模板——一次覆盖了一整类类型，比逐类型写显式特化省事。动手实验里的实验八会把这段代码亲手跑一遍。

## 10 主模板写成缩写形式时的特化

本章第 4 节讲过 C++20 的缩写函数模板（参数列表里写 `auto`）。主模板用这种写法时，特化语法完全不变。例程 `ch11_template_specialization\specialization_auto\specialization_auto.cpp`：

```cpp
void printArray(auto array)              // 主模板：等价于 template <typename T>
{
    std::cout << "baseline(auto template) -> ";

    for (auto value : array)
    {
        std::cout << value << " ";
    }

    std::cout << std::endl;
}

template <>                              // 特化写法与前一节一样
void printArray(std::array<int, 3> array)
{
    // ...
}
```

```text
=== Demo C: specializing an abbreviated template ===
specialization -> 1, 2, 3
baseline(auto template) -> 1.1 2.2 3.3 
```

缩写函数模板和普通函数模板一样可以被特化（标准里对这点有明确说明，本课程的 GCC 16 实测通过，调用时确实走特化）。**但工程上更推荐给类型参数起名的写法**：`T` 有名字，函数体里需要提到这个类型时能直接写出来，特化和错误信息也更可读；缩写形式适合那些"类型只出现在参数列表里、函数体完全不提它"的简单函数。

```cpp
template <typename T>
void printArray(std::array<T, 3> array)
{

    for (auto value : array)
```
