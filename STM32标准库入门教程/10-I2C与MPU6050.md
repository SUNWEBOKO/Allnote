# 第 10 章 I2C 与 MPU6050

本章按课程字幕顺序学习 I2C 与 MPU6050，并完成两个工程：软件 I2C 读写 MPU6050、硬件 I2C 读写 MPU6050。两个工程的 OLED 显示和 MPU6050 驱动接口相同，区别只在通信底层由 GPIO 还是 I2C2 外设产生时序。

## 1. 课程现象与学习目标

课程程序运行后，OLED 第一行显示 MPU6050 的 ID，下面左侧显示加速度计 X/Y/Z，右侧显示陀螺仪 X/Y/Z 的原始数据。改变模块姿态时，六个数据会相应变化。

本章闭环：

```text
接线与供电 -> I2C 时序 -> 设备地址 -> 寄存器读写
          -> MPU6050 初始化 -> 读取六轴数据 -> OLED 显示与排错
```

本章只整理五份课程字幕、课程 PPT、两个配套工程和对应原资料中出现的内容，不加入 HAL、复杂姿态解算或其他芯片扩展。

## 2. 为什么需要 I2C

STM32 访问自身外设时，可以使用内部数据总线和寄存器地址。外挂芯片的寄存器在单片机外部，不能直接共用内部总线，因此需要通信协议。

外挂芯片通常把控制和状态组织成线性寄存器地址空间。主机至少要发送设备地址、寄存器地址和数据。例如向 `0x06` 写入 `0xAA`：

```text
设备地址 + 写方向 + 寄存器地址 0x06 + 数据 0xAA
```

读取时，主机先发送寄存器地址，再切换为读方向，由从机返回该地址的数据。

课程用协议设计任务说明 I2C 的目标：用半双工共用 SDA；每个字节都有 ACK/NACK；一条总线挂载多个模块并用地址选择；增加 SCL 后双方同步，主机暂停传输也不会破坏数据。I2C 是同步时序，所以容易用软件手动翻转电平实现。

## 3. I2C 电气结构和地址

### 3.1 SCL、SDA、开漏和上拉

![I2C 总线连接](assets/ppt/slide-128.png)

I2C 使用 `SCL` 串行时钟线和 `SDA` 串行数据线。所有设备的 SCL 连接在一起，所有设备的 SDA 连接在一起。两根线都使用开漏结构，并通过上拉电阻恢复高电平：输出 0 时器件主动拉低，输出 1 时器件释放总线，由上拉电阻拉高。

课程 PPT 给出的常见上拉电阻约为 `4.7 kΩ`。本章 MPU6050 模块已经内置上拉电阻，通常不需要再外接；若使用没有内置上拉的模块，必须按电路条件添加。

### 3.2 主机、从机和 AD0

本章中 STM32 是主机，负责发起通信、产生 SCL 和选择读写方向；MPU6050 是从机，根据地址响应并返回寄存器数据。

MPU6050 的 `AD0` 决定七位地址最低位：`AD0=0` 时地址为 `0x68`，`AD0=1` 时地址为 `0x69`。课程模块的 AD0 通过下拉保持为低电平。模块上的 `XCL`、`XDA` 是用于扩展主机 I2C 的接口，本章不使用；`INT` 是中断信号输出脚，本章也不接。

课程源码使用地址字节写法：

```c
#define MPU6050_ADDRESS  0xD0
```

`0xD0` 是七位地址左移一位后的写地址字节，读地址字节为 `0xD1`。`0x68` 是七位从机地址，也是课程中常见的 ID 显示值。使用其他库函数时，要先确认参数要求的是七位地址还是地址字节，不能重复左移。

### 3.3 七位、十位和多主机

七位地址最常见；十位地址由两个地址字节组成，过程更复杂，本章使用七位地址。I2C 还支持多主机模型，多个主机同时请求总线时需要仲裁，仲裁失败的一方释放总线。STM32 硬件 I2C 提供仲裁丢失、总线错误和应答错误等状态标志。

## 4. I2C 基本时序

### 4.1 起始和停止

![起始与停止条件](assets/ppt/slide-129.png)

起始条件是 SCL 高电平期间 SDA 从高变低；停止条件是 SCL 高电平期间 SDA 从低变高。普通数据传输时，在 SCL 低电平期间改变 SDA，在 SCL 高电平期间保持稳定并采样。

### 4.2 发送和接收一个字节

![发送一个字节](assets/ppt/slide-130.png)

I2C 高位先行。发送时，主机在 SCL 低电平期间准备 SDA，释放 SCL 后从机在高电平期间读取，随后拉低 SCL，重复八次。接收时，主机先释放 SDA，从机准备数据，主机在 SCL 高电平期间读取。

SCL 高电平期间 SDA 不应改变，否则普通数据变化可能被误判为起始或停止。

### 4.3 ACK 和 NACK

![应答位](assets/ppt/slide-132.png)

每八位数据之后还有第九个时钟。接收方拉低 SDA 表示 ACK，释放 SDA 表示 NACK。主机读取多个字节时，最后一个字节发送 NACK，再产生停止条件。

## 5. 三类 I2C 事务

### 5.1 指定地址写

```text
START -> 从机地址 + W -> ACK -> 寄存器地址 -> ACK -> 数据 -> ACK -> STOP
```

连续写多个字节时，从机内部地址指针通常自动递增。

### 5.2 当前地址读

当前地址读不发送寄存器地址，直接以读方向寻址，从机按当前地址指针返回数据。它依赖前一次事务留下的地址，课程中说明这种时序使用较少。

### 5.3 指定地址读

![指定地址读](assets/ppt/slide-135.png)

```text
START -> 从机地址 + W -> ACK -> 寄存器地址 -> ACK
      -> 重复 START -> 从机地址 + R -> ACK -> 数据 -> ACK/NACK -> STOP
```

前半段设置从机内部地址指针，后半段读取该地址的数据。MPU6050 的 `ReadReg()` 采用这种复合格式。

## 6. MPU6050 功能、手册和寄存器

### 6.1 芯片功能

![MPU6050 功能](assets/ppt/slide-136.png)

MPU6050 是六轴姿态传感器：三轴加速度计测量 X/Y/Z 轴加速度，三轴陀螺仪测量绕 X/Y/Z 轴旋转的角速度。陀螺仪输出的是角速度而不是直接角度；积分可得到角度变化，但误差会随时间累积，因此陀螺仪具有动态稳定性而不具备长期静态稳定性。加速度计可提供静态方向参考，课程提到二者可以进行互补滤波。

芯片还包含温度传感器和数字运动处理器 DMP。陀螺仪内部需要较高电压，芯片通过电荷泵自动升压。本章只保留字幕中的功能说明。

### 6.2 两类手册

产品说明书用于查看功能、参数、引脚和硬件电路；寄存器映射手册用于查看寄存器地址、默认值和位域含义。实际写代码时必须以寄存器映射为直接依据。

### 6.3 课程参数和关键寄存器

课程 PPT 给出的项目包括：加速度计量程 `±2/±4/±8/±16 g`，陀螺仪量程 `±250/±500/±1000/±2000 °/s`，数字低通滤波、时钟源和采样分频。满量程越大，范围越宽；满量程越小，分辨率越高；输出抖动较大时可配置低通滤波。课程资料还介绍 I2C 标准速度最高 `100 kHz`、快速模式最高 `400 kHz`，实际工程使用的 `50 kHz` 低于这些上限。

```c
#define MPU6050_SMPLRT_DIV      0x19
#define MPU6050_CONFIG          0x1A
#define MPU6050_GYRO_CONFIG     0x1B
#define MPU6050_ACCEL_CONFIG    0x1C
#define MPU6050_ACCEL_XOUT_H    0x3B
#define MPU6050_ACCEL_XOUT_L    0x3C
#define MPU6050_ACCEL_YOUT_H    0x3D
#define MPU6050_ACCEL_YOUT_L    0x3E
#define MPU6050_ACCEL_ZOUT_H    0x3F
#define MPU6050_ACCEL_ZOUT_L    0x40
#define MPU6050_TEMP_OUT_H      0x41
#define MPU6050_TEMP_OUT_L      0x42
#define MPU6050_GYRO_XOUT_H     0x43
#define MPU6050_GYRO_XOUT_L     0x44
#define MPU6050_GYRO_YOUT_H     0x45
#define MPU6050_GYRO_YOUT_L     0x46
#define MPU6050_GYRO_ZOUT_H     0x47
#define MPU6050_GYRO_ZOUT_L     0x48
#define MPU6050_PWR_MGMT_1      0x6B
#define MPU6050_PWR_MGMT_2      0x6C
#define MPU6050_WHO_AM_I        0x75
```

上电默认情况下，`PWR_MGMT_1` 的睡眠位为 1，芯片处于睡眠状态；`WHO_AM_I` 常见返回值为 `0x68`。初始化必须先解除睡眠：

```c
MPU6050_WriteReg(MPU6050_PWR_MGMT_1, 0x01);
MPU6050_WriteReg(MPU6050_PWR_MGMT_2, 0x00);
MPU6050_WriteReg(MPU6050_SMPLRT_DIV, 0x09);
MPU6050_WriteReg(MPU6050_CONFIG, 0x06);
MPU6050_WriteReg(MPU6050_GYRO_CONFIG, 0x18);
MPU6050_WriteReg(MPU6050_ACCEL_CONFIG, 0x18);
```

课程注释中，`0x01` 用于解除睡眠并选择时钟源，`0x00` 保持各轴工作，`0x09` 配置采样分频，`0x06` 配置低通滤波，两个 `0x18` 分别选择课程使用的陀螺仪 `±2000 °/s` 和加速度计 `±16 g`。

## 7. 实验一：软件 I2C 读写 MPU6050

### 7.1 工程和接线

工程路径：

```text

```

VCC 接电源正极，GND 接电源负极并与 STM32 共地，SCL 接 PB10，SDA 接 PB11。软件 I2C 由普通 GPIO 手动翻转，端口可以任意指定；课程选择 PB10/PB11 是为了和硬件 I2C2 工程共用接线。上电后电源指示灯不亮，应立即断电检查 VCC/GND、供电和模块状态。

### 7.2 引脚操作层

```c
#include "stm32f10x.h"
#include "Delay.h"

static void MyI2C_W_SCL(uint8_t BitValue)
{
    GPIO_WriteBit(GPIOB, GPIO_Pin_10, (BitAction)BitValue);
    Delay_us(10);
}

static void MyI2C_W_SDA(uint8_t BitValue)
{
    GPIO_WriteBit(GPIOB, GPIO_Pin_11, (BitAction)BitValue);
    Delay_us(10);
}

static uint8_t MyI2C_R_SDA(void)
{
    uint8_t BitValue = GPIO_ReadInputDataBit(GPIOB, GPIO_Pin_11);
    Delay_us(10);
    return BitValue;
}

void MyI2C_Init(void)
{
    RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOB, ENABLE);
    GPIO_InitTypeDef GPIO_InitStructure;
    GPIO_InitStructure.GPIO_Mode = GPIO_Mode_Out_OD;
    GPIO_InitStructure.GPIO_Pin = GPIO_Pin_10 | GPIO_Pin_11;
    GPIO_InitStructure.GPIO_Speed = GPIO_Speed_50MHz;
    GPIO_Init(GPIOB, &GPIO_InitStructure);
    GPIO_SetBits(GPIOB, GPIO_Pin_10 | GPIO_Pin_11);
}
```

开漏输出写 1 表示释放总线。读取 SDA 时，先写 1 释放 SDA，再通过输入数据寄存器读取实际电平。

### 7.3 六个基本时序函数

```c
void MyI2C_Start(void)
{
    MyI2C_W_SDA(1);
    MyI2C_W_SCL(1);
    MyI2C_W_SDA(0);
    MyI2C_W_SCL(0);
}

void MyI2C_Stop(void)
{
    MyI2C_W_SDA(0);
    MyI2C_W_SCL(1);
    MyI2C_W_SDA(1);
}

void MyI2C_SendByte(uint8_t Byte)
{
    uint8_t i;
    for (i = 0; i < 8; i++)
    {
        MyI2C_W_SDA(!!(Byte & (0x80 >> i)));
        MyI2C_W_SCL(1);
        MyI2C_W_SCL(0);
    }
}

uint8_t MyI2C_ReceiveByte(void)
{
    uint8_t i;
    uint8_t Byte = 0x00;
    MyI2C_W_SDA(1);
    for (i = 0; i < 8; i++)
    {
        MyI2C_W_SCL(1);
        if (MyI2C_R_SDA()) Byte |= (0x80 >> i);
        MyI2C_W_SCL(0);
    }
    return Byte;
}

void MyI2C_SendAck(uint8_t AckBit)
{
    MyI2C_W_SDA(AckBit);
    MyI2C_W_SCL(1);
    MyI2C_W_SCL(0);
}

uint8_t MyI2C_ReceiveAck(void)
{
    uint8_t AckBit;
    MyI2C_W_SDA(1);
    MyI2C_W_SCL(1);
    AckBit = MyI2C_R_SDA();
    MyI2C_W_SCL(0);
    return AckBit;
}
```

起始函数先释放 SDA、SCL，再在 SCL 高电平期间拉低 SDA，兼容普通起始和重复起始。停止函数先把 SDA 拉低，再释放 SCL 和 SDA，确保产生 SDA 上升沿。`!!(Byte & mask)` 把按位与结果统一成 0 或 1。

### 7.4 软件 MPU6050 驱动

```c
#define MPU6050_ADDRESS  0xD0

void MPU6050_WriteReg(uint8_t RegAddress, uint8_t Data)
{
    MyI2C_Start();
    MyI2C_SendByte(MPU6050_ADDRESS);
    MyI2C_ReceiveAck();
    MyI2C_SendByte(RegAddress);
    MyI2C_ReceiveAck();
    MyI2C_SendByte(Data);
    MyI2C_ReceiveAck();
    MyI2C_Stop();
}

uint8_t MPU6050_ReadReg(uint8_t RegAddress)
{
    uint8_t Data;
    MyI2C_Start();
    MyI2C_SendByte(MPU6050_ADDRESS);
    MyI2C_ReceiveAck();
    MyI2C_SendByte(RegAddress);
    MyI2C_ReceiveAck();
    MyI2C_Start();
    MyI2C_SendByte(MPU6050_ADDRESS | 0x01);
    MyI2C_ReceiveAck();
    Data = MyI2C_ReceiveByte();
    MyI2C_SendAck(1);
    MyI2C_Stop();
    return Data;
}
```

驱动初始化先调用底层 `MyI2C_Init()`，再按寄存器映射解除睡眠并写入课程配置：

```c
void MPU6050_Init(void)
{
    MyI2C_Init();
    MPU6050_WriteReg(MPU6050_PWR_MGMT_1, 0x01);
    MPU6050_WriteReg(MPU6050_PWR_MGMT_2, 0x00);
    MPU6050_WriteReg(MPU6050_SMPLRT_DIV, 0x09);
    MPU6050_WriteReg(MPU6050_CONFIG, 0x06);
    MPU6050_WriteReg(MPU6050_GYRO_CONFIG, 0x18);
    MPU6050_WriteReg(MPU6050_ACCEL_CONFIG, 0x18);
}

uint8_t MPU6050_GetID(void)
{
    return MPU6050_ReadReg(MPU6050_WHO_AM_I);
}
```

### 7.5 读取六轴数据和 OLED 显示

每个轴由高、低两个字节组成，课程代码按大端顺序拼接为 `int16_t`：

```c
void MPU6050_GetData(int16_t *AccX, int16_t *AccY, int16_t *AccZ,
                     int16_t *GyroX, int16_t *GyroY, int16_t *GyroZ)
{
    uint8_t DataH, DataL;
    DataH = MPU6050_ReadReg(MPU6050_ACCEL_XOUT_H);
    DataL = MPU6050_ReadReg(MPU6050_ACCEL_XOUT_L);
    *AccX = (DataH << 8) | DataL;

    DataH = MPU6050_ReadReg(MPU6050_ACCEL_YOUT_H);
    DataL = MPU6050_ReadReg(MPU6050_ACCEL_YOUT_L);
    *AccY = (DataH << 8) | DataL;

    DataH = MPU6050_ReadReg(MPU6050_ACCEL_ZOUT_H);
    DataL = MPU6050_ReadReg(MPU6050_ACCEL_ZOUT_L);
    *AccZ = (DataH << 8) | DataL;

    DataH = MPU6050_ReadReg(MPU6050_GYRO_XOUT_H);
    DataL = MPU6050_ReadReg(MPU6050_GYRO_XOUT_L);
    *GyroX = (DataH << 8) | DataL;

    DataH = MPU6050_ReadReg(MPU6050_GYRO_YOUT_H);
    DataL = MPU6050_ReadReg(MPU6050_GYRO_YOUT_L);
    *GyroY = (DataH << 8) | DataL;

    DataH = MPU6050_ReadReg(MPU6050_GYRO_ZOUT_H);
    DataL = MPU6050_ReadReg(MPU6050_GYRO_ZOUT_L);
    *GyroZ = (DataH << 8) | DataL;
}
```

课程原工程逐个读取每个轴的高、低字节，寄存器和执行顺序如下。应用层调用方式为：

```c
uint8_t ID;
int16_t AX, AY, AZ, GX, GY, GZ;

int main(void)
{
    OLED_Init();

    {
        MPU6050_GetData(&AX, &AY, &AZ, &GX, &GY, &GZ);
        OLED_ShowSignedNum(2, 1, AX, 5);
        OLED_ShowSignedNum(3, 1, AY, 5);
        OLED_ShowSignedNum(4, 1, AZ, 5);
        OLED_ShowSignedNum(2, 8, GX, 5);
        OLED_ShowSignedNum(3, 8, GY, 5);
        OLED_ShowSignedNum(4, 8, GZ, 5);
    }
}
```

## 8. STM32 硬件 I2C

### 8.1 外设特点和固定引脚

![硬件 I2C 基本结构](assets/ppt/slide-142.png)

硬件 I2C 外设自动完成时钟生成、起始/停止、字节收发和 ACK/NACK，CPU 通过数据寄存器和状态事件推进流程。STM32F103C8T6 有 I2C1、I2C2，本章使用 I2C2：PB10 为 SCL，PB11 为 SDA。硬件引脚不能任意指定，SCL 和 SDA 也不能互换。

课程介绍的库函数包括 `I2C_Init()`、`I2C_Cmd()`、`I2C_GenerateSTART()`、`I2C_GenerateSTOP()`、`I2C_Send7bitAddress()`、`I2C_SendData()`、`I2C_ReceiveData()`、`I2C_AcknowledgeConfig()` 和 `I2C_CheckEvent()`。

### 8.2 事件序列

```text
START -> EV5 主机模式选择
发送从机地址 -> EV6 发送/接收模式选择完成
发送寄存器地址 -> EV8 或 EV8_2
接收数据 -> EV7 主机字节接收完成
STOP
```

指定地址读在发送寄存器地址后产生重复起始，再发送读方向地址。每次写入 DR 或从 DR 取出数据后，都要等待相应事件。

## 9. 实验二：硬件 I2C 读写 MPU6050

### 9.1 工程和初始化

```c

I2C_Cmd(I2C2, ENABLE);
```

### 9.2 硬件指定地址写

```c
void MPU6050_WriteReg(uint8_t RegAddress, uint8_t Data)
{
    I2C_GenerateSTART(I2C2, ENABLE);
    MPU6050_WaitEvent(I2C2, I2C_EVENT_MASTER_MODE_SELECT);
    I2C_Send7bitAddress(I2C2, MPU6050_ADDRESS,
                        I2C_Direction_Transmitter);
    MPU6050_WaitEvent(I2C2,
                      I2C_EVENT_MASTER_TRANSMITTER_MODE_SELECTED);
    I2C_SendData(I2C2, RegAddress);
    MPU6050_WaitEvent(I2C2, I2C_EVENT_MASTER_BYTE_TRANSMITTING);
    I2C_SendData(I2C2, Data);
```

### 9.3 硬件指定地址读

```c
uint8_t MPU6050_ReadReg(uint8_t RegAddress)
{
    uint8_t Data;
    I2C_GenerateSTART(I2C2, ENABLE);
    MPU6050_WaitEvent(I2C2, I2C_EVENT_MASTER_MODE_SELECT);
    I2C_Send7bitAddress(I2C2, MPU6050_ADDRESS,
                        I2C_Direction_Transmitter);
    MPU6050_WaitEvent(I2C2,
                      I2C_EVENT_MASTER_TRANSMITTER_MODE_SELECTED);
    I2C_SendData(I2C2, RegAddress);
    MPU6050_WaitEvent(I2C2, I2C_EVENT_MASTER_BYTE_TRANSMITTED);

    I2C_GenerateSTART(I2C2, ENABLE);
    MPU6050_WaitEvent(I2C2, I2C_EVENT_MASTER_MODE_SELECT);
    I2C_Send7bitAddress(I2C2, MPU6050_ADDRESS,
                        I2C_Direction_Receiver);
    MPU6050_WaitEvent(I2C2,
                      I2C_EVENT_MASTER_RECEIVER_MODE_SELECTED);

    I2C_AcknowledgeConfig(I2C2, DISABLE);
    I2C_GenerateSTOP(I2C2, ENABLE);
    MPU6050_WaitEvent(I2C2, I2C_EVENT_MASTER_BYTE_RECEIVED);
    Data = I2C_ReceiveData(I2C2);
    I2C_AcknowledgeConfig(I2C2, ENABLE);
    return Data;
}
```

读取一个字节时，主机在最后一个字节到来前关闭 ACK 并申请 STOP，读取后恢复 ACK。课程强调单字节接收与多字节接收的 ACK、ADDR、STOP 顺序不能机械混用。

### 9.5 超时处理

课程最初使用无限循环等待事件：

```c
while (I2C_CheckEvent(I2C2, Event) != SUCCESS)
{
}
```

随后封装计数超时：

```c
void MPU6050_WaitEvent(I2C_TypeDef *I2Cx, uint32_t I2C_EVENT)
{
    uint32_t Timeout = 10000;
    while (I2C_CheckEvent(I2Cx, I2C_EVENT) != SUCCESS)
    {
        Timeout--;
        if (Timeout == 0) break;
    }
}
```

该版本只保证退出等待，不代表事务成功。字幕最后指出，实际项目在超时点还应记录错误、复位系统，或根据机械结构风险进行紧急停机。本章不扩展新的错误框架。

### 9.6 波形和验收

![软件与硬件 I2C 波形对比](assets/ppt/slide-145.png)

软件和硬件工程的指定地址读波形逻辑相同，都包含起始、写地址、寄存器地址、重复起始、读地址、数据、NACK 和停止。硬件波形更规整；软件波形可能因 CPU 执行和延时出现不规则边沿，但同步时钟仍可使通信正常。

验收步骤：编译并下载硬件工程；OLED 显示 ID 和六轴数据；改变模块姿态确认数据变化；使用示波器观察起始、重复起始、ACK/NACK 和停止顺序；与软件 I2C 工程比较。

## 10. 故障定位

| 现象 | 检查顺序 |
| --- | --- |
| 电源灯不亮 | VCC/GND 是否接反、供电是否存在、模块是否损坏 |
| 没有 ACK | 共地、上拉、地址、SCL/SDA 是否接反 |
| SDA 始终为高 | GPIO 模式、主机驱动、是否产生 SCL |
| SDA 始终为低 | 短路、从机卡死、开漏释放是否正确 |
| ID 不正确 | `0x68`、`0xD0`、`0xD1` 是否混淆，WHO_AM_I 地址是否正确 |
| ID 正确但数据不变 | 是否解除睡眠、寄存器地址和读取顺序是否正确 |
| 数据高低字节错位 | 起始寄存器、连续地址、高低字节拼接是否正确 |
| 硬件 I2C 卡死 | PB10/PB11、事件顺序、超时处理和错误标志 |
| 软件/硬件结果不同 | 比较初始化参数、设备地址、重复起始、ACK/NACK 和 STOP |

## 11. 课程内自测

1. 为什么 SDA、SCL 使用开漏和上拉？
   - 设备只能拉低或释放总线，多个设备可以共享线路。
2. 起始和停止如何产生？
   - SCL 高电平期间，SDA 高到低为起始，低到高为停止。
3. 为什么指定地址读要重复起始？
   - 先用写方向设置寄存器地址，再用读方向取数据。
4. 单字节读取为什么发送 NACK？
   - 告诉从机当前字节是最后一个。
5. 为什么初始化先写 PWR_MGMT_1？
   - 芯片默认睡眠，必须先解除睡眠。
6. 软件和硬件 I2C 为什么可以共用上层代码？
   - 只替换底层时序，MPU6050 寄存器访问和 main 调用接口不变。
7. 为什么硬件 I2C 等待事件要有超时？
   - 防止掉电、接线错误或总线异常导致程序永久卡死。
