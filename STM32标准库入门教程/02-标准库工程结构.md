# 第 2 章 建立标准库工程


## 本章闭环

从空目录建立一个能编译、下载并运行 `main()` 的 STM32F103C8T6 标准库工程。

![新建工程步骤](../assets/ppt/slide-016.png)

## 1. 为什么文件很多

复位后，处理器先进入启动文件中的复位处理函数，初始化栈和数据段，再调用 `SystemInit()` 配置时钟，最后进入 `main()`。外设寄存器定义来自 `stm32f10x.h`，标准库函数来自 `stm32f10x_xxx.c/.h`，中断函数名由启动文件中的向量表决定。

![标准库工程架构](../assets/ppt/slide-017.png)

## 2. 推荐目录

```text
Project/
├─ Start/       启动文件、core_cm3、system_stm32f10x
├─ Library/     标准外设库 src/inc
├─ User/        main、stm32f10x_it、stm32f10x_conf
├─ System/      Delay、Timer、RTC、Flash 等
└─ Hardware/    LED、Key、OLED、传感器驱动
```

先建立 `Start/Library/User` 就足够。`System/Hardware` 在需要封装模块时再添加。

## 3. Keil 配置步骤

1. 新建工程并选择 `STM32F103C8`。
2. 不使用 Keil 自动添加的旧启动文件，按课程模板复制中容量器件启动文件 `startup_stm32f10x_md.s`。
3. 在 Keil 中建立与目录同名的 Group，再添加对应源文件。
4. 在 `Options for Target -> C/C++ -> Include Paths` 添加所有含头文件的目录。
5. 在 `Define` 中加入 `USE_STDPERIPH_DRIVER`。
6. 在 `stm32f10x_conf.h` 中保留会使用的标准库头文件。
7. 配置 ST-Link 和 Flash Download 算法。

## 4. 最小 main.c

```c
#include "stm32f10x.h"

int main(void)
{
    while (1)
    {
    }
}
```

编译成功只说明语法、文件和链接关系成立；下载成功且程序能从 `main()` 运行，才说明下载配置也正确。可在 `main` 首行设断点进入 Debug 验证。

## 5. 常见报错

| 现象 | 优先检查 |
| --- | --- |
| 找不到 `stm32f10x.h` | Include Paths 是否包含 CMSIS 与库 `inc` |
| 标准库函数未定义 | 对应 `.c` 是否加入工程；是否定义 `USE_STDPERIPH_DRIVER` |
| 重复定义中断函数 | 同一个 IRQHandler 只能有一个全局实现 |
| 下载后不运行 | `Reset and Run`、BOOT0、启动文件型号、Flash 算法 |
| 时序参数全不对 | `SystemInit()` 与 `SystemCoreClock` 是否为预期值 |

## 6. 模块化边界

驱动模块通常由同名 `.c/.h` 组成：头文件只公布调用者需要的函数和类型，GPIO 选择、状态变量等实现细节放在 `.c`。先让单文件实验闭环，再做模块封装；不要在尚未理解配置链时复制大量抽象层。

## 本章小结

标准库工程的关键不是记文件名，而是理解启动、系统时钟、芯片定义、库函数、用户代码之间的调用链。链路完整后，新增外设只是继续添加配置模块。
