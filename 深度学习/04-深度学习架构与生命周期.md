# 04 深度学习架构与生命周期

## 本章定位

深度学习项目不是“写一个网络然后训练”这么简单。一个完整项目通常要经历建模、训练、验证、测试和推理部署，并在这些阶段之间不断迭代。本章从工程视角梳理这条主线，帮助后续理解为什么要划分数据集、为什么要观察验证集、为什么训练完成后还要单独测试。

## 生命周期总览

一个标准深度学习项目可以概括为：

```text
任务定义 -> 数据准备 -> 建模 -> 训练 -> 验证 -> 测试 -> 推理部署 -> 反馈迭代
```

课程中重点关注四个核心阶段：

- **建模**：选择或设计网络结构。
- **训练**：用训练数据更新模型参数。
- **验证**：在训练过程中评估模型并调整方案。
- **测试/推理**：训练完成后评估最终泛化能力，并将模型用于新数据预测。

这四个阶段不是一次性线性流程。验证结果不好时，往往需要回到数据、模型或训练策略重新调整。

## 建模：选择合适的网络结构

建模阶段要回答的问题是：用什么模型结构解决当前任务。

不同数据类型适合不同网络：

| 模型 | 主要数据类型 | 典型任务 | 核心特点 |
|---|---|---|---|
| MLP / 全连接网络 | 表格特征、低维向量 | 分类、回归 | 结构简单，适合入门和表格数据 |
| CNN | 图像、局部空间结构数据 | 图像分类、检测、分割 | 局部连接、权值共享、擅长视觉特征提取 |
| RNN / LSTM / GRU | 序列数据 | 时间序列、早期 NLP | 按顺序处理数据，建模历史状态 |
| Transformer | 文本、图像、多模态 | 翻译、问答、大模型、视觉任务 | 自注意力机制，易并行，扩展能力强 |
| Autoencoder | 向量、图像、信号 | 降维、去噪、异常检测 | 学习压缩表示，再重构输入 |
| GAN | 图像等生成数据 | 图像生成、风格迁移 | 生成器与判别器对抗训练 |
| Diffusion Model | 图像、音频、视频 | 高质量生成 | 学习逐步去噪过程 |
| GNN | 图结构数据 | 节点分类、链接预测 | 通过消息传递聚合邻居信息 |
| Deep RL | 状态-动作-奖励序列 | 游戏、控制、机器人 | 用神经网络近似策略或价值函数 |

建模不是越复杂越好。模型应与任务规模、数据量和部署要求匹配。鸢尾花分类只有 4 个输入特征和 150 条样本，用一个小型 MLP 已经足够；如果强行使用复杂深层模型，反而更容易过拟合。

## 训练：让参数从随机值变成有用值

神经网络刚创建时，权重和偏置通常是随机初始化的。训练的目标是用数据不断调整这些参数，让模型输出越来越接近真实标签。

有监督训练包含三个基本要素：

- **输入** $x$：模型看到的数据，例如鸢尾花的 4 个特征。
- **真值** $y$：标准答案，例如花的类别编号。
- **预测值** $\hat{y}$：模型根据当前参数计算出的结果。

训练时先进行前向传播，得到预测值；再用损失函数衡量预测值与真值之间的差距；最后通过反向传播计算梯度，并用优化器更新参数。

以均方误差为例：

$$
\mathcal{L} = \frac{1}{N}\sum_{i=1}^{N}(\hat{y}_i - y_i)^2
$$

分类任务更常用交叉熵损失。无论损失函数形式如何，本质目标都是让损失尽可能小。

参数更新可以抽象为：

$$
\theta_{\text{new}} = \theta_{\text{old}} - \eta \nabla_{\theta}\mathcal{L}
$$

其中 $\theta$ 表示模型参数，$\eta$ 是学习率，$\nabla_{\theta}\mathcal{L}$ 是损失函数对参数的梯度。

## 验证：训练过程中的质量检查

验证集用于训练过程中的模型选择和超参数调整。它不参与梯度更新，但会被多次用来观察模型表现。

验证阶段主要回答：

- 当前模型是否在未参与训练的数据上也表现良好。
- 学习率、网络结构、训练轮数是否合适。
- 是否出现过拟合。
- 是否需要早停、正则化、增加数据或调整模型。

过拟合的典型表现是：

```text
训练集准确率持续上升，但验证集准确率停滞或下降。
```

这说明模型可能记住了训练集细节，却没有学到可泛化规律。

## 测试：最终泛化能力评估

测试集只在模型选择完成后使用，用于最终评估模型在未知数据上的表现。它不能参与训练，也不应被反复用于调参。

可以把三类数据集类比为：

- **训练集**：平时练习题，用来学习。
- **验证集**：阶段性测验，用来调整学习方法。
- **测试集**：最终考试，用来报告最终能力。

如果频繁根据测试集结果修改模型，测试集就会间接参与模型选择，最终结果会偏乐观，不再能客观反映泛化能力。

## 推理：把训练好的模型用于新数据

推理（inference）是模型训练完成后的使用阶段。此时模型参数固定，不再更新。流程通常是：

```text
输入新样本 -> 执行前向传播 -> 得到输出 -> 转换为类别/数值结果
```

在 PyTorch 中，推理时通常会：

```python
model.eval()
with torch.inference_mode():
    output = model(x)
```

`model.eval()` 会把模型切换到评估模式；`torch.inference_mode()` 会关闭梯度追踪，减少内存占用并提升速度。

推理阶段关注的不只有准确率，还包括：

- 延迟：单个样本预测要多久。
- 吞吐量：单位时间能处理多少样本。
- 模型大小：能否放入目标设备。
- 稳定性：面对真实数据分布变化是否可靠。

## 评价指标

### 分类任务

分类任务最常见指标是准确率：

$$
\text{Accuracy} = \frac{TP + TN}{TP + TN + FP + FN}
$$

但在类别不平衡任务中，准确率可能误导。例如 100 个样本中只有 5 个正类，模型全部预测为负类也能得到 95% 准确率，却完全没有识别正类的能力。

因此还需要关注：

$$
\text{Precision} = \frac{TP}{TP + FP}
$$

$$
\text{Recall} = \frac{TP}{TP + FN}
$$

- **精准率**：预测为正的样本中，有多少是真的正。
- **召回率**：真实为正的样本中，有多少被找出来。

医疗、风控、安全检测等任务中，漏判和误判代价不同，必须结合业务选择指标。

### 回归任务

回归任务常用：

$$
\text{MSE} = \frac{1}{N}\sum_{i=1}^{N}(\hat{y}_i - y_i)^2
$$

$$
\text{RMSE} = \sqrt{\text{MSE}}
$$

MSE 对大误差更敏感；RMSE 与目标变量单位一致，更方便解释。

## 深度学习项目的迭代逻辑

一次训练结果不好，不一定说明模型“不会学习”。可能原因包括：

- 数据量太少或标签质量差。
- 特征没有标准化。
- 模型太简单或太复杂。
- 学习率过大或过小。
- 训练轮数不足或过多。
- 数据集划分不均衡。
- 评价指标与任务目标不一致。

因此项目通常按以下方式迭代：

```text
观察训练/验证结果
-> 定位问题
-> 调整数据、模型或训练策略
-> 重新训练
-> 再次验证
-> 最终测试
```

## 本章速记

- 建模决定“用什么结构学”。
- 训练决定“参数如何从数据中学”。
- 验证决定“训练过程中如何选择模型和超参数”。
- 测试决定“最终模型能否泛化到未见数据”。
- 推理决定“模型如何在真实输入上产生预测”。
- 测试集不能反复拿来调参，否则结果会失去客观性。
