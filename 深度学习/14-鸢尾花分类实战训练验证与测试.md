# 14 鸢尾花分类实战训练验证与测试

## 推理函数的定义

在模型训练开始之前，需要先定义一个推理函数。推理函数的作用是在不改变模型参数的前提下，评估模型当前在某个数据集上的性能表现。它会将模型设置为验证模式，遍历数据集中的所有样本，统计预测正确的样本数量，最后返回准确率。

推理函数接受三个参数：模型 `model`、数据集和设备类型 `device`。函数内部首先调用 `model.eval()` 将模型切换到验证状态，同时使用 `torch.no_grad()` 上下文管理器禁止梯度计算，确保推理过程中不更新模型的权重参数。这两个步骤区分了训练与推理的本质差异——训练需要计算梯度以更新参数，推理只关心模型在当前参数下的表现。

```python
def infer(model, dataset, device):
    model.eval()
    acc_num = torch.zeros(1).to(device)
    with torch.no_grad():
        for data, label in dataset:
            data = data.to(device)
            output = model(data)
            pred = torch.max(output, dim=1)[1]
            acc_num += torch.eq(pred, label.to(device)).sum().item()
    acc = acc_num / len(dataset)
    return acc
```

推理函数的核心逻辑是一个循环：从数据集中逐个取出 batch 的数据和标签，将数据送入设备后传入模型得到输出 `output`。`output` 是一个二维张量，第 0 维是 batch 维度，第 1 维是类别维度。使用 `torch.max(output, dim=1)` 在第 1 维上取最大值，返回的第二个元素是最大值所在的索引，即模型预测的类别编号。

将预测类别与真实标签 `label` 比较（`torch.eq`），统计相等的样本数并累加到 `acc_num` 中。最后用正确样本数除以数据集总样本数得到准确率，作为函数的返回值。

### 模型实例化与设备迁移

首先对之前定义的模型类进行实例化。模型的输入维度固定为 4（花萼长度、花萼宽度、花瓣长度、花瓣宽度），输出维度固定为 3（三种鸢尾花类别）。中间的隐藏层维度是超参数，可以根据实验效果调整，例如第一个隐藏层设为 12 做升维，第二个隐藏层设为 6 做降维。

实例化后的模型需要迁移到指定的计算设备（CPU 或 GPU）上。这一步通过 `model.to(device)` 完成，后续的数据和标签同样需要迁移到同一设备，否则会因设备不匹配而报错。

```python
model = NN(input_dim=4, hidden1_dim=12, hidden2_dim=6, output_dim=3).to(device)
```

### 损失函数与优化器

损失函数选用交叉熵损失 `nn.CrossEntropyLoss()`。交叉熵衡量模型预测的概率分布与真实标签之间的差异，值越小表示预测越接近真实值。对于分类任务，交叉熵是默认的损失函数选择。

优化器选用 Adam，它是梯度下降算法的一种改进版本，能够自适应调整每个参数的学习率。创建优化器时需要传入两个关键信息：哪些参数需要更新、以及学习率大小。

```python
loss_fn = nn.CrossEntropyLoss()
params = [p for p in model.parameters() if p.requires_grad]
optimizer = torch.optim.Adam(params, lr=learning_rate)
```

代码中 `[p for p in model.parameters() if p.requires_grad]` 是一个列表生成式，遍历模型所有参数，筛选出 `requires_grad=True` 的可训练参数传入优化器。大多数情况下模型参数默认都是可训练的，这个过滤步骤主要是为了兼容某些冻结参数的场景。

### 权重保存路径设置

训练过程中需要在每个 epoch 结束后保存模型权重，以便后续加载使用。保存路径通过 `os.path.join(os.getcwd(), "results", "weight")` 拼接得到，其中 `os.getcwd()` 获取当前工作目录。保存路径不存在时需要`os.makedirs` 创建。

```python
save_path = os.path.join(os.getcwd(), "results", "weight")
```

## 训练循环

训练是整个流程的核心环节，它被嵌套在最外层的 `for epoch in range(epochs)` 循环中。每个 epoch 代表模型对全部训练数据完成一次完整的学习。

### 训练状态与计数器初始化

每个 epoch 开始时，首先调用 `model.train()` 将模型切换到训练模式。然后初始化两个计数器：`acc_num` 记录该 epoch 中预测正确的样本总数，`sample_num` 记录该 epoch 中已处理的样本总数。这两个计数器的比值就是训练准确率。

```python
model.train()
acc_num = torch.zeros(1).to(device)
sample_num = torch.zeros(1).to(device)
```

### 数据加载与进度条封装

使用 `tqdm` 对 `train_loader` 进行封装，可以在终端显示一个实时的训练进度条。进度条上可以显示当前 epoch 编号、损失值和准确率等关键指标，方便观察训练状态。

```python
train_bar = tqdm(train_loader, desc=f"Epoch {epoch+1}/{epochs}", ncols=100)
for data, label in train_bar:
    label = label.squeeze()
    sample_num += data.shape[0]
```

循环中取出一个 batch 的数据和标签。`label.squeeze()` 去除标签张量中多余的维度；`data.shape[0]` 获取当前 batch 的样本数量，累加到 `sample_num` 中用于计算准确率。

### 前向传播、反向传播与参数更新

这是梯度下降算法的三个标准步骤，在每个 batch 上执行一次：

1. **梯度清零**：调用 `optimizer.zero_grad()` 将优化器中缓存的上一轮梯度重置为零。如果不执行这一步，每一轮的梯度会叠加到上一轮上，导致参数更新方向偏离当前 batch 的最优方向。类比下山过程——走几步就需要停下来抬头重新审视路线，而不是让之前的历史方向持续影响当前决策。

2. **前向传播与预测**：将数据送入设备后传入模型得到 `output`，再对 `output` 在第 1 维上取最大值索引得到预测类别 `pred_class`。`torch.max` 的返回值是一个元组，第一个元素是最大值，第二个元素是最大值的索引，这里取索引作为类别预测结果。

3. **正确数累计**：用 `torch.eq(pred_class, label.to(device))` 逐元素比较预测与标签，`sum()` 统计当前 batch 中的正确个数并累加到 `acc_num`。

4. **损失计算与反向传播**：将 `output` 和 `label` 传入损失函数得到损失值 `loss`，调用 `loss.backward()` 自动计算梯度，再调用 `optimizer.step()` 根据梯度更新模型参数。

```python
optimizer.zero_grad()
data, label = data.to(device), label.to(device)
output = model(data)
pred_class = torch.max(output, dim=1)[1]
acc_num += torch.eq(pred_class, label).sum()
loss = loss_fn(output, label)
loss.backward()
optimizer.step()
```

### 训练指标打印

每个 batch 结束后计算当前训练准确率 `train_acc = acc_num / sample_num`，并通过 `train_bar.set_postfix` 将准确率和损失值显示在进度条上。这样可以实时监控训练过程是否正常收敛。

```python
train_acc = acc_num / sample_num
train_bar.set_postfix(train_acc=train_acc.item(), loss=loss.item())
```

## 验证过程

每个 epoch 的训练结束后，需要在验证集上评估模型的泛化能力。验证过程直接调用之前定义的 `infer` 函数，传入模型、验证集数据加载器和设备，返回验证准确率。这一过程不涉及梯度计算和参数更新。

验证准确率反映了模型在未见过的数据上的表现，是判断模型是否过拟合的重要依据。如果训练准确率持续上升而验证准确率停滞或下降，说明模型出现了过拟合，需要采取正则化或早停等策略。

```python
val_acc = infer(model, val_loader, device)
print(f"Epoch {epoch+1} Val Acc: {val_acc:.3f}")
```

验证完成后，使用 `torch.save(model.state_dict(), os.path.join(save_path, "NN.pth"))` 保存当前 epoch 的模型权重。`model.state_dict()` 返回模型中所有可训练参数的字典，包含权重和偏置项。

每个 epoch 结束后需要对训练中使用的计数器进行清零操作，否则下一个 epoch 的指标会叠加上一个 epoch 的结果，导致统计不准确。

## 测试过程

所有 epoch 训练完成后，在测试集上进行最终的评估。测试过程同样调用 `infer` 函数，使用训练好的模型和测试集数据加载器。测试集在整个训练过程中从未参与参数更新和模型选择，因此测试准确率是对模型泛化性能最客观的评估。

```python
test_acc = infer(model, test_loader, device)
print(f"Test Acc: {test_acc:.3f}")
```

## 常见运行错误与调试

在实际运行训练脚本时，有几个常见的编码错误需要注意：

- **参数名拼写错误**：在调用 `DataLoader` 等类时，关键字参数名必须与 API 定义完全一致，如 `shuffle` 不能写成 `shuffl`。

- **数据集切分比例错误**：切分训练集、验证集、测试集时，三个比例之和必须严格等于 1。例如 0.7、0.2、0.1 分别对应 70%、20%、10% 的数据。如果误用了同一个变量名（如 `train_size` 重复出现），会导致总比例超过 1 而报错。

- **未保存文件直接运行**：在 VS Code 中编辑代码后，需要按 `Ctrl+S` 保存。未保存时编辑器标签页上显示白点，运行的是旧版本代码，修改不会生效。

- **epoch 循环缺少 range**：如果直接用 `for epoch in epochs` 遍历一个整数，会发生类型错误，因为整数不是可迭代对象。正确的写法是 `for epoch in range(epochs)`。

- **验证集/测试集使用了未封装的数据集**：`infer` 函数需要接收经过 `DataLoader` 封装的数据加载器（按 batch 产出数据），而不是原始的 `Dataset` 对象。如果在 `infer` 中传入了 `Dataset` 而非 `DataLoader`，会导致维度不匹配的错误。

## 实验结果分析

由于鸢尾花数据集仅有 150 条样本，划分后的训练集、验证集和测试集数据量都很小。多次运行训练脚本会发现每次的准确率结果不同。这有两个主要原因：一是每次训练的模型参数初始化是随机的，初始位置不同导致收敛结果存在差异；二是数据量太少，验证集和测试集的评估结果存在较大的随机波动，不能稳定反映模型的真实水平。

神经网络本身具有较强的拟合能力，在 112 条训练数据上可以很快达到较高的训练准确率，但在小验证集上的波动并不意味着模型有问题。对于这种小规模数据集的演示项目，更值得关注的是训练流程的完整性和代码的正确性，而非具体数值的绝对值。在实际项目中，应在更大规模的数据集上验证模型的有效性。
