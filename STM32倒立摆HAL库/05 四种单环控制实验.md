# 05 四种单环控制实验

## 本章问题

如何把同一套 PID 核心分别用于速度控制、位置控制，以及位置式/增量式实现？

> 前置：先完成 [[03 离散PID与HAL调度]] 和 [[04 基础驱动与观测实验]]，确认 40 ms 反馈窗口和电机方向。
>
> 本章对应标准库程序的 02～05：位置式/增量式定速和定位置。

## 1. 四个实验矩阵

| 实验 | 反馈 | 目标 | 周期 | 输出 |
|---|---|---|---:|---|
| 速度位置式 | 一个 40 ms 窗口的编码器增量 | ±150 count/40 ms | 40 ms | ±100 PWM |
| 速度增量式 | 同上 | 同上 | 40 ms | ±100 PWM |
| 位置位置式 | 累计编码器 count | ±408 count | 40 ms | ±100 PWM |
| 位置增量式 | 同上 | 同上 | 40 ms | ±100 PWM |

配套工程把它们合并为一个可切换例程：

- `APP_DEMO_SPEED`：速度位置式；
- `APP_DEMO_POSITION`：位置位置式；
- `APP_DEMO_CASCADE`：位置—速度串级（本章只列出，实验步骤在第 09 章展开）；
- 增量式通过 `pid_config_t.form = PID_FORM_INCREMENTAL` 启用。

## 2. 速度反馈

速度不是"电机转速"自动量，而是固定窗口内的计数增量：

```c
int16_t delta = BSP_EncoderDelta();
app_location += delta;
app_speed_window += delta;
```

这三行在 `App_Tick1ms()` 中每 1 ms 执行一次；每 40 ms 控制拍读取累计值后再清零窗口，读取在 `run_40ms_control()` 之后完成。必须先更新 PID，后清零，否则会丢掉本窗口最后一个计数。

若需要 rpm，可使用：

$$
n=\frac{60\Delta N}{N_{rev}T_s}
$$

其中 `N_rev` 和采样窗口必须与当前机械一致。课程的 408 count/圈只是近似值。

## 3. 位置反馈

位置必须累加：

```c
position += encoder_delta;
```

不能把每个窗口的速度直接当作位置。停止或模式切换时要明确软件零点是否清零；本工程的长周期位置使用 `int32_t`，避免课程 `int16_t` 的边界风险。

## 4. 位置式与增量式

`User/Inc/pid.h` 中：

```c
config.form = PID_FORM_POSITIONAL;
config.form = PID_FORM_INCREMENTAL;
```

位置式每次从误差和历史状态重新计算绝对输出；增量式把本拍变化量加到上次输出。无饱和时二者可等价，输出饱和后不要直接比较"哪个更正确"，要比较恢复时间和积分残留。

主机测试 `test_pid_proportional_and_incremental()` 专门验证了无饱和序列的等价性。

## 5. 实验步骤

本章对应标准库程序的 02、03、04、05 四个实验。HAL 版共用一个 CubeMX 底座，但每次只改变模式、PID 形式或反馈单位。

### 5.0 公共准备

1. 复制第 04 章的工程为 `05_SingleLoop`。
2. 拆下摆杆，使用转盘形态，电机回路限流。
3. 第一次启动前把目标设为 0，确认 `APP_DEMO_OBSERVE` 能正常停止电机。
4. 每完成一个小实验就复制快照；不要在同一份工程中连续叠加多个变量。

### 5.1 标准库 02：位置式 PID 定速

**对应 HAL 模式**：`APP_DEMO_SPEED`，`PID_FORM_POSITIONAL`。

**改动位置**：

- `User/Inc/app_config.h`：`APP_SELECTED_DEMO`；
- `User/Src/app.c` 的 `init_controllers()`：`speed.kp/ki/kd`；
- 不改 CubeMX，不改编码器累加逻辑。

**操作**：

1. 设 `Ki=0、Kd=0`，给一个很小的正 `Kp`；
2. 用 RP1 改变速度目标，分别做正向和反向阶跃；
3. 保持目标和机械不变，只改变 `Kp`；
4. 记录 `target`、`actual`、`command` 和 40 ms 窗口（速度模式下 `actual` 就是 PID 使用的上一个完整窗口计数值）。

**预期**：目标越大，所需输出通常越大；反馈方向正确时误差会减小。达到 ±100 后继续增加目标只会让输出长期饱和。

**通过**：正、负速度都能完成，停止后 `command=0`，没有因反馈符号错误而反向加速。

> HAL 例程的 `APP_SPEED_MIN_TARGET/MAX_TARGET` 当前为 ±150 count/40 ms；00 V1.1 综合程序的定速范围是 ±100。两套数值不要混用。

### 5.2 标准库 03：增量式 PID 定速

**对应 HAL 模式**：`APP_DEMO_SPEED`，`PID_FORM_INCREMENTAL`。

**只改一个变量**：

```c
speed.form = PID_FORM_INCREMENTAL;
```

保持上一节的目标序列、初始状态、`Kp/Ki/Kd` 和机械条件完全相同。

**对比重点**：

- 无饱和时，位置式和增量式应产生相近的目标响应；
- 发生输出限幅时，观察增量式保存的 `pid.output` 如何影响后续恢复；
- 停止时必须执行 `pid_reset()`，不能只把增益改成 0。

**通过**：主机测试 `test_pid_proportional_and_incremental()` 通过，实机曲线的差异能够由"是否饱和"和"是否 reset"解释。

### 5.3 标准库 04：位置式 PID 定位置

**对应 HAL 模式**：`APP_DEMO_POSITION`，`PID_FORM_POSITIONAL`。

**反馈定义**：

```text
app_location = app_location + BSP_EncoderDelta()
```

它是累计位置，不是 40 ms 窗口速度。

**操作**：

1. 启动前把位置目标和软件零点记录下来；
2. 用 K2/K3 每次改变 408 count，先做小范围往返（工程限幅 ±816，与 00 V1.1 定位置模式一致）；按 K4 可把位置目标清零；
3. 先 P，再加入小 D，最后才考虑小 I；
4. 反转机械方向，确认位置误差符号仍能拉回目标。

**预期**：目标改变后电机先向目标运动，接近目标时输出减小；反馈方向错误时会越走越远。

**通过**：正负目标均能回位，停止后无旧积分冲击，位置误差和反向摩擦有数值记录。

### 5.4 标准库 05：增量式 PID 定位置

**对应 HAL 模式**：`APP_DEMO_POSITION`，`PID_FORM_INCREMENTAL`。

只把 `position.form` 改为：

```c
position.form = PID_FORM_INCREMENTAL;
```

重复 5.3 的同一位置目标序列，比较：

- 接近目标时的输出变化；
- 机械摩擦导致的残余误差；
- 目标反向时是否先撤销旧输出；
- 饱和恢复是否比位置式更慢。

### 5.5 四组实验的统一记录

| 标准库实验 | HAL 模式 | PID 形式 | 反馈单位 | 主要观察 |
|---|---|---|---|---|
| 02 | `APP_DEMO_SPEED` | 位置式 | count/40 ms | P/PI 与速度阶跃 |
| 03 | `APP_DEMO_SPEED` | 增量式 | count/40 ms | 饱和和输出历史 |
| 04 | `APP_DEMO_POSITION` | 位置式 | 累计 count | 位置回零与摩擦 |
| 05 | `APP_DEMO_POSITION` | 增量式 | 累计 count | 反向、恢复和 reset |

每次记录：目标、实际、输出、采样周期、是否饱和、停止/重启结果和电机/编码器方向。

## 新手操作卡

1. 复制第 04 章工程为 `05_SingleLoop`。
2. 先选择 `APP_DEMO_SPEED`，只运行速度位置式。
3. 记录 40 ms 窗口内的 `app_speed_window`，确认控制读取后再清零。
4. 再切换 `APP_DEMO_POSITION`，确认位置是累计值而不是速度。
5. 最后把 `init_controllers()` 中对应配置的 `.form` 成员（如 `position.form`）改为 `PID_FORM_INCREMENTAL` 切换增量式；每次只改变一种算法。

## 6. 验收

- [ ] 速度反馈单位明确写成 count/40 ms；
- [ ] 位置反馈确实累加；
- [ ] 正负目标都能测试；
- [ ] 停止后输出为 0，重启无旧积分猛冲；
- [ ] 位置式和增量式的初始条件相同；
- [ ] 记录了超调、稳态误差、限幅和调节时间。

## 排障

| 现象 | 检查 |
|---|---|
| 速度目标越大输出越抖 | 目标是否超出机械可达范围、窗口是否混用 |
| 位置回不去 | `position` 是否误用速度反馈、目标零点是否明确 |
| 增量式停机仍转 | `output` 是状态，必须显式清零 |
| 正转反馈为负 | 先修方向，不要用负 Kp 掩盖接线问题 |
