## 配套工程与主机测试

配套工程 `E:\ProjectStm\倒立摆` 自带两个不需要硬件的检查工具，每个章节的验收都会用到：

- `Tests\run_host_tests.ps1`：在电脑上编译并运行控制核心（PID、串级、平衡、起摆）的单元测试，失败时脚本以非零码退出。它需要 host 端 GCC，脚本按"命令行参数 → PATH → `E:\msys64\ucrt64\bin\gcc.exe`"的顺序探测；
- `Tests\check_project.ps1`：对 `.ioc` 和生成的 `Core/` 代码做静态核对（时钟、引脚、ADC、默认模式等 17 项）。

另外 `build.ps1 -Configuration Debug`（或 Release）可以不依赖 VS Code 插件直接构建固件。

## 每章的固定学习闭环

1. 先回答一个具体问题；
2. 查看本工程的引脚、外设和调度；
3. 只改一个实验变量；
4. 记录目标、反馈、输出和状态；
5. 用 OLED、串口或示波器验收；
6. 失败时沿信号链定位，不用盲目增大增益。

## 三类结论标记

- **课程参考**：来自原 SPL 课程源码或讲义，只用于复现实验；
- **HAL 实现事实**：可以在配套工程代码和构建结果中复核；
- **待实测**：必须在自己的机械、电机和传感器上测量，不能由文档替代。

## 安全提醒

首次上电先断开电机 VM 或准备硬件急停。默认例程模式是 `APP_DEMO_OBSERVE`，不会主动启动闭环；软件停机不能替代硬件断电、限流和过流保护。
