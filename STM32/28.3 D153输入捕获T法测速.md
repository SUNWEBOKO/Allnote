# 28.3 D153 输入捕获 T 法测速：测脉冲周期

这一节讲 D153 模块的 **T 法测速**：A 相接定时器输入捕获，B 相接普通 GPIO。每次捕获到 A 相边沿时，用基于 `DWT->CYCCNT` 的 `getus()` 记录当前微秒时间戳，再用相邻 A 相边沿时间差换算输出轴转速。

T 法测速链路如下：

```text
编码器 A 相边沿
→ TIM 输入捕获触发中断
→ getus() 记录当前时间戳
→ 相邻两次时间戳相减得到 period_us
→ rps / rpm
```

电机驱动层见 [[28.1 D153电机驱动模块]]。编码器模式 M 法测速见 [[28.2 D153编码器M法测速]]。

---

## 本节核心问题

学完这一节，应该能回答下面几个问题：

- T 法测速和 M 法测速的根本区别是什么？
- CubeMX 里怎样把定时器配置成输入捕获？
- 相邻 A 相边沿时间差 `period_us` 怎样换算成 `rps`？
- 为什么 T 法低速分辨率高，但高速中断压力更大？
- A 相输入捕获、B 相 GPIO 怎样处理方向符号？
- T 法测速模块应该怎样接入 `HAL_TIM_IC_CaptureCallback()`？

## 1. T 法测速的基本思想

M 法是在固定时间内数脉冲，T 法反过来：

```text
不先固定时间窗，
而是测相邻两个脉冲之间隔了多久。
```

如果两个脉冲之间时间很短，说明转得快；时间很长，说明转得慢。

设相邻两次 A 相边沿时间差为 `period_us`，则一个脉冲周期为：

$$
T_{\text{pulse}} = period_{\text{us}} \times 10^{-6}
$$

如果输出轴一圈对应 `edges_per_output_rev` 个被捕获边沿，则：

$$
v_{\mathrm{rps}} = \frac{10^6}{period_{\text{us}} \times edges_{\text{per\_output\_rev}}}
$$

这里的关键变化是：

- 输入捕获通道负责“稳定抓到 A 相边沿”
- 真正参与测速计算的是 `getus()` 读出来的 DWT 微秒时间戳
- `getus()` 内部把 32 位 `CYCCNT` 扩成 64 位累计时间，正常工程运行里可认为没有实用意义上的回卷问题

---

## 2. T 法和 M 法的区别

| 方法 | 测量对象 | 低速表现 | 高速表现 |
| --- | --- | --- | --- |
| M 法 | 固定时间内的计数增量 | 计数少，量化误差明显 | 稳定，硬件编码器计数压力小 |
| T 法 | 相邻脉冲的时间间隔 | 周期长，分辨率高 | 中断频繁，捕获处理压力增大 |

简单记法：

```text
M 法：固定时间，数了多少个脉冲
T 法：固定脉冲，等了多少时间
```

所以：

- 低速更适合 T 法
- 中高速更适合 M 法
- 工程上也可以低速用 T 法、高速用 M 法，但初学阶段先把两种方法分别调通

---

## 3. 计数口径

T 法通常只捕获一个编码器相位的一种边沿，例如 A 相上升沿。

D153 参数：

| 参数 | 数值 | 含义 |
| --- | --- | --- |
| `D153C_PPR` | 13 | 电机本体转一圈的编码器脉冲数 |
| `D153C_REDUCTION` | 30 | 减速比 30:1 |
| `D153C_T_EDGE_MULTIPLE` | 1 | 只捕获单相上升沿 |

输出轴一圈对应的捕获边沿数为：

$$
13 \times 30 \times 1 = 390
$$

如果你改成双边沿捕获，则：

$$
D153C\_T\_EDGE\_MULTIPLE = 2
$$

如果改成两相都参与捕获，则还要按真实捕获边沿数重新计算。不要把 M 法编码器模式的四倍频计数 `1560` 直接搬到 T 法里。

## 4. CubeMX 配置输入捕获

T 法测速和 M 法测速通常是**二选一配置**。同一个定时器通道不能同时既做 Encoder Mode，又做 Input Capture。

### 4.1 选择定时器和通道

可以按下面方式分配：

| 电机 | 捕获信号 | 定时器配置 |
| --- | --- | --- |
| A 电机 | A 相上升沿 | `TIM2_CH1` Input Capture |
| B 电机 | A 相上升沿 | `TIM4_CH1` Input Capture |

方向由 B 相 GPIO 电平决定，所以 CubeMX 里除了 A 相输入捕获，还要把 B 相配成普通输入。

### 4.2 定时器基础参数

这里的输入捕获定时器主要负责边沿检测，不再直接参与测速公式。因此：

| 参数 | 示例值 |
| --- | --- |
| 定时器时钟 | 72 MHz |
| PSC | 71 |
| Counter Period | `65535` 即可 |
| 计数频率 | 1 MHz 只是常用习惯，不是测速公式前提 |
| 作用 | 给输入滤波/捕获链路提供稳定定时基准 |

因为测速公式已经改成 `period_us` 口径，而 `getus()` 来自 DWT 周期计数扩展，所以不需要再为 T 法单独维护 `TIMER_HZ` 或 “定时器是否 32 位” 这类换算宏。

### 4.3 `getus()` 的时间基

对 `STM32F103C8T6` 这类 Cortex-M3 芯片，可以直接用 DWT 的周期计数器：

- `DWT->CYCCNT` 按 CPU 主频计数
- 72 MHz 时，1 us 对应 72 个周期
- 驱动里会把 `CYCCNT` 的回卷量扩展累计成 64 位总周期数
- 再按 `SystemCoreClock / 1000000` 换算成微秒

这样做的好处是：

- 不占额外定时器
- 不依赖 SysTick 毫秒中断做拼接
- 相邻边沿时间差更干净

如果你后面运行时动态改了系统主频，记得重新初始化这套测速模块，否则 `cycles -> us` 的换算比例会沿用旧主频。

### 4.4 Input Capture Channel

通道参数建议从下面配置开始：

| 配置项 | 建议值 |
| --- | --- |
| Channel | `Input Capture direct mode` |
| Polarity | `Rising Edge` |
| IC Prescaler | `No division` |
| IC Filter | 先填 0，信号抖动明显再增大 |
| NVIC | 开启对应 TIM 中断 |

如果编码器线较长或干扰明显，可以适当增加输入滤波。滤波太大也会引入延迟，先从小值调。

### 4.5 B 相 GPIO

方向判定需要额外把 B 相接到普通 GPIO 输入：

| 电机 | 方向信号 | 配置 |
| --- | --- | --- |
| A 电机 | 编码器 B 相 | 普通 `GPIO Input` |
| B 电机 | 编码器 B 相 | 普通 `GPIO Input` |

捕获到 A 相边沿时读取 B 相电平：

- 若 B 相高电平代表正转，则配置 `B_HIGH_FORWARD = true`
- 若 B 相低电平代表正转，则配置 `B_HIGH_FORWARD = false`

## 5. T 法测速模块配置

头文件：

```c
#include "d153c_speed_t.h"
```

默认宏在 `d153c_speed_t.h` 中：

```c
#define D153C_T_EDGE_MULTIPLE          1.0f

#define D153C_T_A_IC_TIM              (&htim2)
#define D153C_T_A_IC_CH               TIM_CHANNEL_1
#define D153C_T_A_B_PORT              NULL
#define D153C_T_A_B_PIN               0U
#define D153C_T_A_B_HIGH_FORWARD      true

#define D153C_T_B_IC_TIM              (&htim4)
#define D153C_T_B_IC_CH               TIM_CHANNEL_1
#define D153C_T_B_B_PORT              NULL
#define D153C_T_B_B_PIN               0U
#define D153C_T_B_B_HIGH_FORWARD      true
```

这些宏的含义：

| 宏 | 含义 |
| --- | --- |
| `D153C_T_x_IC_TIM` | 输入捕获使用的定时器句柄 |
| `D153C_T_x_IC_CH` | 输入捕获通道 |
| `D153C_T_x_B_PORT/PIN` | 编码器 B 相 GPIO，不接方向时填 `NULL` |
| `D153C_T_x_B_HIGH_FORWARD` | 捕获到 A 相边沿时，B 相为高电平是否表示正向 |

默认不配置 B 相 GPIO，所以 T 法结果是非负速度。如果要带符号速度，需要把编码器 B 相接成 GPIO 输入，并填写 `B_PORT` 和 `B_PIN`。

## 6. T 法测速 API

```c
void d153c_speed_t_init(void);
void d153c_speed_t_deinit(void);

uint64_t d153c_speed_t_getus(void);
void d153c_speed_t_capture_callback(TIM_HandleTypeDef *htim);
void d153c_speed_t_update_timeout(uint32_t timeout_ms);
void d153c_speed_t_invert(int id, bool inv);

float d153c_speed_t_rps(int id);
float d153c_speed_t_rpm(int id);
uint32_t d153c_speed_t_period_us(int id);
uint32_t d153c_speed_t_period_ticks(int id);
bool d153c_speed_t_valid(int id);
```

接口分工：

- `d153c_speed_t_init()`：启动输入捕获中断
- `d153c_speed_t_getus()`：返回当前单调微秒时间戳，内部基于 DWT
- `d153c_speed_t_capture_callback()`：放进 HAL 输入捕获回调里，处理 A 相边沿
- `d153c_speed_t_update_timeout()`：长时间没有新脉冲时，把速度归零
- `d153c_speed_t_rps()` / `rpm()`：读取输出轴速度
- `d153c_speed_t_period_us()`：读取最近一次 A 相边沿间隔，方便调试
- `d153c_speed_t_period_ticks()`：兼容旧接口，返回值等同 `period_us`

## 7. 推荐调用方式

### 7.1 初始化

```c
#include "d153c_motor.h"
#include "d153c_speed_t.h"

int main(void)
{
    HAL_Init();
    SystemClock_Config();

    MX_GPIO_Init();
    MX_TIM2_Init();   // A 电机输入捕获
    MX_TIM3_Init();   // PWM
    MX_TIM4_Init();   // B 电机输入捕获

    d153c_motor_init();
    d153c_speed_t_init();

    d153c_motor_drive(D153C_MOTOR_A, 300);
    d153c_motor_drive(D153C_MOTOR_B, 300);

    while (1)
    {
        d153c_speed_t_update_timeout(100);

        float ra = d153c_speed_t_rps(D153C_MOTOR_A);
        float rb = d153c_speed_t_rps(D153C_MOTOR_B);
        (void)ra;
        (void)rb;
    }
}
```

### 7.2 接入 HAL 输入捕获回调

```c
void HAL_TIM_IC_CaptureCallback(TIM_HandleTypeDef *htim)
{
    d153c_speed_t_capture_callback(htim);
}
```

只要 CubeMX 开启了 TIM 输入捕获中断，并且 `d153c_speed_t_init()` 执行了 `HAL_TIM_IC_Start_IT()`，每次捕获到边沿时都会进入这个回调。

## 8. 换算示例

假设：

- 捕获单相上升沿，输出轴一圈对应 `390` 个捕获边沿
- 某次边沿间隔 `period_us = 1000`

则一个脉冲周期为：

$$
T_{\text{pulse}} = 1000\ \mu\mathrm{s} = 1\ \mathrm{ms}
$$

输出轴速度为：

$$
v_{\mathrm{rps}} = \frac{1000000}{1000 \times 390} \approx 2.56
$$

如果 `period_us = 10000`：

$$
v_{\mathrm{rps}} = \frac{1000000}{10000 \times 390} \approx 0.256
$$

周期越大，速度越低。

## 9. 方向符号处理

这里不是“纯单相测速”，而是：

1. 捕获 A 相边沿
2. 把 B 相配置为普通 GPIO 输入
3. 在捕获中断发生时读取 B 相电平
4. 根据 A/B 相位关系判断方向

驱动模块提供了可选方向 GPIO：

```c
#define D153C_T_A_B_PORT              GPIOx
#define D153C_T_A_B_PIN               GPIO_PIN_y
#define D153C_T_A_B_HIGH_FORWARD      true
```

如果用户代码还在用旧的 `DIR_PORT/DIR_PIN` 宏名，头文件里保留了兼容别名，但新配置建议统一按 `B_PORT/B_PIN` 理解。

如果读出来的速度符号反了，不要改公式，直接用：

```c
d153c_speed_t_invert(D153C_MOTOR_A, true);
```

如果不配置方向 GPIO，`d153c_speed_t_rps()` 返回非负值，适合只关心速度大小的场景。

## 10. 超时归零

T 法在低速时会很久才等到下一次脉冲。如果电机突然停止，最后一次捕获值会一直留在模块里，所以需要超时归零。

主循环里周期性调用：

```c
d153c_speed_t_update_timeout(100);
```

含义是：超过 100 ms 没有新捕获边沿，就认为速度为 0。

超时时间要按最低可测速度选择：

- 太短：低速时会误判为 0
- 太长：电机停止后速度归零不及时

## 11. 常见故障

| 现象 | 优先检查项 |
| --- | --- |
| `valid` 一直是 false | 输入捕获中断是否开启，`HAL_TIM_IC_Start_IT()` 是否执行，通道宏是否匹配 |
| `period_us` 一直为 0 | 捕获通道没接到编码器信号，或回调没有调用 `d153c_speed_t_capture_callback()` |
| 速度偏大或偏小 | `D153C_T_EDGE_MULTIPLE`、`D153C_PPR`、`D153C_REDUCTION` 是否正确 |
| 高速时系统变慢 | 捕获中断频率太高，考虑改用 M 法或降低捕获边沿数 |
| 速度符号反了 | 检查 B 相 GPIO 电平定义，或调用 `d153c_speed_t_invert()` |
| 停车后速度不归零 | 主循环没有调用 `d153c_speed_t_update_timeout()`，或超时时间过长 |

## 12. M 法和 T 法怎么选

| 场景 | 建议 |
| --- | --- |
| 中高速闭环控制 | 优先 M 法，采样稳定，中断压力小 |
| 很低速测量 | 优先 T 法，分辨率更高 |
| 只需要速度大小 | T 法可只捕获单相，不配方向 GPIO |
| 需要完整方向和速度 | M 法更直接；T 法需要额外方向相判断 |
| 初学调试 | 先单独调通一种方法，再考虑混合测速 |

最重要的是不要混用计数口径：

```text
M 法编码器模式：输出轴一圈 13 × 4 × 30 = 1560 个计数
T 法单相上升沿：输出轴一圈 13 × 1 × 30 = 390 个捕获边沿
```

## 13. 一页速记

- T 法测速：测相邻捕获边沿之间的时间间隔，再换算速度。
- 适合低速，因为低速时周期长，测时间比分固定窗数脉冲更有分辨率。
- 输入捕获必须启动中断，并在 HAL 回调里把捕获值交给测速模块。
- 只捕获单相时，方向需要额外读取 B 相 GPIO 判断。
- 电机停转后要靠超时逻辑归零，否则最后一次速度会残留。
- 高速时捕获中断会变密，可能带来较大 CPU 压力，此时更适合 M 法。
