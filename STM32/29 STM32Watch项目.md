# 29. STM32 Watch 项目：从零实现完整智能手表

> 本节重点：理解从小屏 UI + 多功能模块的完整项目架构——硬件初始化 → 输入采集 → 状态机切页 → 显示刷新 → 模块功能闭环的实现路径。

---

## 本节核心问题

学完本节，需要能回答：

- STM32 Watch 的主线为什么是“硬件初始化 -> 输入采集 -> 状态机切页 -> 显示刷新 -> 模块闭环”？
- 为什么项目复刻要先点亮 OLED、跑通按键和 RTC，而不是一开始就抄完整 `menu.c`？
- 首页、菜单页、设置页和功能模块之间如何分层？
- 定时器中断、按键事件、OLED 刷新分别应该放在哪一层？
- 新增一个功能页时，至少要改哪些文件、验证哪些现象？
- 常见故障应该从底层通信、输入事件、时间基还是页面逻辑开始查？

## 1. 这份文档是给谁看的

这不是一份"把现有代码解释一遍"的注释稿，而是一份按实现顺序组织的教学文档。目标读者是假设你已经会最基础的 STM32 开发，比如：

- 知道怎么用 STM32CubeMX 建工程
- 知道怎么编译、烧录、下载到板子
- 看得懂 C 语言和 HAL 的基础调用

如果你还没有这些基础，这个项目仍然可以学，但你最好先补三个点：GPIO 输入输出、I2C、定时器中断/PWM。

这份教程基于当前仓库的真实实现来写，推荐你一边看文档，一边对照这些文件：

- `stm32WATCH.ioc`：CubeMX 配置入口
- `Core/Src/main.c`：系统初始化和主循环入口
- `Core/Src/menu.c`：页面和功能模块主逻辑
- `Core/Src/oled.c`：OLED 驱动和绘图接口
- `Core/Src/key.c`：按键扫描
- `Core/Src/wb_rtc.c`：RTC 时间读写封装
- `Core/Src/settime.c`：时间设置页面
- `Core/Src/mpu6050.c`：MPU6050 驱动

## 2. 先理解这个项目到底做了什么

这个项目本质上是一个"小屏 UI + 多功能模块"的 STM32 小系统。它不是先做游戏，也不是先堆功能，而是先搭起一个稳定框架：

1. MCU 先把时钟、GPIO、I2C、RTC、TIM 跑起来。
2. OLED 负责把界面显示出来。
3. 三个按键提供统一交互。
4. 首页只做一级分流：进入菜单，或者进入设置。
5. 菜单页再分流到秒表、手电筒、MPU6050、小游戏、表情、水平仪等模块。

你真正要学的，不是"怎么把这几个功能拼起来"，而是下面这条实现主线：

`硬件初始化 -> 输入采集 -> 状态机切页 -> 显示刷新 -> 模块功能闭环`

只要这条线顺了，后面加闹钟、计步、电池电量，本质上都只是继续往菜单里加模块。

## 3. 硬件准备

当前项目对应的核心硬件关系如下：

- 主控：`STM32F103C8T6`
- 显示屏：`SSD1306 128x64 OLED`
- 传感器：`MPU6050`
- 按键：3 个独立按键
- 手电筒输出：1 路 PWM，可接 LED

### 3.1 当前代码使用的引脚

- `PB10` -> `I2C2_SCL`
- `PB11` -> `I2C2_SDA`
- `PB1` -> `K1`
- `PA6` -> `K2`
- `PA4` -> `K3`
- `PB4` -> `TIM3_CH1`，作为 PWM 输出

### 3.2 你要先想清楚的两件事

第一，OLED 和 MPU6050 共用一条 I2C 总线，所以你的硬件连接必须允许它们同时挂在 `I2C2` 上。

第二，当前项目里的 RTC 最终运行逻辑以代码为准，`SystemClock_Config()` 里选择的是 `LSI` 作为 RTC 时钟源。如果你想改成 `LSE + 32.768kHz 晶振`，不能只改 `.ioc`，还要同步检查生成代码和 RTC 初始化逻辑。

## 4. 软件环境准备

建议和本项目保持一致：

- `STM32CubeMX`
- `arm-none-eabi-gcc`
- `CMake >= 3.22`
- `Ninja`
- 一套烧录工具，比如 `ST-Link`

当前仓库使用的是 `STM32CubeMX + HAL + CMake` 结构，不是传统的 Keil 工程。构建命令见根目录 `README.md`：

```powershell

```

如果你只是跟着复刻逻辑，也可以先在 CubeMX 里生成，再在你熟悉的 IDE 里调试；但如果你想和当前仓库完全对齐，最好直接沿用 CMake。

## 5. 推荐实现顺序

不要一上来就照着 `menu.c` 抄整项目。正确顺序是每一步都先做出"肉眼可见的结果"，再进入下一步。

### 阶段 1：先建一个能跑起来的空工程

你在 CubeMX 里先完成这些最小配置：

- MCU 选择 `STM32F103C8T6`
- 系统时钟配置到 `72MHz`
- 开启 `I2C2`
- 开启 `RTC`
- 开启 `TIM2` 基本定时器中断
- 开启 `TIM3 CH1 PWM`
- 把三个按键对应引脚配置为上拉输入
- 生成 `CMake` 工程

#### 这个阶段的验收标准

- 下载后程序能跑，不会卡死在 `Error_Handler()`
- `main.c` 能完成 `HAL_Init()`、时钟配置和各外设初始化

这个阶段对应当前仓库的骨架文件：

- `Core/Src/main.c`
- `Core/Src/gpio.c`
- `Core/Src/i2c.c`
- `Core/Src/rtc.c`
- `Core/Src/tim.c`
- `stm32WATCH.ioc`

### 阶段 2：先点亮 OLED，不要先做 UI

第二步只做一件事：把 OLED 驱动通。

当前项目把 OLED 做成了"显存缓冲区 + 整帧刷新"的结构，也就是：

1. 先在内存里画。
2. 最后统一 `OLED_ShowFrame()` 刷到屏上。

这是对的，因为这样页面代码就不需要直接碰 I2C 细节。你写界面时只需要关心"画什么"，不需要关心"怎么发命令"。

你可以按这个顺序实现：

1. 写 OLED 基础初始化
2. 写发命令、发数据函数
3. 做一块显存缓冲区
4. 实现 `OLED_NewFrame()`
5. 实现 `OLED_ShowFrame()`
6. 再补文字、图片、图形绘制函数

建议一开始只做一段固定字符串显示，比如屏幕上显示 `HELLO`。只有这个通过了，再进入后面的页面开发。

当前实现参考：

- `Core/Src/oled.c`
- `Core/Inc/oled.h`
- `Core/Src/font.c`
- `Core/Inc/font.h`

#### 这个阶段的验收标准

- OLED 能稳定显示固定文字
- 连续刷新时屏幕不乱、不闪、不花

### 阶段 3：做按键输入，建立统一事件模型

这个项目的按键处理有一个很值得学的点：页面不直接读 GPIO，而是统一通过 `Key_GetNum()` 读"按键松手事件"。

当前逻辑在 `Core/Src/key.c`：

- `Key_GetState()`：直接读 GPIO 当前状态
- `Key_Tick()`：做消抖和边沿检测
- `Key_GetNum()`：给页面层返回一次性事件

为什么这样做：

- 页面代码会更干净
- 不会因为按住按键导致一个动作狂触发
- 所有页面交互都能统一成 `K1/K2/K3`

当前项目里 `TIM2` 约每 `1ms` 进一次中断，而 `Key_Tick()` 里每 `20` 次采样处理一次，相当于做了大约 `20ms` 的消抖节拍。

#### 这个阶段的验收标准

- 按一次键，串口或屏幕上的计数只加一次
- 长按不会连续乱跳

### 阶段 4：把 RTC 跑通，先让时间能读出来

很多人做表项目时会太早做"设置页"，结果最后发现 RTC 都没跑稳。正确顺序应该反过来：

1. 先让 RTC 正常走时
2. 再封装成读写接口
3. 最后再做设置页

当前项目做了一个包装层 `Core/Src/wb_rtc.c`，主要提供三个接口：

- `WB_RTC_Init()`
- `WB_RTC_GetTime()`
- `WB_RTC_SetTime()`

这里还有一个关键设计：用备份寄存器记录初始化标记。如果是第一次上电，就写入一组默认时间；以后再次复位，只要标记还在，就不重复覆盖时间。

这是手表类项目里非常实用的一步，否则你每次下载程序，时间都会被重置。

#### 这个阶段的验收标准

- OLED 上能显示当前时间
- 复位后时间继续走，不会每次都回默认值

### 阶段 5：先做首页，再做菜单，不要反过来

`Core/Src/main.c` 的主循环非常简单：

```c
while (1)
{
    clkflag = FirstMenu();
    if (clkflag == 1) { flowMenu(); }
    else if (clkflag == 2) { SetPage(); }
}
```

这说明当前项目把页面组织成了两层：

- 第一层：首页，在"菜单"和"设置"之间切换
- 第二层：真正的功能菜单或设置页面

这一步你应该先复刻首页：

1. 在 OLED 上显示日期时间
2. 底部显示"菜单"和"设置"
3. 用 `K1/K2` 切换高亮
4. 用 `K3` 确认进入

只有首页稳定了，再进入二级菜单开发。这样做的好处是，你始终有一个稳定入口，不会一开始把所有模块耦在一起。

当前实现入口：

- `ShowClock()`
- `FirstMenu()`

都在 `Core/Src/menu.c`。

### 阶段 6：做滑动菜单框架，先跑通路由，再填功能

这一步是整个项目最核心的结构设计。

当前项目的 `flowMenu()` 负责三件事：

1. 接收 `K1/K2/K3`
2. 切换当前选中的菜单项
3. 在按 `K3` 后进入具体模块

而 `Menu_Animation()` 只负责动画，不负责业务跳转。这个拆分很重要，因为它让"显示效果"和"功能路由"分开了。

建议你按这个顺序实现：

1. 先做不带动画的菜单切换
2. 再加高亮框
3. 最后加滑动动画

千万不要一上来就写动画。先做出"菜单能切换、能进模块"的最小闭环，再谈观感。

当前菜单顺序是：

1. 返回
2. 秒表
3. 手电筒
4. MPU6050
5. Dino 游戏
6. 动态表情
7. 水平仪

### 阶段 7：先做设置页，再做时间设置子页

设置模块分成两层：

- `SetPage()`：设置封面
- `SetTime()`：具体的时间修改页面

这里的思路不是"在一个页面里什么都改"，而是继续维持页面状态机结构。当前实现里，年、月、日、时、分、秒分别有独立编辑逻辑，这样每次只改一个字段，出错概率更低，也更容易调试。

如果你自己重做，建议保留这个思路。

#### 这一阶段的重点

- 先确保 `WB_RTC_GetTime()` 读出来的数据可靠
- 修改字段后立即 `WB_RTC_SetTime()`
- 每次只反显当前编辑项

对应文件：

- `Core/Src/settime.c`
- `Core/Inc/settime.h`

### 阶段 8：秒表是最适合练"状态 + 节拍"的模块

秒表模块值得先做，因为它会逼你把"中断里更新状态，主循环里刷新界面"这件事想清楚。

当前项目在 `main.c` 的定时中断回调里调用：

- `Key_Tick()`
- `stopwatch_tick()`

这意味着秒表时间推进不是靠页面 `while` 循环自己 `delay` 出来的，而是依赖固定节拍。这是正确做法，因为显示刷新快慢不应该决定计时精度。

你在自己实现时，至少要做到：

- 计时状态和显示状态分离
- 开始、停止、清零是明确状态切换
- 不要在中断里直接操作 OLED

对应实现：

- `ShowStopWatch()`
- `stopwatch_tick()`
- `Stopwatch()`

都在 `Core/Src/menu.c`。

### 阶段 9：手电筒模块是最简单的 PWM 练手项目

这个模块的逻辑很直接：

- `TIM3_CH1` 输出 PWM
- `K1` 降低占空比
- `K2` 提高占空比
- `K3` 返回

当前代码里实际改亮度用的是：

```c
__HAL_TIM_SET_COMPARE(&htim3, TIM_CHANNEL_1, duty);
```

因为 `TIM3` 的周期被设成了 `100 - 1`，所以这里的 `duty` 本质上就是百分比近似值，理解起来也最直观。

这个模块适合你确认两件事：

- 你的 PWM 输出脚确实接对了
- 你的页面状态变化和实际硬件输出是同步的

### 阶段 10：MPU6050 页面先做"读原始值"，不要先做姿态算法

这是一个非常重要的顺序问题。

很多人一接 MPU6050，就想先做角度、姿态解算、卡尔曼滤波。这个项目没有这么走，而是先把最小闭环做出来：

1. 检测设备是否在线
2. 读取原始寄存器
3. 在 OLED 上显示 `ax/ay/az/temp/gx/gy/gz`
4. 失败时允许重新初始化

当前 `Core/Src/mpu6050.c` 的实现也很克制，只做了：

- 基础寄存器读写
- `WHO_AM_I` 检查
- 一组最基础初始化配置
- 原始数据读取

这才是对的。先把驱动和通信层跑稳，再谈算法层。

### 阶段 11：水平仪是在 MPU6050 原始值之上做一个"小应用"

水平仪不是一个独立硬件模块，而是建立在 MPU6050 数据之上的 UI 应用。

当前项目里的思路是：

1. 页面进入时先做一次校准
2. 后续按固定周期刷新气泡位置
3. `K1` 可重新校准
4. `K3` 返回

你在复刻时要注意，这一步不是"另写一个驱动"，而是"复用已有传感器驱动，重新解释数据"。

这也是整个项目很典型的一种扩展模式：一个底层驱动，多个上层页面。

### 阶段 12：小游戏和动态表情最后做

这是最后做，不是因为它们不重要，而是因为它们依赖前面几乎所有基础能力：

- OLED 绘图
- 按键事件
- 页面循环
- 状态机
- 定时刷新

当前 Dino 游戏写法是"小工程最小闭环"的典型风格：输入、运动更新、碰撞判定、绘制都放在一个模块循环里。对于学习项目，这是合理的，因为你能很快看到结果，也方便后续手动调参数。

如果你是第一次做这类项目，不要急着把游戏重构成复杂引擎。先能玩，再考虑抽象。

### 阶段 13：最后做构建、烧录和回归测试

当所有功能都写完后，这个项目还差最后一个闭环：确认它真的能稳定编译、下载、运行。

如果你沿用当前仓库的 CMake 方式，基本命令是：

```powershell
cmake --preset Debug
cmake --build --preset Debug
```

构建产物会出现在 `build/Debug/` 下。当前仓库里没有统一封装好的烧录脚本，所以你需要自己用常用工具完成下载，比如：

- STM32CubeProgrammer
- ST-Link Utility
- OpenOCD

真正的"项目完成"不是代码都写进去了，而是至少完成一次完整回归：

1. 上电后首页能显示时间
2. 三个按键都能稳定响应
3. 菜单能正常切换和返回
4. 秒表能开始、停止、清零
5. PWM 输出能调亮度
6. MPU6050 数据页能显示数据或至少给出明确错误页
7. 水平仪能校准并刷新

如果你在这一步才发现问题，不要回到最复杂的模块里乱改，而是按"驱动层 -> 页面层 -> 模块层"的顺序往回排查。

## 7. 这个项目最值得你学的几个设计点

### 7.1 中断只改状态，不直接刷新界面

这是本项目最正确的习惯之一。

- `TIM2` 中断里做按键扫描和秒表节拍
- OLED 刷新放在页面逻辑里

这样中断短、逻辑稳，也更容易排错。

### 7.2 输入统一抽象成按键事件

页面只认 `Key_GetNum()`，不直接认 GPIO。这会让你的 UI 层清晰很多。

### 7.3 一个驱动提供多个上层功能

MPU6050 既能做数据页，也能做水平仪。这说明底层驱动和上层页面最好分开。

### 7.4 先做最小闭环，再做效果

这个项目里很多地方都符合这个原则：

- 先有首页，再有菜单动画
- 先能读 RTC，再做设置页
- 先能读 MPU6050 原始值，再做水平仪
- 先把功能跑通，再补小游戏和表情

这套顺序非常适合教学，也非常适合你以后自己做别的 STM32 小项目。

## 8. 常见坑和排查建议

### 8.1 OLED 不亮

先查四件事：

- I2C 引脚是不是接对了
- OLED 地址是不是对的
- 电源和地是不是接好
- 初始化命令有没有发成功

不要一上来怀疑字库或者页面逻辑，先确认最底层通信。

### 8.2 按键乱跳

先查：

- 按键是不是上拉输入
- 按下时电平是不是确实被拉低
- 消抖节拍是不是太短

如果你页面里自己也在重复处理长按，很容易和 `Key_Tick()` 的行为打架。

### 8.3 RTC 每次复位都回默认时间

重点看备份寄存器标记有没有写进去。这个项目依赖 `HAL_RTCEx_BKUPRead()` 和 `HAL_RTCEx_BKUPWrite()` 判断是否首次初始化。

### 8.4 MPU6050 读不到数据

先别急着怀疑算法，先查：

- 地址是不是 `0x68 << 1`
- `WHO_AM_I` 是否返回 `0x68`
- I2C 总线上的 OLED 和 MPU6050 是否都正常供电

### 8.5 PWM 没输出

先查：

- `TIM3` 是否启动了 PWM
- `PB4` 是否完成复用配置
- 占空比是不是一直被写成了 0

## 9. 如果你要带一个新人做这个项目，最好的教学节奏

不要让他一周内同时做完所有功能。更合理的节奏是：

1. 第一天：建工程，点亮 OLED，显示固定文字
2. 第二天：完成按键扫描，做一个简单菜单切换

## 10. 一页速记

- 项目本质：小屏 UI + 多功能模块 + 三按键交互。
- 实现主线：硬件初始化 -> 输入采集 -> 状态机切页 -> 显示刷新 -> 模块功能闭环。
- 推荐顺序：空工程 -> OLED -> 按键 -> RTC -> 首页 -> 菜单 -> 单个功能页 -> 更多模块。
- 中断职责：只做按键扫描、秒表节拍这类短任务，不直接刷新 OLED。
- 页面职责：读取一次性按键事件，根据状态机决定画什么、跳到哪里。
- 调试原则：先做肉眼可见的最小结果，再进入下一层抽象。

## 12. 最后给你的复刻建议

如果你的目标是"完整做出这个项目"，最重要的不是一次写完，而是坚持下面这条顺序：

`先驱动 -> 再页面 -> 先最小闭环 -> 再加观感 -> 先稳定 -> 再扩展`

按当前仓库的真实结构来说，最值得复刻的不是每一行代码，而是这套实现路径。只要路径对了，即使改掉菜单样式、替换 OLED 驱动、换成别的传感器，这个项目也依然能成立。
