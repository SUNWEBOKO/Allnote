# 24. 互补滤波：把 MPU 数据变成稳定角度

> 本节目标：在已经能读出 MPU6050/MPU6500 数据的前提下，理解加速度计和陀螺仪各自的优缺点，并能写出一个可调、可排错的 pitch 角互补滤波流程。

---

## 本节核心问题

学完本节，需要能回答：

- 加速度计为什么能估计倾角？它在哪些情况下会抖或不可信？
- 陀螺仪积分为什么短时间平滑，但长时间会漂？
- 互补滤波里的 `FILTER_GAIN` 到底是在相信谁？
- `pitch_acc`、`gyro_y`、`dt` 和 `pitch` 在更新公式中分别承担什么角色？
- 第一次运行时为什么要用加速度角初始化，而不是从 0 开始积分？
- 角度方向反了、漂了、抖了时，应该优先检查哪些量？

---

## 1. 这一节只关心什么

上一节已经把两种 MPU 的驱动和用法讲清了。

这一节只关心一件事：

```text
怎样把读出来的 ax / az / gy 变成稳定的 pitch 角
```

也就是：

1. 为什么加速度计能算倾角。
2. 为什么单靠加速度计会抖。
3. 为什么陀螺仪要积分。
4. 为什么单靠陀螺仪会漂。
5. 为什么把两者用互补滤波融合后会更好用。

---

## 2. 先把两类数据分清

MPU 里的六轴数据，本质上来自两种传感器。

| 传感器 | 输出 | 优点 | 缺点 |
|---|---|---|---|
| 加速度计 | `ax`、`ay`、`az` | 能反映重力方向，长期不漂 | 振动、碰撞、运动加速度会让角度抖 |
| 陀螺仪 | `gx`、`gy`、`gz` | 响应快，短时间动态好 | 零偏和温漂会让积分慢慢漂 |

最常记的一句话就是：

```text
加速度计：长期稳定，但短期会抖
陀螺仪：短期灵敏，但长期会漂
```

互补滤波就是把这两个特点拼起来。

---

## 3. 加速度计为什么能算倾角

加速度计测到的是“传感器感受到的加速度”。

当板子静止时，它虽然没有平动加速度，但仍会测到重力分量。板子一倾斜，重力在 X/Y/Z 三个轴上的投影就会变化，所以可以反推出倾角。

如果这里先只看 pitch，常见写法是：

```c
float pitch_acc = atan2f(ax_g, -az_g) * 57.29578f;
```

其中：

- `ax_g`、`az_g` 是换算成 `g` 的加速度。
- `atan2f()` 返回弧度，乘 `57.29578` 后变成角度。
- `-az_g` 是为了匹配当前安装方向；如果你的坐标方向不同，符号也要跟着改。

### 3.1 为什么这里能用 `atan2f`

因为 pitch 的本质就是“重力向量在 X-Z 平面里的方向角”。

你可以把它理解成：

```text
平放时：重力主要落在 Z 轴
前后倾斜后：重力会分到 X 轴和 Z 轴
由 X 和 Z 的比例就能反推出倾角
```

### 3.2 为什么它会抖

因为加速度计并不知道自己读到的是：

- 重力分量
- 还是运动带来的瞬时加速度

比如：

- 小车突然前冲
- 电机振动
- 手拿着模块抖动
- 桌面被敲了一下

这些都会让 `pitch_acc` 突然跳动。

所以加速度计适合做“长期参考”，不适合单独当最终角度输出。

---

## 4. 陀螺仪为什么能跟踪角度变化

陀螺仪输出的是**角速度**，不是角度。

比如：

```text
gyro_y = 90 dps
```

意思是：当前绕 Y 轴每秒旋转 `90°`。

如果想知道角度，就要积分：

```text
新角度 = 上一帧角度 + 角速度 × 时间间隔
```

代码里就是：

```c
pitch = pitch + pitch_rate * dt;
```

其中：

- `pitch_rate` 单位是 `deg/s`
- `dt` 单位是 `s`
- 所以 `pitch_rate * dt` 的结果单位正好是 `deg`

### 4.1 陀螺仪为什么会漂

理想情况下，静止时陀螺仪应该输出 0。

但真实芯片常常会有一个小零偏，比如静止时一直输出：

```text
+0.8 dps
```

那积分后就会不断累积误差：

```text
1 秒后误差约 0.8°
60 秒后误差约 48°
```

所以陀螺仪单独用来长期算角度，会越算越偏。

---

## 5. 互补滤波为什么有效

现在两边的优缺点已经很清楚：

- 加速度计能给出长期可靠的倾角参考，但会抖。
- 陀螺仪能给出平滑快速的动态变化，但会漂。

那就可以这样做：

1. 主要相信陀螺仪，让角度变化足够顺滑。
2. 再用少量加速度计结果，慢慢把漂移拉回来。

这就是互补滤波。

核心公式：

```text
pitch = a * (pitch + pitch_rate * dt)
      + (1 - a) * pitch_acc
```

常见起始值：

```text
a = 0.98
```

也就是：

```text
pitch = 0.98 * (pitch + pitch_rate * dt)
      + 0.02 * pitch_acc
```

含义可以直接这么理解：

- `0.98`：大部分相信陀螺仪积分结果
- `0.02`：小部分相信加速度计角度，用来长期纠偏

---

## 6. `FILTER_GAIN` 怎么理解

通常会把上面的 `a` 写成一个宏：

```c
#define FILTER_GAIN 0.98f
```

它越大，说明越相信陀螺仪；越小，说明越相信加速度计。

| `FILTER_GAIN` | 表现 | 适合场景 |
|---:|---|---|
| `0.99` | 更平滑、更抗振，但回正慢 | 振动较大 |
| `0.98` | 常用折中 | 初始调试 |
| `0.95` | 回正更快，但更容易抖 | 需要更快纠偏 |

先记调参规律：

```text
抖动大 -> 增大 FILTER_GAIN
回正慢 -> 减小 FILTER_GAIN
```

但如果一直漂，先别急着调它，先查零偏和 `dt`。

---

## 7. 工程实现的推荐主线

这一节推荐优先用上一节的 `ReadData()` 思路，因为它已经把 raw 换成了 `g` 和 `dps`。

下面先以 **MPU6050** 为例写代码；如果你用的是 **MPU6500**，把前缀 `MPU6050_` 换成 `MPU6500_` 即可，字段名是一致的。

---

## 8. 第一步：准备状态变量

```c
static float pitch = 0.0f;          // 融合后的 pitch 角，单位：度
static float gyro_bias = 0.0f;      // gy 的零偏，单位：dps
static uint8_t pitch_inited = 0;    // 是否已完成初始角度赋值

#define FILTER_GAIN 0.98f
```

这里的 `gyro_bias` 很重要，因为互补滤波前必须先把陀螺仪静止偏置减掉。

---

## 9. 第二步：上电先标定陀螺仪零偏

标定时必须保持模块完全静止。

```c
void CalibrateGyroBias(void)
{
  MPU6050_Data data;
  float sum = 0.0f;
  int valid_count = 0;

  for (int i = 0; i < 200; i++)
  {
    if (MPU6050_ReadData(&data) == MPU6050_OK)
    {
      sum += data.gy_dps;
      valid_count++;
    }

    HAL_Delay(5);
  }

  if (valid_count > 0)
  {
    gyro_bias = sum / (float)valid_count;
  }
}
```

这段代码的含义就是：

```text
静止时 gy_dps 理论上应接近 0
把实际平均值记为偏置
后面每次都减掉它
```

---

## 10. 第三步：每次循环更新 pitch

```c
void UpdatePitch(float dt)
{
  MPU6050_Data data;

  if (MPU6050_ReadData(&data) != MPU6050_OK)
  {
    return;
  }

  float pitch_acc = atan2f(data.ax_g, -data.az_g) * 57.29578f;
  float pitch_rate = data.gy_dps - gyro_bias;

  if (!pitch_inited)
  {
    pitch = pitch_acc;
    pitch_inited = 1;
    return;
  }

  pitch = FILTER_GAIN * (pitch + pitch_rate * dt)
        + (1.0f - FILTER_GAIN) * pitch_acc;
}
```

这段代码可以拆成 4 步读：

1. 读取已经换算好的 `ax_g`、`az_g`、`gy_dps`。
2. 用加速度算出 `pitch_acc`。
3. 用陀螺仪减去零偏后得到 `pitch_rate`。
4. 用互补滤波把两者融合成新的 `pitch`。

---

## 11. 为什么第一次要先用 `pitch_acc` 初始化

如果一上电时板子本来就是倾斜的，而你把 `pitch` 固定从 0 开始，那么第一次进入融合时就会突然跳一下。

所以更稳的做法是：

```text
第一次先用加速度计角度给 pitch 一个初值
后面再进入互补滤波
```

这也是上一段代码里 `pitch_inited` 的作用。

---

## 12. `dt` 必须认真处理

互补滤波里，`dt` 是非常关键的一个量。

如果 `dt` 不准，陀螺仪积分就一定不准。

### 12.1 固定周期调用

如果你在固定定时器里每 `1 ms` 调一次：

```c
UpdatePitch(0.001f);
```

那这样写没问题。

### 12.2 主循环里调用

如果你是在 `while (1)` 里跑，就不要把 `dt` 写死。

```c
static uint32_t last_tick = 0;

void LoopTask(void)
{
  uint32_t now = HAL_GetTick();

  if (last_tick == 0)
  {
    last_tick = now;
    return;
  }

  float dt = (now - last_tick) / 1000.0f;
  last_tick = now;

  UpdatePitch(dt);
}
```

如果循环里有这些东西：

- `HAL_Delay()`
- 串口打印
- OLED 刷新
- I2C 超时重试

那真实 `dt` 往往不是常数。

---

## 13. 如果你更想在高频中断里读 raw

`ReadData()` 内部固定是 `100 ms` 超时，不适合直接放到高频中断里。

这时更常见的写法是：

```c
void UpdatePitchFromRaw(float dt)
{
  MPU6050_AccelGyroRaw raw;

  if (MPU6050_ReadAccelGyroRaw(&raw, 1) != MPU6050_OK)
  {
    return;
  }

  float ax_g = (float)raw.accel_x / 8192.0f;
  float az_g = (float)raw.accel_z / 8192.0f;
  float pitch_acc = atan2f(ax_g, -az_g) * 57.29578f;

  float pitch_rate = (float)raw.gyro_y / 65.5f - gyro_bias;

  if (!pitch_inited)
  {
    pitch = pitch_acc;
    pitch_inited = 1;
    return;
  }

  pitch = FILTER_GAIN * (pitch + pitch_rate * dt)
        + (1.0f - FILTER_GAIN) * pitch_acc;
}
```

这段代码默认基于上一节当前驱动的默认量程：

- `±4 g -> 8192 LSB/g`
- `±500 dps -> 65.5 LSB/(deg/s)`

如果你改了量程，记得同步改这里的除数。

---

## 14. 坐标方向不同时，最先检查什么

如果你发现：

- 前倾时角度反而变小
- 后倾时角度方向反了
- 静止时 `az` 的符号和预期相反

那第一反应不要怀疑滤波公式，而要先检查：

1. `atan2f(data.ax_g, -data.az_g)` 里的负号是否适合你的安装方向。
2. pitch 对应的角速度到底该用 `gy_dps` 还是别的轴。
3. 陀螺仪轴符号是否需要取反。

也就是说，互补滤波的前提是：

```text
加速度角和陀螺仪角速度的正方向必须一致
```

---

## 15. 调参顺序不要乱

建议按下面顺序排查。

### 15.1 先看零偏

板子静止时，观察：

```text
pitch_rate = gy_dps - gyro_bias
```

理想上应该只在 0 附近小幅波动。

如果静止时它一直偏正或偏负，先重新标定，不要急着调 `FILTER_GAIN`。

### 15.2 再看 `dt`

如果 `dt` 比真实值大，积分会偏大；如果 `dt` 比真实值小，积分会偏小。

表现通常是：

- 动态角度变化比例不对
- 漂移看起来很奇怪
- 回正速度不符合预期

### 15.3 最后才调 `FILTER_GAIN`

| 现象 | 常见原因 | 处理 |
|---|---|---|
| 静止时角度抖得厉害 | 加速度计权重太大，或机械振动太强 | 增大 `FILTER_GAIN` |
| 回正太慢 | 太相信陀螺仪 | 减小 `FILTER_GAIN` |
| 长时间持续漂移 | 零偏或 `dt` 有问题 | 先修零偏和 `dt` |
| 快速动作后方向怪异 | 轴映射或正负号不对 | 先查坐标方向 |

---

## 16. 验证动作可以这样做

调完以后，至少做下面几组动作：

| 动作 | 期望结果 |
|---|---|
| 静止平放 | `pitch` 稳定在 0 附近，小幅波动 |
| 缓慢前后倾斜 | 角度平滑变化 |
| 保持某个倾角不动 | 不应持续明显漂移 |
| 快速回正 | 能较快回到 0 附近 |
| 轻敲桌面 | 不应出现夸张跳变 |

调试时很推荐同时打印：

```text
pitch_acc, pitch_rate, pitch
```

这样就能分清：

- 是加速度角在抖
- 还是陀螺仪零偏没扣干净
- 还是融合系数不合适

---

## 17. 常见问题速查

| 现象 | 最可能原因 | 怎么做 |
|---|---|---|
| 角度一直往一边漂 | `gyro_bias` 不准，或 `dt` 不准 | 重新标定零偏，重新测 `dt` |
| 静止时角度抖动大 | 加速度计噪声占比太高 | 增大 `FILTER_GAIN` |
| 角度回正很慢 | 太相信陀螺仪积分 | 减小 `FILTER_GAIN` |
| 前后倾方向反了 | `atan2` 符号或陀螺仪轴向不一致 | 调整 `-az` 或 `gy` 符号 |
| 一上电角度跳一下 | 没做首次 `pitch_acc` 初始化 | 加 `pitch_inited` 逻辑 |
| 中断里卡顿 | 直接在中断里用 `ReadData()` | 改成 `ReadAccelGyroRaw(..., 1)` |

---

## 18. 一页速记

- 加速度计能看重力方向，所以能估倾角，但会受振动和运动加速度影响。
- 陀螺仪输出角速度，积分后能跟踪角度变化，但零偏会导致漂移。
- 互补滤波核心：

```text
pitch = a * (pitch + gyro * dt) + (1 - a) * pitch_acc
```

- 常用起始值：`a = 0.98`。
- `FILTER_GAIN` 大：更平滑、更抗振，但回正慢。
- `FILTER_GAIN` 小：回正更快，但更容易抖。
- 真正漂移时，先查 `gyro_bias` 和 `dt`，不要先怪滤波系数。
- 第一次运行时，最好先用 `pitch_acc` 初始化 `pitch`。
- 如果在高频中断里更新，优先用 `ReadAccelGyroRaw()`，不要直接用 `ReadData()`。
