> 本节重点：理解 GPIO 推挽输出控制 LED 亮灭的原理，掌握从原理图到 CubeMX 配置再到生成代码的完整闭环。

## 1. LED 为什么会亮

### 1.1 硬件连接路径

开发板三色 LED 分别连接到不同 GPIO 引脚。本节以连接到 **PA7** 的绿色 LED 为例：

```text
PA7 ──[限流电阻]── LED 阳极 ── LED 阴极 ── GND
```

LED 一端接地，另一端通过限流电阻接到 PA7。

### 1.2 亮灭条件

| PA7 电平 | 电压 | LED 状态 | 原因 |
|----------|------|----------|------|
| 高电平 | 约 3.3V | 亮 | 形成电压差，有电流流过 |
| 低电平 | 约 0V | 灭 | 两端等电位，无电流 |

```text
GPIO 输出高电平 → PA7 ≈ 3.3V → LED 亮
GPIO 输出低电平 → PA7 ≈ 0V   → LED 灭
```

---

## 2. GPIO 输出模式原理

GPIO 在输出模式下由 STM32 内部控制逻辑决定引脚电平。本节使用 **推挽输出（Push-Pull Output）**：

| 特性 | 说明 |
|------|------|
| 高电平 | 内部上管导通，引脚主动接到 VDD（约 3.3V） |
| 低电平 | 内部下管导通，引脚主动接到 VSS（0V） |
| 驱动能力 | 强，高低电平均可主动驱动 |
| 适用场景 | 普通数字输出（LED、蜂鸣器、通用控制信号） |

---

## 3. 先看原理图，再做配置

这是嵌入式开发最基础的习惯：

> **不先确认硬件连接，软件配置就没有目标。**

典型错误场景：

- 不查原理图就配 CubeMX，配到错误的引脚
- 配对了引脚但不知道 LED 是高电平亮还是低电平亮
- 灯不亮时首先怀疑代码，实际是引脚连错或电路不对

---

## 4. CubeMX 配置步骤

### 4.1 最小配置

| 步骤 | 操作 |
|------|------|
| 1 | 新建工程，选择芯片 `STM32F103C8T6` |
| 2 | 在 Pinout 视图找到 `PA7` |
| 3 | 将 `PA7` 配置为 `GPIO_Output` |
| 4 | 进入 GPIO 详细配置页 |
| 5 | 输出模式保持 `Output Push Pull` |
| 6 | 将 `GPIO output level` 改为 `High` |
| 7 | 保存工程并生成代码 |

### 4.2 为什么没写代码灯也能亮

CubeMX 生成的 `MX_GPIO_Init()` 自动完成了：

1. 使能 GPIOA 外设时钟
2. 配置 PA7 模式寄存器为输出
3. 配置输出类型为推挽
4. 设置初始输出电平为高

因此上电初始化结束后，PA7 已经是高电平，LED 直接亮起。

## 5. 代码控制亮灭

### 5.1 HAL 操作函数

| 函数 | 作用 |
|------|------|
| `HAL_GPIO_WritePin(GPIOA, GPIO_PIN_7, GPIO_PIN_SET)` | PA7 输出高电平 |
| `HAL_GPIO_WritePin(GPIOA, GPIO_PIN_7, GPIO_PIN_RESET)` | PA7 输出低电平 |
| `HAL_GPIO_TogglePin(GPIOA, GPIO_PIN_7)` | PA7 电平翻转 |

### 5.2 LED 闪烁示例

```c
/* USER CODE BEGIN 2 */
HAL_GPIO_WritePin(GPIOA, GPIO_PIN_7, GPIO_PIN_SET);  // 初始亮
/* USER CODE END 2 */

/* USER CODE BEGIN WHILE */
while (1)
{
    HAL_GPIO_TogglePin(GPIOA, GPIO_PIN_7);
    HAL_Delay(500);
}
/* USER CODE END WHILE */
```

## 6. 高频易错点

1. **没确认 LED 是高电平亮还是低电平亮**  
   不同开发板电路不同，必须查原理图确认。

2. **配错了引脚**  
   原理图上 LED 接的是 PA7，CubeMX 里配成了其他引脚。

3. **引脚未配成输出模式**  
   引脚默认可能是输入，必须显式改为 `GPIO_Output`。

4. **初始电平设反**  
   `GPIO output level` 默认是 `Low`，不改的话灯不亮。

5. **代码写在用户保护区外**  
   CubeMX 重新生成代码时会覆盖保护区外的内容。用户代码应写在 `USER CODE BEGIN / END` 之间。

## 7. 一页速记

### 核心流程
```text
原理图查引脚 → CubeMX 配 GPIO_Output → 生成代码 → 下载 → LED 亮
```

### 关键映射
```text
高电平 (3.3V) → LED 亮
低电平 (0V)   → LED 灭
推挽输出      → 高低电平均可主动驱动
```

### 核心 API
| 函数 | 用途 |
|------|------|
| `HAL_GPIO_WritePin(port, pin, state)` | 设置引脚电平 |
| `HAL_GPIO_TogglePin(port, pin)` | 翻转引脚电平 |

### 最重要的一句话
> 点灯不是在完成任务，而是在建立"硬件连接 → 外设配置 → 自动初始化 → 现象验证"的完整开发闭环。
