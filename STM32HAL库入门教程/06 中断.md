# 第 6 章 中断与 EXTI

## 本章闭环

本章解决一个具体问题：红色 LED 正在按固定节奏闪烁时，按下 `K1` 仍能及时翻转绿色 LED。先用轮询实现，再观察 `HAL_Delay()` 造成的漏检，最后把 `PB12` 配置为 `GPIO_EXTI12`，让 GPIO 边沿通过 `EXTI`、`NVIC` 和 HAL 回调通知 CPU。

课程实验使用 `PB0` 驱动红色 LED、`PA7` 驱动绿色 LED、`PB12` 作为 `K1` 输入。两集课程共用下面这条信号链：

```text
K1 电平变化
-> GPIO 输入驱动器
-> EXTI12 边沿检测
-> PR 挂起位 / IMR 屏蔽
-> NVIC 仲裁
-> EXTI15_10_IRQHandler()
-> HAL_GPIO_EXTI_IRQHandler()
-> HAL_GPIO_EXTI_Callback()
-> 翻转绿色 LED 或发布按键事件
```

| 工程 | 目标 | 主要资源与核心机制 |
| --- | --- | --- |
| 轮询版本 | 红灯周期闪烁，按键控制绿灯 | `HAL_GPIO_ReadPin()`、`HAL_Delay()` |
| EXTI 版本 | 红灯继续闪烁，按下 `K1` 立即翻转绿灯 | `GPIO_EXTI12`、`EXTI15_10_IRQn`、HAL 回调 |

## 1. 核心概念

### 1.1 为什么需要中断

中断（Interrupt）是 CPU 暂停当前程序、处理突发事件、再返回原执行位置的机制。主循环可以继续做周期性任务，按键、串口接收、定时器溢出等异步事件则在真正发生时主动请求 CPU 处理。

```text
主程序运行 -> 事件发生 -> 保存现场并暂停 -> 执行 ISR -> 恢复现场并返回
```

中断解决的是“检测时机”问题，而不是让所有任务都变快。中断服务函数（ISR，Interrupt Service Routine）执行时间越长，对主循环和其他中断的影响越大。

### 1.2 轮询为什么会漏检按键

轮询把判断写在主循环中：

```c
while (1)
{
    if (HAL_GPIO_ReadPin(GPIOB, GPIO_PIN_12) == GPIO_PIN_RESET)
    {
        HAL_GPIO_TogglePin(GPIOA, GPIO_PIN_7);
        while (HAL_GPIO_ReadPin(GPIOB, GPIO_PIN_12) == GPIO_PIN_RESET)
        {
            /* 等待松手 */
        }
    }
}
```

如果主循环还要让红灯亮 `2 s`、灭 `2 s`，按键判断每隔约 `4 s` 才执行一次，而且判断本身很短。按键在两个判断点之间发生并释放，程序就完全看不到这次变化；这就是课程中“按键大概率失效”的原因。

轮询适合持续、可预测、检查成本很低的状态；异步且持续时间短的事件更适合用中断记录下来。

### 1.3 外部中断与普通中断的范围

外部中断（External Interrupt）是由 GPIO 等芯片外部信号引起的中断。STM32 还可以由定时器、USART、SPI、ADC、DMA 等外设产生中断。它们最终都要经过 NVIC，但触发源和状态寄存器不同。

`EXTI` 是外部中断/事件控制器（External Interrupt/Event Controller），不是 STM32 全部中断的总称；`NVIC` 是内核中的嵌套向量中断控制器，负责统一使能、仲裁和分发。

## 2. EXTI 与 NVIC 的工作机制

### 2.1 GPIO 信号如何进入 EXTI

以课程中的 `PB12` 为例，GPIO 输入驱动器先把引脚电压转换成高、低电平逻辑值。该逻辑值同时送往输入数据寄存器和 EXTI 的边沿检测电路。

STM32F1 的 GPIO 相关 EXTI 线为 `EXTI0`～`EXTI15`。线号由引脚编号决定，而不是由端口字母决定：

```text
PA0、PB0、PC0、... -> EXTI0（同一时刻只能选一个端口）
PA1、PB1、PC1、... -> EXTI1
...
PA15、PB15、PC15、... -> EXTI15
```

因此 `PA0` 与 `PB0` 竞争 `EXTI0`，不能同时作为两个独立的 EXTI0 来源；`PA0` 与 `PB1` 则分别占用 `EXTI0` 和 `EXTI1`。F1 还存在 `EXTI16`～`EXTI18` 等内部信号线路，具体数量和连接关系以目标芯片参考手册为准。

### 2.2 端口映射、边沿与事件路径

F1 通过 AFIO 的 EXTICR 选择器把某一端口接到 `EXTI0`～`EXTI15` 中的对应线路。CubeMX 在生成 `MX_GPIO_Init()` 时完成这项映射，HAL 用户通常不需要直接调用标准库中的 `GPIO_EXTILineConfig()`。

边沿检测由两个选择位控制：

- 上升沿（Rising）：低电平变为高电平；
- 下降沿（Falling）：高电平变为低电平；
- 双边沿（Rising/Falling）：两种转换都触发。

EXTI 同时提供中断路径和事件路径。中断路径把请求送往 NVIC，CPU 最终执行 IRQHandler；事件路径只产生硬件事件，可用于唤醒或触发其他外设，本章只使用中断路径。

### 2.3 PR、IMR 与软件触发

把 EXTI 线路理解为一条“带记忆的通知线”即可：

1. 边沿检测电路发现满足配置的转换；
2. 对应请求挂起寄存器 `PR`（Pending Register）位置 1，记录事件已经发生；
3. 中断屏蔽寄存器 `IMR`（Interrupt Mask Register）决定该请求能否继续送往 NVIC；
4. 处理结束时清除 `PR`，避免返回后因旧标志再次进入中断。

EXTI 还有软件中断事件寄存器 `SWIER`，可以由程序主动置位来模拟触发。它用于测试或特殊唤醒场景，课程实验不需要使用。

在 STM32F1 中，清除挂起位通常是向 `PR` 对应位写 `1`。HAL 的 `HAL_GPIO_EXTI_IRQHandler()` 已经封装了检查和清除操作，用户不应再用普通写 0 的方式“清除”它。

### 2.4 NVIC 与中断向量表

NVIC（Nested Vectored Interrupt Controller）是 Cortex-M 内核外设，主要负责：

- 使能或禁止中断；
- 保存挂起状态并进行优先级仲裁；
- 允许更高抢占优先级的中断嵌套；
- 按中断号查找中断向量表，跳转到对应 IRQHandler。

中断向量表可以看成“中断号到入口地址的目录”。IRQHandler 不是主程序主动调用的普通函数，函数名必须与启动文件中的向量名称完全一致，否则硬件会落到默认处理函数。

EXTI 线路与 IRQHandler 的对应关系如下：

| EXTI 线路 | NVIC 通道 | 入口函数 |
| --- | --- | --- |
| `EXTI0`～`EXTI4` | `EXTI0_IRQn`～`EXTI4_IRQn` | `EXTI0_IRQHandler()`～`EXTI4_IRQHandler()` |
| `EXTI5`～`EXTI9` | `EXTI9_5_IRQn` | `EXTI9_5_IRQHandler()` |
| `EXTI10`～`EXTI15` | `EXTI15_10_IRQn` | `EXTI15_10_IRQHandler()` |

课程使用 `PB12`，所以它经过 `EXTI12` 后进入共享入口 `EXTI15_10_IRQHandler()`。

### 2.5 HAL 的三层中断入口

HAL 工程把硬件入口和用户逻辑分成三层：

```text
EXTI15_10_IRQHandler()
-> HAL_GPIO_EXTI_IRQHandler(GPIO_PIN_12)
-> HAL_GPIO_EXTI_Callback(GPIO_PIN_12)
```

第一层由启动文件和 CubeMX 生成；第二层检查指定引脚的 EXTI 挂起位、清除它并调用回调；第三层是用户实现的弱回调覆盖函数。多个引脚共用一个 IRQHandler 时，生成代码可以依次调用多个 `HAL_GPIO_EXTI_IRQHandler(GPIO_PIN_x)`，回调必须通过 `GPIO_Pin` 参数分流。

## 3. NVIC 优先级与 HAL 时基

### 3.1 抢占优先级和响应优先级

STM32F1 的中断优先级字段实际使用 4 位，数值范围为 `0`～`15`，数值越小表示优先级越高。HAL/Cortex-M 将这 4 位按优先级分组拆成两部分：

- 抢占优先级（Preemption Priority）：决定一个中断能否打断正在执行的另一个中断；
- 响应优先级，也称子优先级（Subpriority）：当多个中断同时挂起且抢占优先级相同，用于决定先处理谁。

两种场景的判断顺序不同：

```text
多个中断同时挂起：先比抢占优先级，再比响应优先级
当前 ISR 执行时来了新中断：只看新中断能否抢占当前 ISR
```

优先级相同且没有其他配置可区分时，硬件按中断号等固定规则决定先后，不应依赖这种顺序实现业务逻辑。

### 3.2 优先级分组

优先级分组决定 4 位在两种优先级之间如何切分。常见含义如下（具体宏名以 HAL 头文件为准）：

| 抢占位数 | 响应位数 | 能表达的范围 |
| ---: | ---: | --- |
| 0 | 4 | 只能排队，不能嵌套 |
| 1 | 3 | 少量嵌套，较细排队 |
| 2 | 2 | 折中 |
| 3 | 1 | 较多嵌套 |
| 4 | 0 | 只使用抢占优先级 |

CubeMX/HAL 工程常使用 `NVIC_PRIORITYGROUP_4`，此时 4 位都用于抢占优先级，响应优先级通常固定为 `0`。一个工程应统一优先级分组，不能让不同模块各自修改全局分组。

对应的 HAL 接口为：

```c
HAL_NVIC_SetPriorityGrouping(NVIC_PRIORITYGROUP_4);
HAL_NVIC_SetPriority(EXTI15_10_IRQn, 1, 0);
HAL_NVIC_EnableIRQ(EXTI15_10_IRQn);
```

`HAL_NVIC_SetPriority()` 的第二、第三个参数分别是抢占优先级和响应优先级。在 `NVIC_PRIORITYGROUP_4` 下，第三个参数没有可用位，通常写 `0`。`HAL_Init()` 通常已经建立全局分组，CubeMX 再根据图形化配置生成具体中断的优先级与使能调用；不要在多个模块中重复修改全局分组。

### 3.3 为什么 `HAL_Delay()` 不能随便放进 ISR

`HAL_Delay()` 依赖 `SysTick` 中断维护的 HAL Tick。若 EXTI ISR 的抢占优先级高于 `SysTick`，ISR 执行期间 `SysTick` 无法抢占，Tick 不再增加，`HAL_Delay()` 的等待条件永远无法满足：

```text
EXTI ISR -> HAL_Delay(10)
         -> 等待 HAL Tick 增加
         -> SysTick 被更高优先级的 EXTI ISR 挡住
         -> 时间不前进，程序卡在 ISR 中
```

课程通过把 `SysTick` 的优先级数字设得比 `EXTI15_10` 更小来验证这个问题。这能解释实验现象，但工程上更稳妥的做法是 ISR 不延时、不等待，使用标志、时间戳或定时器在主循环中完成消抖和业务处理。

## 4. HAL 配置链

从按键引脚到用户回调，需要依次打通：

```text
RCC 开启 GPIO/AFIO 时钟
-> GPIO 配置为下降沿中断输入并选择上下拉
-> HAL_GPIO_Init() 完成 GPIO 与 EXTI 映射
-> HAL_NVIC_SetPriority() / HAL_NVIC_EnableIRQ()
-> EXTI15_10_IRQHandler()
-> HAL_GPIO_EXTI_IRQHandler()
-> HAL_GPIO_EXTI_Callback()
```

在 CubeMX 工程中，GPIO、AFIO 映射和 EXTI/NVIC 初始化通常集中在 `MX_GPIO_Init()`，入口函数位于 `stm32f1xx_it.c`，用户逻辑放在回调或独立模块中。STM32F1 的 EXTI 本身没有单独的 RCC 时钟开关，但 GPIO 端口和负责映射的 AFIO 必须有时钟。寄存器结构、HAL 初始化函数和应用层处理应保持分层，排错时再沿链路逐级检查。

### 4.1 CubeMX 引脚与触发配置

课程板卡的按键松开时为高电平、按下时为低电平，因此按下瞬间是下降沿。配置步骤为：

| 步骤 | CubeMX 操作 | 目的与错误现象 |
| --- | --- | --- |
| 1 | `PB0`、`PA7` 设为 `GPIO_Output` | 让两个 LED 由 GPIO 控制；模式错会无输出或电平不稳定 |
| 2 | `PB12` 设为 `GPIO_EXTI12` | 让引脚进入 EXTI12 路径；仍为普通输入则不会产生 EXTI 请求 |
| 3 | 选择 `Falling edge` | 匹配按下时高到低的变化；边沿选反会表现为按下无响应 |
| 4 | 按原理图设置 `Pull-up/Pull-down` | 保证松开时有确定电平；悬空会误触发 |
| 5 | 在 `NVIC Settings` 勾选 `EXTI line[15:10] interrupts` | 允许 EXTI12 请求进入 NVIC；漏勾则 PR 可能置位但 CPU 不进 IRQHandler |
| 6 | 保存并生成代码 | 生成 GPIO、EXTI、NVIC 初始化和 IRQHandler 框架 |

如果按键电路已经有外部上拉，内部 `Pull` 可按原理图选择 `No pull`；不要在不了解外部电路时盲目叠加上下拉。

### 4.2 生成代码中的关键配置

不同 CubeMX 版本生成代码的排版可能不同，但关键配置可以抽象为：

```c
/* GPIOB、GPIOA、AFIO 时钟由 MX_GPIO_Init() 开启 */
GPIO_InitTypeDef GPIO_InitStruct = {0};

GPIO_InitStruct.Pin = GPIO_PIN_12;
GPIO_InitStruct.Mode = GPIO_MODE_IT_FALLING;
GPIO_InitStruct.Pull = GPIO_PULLUP;       /* 按原理图调整 */
HAL_GPIO_Init(GPIOB, &GPIO_InitStruct);

HAL_NVIC_SetPriority(EXTI15_10_IRQn, 1, 0);
HAL_NVIC_EnableIRQ(EXTI15_10_IRQn);
```

`GPIO_MODE_IT_RISING`、`GPIO_MODE_IT_FALLING` 和 `GPIO_MODE_IT_RISING_FALLING` 分别对应上升沿、下降沿和双边沿触发。F1 的 EXTI 映射由 HAL 在 GPIO 初始化时写入 AFIO 配置寄存器；用户不需要再写一套标准库的 `GPIO_EXTILineConfig()`。

### 4.3 IRQHandler 与回调代码

CubeMX 通常在 `stm32f1xx_it.c` 中生成入口：

```c
void EXTI15_10_IRQHandler(void)
{
    HAL_GPIO_EXTI_IRQHandler(GPIO_PIN_12);
}
```

HAL 随后调用用户回调。回调可以放在 `main.c` 或独立用户模块中：

```c
void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin)
{
    if (GPIO_Pin == GPIO_PIN_12)
    {
        /* PB12 触发后的用户逻辑 */
    }
}
```

不要在重新生成代码后把用户逻辑写在生成区域之外；使用 `USER CODE BEGIN/END` 区域或独立源文件，避免 CubeMX 覆盖代码。若同一共享向量下有多个 EXTI 引脚，应在入口中为每个引脚调用 HAL 处理函数，并在回调里逐一判断 `GPIO_Pin`。

## 5. 实验一：按键 EXTI 翻转绿色 LED

### 5.1 目标、接线与现象

目标是让红色 LED 按“亮 `2 s`、灭 `2 s`”循环，按下 `K1` 时绿色 LED 立即翻转，而且按键发生在红灯延时期间也不能被漏掉。

课程板卡的逻辑资源为：

| 器件 | 引脚 | 说明 |
| --- | --- | --- |
| 红色 LED | `PB0` | 输出，以下示例假设高电平点亮 |
| 绿色 LED | `PA7` | 输出，`HAL_GPIO_TogglePin()` 翻转状态 |
| `K1` | `PB12` | `GPIO_EXTI12`，按下为低电平 |

若实际板卡 LED 为低电平有效，只需交换红灯初始输出的 `GPIO_PIN_SET/RESET`，绿色 LED 的翻转调用不需要改变。

### 5.2 先看轮询版本为什么失败

轮询版本通常把红灯延时和按键读取放在同一个 `while` 中。两次 `HAL_Delay(2000)` 之间，按键只被检查一次，因此短按可能完全错过。这个失败版本的价值在于说明：问题来自检测路径被阻塞，而不是按键硬件一定损坏。

### 5.3 EXTI 版本的最小回调

按课程目标，收到 `PB12` 的有效边沿后直接翻转绿灯：

```c
void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin)
{
    if (GPIO_Pin == GPIO_PIN_12)
    {
        HAL_GPIO_TogglePin(GPIOA, GPIO_PIN_7);
    }
}
```

这里不需要在回调中再次清除 EXTI 挂起位，`HAL_GPIO_EXTI_IRQHandler()` 已经完成清除。也不要把回调当成普通函数在主循环中手动调用；它由 HAL 中断处理流程进入。

### 5.4 主程序与红灯数据流

```c
int main(void)
{
    HAL_Init();
    SystemClock_Config();
    MX_GPIO_Init();

    while (1)
    {
        HAL_GPIO_WritePin(GPIOB, GPIO_PIN_0, GPIO_PIN_SET);
        HAL_Delay(2000);

        HAL_GPIO_WritePin(GPIOB, GPIO_PIN_0, GPIO_PIN_RESET);
        HAL_Delay(2000);
    }
}
```

主循环只负责红灯节奏；按键边沿在任意时刻进入 EXTI ISR，回调翻转绿灯，然后 CPU 返回原来的 `HAL_Delay()` 或主循环位置。绿色 LED 的响应不再依赖主循环刚好执行到某一行。

### 5.5 课程中的软件消抖与优先级陷阱

机械按键按下、抬起时会产生抖动，抖动也可能包含下降沿，于是一次操作可能多次进入回调。课程尝试在中断处理函数中先 `HAL_Delay(10)`，再读取 `PB12` 确认仍为低电平；但如果 `SysTick` 不能在该 EXTI ISR 期间运行，程序会卡在 `HAL_Delay()`。

要理解这个现象，需要同时检查两项：

1. `HAL_Delay()` 的 Tick 是否由 `SysTick` 持续递增；
2. `SysTick` 的抢占优先级是否高于当前 `EXTI15_10` ISR。

课程用 CubeMX 把 `SysTick` 的优先级数字调得比 `EXTI15_10` 小，验证了优先级对时基的影响。这只是演示优先级关系，仍不推荐在 GPIO 中断里延时。

## 6. 工程写法与适用边界

### 6.1 回调只发布事件

正式工程中，回调更适合只记录事件，把 LED 控制和消抖放回主循环或定时任务：

```c
static volatile uint8_t key_event;

void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin)
{
    if (GPIO_Pin == GPIO_PIN_12)
    {
        key_event = 1;
    }
}

int main(void)
{
    HAL_Init();
    SystemClock_Config();
    MX_GPIO_Init();

    while (1)
    {
        if (key_event != 0U)
        {
            key_event = 0U;
            HAL_GPIO_TogglePin(GPIOA, GPIO_PIN_7);
        }
        /* 其他主循环任务 */
    }
}
```

`key_event` 同时由主程序和中断访问，因此使用 `volatile`。`volatile` 只保证每次读写都从内存取值，不保证“读取并清零”等多步操作的原子性；高速或不可丢失的事件应改用计数器、环形缓冲区或临界区。

### 6.2 消抖不要阻塞 ISR

可以在回调中记录 `HAL_GetTick()` 时间戳，只有距上次接受事件超过约 `10~20 ms` 才置位一次事件：

```c
static volatile uint8_t key_event;
static volatile uint32_t key_last_tick;

void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin)
{
    if (GPIO_Pin == GPIO_PIN_12)
    {
        uint32_t now = HAL_GetTick();
        if ((uint32_t)(now - key_last_tick) >= 20U)
        {
            key_last_tick = now;
            key_event = 1U;
        }
    }
}
```

这段代码不等待、不调用 `HAL_Delay()`，利用无符号减法自然处理 Tick 回绕。对要求更高的按键，应由定时器周期采样并确认连续稳定电平；对高速脉冲，EXTI 回调不应承担复杂滤波或计数之外的业务。

### 6.3 什么时候不该使用 EXTI 按键

EXTI 适合短促、异步、需要及时记录的边沿，例如脉冲输入或唤醒信号。机械按键通常需要消抖、长按和连发判断；如果系统任务不多，主循环周期采样往往更简单、更可靠。不要为了“响应快”把所有输入都改成 EXTI。

## 7. 验收与排错

### 7.1 正常现象

- 上电后红色 LED 按约 `2 s` 亮、`2 s` 灭的节奏循环；
- 在红灯亮或灭的等待期间按下 `K1`，绿色 LED 仍能翻转；
- 松开按键不会因为普通单次操作而必然翻转，若出现多次翻转通常与机械抖动或双边沿配置有关。

### 7.2 沿信号链定位故障

```text
供电/共地/按键电平
-> PB12 GPIO 模式与上下拉
-> EXTI12 触发边沿
-> PR 是否置位、IMR 是否放行
-> NVIC EXTI15_10 是否使能
-> EXTI15_10_IRQHandler() 是否进入
-> HAL_GPIO_EXTI_IRQHandler() 是否传入 GPIO_PIN_12
-> HAL_GPIO_EXTI_Callback() 是否按引脚分流
-> PA7 输出有效电平是否正确
```

对应症状可优先检查：

| 症状 | 优先检查 |
| --- | --- |
| 按键完全无响应 | `PB12` 是否为 `GPIO_EXTI12`、下降沿是否匹配、`EXTI15_10` NVIC 是否勾选 |
| 只能松开时响应 | 实际有效边沿与触发选项是否相反 |
| 一次按键翻转多次 | 机械抖动、双边沿配置、回调是否重复处理 |
| 进了 IRQHandler 但回调不执行 | 是否调用 `HAL_GPIO_EXTI_IRQHandler(GPIO_PIN_12)`，回调参数是否为 `GPIO_PIN_12` |
| 按键后红灯停止、程序像死机 | ISR 中是否调用 `HAL_Delay()`；检查 `SysTick` 优先级和 HAL Tick |
| 绿灯电平相反 | 板载 LED 是否低电平有效，核对 `PA7` 接线和电路有效电平 |

如果 `PB12`、`PB13` 等多条线路共用 `EXTI15_10`，应在同一个 IRQHandler 中分别调用 HAL 处理函数，并在回调中根据 `GPIO_Pin` 分流；一个工程不能为同名 IRQHandler 提供多个定义。

## 本章小结

轮询的检测时机由主循环位置决定，长时间 `HAL_Delay()` 会让短按事件被漏掉。EXTI 把 GPIO 边沿转换为挂起请求，NVIC 再依据使能和优先级选择中断向量，HAL 通过 `IRQHandler -> HAL_GPIO_EXTI_IRQHandler() -> HAL_GPIO_EXTI_Callback()` 把硬件事件交给用户代码。

配置外部中断时，应按 **GPIO 模式与上下拉 -> EXTI 触发边沿 -> NVIC 使能与优先级 -> HAL 回调** 的顺序检查。课程示例证明了中断能在红灯延时期间及时响应按键；工程实现则应让 ISR 快速完成事件交接，把消抖、显示和其他耗时逻辑留给主循环或定时任务。
