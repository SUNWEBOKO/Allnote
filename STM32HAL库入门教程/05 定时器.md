# STM32F103 定时器、PWM 与电机控制教学文档

## 本章闭环

```text
定时器计数器 -> 预分频/自动重装 -> 更新事件
             -> PWM 输出 / 输入捕获 / 从模式 / 外部时钟
             -> 编码器计数 / 超声波测距 / 传送带测速 / TB6612 电机控制
```

默认目标芯片为 STM32F103C8T6，常见系统时钟为 `72 MHz`。不同封装的定时器和引脚数量可能不同，最终以芯片数据手册和 CubeMX 实际可选资源为准。

## 1. 学习目标与准备

完成本章后，应能够：

- 用 `PSC`、`ARR`、`CNT` 计算定时器频率和周期；
- 用 PWM 控制 LED、舵机和 TB6612 电机；
- 用输入捕获测量脉宽、周期和超声波回波时间；
- 解释复位、门控、触发开始等从模式；
- 用外部时钟模式统计光电传感器脉冲；
- 用编码器模式读取 AB 相增量编码器；
- 计算传送带距离、速度，并处理计数器回绕；
- 使用 TB6612 驱动库的滑行、刹车、正反转与有符号速度接口。

准备：STM32F103C8T6 开发板、ST-LINK、CubeMX、Keil MDK、示波器或逻辑分析仪（可选）、SG90 类舵机、增量式旋转编码器、超声波模块、光电/循迹传感器、TB6612FNG 模块和带编码器的直流电机。

## 2. 定时器的本质：计数器

### 2.1 计数链

定时器不是只能“等待一段时间”的闹钟，而是一组由时钟驱动的计数逻辑：

```text
定时器时钟 -> 预分频器 PSC -> CNT 计数器 -> 比较/自动重装载 -> 事件或输出
```

计数器每收到一个有效计数脉冲，就按计数方向加一或减一。计数到 `ARR` 后产生更新事件，向上计数时通常重新从 `0` 开始。

### 2.2 STM32F1 定时器分类

STM32F1 家族可能包含基本、通用和高级定时器。STM32F103C8T6 常见资源主要是 `TIM1`、`TIM2`、`TIM3`、`TIM4`：

| 类型 | 代表 | 主要能力 |
| --- | --- | --- |
| 高级定时器 | `TIM1` | 通用功能外，还支持互补输出、刹车等电机控制能力 |
| 通用定时器 | `TIM2~TIM4` | 基础定时、PWM、输入捕获、外部时钟、编码器和从模式 |
| 基本定时器 | 某些更高资源型号的 `TIM6/TIM7` | 主要用于基础定时和触发 DAC 等 |

在 F103C8T6 上，即使没有基本定时器，也可把通用定时器当作普通定时器使用。

### 2.3 定时器时钟来源

定时器时钟来自 APB1 或 APB2。常用 `72 MHz` 配置下，若 APB1 分频为 `2`，则 `PCLK1=36 MHz`，但 APB1 定时器时钟通常自动乘二，得到 `TIM2~TIM4` 的 `72 MHz` 输入。计算前必须先确认定时器挂在哪条总线以及 APB 分频系数。

## 3. PSC、ARR、CNT 与时间计算

### 3.1 预分频器 `PSC`

预分频器寄存器写入值为 `PSC` 时，实际分频系数是 `PSC+1`。例如：

- `PSC=0`：不分频；
- `PSC=1`：二分频；
- `PSC=7199`：七千二百分频。

定时器计数频率为：

$$f_{CNT}=\frac{f_{TIM}}{PSC+1}$$

### 3.2 自动重装载寄存器 `ARR`

向上计数时，`CNT` 从 `0` 数到 `ARR`，共有 `ARR+1` 个计数状态，因此更新频率为：

$$f_{update}=\frac{f_{TIM}}{(PSC+1)(ARR+1)}$$

周期为：

$$T_{update}=\frac{(PSC+1)(ARR+1)}{f_{TIM}}$$

### 3.3 示例：1 秒更新中断

假设 `f_TIM=72 MHz`，希望每秒触发一次更新事件：

1. 先选 `PSC=7199`，得到 `f_CNT=10 kHz`；
2. 需要计数 `10000` 次，因此 `ARR=9999`；
3. 周期为 `10000 / 10000 = 1 s`。

```c
htim4.Instance = TIM4;
htim4.Init.Prescaler = 7199U;
htim4.Init.CounterMode = TIM_COUNTERMODE_UP;
htim4.Init.Period = 9999U;
/* 72 MHz / 7200 / 10000 = 1 Hz 更新事件。 */
```

若开启更新中断，还需要在 NVIC 中启用对应 IRQ，并调用：

```c
if (HAL_TIM_Base_Start_IT(&htim4) != HAL_OK)
{
    Error_Handler();
}

void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim)
{
    if (htim->Instance == TIM4)
    {
        /* 每秒执行一次的任务。 */
    }
}
```

空 `for` 循环不能替代定时器定时，因为编译优化、流水线和主频变化都会改变其时间。

## 4. PWM：把计数器变成可调占空比波形

### 4.1 PWM mode 1 的工作规律

在边沿对齐、向上计数、有效高电平的 PWM mode 1 中，计数器小于 `CCR` 时输出有效电平，达到比较值后输出无效电平。理想情况下：

$$D \approx \frac{CCR}{ARR+1}$$

其中 `D` 是占空比。严格的 100% 占空比要注意 `CCR=ARR+1` 可能超出比较寄存器范围，工程中通常采用接近满占空比或使用芯片允许的特殊处理。

### 4.2 CubeMX 配置

1. 打开目标定时器，例如 `TIM3`；
2. `Clock Source` 选择 `Internal Clock`；
3. 目标通道选择 `PWM Generation CHx`；
4. 选择 `PWM mode 1`、向上计数、有效高电平；
5. 计算 `PSC/ARR`，让频率满足负载要求；
6. 生成代码后调用 `HAL_TIM_PWM_Start()`。

```c
HAL_TIM_PWM_Start(&htim3, TIM_CHANNEL_1);
/* CCR 决定有效电平持续时间，ARR 决定 PWM 周期。 */
__HAL_TIM_SET_COMPARE(&htim3, TIM_CHANNEL_1, 1800U);
```

### 4.3 示例：20 kHz 电机 PWM

若 `TIM3CLK=72 MHz`，设置 `PSC=0`、`ARR=3599`：

$$f_{PWM}=\frac{72\,\text{MHz}}{(0+1)(3599+1)}=20\,\text{kHz}$$

`CCR=1800` 约对应 50% 占空比。电机转速不等于占空比，负载和供电变化会导致相同占空比对应不同转速。

### 4.4 PWM 调试顺序

先用示波器确认引脚有正确频率和占空比，再接入舵机或电机。若没有波形，依次检查：定时器时钟、通道 GPIO 复用、`HAL_TIM_PWM_Start()`、比较寄存器、引脚冲突和共地。

## 5. 实验一：PWM 控制 LED 呼吸灯

### 5.1 目标

让 LED 的占空比缓慢增加和减少，观察平均亮度变化。这个实验只用于理解 PWM，不要求人眼看到真实线性亮度。

### 5.2 代码

```c
HAL_TIM_PWM_Start(&htim3, TIM_CHANNEL_1);

while (1)
{
    for (uint32_t ccr = 0U; ccr <= 3599U; ccr += 10U)
    {
        __HAL_TIM_SET_COMPARE(&htim3, TIM_CHANNEL_1, ccr);
        HAL_Delay(5U);
    }
    for (int32_t ccr = 3599; ccr >= 0; ccr -= 10)
    {
        __HAL_TIM_SET_COMPARE(&htim3, TIM_CHANNEL_1, (uint32_t)ccr);
        HAL_Delay(5U);
    }
}
```

### 5.3 现象与边界

占空比提高时，LED 平均电流通常增大，亮度提高；但人眼感知近似对数关系，亮度不一定随 `CCR` 线性增加。LED 必须串限流电阻，不能直接由 MCU 引脚承担过大电流。

## 6. 实验二：PWM 控制舵机

### 6.1 舵机信号

常见 180° 舵机使用约 `50 Hz`、周期 `20 ms` 的控制脉冲。许多 SG90 类舵机可用约 `500~2500 µs` 的高电平宽度对应 `0~180°`，但具体范围必须以手中舵机规格书为准。

以 `PSC=719`、`ARR=1999`、定时器时钟 `72 MHz` 为例：

$$f_{PWM}=\frac{72\,\text{MHz}}{(719+1)(1999+1)}=50\,\text{Hz}$$

此时计数分辨率为 `10 kHz`，每个计数约 `100 µs`，不够细。更适合的配置是让计数频率为 `1 MHz`：`PSC=71`，再令 `ARR=19999`，则一个计数对应 `1 µs`。

### 6.2 角度映射

若规格书给出 `500~2500 µs` 对应 `0~180°`，可用线性映射：

$$pulse(\theta)=500+\frac{2000\theta}{180}\ \mu s$$

```c
static uint16_t Servo_AngleToPulse(uint16_t angle)
{
    if (angle > 180U) angle = 180U;
    return (uint16_t)(500U + (2000U * angle) / 180U);
}

HAL_TIM_PWM_Start(&htim4, TIM_CHANNEL_3);
__HAL_TIM_SET_COMPARE(&htim4, TIM_CHANNEL_3,
                      Servo_AngleToPulse(90U));
```

### 6.3 电源与现象

舵机启动和堵转时电流较大，不应把电机电流直接从 MCU 3.3 V 稳压输出中抽取。舵机电源、STM32 地和 PWM 信号地必须建立正确参考；供电压降会造成复位、抖动或角度异常。

## 7. 输入捕获：测量时间而不是主动输出

### 7.1 捕获原理

输入捕获把某个输入边沿到来时的 `CNT` 值锁存到 `CCR`。两次捕获值之差就是输入信号经历的计数时间。

若计数频率为 `1 MHz`，则每个计数为 `1 µs`：

$$t=(capture_2-capture_1)\times1\,\mu s$$

若计数器发生回绕，应使用无符号模差：

```c
uint32_t delta = (uint32_t)(capture2 - capture1);
```

只要单次真实间隔小于计数器模数对应的时间，模差仍能得到正确结果。

### 7.2 输入捕获配置

1. 选择 `Input Capture direct mode`；
2. 配置捕获边沿；
3. 设置输入滤波和分频，抑制毛刺；
4. 开启捕获中断；
5. 启动 `HAL_TIM_IC_Start_IT()`；
6. 在 `HAL_TIM_IC_CaptureCallback()` 中读取 `HAL_TIM_ReadCapturedValue()`。

### 7.3 超声波测距

HC-SR04 类模块通常需要给 `TRIG` 一个约 `10 µs` 高脉冲，然后测量 `ECHO` 高电平宽度。若声速取 `340 m/s`，距离为：

$$d=\frac{t\times340}{2}$$

当 `t` 用微秒表示、`d` 希望得到厘米时，可近似为：

$$d_{cm}\approx\frac{t_{\mu s}}{58}$$

```c
HAL_GPIO_WritePin(TRIG_GPIO_Port, TRIG_Pin, GPIO_PIN_SET);
delay_us(10U); /* 应使用定时器/DWT 等可靠微秒延时。 */
HAL_GPIO_WritePin(TRIG_GPIO_Port, TRIG_Pin, GPIO_PIN_RESET);

/* 在捕获回调中得到 echo_us 后： */
uint32_t distance_cm = echo_us / 58U;
```

空 `for` 延时只能做演示，不能作为可靠的微秒级测量基准。输入捕获必须处理超时，否则没有回波时程序可能一直等待。

## 8. 从模式：让触发信号参与控制定时器

从模式控制器位于定时器内部，能够根据触发输入决定计数器的开始、停止、复位或门控。常见模式包括：

| 从模式 | 行为 |
| --- | --- |
| 复位模式 | 触发边沿到来时把 CNT 清零并重新计数 |
| 门模式 | 触发输入有效时允许计数，无效时暂停 |
| 触发开始模式 | 检测到触发后开始计数 |
| 外部时钟模式 1 | 使用选定触发输入作为计数时钟 |
| 外部时钟模式 2 | 使用 ETR 作为外部计数时钟 |

### 8.1 复位模式示例

周期性输入脉冲到来时复位 `CNT`，可用来测量相邻事件之间的时间。触发边沿还可能置位触发中断标志，不能把所有更新事件都误认为 ARR 溢出。

### 8.2 门模式示例

将光电开关接到触发输入：高电平时计数器运行，低电平时暂停。门控边沿可以触发标志，但门模式本身不会因为边沿自动清零 CNT。

## 9. 外部时钟与传送带测速

### 9.1 外部时钟模式 2

在外部时钟模式 2 中，`ETR` 经过极性、滤波和外部触发预分频后，直接作为定时器计数时钟。CubeMX 选择 `External Clock Mode 2` 后，具体可用引脚由芯片映射决定。

每来一个有效边沿，`CNT` 加一。与 CPU 在 GPIO 中断里手动累加相比，定时器硬件计数不会为每个脉冲进入软件中断，更适合频率较高的传感器。

### 9.2 传送带距离

假设传送带每经过一条黑白边界产生一个脉冲，编码器或条纹间距为 `s`，则：

$$distance = count\times s$$

必须明确“每个脉冲代表一条边界、半个周期还是完整周期”，否则距离会差一倍。

### 9.3 传送带速度

固定采样窗口 `\Delta t` 内读取计数增量 `\Delta N`：

$$v=\frac{\Delta N\times s}{\Delta t}$$

```c
uint16_t now = __HAL_TIM_GET_COUNTER(&htim2);
uint16_t delta = (uint16_t)(now - last);
last = now;
speed_mm_s = ((uint32_t)delta * pitch_mm * 1000U) / sample_ms;
```

这里利用 16 位无符号模差处理一次采样窗口内的回绕；采样间隔必须足够短，使真实增量不超过计数器模数。

## 10. 编码器模式：读取 AB 相方向与位移

### 10.1 AB 相原理

增量编码器输出相差约 90° 的 A、B 两路方波。根据某一路边沿发生时另一路的电平，可以判断旋转方向；根据边沿数量可以得到相对位移。

### 10.2 定时器编码器接口

通用/高级定时器可将 `TI1FP1`、`TI2FP2` 送入编码器接口：

1. 将 A 相接通道 1，B 相接通道 2；
2. CubeMX 选择 `Encoder Mode`；
3. 根据机械噪声设置输入滤波；
4. 启动 `HAL_TIM_Encoder_Start()`；
5. 周期性读取 `__HAL_TIM_GET_COUNTER()`。

编码器模式通常同时利用两路边沿，计数倍频与具体模式有关。不要直接把“每转 20 脉冲”当作“计数器每转增加 20”，必须根据编码器规格书、模式和边沿数确定换算系数。

```c
HAL_TIM_Encoder_Start(&htim1, TIM_CHANNEL_ALL);

int16_t encoder_count = (int16_t)__HAL_TIM_GET_COUNTER(&htim1);
```

若要把旋钮限制在 `0~20`：

```c
if (encoder_count < 0) encoder_count = 0;
if (encoder_count > 20) encoder_count = 20;
__HAL_TIM_SET_COUNTER(&htim1, (uint16_t)encoder_count);
```

对于高速电机编码器，不能只在主循环里简单读计数器后强行写回；应根据采样周期和回绕规则计算模差，必要时使用更宽的软件累计量。

## 11. 实验三：旋钮调节 LED 亮度

### 11.1 目标

`TIM1` 编码器模式读取旋钮，`TIM3` PWM 输出驱动 LED。旋转方向改变 `CNT`，`CCR` 跟随变化。

### 11.2 核心代码

```c
HAL_TIM_Encoder_Start(&htim1, TIM_CHANNEL_ALL);
HAL_TIM_PWM_Start(&htim3, TIM_CHANNEL_1);

while (1)
{
    int32_t count = (int32_t)(int16_t)__HAL_TIM_GET_COUNTER(&htim1);
    if (count < 0) count = 0;
    if (count > 100) count = 100;

    uint32_t arr = __HAL_TIM_GET_AUTORELOAD(&htim3);
    uint32_t ccr = ((arr + 1U) * (uint32_t)count) / 100U;
    __HAL_TIM_SET_COMPARE(&htim3, TIM_CHANNEL_1, ccr);
    HAL_Delay(10U);
}
```

### 11.3 方法提示

编码器计数范围、PWM 的 `ARR` 和用户界面的“百分比”是三个不同概念。先把硬件计数归一化到应用范围，再映射到 CCR，不要直接拿任意 CNT 值写入比较寄存器。

## 12. 实验四：使用 TB6612 驱动直流电机

### 12.1 为什么需要电机驱动

直流电机启动电流和堵转电流远高于 MCU GPIO 的承受能力，线圈的电感和反电动势还会产生电压尖峰。STM32 只输出逻辑控制信号，电机电流由 TB6612 的 H 桥和独立电机电源承担。

### 12.2 TB6612 驱动库评价

原库的基础控制逻辑是正确方向，但存在以下工程问题：

- 引脚和 PWM 句柄集中写死，迁移需要改库文件；
- 没有 `STBY` 控制，无法完整表达模块待机状态；
- 速度参数仅为 `0~100`，反转需要调用另一套函数；
- 无返回值，定时器启动失败无法向上层报告；
- 只提供默认全局实例，不支持多个独立电机驱动配置；
- 换向虽先把 PWM 置零，但没有提供有符号速度和统一状态接口。

当前 `TB6612` 驱动库已重写为兼容增强版。新接口使用 `TB6612_Config` 和 `TB6612_Handle`，旧接口仍可继续使用。

### 12.3 TB6612 的状态

| IN1 | IN2 | PWM | 结果 |
| ---: | ---: | ---: | --- |
| 1 | 0 | 高/有效 | 正转 |
| 0 | 1 | 高/有效 | 反转 |
| 0 | 0 | 高/有效 | 停止（通常为滑行/高阻，具体输出状态以器件版本和模块实现为准） |
| 1 | 1 | 高/有效 | 短刹车 |
| 任意 | 任意 | 低 | 停止；不要把 PWM 低电平误写成“短刹车” |
| 任意 | 任意 | `STBY=0` | 待机、高阻 |

开环 PWM 调速不能保证恒速；要实现恒速，应把电机编码器接入另一个定时器的编码器接口，并在固定周期内根据速度误差调节 PWM。

### 12.4 使用旧兼容接口

```c
#include "tb6612.h"

TB6612_Init(ALL);

while (1)
{
    TB6612_Forward(ONLY_A, 40U);
    HAL_Delay(1000U);

    TB6612_Brake(ONLY_A);
    HAL_Delay(200U);

    TB6612_Backward(ONLY_A, 40U);
    HAL_Delay(1000U);

    TB6612_Coast(ONLY_A);
    HAL_Delay(500U);
}
```

### 12.5 推荐的新接口

```c
static const TB6612_Config motor_cfg = {
    TB6612_AIN1_GPIO_Port, TB6612_AIN1_Pin,
    TB6612_AIN2_GPIO_Port, TB6612_AIN2_Pin,
    TB6612_BIN1_GPIO_Port, TB6612_BIN1_Pin,
    TB6612_BIN2_GPIO_Port, TB6612_BIN2_Pin,
    &htim3, TIM_CHANNEL_1,
    &htim3, TIM_CHANNEL_2,
    NULL, 0U, 0U
};

static TB6612_Handle motor;

TB6612_HandleInit(&motor, &motor_cfg, TB6612_MOTOR_BOTH);

while (1)
{
    TB6612_HandleSetSignedSpeed(&motor, TB6612_MOTOR_A, 35);
    HAL_Delay(1000U);
    TB6612_HandleBrake(&motor, TB6612_MOTOR_A);
    HAL_Delay(200U);
    TB6612_HandleSetSignedSpeed(&motor, TB6612_MOTOR_A, -35);
    HAL_Delay(1000U);
    TB6612_HandleCoast(&motor, TB6612_MOTOR_A);
    HAL_Delay(500U);
}
```

`+35` 表示正转 35%，`-35` 表示反转 35%。`0` 的具体行为由驱动库约定：若库把 `0` 映射为 `Coast`，则为滑行；若需要短刹车，应明确调用 `TB6612_HandleBrake()`。若硬件连接了 `STBY`，将 `stby_port`、`stby_pin` 和 `has_stby=1` 填入配置即可。

### 12.6 编码器闭环测速框架

```c
HAL_TIM_Encoder_Start(&htim1, TIM_CHANNEL_ALL);
TB6612_HandleInit(&motor, &motor_cfg, TB6612_MOTOR_A);

uint16_t last_count = 0U;
while (1)
{
    HAL_Delay(100U);
    uint16_t now = (uint16_t)__HAL_TIM_GET_COUNTER(&htim1);
    int16_t delta = (int16_t)(now - last_count);
    last_count = now;

    /* delta / 0.1 s -> 脉冲频率，再根据每转脉冲数换算转速。 */
    int16_t command = /* 根据目标速度和测量速度计算 */ 0;
    TB6612_HandleSetSignedSpeed(&motor, TB6612_MOTOR_A, command);
}
```

这只是控制链骨架。真实闭环还需明确编码器每转计数、减速比、采样周期、方向符号、最大单周期增量和 PID 参数。

## 13. 验收与排错

### 13.1 定时器与 PWM

1. 用公式重新计算 `f_TIM`、`PSC`、`ARR` 和目标频率；
2. 检查 APB1/APB2 定时器时钟是否因分频乘二；
3. 确认通道 GPIO 处于复用推挽，而不是普通 GPIO；
4. 确认调用了正确的 `HAL_TIM_*_Start`；
5. 用示波器检查频率、极性、占空比和是否有毛刺。

### 13.2 输入捕获与超声波

- 没有回波时必须有超时退出；
- 捕获边沿要与状态机匹配，不能只测一个边沿却把它当作完整脉宽；
- 处理计数器回绕时用无符号模差；
- 输入滤波不是万能的，传感器供电和接地同样重要。

### 13.3 编码器与外部时钟

- A/B 相不要接反，否则方向相反；
- 根据编码器模式确认 x1/x2/x4 计数关系；
- 外部时钟模式要确认输入映射到 ETR 或 TIx，不能只看引脚电平；
- 计数器溢出不是错误，错误的是未按采样窗口和模数处理增量。

### 13.4 TB6612 电机

- STM32、TB6612 和电机电源必须共地；
- 电机电源不要直接取自 MCU 稳压输出；
- 检查 `STBY` 是否为高；
- 先低占空比、空载测试，再逐步增加负载；
- 高速运行时不要立即反向，先刹车或降速；
- 电机不转时，分别测量 PWM、IN1/IN2、STBY 和 VM 电源，而不是只看软件变量。

## 14. 综合自测

### 题 1

`TIM3CLK=72 MHz`、`PSC=71`、`ARR=999`，PWM 频率是多少？

**答案**：`72 MHz / (72 × 1000) = 1 kHz`。

### 题 2

为什么 `PSC=7199` 表示 7200 分频而不是 7199 分频？

**答案**：预分频器实际分频系数为 `PSC+1`。

### 题 3

输入捕获两次读数为 `65000` 和 `1000`，如何计算回绕后的增量？

**答案**：使用 16 位无符号模差，`(uint16_t)(1000 - 65000)` 得到正确的回绕增量，前提是实际间隔小于一个计数器周期。

### 题 4

TB6612 中为什么 `IN1=IN2=0` 时要让 PWM 保持高电平才能滑行？

**答案**：该状态对应高阻输出；若 PWM 被拉低，驱动器会进入另一种低电平制动路径，不能得到高阻滑行。

### 题 5

舵机控制信号频率正确但角度仍抖动，优先检查什么？

**答案**：先检查脉宽范围是否符合舵机规格、电源是否有压降、信号地是否共地，再检查机械负载和 PWM 分辨率。

## 本章小结

定时器的核心是“用计数器记录时间或事件”。`PSC` 决定计数速度，`ARR` 决定周期边界，`CCR` 决定比较时刻。由此可以构造：

```text
更新事件 -> 定时中断
比较输出 -> PWM
输入边沿 -> 捕获脉宽/周期
触发输入 -> 从模式控制计数
ETR/TIx   -> 外部脉冲计数
TI1/TI2   -> 增量编码器方向与位移
```

电机系统则在此基础上增加了电气安全边界：STM32 输出控制信号，TB6612 承担功率驱动，编码器提供反馈，定时器负责计数和测速，上层控制器才负责把“目标速度”变成稳定的 PWM 命令。
