# STM32 HAL 库：I2C 基础与软件 I2C 驱动 OLED

> 本章是 I2C 的基础篇。你将先让 OLED 显示出可观察的结果，再回头把屏幕现象对应到 GPIO 电平、I2C 时序和 SSD1306 写事务。下一篇《09 MPU6050》会在本章基础上增加读事务、ACK/NACK 判断和 HAL 硬件 I2C。

## 1. 本章要完成什么

本章使用 STM32F103C8T6 和 0.96 英寸 SSD1306 OLED，不启用 STM32 的硬件 I2C 外设，而是用 PB8、PB9 两个普通 GPIO 产生 I2C 时序。

完成本章后，你应能独立完成下面的闭环：

```text
接线与上拉
    -> CubeMX 配置开漏 GPIO
    -> 软件 I2C 产生 START、地址、数据和 STOP
    -> SSD1306 解释命令/显示数据
    -> OLED 显示字符和变量
    -> 逻辑分析仪验证波形
    -> 根据现象定位故障
```

本章的实验分为三个阶段：

1. **最小实验**：只显示一个字符，确认工程、接线和初始化正确；
2. **显示实验**：显示字符串、数字和递增变量，确认上层驱动可用；
3. **波形实验**：用逻辑分析仪验证一次 OLED 写事务。

### 1.1 前置条件

建议已经掌握：

- 使用 STM32CubeMX 建立 STM32F103 HAL 工程；
- GPIO 输出和 `HAL_GPIO_WritePin()`；
- C 语言数组、位运算和函数调用；
- 编译、下载、复位和使用 CubeMX 用户代码区。

### 1.2 本章边界

本章只实现 OLED 所需的**主机写操作**。课程版代码会产生 ACK 时钟，但不读取 ACK 返回值，因此它适合学习协议和复现显示实验，不是生产级通用 I2C 驱动。

本章暂不实现：

- ACK 错误返回；
- 时钟拉伸等待；
- 总线忙检测和超时；
- SDA 被从机拉低时的总线恢复；
- 多主仲裁、DMA、任务并发保护；
- 连续数据批量事务的性能优化。

> 本章的“显示成功”只证明当前 OLED、接线和课程时序能够完成这组写事务。下一篇会把 ACK 读取和寄存器读事务补完整。

## 2. 实验硬件与接线

### 2.1 硬件清单

- STM32F103C8T6 最小系统板；
- 4 针 I2C 接口的 SSD1306 128×64 OLED；
- ST-Link；
- 杜邦线；
- 可选：逻辑分析仪或示波器。

### 2.2 接线

| OLED | STM32F103C8T6 | 作用 |
| --- | --- | --- |
| `VCC` | `3.3V` | 模块供电 |
| `GND` | `GND` | 共地 |
| `SCL` | `PB8` | 软件 I2C 时钟 |
| `SDA` | `PB9` | 软件 I2C 数据 |

```text
STM32 PB8  ---------------- OLED SCL
STM32 PB9  ---------------- OLED SDA
STM32 3.3V ---------------- OLED VCC
STM32 GND  ---------------- OLED GND
```

本实验中的 PB8、PB9 是普通 GPIO，不是硬件 I2C1 重映射功能。不要在 CubeMX 中同时启用 I2C1 重映射，否则外设和软件驱动会争用同一组引脚。

### 2.3 上电前检查

1. STM32 与 OLED 必须共地；
2. 确认模块供电要求，不要仅凭外观判断可以接 5 V；
3. SCL、SDA 不能接反；
4. 总线空闲时，SCL、SDA 都应接近 3.3 V；
5. 多数 OLED 模块自带上拉电阻，但应以模块原理图或实测为准。

若空闲时某根线始终为低，先断电检查短路、接反、GPIO 初始电平和上拉，不要继续反复下载程序。

## 3. 先完成最小 OLED 实验

这一节先不要求你理解所有协议细节。目标是把工程放置正确、让屏幕显示一个字符，并建立后续排错的基准。

### 3.1 CubeMX 配置

以 STM32F103C8T6、外部 8 MHz 晶振和 72 MHz 系统时钟为例：

1. `System Core -> SYS -> Debug` 选择 `Serial Wire`；
2. `RCC -> High Speed Clock` 选择外部晶振；
3. Clock Configuration 配置系统时钟为 72 MHz；
4. PB8、PB9 配置为 `Output Open Drain`；
5. 输出初值设为 High，Pull 选择 `No pull`，Speed 选择 High；
6. 不启用 I2C1。

| 引脚 | User Label | Mode | Output Level | Pull | Speed |
| --- | --- | --- | --- | --- | --- |
| PB8 | `OLED_SCL` | Output Open Drain | High | No pull | High |
| PB9 | `OLED_SDA` | Output Open Drain | High | No pull | High |

生成代码后，确认 `MX_GPIO_Init()` 中已经使能 GPIOB 时钟，并把 PB8、PB9 初始化为 `GPIO_MODE_OUTPUT_OD`。高电平初值表示释放总线，不是推挽输出 3.3 V。

参考驱动文件位于：

将文件加入你自己的 CubeMX 工程，例如：

## 4. I2C 总线模型

### 4.1 两根信号线

I2C 使用两根共享信号线：

- `SCL`：Serial Clock，串行时钟；
- `SDA`：Serial Data，串行数据。

主机发起通信并产生时钟，从机根据地址决定是否响应。多个从机可以并联在同一组 SCL、SDA 上，因此 I2C 适合板内或短距离的低速外设连接。

I2C 是同步、半双工通信：双方共用时钟；数据只有一根 SDA，同一时刻只能沿一个方向传输。一次事务通常由 START、地址、数据字节、应答和 STOP 组成。

### 4.2 为什么必须使用开漏和上拉

I2C 设备不能主动把总线推成高电平，只能执行两个动作：

- 写 0：引脚主动拉低；
- 写 1：引脚进入高阻态，释放总线。

线路释放后，由外部上拉电阻把它恢复为高电平。只要任意设备拉低，整根线就是低电平；只有所有设备都释放，线路才为高电平。

这让主机可以在发送完 8 位后释放 SDA，由从机在第 9 个时钟拉低 SDA 表示 ACK。若使用推挽输出，主机输出高、从机输出低时可能产生电气冲突。

> CubeMX 中的 `Output Open Drain` 决定输出结构；`No pull` 只表示不启用 STM32 内部弱上下拉。I2C 仍需要外部上拉，常见起点是 4.7 kΩ，但最终要结合模块电阻、总线电容和实测波形判断。

### 4.3 数据什么时候允许变化

普通数据位遵循一条核心规则：

- SCL 为低时，发送方改变 SDA；
- SCL 为高时，接收方读取 SDA，SDA 必须保持稳定。

只有两种特殊情况允许 SDA 在 SCL 为高时跳变：

- SDA 从高变低：START；
- SDA 从低变高：STOP。

```text
空闲      START          数据阶段             STOP
SCL  ─────────┐  ┌─┐  ┌─┐  ┌─┐          ┌────────
              └──┘ └──┘ └──┘ └──────────┘
SDA  ───────┐    D7   D6   D5   ...      ┌────────
            └────────────────────────────┘
       SCL 高时下降                     SCL 高时上升
```

### 4.4 一个字节和第 9 个时钟

I2C 每次发送 8 位，最高位先发送。第 9 个时钟是应答位：

- `ACK=0`：接收方拉低 SDA，表示已经接收；
- `NACK=1`：接收方没有拉低 SDA。

本章的 OLED 驱动只产生第 9 个时钟，不读取 SDA，所以不能自动判断 OLED 是否 ACK。第 9 个时钟前仍必须释放 SDA，否则主机可能一直把线路拉低。

## 5. 地址与 SSD1306 写事务

### 5.1 `0x3C` 和 `0x78` 为什么都出现

常用 I2C 地址是 7 位。线上发送的第一个字节由 7 位地址和 1 位读写方向组成：

$$
\text{AddressByte}=(\text{Address7}\ll 1)\;|\;R/W
$$

SSD1306 常见 7 位地址为 `0x3C`：

| 含义 | 数值 |
| --- | ---: |
| 7 位从机地址 | `0x3C` |
| 写地址字节 | `0x3C << 1 = 0x78` |
| 读地址字节 | `(0x3C << 1) | 1 = 0x79` |

本章只向 OLED 写数据，所以驱动发送 `0x78`。部分模块的 7 位地址可能是 `0x3D`，对应写地址字节 `0x7A`。

代码中建议明确区分：

```c
#define OLED_ADDR_7BIT   0x3CU
#define OLED_ADDR_WRITE  (OLED_ADDR_7BIT << 1)
```

### 5.2 写命令和写显示数据

地址之后还要发送控制字节，告诉 SSD1306 后续内容是命令还是显存数据。

```text
START
-> 0x78      OLED 地址 + 写
<- ACK
-> 0x00      后续字节按命令解释
<- ACK
-> Command
<- ACK
STOP
```

```text
START
-> 0x78      OLED 地址 + 写
<- ACK
-> 0x40      后续字节按显示数据解释
<- ACK
-> Data
<- ACK
STOP
```

`0x00` 表示命令，`0x40` 表示显示数据。例如 `0xAE` 关闭显示，`0xAF` 开启显示。

当前课程驱动每写一个命令或数据字节都单独产生 START 和 STOP，便于初学者观察。跑通后可以把连续数据改为一次事务批量发送，这属于性能扩展，不改变协议主线。

## 6. 从 GPIO 到 OLED 的代码调用链

```text
OLED_ShowString()
    -> OLED_ShowChar()
        -> OLED_SetCursor()
        -> OLED_WriteData()
            -> OLED_I2C_Start()
            -> OLED_I2C_SendByte(0x78)
            -> OLED_I2C_SendByte(0x40)
            -> OLED_I2C_SendByte(Data)
            -> OLED_I2C_Stop()
                -> HAL_GPIO_WritePin(PB8/PB9)
```

看到屏幕上的字符，意味着 GPIO 配置、软件时序、OLED 地址、控制字节、初始化命令、光标设置和字模数据都已经参与了工作。

### 6.1 引脚操作与初始化

```c
#include "OLED_Font.h"
#include "gpio.h"

#define OLED_W_SCL(x) \
    HAL_GPIO_WritePin(GPIOB, GPIO_PIN_8, \
                      (x) ? GPIO_PIN_SET : GPIO_PIN_RESET)

#define OLED_W_SDA(x) \
    HAL_GPIO_WritePin(GPIOB, GPIO_PIN_9, \
                      (x) ? GPIO_PIN_SET : GPIO_PIN_RESET)

static void OLED_I2C_Init(void)
{
    /* MX_GPIO_Init() 已在 main() 中调用，这里只释放总线。 */
    OLED_W_SCL(1);
    OLED_W_SDA(1);
}
```

驱动层不应在 `OLED_I2C_Init()` 内再次调用 `MX_GPIO_Init()`。GPIO 初始化由 `main()` 统一完成，避免驱动层重置同一端口上的其他引脚。

### 6.2 START 与 STOP

```c
static void OLED_I2C_Start(void)
{
    OLED_W_SDA(1);
    OLED_W_SCL(1);
    OLED_W_SDA(0);  /* SCL 高时，SDA 高 -> 低：START */
    OLED_W_SCL(0);
}

static void OLED_I2C_Stop(void)
{
    OLED_W_SDA(0);
    OLED_W_SCL(1);
    OLED_W_SDA(1);  /* SCL 高时，SDA 低 -> 高：STOP */
}
```

### 6.3 发送一个字节

```c
static void OLED_I2C_SendByte(uint8_t Byte)
{
    uint8_t i;

    for (i = 0U; i < 8U; i++)
    {
        OLED_W_SCL(0);
        OLED_W_SDA((Byte & (0x80U >> i)) != 0U);
        OLED_W_SCL(1);  /* OLED 在 SCL 高电平期间读取 SDA */
        OLED_W_SCL(0);
    }

    /* 第 9 个时钟属于 ACK，主机必须先释放 SDA。 */
    OLED_W_SDA(1);
    OLED_W_SCL(1);
    OLED_W_SCL(0);
}
```

以 `0xA5 = 1010 0101` 为例，`0x80U >> i` 依次选出 D7 到 D0：

```text
i=0 -> 0x80 -> D7=1
 i=1 -> 0x40 -> D6=0
 i=2 -> 0x20 -> D5=1
 i=3 -> 0x10 -> D4=0
 i=4 -> 0x08 -> D3=0
 i=5 -> 0x04 -> D2=1
 i=6 -> 0x02 -> D1=0
 i=7 -> 0x01 -> D0=1
```

这八个数据时钟之后，主机释放 SDA，再产生一个 ACK 时钟。本章不读取这个时钟期间的 SDA 电平；逻辑分析仪仍可能显示从机实际返回的 ACK 或 NACK。

### 6.4 写命令和写数据

```c
#define OLED_ADDR_WRITE  0x78U

static void OLED_WriteCommand(uint8_t Command)
{
    OLED_I2C_Start();
    OLED_I2C_SendByte(OLED_ADDR_WRITE);
    OLED_I2C_SendByte(0x00U);
    OLED_I2C_SendByte(Command);
    OLED_I2C_Stop();
}

static void OLED_WriteData(uint8_t Data)
{
    OLED_I2C_Start();
    OLED_I2C_SendByte(OLED_ADDR_WRITE);
    OLED_I2C_SendByte(0x40U);
    OLED_I2C_SendByte(Data);
    OLED_I2C_Stop();
}
```

两者的地址相同，区别只在控制字节。下一篇软件 I2C 会把这里的“只发送”扩展为“发送后读取 ACK，并在需要时切换 SDA 输入”。

## 7. 实验一：固定显示和变量显示

### 7.1 固定显示多个类型

在最小实验通过后，把用户代码扩展为：

```c
int main(void)
{
    HAL_Init();
    SystemClock_Config();
    MX_GPIO_Init();

    OLED_Init();
    OLED_ShowChar(1, 1, 'A');
    OLED_ShowString(2, 1, "Hello World");
    OLED_ShowNum(3, 1, 12345U, 5U);
    OLED_ShowHexNum(4, 1, 0x5AU, 2U);

    while (1)
    {
    }
}
```

预期显示：

```text
第 1 行：A
第 2 行：Hello World
第 3 行：12345
第 4 行：5A
```

验收条件：

- 屏幕正常点亮，不是全亮或随机像素；
- `Hello World` 顺序正确；
- 数字位数与 `Length` 参数一致；
- 复位后显示可以稳定复现。

当前 8×16 字体接口把屏幕分成 4 行、16 列，行列编号从 1 开始。若只显示部分字符，先检查行列是否越界。

### 7.2 显示递增变量

固定宽度显示可以覆盖旧内容，适合做简单调试终端：

```c
uint32_t count = 0U;

OLED_Init();
OLED_ShowString(1, 1, "COUNT:");

while (1)
{
    OLED_ShowNum(2, 1, count, 6U);
    count++;
    HAL_Delay(100U);
}
```

预期现象是第二行每 100 ms 增加 1。完整数据链为：

```text
变量 count
    -> 十进制拆位
    -> 字模索引
    -> OLED 显存数据
    -> 软件 I2C 写事务
    -> 屏幕像素变化
```

显示有符号数时：

```c
int16_t value = -1234;
OLED_ShowSignedNum(3, 1, value, 5U);
```

`Length=5` 表示数字部分固定占 5 位，前面还会额外显示一个正负号，总共占 6 列。下一篇显示 MPU6050 的 `int16_t` 原始值时会用到同样的接口。

### 7.3 实验失败时先查什么

- 无显示：回到最小实验，先确认 `OLED_Init()` 和单字符显示；
- 字符错位：检查 `Line`、`Column` 和字体尺寸；
- 旧数字残留：增加显示宽度或先清屏；
- 变量不变化：确认 `while (1)` 执行、变量确实递增，并保留 `HAL_Delay()`；
- 显示稳定但波形异常：进入下一节用逻辑分析仪定位协议层。

## 8. 实验二：用逻辑分析仪读懂一次写入

### 8.1 操作步骤

1. 逻辑分析仪的地线接 STM32 `GND`；
2. 一路接 PB8，协议分析器定义为 `SCL`；
3. 一路接 PB9，协议分析器定义为 `SDA`；
4. 设置采样率，使每个 SCL 周期至少有足够采样点；
5. 让程序触发一次 `OLED_WriteCommand(0xAF)`；
6. 在协议解码器中选择 I2C，查看地址、数据、ACK 和 STOP。

应看到等价于下面的事务：

```text
START -> 0x3C Write -> ACK -> 0x00 -> ACK -> 0xAF -> ACK -> STOP
```

有些工具显示线上完整地址字节 `0x78`，有些显示 `0x3C Write`。两者表示同一个地址和方向。

### 8.2 验收标准

逐项确认：

1. START 时 SDA 是否在 SCL 高电平期间下降；
2. 地址是否为 `0x3C/W` 或线上字节 `0x78`；
3. 每个字节是否有 8 个数据时钟和第 9 个 ACK 时钟；
4. 数据是否最高位先发送；
5. 控制字节是否为 `0x00`；
6. 最后是否以 STOP 结束。

> 待确认项：实际 SCL 频率、上升时间和模块是否自带上拉必须以逻辑分析仪/示波器或模块原理图为准。静态检查代码不能替代硬件波形验证。

## 9. 分层故障定位

### 9.1 完全不亮，SCL/SDA 也没有波形

- **先检查**：程序是否执行到 `OLED_Init()`，`OLED.c` 是否加入编译；
- **再检查**：`MX_GPIO_Init()` 是否执行，PB8/PB9 宏是否与接线一致；
- **结论**：没有波形时先查程序调用和 GPIO 层，不要先修改 OLED 地址。

### 9.2 SCL、SDA 空闲时为低

- **先检查**：GPIO 是否为开漏、初始值是否为 High；
- **再检查**：外部上拉、接反、短路和模块供电；
- **隔离操作**：断开 OLED，只测 MCU 端能否释放为高；
- **结论**：总线未恢复空闲前，后续协议分析没有意义。

### 9.3 有波形，但地址后没有 ACK

- **先检查**：供电、共地、SCL/SDA 是否接反；
- **再检查**：7 位地址是 `0x3C` 还是 `0x3D`，是否发送了 `0x78`；
- **继续检查**：第 9 个时钟前主机是否释放 SDA，上升沿是否过慢；
- **结论**：本章代码不读取 ACK，程序不报错时仍需看逻辑分析仪。

### 9.4 有 ACK，但屏幕为空白

地址层已经基本正常，继续检查：

- `OLED_Init()` 的初始化命令是否完整；
- 命令是否使用 `0x00`，显示数据是否使用 `0x40`；
- 是否发送了开启显示命令 `0xAF`；
- 光标页地址、列地址和列偏移是否正确；
- 字符是否存在于 `OLED_Font.h` 的字模范围内。

### 9.5 字符错位、镜像或上下颠倒

这通常不是 I2C 失败，而是 SSD1306 扫描方向、页地址或列偏移不匹配。检查初始化命令中的 `0xA0/0xA1`、`0xC0/0xC8` 以及模块的列偏移。

### 9.6 偶发花屏或复位后不稳定

检查 OLED 上电稳定时间、软件 I2C 速率、上拉与连线、电源质量，以及程序是否在中断中长时间调用显示函数。可以临时增加微秒级延时，观察降低速率后是否稳定；需要固定频率时应使用定时器或 DWT，并用波形实测。

### 10.1 自测题

1. 为什么开漏引脚写 1 更准确地说是“释放总线”？
2. START 和 STOP 分别由什么电平变化产生？
3. 数据位为什么只能在 SCL 为低时改变？
4. OLED 的 7 位地址为 `0x3C` 时，写地址字节为什么是 `0x78`？
5. 第 9 个时钟前，主机为什么必须释放 SDA？
6. `0x00` 和 `0x40` 两个控制字节分别表示什么？
7. `OLED_I2C_SendByte()` 为什么从 `0x80` 掩码开始？
8. 有 ACK 但屏幕空白时，为什么不应继续只检查接线？

### 10.2 参考答案

1. 开漏输出不能主动产生高电平，写 1 只是关断下拉管，由上拉电阻恢复高电平。
2. SCL 为高时，SDA 高到低是 START，SDA 低到高是 STOP。
3. 接收方在 SCL 高电平期间采样，若此时数据变化会破坏位值；START 和 STOP 是协议规定的例外。
4. 7 位地址左移一位后，最低位留给 R/W；写方向为 0，所以得到 `0x78`。
5. ACK 由接收方驱动；主机不释放 SDA，就无法判断从机是否应答。
6. `0x00` 表示后续字节按命令解释，`0x40` 表示后续字节按显示数据解释。
7. I2C 最高位先发送，`0x80 >> i` 可依次选出 D7 到 D0。
8. ACK 已证明供电、地址和基本时序大致正常，下一步应检查控制字节、初始化命令、光标和字模数据。

当 OLED 能稳定显示 `Hello World` 和递增变量，并且逻辑分析仪能识别 `START -> 0x3C/W -> ACK -> 控制字节 -> 数据 -> STOP`，本章的软件 I2C 写链路就完成了。
