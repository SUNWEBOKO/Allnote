# 第 5 章 时钟系统

## 本章闭环

本章解决两个问题：STM32 的时钟从哪里产生、怎样分配到 CPU 和外设；以及如何用 CubeMX/HAL 把 STM32F103 从默认 `8 MHz` 配置到常用的 `72 MHz`。

本章完成两个共用同一条硬件主线的实验：先用默认时钟让 `PC13` 板载 LED 闪烁，再修改时钟树并观察同一段程序明显变快。

```text
HSI/HSE -> PLL/时钟选择 -> SYSCLK -> AHB/APB 分频 -> HCLK/PCLK
        -> CPU 与外设工作节拍 -> LED 翻转速度
```

## 1. 时钟系统的核心概念

### 1.1 为什么需要时钟

STM32 内部的 CPU、Flash、RAM、DMA、GPIO、USART、SPI、I2C、TIM、ADC 等模块大多是时序逻辑电路，需要统一的时钟沿驱动。时钟系统负责产生时钟、选择来源，并按模块的最高频率限制把时钟分配到不同总线和外设。

时钟越快，代码执行和外设工作节拍通常越快；但不同模块的上限不同，不能把一个高频时钟直接送给所有模块。

### 1.2 四个基础时钟源

STM32F1 常见的四个时钟源如下：

| 缩写 | 全称 | 来源 | 特点与用途 |
| --- | --- | --- | --- |
| `HSI` | High Speed Internal | 片内 RC 振荡器 | 无需外部器件，成本低，精度一般；常见为 `8 MHz` |
| `HSE` | High Speed External | 外部晶振或外部时钟输入 | 精度较高；常见外接 `8 MHz` 晶振 |
| `LSI` | Low Speed Internal | 片内低速 RC | 精度一般，常给 `IWDG` 等低速模块 |
| `LSE` | Low Speed External | 外部 `32.768 kHz` 晶振 | 精度较高，常给 `RTC` |

命名规律是 `HS/LS` 表示高速/低速，`I/E` 表示内部/外部。高速源主要供系统主时钟树，低速源主要供 RTC、独立看门狗等低速模块。

### 1.3 频率配置与外设时钟门控

“总线已经有时钟”和“某个外设已经获得时钟”是两件事。`PCLK1`、`PCLK2` 决定总线运行频率，RCC 中的外设时钟使能位则像开关，决定时钟是否真正送到某个外设。

```text
SYSCLK -> AHB/APB 分频 -> PCLKx -> 外设时钟门控 -> 外设寄存器和内部状态机
```

即使 `PCLK2 = 72 MHz`，没有使能 GPIOC 时钟，`PC13` 的初始化也不会按预期生效。门控既能避免误操作，也是降低动态功耗的重要手段。CubeMX 通常把对应的 HAL 宏放在 `MX_GPIO_Init()`、`MX_TIMx_Init()` 等外设初始化函数中。

## 2. 时钟树与频率关系

![STM32F1 时钟树总览](<image/Pasted image 20260727154625.png>)

图中左边的高速树负责系统主频和大多数外设，右边的低速分支主要服务于 `RTC`、`IWDG` 等模块。阅读时先沿 `HSI/HSE -> PLL -> SYSCLK` 看主干，再检查 `AHB/APB` 分频和各外设专用分支。

### 2.1 总线和频率上限

STM32F103 的学习主线是高速时钟树。三条总线及其常见上限为：

| 总线 | 对应时钟 | 常见最高频率 | 主要作用 |
| --- | --- | ---: | --- |
| `AHB` | `HCLK` | `72 MHz` | Cortex-M3 内核、DMA 和高速存储器等 |
| `APB1` | `PCLK1` | `36 MHz` | 低速外设，如部分定时器、USART、I2C |
| `APB2` | `PCLK2` | `72 MHz` | 高速外设，如 GPIO、ADC、部分定时器和 USART |

### 2.2 `SYSCLK` 与 `PLL`

`SYSCLK`（System Clock，系统时钟）是高速树的核心节点，后续总线分频都从这里开始。STM32F1 中它通常直接来自 `HSI`、`HSE`，或来自 `PLL` 输出。

`PLL`（Phase-Locked Loop，锁相环）可以对输入时钟进行倍频。STM32F1 的 PLL 输入常见选项为 `HSI / 2`、`HSE` 或 `HSE / 2`。因此配置时钟本质上是“选路、乘法、除法”的组合。

假设 `HSE = 8 MHz`：

- 直接选择 `HSI` 或 `HSE`，可以得到约 `8 MHz` 的 `SYSCLK`；
- 选择 `HSI / 2 = 4 MHz` 或 `HSE / 2 = 4 MHz`，再经 `PLL x3`，可得到 `12 MHz`；
- 选择 `HSE = 8 MHz`，经 `PLL x9`，可得到常用的 `72 MHz`。

### 2.3 `HCLK`、`PCLK1`、`PCLK2`

`SYSCLK` 经过 AHB 分频得到 `HCLK`，再由 APB1、APB2 分别分频得到 `PCLK1`、`PCLK2`：

$$HCLK = \frac{SYSCLK}{AHB\_Prescaler}$$

$$PCLK1 = \frac{HCLK}{APB1\_Prescaler}, \qquad PCLK2 = \frac{HCLK}{APB2\_Prescaler}$$

常用满速配置为：

```text
HSE = 8 MHz
PLL Source = HSE, PLL Mul = x9
SYSCLK = 72 MHz
AHB  = /1 -> HCLK  = 72 MHz
APB1 = /2 -> PCLK1 = 36 MHz
APB2 = /1 -> PCLK2 = 72 MHz
```

### 2.4 定时器和特殊时钟分支

当 APB 分频系数为 `1` 时，定时器时钟等于 `PCLKx`；当 APB 分频系数大于 `1` 时，STM32F1 的定时器时钟通常为 `2 × PCLKx`。因此上述配置中，APB1 定时器虽然看到 `PCLK1 = 36 MHz`，实际定时器时钟仍为 `72 MHz`。

还需注意：

| 时钟节点 | 作用 | 边界 |
| --- | --- | --- |
| `SysTick` | HAL Tick 和 `HAL_Delay()` 的时间基准 | 必须由 HAL 初始化并持续运行 |
| `ADC` 时钟 | 模数转换时钟 | 通常由 `PCLK2` 再分频，F103 常见上限为 `14 MHz` |
| `USB` 时钟 | USB 外设时钟 | 必须得到 `48 MHz`；`72 MHz` PLL 输出时通常经 `÷1.5` 得到 |
| `RTC` 时钟 | RTC 计数基准 | 可选 `LSE`、`LSI` 或 `HSE/128`，精度和掉电保持能力不同 |
| `IWDG` 时钟 | 独立看门狗计数基准 | 来自 `LSI`，不依赖主系统高速时钟 |

主频提高时，Flash 访问还需要等待周期：`0~24 MHz` 为 `0` 个，`24~48 MHz` 为 `1` 个，`48~72 MHz` 为 `2` 个。CubeMX 会在 `HAL_RCC_ClockConfig()` 中按频率设置，但排障时仍应确认该参数。

以 ADC 为例，`PCLK2 = 72 MHz` 时可选 `/2`、`/4`、`/6`、`/8`。前两者得到 `36 MHz`、`18 MHz`，均超过 STM32F103 的 `14 MHz` 上限；常用 `/6` 得到 `12 MHz`，或 `/8` 得到 `9 MHz`。这说明外设专用分支必须从上游实际频率继续计算。

RTC 若使用 `32.768 kHz` 的 LSE，经 `32768` 分频可得到 `1 Hz` 计数基准。LSE 精度高且可由 `VBAT` 维持；LSI 无需外部晶振但精度较低；`HSE/128` 依赖主电源和高速时钟，不适合要求掉电继续走时的场景。

`CSS`（Clock Security System，时钟安全系统）可监测 HSE 故障，`MCO`（Microcontroller Clock Output）可把内部时钟输出到引脚。前者用于故障保护，后者可配合示波器或逻辑分析仪验证实际频率。

## 3. HAL/CubeMX 时钟配置链

### 3.1 配置顺序

HAL 工程的时钟配置链可以按下面顺序阅读和检查：

```text
选择 HSI/HSE -> 配置 PLL -> 选择 SYSCLK
-> 配置 AHB/APB 分频 -> 设置 Flash 等待周期
-> HAL_RCC_OscConfig() -> HAL_RCC_ClockConfig()
-> 更新 SystemCoreClock 和 SysTick
```

每一步都要同时确认资源、参数和现象：时钟源选错会导致 PLL 不锁定；总线分频过小会超过外设上限；Flash 等待周期不足会造成高频运行不稳定。

### 3.2 CubeMX 时钟树阅读顺序

打开 `Clock Configuration` 页面后，依次检查：

1. 树根：实际启用的是 `HSI`、`HSE` 还是其他源，输入频率是多少；
2. 树干：`SYSCLK` 选用哪一路，PLL 输入和倍频是多少；
3. 树枝：`AHB`、`APB1`、`APB2` 分频是否满足上限；
4. 结果：`SYSCLK`、`HCLK`、`PCLK1`、`PCLK2` 和 ADC/USB 等特殊时钟是否正确。

### 3.3 生成的 HAL 代码

生成代码后，时钟树参数主要落在 `SystemClock_Config()` 中：

```c
if (HAL_RCC_OscConfig(&RCC_OscInitStruct) != HAL_OK)
{
    Error_Handler();
}

if (HAL_RCC_ClockConfig(&RCC_ClkInitStruct, FLASH_LATENCY_2) != HAL_OK)
{
    Error_Handler();
}
```

前者配置并启动 HSI/HSE/PLL，并等待相应就绪状态；后者选择系统时钟、配置总线分频和 Flash 等待周期。返回值异常通常说明振荡器没有就绪、PLL 参数非法或切换失败。课程示例由 CubeMX 生成这些调用，不建议手工修改生成区。

### 3.4 从复位到 `main()` 的时钟配置时机

复位后的调用链为：

```text
Reset_Handler -> SystemInit() -> C 运行库初始化 -> main()
              -> HAL_Init() -> SystemClock_Config() -> MX_xxx_Init()
```

标准库课程的工程模板可能在 `SystemInit()` 中直接把系统配置为 `72 MHz`；CubeMX 生成的 HAL 工程则通常先由 `SystemInit()` 把 RCC 置于复位后的基础状态，再在 `main()` 中调用 `SystemClock_Config()` 完成 HSE、PLL 和总线配置。不能看到 `SystemInit()` 就默认当前已经是 `72 MHz`，应以实际工程的启动文件、`system_stm32f1xx.c` 和 `SystemClock_Config()` 为准。

`HAL_Init()` 会建立 HAL Tick，系统时钟切换后 `HAL_RCC_ClockConfig()` 会按新的 `HCLK` 更新节拍配置。因此初始化顺序应保持为 `HAL_Init()`、`SystemClock_Config()`、各 `MX_xxx_Init()`，不要让依赖准确时钟的外设先于系统时钟初始化。

### 3.5 外设时钟使能与总线归属

HAL 使用专用宏控制外设时钟门控。以 STM32F103 为例：

```c
__HAL_RCC_GPIOC_CLK_ENABLE();  /* GPIOC 位于 APB2 */
__HAL_RCC_TIM2_CLK_ENABLE();   /* TIM2 位于 APB1 */
__HAL_RCC_DMA1_CLK_ENABLE();   /* DMA1 位于 AHB */
```

宏的总线归属必须与芯片的总线矩阵一致。开启外设时钟只表示允许该外设工作，不会改变 `PCLKx` 的频率；关闭门控也不会改变同一总线上其他外设的频率。

### 3.6 运行时读取和测量实际时钟

不能只凭 CubeMX 图形界面判断运行时状态。HAL 可直接读取当前各级时钟：

```c
uint32_t sysclk = HAL_RCC_GetSysClockFreq();
uint32_t hclk   = HAL_RCC_GetHCLKFreq();
uint32_t pclk1  = HAL_RCC_GetPCLK1Freq();
uint32_t pclk2  = HAL_RCC_GetPCLK2Freq();
```

这些值适合在调试器中观察，或临时通过串口/OLED 输出。`SystemCoreClock` 表示当前内核时钟，时钟切换后应由系统代码保持更新。需要独立于软件验证时，可用 MCO 把时钟输出到 `PA8` 后测量；具体可选源和分频以芯片型号为准。

## 4. 实验一：默认 `8 MHz` 时钟驱动板载 LED

### 4.1 目标、接线与现象

目标是在不修改时钟树的情况下，用默认 `HSI = 8 MHz` 运行空循环，让板载 LED 周期性亮灭。实验只用于观察主频变化，不作为精确定时方案。

以常见 STM32F103C8T6 开发板为例：LED 接在 `PC13`，低电平点亮。不同板卡的 LED 接法可能相反，应以原理图为准。

### 4.2 CubeMX 配置

1. 新建 `STM32F103C8T6` 工程；
2. `System Core -> SYS -> Debug` 选择 `Serial Wire`；
3. 将 `PC13` 配置为 `GPIO_Output`；
4. 常见低电平点亮板卡可使用 `Output Open Drain`、低速、初始高电平；若 LED 阳极接引脚，则改用 `Output Push-Pull`；
5. 设置工程名、路径和工具链，生成代码。

### 4.3 主程序与数据流

在 `while (1)` 的用户代码区域中写入：

```c
uint32_t i;

while (1)
{
    HAL_GPIO_WritePin(GPIOC, GPIO_PIN_13, GPIO_PIN_RESET);
    for (i = 0; i < 1000000; i++);

    HAL_GPIO_WritePin(GPIOC, GPIO_PIN_13, GPIO_PIN_SET);
    for (i = 0; i < 1000000; i++);
}
```

数据链为：`HCLK = 8 MHz` -> CPU 执行空循环 -> `PC13` 输出翻转 -> LED 亮灭。

### 4.4 现象解释和边界

`1000000` 次循环通常得到接近秒级的亮灭节奏，但实际时间会受编译器优化、内核流水线、工程设置和编译器版本影响。因此它只能验证“主频改变会影响执行速度”，不能替代 `HAL_Delay()` 或定时器。

## 5. 实验二：配置 `72 MHz` 并对比 LED 速度

### 5.1 目标与验收现象

将 `SYSCLK`、`HCLK` 配置为 `72 MHz`，将 `PCLK1` 限制在 `36 MHz`，`PCLK2` 保持 `72 MHz`。重新下载同一份 LED 程序后，LED 应明显比实验一闪烁更快。

### 5.2 配置 HSE 与 PLL

在 `Pinout & Configuration -> RCC` 中，根据板卡硬件选择 HSE：

- `Crystal/Ceramic Resonator`：外接晶振或陶瓷谐振器；
- `Bypass Clock Source`：外部已有成品时钟波形，直接输入芯片。

常见 `8 MHz` 晶振应选择前者。随后在 `Clock Configuration` 中设置：

1. `HSE = 8 MHz`；
2. `PLL Source = HSE`；
3. `HSE Prediv = /1`；
4. `PLL Mul = x9`；
5. `System Clock Mux = PLLCLK`。

参数推导为：

$$PLL\_CLK = 8\,\text{MHz} \times 9 = 72\,\text{MHz}$$

因此 `SYSCLK = 72 MHz`。

### 5.3 配置 AHB、APB1、APB2

设置：

- `AHB Prescaler = /1`；
- `APB1 Prescaler = /2`；
- `APB2 Prescaler = /1`。

得到：

$$HCLK = 72 / 1 = 72\,\text{MHz}$$

$$PCLK1 = 72 / 2 = 36\,\text{MHz}, \qquad PCLK2 = 72 / 1 = 72\,\text{MHz}$$

生成代码后，重点查看 `SystemClock_Config()`、`HAL_RCC_OscConfig()` 和 `HAL_RCC_ClockConfig()` 是否包含相应设置。

### 5.4 对比结果

重新下载程序后，`SYSCLK/HCLK` 从 `8 MHz` 提升到 `72 MHz`，CPU 执行同样的空循环所需时间大幅缩短，LED 会明显变快。这证明时钟树会直接影响代码执行速度和外设工作节拍。

## 6. 程序设计边界与常见误区

### 6.1 课程示例与工程写法

课程示例使用空循环观察主频变化；工程中应使用 `HAL_Delay()`、定时器或 RTOS 时基，并确保 `SysTick` 已正确配置。课程示例默认板卡为 `HSE = 8 MHz`、`LSE = 32.768 kHz`、LED 在 `PC13`，换板卡必须重新核对原理图和数据手册。

### 6.2 高频配置的边界

- `APB1` 不能在 STM32F103 上直接配置为 `72 MHz`，主频 `72 MHz` 时通常必须 `/2`；
- 定时器频率不能总按 `PCLKx` 计算，APB 分频大于 `1` 时通常要乘 `2`；
- `ADC` 必须检查独立分频后的时钟是否不超过 `14 MHz`；
- 使用 USB 必须确认 `48 MHz` 时钟；
- `Bypass` 只适用于外部已有时钟输入，不适用于普通晶振；
- 提高主频时不能忽略 Flash 等待周期。

### 6.3 低功耗唤醒后的时钟恢复

睡眠模式通常只停止 CPU，外设时钟可继续运行；停止模式会关闭 PLL、HSI、HSE 等高速时钟。STM32 从停止模式唤醒后会先使用 HSI，若工程原本依赖 `72 MHz` PLL，必须再次调用 `SystemClock_Config()` 恢复时钟树，再继续使用串口、定时器和精确定时逻辑。

待机模式唤醒相当于复位，程序会重新执行完整启动流程。RTC/LSE 属于后备域，是否保留取决于 `VBAT`、后备域配置以及是否发生了后备域复位，不能按普通 SRAM 状态理解。

### 6.4 外设异常先查上游时钟

串口波特率不准、PWM 频率错误、ADC 采样异常等问题，可能是外设参数正确但上游时钟已经算错。排查时先沿“时钟源 -> PLL -> SYSCLK -> HCLK -> PCLKx -> 外设时钟”逐级核对，再检查外设寄存器。

## 7. 验收与排错

### 7.1 正常现象

| 实验 | 正常现象 | 首要验收点 |
| --- | --- | --- |
| 默认 `8 MHz` LED | LED 周期性亮灭，节奏较慢 | `SYSCLK/HCLK = 8 MHz`，GPIO 极性正确 |
| `72 MHz` LED | 同一循环明显变快 | `SYSCLK = 72 MHz`、`PCLK1 = 36 MHz`、Flash 等待周期正确 |

### 7.2 按信号链排查

1. **供电与硬件**：确认芯片供电、复位、晶振和 LED 接法；
2. **GPIO**：确认 `PC13` 模式、速度、初始电平和有效电平；
3. **时钟源**：确认 HSE 是晶振模式还是旁路模式，晶振频率与工程设定一致；
4. **PLL 与分频**：逐级计算 `SYSCLK/HCLK/PCLK1/PCLK2`，确认没有超过上限；
5. **外设门控**：确认 GPIO、TIM、ADC、DMA 等对应的 `__HAL_RCC_xxx_CLK_ENABLE()` 已执行，且总线归属正确；
6. **HAL 初始化**：确认 `HAL_RCC_OscConfig()`、`HAL_RCC_ClockConfig()` 返回 `HAL_OK`，并检查 `FLASH_LATENCY_2` 等等待周期；
7. **运行时频率**：用 `HAL_RCC_GetHCLKFreq()` 等函数读取实际值；若周期近似慢 `9` 倍，优先检查 HSE、PLL 和系统时钟选择是否仍停留在 `8 MHz`；
8. **应用代码**：确认循环变量未被优化掉，下载的是最新生成的工程，且没有在其他位置重复配置系统时钟。

## 本章小结

STM32 时钟系统的核心是“时钟源 -> PLL/选择 -> `SYSCLK` -> AHB/APB 分频 -> 各总线和外设时钟”。掌握这条计算链，就能读懂 CubeMX 时钟树，而不是死记 `72/36/72` 这组结果。

本章还完成了从默认 `8 MHz` 到 `72 MHz` 的 HAL 配置，并用同一段 LED 程序验证主频变化。时钟树决定频率，RCC 门控决定时钟是否送达外设，专用分支再决定 ADC、USB、RTC 等模块的最终节拍。今后学习具体外设时，应同时确认总线归属、门控状态、实际输入时钟和对应上限。
