## 1. 先理解控制：系统为什么要"看结果再修正"

在正式学习 PID 之前，先看一个很普通的场景：洗澡时调水温。水太冷，你会把热水阀开大；水太烫，你会把热水阀关小；水温快接近舒服的范围时，你不会再猛拧阀门，而是会提前放慢动作，避免一下子调过头。

这个过程其实已经包含了控制系统最核心的思想：我们不是只给一个固定动作就不管了，而是不断观察实际结果，并根据"实际结果"和"目标结果"的差距来修正动作。

工程里把这种思想叫作**闭环控制**。闭环控制至少包含几个对象：

- **设定值**（Setpoint，SP）：希望系统达到的目标，例如目标温度 $28^\circ \mathrm{C}$、目标速度 $1\ \mathrm{m/s}$、目标角度 $0^\circ$。
- **过程值 / 测量值**（Process Variable，PV）：传感器测到的实际值，例如当前温度、当前速度、当前倾角。
- **误差**（Error）：目标值与实际值之差，通常写作

$$
e(t)=SP-PV(t)
$$

- **控制输出**（Output，$u$）：控制器算出来送给执行器的量，例如 PWM 占空比、电机电流、阀门开度、加热功率。

闭环控制的信息流可以概括为：

```text
目标值 SP
   ↓
与测量值 PV 比较，得到误差 e
   ↓
PID 控制器根据误差计算输出 u
   ↓
执行器动作：电机 / 加热片 / 阀门 / 舵机
   ↓
被控对象状态改变：速度 / 温度 / 角度
   ↓
传感器测量新的 PV，再反馈回来
```

与闭环相对的是**开环控制**。例如给电机固定 `PWM = 4000`，不管车速有没有达到目标，程序都不再调整输出。平地上也许能跑到 $1\ \mathrm{m/s}$，上坡时可能只有 $0.7\ \mathrm{m/s}$，但 PWM 仍然不变。开环系统的缺点是：**不能自动抵抗干扰，也不能自动修正误差**。

PID 正是最经典的闭环控制算法。它不要求你先写出非常精确的被控对象数学模型，而是直接根据误差的大小、误差累积的时间、误差变化的趋势来计算控制输出。

## 2. PID 的核心直觉：现在、过去和未来

PID 是三个英文单词的缩写：

- **P**：Proportional，比例；
- **I**：Integral，积分；
- **D**：Derivative，微分。

可以用一句话理解：

> P 看现在，I 看过去，D 看趋势。

完整 PID 的连续形式为：

$$
u(t)=K_p e(t)+K_i\int_0^t e(\tau)\,d\tau+K_d\frac{de(t)}{dt}
$$

其中 $K_p$、$K_i$、$K_d$ 分别是比例、积分、微分增益，也就是调参时要调整的三个参数。

### 2.1 P：比例控制，当前误差越大，出力越大

比例项的表达式是：

$$
u_P=K_p e(t)
$$

它的思想非常直接：误差越大，输出越大。比如小车目标位置是 $10\ \mathrm{m}$，当前只走到 $2\ \mathrm{m}$，误差是 $8\ \mathrm{m}$，控制器应该让电机更用力；如果当前已经走到 $9.8\ \mathrm{m}$，误差只剩 $0.2\ \mathrm{m}$，输出就应该变小。

P 项是 PID 里最重要的主力项，它决定系统有没有"反应"和反应强不强。$K_p$ 太小，系统会显得疲软，靠近目标非常慢；$K_p$ 增大，响应会变快；但 $K_p$ 过大时，系统容易过冲、振荡甚至发散。

P 项还有一个典型问题：**稳态误差**。以电机速度控制为例，假设目标速度是 $100\ \mathrm{rpm}$，实际速度稳定在 $95\ \mathrm{rpm}$。此时误差只有 $5\ \mathrm{rpm}$，如果 $K_p e$ 产生的输出刚好不足以克服摩擦、负载或风阻，系统就可能永远停在 $95\ \mathrm{rpm}$，差一点到不了目标。这种最终稳定后仍然存在的误差，就叫稳态误差或静差。

### 2.2 I：积分控制，误差存在越久，修正越强

积分项的表达式是：

$$
u_I=K_i\int_0^t e(\tau)\,d\tau
$$

积分项关心的不是某一瞬间误差有多大，而是误差在一段时间内累积了多少。只要误差不为零，积分项就会继续累加，输出会慢慢变大，直到把残余误差推掉。

这正好解决 P 项的稳态误差问题。如果电机速度长期停在目标值以下，即使每次误差都不大，积分项也会把这些小误差逐步累积起来，最终给出足够的额外输出，让速度继续逼近目标。

但是 I 项也有明显副作用：它容易"记仇过头"。如果执行器已经达到极限，例如 PWM 已经到 100%，但目标还是达不到，误差会继续存在，积分项会继续累加。等到误差方向改变时，积分项里已经积累了一个很大的值，系统会出现明显超调、长时间恢复不过来，甚至直接失控。这种现象叫**积分饱和**。

因此实际工程中，只要使用 I 项，就必须考虑积分限幅、条件积分或积分清零。

### 2.3 D：微分控制，误差变化越快，提前制动越强

微分项的表达式是：

$$
u_D=K_d\frac{de(t)}{dt}
$$

微分项关注的是误差变化速度，也就是系统正在怎样靠近或远离目标。它的直觉是"提前刹车"。

比如小车正高速冲向目标位置，虽然当前位置还没到目标，P 项仍然会继续给正向输出，但如果误差正在迅速变小，说明系统已经带着惯性接近目标了。D 项会根据这种变化趋势给出反向阻尼，减小过冲和振荡。

D 项的好处是提高稳定性、减少超调；坏处是对噪声非常敏感。传感器数据如果有一点抖动，差分后会被放大成很大的变化率，导致输出抖动。因此实际使用 D 项时，常常需要低通滤波，或者采用"对测量值微分"而不是"对误差微分"。

### 2.4 三项作用总结

| 项 | 关注对象 | 主要作用 | 常见副作用 |
| --- | --- | --- | --- |
| P | 当前误差 | 快速响应，让系统动起来 | 过大时超调、振荡；单独使用可能有稳态误差 |
| I | 历史误差累积 | 消除稳态误差 | 积分饱和、响应变慢、超调增大 |
| D | 误差变化趋势 | 提供阻尼，抑制超调和振荡 | 放大噪声，对采样周期敏感 |

实际控制中不一定三项全用。很多系统只用 PI 或 PD：

- 温度、液位、速度控制常用 **PI**，因为它们需要消除稳态误差，D 项又容易受噪声影响。
- 平衡小车直立环常用 **PD**，因为它需要快速回正和阻尼，但积分会带来滞后，容易失控。
- 高精度伺服系统或特殊对象可能使用完整 **PID**。

## 3. 单片机里的 PID：连续公式必须离散化

理论公式里的积分和微分是连续时间运算，但单片机只能每隔固定时间读一次传感器、算一次输出。例如每 $10\ \mathrm{ms}$ 执行一次控制，那么程序看到的是一串离散数据：

```text
e(0), e(1), e(2), ... , e(k)
```

设采样周期为 $\Delta t$，离散化时通常这样处理：

$$
\int e(t)\,dt \approx \sum_{i=0}^{k} e(i)\Delta t
$$

$$
\frac{de(t)}{dt}\approx \frac{e(k)-e(k-1)}{\Delta t}
$$

因此位置式 PID 的离散表达式为：

$$
u(k)=K_p e(k)+K_i\sum_{i=0}^{k}e(i)\Delta t+K_d\frac{e(k)-e(k-1)}{\Delta t}
$$

在很多嵌入式工程代码中，为了简化，$\Delta t$ 会被吸收到 $K_i$ 和 $K_d$ 里面。于是代码形式可能写成：

$$
u(k)=K_p e(k)+K_i\sum e(k)+K_d[e(k)-e(k-1)]
$$

这并不表示采样周期不重要，而是表示调出来的 $K_i$、$K_d$ 已经默认绑定了当前控制周期。一旦控制周期改变，原来的 PID 参数就不一定还能用。

### 3.1 位置式 PID

位置式 PID 直接计算控制输出本身，例如最终 PWM 值：

```c
error = target - actual;
integral += error * dt;
derivative = (error - last_error) / dt;
output = Kp * error + Ki * integral + Kd * derivative;
last_error = error;
```

它直观、容易理解，适合初学者和大多数控制场景。缺点是积分项作为历史累积量，必须处理好限幅、清零和模式切换。

### 3.2 增量式 PID

增量式 PID 不直接算输出，而是算本次输出相对上次输出的变化量：

$$
\Delta u(k)=K_p[e(k)-e(k-1)]+K_i e(k)\Delta t+K_d\frac{e(k)-2e(k-1)+e(k-2)}{\Delta t}
$$

然后再执行：

```c
output += delta_output;
```

增量式 PID 更适合某些只关心"输出变化"的执行机构，也更容易做手自动无扰切换。但它对初学者不如位置式直观，所以学习时通常先掌握位置式，再理解增量式。

## 4. 当前配套 PID 驱动怎样实现

下面代码对应 `E:\ProjectStm\驱动库\PID` 的实际实现，便于把理论公式和当前接口逐项对照。它采用结构体封装、多实例、输出限幅、积分累加限幅、测量值差分和输出偏置。这里的 `Ki`、`Kd` 没有显式乘除 `dt`，因此参数与调用周期绑定。

### 4.1 PID 结构体

```c
typedef struct
{
    float Target;      // 目标值 SP
    float Actual;      // 当前测量值 PV
    float Actual1;     // 上一拍测量值，用于微分先行
    float Out;         // PID 输出

    float Kp;
    float Ki;
    float Kd;

    float Error0;      // 当前误差
    float Error1;      // 上一拍误差
    float ErrorInt;    // 积分累加

    float OutMax;
    float OutMin;
    float ErrorIntMax;
    float ErrorIntMin;

    float OutOffset;   // 死区补偿
} PID_t;
```

用结构体封装 PID 的好处是可以创建多个互不干扰的控制器。例如平衡小车中可以有：

```c
PID_t angle_pid;
PID_t speed_pid;
PID_t turn_pid;
```

它们各自保存自己的目标值、测量值、历史误差和输出限幅，不会互相污染。

### 4.2 初始化函数

```c
void PID_Init(PID_t *pid, float kp, float ki, float kd,
              float out_min, float out_max)
{
    if (pid == 0) return;

    pid->Target = 0.0f;
    pid->Actual = 0.0f;
    pid->Actual1 = 0.0f;
    pid->Out = 0.0f;

    pid->Kp = kp;
    pid->Ki = ki;
    pid->Kd = kd;

    pid->Error0 = 0.0f;
    pid->Error1 = 0.0f;
    pid->ErrorInt = 0.0f;

    pid->OutMin = out_min;
    pid->OutMax = out_max;
    pid->ErrorIntMin = out_min;
    pid->ErrorIntMax = out_max;
    pid->OutOffset = 0.0f;
}
```

初始化时要把历史误差、积分值、上一拍测量值全部清零。否则程序刚启动时，旧数据可能导致首拍输出异常。

不过，把 `Actual1` 初始化为 0 仍有一个首拍边界：若第一次测量值本身不为 0，微分项会把“0 到首个测量值”当成一次真实变化。启用较大 $K_d$ 前，应用层应先用首个有效测量值同时初始化 `Actual` 和 `Actual1`，或跳过第一拍微分。

### 4.3 核心更新函数：位置式 PID + 微分先行

```c
static float PID_Clamp(float x, float min, float max)
{
    if (x > max) return max;
    if (x < min) return min;
    return x;
}

float PID_Update(PID_t *pid)
{
    if (pid == 0) return 0.0f;

    // 1. 更新误差
    pid->Error1 = pid->Error0;
    pid->Error0 = pid->Target - pid->Actual;

    // 2. 积分项：Ki=0 时强制清零，避免残留积分污染输出
    if (pid->Ki != 0.0f)
    {
        pid->ErrorInt += pid->Error0;
        pid->ErrorInt = PID_Clamp(pid->ErrorInt,
                                  pid->ErrorIntMin,
                                  pid->ErrorIntMax);
    }
    else
    {
        pid->ErrorInt = 0.0f;
    }

    // 3. 核心 PID：微分先行，对测量值求差分
    pid->Out = pid->Kp * pid->Error0
             + pid->Ki * pid->ErrorInt
             - pid->Kd * (pid->Actual - pid->Actual1);

    // 4. 死区补偿
    if (pid->Out > 0.0f)
        pid->Out += pid->OutOffset;
    else if (pid->Out < 0.0f)
        pid->Out -= pid->OutOffset;

    // 5. 输出限幅
    pid->Out = PID_Clamp(pid->Out, pid->OutMin, pid->OutMax);

    // 6. 保存本拍测量值，供下一拍微分使用
    pid->Actual1 = pid->Actual;

    return pid->Out;
}
```

这里最值得注意的是微分项：

$$
u_D=-K_d[Actual(k)-Actual(k-1)]
$$

标准公式中常写 $K_d[e(k)-e(k-1)]$，这是对误差微分。工程中经常改为对测量值微分，也叫**微分先行**或 **Derivative on Measurement**。

当目标值 $Target$ 不变时：

$$
e(k)-e(k-1)=[Target-Actual(k)]-[Target-Actual(k-1)]
$$

$$
e(k)-e(k-1)=-[Actual(k)-Actual(k-1)]
$$

所以两种形式本质等价。但当目标值突然变化时，对误差微分会产生一个很大的尖峰输出，称为**微分冲击**；而测量值是连续物理量，不会因为目标值突变而跳变，所以对测量值微分更平滑。

要注意，这段驱动计算的是“每采样拍的差分”，不是带物理单位的变化率。采样周期改变后，即使 $K_p$ 不变，$K_i$、$K_d$ 也需要按新周期重新换算或重新整定。

### 4.4 便捷接口与复位

实际使用时可以写一个便捷函数：

```c
float PID_UpdateValue(PID_t *pid, float target, float actual)
{
    if (pid == 0) return 0.0f;

    pid->Target = target;
    pid->Actual = actual;
    return PID_Update(pid);
}
```

当系统重新启动控制、切换模式、平衡小车倒地后重新扶起时，应清除历史状态：

```c
void PID_Reset(PID_t *pid)
{
    if (pid == 0) return;

    pid->Target = 0.0f;
    pid->Actual = 0.0f;
    pid->Actual1 = 0.0f;
    pid->Out = 0.0f;
    pid->Error0 = 0.0f;
    pid->Error1 = 0.0f;
    pid->ErrorInt = 0.0f;
}
```

注意：复位通常只清零状态，不改 $K_p$、$K_i$、$K_d$ 和限幅参数。这样复位后可以直接重新开始控制。

## 5. PID 工程中必须注意的几个问题

### 5.1 固定采样周期是底线

PID 必须在固定周期内运行，例如每 $5\ \mathrm{ms}$ 或 $10\ \mathrm{ms}$ 执行一次。尤其是 D 项，它本质上依赖"相邻两次数据之间的时间差"。如果这次间隔 $10\ \mathrm{ms}$，下次间隔 $30\ \mathrm{ms}$，同样的物理运动会得到不同的差分值，D 项就会失真。

因此电机控制、平衡小车、姿态控制这类实时系统中，PID 应由硬件定时器、数据就绪事件或严格固定周期的实时任务调度。只有执行时间有明确上界、且不调用阻塞式 HAL 接口的短控制步骤才适合直接放在 ISR 中。

推荐结构：

```text
定时器 / IMU 中断：
    记录节拍或数据就绪事件

固定周期控制任务：
    获取已经就绪的传感器数据
    滤波并执行 PID
    合并输出并更新电机 PWM

主循环 while(1)：
    OLED 显示
    串口打印
    按键扫描
    参数显示
    非实时任务
```

阻塞式 I2C/SPI 读取、OLED、串口打印、文件操作等耗时任务不应放在 ISR 中，也不能让它们破坏 PID 的固定执行周期。若传感器读取本身阻塞，应放在任务上下文，并用定时调度或 DMA 保证数据更新时间。

### 5.2 输出限幅必须有

执行器都有物理极限。电机 PWM 可能只能在 `-1000 ~ +1000`，舵机角度可能只有 `0 ~ 180°`，加热功率也有最大值。如果 PID 算出一个超出硬件范围的输出，必须限幅：

```c
output = PID_Clamp(output, output_min, output_max);
```

输出限幅不仅保护硬件，也让调参更可控。没有限幅的 PID 很容易在启动瞬间给出过大输出，造成过流、机械冲击或系统失控。

### 5.3 积分限幅与抗积分饱和

如果使用 I 项，必须限制积分累加值：

```c
pid->ErrorInt += pid->Error0;
pid->ErrorInt = PID_Clamp(pid->ErrorInt,
                          pid->ErrorIntMin,
                          pid->ErrorIntMax);
```

这正是当前配套驱动采用的策略，但它只是**积分累加限幅**，不是完整的抗积分饱和。执行器输出已经达到 `OutMax/OutMin` 时，`ErrorInt` 仍可能继续向同一方向累加，直到自己的限幅边界。

更进一步的做法是**条件积分**：当输出已经饱和，而且误差还在推动输出继续往饱和方向走时，暂时停止积分；只有输出未饱和，或者误差方向有助于从饱和中恢复时，才继续积分。

简单理解：积分是用来消除小误差的，不是用来在系统已经失控或执行器已经打满时继续堆能量的。

### 5.4 微分项要防噪声

D 项对噪声敏感。如果传感器数值有毛刺，差分后会变成很大的变化率，使电机高频抖动。

常用解决办法有三种：

第一，对测量值做一阶低通滤波，再送入 PID：

```c
float alpha = 0.3f;
filtered = alpha * raw + (1.0f - alpha) * last_filtered;
last_filtered = filtered;
```

这里 $\alpha$ 越大，响应越快但滤波弱；$\alpha$ 越小，滤波强但响应慢。速度环、编码器测速、陀螺仪角速度等信号都常用低通滤波。

`alpha` 不是拍脑袋选的，它对应一阶低通截止频率 $f_c$ 与采样周期 $T$ 的关系：

$$
\alpha \approx \frac{2\pi f_c T}{1+2\pi f_c T}
$$

例如采样周期 $T=10\ \mathrm{ms}$、想滤掉 `20 Hz` 以上的抖动，则 $\alpha \approx \frac{2\pi\times20\times0.01}{1+2\pi\times20\times0.01} \approx 0.56$；想要截止频率更低（更平滑），$f_c$ 取更小值即可。经验上速度环先取 $\alpha \approx 0.2\sim0.5$ 起步，再按"太抖就调小、太迟钝就调大"微调。

第二，采用微分先行，对测量值微分，避免目标值突变造成微分冲击。

第三，减小 $K_d$，或者给 D 项单独加低通滤波。

### 5.5 死区补偿要小心

很多电机在 PWM 很小时不会转，因为有静摩擦、齿轮阻力或驱动死区。死区补偿的做法是：只要 PID 输出不是 0，就额外加一个小偏置。

```c
if (out > 0) out += offset;
else if (out < 0) out -= offset;
```

这样可以帮助电机越过起步死区。但该映射在 0 附近不连续：任意很小的正负输出都会立刻跳到约 `+offset` 或 `-offset`。`offset` 过大时，系统会在目标点附近反复跨零并来回抖动。必要时应配合输出死区、迟滞或最小保持时间，而不是只增大偏置。

## 6. 调参方法：先让系统能动，再让系统稳定

PID 调参没有万能参数。正确思路不是背数字，而是观察响应曲线或物理现象，然后判断问题属于"太慢、超调、振荡、静差、噪声"中的哪一种。

### 6.1 通用手动调参流程

第一步，先只开 P：

```text
Ki = 0
Kd = 0
逐渐增大 Kp
```

观察系统是否能朝目标方向运动。如果方向反了，先调整控制极性，例如把 $K_p$ 取反或修正电机方向。方向没错后，继续增大 $K_p$，直到系统响应明显变快，但还没有不可接受的剧烈振荡。

第二步，加入 I：

```text
在合适 Kp 基础上，从小增加 Ki
```

目标是消除稳态误差。如果系统长期差一点到不了目标，说明需要 I；如果加入 I 后低频振荡、超调明显变大，说明 $K_i$ 太大或积分限幅太宽。

第三步，谨慎加入 D：

```text
在 P / PI 基础上，从小增加 Kd
```

目标是减少超调、增强阻尼。如果加入 D 后电机吱吱响、输出毛刺明显、系统高频抖动，通常是 $K_d$ 太大或测量信号噪声太多。

### 6.2 参数增大时的典型影响

| 参数 | 增大后的好处 | 过大时的问题 |
| --- | --- | --- |
| $K_p$ | 响应更快，误差更小 | 超调、振荡、输出饱和 |
| $K_i$ | 消除静差 | 积分饱和、低频振荡、超调变大 |
| $K_d$ | 抑制超调，提高稳定性 | 放大噪声、高频抖动、响应变钝 |

### 6.3 Ziegler-Nichols 临界比例法

如果系统允许进入等幅振荡，可以用 Ziegler-Nichols 方法得到一组初始参数：

1. 令 $K_i=0$，$K_d=0$。
2. 逐渐增大 $K_p$，直到系统出现持续等幅振荡。
3. 记录此时的临界增益 $K_u$ 和振荡周期 $T_u$。
4. 按经验公式得到初始值。

并联式 PID 常用参考为：

| 控制器 | $K_p$ | $K_i$ | $K_d$ |
| --- | --- | --- | --- |
| P | $0.5K_u$ | - | - |
| PI | $0.45K_u$ | $0.54K_u/T_u$ | - |
| PID | $0.6K_u$ | $1.2K_u/T_u$ | $0.075K_uT_u$ |

注意：这个方法通常偏激进，只适合作为起点，实际还要根据超调、噪声和硬件安全性降参微调。

## 7. 平衡小车中的多环 PID

平衡小车是学习 PID 的典型场景，因为它不是单环系统。一个能稳定站立并按要求前进的小车，通常至少需要直立环、速度环和转向环。

### 7.1 直立环：PD 控制，让车不倒

直立环的目标是让车身角度保持在机械中位附近，例如 $0^\circ$。

- 目标值：机械中位角；
- 测量值：IMU 解算出的俯仰角；
- 输出：左右轮共同的基础 PWM；
- 控制策略：通常用 PD。

P 项根据倾角产生回正力。车往前倒，轮子就应该往前转，用轮子的加速度把车身拉回来；车往后倒，轮子就往后转。

D 项根据角度变化趋势提供阻尼。没有 D 时，单纯 P 很容易让车身越过平衡点，来回大幅摇摆。D 项可以抑制这种过冲。

直立环一般不用 I，因为平衡控制要求实时性很强，积分会带来滞后和累积风险。如果车已经倒地，积分还在累加，扶起来瞬间可能直接暴冲。

### 7.2 速度环：PI 控制，减少漂移并增强抗干扰

只有直立环的小车可能能短暂站住，但会前后漂移。速度环的目标是让轮子的平均速度趋近目标速度。原地平衡时，目标速度通常是 0；需要前进时，目标速度是一个给定值。

- 目标值：目标速度；
- 测量值：左右编码器计算出的平均速度；
- 输出：速度补偿量；
- 控制策略：通常用 PI。

速度环的 I 项可以消除长期速度偏差，减少持续漂移。但速度信号必须滤波，否则编码器测速毛刺会导致输出抖动。

在某些平衡车并联控制写法中，速度环可能表现为正反馈特性：车身向某方向倒时，轮子需要顺着倒的方向加速，从而把车身拉回直立。调试时必须检查极性：方向错了，小车会越控越倒。

### 7.3 转向环：P 或 PD 控制，让车走直或转弯

转向环控制车身航向角，也就是 yaw。

- 目标值：希望保持的航向角，或遥控器给定的转向目标；
- 测量值：IMU 的 yaw 角或角速度；
- 输出：左右轮差速量。

差速分配通常写成：

```c
motor_left_pwm  = average_pwm + differential_pwm / 2;
motor_right_pwm = average_pwm - differential_pwm / 2;
```

其中 `average_pwm` 负责前进/后退和直立，`differential_pwm` 负责左右轮速度差。一个加，一个减，车就能转向。

### 7.4 并联与级联

平衡小车常见两种多环结构。

第一种是并联相加：

```text
直立环输出 + 速度环输出 + 转向环输出 → 合成 PWM
```

这种方式实现简单，适合快速调通。

第二种是级联：

```text
角度环输出目标速度
        ↓
速度环跟踪目标速度，输出 PWM
```

级联结构物理意义更清楚，速度环可以更好地保证内层执行效果，但调参更复杂。一般建议先用并联方式调通方向和基本平衡，再考虑级联优化。

## 8. 平衡小车调参流程

平衡小车调参一定要分环进行，不要一上来把所有环都打开。

### 8.1 先调直立环极性

只保留直立环，令速度环和转向环输出为 0。给一个较小的 $K_p$，轻轻让车身前后倾斜，观察轮子方向。

正确现象是：车身往哪边倒，轮子就往哪边追。这样轮子加速产生的反作用才能把车身拉回。若方向相反，优先调整 PID 参数符号或电机方向。

### 8.2 调直立环 $K_p$

在 $K_d=0$ 的情况下，从小到大增加 $K_p$。

- $K_p$ 太小：轮子无力，小车直接倒下；
- $K_p$ 逐渐合适：车有明显回正趋势，但会大幅低频摇摆；
- $K_p$ 太大：输出接近饱和，车剧烈振荡。

目标不是纯 P 就平衡，而是找到一个"有力但不过分"的 $K_p$ 区间。

### 8.3 调直立环 $K_d$

在合适的 $K_p$ 基础上，从小到大增加 $K_d$。

- $K_d$ 太小：大幅摇摆仍然明显；
- $K_d$ 合适：摇摆被压住，车身接近平衡；
- $K_d$ 过大：出现高频小幅抖动，电机声音变尖，系统对噪声敏感。

调到接近平衡后，不要长时间让车在高频抽搐状态通电，避免电机和驱动过热。

### 8.4 再加入速度环

加入速度环前，建议把已经比较敏感的直立环 $K_p$、$K_d$ 适当降低，例如乘以 $0.6$ 左右，给速度环留出空间。

速度环一般按 PI 调：

1. 先确认速度方向和编码器方向正确；
2. 给较小 $K_p$，观察小车是否漂移减小；
3. 加入较小 $K_i$，让长期漂移逐步消失；
4. 若小车出现前后"走路不稳"的抖动，说明速度环太强，需要减小参数或加强速度滤波。

工程上有些平衡车速度环 $K_p:K_i$ 会按近似比例设置，例如 $K_i=K_p/200$，但这只是经验起点，不能当成固定真理。

### 8.5 最后加入转向环

转向环应在车已经能稳定直立和原地平衡后加入。先用较小 P 控制，让小车能抵抗轻微偏航。若转向过冲明显，可加少量 D 或使用陀螺仪 yaw 角速度作为阻尼。

## 9. 常见故障与判断

| 现象 | 可能原因 | 处理方向 |
| --- | --- | --- |
| 一启动就往更倒的方向冲 | 控制极性反了 | 改 PID 符号或电机方向 |
| 电机完全不动 | PID 未执行、使能未开、误差接近 0、PWM 输出没接上 | 查中断、目标值、输出变量和驱动接口 |
| 输出长期卡在最大值 | 角度偏差太大、$K_p$ 过大、方向反、机械零点错误 | 查零点、限幅、极性，降低参数 |
| 低频大幅摇摆 | $K_p$ 偏大或 $K_d$ 不足 | 降 $K_p$ 或加 $K_d$ |
| 高频小幅抖动 | $K_d$ 过大、传感器噪声大、滤波不足 | 降 $K_d$，加滤波 |
| 加入 I 后失控 | 积分饱和或积分方向错误 | 减小 $K_i$，加积分限幅和 Reset |
| 小车能站但一直漂移 | 速度环太弱或机械中位角不准 | 调速度环，校准平衡角 |
| 加速度环后"走路不稳" | 速度环参数过大或速度滤波不好 | 降速度环，改善滤波 |

## 10. 一个简单的 PID 使用模板

下面是一个通用调用流程，适合放在固定周期控制任务中：

```c
PID_t speed_pid;

void Control_Init(void)
{
    PID_Init(&speed_pid, 2.0f, 0.05f, 0.0f, -1000.0f, 1000.0f);
    speed_pid.ErrorIntMax = 300.0f;
    speed_pid.ErrorIntMin = -300.0f;
}

void Control_Loop_10ms(void)
{
    float target_speed = 100.0f;
    float raw_speed = Encoder_GetSpeed();

    static float filtered_speed = 0.0f;
    filtered_speed = 0.3f * raw_speed + 0.7f * filtered_speed;

    float pwm = PID_UpdateValue(&speed_pid, target_speed, filtered_speed);
    Motor_SetPWM((int16_t)pwm);
}
```

注意这里的 `Control_Loop_10ms()` 必须由定时器或稳定调度触发，不能随便放在执行周期不确定的 `while(1)` 中。

## 11. 一页速记

PID 的本质是把误差转化为控制输出：

$$
u(t)=K_p e(t)+K_i\int e(t)dt+K_d\frac{de(t)}{dt}
$$

P 看现在，误差越大输出越大；I 看过去，误差存在越久修正越强；D 看趋势，变化越快阻尼越强。

单片机里跑的是离散 PID，积分用累加，微分用差分。采样周期必须固定，否则 $K_i$、$K_d$ 的实际意义会变化，D 项也会失真。

实际工程中常用位置式 PID：

```c
Out = Kp * Error0 + Ki * ErrorInt - Kd * (Actual - Actual1);
```

这里 `-Kd * (Actual - Actual1)` 是微分先行，可以避免目标值突变带来的微分冲击。

工程铁律：

- PID 必须固定周期执行；
- 输出必须限幅；
- 使用 I 项必须积分限幅；
- 使用 D 项必须注意噪声和滤波；
- 传感器数据、PID 运算和电机输出应属于同一个受控周期，但阻塞式总线读取不能塞进 ISR；
- OLED、串口打印等耗时任务不要阻塞 PID。

当前配套驱动还要记住三点：`Ki/Kd` 与调用周期绑定；`ErrorInt` 限幅不等于完整抗饱和；首拍测量值不为 0 时需要处理微分初值。

调参顺序：

```text
先确认方向 → 调 P 让系统有力 → 加 I 消除静差 → 加 D 抑制超调
```

平衡小车调参顺序：

```text
直立环极性 → 直立环 P → 直立环 D → 速度环 PI → 转向环 P/PD
```

如果系统越控越偏，先查极性；如果输出一直打满，先查限幅、零点和参数过大；如果系统抖得很快，优先怀疑 D 项过大或传感器噪声；如果加入 I 后暴冲，优先检查积分限幅和积分清零。
