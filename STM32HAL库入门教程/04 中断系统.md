# STM32F103 HAL 库中断系统与 EXTI 教学文档

## 本章闭环

```text
外部电平变化 -> GPIO 输入 -> EXTI 边沿检测 -> 挂起标志
             -> NVIC 优先级裁决 -> CPU 进入 IRQHandler
             -> HAL 回调 -> 更新状态/计数 -> 主循环显示或处理
```

本章以 STM32F103C8T6、STM32CubeMX 和 HAL 库为对象，重点学习外部中断（EXTI）。示例来自两个典型应用：对射式红外传感器计次，以及使用 A/B 两相信号判断旋转编码器方向。具体引脚、IRQ 分组和外设资源仍应以芯片数据手册、开发板原理图和 CubeMX 实际配置为准。

## 1. 学习目标与准备

完成本章后，应能够：

- 解释中断相对于轮询的价值，以及 CPU 处理中断的基本过程；
- 区分中断源、EXTI 线路、NVIC、IRQHandler 和 HAL 回调；
- 在 CubeMX 中配置 GPIO 外部中断、触发边沿和 NVIC 优先级；
- 使用 `HAL_GPIO_EXTI_Callback()` 编写红外传感器计次程序；
- 根据旋转编码器 A/B 两相电平判断顺时针与逆时针；
- 处理机械抖动、重复触发、共享 IRQ 和计数变量并发访问等问题；
- 用“接线 -> 电平 -> 触发边沿 -> IRQ -> 回调 -> 应用状态”的链路排查故障。

准备：STM32F103C8T6 开发板、ST-LINK、CubeMX、Keil MDK、OLED（可选）、对射式红外传感器模块、普通增量式旋转编码器、杜邦线和示波器或逻辑分析仪（可选）。

## 2. 为什么需要中断

### 2.1 轮询的局限

轮询是在主循环中反复读取输入：

```c
while (1)
{
    if (HAL_GPIO_ReadPin(GPIOB, GPIO_PIN_14) == GPIO_PIN_RESET)
    {
        count++;
    }
}
```

这种写法有两个问题：

1. 一个持续的低电平会被循环读取很多次，难以区分“一次事件”和“保持状态”；
2. 主循环被延时、显示刷新或其他任务占用时，短脉冲可能完全错过。

中断把“发生事件时才处理”交给硬件。主程序可以继续执行其他任务，输入边沿到来时由硬件通知 CPU。

### 2.2 中断的基本过程

```text
主程序运行
    |
    | 发生满足条件的外部边沿
    v
EXTI 置位挂起标志 -> NVIC 判断是否允许响应 -> 保存现场并跳入 IRQHandler
                                                    |
                                                    v
                                             HAL 处理并进入回调
                                                    |
                                                    v
                                             清除/确认标志后返回主程序
```

中断服务代码应尽量短：记录事件、读取必要电平、修改计数或置位标志即可。OLED 刷新、串口打印、复杂计算和长时间延时放到主循环或任务中完成。

### 2.3 中断嵌套与优先级

如果一个中断正在执行，更高优先级的中断可以抢占它，形成中断嵌套。STM32 的 NVIC 使用“优先级编号越小，优先级越高”的规则：`0` 比 `3` 更紧急。

优先级通常分成两部分：

- **抢占优先级**：决定能否打断当前正在运行的中断；
- **响应（子）优先级**：多个同级抢占优先级同时挂起时，决定先后顺序。

优先级分组决定这两部分各占多少位。入门工程只有一个外部中断时，使用默认分组和同一优先级即可；不要为了“优先级更高”随意把所有中断设为 `0`，应先明确实时性需求。

## 3. EXTI 的硬件信号链

### 3.1 EXTI 解决什么问题

EXTI（External Interrupt/Event Controller）监听 GPIO 或其他片上信号的变化，把指定边沿转换成中断请求。对 STM32F1 来说，一个 EXTI 线路通常对应一个引脚编号：`PA0`、`PB0`、`PC0` 都属于 `EXTI0`，但同一时刻只能选择其中一个端口连接到该线路。

```text
GPIO 端口选择（AFIO）
        |
        v
指定 EXTI 线路 -> 上升沿/下降沿检测 -> 中断屏蔽与挂起标志 -> NVIC
```

STM32F1 手册中常出现 AFIO 端口选择和重映射术语；在 CubeMX/HAL 工程中，通常直接在 GPIO 的 `GPIO_EXTI` 模式下完成这些配置。

### 3.2 四种常见触发来源

- **上升沿触发**：`0 -> 1` 时触发；
- **下降沿触发**：`1 -> 0` 时触发；
- **双边沿触发**：任意电平变化都触发；
- **软件触发**：程序通过 EXTI 软件事件/中断寄存器产生请求。

触发边沿必须和传感器输出逻辑配套。例如红外模块常见“遮挡时输出低电平”，若只想在遮挡开始计数，就选择下降沿；若模块有效电平相反，则应选择上升沿。

### 3.3 事件与中断不是一回事

EXTI 检测到边沿后，可以产生事件，也可以向 NVIC 产生中断请求。事件适合触发其他硬件动作，不一定进入 CPU；本章的计次和编码器示例需要 CPU 执行应用代码，因此启用的是中断路径。

## 4. CubeMX 配置与 HAL 代码入口

### 4.1 GPIO 配置步骤

以 `PB14` 接红外模块数字输出为例：

1. 在 Pinout 中将 `PB14` 设置为 `GPIO_EXTI14`；
2. 根据模块空闲电平选择 `Pull-up`、`Pull-down` 或 `No pull`；
3. 在 GPIO 参数中选择 `Rising`、`Falling` 或 `Rising/Falling`；
4. 在 `System Core -> NVIC` 中勾选对应 IRQ（`EXTI15_10_IRQn`）；
5. 设置抢占优先级和响应优先级；
6. 生成代码，并只在 `USER CODE BEGIN/END` 区域添加用户逻辑。

`PB0` 和 `PB1` 则分别对应 `EXTI0_IRQn`、`EXTI1_IRQn`。多个线路可能共享一个 IRQ，例如 `EXTI10~15` 共用 `EXTI15_10_IRQHandler`。

### 4.2 HAL 的三层入口

CubeMX 通常生成如下结构：

```c
void EXTI15_10_IRQHandler(void)
{
    /* 共享 IRQ 中逐条交给 HAL 处理可能挂起的线路。 */
    HAL_GPIO_EXTI_IRQHandler(GPIO_PIN_14);
}
```

`HAL_GPIO_EXTI_IRQHandler()` 会判断并清除指定线路的挂起标志，然后调用用户回调：

```c
void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin)
{
    if (GPIO_Pin == GPIO_PIN_14)
    {
        /* 用户逻辑：尽量短。 */
    }
}
```

在共享 IRQ 中，应为每一条可能触发的引脚调用一次 `HAL_GPIO_EXTI_IRQHandler()`，否则某些线路的挂起标志不会被处理。不要直接把业务代码塞进自动生成的 IRQ 函数中，以免重新生成工程时被覆盖。

### 4.3 共享状态的声明

中断回调和主循环共同访问的变量应声明为 `volatile`，告诉编译器该变量可能在当前执行流之外被修改：

```c
static volatile int32_t g_count = 0;
```

在 Cortex-M3 上，单次读写对齐的 32 位变量通常是原子的，但“读取并清零”“读取后再计算”等复合操作仍可能与中断交错。需要一致快照时，可短暂关闭中断或采用事件队列；不要在中断中调用阻塞函数。

## 5. 实验一：对射式红外传感器计次

### 5.1 实验目标与接线

传感器由红外发射端和接收端组成。物体经过光路时，接收端输出发生变化，模块的 `DO`（数字输出）接到 `PB14`。常见接线为：

```text
传感器 VCC -> 3.3 V（按模块规格确认）
传感器 GND -> GND
传感器 DO  -> PB14
```

本实验假设“无遮挡为高电平、遮挡为低电平”，在下降沿计数一次。若实测逻辑相反，只需把触发边沿和判断条件一起反向。

### 5.2 代码实现

在 `main.c` 的用户区声明计数变量和读取函数：

```c
static volatile uint32_t g_ir_count = 0U;

uint32_t IR_GetCount(void)
{
    return g_ir_count;
}
```

在 `HAL_GPIO_EXTI_Callback()` 中响应 `PB14`：

```c
void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin)
{
    if (GPIO_Pin == GPIO_PIN_14)
    {
        /* 回调只记录事件，避免在中断上下文中阻塞。 */
        g_ir_count++;
    }
}
```

主循环只负责显示或进一步处理：

```c
while (1)
{
    OLED_ShowNum(1, 1, IR_GetCount(), 6);
    HAL_Delay(50U);
}
```

### 5.3 为什么“一次遮挡”可能计两次

原始演示中出现“手移动快时一次，慢时两次”的现象，这通常不是 CPU 随机出错，而是以下因素之一：

1. 物体边缘使光路经历多次 `高 -> 低 -> 高 -> 低`；
2. 传感器比较器阈值附近抖动，导致一个遮挡产生多个下降沿；
3. 模块输出端或接线受到干扰；
4. 没有设置最小事件间隔。

若业务含义是“每个物体只计一次”，可以在回调中加入简单时间门限。时间来自 HAL Tick，因此不需要在中断中延时：

```c
static volatile uint32_t g_ir_count = 0U;
static volatile uint32_t g_last_tick = 0U;

void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin)
{
    if (GPIO_Pin == GPIO_PIN_14)
    {
        uint32_t now = HAL_GetTick();

        /* 用无符号减法处理 HAL Tick 回绕；门限按实际速度调整。 */
        if ((uint32_t)(now - g_last_tick) >= 20U)
        {
            g_ir_count++;
            g_last_tick = now;
        }
    }
}
```

这个方法只适合事件间隔明显大于 `20 ms` 的低速计次。高速计数应优先使用传感器硬件滤波、定时器输入捕获或外部计数功能，并根据被测对象速度重新设计门限。

### 5.4 方法提示

不要在 EXTI 回调中刷新 OLED、调用 `HAL_Delay()` 或打印长字符串。回调应完成“确认是哪根线 -> 记录事件”，主循环完成“显示计数 -> 更新界面”。这能减少中断占用时间，也避免阻塞其他中断。

## 6. 实验二：旋转编码器判向与计数

### 6.1 增量式编码器的 A/B 两相

普通机械增量编码器通常有 `VCC`、`GND`、`A`、`B` 和一个按键公共端。A、B 两路方波相差约四分之一周期：

```text
顺时针（示意）：A: __--__--__
                 B: ____--__--

逆时针（示意）：B 相对 A 提前，电平相位关系相反
```

判断方向的关键不是“看某一路变高”，而是：在 A 相发生指定边沿的瞬间读取 B 相电平。若约定 A 下降沿时 `B=1` 表示顺时针，则 `B=0` 表示逆时针；若接线或编码器型号不同，方向符号可能相反，应通过实测校准。

### 6.2 CubeMX 配置

以 `PB0=A`、`PB1=B` 为例：

- `PB0` 设置为 `GPIO_EXTI0`，选择下降沿触发；
- `PB1` 设置为 `GPIO_EXTI1`，也可选择下降沿触发；
- 两路使用合适的上拉或下拉，保证旋钮静止时电平确定；
- 勾选 `EXTI0_IRQn` 和 `EXTI1_IRQn`；
- 若机械抖动严重，优先启用 GPIO/外部滤波，或在软件中加入状态机。

只监听 A 相的一种边沿可以实现简单的 x1 解码，CPU 负担较小；监听双边沿或 A、B 两路可以提高分辨率，但也更容易受到抖动影响。

### 6.3 HAL 回调实现

```c
static volatile int16_t g_encoder_count = 0;

void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin)
{
    if (GPIO_Pin == GPIO_PIN_0)
    {
        GPIO_PinState b = HAL_GPIO_ReadPin(GPIOB, GPIO_PIN_1);

        if (b == GPIO_PIN_SET)
        {
            g_encoder_count++;
        }
        else
        {
            g_encoder_count--;
        }
    }
}

int16_t Encoder_GetCount(void)
{
    return g_encoder_count;
}
```

这里仅使用 A 相下降沿作为“计数时刻”，B 相只作为方向信息。若同时给 B 相配置 EXTI，应明确两路回调的计数规则，不能简单地让 A、B 两路都各自加减，否则一次机械动作可能被放大为两次或更多次。

主循环可以把有符号计数显示在 OLED 上：

```c
while (1)
{
    int16_t count = Encoder_GetCount();
    OLED_ShowSignedNum(1, 1, count, 5);
    HAL_Delay(20U);
}
```

### 6.4 机械抖动与稳定解码

机械编码器的触点不是理想方波。一个边沿附近可能出现多个快速跳变，导致计数抖动。可按需求选择：

1. **时间门限**：两次有效边沿必须间隔一定时间，适合低速旋钮；
2. **四状态状态机**：只接受合法的 Gray code 状态转移，能过滤部分非法跳变；
3. **定时器编码器模式**：由硬件完成 A/B 相计数，适合较高频率和连续转动；
4. **硬件 RC/施密特整形**：从信号源头降低毛刺和慢边沿影响。

时间门限不是万能方案：门限过大时，快速旋转会漏计数；门限过小时，抖动仍可能通过。应先用示波器观察实际波形，再决定滤波策略。

## 7. EXTI 与定时器编码器模式如何选择

| 需求 | GPIO EXTI | 定时器编码器模式 |
| --- | --- | --- |
| 学习中断流程、低速按键/传感器 | 合适 | 过于复杂 |
| 只需检测单个边沿并执行动作 | 合适 | 不必要 |
| A/B 相高速连续计数 | 容易占用 CPU，需软件消抖 | 更合适 |
| 需要精确 x1/x2/x4 解码 | 需自行设计状态机 | 硬件支持更完整 |
| 需要同时执行复杂主循环任务 | 可能漏事件 | 硬件计数更稳 |

EXTI 的价值在于理解“事件到来 -> CPU 响应”的完整链路；当脉冲频率提高后，应把计数工作交给定时器、输入捕获或外部时钟，而不是无限增加中断频率。

## 8. 常见故障诊断

### 8.1 回调没有进入

按以下顺序检查：

1. GPIO 是否真的配置成 `GPIO_EXTI`，而不是普通输入；
2. 触发边沿是否与实测电平变化一致；
3. 对应 NVIC IRQ 是否启用；
4. `stm32f1xx_it.c` 中是否调用了正确的 `HAL_GPIO_EXTI_IRQHandler()`；
5. 传感器和开发板是否共地，输入是否悬空；
6. 是否把业务代码误写在自动生成代码之外并被重新生成覆盖。

### 8.2 计数加倍或随机

优先怀疑边沿抖动、传感器阈值抖动、编码器触点抖动和回调中重复处理。确认“一个物理事件对应几个有效边沿”，再决定使用下降沿、双边沿、时间门限还是状态机。

### 8.3 共享 IRQ 处理不完整

例如 `EXTI10~15` 共用一个 IRQ。若只调用 `HAL_GPIO_EXTI_IRQHandler(GPIO_PIN_14)`，而 `PB13` 也可能触发，就需要同时处理 `GPIO_PIN_13`。否则另一条线路的挂起标志可能一直保留，造成后续响应异常。

### 8.4 中断中程序卡死

禁止在 EXTI 回调中调用 `HAL_Delay()`、等待串口发送完成、刷新整屏 OLED 或执行长循环。应在回调中设置标志：

```c
static volatile uint8_t g_event_pending = 0U;

void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin)
{
    if (GPIO_Pin == GPIO_PIN_14)
    {
        g_event_pending = 1U;
    }
}

while (1)
{
    if (g_event_pending != 0U)
    {
        g_event_pending = 0U;
        /* 在主循环中执行耗时处理。 */
    }
}
```

### 8.5 中断变量读写异常

确认共享变量已声明为 `volatile`，类型和符号范围足够，且主循环没有在中断可能到来的同时执行不完整的复合更新。计数器可能正负变化时，不要使用 `uint16_t` 代替带符号类型。

## 9. 综合自测

### 题 1：轮询与中断

为什么一个持续低电平不适合直接在轮询中 `count++`？

**答案**：主循环会在低电平保持期间重复执行，无法把“保持状态”区分为“一次事件”。应检测边沿、状态变化或使用 EXTI 在边沿到来时记录一次。

### 题 2：EXTI 线路冲突

为什么 `PA0` 和 `PB0` 不能同时作为两个独立的 `EXTI0` 输入？

**答案**：它们共享同一条 EXTI0 线路，AFIO 只能选择一个端口连接到该线路。若需要同时使用，应改用不同引脚编号或其他硬件资源。

### 题 3：优先级判断

在 NVIC 中，优先级数值 `1` 和 `3` 哪个更高？

**答案**：`1` 更高。Cortex-M 的优先级编号越小，抢占能力越强；`0` 是最高优先级。

### 题 4：红外计次

红外模块空闲时为高电平、遮挡时为低电平，想在遮挡开始计数，应选择什么边沿？

**答案**：选择下降沿，因为遮挡开始对应 `1 -> 0`。还要确认模块输出是否真的符合该电平逻辑。

### 题 5：旋转编码器

在 A 相下降沿进入回调时，为什么还要读取 B 相？

**答案**：A 相边沿只说明“发生了一个相位事件”，B 相的电平决定两路信号的相位先后，从而判断旋转方向。

### 题 6：中断服务函数

为什么不应在 EXTI 回调中直接刷新 OLED？

**答案**：OLED 刷新通常包含较长的 I2C/SPI 传输，会延长中断占用时间，阻塞其他中断并增加丢事件风险。回调只记录事件，显示放在主循环中。

## 本章小结

中断系统的核心不是“把代码放进回调”，而是建立完整的事件链：

```text
确定输入电平 -> 选择触发边沿 -> EXTI 检测 -> NVIC 排队/抢占
-> IRQHandler 清除标志 -> HAL 回调记录事件 -> 主循环完成耗时工作
```

对射式红外传感器展示了“单路边沿计次”；旋转编码器展示了“边沿触发 + 读取另一相电平判向”。当速度、频率或可靠性要求提高时，应从 EXTI 逐步迁移到定时器输入捕获、编码器接口或外部时钟模式。最终排错仍回到同一条链路：先确认真实波形，再核对 GPIO 模式、触发边沿、NVIC、IRQHandler、回调和共享状态。
