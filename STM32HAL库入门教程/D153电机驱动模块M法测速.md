# D153 编码器 M 法测速：定时器编码器模式

这一节只讲 D153 模块的 **M 法测速**：让定时器工作在编码器模式，固定周期读取计数增量，再把增量换算成输出轴转速。

M 法测速链路如下：

```text
电机转动
→ 编码器 A/B 相
→ TIM 编码器模式正反计数
→ 固定周期采样 delta
→ delta / dt
→ rps / rpm
```

电机驱动层见 [[28.1 D153电机驱动模块]]。输入捕获 T 法测速见 [[28.3 D153输入捕获T法测速]]。

- `d153c_speed_m_sample(id, dt_ms)` 的 `dt_ms` 应该填什么？
- 什么时候该先看 `delta`，什么时候再看 `rps`？
- M 法测速和 T 法测速适合的速度范围有什么不同？

## 1. M 法测速的基本思想

M 法也叫**计数法**。它不直接测相邻脉冲间隔，而是在一个固定时间窗里数脉冲。

```text
固定时间内数到多少个编码器计数
→ 数得越多，速度越快
→ 数得越少，速度越慢
```

假设采样周期为 $dt$，这段时间内编码器增量为 `delta`，则：

$$
\text{速度} = \frac{\text{这段时间转过的圈数}}{\text{这段时间长度}}
$$

M 法的关键不是公式复杂，而是**采样周期必须稳定**。

## 2. CubeMX 配置

D153 的 M 法测速需要两类定时器资源：

- 编码器定时器：读取 A/B 相正交编码器计数
- 基准定时器：提供固定周期采样节拍

当前驱动库默认映射在 `d153c_speed_m.h` 中（完整驱动源码位于 `E:\ProjectStm\驱动库\D153C` 的 `d153c_speed_m.c` / `d153c_speed_m.h`）：

```c
#define D153C_M_A_ENC_TIM    (&htim2)
#define D153C_M_A_TIM_32BIT  false

#define D153C_M_B_ENC_TIM    (&htim4)
#define D153C_M_B_TIM_32BIT  false
```

这里的 `TIM_32BIT` 说的是**当前工程的计数回绕口径**，不是只看芯片手册上的理论位宽。STM32F103 的 TIM2 硬件可以是 32 位，但当前工程把 TIM2、TIM4 的 `ARR` 都设为 `65535`，驱动也按 16 位模回绕计算，所以两个宏有意设为 `false`。

16 位分支实际执行的是带符号模差：

```c
delta = (int32_t)(int16_t)(uint16_t)(now - last);
```

它能自动处理一次回绕，但有一个必要条件：每个采样周期内的真实计数增量绝对值必须小于 `32768`。达到或超过半个模数后，正反方向会产生歧义；应缩短采样周期，或在计数范围和驱动宏都正确配置后改用 32 位口径。

这个条件换算成物理量可以直观感受量级：四倍频下电机轴每圈 `13 × 4 = 52` 个计数，`32768` 计数对应约 `630` 个电机轴圈（输出轴 `1560` 计数/圈，即约 `21` 个输出轴圈）。即使采样周期长达 `10 ms`，也要电机轴平均转速超过 `63000 rps ≈ 380 万 rpm` 才会触及上限——MG513 这类减速电机物理上远达不到，因此该边界在工程上不会触发，知道"半模数歧义"这个原理即可。

### 2.1 TIM2 / TIM4：编码器模式

两路电机各需要一个定时器工作在 Encoder Mode：

- `TIM2`：A 电机编码器
- `TIM4`：B 电机编码器

CubeMX 要点：

- Combined Channels 选择 `Encoder Mode`
- A/B 两相信号分别接入对应的 `CH1`、`CH2`
- Counter Period 尽量设到最大
- 输入滤波视编码器信号质量设置，抖动明显时适当加滤波

定时器编码器模式会根据 A/B 相位自动判断方向，因此计数器可以正反变化。

### 2.2 TIM1：固定周期采样节拍

测速采样不能依赖 `while (1)` 里的 `HAL_Delay()`。建议用基础定时器提供固定周期。

当前工程常用做法：

| 参数 | 值 |
| --- | --- |
| 定时器 | `TIM1` |
| 时钟 | 72 MHz |
| PSC | 71 |
| Period | 999 |
| 中断周期 | 1 ms |

计算过程：

$$
f_{\text{cnt}} = \frac{72\ \mathrm{MHz}}{71 + 1} = 1\ \mathrm{MHz}
$$

再配合 `Period = 999`：

$$
f_{\text{update}} = \frac{1\ \mathrm{MHz}}{999 + 1} = 1\ \mathrm{kHz}
$$

也就是每 1 ms 进一次中断。如果每 10 次中断调用一次采样函数，就得到 10 ms 采样周期。

## 3. 输出轴一圈对应多少计数

D153 笔记采用的参数口径如下：

| 参数 | 数值 | 含义 |
| --- | --- | --- |
| `D153C_PPR` | 13 | 电机本体转一圈，编码器产生 13 个脉冲 |
| `D153C_MULTIPLE` | 4 | 定时器编码器模式按 A/B 相四倍频计数 |
| `D153C_REDUCTION` | 30 | 减速比 30:1，电机转 30 圈，输出轴转 1 圈 |

所以输出轴转一圈对应：

$$
13 \times 4 \times 30 = 1560
$$

也就是说：

- `delta = 1560`：输出轴转了 1 圈
- `delta = 780`：输出轴转了半圈
- `delta = 156`：输出轴转了 0.1 圈

这个 `1560` 只适用于**编码器模式四倍频 M 法计数口径**。如果改成 T 法输入捕获，计数口径通常不是四倍频，不能直接套用。

## 4. 速度换算公式

设某次采样周期内，编码器增量为 `delta`，采样周期是 `dt_ms` 毫秒。

先把计数换成输出轴圈数：

$$
\text{圈数} = \frac{delta}{1560}
$$

再除以时间：

$$
v_{\mathrm{rps}} = \frac{delta / 1560}{dt_{\text{ms}} / 1000}
$$

整理得到：

$$
v_{\mathrm{rps}} = delta \times \frac{1000}{1560 \times dt_{\text{ms}}}
$$

如果采样周期固定为 10 ms：

$$
v_{\mathrm{rps}} = delta \times \frac{1000}{1560 \times 10} = \frac{delta}{15.6}
$$

| `delta` | 输出轴速度 |
| --- | --- |
| `16` | 约 `1.0 r/s` |
| `31` | 约 `2.0 r/s` |
| `78` | 约 `5.0 r/s` |
| `-16` | 约 `-1.0 r/s` |
| `0` | `0 r/s` |

## 6. 推荐调用方式

### 6.1 初始化

```c
#include "d153c_motor.h"
#include "d153c_speed_m.h"

int main(void)
{
    HAL_Init();
    SystemClock_Config();

    MX_GPIO_Init();
    MX_TIM1_Init();
    MX_TIM2_Init();
    MX_TIM3_Init();
    MX_TIM4_Init();

    d153c_motor_init();
    d153c_speed_m_init();

    HAL_TIM_Base_Start_IT(&htim1);

    d153c_motor_drive(D153C_MOTOR_A, 300);
    d153c_motor_drive(D153C_MOTOR_B, 300);

    while (1)
    {
    }
}
```

### 6.2 固定周期采样

```c
#define SAMPLE_MS  10.0f

void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim)
{
    static uint32_t divider = 0;

    if (htim->Instance == TIM1)
    {
        if (++divider >= 10)
        {
            divider = 0;
            d153c_speed_m_sample(D153C_MOTOR_A, SAMPLE_MS);
            d153c_speed_m_sample(D153C_MOTOR_B, SAMPLE_MS);
        }
    }
}
```

注意：

```text
d153c_speed_m_sample() 的 dt_ms 不是你希望的周期，
而是这个函数真实被调用的周期。
```

如果 TIM1 每 1 ms 中断一次，累计 10 次后采样，那么 `dt_ms` 就应该填 `10.0f`。

`sample()` 在中断中更新 `delta` 和 `rps`，主循环读取时要注意共享状态。单独读取一个对齐的 32 位值通常不会被撕裂，但若要让 `delta`、`rps` 和时间戳属于同一次采样，应在短临界区内复制快照，或由应用层用序号/双缓冲完成一致性交接。

## 7. 为什么不要用 HAL_Delay 测速

错误写法：

```c
while (1)
{
    d153c_speed_m_sample(D153C_MOTOR_A, 10.0f);
    HAL_Delay(10);
}
```

问题在于 `HAL_Delay(10)` 只保证“大约至少 10 ms”，实际一轮循环还包含：

- `d153c_speed_m_sample()` 自身执行时间
- 主循环其他代码的执行时间
- 中断打断带来的抖动

你填了 `10.0f`，不代表真实周期就是 10 ms。周期不准，速度结果就会抖。

## 8. 方向和符号修正

先区分两个问题：

```text
电机物理方向反了 → d153c_motor_invert()
速度反馈符号反了 → d153c_speed_m_invert_encoder()
```

如果电机已经按预期方向转动，但 `delta` 和 `rps` 的正负号相反，用：

```c
d153c_speed_m_invert_encoder(D153C_MOTOR_A, true);
```

调试时不要一上来同时改电机方向和编码器方向，否则很容易把问题越调越乱。

推荐顺序：

```text
先低速转动
→ 看物理方向
→ 看 delta 正负
→ 最后看 rps 数值
```

## 9. 调试优先看 delta

调试早期不要直接盯着 `rps`。先看 `delta`，因为它最接近原始编码器计数。

如果 `delta` 都不对，那么：

- 方向修正没意义
- 速度换算没意义
- 闭环控制更没意义

常用观察代码：

```c
volatile int32_t da = 0;
volatile int32_t db = 0;
volatile float ra = 0.0f;
volatile float rb = 0.0f;

void update_speed_debug(void)
{
    da = d153c_speed_m_delta(D153C_MOTOR_A);
    db = d153c_speed_m_delta(D153C_MOTOR_B);
    ra = d153c_speed_m_rps(D153C_MOTOR_A);
    rb = d153c_speed_m_rps(D153C_MOTOR_B);
}
```

## 10. M 法特点

M 法适合中高速测速，因为固定时间窗内能数到足够多的脉冲。

| 速度范围 | 表现 |
| --- | --- |
| 低速 | 一个采样窗里可能只有 0 或少量计数，量化误差明显 |
| 中高速 | 每个采样窗内计数较多，结果稳定 |
| 极高速 | 编码器计数硬件还能承受，但采样周期和控制周期要合理选择 |

低速时，如果 10 ms 内只数到 0、1、2 个计数，换算出来的速度会跳。这不是公式错，而是 M 法在低速下的分辨率限制。

低速测速更适合用 T 法：测相邻脉冲间隔，见 [[28.3 D153输入捕获T法测速]]。

## 11. 常见故障

| 现象 | 优先检查项 |
| --- | --- |
| `delta` 一直为 0 | 编码器供电、A/B 相接线、共地、TIM 是否真是 Encoder Mode |
| `delta` 正负反了 | 调 `d153c_speed_m_invert_encoder()` |
| `rps` 整体偏大或偏小 | `D153C_PPR`、`D153C_MULTIPLE`、`D153C_REDUCTION`、`dt_ms` 是否正确 |
| 速度明显抖动 | 是否用硬件定时器固定采样周期，采样周期是否太短 |
| A 电机正常，B 电机异常 | 分别检查 TIM2/TIM4 映射和计数器位宽宏 |

可以打印定时器计数器做自检：

```c
printf("TIM2 CNT=%ld TIM4 CNT=%ld\n",
       (long)__HAL_TIM_GET_COUNTER(&htim2),
       (long)__HAL_TIM_GET_COUNTER(&htim4));
```

手动转动车轮时，如果计数器没有变化，先排查硬件接线和 CubeMX 编码器模式配置。

## 12. 一页速记

- M 法测速：在固定时间窗内数编码器增量 `delta`。
- 适合中高速，因为单位时间内能数到足够多的脉冲。
- 固定周期采样很关键，推荐用硬件定时器触发，不要用 `HAL_Delay()` 凑周期。
- 输出轴一圈计数要把 PPR、倍频和减速比一起算进去。
- 16 位模差成立的前提是每次真实增量绝对值小于 `32768`；TIM2 硬件位宽不能替代当前 `ARR` 和驱动口径。
- 速度符号反了，优先用方向反转接口修正，不要先改公式。
- 中断更新、主循环读取多个测速量时，应先复制一致快照。
- 低速时跳动明显通常是 M 法分辨率限制，可改用 T 法或加滤波。
