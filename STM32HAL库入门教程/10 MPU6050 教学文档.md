# STM32 HAL 库 MPU6050 教学文档

## 1. 学完以后能做什么

完成本文后，你应该能够：

- 说明 MPU6050 的三轴加速度计、三轴陀螺仪和温度传感器分别输出什么数据。
- 区分 7 位 I2C 地址、HAL 使用的左移后地址和 `WHO_AM_I` 设备标识。
- 看懂 `mpu6050.c` 与 `mpu6050.h` 的职责，以及驱动保存的运行时状态。
- 按复位、唤醒、时钟、滤波、采样率和量程的顺序完成初始化。
- 从 `ACCEL_XOUT_H` 开始连续读取 14 字节，并将大端数据还原为 `int16_t`。
- 根据当前量程把原始值换算为 `g`、`°/s` 和 `℃`。
- 使用驱动 API 完成初始化、读取、量程切换和错误判断。
- 按总线、设备识别、初始化、原始数据和物理量的顺序定位常见问题。
- 说明轮询式单实例驱动的边界，并判断何时需要校准、中断、FIFO 或多实例支持。

本文基于 `mpu6050.c` 和 `mpu6050.h` 展开，源码位于 `E:\ProjectStm\驱动库\MPU6050`。当前驱动采用阻塞式 I2C 和单实例状态，适合先建立寄存器配置、数据读取与单位换算的最小闭环；FIFO、DMP 姿态解算、轴重映射等高级功能不在本文范围内。

## 2. 对外类型与数据结构

### 2.1 状态码

`mpu6050.h` 用枚举统一表示初始化、通信和参数检查结果：

```c
typedef enum
{
    MPU6050_OK = 0,
    MPU6050_ERROR = -1,
    MPU6050_NOT_FOUND = -2,
    MPU6050_INVALID_ARG = -3,
} MPU6050_Status;
```

错误码含义如下：

| 错误码 | 含义 |
| --- | --- |
| `MPU6050_OK` | 操作成功 |
| `MPU6050_ERROR` | I2C 读写失败或初始化过程中某一步失败 |
| `MPU6050_NOT_FOUND` | 未找到 MPU6050，或 `WHO_AM_I` 不正确 |
| `MPU6050_INVALID_ARG` | 传入空指针或非法参数 |

### 2.2 原始数据与物理量

头文件定义了两类数据结构：

```c
typedef struct
{
    int16_t accel_x;
    int16_t accel_y;
    int16_t accel_z;
    int16_t temp;
    int16_t gyro_x;
    int16_t gyro_y;
    int16_t gyro_z;
} MPU6050_AccelGyroRaw;
```

`MPU6050_AccelGyroRaw` 保存直接从寄存器读出的原始数据，单位是 LSB，也就是传感器 ADC 输出的数字量。

```c
typedef struct
{
    float ax_g;
    float ay_g;
    float az_g;
    float temperature_c;
    float gx_dps;
    float gy_dps;
    float gz_dps;
} MPU6050_Data;
```

`MPU6050_Data` 保存转换后的物理量：

| 字段 | 含义 | 单位 |
| --- | --- | --- |
| `ax_g` | X 轴加速度 | g |
| `ay_g` | Y 轴加速度 | g |
| `az_g` | Z 轴加速度 | g |
| `temperature_c` | 温度 | ℃ |
| `gx_dps` | X 轴角速度 | °/s |
| `gy_dps` | Y 轴角速度 | °/s |
| `gz_dps` | Z 轴角速度 | °/s |

`dps` 是 degrees per second 的缩写，即度每秒。

## 3. 驱动内部状态：为什么这些变量是 static

`mpu6050.c` 开头定义了若干静态全局变量：

```c
static I2C_HandleTypeDef *mpu_i2c = NULL;
static uint8_t mpu_address = (MPU6050_ADDR_LOW_7BIT << 1);
static MPU6050_Device mpu_device = MPU6050_DEVICE_UNKNOWN;
static float accel_lsb_per_g = 8192.0f;
static float gyro_lsb_per_dps = 65.5f;
```

这些变量构成了驱动的运行时状态。

### 3.1 `mpu_i2c`

```c
static I2C_HandleTypeDef *mpu_i2c = NULL;
```

它保存用户传入的 STM32 HAL I2C 句柄。后续所有 I2C 读写都通过这个句柄完成。

这意味着驱动本身不负责初始化 I2C 外设。I2C 时钟、GPIO、上拉电阻、外设参数等都需要用户在调用 `MPU6050_Init()` 之前配置好。

### 3.2 `mpu_address`

```c
static uint8_t mpu_address = (MPU6050_ADDR_LOW_7BIT << 1);
```

它保存当前使用的 I2C 设备地址。

MPU6050 的 7 位 I2C 地址通常是：

| AD0 引脚电平 | 7 位地址 |
| --- | --- |
| 低 | `0x68` |
| 高 | `0x69` |

代码中保存的是左移一位后的 8 位地址：

```c
mpu_address = (uint8_t)(address_7bit << 1);
```

例如：

```text
0x68 << 1 = 0xD0
0x69 << 1 = 0xD2
```

STM32 HAL 的 I2C 接口通常要求传入 8 位形式的设备地址，最低位由 HAL 在具体读写操作中设置。因此驱动内部统一保存左移后的地址。

### 3.3 `mpu_device`

```c
static MPU6050_Device mpu_device = MPU6050_DEVICE_UNKNOWN;
```

它表示当前识别到的设备类型。当前代码只识别一种设备：

```c
typedef enum
{
    MPU6050_DEVICE_UNKNOWN = 0,
    MPU6050_DEVICE_MPU6050,
} MPU6050_Device;
```

设备类型来自 `WHO_AM_I` 寄存器。

### 3.4 `accel_lsb_per_g` 和 `gyro_lsb_per_dps`

```c
static float accel_lsb_per_g = 8192.0f;
static float gyro_lsb_per_dps = 65.5f;
```

这两个变量保存当前量程对应的灵敏度。

默认值对应：

- 加速度计量程：±4 g；
- 陀螺仪量程：±500 °/s。

这与初始化代码中的默认配置一致：

```c
MPU6050_SetGyroRange(MPU6050_GYRO_RANGE_500DPS)
MPU6050_SetAccelRange(MPU6050_ACCEL_RANGE_4G)
```

当用户调用量程设置函数时，这两个静态变量会同步更新。之后调用 `MPU6050_ReadData()` 时，驱动会使用新的灵敏度进行换算。

这种设计的好处是调用者不需要每次手动保存灵敏度；缺点是当前驱动只支持单个 MPU6050 实例，因为这些状态是全局静态的。

## 4. I2C 寄存器读写封装

MPU6050 的内部寄存器通过 I2C 访问。驱动封装了三个基础函数：

```c
static MPU6050_Status MPU6050_ReadReg(uint8_t reg, uint8_t *data);
static MPU6050_Status MPU6050_ReadRegs(uint8_t reg, uint8_t *data, uint16_t len, uint32_t timeout_ms);
static MPU6050_Status MPU6050_WriteReg(uint8_t reg, uint8_t value);
```

### 4.1 单字节读

```c
static MPU6050_Status MPU6050_ReadReg(uint8_t reg, uint8_t *data)
{
    if (data == NULL)
    {
        return MPU6050_INVALID_ARG;
    }

    return MPU6050_FromHal(HAL_I2C_Mem_Read(
        mpu_i2c,
        mpu_address,
        reg,
        I2C_MEMADD_SIZE_8BIT,
        data,
        1U,
        MPU6050_I2C_TIMEOUT_MS));
}
```

这里使用 `HAL_I2C_Mem_Read()` 读取 MPU6050 内部某个 8 位寄存器地址对应的数据。

参数含义如下：

| 参数 | 含义 |
| --- | --- |
| `mpu_i2c` | STM32 HAL I2C 句柄 |
| `mpu_address` | MPU6050 的 8 位 I2C 地址 |
| `reg` | MPU6050 内部寄存器地址 |
| `I2C_MEMADD_SIZE_8BIT` | 寄存器地址宽度为 8 位 |
| `data` | 接收缓冲区 |
| `1U` | 读取 1 字节 |
| `MPU6050_I2C_TIMEOUT_MS` | 超时时间，100 ms |

这里的 `I2C_MEMADD_SIZE_8BIT` 不是 I2C 设备地址宽度，而是 MPU6050 内部寄存器地址宽度。MPU6050 的寄存器地址是 8 位，例如 `WHO_AM_I` 是 `0x75`。

### 4.2 多字节连续读

```c
static MPU6050_Status MPU6050_ReadRegs(uint8_t reg, uint8_t *data, uint16_t len, uint32_t timeout_ms)
{
    if ((data == NULL) || (len == 0U))
    {
        return MPU6050_INVALID_ARG;
    }

    return MPU6050_FromHal(HAL_I2C_Mem_Read(
        mpu_i2c,
        mpu_address,
        reg,
        I2C_MEMADD_SIZE_8BIT,
        data,
        len,
        timeout_ms));
}
```

多字节连续读是读取传感器数据的关键。

MPU6050 的数据寄存器是连续排列的。从 `ACCEL_XOUT_H` 开始，可以一次性读取 14 字节，得到同一时刻的加速度、温度和陀螺仪数据。相比每个轴单独读取，突发读可以减少 I2C 通信次数，也可以降低不同数据之间被传感器更新打断的概率。

### 4.3 单字节写

```c
static MPU6050_Status MPU6050_WriteReg(uint8_t reg, uint8_t value)
{
    return MPU6050_FromHal(HAL_I2C_Mem_Write(
        mpu_i2c,
        mpu_address,
        reg,
        I2C_MEMADD_SIZE_8BIT,
        &value,
        1U,
        MPU6050_I2C_TIMEOUT_MS));
}
```

写寄存器时，驱动把要写入的值地址传给 HAL：

```c
&value
```

HAL 会把这个字节发送到指定寄存器。

## 5. 设备识别：`WHO_AM_I` 和地址探测

MPU6050 有一个只读身份寄存器：

```c
#define MPU6050_REG_WHO_AM_I 0x75U
```

读取它可以判断设备是否正常连接。

驱动中的识别逻辑如下：

```c
static MPU6050_Device MPU6050_DeviceFromWhoAmI(uint8_t who_am_i)
{
    if (who_am_i == 0x68U)
    {
        return MPU6050_DEVICE_MPU6050;
    }

    return MPU6050_DEVICE_UNKNOWN;
}
```

当前代码认为 `WHO_AM_I == 0x68` 时设备是 MPU6050。

地址探测函数如下：

```c
static MPU6050_Status MPU6050_ProbeAddress(uint8_t address_7bit)
{
    uint8_t who_am_i = 0U;

    mpu_address = (uint8_t)(address_7bit << 1);

    if (MPU6050_ReadWhoAmI(&who_am_i) != MPU6050_OK)
    {
        return MPU6050_NOT_FOUND;
    }

    mpu_device = MPU6050_DeviceFromWhoAmI(who_am_i);

    return (mpu_device == MPU6050_DEVICE_UNKNOWN) ? MPU6050_NOT_FOUND : MPU6050_OK;
}
```

它做了三件事：

1. 设置当前尝试的 I2C 地址；
2. 读取 `WHO_AM_I`；
3. 判断读到的值是否是已知设备。

如果 I2C 通信失败，返回 `MPU6050_NOT_FOUND`。如果通信成功但 `WHO_AM_I` 不是 `0x68`，也返回 `MPU6050_NOT_FOUND`。

### 5.1 为什么先探测地址，再初始化

直接对传感器写配置寄存器当然可以，但在工程上更稳妥的做法是先确认设备存在。原因有三个：

1. 如果 I2C 地址错误，后续所有写操作都会失败；
2. 如果总线上没有 MPU6050，初始化函数会浪费大量时间等待超时；
3. 如果 `WHO_AM_I` 不正确，说明接线、地址或芯片型号可能有问题。

因此驱动先探测，再配置。

## 6. 初始化入口：自动地址探测

驱动提供两个初始化函数：

```c
MPU6050_Status MPU6050_Init(I2C_HandleTypeDef *hi2c);
MPU6050_Status MPU6050_InitWithAddress(I2C_HandleTypeDef *hi2c, uint8_t address_7bit);
```

### 6.1 `MPU6050_Init()`

```c
MPU6050_Status MPU6050_Init(I2C_HandleTypeDef *hi2c)
{
    MPU6050_Status status;

    if (hi2c == NULL)
    {
        return MPU6050_INVALID_ARG;
    }

    mpu_i2c = hi2c;

    status = MPU6050_ProbeAddress(MPU6050_ADDR_LOW_7BIT);

    if (status != MPU6050_OK)
    {
        status = MPU6050_ProbeAddress(MPU6050_ADDR_HIGH_7BIT);
    }

    if (status != MPU6050_OK)
    {
        return status;
    }

    return MPU6050_InitWithAddress(mpu_i2c, (uint8_t)(mpu_address >> 1));
}
```

这个函数适合不确定 AD0 引脚电平时使用。

它会先尝试 `0x68`：

```c
MPU6050_ProbeAddress(MPU6050_ADDR_LOW_7BIT);
```

如果失败，再尝试 `0x69`：

```c
MPU6050_ProbeAddress(MPU6050_ADDR_HIGH_7BIT);
```

只要其中一个地址探测成功，就使用该地址继续完整初始化。

### 6.2 `MPU6050_InitWithAddress()`

如果已经明确知道 MPU6050 的地址，可以直接调用：

```c
MPU6050_InitWithAddress(&hi2c1, 0x68);
```

或者：

```c
MPU6050_InitWithAddress(&hi2c1, 0x69);
```

这个函数会跳过自动扫描，直接探测指定地址，然后配置传感器。

## 7. 初始化流程详解

完整初始化发生在 `MPU6050_InitWithAddress()` 中：

```c
if (MPU6050_WriteReg(MPU6050_REG_PWR_MGMT_1, 0x80U) != MPU6050_OK)
{
    return MPU6050_ERROR;
}

HAL_Delay(100U);

if (MPU6050_WriteReg(MPU6050_REG_PWR_MGMT_1, 0x01U) != MPU6050_OK)
{
    return MPU6050_ERROR;
}

HAL_Delay(10U);

if ((MPU6050_WriteReg(MPU6050_REG_PWR_MGMT_2, 0x00U) != MPU6050_OK) ||
    (MPU6050_WriteReg(MPU6050_REG_CONFIG, 0x03U) != MPU6050_OK) ||
    (MPU6050_WriteReg(MPU6050_REG_SMPLRT_DIV, 0x09U) != MPU6050_OK) ||
    (MPU6050_SetGyroRange(MPU6050_GYRO_RANGE_500DPS) != MPU6050_OK) ||
    (MPU6050_SetAccelRange(MPU6050_ACCEL_RANGE_4G) != MPU6050_OK))
{
    return MPU6050_ERROR;
}
```

这段代码是整份驱动的核心之一。下面逐段解释。

### 7.1 软件复位

```c
MPU6050_WriteReg(MPU6050_REG_PWR_MGMT_1, 0x80U);
HAL_Delay(100U);
```

`PWR_MGMT_1` 寄存器地址是：

```c
#define MPU6050_REG_PWR_MGMT_1 0x6BU
```

写入 `0x80` 表示置位 `DEVICE_RESET` 位。

二进制形式：

```text
0x80 = 1000 0000
```

最高位为 1 时，MPU6050 执行软件复位。复位会清除内部寄存器状态，使传感器回到较已知的初始状态。

复位后需要等待一段时间，让内部电路稳定。代码使用：

```c
HAL_Delay(100U);
```

也就是等待 100 ms。

这一步在工程上很有价值。因为如果 MCU 之前异常复位，MPU6050 可能仍处于某种未知配置状态。通过软件复位，可以减少“第一次烧录正常，复位后异常”的问题。

### 7.2 唤醒并选择时钟源

```c
MPU6050_WriteReg(MPU6050_REG_PWR_MGMT_1, 0x01U);
HAL_Delay(10U);
```

写入 `0x01` 的二进制形式：

```text
0x01 = 0000 0001
```

这里主要配置了两件事：

1. `SLEEP` 位为 0，传感器不进入睡眠；
2. `CLKSEL = 1`，使用 X 轴陀螺仪 PLL 作为时钟源。

MPU6050 上电后默认可能处于睡眠状态，或者使用内部 8 MHz 振荡器。为了获得更稳定的采样时序，通常建议将时钟源切换到陀螺仪 PLL。

代码写入 `0x01` 后延时 10 ms，让时钟源切换稳定。

### 7.3 使能加速度计和陀螺仪

```c
MPU6050_WriteReg(MPU6050_REG_PWR_MGMT_2, 0x00U);
```

`PWR_MGMT_2` 寄存器地址是：

```c
#define MPU6050_REG_PWR_MGMT_2 0x6CU
```

写入 `0x00` 表示所有轴都不进入待机状态。

MPU6050 的 `PWR_MGMT_2` 中有若干 STBY 位，可以单独让加速度计或陀螺仪的某个轴进入 standby。写入 `0x00` 后：

- X/Y/Z 加速度计使能；
- X/Y/Z 陀螺仪使能。

这一步保证后续可以读到六轴数据。

### 7.4 配置数字低通滤波器

```c
MPU6050_WriteReg(MPU6050_REG_CONFIG, 0x03U);
```

`CONFIG` 寄存器地址是：

```c
#define MPU6050_REG_CONFIG 0x1AU
```

写入 `0x03` 主要配置 `DLPF_CFG = 3`。

二进制形式：

```text
0x03 = 0000 0011
```

低三位是 `DLPF_CFG`，因此：

```text
DLPF_CFG = 3
```

在 MPU6050 的数据手册中，`DLPF_CFG = 3` 对应加速度计 `44 Hz`、陀螺仪 `42 Hz` 的数字低通带宽（两个传感器各有一个 DLPF，带宽略有差别）。

低通滤波的作用是抑制高频噪声。带宽越低，输出越平滑，但对快速变化的响应也会变慢，并引入一定相位延迟。

对于姿态检测、平衡车、云台等应用，适当滤波通常比直接输出原始高频噪声更实用。对于需要极高动态响应的控制回路，则需要重新评估这个配置。

### 7.5 配置采样率

```c
MPU6050_WriteReg(MPU6050_REG_SMPLRT_DIV, 0x09U);
```

`SMPLRT_DIV` 寄存器地址是：

```c
#define MPU6050_REG_SMPLRT_DIV 0x19U
```

写入 `0x09`，即十进制 9。

MPU6050 的输出采样率由下式决定：

$$
f_s = \frac{f_{gyro}}{1 + SMPLRT\_DIV}
$$

其中：

- $f_s$：传感器输出采样率；
- $f_{gyro}$：陀螺仪输出速率；
- $SMPLRT\_DIV$：采样率分频值。

当数字低通滤波器使能时，陀螺仪输出速率通常为 1 kHz。代码中：

```c
SMPLRT_DIV = 9
```

因此：

$$
f_s = \frac{1000}{1 + 9} = 100 \text{ Hz}
$$

因此，当前驱动默认把 MPU6050 配置为约 100 Hz 的数据输出率。

如果主循环以 100 Hz 调用 `MPU6050_ReadData()`，大致可以跟上传感器更新速度。如果调用频率远高于 100 Hz，可能多次读到同一帧数据；如果调用频率远低于 100 Hz，则会丢失中间采样，但对于许多轮询应用这是可以接受的。

### 7.6 配置陀螺仪和加速度计量程

初始化最后两步：

```c
MPU6050_SetGyroRange(MPU6050_GYRO_RANGE_500DPS);
MPU6050_SetAccelRange(MPU6050_ACCEL_RANGE_4G);
```

默认量程是：

- 陀螺仪：±500 °/s；
- 加速度计：±4 g。

这是一个比较折中的配置。

对于一般手持设备、小车、平衡车、姿态演示，±4 g 和 ±500 °/s 通常够用。如果应用场景有强烈冲击或高速旋转，则需要选择更大量程。

## 8. 量程配置与灵敏度换算

量程决定了传感器能测量的最大物理量，也决定了每个 LSB 对应的物理量大小。

### 8.1 加速度计量程

加速度计量程设置函数：

```c
MPU6050_Status MPU6050_SetAccelRange(MPU6050_AccelRange range)
{
    uint8_t value = 0U;

    switch (range)
    {
        case MPU6050_ACCEL_RANGE_2G:
            accel_lsb_per_g = 16384.0f;
            break;

        case MPU6050_ACCEL_RANGE_4G:
            accel_lsb_per_g = 8192.0f;
            value = 0x08U;
            break;

        case MPU6050_ACCEL_RANGE_8G:
            accel_lsb_per_g = 4096.0f;
            value = 0x10U;
            break;

        case MPU6050_ACCEL_RANGE_16G:
            accel_lsb_per_g = 2048.0f;
            value = 0x18U;
            break;

        default:
            return MPU6050_INVALID_ARG;
    }

    return MPU6050_WriteReg(MPU6050_REG_ACCEL_CONFIG, value);
}
```

对应关系如下：

| 量程 | 寄存器值 | 灵敏度 |
| --- | ---: | ---: |
| ±2 g | `0x00` | 16384 LSB/g |
| ±4 g | `0x08` | 8192 LSB/g |
| ±8 g | `0x10` | 4096 LSB/g |
| ±16 g | `0x18` | 2048 LSB/g |

寄存器值实际上是 `AFS_SEL` 位左移后的结果：

```text
0x00 = 0000 0000  AFS_SEL = 0  ±2 g
0x08 = 0000 1000  AFS_SEL = 1  ±4 g
0x10 = 0001 0000  AFS_SEL = 2  ±8 g
0x18 = 0001 1000  AFS_SEL = 3  ±16 g
```

加速度物理量换算公式为：

$$
a_g = \frac{raw}{S_a}
$$

其中：

- $a_g$：加速度，单位 g；
- $raw$：加速度原始值，范围大约为 -32768 到 32767；
- $S_a$：加速度灵敏度，单位 LSB/g。

例如在 ±4 g 量程下：

$$
S_a = 8192 \text{ LSB/g}
$$

如果读到：

```c
raw.accel_z = 8192;
```

则：

$$
a_z = \frac{8192}{8192} = 1 \text{ g}
$$

如果读到：

```c
raw.accel_z = -8192;
```

则：

$$
a_z = -1 \text{ g}
$$

如果希望得到 m/s²，可以再乘以标准重力加速度：

$$
a_{m/s^2} = a_g \times 9.80665
$$

但本驱动输出的是 g，没有自动转换成 m/s²。

### 8.2 陀螺仪量程

陀螺仪量程设置函数：

```c
MPU6050_Status MPU6050_SetGyroRange(MPU6050_GyroRange range)
{
    uint8_t value = 0U;

    switch (range)
    {
        case MPU6050_GYRO_RANGE_250DPS:
            gyro_lsb_per_dps = 131.0f;
            break;

        case MPU6050_GYRO_RANGE_500DPS:
            gyro_lsb_per_dps = 65.5f;
            value = 0x08U;
            break;

        case MPU6050_GYRO_RANGE_1000DPS:
            gyro_lsb_per_dps = 32.8f;
            value = 0x10U;
            break;

        case MPU6050_GYRO_RANGE_2000DPS:
            gyro_lsb_per_dps = 16.4f;
            value = 0x18U;
            break;

        default:
            return MPU6050_INVALID_ARG;
    }

    return MPU6050_WriteReg(MPU6050_REG_GYRO_CONFIG, value);
}
```

对应关系如下：

| 量程 | 寄存器值 | 灵敏度 |
| --- | ---: | ---: |
| ±250 °/s | `0x00` | 131 LSB/(°/s) |
| ±500 °/s | `0x08` | 65.5 LSB/(°/s) |
| ±1000 °/s | `0x10` | 32.8 LSB/(°/s) |
| ±2000 °/s | `0x18` | 16.4 LSB/(°/s) |

寄存器值对应 `FS_SEL` 位：

```text
0x00 = 0000 0000  FS_SEL = 0  ±250 °/s
0x08 = 0000 1000  FS_SEL = 1  ±500 °/s
0x10 = 0001 0000  FS_SEL = 2  ±1000 °/s
0x18 = 0001 1000  FS_SEL = 3  ±2000 °/s
```

角速度换算公式为：

$$
\omega_{dps} = \frac{raw}{S_g}
$$

其中：

- $\omega_{dps}$：角速度，单位 °/s；
- $raw$：陀螺仪原始值；
- $S_g$：陀螺仪灵敏度，单位 LSB/(°/s)。

例如在 ±500 °/s 量程下：

$$
S_g = 65.5 \text{ LSB/(°/s)}
$$

如果读到：

```c
raw.gyro_x = 655;
```

则：

$$
\omega_x = \frac{655}{65.5} = 10 \text{ °/s}
$$

如果读到：

```c
raw.gyro_x = -655;
```

则：

$$
\omega_x = -10 \text{ °/s}
$$

### 8.3 量程选择的直觉

量程不是越大越好。

量程越大，传感器越不容易饱和，但每个 LSB 代表的物理量越大，分辨率越低。

以加速度计为例：

| 量程 | 灵敏度 | 特点 |
| --- | ---: | --- |
| ±2 g | 16384 LSB/g | 分辨率最高，适合缓慢运动、倾角检测 |
| ±4 g | 8192 LSB/g | 折中选择 |
| ±8 g | 4096 LSB/g | 适合较强加速度场景 |
| ±16 g | 2048 LSB/g | 最不容易饱和，但分辨率最低 |

陀螺仪也是类似：

| 量程 | 灵敏度 | 特点 |
| --- | ---: | --- |
| ±250 °/s | 131 LSB/(°/s) | 分辨率高，适合慢速转动 |
| ±500 °/s | 65.5 LSB/(°/s) | 折中选择 |
| ±1000 °/s | 32.8 LSB/(°/s) | 适合较快旋转 |
| ±2000 °/s | 16.4 LSB/(°/s) | 适合高速旋转，但噪声和量化误差更明显 |

因此，修改量程时需要同时考虑：

1. 是否会超出测量范围；
2. 是否需要更高分辨率；
3. 控制回路对噪声和延迟是否敏感；
4. 后续算法是否依赖固定单位。

## 9. 原始数据读取：14 字节突发读

MPU6050 的数据寄存器从 `0x3B` 开始连续排列：

```c
#define MPU6050_REG_ACCEL_XOUT_H 0x3BU
```

驱动使用一次 14 字节读取：

```c
MPU6050_Status MPU6050_ReadAccelGyroRaw(MPU6050_AccelGyroRaw *raw, uint32_t timeout_ms)
{
    uint8_t buffer[14] = {0};

    if (raw == NULL)
    {
        return MPU6050_INVALID_ARG;
    }

    if (MPU6050_ReadRegs(MPU6050_REG_ACCEL_XOUT_H, buffer, sizeof(buffer), timeout_ms) != MPU6050_OK)
    {
        return MPU6050_ERROR;
    }

    raw->accel_x = MPU6050_ToInt16BE(buffer[0], buffer[1]);
    raw->accel_y = MPU6050_ToInt16BE(buffer[2], buffer[3]);
    raw->accel_z = MPU6050_ToInt16BE(buffer[4], buffer[5]);
    raw->temp    = MPU6050_ToInt16BE(buffer[6], buffer[7]);
    raw->gyro_x  = MPU6050_ToInt16BE(buffer[8], buffer[9]);
    raw->gyro_y  = MPU6050_ToInt16BE(buffer[10], buffer[11]);
    raw->gyro_z  = MPU6050_ToInt16BE(buffer[12], buffer[13]);

    return MPU6050_OK;
}
```

14 字节数据布局如下：

| 缓冲区索引 | 寄存器 | 含义 |
| ---: | --- | --- |
| 0 | `ACCEL_XOUT_H` | 加速度 X 高字节 |
| 1 | `ACCEL_XOUT_L` | 加速度 X 低字节 |
| 2 | `ACCEL_YOUT_H` | 加速度 Y 高字节 |
| 3 | `ACCEL_YOUT_L` | 加速度 Y 低字节 |
| 4 | `ACCEL_ZOUT_H` | 加速度 Z 高字节 |
| 5 | `ACCEL_ZOUT_L` | 加速度 Z 低字节 |
| 6 | `TEMP_OUT_H` | 温度高字节 |
| 7 | `TEMP_OUT_L` | 温度低字节 |
| 8 | `GYRO_XOUT_H` | 陀螺仪 X 高字节 |
| 9 | `GYRO_XOUT_L` | 陀螺仪 X 低字节 |
| 10 | `GYRO_YOUT_H` | 陀螺仪 Y 高字节 |
| 11 | `GYRO_YOUT_L` | 陀螺仪 Y 低字节 |
| 12 | `GYRO_ZOUT_H` | 陀螺仪 Z 高字节 |
| 13 | `GYRO_ZOUT_L` | 陀螺仪 Z 低字节 |

这种读取方式的关键是：从 `ACCEL_XOUT_H` 开始连续读 14 字节，MPU6050 会自动把后续寄存器数据依次返回。

## 10. 大端数据转换：为什么高字节在前

MPU6050 的每个 16 位数据由高字节和低字节两个寄存器组成，并且高字节在前。这种顺序通常称为大端序，big-endian。

驱动中的转换函数：

```c
static int16_t MPU6050_ToInt16BE(uint8_t high, uint8_t low)
{
    return (int16_t)((uint16_t)high << 8 | low);
}
```

它的作用是：

1. 把高字节左移 8 位；
2. 与低字节按位或；
3. 得到 16 位无符号整数；
4. 再转换为有符号 `int16_t`。

例如：

```text
high = 0xFF
low  = 0xF6
```

组合后：

```text
0xFFF6
```

作为 16 位有符号整数，`0xFFF6` 表示 -10。

如果只写：

```c
return (high << 8) | low;
```

在某些平台上可能因为 `high` 的类型提升和符号扩展产生意料之外的问题。代码中先使用 `uint16_t` 组合，再转换为 `int16_t`，写法更稳妥。

## 11. 物理量转换：从 LSB 到 g、°/s、℃

原始数据读取后，`MPU6050_ReadData()` 会将其转换为物理量：

```c
MPU6050_Status MPU6050_ReadData(MPU6050_Data *data)
{
    MPU6050_AccelGyroRaw raw;
    MPU6050_Status status;

    if (data == NULL)
    {
        return MPU6050_INVALID_ARG;
    }

    status = MPU6050_ReadAccelGyroRaw(&raw, MPU6050_I2C_TIMEOUT_MS);

    if (status != MPU6050_OK)
    {
        return status;
    }

    data->ax_g = (float)raw.accel_x / accel_lsb_per_g;
    data->ay_g = (float)raw.accel_y / accel_lsb_per_g;
    data->az_g = (float)raw.accel_z / accel_lsb_per_g;

    data->temperature_c = ((float)raw.temp / 340.0f) + 36.53f;

    data->gx_dps = (float)raw.gyro_x / gyro_lsb_per_dps;
    data->gy_dps = (float)raw.gyro_y / gyro_lsb_per_dps;
    data->gz_dps = (float)raw.gyro_z / gyro_lsb_per_dps;

    return MPU6050_OK;
}
```

### 11.1 加速度换算

```c
data->ax_g = (float)raw.accel_x / accel_lsb_per_g;
```

公式：

$$
a_g = \frac{raw}{S_a}
$$

如果当前量程是 ±4 g：

$$
S_a = 8192
$$

当原始值为 8192 时：

$$
a_x = 1 \text{ g}
$$

当原始值为 -8192 时：

$$
a_x = -1 \text{ g}
$$

静止状态下，如果 MPU6050 水平放置，Z 轴通常接近 ±1 g，具体正负取决于芯片安装方向和坐标轴定义。X、Y 轴应接近 0 g。实际中由于零偏、噪声和安装误差，不会完全等于 0。

### 11.2 角速度换算

```c
data->gx_dps = (float)raw.gyro_x / gyro_lsb_per_dps;
```

公式：

$$
\omega_{dps} = \frac{raw}{S_g}
$$

如果当前量程是 ±500 °/s：

$$
S_g = 65.5
$$

当原始值为 655 时：

$$
\omega_x = 10 \text{ °/s}
$$

静止状态下，陀螺仪输出理论上应为 0，但实际会有零偏。例如静止时读到：

```text
gx_dps = 0.3 °/s
```

这并不一定代表传感器损坏，而是常见零偏和噪声。若要用于姿态积分，通常需要进行零偏校准。

### 11.3 温度换算

```c
data->temperature_c = ((float)raw.temp / 340.0f) + 36.53f;
```

公式：

$$
T = \frac{raw}{340} + 36.53
$$

其中：

- $T$：温度，单位 ℃；
- $raw$：温度传感器原始值；
- 340：温度灵敏度，单位 LSB/℃；
- 36.53：温度公式偏移量。

这个公式来自 MPU6050 常见数据手册定义。

温度原始值可能为负数。例如当温度为 25 ℃ 时：

$$
raw = 340 \times (25 - 36.53)
$$

$$
raw \approx -3920
$$

因此看到温度原始值为负数并不异常。

## 12. API 使用示例

下面示例假设 STM32 HAL 已经初始化好 I2C 句柄 `hi2c1`。

### 12.1 初始化并读取数据

```c
#include "mpu6050.h"
#include <stdio.h>

extern I2C_HandleTypeDef hi2c1;

int main(void)
{
    HAL_Init();
    SystemClock_Config();
    MX_I2C1_Init();

    MPU6050_Status status = MPU6050_Init(&hi2c1);

    if (status != MPU6050_OK)
    {
        printf("MPU6050 init failed: %s\r\n", MPU6050_StatusString(status));

        while (1)
        {
            HAL_Delay(1000);
        }
    }

    printf("MPU6050 init OK, address = 0x%02X\r\n", MPU6050_GetAddress());

    MPU6050_Data data;

    while (1)
    {
        status = MPU6050_ReadData(&data);

        if (status == MPU6050_OK)
        {
            printf("ax=%.3f g, ay=%.3f g, az=%.3f g, ",
                   data.ax_g,
                   data.ay_g,
                   data.az_g);

            printf("gx=%.3f dps, gy=%.3f dps, gz=%.3f dps, ",
                   data.gx_dps,
                   data.gy_dps,
                   data.gz_dps);

            printf("temp=%.2f C\r\n",
                   data.temperature_c);
        }
        else
        {
            printf("MPU6050 read failed: %s\r\n", MPU6050_StatusString(status));
        }

        HAL_Delay(10);
    }
}
```

这里 `HAL_Delay(10)` 对应大约 100 Hz 的读取频率，与驱动默认采样率配置相匹配。

### 12.2 修改加速度计和陀螺仪量程

```c
MPU6050_SetAccelRange(MPU6050_ACCEL_RANGE_8G);
MPU6050_SetGyroRange(MPU6050_GYRO_RANGE_1000DPS);
```

调用后，驱动内部的灵敏度会更新为：

```c
accel_lsb_per_g = 4096.0f;
gyro_lsb_per_dps = 32.8f;
```

之后调用 `MPU6050_ReadData()` 时会自动使用新的灵敏度。

### 12.3 只读取原始数据用于调试

```c
MPU6050_AccelGyroRaw raw;

if (MPU6050_ReadAccelGyroRaw(&raw, 100) == MPU6050_OK)
{
    printf("raw accel: %d %d %d\r\n",
           raw.accel_x,
           raw.accel_y,
           raw.accel_z);

    printf("raw gyro: %d %d %d\r\n",
           raw.gyro_x,
           raw.gyro_y,
           raw.gyro_z);

    printf("raw temp: %d\r\n", raw.temp);
}
```

原始数据适合排查以下问题：

1. I2C 是否真的读到数据；
2. 数据是否一直为 0；
3. 数据是否一直为 -1 或 0xFFFF；
4. 某个轴是否明显异常；
5. 量程切换后原始值是否变化合理。

### 12.4 读取设备地址和识别状态

```c
uint8_t addr = MPU6050_GetAddress();
MPU6050_Device device = MPU6050_GetDevice();
```

如果初始化成功：

```c
addr == 0x68
```

或：

```c
addr == 0x69
```

并且：

```c
device == MPU6050_DEVICE_MPU6050
```

`MPU6050_GetAddress()` 返回的是 7 位地址，因为代码内部做了右移：

```c
return (uint8_t)(mpu_address >> 1);
```

## 14. 常见排错方法

### 14.1 返回 `MPU6050_NOT_FOUND`

这通常表示驱动没有找到 MPU6050，或者读到的 `WHO_AM_I` 不正确。

检查顺序如下：

1. **供电是否正常**
   - MPU6050 常见工作电压为 3.3 V；
   - 确认 VCC、GND 连接正确；
   - 确认电源能力足够。

2. **I2C 地址是否正确**
   - AD0 接低时地址通常为 `0x68`；
   - AD0 接高时地址通常为 `0x69`；
   - 如果 AD0 悬空，地址可能不稳定。

3. **SCL 和 SDA 是否接好**
   - 确认没有接反；
   - 确认 MCU 引脚配置到正确的 I2C 外设；
   - 确认 GPIO 复用功能配置正确。

4. **是否有上拉电阻**
   - I2C 是开漏总线；
   - SCL 和 SDA 通常需要上拉电阻；
   - 常见上拉值为 4.7 kΩ，具体与总线电压、速率和电容有关。

5. **I2C 外设是否初始化**
   - 确认调用 `MPU6050_Init()` 前 I2C 已经初始化；
   - 确认 I2C 时钟配置正确；
   - 确认 NVIC 和时钟树没有配置错误。

6. **WHO_AM_I 是否正确**
   - 当前代码只识别 `0x68`；
   - 如果使用兼容芯片，`WHO_AM_I` 可能不同；
   - 如果读到的值不是 `0x68`，驱动会返回 `MPU6050_NOT_FOUND`。

### 14.2 返回 `MPU6050_ERROR`

`MPU6050_ERROR` 通常来自 HAL I2C 操作失败。

可能原因包括：

1. I2C 总线超时；
2. I2C NACK；
3. SCL/SDA 被拉死；
4. MPU6050 初始化过程中某一步写寄存器失败；
5. I2C 中断配置错误；
6. I2C 时钟速率过高；
7. 总线电容过大；
8. 多个设备地址冲突。

可以先用原始读取函数定位问题：

```c
MPU6050_AccelGyroRaw raw;
MPU6050_Status status = MPU6050_ReadAccelGyroRaw(&raw, 100);
```

如果原始读取也失败，说明问题更可能发生在 I2C 通信层，而不是数据换算层。

### 14.3 返回 `MPU6050_INVALID_ARG`

这通常是因为传入了空指针。

例如：

```c
MPU6050_ReadData(NULL);
```

或者：

```c
MPU6050_Init(NULL);
```

解决方法是确保传入有效对象：

```c
MPU6050_Data data;
MPU6050_ReadData(&data);
```

### 14.4 数据全为 0

如果读到的原始数据全为 0，可能原因包括：

1. 传感器未真正使能；
2. I2C 通信异常但没有正确返回错误；
3. 读取的寄存器地址错误；
4. MPU6050 处于异常状态；
5. 芯片供电异常。

可以先检查初始化是否成功：

```c
if (MPU6050_Init(&hi2c1) == MPU6050_OK)
{
    // 初始化成功
}
```

再读取 `WHO_AM_I`：

```c
uint8_t who = 0;

if (MPU6050_ReadWhoAmI(&who) == MPU6050_OK)
{
    printf("WHO_AM_I = 0x%02X\r\n", who);
}
```

正常情况下应读到：

```text
WHO_AM_I = 0x68
```

### 14.5 数据全为 -1 或 0xFFFF

如果原始数据大量为 -1：

```text
raw.accel_x = -1
raw.accel_y = -1
raw.accel_z = -1
```

通常说明 I2C 读到的数据可能是 `0xFF`。

常见原因：

1. SDA 被上拉到高电平，但没有设备真正返回数据；
2. I2C 地址错误；
3. 总线处于异常状态；
4. 读取超时后缓冲区未被正确更新。

此时应重点检查 I2C 总线，而不是数据换算逻辑。

### 14.6 静止时陀螺仪不为 0

静止时陀螺仪仍有少量偏移是正常现象，例如：

```text
gx_dps = 0.2
gy_dps = -0.1
gz_dps = 0.3
```

这通常来自零偏和噪声。

如果要用于角度积分，需要做零偏校准。简单方法是：

1. 将 MPU6050 静止放置；
2. 连续读取多帧陀螺仪数据；
3. 求平均值；
4. 后续读数减去该平均值。

例如：

```c
float gyro_x_bias = 0.0f;

// 假设已经采集 N 帧静止数据并求平均
// gyro_x_bias = sum_gx / N;

float gx_calibrated = data.gx_dps - gyro_x_bias;
```

本驱动没有内置校准功能，需要应用层自行实现。

### 14.7 加速度计静止时不是正好 1 g

静止水平放置时，Z 轴接近 1 g，X/Y 轴接近 0 g，但通常不会完全等于理论值。

可能原因：

1. 传感器安装不水平；
2. 加速度计零偏；
3. 轴方向定义与预期不同；
4. 振动和噪声；
5. 量程切换后未重新校准。

如果只是做倾角检测，可以通过校准改善效果。如果用于高精度导航，仅靠 MPU6050 原始数据通常不够，需要更复杂的滤波和校准。

## 15. 代码设计特点与工程含义

### 15.1 单实例设计

驱动使用静态全局变量保存状态：

```c
static I2C_HandleTypeDef *mpu_i2c = NULL;
static uint8_t mpu_address = (MPU6050_ADDR_LOW_7BIT << 1);
static MPU6050_Device mpu_device = MPU6050_DEVICE_UNKNOWN;
static float accel_lsb_per_g = 8192.0f;
static float gyro_lsb_per_dps = 65.5f;
```

这意味着当前驱动一次只能管理一个 MPU6050。

如果系统中有两个 MPU6050，例如分别挂在不同 I2C 总线上，或者同一总线上使用不同地址，当前驱动不能直接同时支持。此时应改成句柄式多实例结构，例如：

```c
typedef struct
{
    I2C_HandleTypeDef *hi2c;
    uint8_t address;
    MPU6050_Device device;
    float accel_lsb_per_g;
    float gyro_lsb_per_dps;
} MPU6050_Handle;
```

然后所有 API 都传入句柄：

```c
MPU6050_Status MPU6050_InitHandle(MPU6050_Handle *handle, I2C_HandleTypeDef *hi2c);
MPU6050_Status MPU6050_ReadDataHandle(MPU6050_Handle *handle, MPU6050_Data *data);
```

### 15.2 阻塞式 I2C

驱动使用 HAL 阻塞接口：

```c
HAL_I2C_Mem_Read()
HAL_I2C_Mem_Write()
```

优点是简单、容易调试。

缺点是在 I2C 通信期间，CPU 会等待通信完成。如果总线异常，可能会等待到超时。

在实时性要求较高的系统中，可以考虑：

1. 使用 DMA；
2. 使用中断式 I2C；
3. 使用传感器中断引脚提示数据就绪；
4. 使用 FIFO 批量读取。

### 15.3 默认采样率约 100 Hz

代码中：

```c
MPU6050_WriteReg(MPU6050_REG_SMPLRT_DIV, 0x09U);
```

配合 DLPF 使能时，输出速率约为 100 Hz。

如果应用需要更高更新率，可以减小 `SMPLRT_DIV`。

例如：

```c
SMPLRT_DIV = 0
```

在 1 kHz 内部采样率下：

$$
f_s = \frac{1000}{1 + 0} = 1000 \text{ Hz}
$$

但更高采样率意味着：

1. I2C 带宽压力更大；
2. CPU 读取更频繁；
3. 数据噪声更多；
4. 后续算法计算量增加。

因此不要盲目提高采样率，应结合控制周期和通信能力选择。

### 15.4 默认低通滤波约 42 Hz

代码中：

```c
MPU6050_WriteReg(MPU6050_REG_CONFIG, 0x03U);
```

这会启用数字低通滤波器。精确说法是 `DLPF_CFG = 3` 时加速度计 `44 Hz`、陀螺仪 `42 Hz`（两个 DLPF 带宽略有差别），工程上约称"42 Hz"。

对于许多姿态检测应用，滤波后的数据更稳定。但对于高速控制回路，低通滤波会带来延迟。

如果需要更快速响应，可以选择更低的 `DLPF_CFG` 值，甚至关闭 DLPF。但关闭后噪声会增加，采样率计算也会变化。

## 16. 高频易错点

### 16.1 地址左移问题

MPU6050 数据手册中常说地址是 `0x68` 或 `0x69`，这是 7 位地址。

但在 STM32 HAL 中通常需要传入左移后的 8 位地址：

```text
0x68 -> 0xD0
0x69 -> 0xD2
```

驱动内部已经处理：

```c
mpu_address = (uint8_t)(address_7bit << 1);
```

如果直接调用底层 HAL，地址必须只左移一次：不能漏移，也不能重复左移。

### 16.2 `WHO_AM_I` 不等于 I2C 地址

很多初学者会误以为 `WHO_AM_I` 应该等于当前 I2C 地址。

实际上：

- I2C 地址由 AD0 引脚决定，可能是 `0x68` 或 `0x69`；
- `WHO_AM_I` 是设备身份寄存器值；
- 当前代码期望 `WHO_AM_I == 0x68`。

因此即使设备地址是 `0x69`，`WHO_AM_I` 仍可能返回 `0x68`。这并不一定错误。

### 16.3 修改量程后必须使用对应灵敏度

如果直接读取原始值：

```c
MPU6050_ReadAccelGyroRaw(&raw, 100);
```

然后自己换算，必须知道当前量程。

例如 ±4 g 时：

$$
a_g = \frac{raw}{8192}
$$

±8 g 时：

$$
a_g = \frac{raw}{4096}
$$

如果用错灵敏度，结果会差一倍。

`MPU6050_ReadData()` 会自动使用驱动内部保存的灵敏度。若无特殊调试需求，优先使用这个接口读取物理量。

### 16.4 驱动输出的是 g，不是 m/s²

```c
data->ax_g
```

单位是 g。

如果控制算法需要 m/s²，需要手动转换：

$$
a_{m/s^2} = a_g \times 9.80665
$$

例如：

```c
float ax_m_s2 = data.ax_g * 9.80665f;
```

### 16.5 陀螺仪积分会漂移

陀螺仪输出角速度。角度可以通过积分得到：

$$
\theta(t) = \theta_0 + \int \omega(t) dt
$$

但 MPU6050 的陀螺仪存在零偏和噪声，直接积分会导致角度逐渐漂移。

因此实际姿态系统通常会融合加速度计、陀螺仪，有时还融合磁力计，例如使用互补滤波、卡尔曼滤波等方法。

本驱动只提供原始物理量，不负责姿态解算。

### 16.6 量程设置失败时内部灵敏度可能已经改变

以加速度计为例：

```c
case MPU6050_ACCEL_RANGE_4G:
    accel_lsb_per_g = 8192.0f;
    value = 0x08U;
    break;
```

代码先更新 `accel_lsb_per_g`，最后才写寄存器：

```c
return MPU6050_WriteReg(MPU6050_REG_ACCEL_CONFIG, value);
```

如果 `MPU6050_WriteReg()` 失败，硬件寄存器可能没有切换成功，但驱动内部的灵敏度已经改变。这会导致后续 `MPU6050_ReadData()` 使用错误的换算系数。

在要求较高的应用中，可以改成：

1. 先写寄存器；
2. 写成功后再更新内部灵敏度；
3. 或者写失败时恢复原来的灵敏度。

## 17. 关键寄存器速查表

| 寄存器 | 地址 | 代码中的配置 | 作用 |
| --- | ---: | ---: | --- |
| `SMPLRT_DIV` | `0x19` | `0x09` | 采样率分频，默认约 100 Hz |
| `CONFIG` | `0x1A` | `0x03` | 数字低通滤波配置 |
| `GYRO_CONFIG` | `0x1B` | 默认 `0x08` | 陀螺仪 ±500 °/s |
| `ACCEL_CONFIG` | `0x1C` | 默认 `0x08` | 加速度计 ±4 g |

## 18. 推荐调试流程

调试 MPU6050 时，建议按以下顺序进行。

### 18.1 确认 I2C 总线

先不关心传感器数据，只确认 I2C 是否通信正常。

检查：

1. VCC、GND；
2. SCL、SDA；
3. AD0；
4. 上拉电阻；
5. I2C 外设初始化；
6. 地址是否正确。

目标：

```c
MPU6050_ReadWhoAmI(&who_am_i) == MPU6050_OK
```

并且：

```c
who_am_i == 0x68
```

### 18.2 确认初始化成功

调用：

```c
MPU6050_Status status = MPU6050_Init(&hi2c1);
```

如果失败，用：

```c
MPU6050_StatusString(status)
```

打印错误信息。

### 18.3 读取原始数据

使用：

```c
MPU6050_ReadAccelGyroRaw()
```

观察原始值是否变化。

轻轻倾斜传感器时，加速度原始值应变化。

轻轻旋转传感器时，陀螺仪原始值应变化。

### 18.4 读取物理量

使用：

```c
MPU6050_ReadData()
```

静止水平放置时，可以预期：

```text
ax_g 接近 0
ay_g 接近 0
az_g 接近 +1 或 -1
gx_dps 接近 0
gy_dps 接近 0
gz_dps 接近 0
temperature_c 在室温附近
```

具体 Z 轴正负取决于安装方向。

### 18.5 验证量程切换

例如从 ±4 g 切换到 ±16 g：

```c
MPU6050_SetAccelRange(MPU6050_ACCEL_RANGE_16G);
```

在相同姿态下，物理量结果仍应接近原来的重力值，但原始值会变小。

因为 ±16 g 的灵敏度是：

$$
2048 \text{ LSB/g}
$$

而 ±4 g 的灵敏度是：

$$
8192 \text{ LSB/g}
$$

所以同样的 1 g 加速度，±16 g 下的原始值大约是 ±4 g 下的四分之一。

## 19. 工程扩展方向

完成轮询读取的最小闭环后，可以按项目需求继续扩展。

### 19.1 增加零偏校准

适合姿态检测、平衡车、云台等应用。

基本思路：

1. 静止采集若干帧陀螺仪数据；
2. 求平均得到零偏；
3. 后续读数减去零偏。

加速度计也可以做简单的零偏和比例校准。

### 19.2 增加数据就绪中断

MPU6050 可以配置 INT 引脚，在数据就绪时通知 MCU。

相比固定延时轮询，中断方式更适合实时系统。

### 19.3 增加 FIFO

FIFO 可以缓存多帧数据，适合突发读取，减少 CPU 频繁访问 I2C。

### 19.4 支持多实例

如果系统中有多个 MPU6050，应把静态全局状态改成句柄结构体。

### 19.5 支持更多兼容设备

当前代码只识别：

```c
who_am_i == 0x68
```

如果实际使用 MPU6500、MPU9250 等兼容设备，需要修改设备识别逻辑，并检查寄存器差异。

## 20. 速记与自测

### 20.1 一页速记

- MPU6050 集成三轴加速度计、三轴陀螺仪和温度传感器。
- AD0 决定 7 位 I2C 地址是 `0x68` 还是 `0x69`；HAL 接口通常使用左移一位后的地址。
- `WHO_AM_I` 是设备标识，不等于当前 I2C 地址；本文驱动期望读到 `0x68`。
- 初始化主线是复位、唤醒、选择时钟、使能各轴、配置 DLPF、采样率和量程。
- 从 `0x3B` 开始连续读取 14 字节，可以在同一帧中获得加速度、温度和角速度原始值。
- 每个测量值由高、低两个字节组成，应先按大端顺序组合，再转换为 `int16_t`。
- 原始值除以当前量程的灵敏度，得到单位为 `g` 或 `°/s` 的物理量。
- 温度换算公式为 $T = raw / 340 + 36.53$，温度原始值为负数不一定异常。
- 静止时加速度计会测到重力，陀螺仪也可能存在零偏；驱动读数不等于完成校准或姿态解算。
- 当前实现采用阻塞式 I2C 和静态全局状态，默认只支持一个 MPU6050 实例。
- 排障时先确认总线和 `WHO_AM_I`，再检查初始化、原始数据、物理量换算与量程切换。

驱动的数据链路如下：

```text
I2C 地址探测
    ↓
WHO_AM_I 识别
    ↓
复位与唤醒
    ↓
配置采样率、滤波、量程
    ↓
从 0x3B 开始连续读 14 字节
    ↓
大端转 int16
    ↓
按当前量程换算为 g、°/s、℃
```

扩展驱动前，先保证这条数据链路稳定，再加入校准、中断、FIFO 或多实例支持。
