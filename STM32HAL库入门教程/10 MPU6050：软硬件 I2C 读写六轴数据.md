# 10 MPU6050：软硬件 I2C 读写六轴数据

## 本章问题

怎样先确认 MPU6050 的身份，再读取并解释六轴数据？

## 学习目标

- 配置 MPU6050 的 3.3 V I2C 接线
- 区分设备地址、HAL 参数与寄存器地址
- 用 `WHO_AM_I` 验证两种 I2C 通信
- 解析连续读取的 14 字节六轴数据
- 按实验现象定位通信与换算故障

## 0. 先建立直觉：六轴在测什么

拆开名字看：MPU6050 把两只传感器装进了同一颗芯片——一只三轴加速度计和一只三轴陀螺仪，合计"六轴"。本章不做姿态解算，只做两件事：把六个物理量对应的原始值从芯片里读出来，再换算成看得懂的数字。

**加速度计测量线性加速度，其中静止时主要表现为重力分量。** 每个轴输出一个带符号的加速度。传感器静止且水平放置时，合加速度约为地球重力加速度 $9.8\ \text{m/s}^2$，工程上通常记作 $1\ g$。重力在三个轴上的分量随姿态变化：大致竖直的轴接近 $\pm1\ g$，另外两个轴接近 $0$。这就是 4.4 节水平静止时某个轴接近 2048 的原因，也是加速度计可以反映倾斜姿态的基础。

**陀螺仪测量绕各轴的角速度。** 单位为 °/s（度每秒）：读数 360 °/s 表示每秒转一整圈。它输出的是瞬时转速，不是已经转过的角度；角度需要对角速度积分，本章不展开。

**芯片内部发生的事**：六个物理量各自被模数转换成一个 16 位有符号整数（原始值），放进一组内部寄存器。本章的全部工作就是用 I2C 把这些原始值取回来、按量程换算成 g 和 °/s。

方向问题留到实验里解决：绕哪个方向转读数变正、往哪边倾斜变负，与芯片焊接朝向和你的观察方向都有关，先记录"朝某方向转动时数值变大还是变小"再解读数据，比背方向定义更可靠。

## 1. 硬件接线、电平与地址

### 1.1 接线与引脚配置

本章使用 STM32F103C8T6、MPU6050 和软件 I2C OLED。OLED 与 MPU6050 使用两组独立总线。本章配套工程为 `E:\ProjectStm\Courses\HAL10_MPU6050_I2C`，两个子工程 `01_SoftI2C`（软件版，第 4 节）与 `02_HardwareI2C`（硬件版，第 5 节）与正文一一对应：

| 模块 | 信号 | STM32 引脚 | 配置与用途 |
| --- | --- | --- | --- |
| OLED | SCL | PB8 | `Output Open Drain`，软件 I2C |
| OLED | SDA | PB9 | `Output Open Drain`，软件 I2C |
| MPU6050 | SCL | PB10 | 软件版为开漏 GPIO；硬件版为 `I2C2_SCL` |
| MPU6050 | SDA | PB11 | 软件版为开漏 GPIO；硬件版为 `I2C2_SDA` |
| 两模块 | VCC | 3.3 V | 先确认模块供电规格，不能把 3.3 V 信号上拉到 5 V |
| 两模块 | GND | GND | STM32、OLED、MPU6050 必须共地 |

上电前检查：

1. PB10 接 SCL，PB11 接 SDA，PB8/PB9 不要与 PB10/PB11 接混；
2. SCL、SDA 必须有到 3.3 V 的上拉，总线空闲时均为高电平；
3. 软件版将 PB8～PB11 配为 `Output Open Drain`、初始电平 `High`；开漏输出写 1 是"释放"线路，不是主动输出强高电平；
4. 硬件版把 PB10/PB11 配为 I2C2 复用开漏，不要再用普通 GPIO 初始化覆盖它们；
5. `AD0=0` 时 MPU6050 的 7 位地址为 `0x68`，`AD0=1` 时为 `0x69`，本章使用 `0x68`；
6. `INT` 暂不连接，`XDA/XCL` 不使用。

这些配置在 CubeMX 里这样落实（软件版，PB8～PB11 四只脚做法相同）：

1. 在芯片图上依次单击 `PB8`、`PB9`、`PB10`、`PB11`，都选 `GPIO_Output`；
2. 在 `System Core -> GPIO` 详细配置里逐脚确认四项：`GPIO output level` 为 `High`（总线空闲高电平）、`GPIO Mode` 为 `Output Open Drain`、`GPIO Pull-up/Pull-down` 为 `No pull-up and no pull-down`（上拉交给模块电阻或外接电阻）、`Maximum output speed` 选 `High`（配套工程为 `GPIO_SPEED_FREQ_HIGH`）；
3. 两处容易填错：`GPIO Mode` 留成默认 `Output Push Pull` 时，写 1 不再是"释放线路"而是主动强推高电平，从机拉低期间会形成从电源到地的直通电流；`GPIO output level` 填 `Low` 会让总线一上电就被拉住，第一个 START 无法形成；
4. 点 `GENERATE CODE` 后对照生成的 `MX_GPIO_Init()`：四只脚应为 `GPIO_MODE_OUTPUT_OD`，且初始化前先写入 `GPIO_PIN_SET`（见配套工程 `01_SoftI2C/Core/Src/main.c`）。

软件版用 `MYI2C_DELAY_LOOPS` 控制速度，默认值为 `40U`。改变系统主频或编译优化后，应重新测量 SCL 频率，不能仅凭延时循环数判断通信速率。

### 1.2 四种容易混淆的地址

| 名称 | 本章数值 | 含义 |
| --- | ---: | --- |
| 7 位设备地址 | `0x68` | `AD0=0` 时的 MPU6050 地址 |
| 软件 I2C 写地址字节 | `0xD0` | `0x68 << 1`，最低位为写方向 |
| 软件 I2C 读地址字节 | `0xD1` | `(0x68 << 1) \| 0x01U` |
| HAL 地址参数 | `0xD0` | 传给 `HAL_I2C_Mem_Read()`、`HAL_I2C_Mem_Write()` 和 `HAL_I2C_IsDeviceReady()` 的参数：7 位地址左移 1 位 |

```c
#define MPU6050_ADDR_7BIT  0x68U
#define MPU6050_ADDR_HAL   (MPU6050_ADDR_7BIT << 1)
#define MPU6050_ADDR_WRITE (MPU6050_ADDR_7BIT << 1)
#define MPU6050_ADDR_READ  ((MPU6050_ADDR_7BIT << 1) | 0x01U)
```

为什么线上字节要左移：I2C 的地址字节共 8 位，高 7 位是设备地址，最低位留给读写方向（0 表示写、1 表示读）。主机发出的地址字节 = 7 位地址左移 1 位、再把最低位填上方向：`0x68` 左移得 `0xD0`，填上读方向得 `0xD1`。

软件 I2C 自己拼这个字节，直接发送 `0xD0/0xD1`；STM32F1 HAL 的 `DevAddress` 参数要求传入已左移的 `0xD0`，方向位由 HAL 在事务中自行填——本地 HAL 源码对 `DevAddress` 的说明是"datasheet 中的 7 位地址在调用接口前必须左移"，配套工程的 `MPU6050_ADDR_HAL` 正是 `(0x68 << 1)`。把 `0x68` 直接传给本课程这版 F1 HAL，线上地址字节会对应 7 位地址 `0x34`（`0x68 >> 1`），MPU6050 永远不应答，后果见 5.2 节。

不同系列、不同版本的 HAL 约定可能不同，升级 HAL 后以本地头文件和源码注释为准。

最后区分两个容易混淆的编号：`WHO_AM_I(0x75)` 是芯片内部的寄存器地址，与设备地址不是同一个概念——设备地址 `0x68` 负责"总线上找谁"，寄存器地址 `0x75` 负责"找到之后读它内部的哪个寄存器"。

## 2. 寄存器、初始化与数据格式

### 2.1 关键寄存器和配置值

```c
#define MPU6050_SMPLRT_DIV      0x19U
#define MPU6050_CONFIG          0x1AU
#define MPU6050_GYRO_CONFIG     0x1BU
#define MPU6050_ACCEL_CONFIG    0x1CU
#define MPU6050_ACCEL_XOUT_H    0x3BU
#define MPU6050_GYRO_XOUT_H     0x43U
#define MPU6050_PWR_MGMT_1      0x6BU
#define MPU6050_PWR_MGMT_2      0x6CU
#define MPU6050_WHO_AM_I        0x75U

#define MPU6050_PWR_MGMT_1_VALUE  0x01U
#define MPU6050_PWR_MGMT_2_VALUE  0x00U
#define MPU6050_SMPLRT_DIV_VALUE  0x09U
#define MPU6050_CONFIG_VALUE      0x06U
#define MPU6050_GYRO_FS_2000DPS   0x18U
#define MPU6050_ACCEL_FS_16G      0x18U

#define MPU6050_ACCEL_LSB_PER_G   2048.0f
#define MPU6050_GYRO_LSB_PER_DPS  16.4f
#define MPU6050_WHO_AM_I_VALUE    0x68U
```

| 寄存器 | 写入值 | 作用 |
| --- | ---: | --- |
| `PWR_MGMT_1(0x6B)` | `0x01` | 解除睡眠，选择 X 轴陀螺仪 PLL 作为时钟参考 |
| `PWR_MGMT_2(0x6C)` | `0x00` | 使能三个加速度计轴和三个陀螺仪轴 |
| `SMPLRT_DIV(0x19)` | `0x09` | 与数字低通滤波器配合，将采样率设为约 100 Hz |
| `CONFIG(0x1A)` | `0x06` | 设置 `DLPF_CFG=6` |
| `GYRO_CONFIG(0x1B)` | `0x18` | 陀螺仪量程设为 ±2000 °/s |
| `ACCEL_CONFIG(0x1C)` | `0x18` | 加速度计量程设为 ±16 g |

两个"调速"寄存器的直觉：`SMPLRT_DIV` 是分频器，值越大，寄存器里的测量结果刷新越慢；`CONFIG` 里的 `DLPF_CFG` 选择内部数字低通滤波器的强度——滤波越强，数值越平滑，但对转动的响应越迟钝。本章 `0x06` 与 `0x09` 的组合得到约 100 Hz 的采样率；想改采样率或平滑程度时，两者要一起权衡。

初始化必须按以下顺序执行：

```text
MyI2C_Init()（仅软件版）
-> 读取 WHO_AM_I，必须为 0x68
-> 写 PWR_MGMT_1=0x01
-> HAL_Delay(100U)
-> 写 PWR_MGMT_2=0x00
-> 写 SMPLRT_DIV=0x09
-> 写 CONFIG=0x06
-> 写 GYRO_CONFIG=0x18
-> 写 ACCEL_CONFIG=0x18
```

MPU6050 上电后默认休眠；若未先写 `PWR_MGMT_1`，即使 `WHO_AM_I` 正确，测量值也可能不更新。

先验身份再配置的用意：`WHO_AM_I` 通过，说明供电、接线、地址、时序四件事都通了；它不通过时，后面写六个配置寄存器全是无效操作，还会把"总线问题"和"配置问题"搅在一起——这正是 3.2 节实验顺序的依据。

### 2.2 写寄存器与读寄存器时序

先把"寄存器"想具体：MPU6050 内部有一排按地址编号的存储格——`WHO_AM_I(0x75)` 这一格放着出厂写死的身份编号，`0x3B` 起的十几格放着最新一次的测量结果。芯片只有 SCL/SDA 两个引脚，不会主动开口；主机想访问哪一格，必须先在写方向上把格号（寄存器地址）送进去，芯片把它锁存到内部的地址指针里，随后的读操作从指针所指的格子取数，每取出一个字节指针自动加一——这正是 2.4 节能从 `0x3B` 一口气读出 14 字节的前提。所以"读寄存器"永远是两段：先用写方向送地址，再切换读方向取数据。

写一个内部寄存器：

```text
START -> 0xD0 -> ACK -> Register Address -> ACK -> Data -> ACK -> STOP
```

读取指定寄存器时，先用写方向发送内部寄存器地址，再用重复起始切换为读：

```text
START
-> 0xD0       设备地址 + 写
-> ACK
-> 0x75       WHO_AM_I
-> ACK
-> REPEATED START
-> 0xD1       设备地址 + 读
-> ACK
<- 0x68       返回数据
-> NACK       最后一个字节后不再继续读取
-> STOP
```

读多个字节时，中间字节后发送 ACK，最后一个字节后发送 NACK。这里的 NACK 是正常结束动作，不是错误。

### 2.3 逐寄存器读取与大端有符号拼接

每个 16 位数据按高字节在前、低字节在后的方式存放，并按二进制补码解释。完整辅助函数见 4.3 节；这里先用展开式看清字段关系。用 `MPU6050_ReadRegs()` 分别读取高、低字节：

```c
uint8_t high;
uint8_t low;

if ((MPU6050_ReadRegs(MPU6050_ACCEL_XOUT_H, &high, 1U) == HAL_OK) &&
    (MPU6050_ReadRegs(MPU6050_ACCEL_XOUT_H + 1U, &low, 1U) == HAL_OK))
{
    int16_t accel_x = (int16_t)(((uint16_t)high << 8) | (uint16_t)low);
}
```

`0x3B` 是 `ACCEL_XOUT_H`，`0x3C` 是其低字节。两次独立事务只用于理解寄存器布局；实际连续采样时，高、低字节可能来自相邻时刻，应使用一次连续读取。

补码解释一个具体例子：设某个轴的静止读数约 +2048，即 `0x0800`，高字节 `0x08`、低字节 `0x00`；把模块翻转让该轴反向后读数约 -2048，按 16 位补码是 `0xF800`，高字节 `0xF8`、低字节 `0x00`。拼接后若误存进 `uint16_t`，`0xF800` 会变成 63488 的大正数——第 7 节"负数变成大正数"的故障正是这个机理。

### 2.4 连续读取 14 字节

从 `ACCEL_XOUT_H(0x3B)` 开始连续读取 14 字节：

| 缓冲区偏移 | 数据 |
| ---: | --- |
| 0、1 | Accel X 高、低字节 |
| 2、3 | Accel Y 高、低字节 |
| 4、5 | Accel Z 高、低字节 |
| 6、7 | Temperature 高、低字节，本章跳过 |
| 8、9 | Gyro X 高、低字节 |
| 10、11 | Gyro Y 高、低字节 |
| 12、13 | Gyro Z 高、低字节 |

```text
START -> 0xD0 -> ACK -> 0x3B -> ACK -> REPEATED START
-> 0xD1 -> ACK -> byte[0..13] -> NACK -> STOP
```

前 13 个接收字节后发送 ACK，第 14 个字节后发送 NACK。连续读取减少了起停条件和内部寄存器寻址的重复开销，也能让六个轴的数值更接近同一时刻。

温度两个字节的换算式是 °C = 原始值 / 340 + 36.53，本章不实现，读出来后原样跳过。

注意六个轴的寄存器并不连续：加速度占 `0x3B~0x40`，中间隔着温度 `0x41/0x42`，角速度从 `0x43` 才开始。所以"跳过温度只读 12 字节"用一次连续读取做不到——指针会顺着温度一路走下来。这正是本章驱动从 `0x3B` 一次读满 14 字节、在软件里丢弃温度两字节的原因。

### 2.5 量程换算

| 加速度量程 | 灵敏度 | 陀螺仪量程 | 灵敏度 |
| --- | ---: | --- | ---: |
| ±2 g | 16384 LSB/g | ±250 °/s | 131 LSB/(°/s) |
| ±4 g | 8192 LSB/g | ±500 °/s | 65.5 LSB/(°/s) |
| ±8 g | 4096 LSB/g | ±1000 °/s | 32.8 LSB/(°/s) |
| ±16 g | 2048 LSB/g | ±2000 °/s | 16.4 LSB/(°/s) |

本章写入 `GYRO_CONFIG=0x18` 和 `ACCEL_CONFIG=0x18`，因此换算为：

```c
accel_g  = accel_raw / 2048.0f;
gyro_dps = gyro_raw / 16.4f;
```

量程的含义先建立直觉：量程是芯片一次测量能表示的最大物理量。±16 g 档能记录到 16 g 的冲击，代价是 16 位数值要铺满 32 g 的全程，每一级（LSB）对应的物理量更大，微小变化更难分辨；±2 g 档把 16 位数值铺在 4 g 的全程上，分辨率高 8 倍，但超过 2 g 的加速度会"顶格"削平。选择原则：让预期的最大加速度、角速度落在量程内，并尽量用小量程换取分辨率。

表中灵敏度不必死记，可以算出来：16 位有符号数共 65536 级，均匀铺满量程全程。±2 g 全程 4 g，$65536 / 4 = 16384$，即每 1 g 对应 16384 级；±16 g 全程 32 g，$65536 / 32 = 2048$。陀螺仪同理：±250 °/s 全程 500 °/s，$65536 / 500 \approx 131$；±2000 °/s 全程 4000 °/s，$65536 / 4000 \approx 16.4$。改量程时换算常量必须跟着改，否则结果整体偏差一个固定倍数——最大档与最小档的灵敏度正好差 8 倍，对应第 7 节"数据相差约 8 倍"的故障。

两个心算例子（对应 4.4 节屏幕上的原始值）：水平静置时某个轴显示约 2048，$2048 / 2048 = 1.0$ g，正是重力；带着模块慢慢转动，某陀螺仪轴显示约 820，$820 / 16.4 = 50$ °/s，即每秒转 50 度。记住"2048 个 LSB ≈ 1 g、16.4 个 LSB ≈ 1 °/s"，看原始值就能直接估算物理量。

驱动提供的等价接口为：

```c
accel_g  = MPU6050_AccelToG(accel_raw);
gyro_dps = MPU6050_GyroToDps(gyro_raw);
```

先确认原始值和 `WHO_AM_I`，再查看物理量，避免把接线或换算问题混在一起。

想换量程时的完整动作：改 2.1 节 `GYRO_CONFIG`/`ACCEL_CONFIG` 的写入值，同时把驱动头文件里的 `MPU6050_ACCEL_LSB_PER_G`、`MPU6050_GYRO_LSB_PER_DPS` 换成本表对应行的灵敏度，两个子工程各改各的，不要只改一处。

## 3. 共用上层接口与实验顺序

### 3.1 共用数据结构与函数签名

软硬件驱动使用相同的数据结构和函数签名：

```c
#define MPU6050_DATA_LENGTH 14U
#define MPU6050_TIMEOUT_MS  100U

typedef struct
{
    int16_t AccX;
    int16_t AccY;
    int16_t AccZ;
    int16_t GyroX;
    int16_t GyroY;
    int16_t GyroZ;
} MPU6050_Data;

HAL_StatusTypeDef MPU6050_Init(I2C_HandleTypeDef *hi2c);
HAL_StatusTypeDef MPU6050_WriteReg(uint8_t reg, uint8_t value);
HAL_StatusTypeDef MPU6050_ReadRegs(uint8_t reg, uint8_t *data, uint16_t length);
HAL_StatusTypeDef MPU6050_ReadDeviceID(uint8_t *id);
HAL_StatusTypeDef MPU6050_GetData(MPU6050_Data *data);
float MPU6050_AccelToG(int16_t raw);
float MPU6050_GyroToDps(int16_t raw);
```

软件版调用 `MPU6050_Init(NULL)`，硬件版调用 `MPU6050_Init(&hi2c2)`。这个参数只是为了共用同一份上层代码；软件版不使用 I2C 句柄。软件版没有 HAL 总线超时，`MPU6050_TIMEOUT_MS` 在硬件版中使用。

两版之间切换时，上层代码只动三四处：头文件名（软件版 `MPU6050.h` ↔ 硬件版 `mpu6050.h`）、`MPU6050_Init()` 的参数（`NULL` ↔ `&hi2c2`）、是否初始化 I2C2；硬件版的上层文件还会多一句 `#include "i2c.h"`（声明 `hi2c2` 用）。数据结构、换算函数和显示代码一行不动——这正是 3.2 节实验步骤 4 能"只换底层"的原因。

> [!warning]
> 两个头文件目前仅靠大小写区分（`MPU6050.h` 与 `mpu6050.h`）。Windows 文件系统对大小写不敏感，两份文件放进同一目录会互相覆盖、`#include` 也可能解析到错的那个——当前约定是它们分属各自子工程的独立目录；若以后合并维护，建议改成 `MPU6050_Soft.h` / `MPU6050_Hw.h` 这类一眼可辨的名字。

### 3.2 实验顺序

1. 用软件 I2C 只读 `WHO_AM_I`，得到 `0x68`；
2. 用软件 I2C 执行初始化，并先用逐寄存器方式核对一个轴的字节顺序；
3. 把六轴读取改为从 `0x3B` 连续读取 14 字节；
4. 保持数据结构和显示代码不变，只把底层替换为 HAL 硬件 I2C。

不要在 `WHO_AM_I` 未通过时直接调试六轴换算，也不要同时把软件版和硬件版同名驱动加入同一工程。

把四个步骤的"输入 → 处理 → 输出"摆在一起，每一步都有明确的预期现象：

| 步骤 | 输入 | 处理 | 输出与预期现象 |
| --- | --- | --- | --- |
| 1. 只读 `WHO_AM_I` | 上电、接好总线 | 发 `0x75` 读 1 字节 | OLED 显示 `ID:68`；显示 `READ ERR` 时按第 7 节从供电查起 |
| 2. 逐寄存器核对字节顺序 | 模块竖起，让 X 轴大致竖直 | 分别读 `0x3B`、`0x3C` 各 1 字节 | `AccX` ≈ ±2048 = `±0x0800`：高字节约 `0x08`（或 `0xF8`，取决于朝向，待实测），低字节在 `0x00` 附近小幅跳动 |
| 3. 连续读取 14 字节 | 转动、倾斜模块 | 从 `0x3B` 一次读 14 字节并解析 | 六列数值同时刷新；绕哪个轴转，对应陀螺仪列变化最明显 |
| 4. 底层换成 HAL 硬件 I2C | 与步骤 3 相同姿态 | 数据结构、显示代码不变 | 现象与步骤 3 一致，瞬时值不要求逐位相同 |

步骤 2 中如果看到高字节在 `0x00`/`0xFF` 附近、低字节反而稳定出现 `0x08` 一类值，说明高低字节的角色颠倒了：本该约 2048 的读数变成约 8，与第 7 节"相差 256 倍"的故障同源。

## 4. 软件 I2C 的最小完整实现

### 4.1 GPIO 模拟 I2C

PB8～PB11 必须先由 `MX_GPIO_Init()` 配为开漏输出、高电平。`MyI2C_Init()` 只释放线路，不负责配置 GPIO。

```c
#ifndef __MY_I2C_H
#define __MY_I2C_H

#include "main.h"

#define MYI2C_PORT        GPIOB
#define MYI2C_SCL_PIN     GPIO_PIN_10
#define MYI2C_SDA_PIN     GPIO_PIN_11

#ifndef MYI2C_DELAY_LOOPS
#define MYI2C_DELAY_LOOPS 40U
#endif

void MyI2C_Init(void);
void MyI2C_Start(void);
void MyI2C_Stop(void);
void MyI2C_SendByte(uint8_t byte);
uint8_t MyI2C_ReceiveByte(void);
void MyI2C_SendAck(uint8_t ack_bit);
uint8_t MyI2C_ReceiveAck(void);

#endif
```

```c
#include "MyI2C.h"

static void MyI2C_Delay(void)
{
    volatile uint32_t i;

    for (i = 0U; i < MYI2C_DELAY_LOOPS; i++)
    {
        __NOP();
    }
}

static void MyI2C_W_SCL(uint8_t bit)
{
    HAL_GPIO_WritePin(MYI2C_PORT, MYI2C_SCL_PIN,
                      bit ? GPIO_PIN_SET : GPIO_PIN_RESET);
    MyI2C_Delay();
}

static void MyI2C_W_SDA(uint8_t bit)
{
    HAL_GPIO_WritePin(MYI2C_PORT, MYI2C_SDA_PIN,
                      bit ? GPIO_PIN_SET : GPIO_PIN_RESET);
    MyI2C_Delay();
}

static uint8_t MyI2C_R_SDA(void)
{
    uint8_t bit = (HAL_GPIO_ReadPin(MYI2C_PORT, MYI2C_SDA_PIN)
                   == GPIO_PIN_SET) ? 1U : 0U;
    MyI2C_Delay();
    return bit;
}

void MyI2C_Init(void)
{
    MyI2C_W_SDA(1U);
    MyI2C_W_SCL(1U);
}

void MyI2C_Start(void)
{
    MyI2C_W_SDA(1U);
    MyI2C_W_SCL(1U);
    MyI2C_W_SDA(0U);
    MyI2C_W_SCL(0U);
}

void MyI2C_Stop(void)
{
    MyI2C_W_SDA(0U);
    MyI2C_W_SCL(1U);
    MyI2C_W_SDA(1U);
}

void MyI2C_SendByte(uint8_t byte)
{
    uint8_t i;

    for (i = 0U; i < 8U; i++)
    {
        MyI2C_W_SDA((byte & (0x80U >> i)) != 0U);
        MyI2C_W_SCL(1U);
        MyI2C_W_SCL(0U);
    }
}

uint8_t MyI2C_ReceiveByte(void)
{
    uint8_t byte = 0U;
    uint8_t i;

    MyI2C_W_SDA(1U);  /* 读周期必须释放 SDA */
    for (i = 0U; i < 8U; i++)
    {
        MyI2C_W_SCL(1U);
        if (MyI2C_R_SDA() != 0U)
        {
            byte |= (uint8_t)(0x80U >> i);
        }
        MyI2C_W_SCL(0U);
    }
    return byte;
}

void MyI2C_SendAck(uint8_t ack_bit)
{
    MyI2C_W_SDA(ack_bit);
    MyI2C_W_SCL(1U);
    MyI2C_W_SCL(0U);
}

uint8_t MyI2C_ReceiveAck(void)
{
    uint8_t ack_bit;

    MyI2C_W_SDA(1U);
    MyI2C_W_SCL(1U);
    ack_bit = MyI2C_R_SDA();
    MyI2C_W_SCL(0U);
    return ack_bit;
}
```

发送字节必须高位先发；接收第 9 个时钟时，`ack_bit=0` 表示从机 ACK，`ack_bit=1` 表示 NACK。

这套底层与第 9 章 [[09 I2C：总线时序与软件 I2C 驱动 OLED]] 的 `OLED_I2C_*` 同源：同样的开漏 GPIO、同样的"SCL 高电平期间 SDA 保持稳定"节拍。两处差异都是为 MPU6050 补的：一是 OLED 只写不读，第 9 章没有接收函数、也不检查应答；本章要读回数据、并靠应答判断"器件在不在"，所以多了 `MyI2C_ReceiveByte()` 和应答收发两个动作。二是第 9 章位与位之间没有逐位延时，本章每次电平翻转后插入 `MyI2C_Delay()`，用空循环把 SCL 压到传感器稳定工作的低速。另外，本章 OLED 走 PB8/PB9、MPU6050 走 PB10/PB11，是两条物理独立的软件 I2C 总线，`MyI2C.h` 的宏只作用于 MPU6050 这一条。

新建 `MyI2C.c`、`MPU6050.c` 这类文件后，记得按 [[00 从零建立HAL工程]] 第 5 节在根 `CMakeLists.txt` 登记源文件和头文件目录，否则链接时会报 `undefined reference`。

### 4.2 MPU6050 寄存器读写与身份验证

```c
HAL_StatusTypeDef MPU6050_WriteReg(uint8_t reg, uint8_t value)
{
    MyI2C_Start();
    MyI2C_SendByte(MPU6050_ADDR_WRITE);
    if (MyI2C_ReceiveAck() != 0U)
    {
        goto nack;
    }

    MyI2C_SendByte(reg);
    if (MyI2C_ReceiveAck() != 0U)
    {
        goto nack;
    }

    MyI2C_SendByte(value);
    if (MyI2C_ReceiveAck() != 0U)
    {
        goto nack;
    }

    MyI2C_Stop();
    return HAL_OK;

nack:
    MyI2C_Stop();
    return HAL_ERROR;
}

HAL_StatusTypeDef MPU6050_ReadRegs(uint8_t reg, uint8_t *data, uint16_t length)
{
    uint16_t i;

    if ((data == NULL) || (length == 0U))
    {
        return HAL_ERROR;
    }

    MyI2C_Start();
    MyI2C_SendByte(MPU6050_ADDR_WRITE);
    if (MyI2C_ReceiveAck() != 0U)
    {
        goto nack;
    }

    MyI2C_SendByte(reg);
    if (MyI2C_ReceiveAck() != 0U)
    {
        goto nack;
    }

    MyI2C_Start();  /* 重复起始，不先发送 STOP */
    MyI2C_SendByte(MPU6050_ADDR_READ);
    if (MyI2C_ReceiveAck() != 0U)
    {
        goto nack;
    }

    for (i = 0U; i < length; i++)
    {
        data[i] = MyI2C_ReceiveByte();
        MyI2C_SendAck((i + 1U == length) ? 1U : 0U);
    }

    MyI2C_Stop();
    return HAL_OK;

nack:
    MyI2C_Stop();
    return HAL_ERROR;
}

HAL_StatusTypeDef MPU6050_ReadDeviceID(uint8_t *id)
{
    return MPU6050_ReadRegs(MPU6050_WHO_AM_I, id, 1U);
}
```

先在 `main()` 的 `MX_GPIO_Init()` 之后、`/* USER CODE BEGIN 2 */` 中临时验证最短闭环：

```c
/* USER CODE BEGIN PV */
static uint8_t mpu_id;
/* USER CODE END PV */

/* USER CODE BEGIN 2 */
OLED_Init();

if (MPU6050_ReadDeviceID(&mpu_id) == HAL_OK)
{
    OLED_ShowString(1, 1, "ID:");
    OLED_ShowHexNum(1, 4, mpu_id, 2U);
}
else
{
    OLED_ShowString(1, 1, "READ ERR");
}
/* USER CODE END 2 */
```

预期 OLED 显示 `ID:68`，逻辑分析仪应看到：

```text
START -> 0xD0/W -> ACK -> 0x75 -> ACK
-> REPEATED START -> 0xD1/R -> ACK -> 0x68 -> NACK -> STOP
```

如果屏幕停在 `READ ERR`，说明最短闭环没通过——此时不要往下写任何配置寄存器，回到第 7 节从供电查起。如果显示的是别的十六进制值而不是 `68`，说明时序已经通了、但读回的内容不对，重点对照第 7 节 `WHO_AM_I` 读到 `0xFF`、`0x00` 和"地址有 ACK 但值不对"的三行。验证通过后，这段最短闭环可以保留在 `USER CODE` 区域里，作为每次开机的自检。

### 4.3 软件版初始化与 14 字节连续读取

软件版初始化函数和 14 字节解析如下。它通过 `NULL` 与硬件版保持同一函数签名：

```c
HAL_StatusTypeDef MPU6050_Init(I2C_HandleTypeDef *hi2c)
{
    uint8_t id;

    (void)hi2c;
    MyI2C_Init();

    if (MPU6050_ReadDeviceID(&id) != HAL_OK)
    {
        return HAL_ERROR;
    }
    if (id != MPU6050_WHO_AM_I_VALUE)
    {
        return HAL_ERROR;
    }

    if (MPU6050_WriteReg(MPU6050_PWR_MGMT_1,
                         MPU6050_PWR_MGMT_1_VALUE) != HAL_OK)
    {
        return HAL_ERROR;
    }
    HAL_Delay(100U);

    if (MPU6050_WriteReg(MPU6050_PWR_MGMT_2,
                         MPU6050_PWR_MGMT_2_VALUE) != HAL_OK)
    {
        return HAL_ERROR;
    }
    if (MPU6050_WriteReg(MPU6050_SMPLRT_DIV,
                         MPU6050_SMPLRT_DIV_VALUE) != HAL_OK)
    {
        return HAL_ERROR;
    }
    if (MPU6050_WriteReg(MPU6050_CONFIG,
                         MPU6050_CONFIG_VALUE) != HAL_OK)
    {
        return HAL_ERROR;
    }
    if (MPU6050_WriteReg(MPU6050_GYRO_CONFIG,
                         MPU6050_GYRO_FS_2000DPS) != HAL_OK)
    {
        return HAL_ERROR;
    }

    return MPU6050_WriteReg(MPU6050_ACCEL_CONFIG, MPU6050_ACCEL_FS_16G);
}

static int16_t MPU6050_BE16(const uint8_t *p)
{
    return (int16_t)(((uint16_t)p[0] << 8) | (uint16_t)p[1]);
}

HAL_StatusTypeDef MPU6050_GetData(MPU6050_Data *data)
{
    uint8_t buffer[MPU6050_DATA_LENGTH];
    HAL_StatusTypeDef status;

    if (data == NULL)
    {
        return HAL_ERROR;
    }

    status = MPU6050_ReadRegs(MPU6050_ACCEL_XOUT_H,
                               buffer,
                               MPU6050_DATA_LENGTH);
    if (status != HAL_OK)
    {
        return status;
    }

    data->AccX  = MPU6050_BE16(&buffer[0]);
    data->AccY  = MPU6050_BE16(&buffer[2]);
    data->AccZ  = MPU6050_BE16(&buffer[4]);
    data->GyroX = MPU6050_BE16(&buffer[8]);
    data->GyroY = MPU6050_BE16(&buffer[10]);
    data->GyroZ = MPU6050_BE16(&buffer[12]);

    return HAL_OK;
}
```

`buffer[6]`、`buffer[7]` 是温度字节，本章不写入 `MPU6050_Data`。

选做练习（时间富余再做）：临时把 `MPU6050_BE16()` 里的 `<< 8` 去掉再编译下载，屏幕上静止时的读数会从约 2048 掉到个位数——这正是第 7 节"相差 256 倍"故障的现场；验证完把移位加回去，读数恢复正常。做过这一遍，高低字节的拼接就真正属于你了。

`app_mpu6050.c` 的完整内容如下（与配套工程 `01_SoftI2C/User/Src/app_mpu6050.c` 一致）。`MPU6050_Init(NULL)` 必须放在 `MX_GPIO_Init()` 和 `OLED_Init()` 之后：

程序先初始化 OLED 和 MPU6050，读回 `WHO_AM_I` 并显示在第四行；初始化或读 ID 失败时显示 `MPU6050 ID ERR` 并停机，避免在未验证身份的芯片上继续写配置。之后进入主循环，每 100 ms 刷新一次六轴读数。硬件版（`02_HardwareI2C`）只是把 `MPU6050_Init(NULL)` 换成 `MPU6050_Init(&hi2c2)`，并多一句 `#include "i2c.h"`，其余完全相同。

预期现象：

- 第四行稳定显示 `ID:68`；
- 水平静止时，一个加速度轴的绝对值接近 `2048 LSB`，约合 1 g；
- 静止时三个陀螺仪轴接近 0，但允许存在零偏；
- 绕单轴旋转时，对应陀螺仪轴变化明显；
- 翻转模块时，对应加速度轴的正负号改变。

如果现象不符合上面任何一条：某次读取失败显示 `READ ERR`，按第 7 节"不 ACK"与"程序卡在通信函数"两行处理；数值有了但静止基线、符号、变化趋势不对，逐条回到第 7 节对应行，先原始值后物理量地缩小范围。

## 5. HAL 硬件 I2C 的最小完整实现

### 5.1 I2C2 配置与调用顺序

硬件版保留 PB8/PB9 的软件 I2C OLED，在 CubeMX 中配置（对照配套工程 `02_HardwareI2C` 的 `.ioc`）。I2C2 的配置方法与第 2 章 [[02 OLED 调试：I2C 显示数据流]] 相同，这里只列本章关心的操作与字段：

1. 打开 `.ioc`，左侧 `Connectivity -> I2C2`，把 `Mode` 下拉框选为 `I2C`。芯片图上 `PB10`、`PB11` 自动变绿并标注 `I2C2_SCL`、`I2C2_SDA`——不需要手动点引脚，但要把标注方向与实际接线核对一遍。忘记选 Mode 时 CubeMX 不生成 I2C2 代码，编译能通过但 `MPU6050_Init()` 必然失败；
2. `Parameter Settings` 逐项确认，每一项都对应生成的 `i2c.c` 里的 `hi2c2.Init` 字段：

| 字段 | 本工程取值 | 对应生成代码 | 填错的后果 |
| --- | --- | --- | --- |
| I2C Speed Mode / I2C Clock Speed (Hz) | Standard Mode / `100000` | `hi2c2.Init.ClockSpeed = 100000` | F103 I2C 的规范上限是 `400 kHz`（快速模式）：Clock Speed 超过 `100000` 时 HAL 按快速模式计算分频，填 `400000` 时 CubeMX 会自动切 Fast 模式并要求配 Duty Cycle。初学先用 100 kHz |
| Duty Cycle | `I2C_DUTYCYCLE_2` | 同名 | 仅 Fast 模式有效，标准模式保持默认 |
| Own Address1 | `0` | `hi2c2.Init.OwnAddress1 = 0` | 本芯片只当主机，保持 0 |
| Addressing Mode | 7 bit | `I2C_ADDRESSINGMODE_7BIT` | 保持默认 |
| Dual Address / General Call / No Stretch | Disable | 同名 | 保持默认 |

3. 时钟树保持 72 MHz。I2C2 挂在 APB1（36 MHz），HAL 内部按 PCLK1 分频产生 SCL 速率，改了主频就要复核 Clock Speed；
4. PB8/PB9 保持 `Output Open Drain` 不动；PB10/PB11 不要配成普通 GPIO，也不要在 `USER CODE` 区域里用 `HAL_GPIO_Init()` 重新初始化它们——那会覆盖 MspInit 配好的复用开漏；总线上拉保留（模块自带或外接电阻）；
5. 点 `GENERATE CODE` 后检查三处：`i2c.c` 里有 `I2C_HandleTypeDef hi2c2` 和 `MX_I2C2_Init()`；`HAL_I2C_MspInit()` 把 PB10/PB11 配成 `GPIO_MODE_AF_OD`（复用开漏）并打开 I2C2、GPIOB 时钟；`Core/Inc/stm32f1xx_hal_conf.h` 中 `HAL_I2C_MODULE_ENABLED` 处于启用状态——漏了它，HAL 的 I2C 函数原型整个不可见，编译报函数未声明。

MPU6050 的 7 位地址是 `0x68`；传给 HAL 的参数为什么是 `0xD0`，见 1.2 节和 5.2 节。

生成代码后应提供：

```c
extern I2C_HandleTypeDef hi2c2;
void MX_I2C2_Init(void);
```

软件版使用 `MPU6050.h`，硬件版使用 `mpu6050.h`（大小写区分的问题见 3.1 节的警告框）。硬件版不要包含软件版 MPU6050 驱动，也不要让 MPU6050 走 `MyI2C_*`。初始化顺序必须是：

```text
MX_GPIO_Init()
-> MX_I2C2_Init()
-> OLED_Init()
-> MPU6050_Init(&hi2c2)
```

### 5.2 HAL 寄存器读写

硬件版只替换最底层读写事务，数据结构、初始化配置、`WHO_AM_I` 检查和 14 字节解析保持不变：

```c
static I2C_HandleTypeDef *g_mpu_i2c = NULL;

HAL_StatusTypeDef MPU6050_WriteReg(uint8_t reg, uint8_t value)
{
    if (g_mpu_i2c == NULL)
    {
        return HAL_ERROR;
    }

    return HAL_I2C_Mem_Write(g_mpu_i2c,
                             MPU6050_ADDR_HAL,
                             reg,
                             I2C_MEMADD_SIZE_8BIT,
                             &value,
                             1U,
                             MPU6050_TIMEOUT_MS);
}

HAL_StatusTypeDef MPU6050_ReadRegs(uint8_t reg, uint8_t *data, uint16_t length)
{
    if ((g_mpu_i2c == NULL) || (data == NULL) || (length == 0U))
    {
        return HAL_ERROR;
    }

    return HAL_I2C_Mem_Read(g_mpu_i2c,
                            MPU6050_ADDR_HAL,
                            reg,
                            I2C_MEMADD_SIZE_8BIT,
                            data,
                            length,
                            MPU6050_TIMEOUT_MS);
}
```

本课程 STM32F1 HAL 的设备地址参数是已左移的 `MPU6050_ADDR_HAL=0xD0`；它对应 MPU6050 的 7 位地址 `0x68`。内部寄存器地址宽度是 `I2C_MEMADD_SIZE_8BIT`，超时是 `MPU6050_TIMEOUT_MS=100U`。`HAL_I2C_Mem_Write()` 的 `pData` 必须是有效缓冲区地址，因此传 `&value`，不能把寄存器值直接当作指针。

函数名里的 `Mem` 值得停一下：HAL 把"先写寄存器地址、再读/写数据"的两段事务打包成了一个调用——参数 `reg` 就是 2.2 节手拼时序里先送进去的寄存器地址，`I2C_MEMADD_SIZE_8BIT` 声明这个内部地址是 8 位宽。也就是说，软件版从 `MyI2C_Start()` 到 `MyI2C_Stop()` 的整整一段，硬件版只相当于一次 `HAL_I2C_Mem_Read()`/`HAL_I2C_Mem_Write()`：时序没有消失，只是被外设接管了。

`DevAddress` 传 `0xD0` 的依据就在工程内 HAL 源码的注释里（"7 位地址在调用前必须左移"），HAL 内部用 `I2C_7BIT_ADD_WRITE/READ` 宏清零或置位最低位来区分读写方向。`HAL_I2C_IsDeviceReady()` 的第三个参数 `3U` 是探测次数（HAL 注释写作 Number of trials）：连发 3 次地址探测，全部无应答才判定器件不在线，以此容忍个别毛刺。

### 5.3 硬件版初始化差异

硬件版不调用 `MyI2C_Init()`，而是在 4.3 节 `MPU6050_Init()` 的开头保存句柄并先检查设备应答：

```c
if (hi2c == NULL)
{
    return HAL_ERROR;
}
g_mpu_i2c = hi2c;

if (HAL_I2C_IsDeviceReady(g_mpu_i2c,
                          MPU6050_ADDR_HAL,
                          3U,
                          MPU6050_TIMEOUT_MS) != HAL_OK)
{
    return HAL_ERROR;
}
```

通过后，直接执行 2.1 节和 4.3 节中相同的 `WHO_AM_I` 检查及六个配置寄存器写入，不再重复一份初始化代码。`MPU6050_ReadDeviceID()`、`MPU6050_GetData()` 和 14 字节缓冲区解析也无需重写；它们调用上面的硬件版 `MPU6050_ReadRegs()`，上层显示代码保持不变。

注意 `HAL_I2C_IsDeviceReady()` 只探测地址应答、不读任何寄存器，它通过不代表 `WHO_AM_I` 一定正确——两步各查各的问题，与软件版"先 ACK 后身份"的分层是一回事。

### 5.4 硬件版主程序差异

硬件版沿用 4.4 节的结构：`main.c` 的 `USER CODE` 区域仍然只有 `MPU6050_Test()` 一行，所有上层逻辑留在 `app_mpu6050.c`。改动只有三处：

1. **`app_mpu6050.c` 的头部与初始化实参**：

```c
#include "i2c.h"        /* 新增：声明 hi2c2 */
#include "mpu6050.h"    /* 换成硬件版驱动（原来是 MPU6050.h） */
#include "OLED.h"

/* MPU6050_Test() 内部把：
   MPU6050_Init(NULL)  换成  MPU6050_Init(&hi2c2) */
```

   其余显示代码、`WHO_AM_I` 检查和主循环一行不动。

2. **`main.c` 的用户区**（`MX_I2C2_Init()` 由 CubeMX 生成的外设初始化段自动调用，排在 `MX_GPIO_Init()` 之后、用户区之前，不需要手写）：

```c
/* USER CODE BEGIN 2 */
HAL_Delay(20U);      /* 给模块上电稳定时间，非协议要求 */
MPU6050_Test();
/* USER CODE END 2 */
```

3. **有效的初始化顺序**：

```text
MX_GPIO_Init()
-> MX_I2C2_Init()        （CubeMX 生成，自动调用）
-> MPU6050_Test()：OLED_Init() -> MPU6050_Init(&hi2c2) -> WHO_AM_I 检查 -> 显示主循环
```

`hi2c2` 由 CubeMX 生成，不要在 `main.c` 中重复定义。

显示布局按固定宽度打印（`OLED_ShowSignedNum(..., 5U)` 恒为"符号 + 5 位数字"），数值变短时旧字符被同宽度的新内容覆盖，不会留下残影——这正是第 7 节提到"OLED 固定宽度覆盖"的含义。

硬件版预期仍显示 `ID:68` 和相同布局的六轴数据；相同姿态下，软硬件版本的符号、量级和变化趋势应一致，瞬时值不要求逐位相同。

## 7. 按现象故障定位

下表按"看到什么"组织，每行给出按顺序检查的入口；7.1 节把最常见的 `READ ERR` 一行走完整。

| 现象 | 按顺序检查 |
| --- | --- |
| OLED 不亮 | 先单独验证 `OLED_Init()` 和 `OLED_ShowString()`；显示端未正常时，不能用它判断 MPU6050 |
| MPU6050 不 ACK，HAL 返回 `HAL_ERROR`、`HAL_BUSY` 或 `HAL_TIMEOUT` | 依次检查 3.3 V 供电、共地、SCL/SDA 是否接反、上拉和空闲高电平、AD0 对应 `0x68/0x69`、软件地址是否为 `0xD0/0xD1`、HAL 参数是否为左移后的 `0xD0`（对应 7 位 `0x68`） |
| `WHO_AM_I` 读到 `0xFF` | 通常是 SDA 一直为高或从机未驱动；重点检查 SDA 接线、上拉、读地址 `0xD1`、重复起始和读前是否释放 SDA |
| `WHO_AM_I` 读到 `0x00` | 通常是 SDA 一直为低；检查短路、主机是否释放 SDA、从机是否卡住，以及第 9 个 ACK 时钟是否正确 |
| 地址有 ACK，但 `WHO_AM_I` 不是 `0x68` | 检查是否发送 `0x75`、重复起始后是否切换到 `0xD1`、软件是否先 STOP 再错误地重新起始，以及 HAL 是否把内部地址宽度设为 8 位 |
| `ID:68` 正确，但六轴不变化 | 先确认已写 `PWR_MGMT_1=0x01` 并等待 100 ms，再检查起始地址 `0x3B`、长度 14、字节偏移、主循环调用和 OLED 固定宽度覆盖 |
| 数据相差约 8 倍 | 回读 `GYRO_CONFIG` 和 `ACCEL_CONFIG`，两者都应为 `0x18`；同时排除下载旧程序或初始化未成功 |
| 数据相差 256 倍，负数变成大正数 | 检查高字节是否左移 8 位、低字节是否按位或拼接，以及结果是否保存为 `int16_t` |
| 软件 I2C 失败、HAL 硬件 I2C 成功 | 检查 START/STOP 边沿、最高位先发、读前释放 SDA、第 9 个时钟 ACK、最后字节 NACK；改变主频或优化等级后重新测量 SCL，必要时增大 `MYI2C_DELAY_LOOPS` |
| HAL 硬件 I2C 失败、软件 I2C 成功 | 检查 I2C2 是否启用、PB10/PB11 是否为复用开漏、APB1 时钟、100 kHz 设置、普通 GPIO 初始化是否覆盖引脚，以及 HAL 返回的具体状态 |
| 程序卡在通信函数 | HAL 调用使用 `MPU6050_TIMEOUT_MS` 等有限超时，不要传 `HAL_MAX_DELAY`；软件 I2C 没有完整的时钟拉伸超时，可释放 SDA、产生最多 9 个 SCL 脉冲后再发 STOP，但恢复总线不能修复短路或错误供电 |

### 7.1 示例：从 `READ ERR` 走一遍

假设现象是：OLED 能正常显示（显示链已单独验证过），但 `WHO_AM_I` 始终读不到，屏幕停在 `READ ERR`。按下面的顺序走，每一步"只改一处，复位重测"，不要同时动几个地方：

1. 断电，量 MPU6050 模块 VCC 与 GND 之间无短路；上电量 VCC-GND 是否为 3.3 V，确认 STM32、OLED、MPU6050 三者共地；
2. 断电核对 SCL→PB10、SDA→PB11 没有接反；确认 AD0 已接 GND（对应 `0x68`）——若 AD0 接了高电平，实际地址是 `0x69`，地址宏和 HAL 参数都要跟着改；
3. 上电量 SCL、SDA 空闲电平，都应接近 3.3 V：哪根线不是高电平，问题就在哪根线的上拉或接线上；
4. 软件版核对 `MPU6050_ADDR_WRITE/READ` 为 `0xD0/0xD1`、`MyI2C.h` 的引脚宏与实际接线一致；硬件版核对传给 HAL 的是 `0xD0`、`MX_I2C2_Init()` 在 `MPU6050_Init()` 之前执行；
5. 有逻辑分析仪就看地址字节后第 9 个时钟 SDA 是否被从机拉低；没有分析仪，硬件版看 HAL 返回值——无应答通常表现为 `HAL_ERROR` 或 `HAL_TIMEOUT`，`HAL_BUSY` 多为上一笔事务尚未收尾，具体语义以本地 HAL 源码为准；
6. 每改一处就复位重测一次 `WHO_AM_I`，通过后再继续后面的问题。

身份验证与六轴显示必须同时成立：仅看到数值变化不能证明读到了正确的 MPU6050。
