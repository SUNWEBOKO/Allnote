## 1. 本章要完成什么

本章使用 STM32F103C8T6、MPU6050 和前篇已经验收过的 SSD1306 OLED，完成两个独立实现：

1. PB10、PB11 配置为普通 GPIO，用软件 I2C 读写 MPU6050；
2. PB10、PB11 交给 I2C2 外设，用 HAL 硬件 I2C 读写 MPU6050。

两套实现保持以下内容不变：

- OLED 显示布局；
- MPU6050 设备地址和寄存器；
- 初始化参数；
- `MPU6050_Data` 数据结构；
- 六轴数据的验收方法。

只替换 MPU6050 的底层通信方式：

```text
供电与上拉
    -> PB10/PB11 软件 I2C 或 I2C2 硬件 I2C
    -> MPU6050 地址与寄存器事务
    -> WHO_AM_I 和六轴原始数据
    -> PB8/PB9 软件 I2C OLED
    -> OLED 同屏显示
```

完成本章后，你应能解释：

- 为什么指定寄存器读取需要“写寄存器地址，再重复起始后读取”；
- 为什么软件 I2C 要在读前释放 SDA；
- 为什么最后一个读字节后发送 NACK；
- 为什么 HAL 地址参数写成 `0x68 << 1`；
- 如何把两个字节拼成有符号的 16 位数据；
- 为什么相同上层代码可以更换不同的 I2C 底层。

## 2. 硬件连接

### 2.1 两组 I2C 引脚

| 模块 | 信号 | STM32F103C8T6 | 实现方式 |
| --- | --- | --- | --- |
| OLED | SCL | PB8 | GPIO 软件 I2C |
| OLED | SDA | PB9 | GPIO 软件 I2C |
| MPU6050 | SCL | PB10 | 软件版为 GPIO；硬件版为 I2C2_SCL |
| MPU6050 | SDA | PB11 | 软件版为 GPIO；硬件版为 I2C2_SDA |
| 两模块 | VCC | 3.3V | 按模块供电要求确认 |
| 两模块 | GND | GND | 必须与 STM32 共地 |

```text
PB8  ---------------- OLED SCL
PB9  ---------------- OLED SDA

PB10 ---------------- MPU6050 SCL
PB11 ---------------- MPU6050 SDA

3.3V ---------------- OLED VCC、MPU6050 VCC
GND  ---------------- OLED GND、MPU6050 GND
```

OLED 和 MPU6050 使用两组互相独立的总线。即使硬件版把 PB10/PB11 交给 I2C2，OLED 仍由 PB8/PB9 软件驱动，因此切换 MPU6050 底层时不需要修改显示端。

### 2.2 MPU6050 其余引脚

- `AD0=0` 时，MPU6050 的 7 位地址是 `0x68`；
- `AD0=1` 时，7 位地址是 `0x69`；
- 本章默认模块把 AD0 下拉，因此使用 `0x68`；
- `INT` 暂不连接，本章使用轮询读取；
- `XDA/XCL` 是辅助 I2C 接口，本章不使用。

### 2.3 上电前检查

1. OLED、MPU6050 和 STM32 共地；
2. VCC、GND 没有接反，确认模块允许 3.3 V 供电；
3. PB10 为 SCL，PB11 为 SDA；
4. PB8/PB9 与 PB10/PB11 没有接混；
5. 两组总线空闲时，SCL、SDA 都应接近 3.3 V；
6. 确认模块已有上拉，或按原理图补充合适的外部上拉；
7. 软件版不要让 PB10/PB11 同时被 I2C2 或 USART3 占用；
8. 软件版必须由 CubeMX 把 PB10/PB11 配成 `Output Open Drain`、初始电平 `High`：驱动的 `MyI2C_Init()` 只是把这两条线释放为高，不会替你配置 GPIO；
9. 软件版的 SCL 速度由 `MyI2C.h` 里的 `MYI2C_DELAY_LOOPS`（默认 `40`）决定。改了主频（例如从 72 MHz 换到 8 MHz）或开了更高的编译优化后，必须重新实测 SCL 频率，确认没有超过从机上限。

## 3. 地址和寄存器：先分清四种数值

初学者最容易把设备地址、线上地址字节和内部寄存器地址混在一起。始终使用下面的区分：

| 名称 | 示例 | 用途 |
| --- | ---: | --- |
| 7 位设备地址 | `0x68` | 表示是哪一个 MPU6050 |
| 软件 I2C 线上写地址字节 | `0xD0` | `0x68 << 1`，最低位为写方向 |
| 软件 I2C 线上读地址字节 | `0xD1` | `(0x68 << 1) \| 1`，最低位为读方向 |
| HAL 地址参数 | `0x68 << 1` | 传给 `HAL_I2C_Mem_Read/Write()` |
| 内部寄存器地址 | `0x75`、`0x3B` | 指定芯片内部的寄存器 |

```c
#define MPU6050_ADDR_7BIT  0x68U
#define MPU6050_ADDR_HAL   (MPU6050_ADDR_7BIT << 1)
#define MPU6050_ADDR_WRITE (MPU6050_ADDR_7BIT << 1)
#define MPU6050_ADDR_READ  ((MPU6050_ADDR_7BIT << 1) | 0x01U)
```

这四个宏**已经定义在驱动头文件里**（`E:\ProjectStm\驱动库\MPU6050（软件IIC）\MPU6050.h` 与 `MPU6050（硬件iic）\mpu6050.h` 内容相同），**`main.c` 不要再定义一遍**。这里列出来只是为了看清四种地址数值的换算关系。

注意：上表中的“软件 I2C 线上读地址字节”应写成 `((0x68 << 1) | 1)`；这里的 `|` 是按位或，不是数学加法。软件代码直接发送 `0xD0/0xD1`，HAL 接口传入左移后的 `0xD0`，不要把 `0xD0` 再左移一次。

## 4. 指定地址读事务

### 4.1 写一个寄存器

```text
START
-> 0xD0              地址 0x68 + 写
<- ACK
-> Register Address
<- ACK
-> Data
<- ACK
STOP
```

例如向 `PWR_MGMT_1(0x6B)` 写 `0x01`，可以解除睡眠并选择 X 轴陀螺仪 PLL 作为时钟参考。

### 4.2 读一个寄存器

读取 `WHO_AM_I(0x75)` 时，主机先用写方向设置内部寄存器地址，再用重复起始切换到读方向：

```text
START
-> 0xD0              地址 0x68 + 写
<- ACK
-> 0x75              WHO_AM_I 寄存器
<- ACK
REPEATED START
-> 0xD1              地址 0x68 + 读
<- ACK
<- 0x68              从机返回一个数据字节
-> NACK              主机声明不再读取
STOP
```

最后一个字节后的 NACK 在这里是**正常的结束动作**，不是通信失败。若读取多个字节，前面的字节后发送 ACK，最后一个字节后才发送 NACK。

### 4.3 连续读取 14 字节

从 `ACCEL_XOUT_H(0x3B)` 开始连续读取 14 字节：

| 偏移 | 数据 |
| ---: | --- |
| 0, 1 | Accel X 高、低字节 |
| 2, 3 | Accel Y 高、低字节 |
| 4, 5 | Accel Z 高、低字节 |
| 6, 7 | Temperature 高、低字节 |
| 8, 9 | Gyro X 高、低字节 |
| 10, 11 | Gyro Y 高、低字节 |
| 12, 13 | Gyro Z 高、低字节 |

连续读取减少了地址和起停条件的重复开销，也减少了逐轴读取的时间跨度。它不能表述成所有数据在模拟意义上绝对同时采样；准确说法是，MPU6050 提供了连续寄存器读取路径，主机可以更一致地取得这一组数据。

## 5. MPU6050 寄存器和数据格式

### 5.1 本章使用的寄存器

```c
#define MPU6050_SMPLRT_DIV      0x19U
#define MPU6050_CONFIG          0x1AU
#define MPU6050_GYRO_CONFIG     0x1BU
#define MPU6050_ACCEL_CONFIG    0x1CU
#define MPU6050_ACCEL_XOUT_H    0x3BU
#define MPU6050_GYRO_XOUT_H     0x43U
#define MPU6050_PWR_MGMT_1      0x6BU
#define MPU6050_PWR_MGMT_2      0x6CU
#define MPU6050_WHO_AM_I        0x75U

#define MPU6050_PWR_MGMT_1_VALUE  0x01U
#define MPU6050_PWR_MGMT_2_VALUE  0x00U
#define MPU6050_SMPLRT_DIV_VALUE  0x09U
#define MPU6050_CONFIG_VALUE      0x06U
#define MPU6050_GYRO_FS_2000DPS   0x18U
#define MPU6050_ACCEL_FS_16G      0x18U
```

这些寄存器宏、六个配置写入值，以及 `MPU6050_ACCEL_LSB_PER_G(2048.0f)`、`MPU6050_GYRO_LSB_PER_DPS(16.4f)`、`MPU6050_WHO_AM_I_VALUE(0x68U)` 都已经定义在驱动头文件 `MPU6050.h` / `mpu6050.h` 里，`main.c` 直接引用即可，不要再定义一遍。

MPU6050 上电后默认处于睡眠状态，必须先配置 `PWR_MGMT_1`，否则即使 `WHO_AM_I` 正确，测量值也可能不更新。

### 5.2 初始化配置和验证

| 寄存器 | 写入值 | 作用 | 建议验证 |
| --- | ---: | --- | --- |
| `PWR_MGMT_1` | `0x01` | 解除睡眠，选择 X 轴陀螺仪 PLL | 回读后确认不在睡眠 |
| `PWR_MGMT_2` | `0x00` | 使能全部加速度计和陀螺仪轴 | 回读值为 `0x00` |
| `SMPLRT_DIV` | `0x09` | DLPF 开启时采样率约 100 Hz | 与 `CONFIG` 一起理解 |
| `CONFIG` | `0x06` | 设置 DLPF_CFG=6 | 回读值为 `0x06` |
| `GYRO_CONFIG` | `0x18` | 陀螺仪量程 ±2000 °/s | 回读值为 `0x18` |
| `ACCEL_CONFIG` | `0x18` | 加速度计量程 ±16 g | 回读值为 `0x18` |

本章两套工程使用同一组配置。统一参数保证灵敏度和量级可对照，不保证两次不同采样时刻的每个原始值逐位相同。

### 5.3 大端、有符号数据拼接

每个轴是大端存放的 16 位二进制补码：

```c
static int16_t MPU6050_BE16(const uint8_t *p)
{
    return (int16_t)(((uint16_t)p[0] << 8) | p[1]);
}
```

高字节必须左移 8 位。先按 `uint16_t` 拼接，再转成 `int16_t` 解释符号，可以避免整数提升带来的歧义。这个函数在驱动里就是 `MPU6050.c` / `mpu6050.c` 文件内的 `static` 辅助函数，两套写法相同，但都不对外公开。下面是错误写法：

```c
value = high | low;
value = (high >> 8) | low;
```

### 5.4 量程换算

| 加速度量程 | 灵敏度 |
| --- | ---: |
| ±2 g | 16384 LSB/g |
| ±4 g | 8192 LSB/g |
| ±8 g | 4096 LSB/g |
| ±16 g | 2048 LSB/g |

| 陀螺仪量程 | 灵敏度 |
| --- | ---: |
| ±250 °/s | 131 LSB/(°/s) |
| ±500 °/s | 65.5 LSB/(°/s) |
| ±1000 °/s | 32.8 LSB/(°/s) |
| ±2000 °/s | 16.4 LSB/(°/s) |

本章统一使用 ±16 g 和 ±2000 °/s：

```c
accel_g  = accel_raw / 2048.0f;
gyro_dps = gyro_raw / 16.4f;
```

驱动已经提供这两个换算函数，直接调用即可：

```c
accel_g  = MPU6050_AccelToG(raw);   /* 等价于 raw / MPU6050_ACCEL_LSB_PER_G */
gyro_dps = MPU6050_GyroToDps(raw);  /* 等价于 raw / MPU6050_GYRO_LSB_PER_DPS */
```

先显示原始值，确认通信和拼接正确后，再显示物理量。不要在通信尚未通过时直接用换算结果判断传感器。

### 6.2 软件 I2C 头文件和底层时序

`MyI2C.h` 里的接口和可调宏如下。**这些驱动库里已经写好，不要在自己的工程里再定义一遍**：

```c
#ifndef __MY_I2C_H
#define __MY_I2C_H

#include "main.h"

#define MYI2C_PORT              GPIOB
#define MYI2C_SCL_PIN           GPIO_PIN_10
#define MYI2C_SDA_PIN           GPIO_PIN_11

/* 每次电平翻转后插入的空循环次数：用来把 SCL 频率压到从机能接受的范围 */
#ifndef MYI2C_DELAY_LOOPS
#define MYI2C_DELAY_LOOPS       40U
#endif

void MyI2C_Init(void);                  /* 释放 SCL/SDA，进入空闲态 */
void MyI2C_Start(void);
void MyI2C_Stop(void);
void MyI2C_SendByte(uint8_t byte);      /* 高位先发 */
uint8_t MyI2C_ReceiveByte(void);        /* 读一个字节，不去动 ACK */
void MyI2C_SendAck(uint8_t ack_bit);    /* 0 = 回 ACK，1 = 回 NACK */
uint8_t MyI2C_ReceiveAck(void);         /* 返回 0 = 从机 ACK，1 = NACK */

#endif
```

换引脚只改前三个宏，换总线速度只改 `MYI2C_DELAY_LOOPS`。下面是 `MyI2C.c` 里 PB10/PB11 的引脚操作和延时：

```c
#include "MyI2C.h"

static void MyI2C_Delay(void)
{
    volatile uint32_t i;

    for (i = 0U; i < MYI2C_DELAY_LOOPS; i++)
    {
        __NOP();
    }
}

static void MyI2C_W_SCL(uint8_t bit_value)
{
    HAL_GPIO_WritePin(MYI2C_PORT, MYI2C_SCL_PIN,
                      bit_value ? GPIO_PIN_SET : GPIO_PIN_RESET);
    MyI2C_Delay();
}

static void MyI2C_W_SDA(uint8_t bit_value)
{
    HAL_GPIO_WritePin(MYI2C_PORT, MYI2C_SDA_PIN,
                      bit_value ? GPIO_PIN_SET : GPIO_PIN_RESET);
    MyI2C_Delay();
}

static uint8_t MyI2C_R_SDA(void)
{
    uint8_t bit_value;

    bit_value = (HAL_GPIO_ReadPin(MYI2C_PORT, MYI2C_SDA_PIN)
                 == GPIO_PIN_SET) ? 1U : 0U;
    MyI2C_Delay();
    return bit_value;
}

void MyI2C_Init(void)
{
    MyI2C_W_SDA(1U);
    MyI2C_W_SCL(1U);
}
```

开漏输出写 1 表示释放线路。读取 SDA 前也必须先写 1；否则主机仍在拉低 SDA，从机发送的 1 会被覆盖。

注意 `MyI2C_Init()` 只做这两句，**它不调用 `MX_GPIO_Init()`**：PB10/PB11 必须已经由 CubeMX 生成的开漏输出初始化代码配置好。

`MyI2C.c` 里的六个基本时序函数：

```c
void MyI2C_Start(void)
{
    MyI2C_W_SDA(1U);
    MyI2C_W_SCL(1U);
    MyI2C_W_SDA(0U);
    MyI2C_W_SCL(0U);
}

void MyI2C_Stop(void)
{
    MyI2C_W_SDA(0U);
    MyI2C_W_SCL(1U);
    MyI2C_W_SDA(1U);
}

void MyI2C_SendByte(uint8_t byte)
{
    uint8_t i;

    for (i = 0U; i < 8U; i++)
    {
        MyI2C_W_SDA((byte & (0x80U >> i)) != 0U);
        MyI2C_W_SCL(1U);
        MyI2C_W_SCL(0U);
    }
}

uint8_t MyI2C_ReceiveByte(void)
{
    uint8_t byte = 0U;
    uint8_t i;

    MyI2C_W_SDA(1U);
    for (i = 0U; i < 8U; i++)
    {
        MyI2C_W_SCL(1U);
        if (MyI2C_R_SDA() != 0U)
        {
            byte |= (uint8_t)(0x80U >> i);
        }
        MyI2C_W_SCL(0U);
    }
    return byte;
}

void MyI2C_SendAck(uint8_t ack_bit)
{
    MyI2C_W_SDA(ack_bit);
    MyI2C_W_SCL(1U);
    MyI2C_W_SCL(0U);
}

uint8_t MyI2C_ReceiveAck(void)
{
    uint8_t ack_bit;

    MyI2C_W_SDA(1U);
    MyI2C_W_SCL(1U);
    ack_bit = MyI2C_R_SDA();
    MyI2C_W_SCL(0U);
    return ack_bit;
}
```

这里 `ack_bit=0` 表示 ACK，`ack_bit=1` 表示 NACK。最后一个接收字节后发送 `1U`，也就是 NACK。

### 6.3 软件版读取一个寄存器

`MPU6050.c` 里负责这件事的公开函数就是 `MPU6050_ReadRegs()`（硬件版有同名函数，内部改用 `HAL_I2C_Mem_Read()`）。**这部分驱动已经实现，读者不需要自己写**：

```c
HAL_StatusTypeDef MPU6050_ReadRegs(uint8_t reg, uint8_t *data, uint16_t length)
{
    uint16_t i;

    if ((data == NULL) || (length == 0U))
    {
        return HAL_ERROR;
    }

    MyI2C_Start();
    MyI2C_SendByte(MPU6050_ADDR_WRITE);
    if (MyI2C_ReceiveAck() != 0U)
    {
        goto nack;
    }

    /* 先用写方向把内部寄存器地址送进从机 */
    MyI2C_SendByte(reg);
    if (MyI2C_ReceiveAck() != 0U)
    {
        goto nack;
    }

    /* 重复 START 切换方向，主机仍然握着总线 */
    MyI2C_Start();
    MyI2C_SendByte(MPU6050_ADDR_READ);
    if (MyI2C_ReceiveAck() != 0U)
    {
        goto nack;
    }

    for (i = 0U; i < length; i++)
    {
        data[i] = MyI2C_ReceiveByte();
        /* 中间字节回 ACK(0)，最后一个字节回 NACK(1)，告诉从机到此为止 */
        MyI2C_SendAck((i + 1U == length) ? 1U : 0U);
    }

    MyI2C_Stop();
    return HAL_OK;

nack:
    MyI2C_Stop();
    return HAL_ERROR;
}
```

函数在地址、寄存器地址和读地址三个阶段都检查 ACK；任一步收到 NACK，就发送 STOP 并返回 `HAL_ERROR`。最短闭环的身份校验由驱动提供的公开函数完成：

```c
HAL_StatusTypeDef MPU6050_ReadDeviceID(uint8_t *id)
{
    return MPU6050_ReadRegs(MPU6050_WHO_AM_I, id, 1U);
}
```

`main.c` 只调用这一类公开接口；文件内的 `static` 辅助函数（例如拼字节用的 `MPU6050_BE16()`）不对外暴露，`main.c` 里不能调用它们。

### 6.4 最小主程序和验收

先只读取 `WHO_AM_I`。代码分三处放，位置放错会编译不过或被 CubeMX 重新生成时覆盖：

- **文件作用域声明**（`/* USER CODE BEGIN PV */` 区域，在所有函数之外）：`static uint8_t mpu_id;`
- **初始化调用**：写在 `main()` 里 `MX_GPIO_Init()` 之后、`/* USER CODE BEGIN 2 */` 区域；
- **主循环**：本实验只需要显示一次，`while (1)` 里留空。

```c

```

`main.c` 里只需要包含这两个头文件（`MyI2C.h` 由 `MPU6050.c` 内部包含，`main.c` 不直接调用 `MyI2C_*`）：

```c
/* USER CODE BEGIN Includes */
#include "MPU6050.h"

```

注意：本实验直接调用 `MPU6050_ReadDeviceID()`，它不会调用 `MyI2C_Init()`；能正常收发是因为 `MX_GPIO_Init()` 已经把 PB10/PB11 置为开漏输出高电平（释放总线），而 `MyI2C_Start()` 开头也会先释放两条线。实验二的 `MPU6050_Init()` 内部会正式调用一次 `MyI2C_Init()`。

预期现象：OLED 显示 `ID:68`。

验收条件：

## 7. 实验二：配置并读取六轴原始数据

### 7.1 共用上层数据接口

两套驱动的头文件（`MPU6050.h` / `mpu6050.h`）里已经定义了完全相同的数据结构和公开接口，`main.c` 直接使用即可：

```c
typedef struct
{
    int16_t AccX;
    int16_t AccY;
    int16_t AccZ;
    int16_t GyroX;
    int16_t GyroY;
    int16_t GyroZ;
} MPU6050_Data;

HAL_StatusTypeDef MPU6050_Init(I2C_HandleTypeDef *hi2c);
HAL_StatusTypeDef MPU6050_ReadDeviceID(uint8_t *id);
HAL_StatusTypeDef MPU6050_GetData(MPU6050_Data *data);
```

软件版不使用这个句柄，传 `NULL` 即可；硬件版传 `&hi2c2`。这个参数存在的唯一目的，是让两套驱动共用同一份 `main.c`，并不代表软件版真的使用了硬件 I2C 句柄。

### 7.2 软件版初始化

软件版初始化的顺序是：

```text
MyI2C_Init()
    -> 读取 WHO_AM_I
    -> 写 PWR_MGMT_1
    -> 写 PWR_MGMT_2
    -> 写 SMPLRT_DIV
    -> 写 CONFIG
    -> 写 GYRO_CONFIG
    -> 写 ACCEL_CONFIG
```

驱动已经把这套顺序封装成公开函数 `MPU6050_Init(I2C_HandleTypeDef *hi2c)`。**读者的 `main.c` 只需要调用它，不需要自己写初始化流程**。

在 `MPU6050.c` 内部，写单个寄存器的公开函数是 `MPU6050_WriteReg(uint8_t reg, uint8_t value)`，它用 `MyI2C_*` 拼出完整的写事务（硬件版的同名函数改用 `HAL_I2C_Mem_Write()`）：

```c
HAL_StatusTypeDef MPU6050_WriteReg(uint8_t reg, uint8_t value)
{
    MyI2C_Start();
    MyI2C_SendByte(MPU6050_ADDR_WRITE);
    if (MyI2C_ReceiveAck() != 0U)   /* ReceiveAck 返回 0 表示从机应答 */
    {
        goto nack;
    }

    MyI2C_SendByte(reg);
    if (MyI2C_ReceiveAck() != 0U)
    {
        goto nack;
    }

    MyI2C_SendByte(value);
    if (MyI2C_ReceiveAck() != 0U)
    {
        goto nack;
    }

    MyI2C_Stop();
    return HAL_OK;

nack:
    MyI2C_Stop();
    return HAL_ERROR;
}
```

`MPU6050_Init()` 本身也是驱动提供的，软件版的内部顺序是 `MyI2C_Init()` → 读 `WHO_AM_I` 校验 `0x68` → 依次写六个配置寄存器；硬件版则先保存句柄、再做设备应答检查。下面是软件版的真实实现，用来理解驱动做了什么，不需要抄进自己的代码：

```c
HAL_StatusTypeDef MPU6050_Init(I2C_HandleTypeDef *hi2c)
{
    uint8_t id;

    /* 软件版不使用 HAL 的 I2C 句柄，这个参数只为与硬件版共用同一份 main.c */
    (void)hi2c;

    /* GPIO 必须已经由 CubeMX 配成开漏输出并拉到高电平，这里只释放两条线 */
    MyI2C_Init();

    /* 身份层：能读到 0x68 说明供电、地址、时序都通了 */
    if (MPU6050_ReadDeviceID(&id) != HAL_OK)
    {
        return HAL_ERROR;
    }
    if (id != MPU6050_WHO_AM_I_VALUE)
    {
        return HAL_ERROR;
    }

    /* 配置层：上电默认睡眠，必须先解除，否则测量值不更新 */
    if (MPU6050_WriteReg(MPU6050_PWR_MGMT_1, MPU6050_PWR_MGMT_1_VALUE) != HAL_OK)
    {
        return HAL_ERROR;
    }
    if (MPU6050_WriteReg(MPU6050_PWR_MGMT_2, MPU6050_PWR_MGMT_2_VALUE) != HAL_OK)
    {
        return HAL_ERROR;
    }
    if (MPU6050_WriteReg(MPU6050_SMPLRT_DIV, MPU6050_SMPLRT_DIV_VALUE) != HAL_OK)
    {
        return HAL_ERROR;
    }
    if (MPU6050_WriteReg(MPU6050_CONFIG, MPU6050_CONFIG_VALUE) != HAL_OK)
    {
        return HAL_ERROR;
    }
    if (MPU6050_WriteReg(MPU6050_GYRO_CONFIG, MPU6050_GYRO_FS_2000DPS) != HAL_OK)
    {
        return HAL_ERROR;
    }

    return MPU6050_WriteReg(MPU6050_ACCEL_CONFIG, MPU6050_ACCEL_FS_16G);
}
```

每一次写寄存器后都检查 `MyI2C_ReceiveAck()` 的返回值。若任一步返回 NACK，发送 STOP 并返回 `HAL_ERROR`；`main()` 收到 `HAL_ERROR` 时说明初始化没有通过，不要继续往下读六轴数据。

### 7.3 主循环显示

同样是三处放代码：`MPU6050_Data` 变量属于**文件作用域声明**（`/* USER CODE BEGIN PV */` 区域）；`MPU6050_Init(NULL)` 写在 `main()` 的 `/* USER CODE BEGIN 2 */` 区域，位置在 `OLED_Init()` 之后；六轴显示循环写在 `while (1)` 里面。完整的 `main()` 如下：

```c
/* USER CODE BEGIN PV */
static MPU6050_Data mpu_data;   /* 文件作用域：必须在所有函数之外 */
/* USER CODE END PV */

int main(void)
{
    HAL_Init();
    SystemClock_Config();
    MX_GPIO_Init();

    /* USER CODE BEGIN 2 */
    OLED_Init();

    if (MPU6050_Init(NULL) != HAL_OK)   /* 软件版传 NULL；硬件版这里改传 &hi2c2 */
    {
        OLED_ShowString(1, 7, "I2C ERR");
        Error_Handler();
    }

    /* 初始化里已经校验过 WHO_AM_I == 0x68，这里把身份层结果显示在第一行左侧，
       右边 7 列留给错误提示，和第 7.4 节的验收现象对应 */
    OLED_ShowString(1, 1, "ID:");
    OLED_ShowHexNum(1, 4, MPU6050_WHO_AM_I_VALUE, 2U);
    /* USER CODE END 2 */

    /* USER CODE BEGIN WHILE */
    while (1)
    {
        if (MPU6050_GetData(&mpu_data) == HAL_OK)
        {
            OLED_ShowSignedNum(2, 1, mpu_data.AccX, 5U);
            OLED_ShowSignedNum(3, 1, mpu_data.AccY, 5U);
            OLED_ShowSignedNum(4, 1, mpu_data.AccZ, 5U);

            OLED_ShowSignedNum(2, 8, mpu_data.GyroX, 5U);
            OLED_ShowSignedNum(3, 8, mpu_data.GyroY, 5U);
            OLED_ShowSignedNum(4, 8, mpu_data.GyroZ, 5U);
        }
        else
        {
            OLED_ShowString(1, 7, "READ ERR");
        }

        HAL_Delay(50U);

        /* USER CODE END WHILE */

        /* USER CODE BEGIN 3 */
    }
    /* USER CODE END 3 */
}
```

### 7.4 预期现象与验收

- 第一行显示 `ID:68`；
- 第二到四行左侧为 AccX/Y/Z，右侧为 GyroX/Y/Z；
- 静止水平放置时，某一加速度轴绝对值接近 `2048 LSB`，约为 1 g；
- 静止时陀螺仪接近 0，但允许存在零偏；
- 转动模块时，对应陀螺仪轴变化明显；
- 翻转模块时，对应加速度轴正负号改变。

“数字会变化”不能单独证明设备身份正确，必须先通过 `WHO_AM_I=0x68`。

## 8. 实验三：从逐寄存器读取迁移到 14 字节连续读取

### 8.1 先用逐寄存器方式理解拼接

教学上可以先分别读取高、低字节，用的是驱动已经提供的公开函数 `MPU6050_ReadRegs(uint8_t reg, uint8_t *data, uint16_t length)`：

```c
uint8_t pair[2];

if (MPU6050_ReadRegs(MPU6050_ACCEL_XOUT_H, pair, sizeof(pair)) == HAL_OK)
{
    /* 高字节先左移 8 位再拼低字节；这里只为看清关系，
       驱动里同等功能由 MPU6050_GetData() 直接填进 MPU6050_Data */
    AccX = (int16_t)(((uint16_t)pair[0] << 8) | (uint16_t)pair[1]);
}
```

注意第 5.3 节的 `MPU6050_BE16()` 在驱动里是 `MPU6050.c` 文件内的 `static` 辅助函数，`main.c` 不能调用它，所以在自己的代码里照上面这样展开写。

这里一次读取 X 轴的高、低字节；如果要严格观察两个独立寄存器事务，也可以分别以 `0x3B` 和 `0x3C` 为起始地址读取。

这样最容易看清“寄存器地址 -> 高字节 -> 低字节 -> 16 位数”的关系，但一轮六轴读取会产生很多次完整事务。

### 8.2 改为连续读取

将起始地址设为 `ACCEL_XOUT_H(0x3B)`，一次读取 14 字节，再按第 5.3 节的偏移解析。驱动已经把它做成公开函数 `MPU6050_GetData(MPU6050_Data *data)`，**读者不需要自己写这个函数**：它内部调用的就是前一节的公开函数 `MPU6050_ReadRegs()`。

软件版 `MPU6050.c` 里的真实实现：

```c
HAL_StatusTypeDef MPU6050_GetData(MPU6050_Data *data)
{
    uint8_t buffer[14];
    HAL_StatusTypeDef status;

    if (data == NULL)
    {
        return HAL_ERROR;
    }

    /* 从 0x3B 起一次读 14 字节，比逐轴读的事务数少得多 */
    status = MPU6050_ReadRegs(MPU6050_ACCEL_XOUT_H, buffer, sizeof(buffer));
    if (status != HAL_OK)
    {
        return status;
    }

    /* 偏移：0/2/4 加速度，6/7 温度（本章跳过），8/10/12 角速度 */
    data->AccX  = MPU6050_BE16(&buffer[0]);
    data->AccY  = MPU6050_BE16(&buffer[2]);
    data->AccZ  = MPU6050_BE16(&buffer[4]);
    data->GyroX = MPU6050_BE16(&buffer[8]);
    data->GyroY = MPU6050_BE16(&buffer[10]);
    data->GyroZ = MPU6050_BE16(&buffer[12]);

    return HAL_OK;
}
```

硬件版 `mpu6050.c` 里的同名函数，**只有底层读那两行不同，偏移解析六行完全一样**：

```c
    uint8_t buffer[MPU6050_DATA_LENGTH];
    ...
    status = MPU6050_ReadRegs(MPU6050_ACCEL_XOUT_H, buffer, MPU6050_DATA_LENGTH);
```

两套头文件的宏集合**完全相同**（各 25 个）：`MPU6050_DATA_LENGTH(14U)`、`MPU6050_TIMEOUT_MS(100U)` 在两套里都有定义，`main.c` 里可以直接用，不必替换成数字。区别只在实现：软件版的 `MPU6050_ReadRegs()` 用 `MyI2C_*` 拼事务，硬件版的内部是 `HAL_I2C_Mem_Read()`；`MPU6050_TIMEOUT_MS` 在软件版里不参与工作（软件 I2C 没有超时机制），保留定义就是为了让两套头文件的宏一致，跨版本抄代码不会因宏未定义而编译不过。两版的函数名、参数和返回值完全一致。

连续读取的验收不是“数值必须完全相同”，而是：

- 六个轴仍能按相同位置显示；
- 姿态变化趋势不变；
- 逻辑分析仪看到中间字节后 ACK，最后一个字节后 NACK 和 STOP；
- 一轮数据读取的事务数量减少。

## 9. 实验四：用 HAL 硬件 I2C 替换底层

### 9.1 硬件版 CubeMX 配置

生成代码后应存在：

**加入文件（硬件版）**：只需要两个文件，来自驱动库目录

```text
├─ mpu6050.c
└─ mpu6050.h
```

硬件版**不需要** `MyI2C.c`、`MyI2C.h`：时序由 I2C2 外设产生，没有 GPIO 模拟的部分。把这两个文件加入工程（文件名是小写的 `mpu6050.c/.h`，软件版是大写的 `MPU6050.c/.h`），并在 `main.c` 里包含它：


OLED 仍然使用 `E:\ProjectStm\驱动库\OLED（软件IIC）` 里的 `OLED.c`、`OLED.h`、`OLED_Font.h`（PB8/PB9 软件 I2C 那一套），与 MPU6050 走 I2C2 并不冲突。

### 9.2 HAL 寄存器读写

`MPU6050_ADDR_HAL`、`MPU6050_TIMEOUT_MS` 这些宏已经定义在驱动头文件里（两套头文件里都有，见 `mpu6050.h` / `MPU6050.h`），**`main.c` 不要再定义一遍**，否则会出现宏重定义告警。下面是 `mpu6050.c` 里的真实实现：

```c
/* CubeMX 生成的 I2C 句柄，由 MPU6050_Init() 保存，例如 I2C2 对应 &hi2c2 */
static I2C_HandleTypeDef *g_mpu_i2c = NULL;

HAL_StatusTypeDef MPU6050_WriteReg(uint8_t reg, uint8_t value)
{
    if (g_mpu_i2c == NULL)
    {
        return HAL_ERROR;
    }

    /* pData 必须是有效缓冲区地址，不能把寄存器值本身当指针传进去，
     * 所以先把值放进局部变量 value，再传 &value。 */
    return HAL_I2C_Mem_Write(g_mpu_i2c,
                             MPU6050_ADDR_HAL,
                             reg,
                             I2C_MEMADD_SIZE_8BIT,   /* MPU6050 内部寄存器地址是 8 位 */
                             &value,
                             1U,
                             MPU6050_TIMEOUT_MS);
}

HAL_StatusTypeDef MPU6050_ReadRegs(uint8_t reg, uint8_t *data, uint16_t length)
{
    if ((g_mpu_i2c == NULL) || (data == NULL) || (length == 0U))
    {
        return HAL_ERROR;
    }

    return HAL_I2C_Mem_Read(g_mpu_i2c,
                            MPU6050_ADDR_HAL,
                            reg,
                            I2C_MEMADD_SIZE_8BIT,
                            data,
                            length,
                            MPU6050_TIMEOUT_MS);
}
```

`HAL_I2C_Mem_Write()` 的 `pData` 必须是有效缓冲区地址，不能把 `0x00`、`0x07` 等寄存器值直接当作指针传入。这里使用局部变量 `value`，再传 `&value`。

`I2C_MEMADD_SIZE_8BIT` 表示 MPU6050 内部寄存器地址宽度为 8 位。

### 9.3 硬件版初始化和主程序

硬件版初始化先保存句柄，再用有限超时检查设备和寄存器。这也是**驱动 `mpu6050.c` 里已经写好的实现**，读者不需要自己写：

```c
HAL_StatusTypeDef MPU6050_Init(I2C_HandleTypeDef *hi2c)
{
    uint8_t id;

    if (hi2c == NULL)
    {
        return HAL_ERROR;
    }
    g_mpu_i2c = hi2c;

    /* 先只做“设备是否应答”，把接线/地址问题和寄存器内容问题分开 */
    if (HAL_I2C_IsDeviceReady(g_mpu_i2c, MPU6050_ADDR_HAL, 3U,
                              MPU6050_TIMEOUT_MS) != HAL_OK)
    {
        return HAL_ERROR;
    }

    /* 身份层：WHO_AM_I 必须是 0x68，否则后面读到的数据没有意义 */
    if (MPU6050_ReadDeviceID(&id) != HAL_OK)
    {
        return HAL_ERROR;
    }
    if (id != MPU6050_WHO_AM_I_VALUE)
    {
        return HAL_ERROR;
    }

    /* 配置层：上电默认睡眠，必须先解除，否则测量值不更新 */
    if (MPU6050_WriteReg(MPU6050_PWR_MGMT_1, MPU6050_PWR_MGMT_1_VALUE) != HAL_OK)
    {
        return HAL_ERROR;
    }
    if (MPU6050_WriteReg(MPU6050_PWR_MGMT_2, MPU6050_PWR_MGMT_2_VALUE) != HAL_OK)
    {
        return HAL_ERROR;
    }
    if (MPU6050_WriteReg(MPU6050_SMPLRT_DIV, MPU6050_SMPLRT_DIV_VALUE) != HAL_OK)
    {
        return HAL_ERROR;
    }
    if (MPU6050_WriteReg(MPU6050_CONFIG, MPU6050_CONFIG_VALUE) != HAL_OK)
    {
        return HAL_ERROR;
    }
    if (MPU6050_WriteReg(MPU6050_GYRO_CONFIG, MPU6050_GYRO_FS_2000DPS) != HAL_OK)
    {
        return HAL_ERROR;
    }

    return MPU6050_WriteReg(MPU6050_ACCEL_CONFIG, MPU6050_ACCEL_FS_16G);
}
```

硬件版 `main.c` 和第 7.3 节的结构完全一样（`static MPU6050_Data mpu_data;` 放在 `/* USER CODE BEGIN PV */`，初始化在 `/* USER CODE BEGIN 2 */`，显示循环在 `while (1)` 里），只需要改两处：

1. 在 `MX_GPIO_Init();` 之后多初始化一个 I2C2 外设：加一行 `MX_I2C2_Init();`（属于 CubeMX 生成的固定内容，不在 USER CODE 区域内）；
2. `/* USER CODE BEGIN 2 */` 区域内，把软件版的 `MPU6050_Init(NULL)` 改成 `MPU6050_Init(&hi2c2)`。

```c
    HAL_Init();
    SystemClock_Config();
    MX_GPIO_Init();
    MX_I2C2_Init();     /* 硬件版新增，且必须在 MPU6050_Init(&hi2c2) 之前 */

    /* USER CODE BEGIN 2 */
    OLED_Init();
    OLED_ShowString(1, 1, "ID:");

    if (MPU6050_Init(&hi2c2) != HAL_OK)     /* 硬件版：传句柄；软件版这里是 NULL */
    {
        OLED_ShowString(1, 7, "I2C ERR");
        Error_Handler();
    }
    /* USER CODE END 2 */
```

`hi2c2` 是 CubeMX 在 `main.c` 私有变量区生成的 `I2C_HandleTypeDef`（位置在 `/* USER CODE BEGIN PV */` 之前），由 `MX_I2C2_Init()` 初始化，读者不需要自己声明。

硬件版还要在 `main.c` 的 `/* USER CODE BEGIN Includes */` 区域改成包含 `"mpu6050.h"`（见 9.1），第 7.3 节里的 `OLED_ShowSignedNum(...)` 六行显示代码一行都不用改。

### 9.4 软硬件对照验收

| 对比项 | 软件 I2C | HAL 硬件 I2C |
| --- | --- | --- |
| MPU6050 引脚 | PB10/PB11 GPIO | PB10/PB11 I2C2 |
| 时序产生 | CPU 调用 GPIO | I2C2 外设 |
| 寄存器接口 | `MyI2C_*` 组合事务 | `HAL_I2C_Mem_*` |
| OLED | PB8/PB9 软件 I2C | PB8/PB9 软件 I2C |
| 上层输出 | `ID:68` + 六轴原始值 | `ID:68` + 六轴原始值 |
| CPU 占用 | 较高 | 较低 |
| 波形 | 受代码延时影响 | 通常更规整 |

保持接线、姿态、显示代码和读取周期一致后，两边的符号、量级和变化趋势应一致；瞬时值会受噪声、零偏和采样时刻影响，不要求逐位相同。

## 10. 分层验收

### 10.1 电气层

- 两个模块供电正常并共地；
- PB8/PB9、PB10/PB11 空闲时都为高；
- 主机拉低时能接近 0 V；
- 上升沿能在下一个采样时刻前恢复到有效高电平。

### 10.2 地址层

- 软件版发送 `0xD0` 后收到 ACK；
- 硬件版 `HAL_I2C_IsDeviceReady(&hi2c2, 0x68 << 1, ...)` 返回 `HAL_OK`；
- 失败时根据 AD0 检查 `0x68/0x69`，不要同时随意修改 `WHO_AM_I` 的期望值。

### 10.3 身份层

- `WHO_AM_I(0x75)` 返回 `0x68`；
- OLED 第一行稳定显示 `ID:68`；
- 地址应答正常但 ID 错误时，检查寄存器地址、重复起始和读方向。

### 10.4 数据层

- 第二到四行同时显示六个有符号值；
- 静止时陀螺仪接近 0，但允许存在零偏；
- 水平静止时某一加速度轴绝对值接近 `2048 LSB`；
- 沿单轴旋转时对应陀螺仪轴变化最明显；
- 翻转模块时对应加速度轴正负改变。

### 10.5 波形层

读取 `WHO_AM_I` 时，应看到：

```text
START -> 0x68/W -> ACK -> 0x75 -> ACK
      -> RESTART -> 0x68/R -> ACK -> 0x68 -> NACK -> STOP
```

连续读取 14 字节时，中间 13 个字节后主机发送 ACK，最后一个字节后发送 NACK 和 STOP。

> 待确认项：实际总线频率、上升时间、上拉电阻和模块是否为真正的 MPU6050，需要以逻辑分析仪/示波器、模块资料和实测结果为准。本文的代码链路检查不能替代硬件测试。

## 11. 按现象故障定位

### 11.1 OLED 不亮

先回到前篇，单独运行 `OLED_Init()` 和 `OLED_ShowString()`。OLED 自身尚未通过验收时，不要用它判断 MPU6050 是否正常。

### 11.2 MPU6050 没有 ACK

按顺序检查：

1. VCC、GND 和共地；
2. PB10=SCL、PB11=SDA；
3. 空闲高电平和上拉；
4. AD0 对应地址 `0x68/0x69`；
5. 软件版是否发送 `0xD0`，而不是 `0x68`；
6. HAL 是否传入 `0x68 << 1`，且没有重复左移；
7. 软件版第 9 个时钟前是否释放 SDA；
8. 软件版 `MPU6050_ReadRegs()` 在**地址、寄存器地址、读地址三个阶段**都会检查 ACK，任一步收到 NACK 就发送 STOP 并返回 `HAL_ERROR`，所以先用逻辑分析仪看清是第几个字节开始没有 ACK；
9. 软件版的 `MyI2C_Init()` 只是把 SCL/SDA 释放为高，**引脚必须由 CubeMX 配成 `Output Open Drain` 且初始电平 `High`**；若被配成推挽输出或初始电平为低，从机看到的空闲电平就是错的。

### 11.3 `WHO_AM_I` 为 `0xFF`

通常表示 SDA 始终为高或从机没有驱动。先查地址、SDA 接线、重复起始、读方向和上拉。

### 11.4 `WHO_AM_I` 为 `0x00`

通常表示 SDA 始终为低。检查短路、主机是否释放 SDA、从机是否卡住，以及读取代码是否一直把低电平拼入结果。

### 11.5 ID 正确，但六轴不变化

- **先检查**：是否写入 `PWR_MGMT_1=0x01`；
- **再检查**：读取起始地址是否为 `0x3B`，长度是否为 14；
- **继续检查**：高低字节拼接、主循环调用和 OLED 固定宽度覆盖；
- **结论**：身份层通过后，优先查配置、数据地址和解析，不要再反复改设备地址。

### 11.6 数值相差约 8 倍

两套工程都应向 `GYRO_CONFIG` 和 `ACCEL_CONFIG` 写入 `0x18`。若对应数据仍相差约 8 倍，可能是一套工程没有成功写入配置、下载的是旧程序，或仍处于默认量程。回读两个寄存器，确认它们均为 `0x18`。

### 11.7 数值相差 256 倍或负数变成大正数

检查高字节是否左移 8 位，以及最终变量是否为 `int16_t`：

```c
value = (int16_t)(((uint16_t)high << 8) | low);
```

### 11.8 硬件 I2C 失败，软件 I2C 成功

检查 I2C2 是否启用、PB10/PB11 是否为复用开漏、APB1 时钟和速度是否正确、HAL 返回值是 `HAL_BUSY`、`HAL_TIMEOUT` 还是 `HAL_ERROR`，以及 GPIO 初始化是否覆盖了 I2C2 引脚配置。

### 11.9 软件 I2C 失败，硬件 I2C 成功

检查 START/STOP 边沿、最高位先发、ACK 第 9 个时钟、读前释放 SDA、最后一个字节 NACK，以及空循环延时是否因优化或系统时钟变化而过短。

软件版的两条专有原因：

- **SCL 速度由 `MYI2C_DELAY_LOOPS`（默认 `40`）决定**：改主频（例如 72 MHz 换成 8 MHz）或开启更高编译优化后，空循环变短、SCL 变快，可能超出从机上限；加大该宏后用示波器/逻辑分析仪重新实测 SCL 频率；
- **ACK 检查点**：驱动的 `MPU6050_ReadRegs()` 在地址、寄存器地址、读地址三个阶段都检查 `MyI2C_ReceiveAck()`，最后字节回 NACK；`MPU6050_Init()` 返回 `HAL_ERROR` 时，先用波形确认失败发生在哪一次事务，再决定是查地址、查重复起始还是查从机供电。

### 11.10 程序卡在通信函数

- HAL 调用必须使用有限超时，不要全部传 `HAL_MAX_DELAY`；
- 软件 I2C 课程版没有完整的时钟拉伸超时，SCL 被持续拉低时可能无法自行退出；
- 总线异常后可以释放 SDA、产生最多 9 个 SCL 脉冲，再发送 STOP；
- 总线恢复不能修复短路、错误供电或损坏的模块。

软件 I2C 的空循环延时只适合入门复现实验，正式项目应增加可测的定时、拉伸等待、超时和并发保护。

## 12. 自测题与参考答案

### 12.1 自测题

1. 为什么软件 I2C 发送 `0xD0/0xD1`，而 HAL 接口写成 `0x68 << 1`？
2. 指定地址读为什么需要重复起始？
3. 读取最后一个字节后为什么发送 NACK？
4. MPU6050 上电后为什么必须先配置 `PWR_MGMT_1`？
5. 高字节为什么要左移 8 位？
6. 软件版和硬件版参数统一后，为什么瞬时原始值仍不会完全相等？
7. 为什么应先验收 `WHO_AM_I`，再调试六轴和 OLED 布局？
8. 14 字节连续读取相对逐寄存器读取解决了什么问题？
9. 为什么读前必须释放 SDA？
10. 软件版和硬件版分别应该在什么位置改变代码？

### 12.2 参考答案

1. 两者最终都把 7 位地址放到地址字节的高 7 位；软件代码直接构造线上字节，HAL 要求传入左移后的地址参数。
2. 前半段用写方向设置内部寄存器地址，后半段保持总线控制权并切换到读方向。
3. NACK 告诉从机当前字节是最后一个，随后主机发送 STOP 结束事务。
4. MPU6050 默认睡眠，不解除睡眠就不能正常更新测量数据。
5. 大端数据的高字节对应 bit15 到 bit8，必须左移 8 位后再与低字节拼接。
6. 两次读取的采样时刻不同，还存在噪声、零偏和姿态误差；统一参数保证的是灵敏度和量级一致。
7. `WHO_AM_I` 是最短的“供电 -> 地址 -> 寄存器读”闭环；它失败时继续看六轴和显示只会扩大排查范围。
8. 它减少事务开销和一轮读取的时间跨度，并降低跨数据更新边界读取的风险。
9. SDA 由从机发送时，主机必须停止拉低线路，否则从机发送的高电平会被主机覆盖。
10. 软件版改变 `MyI2C_*` 组合事务和 GPIO 配置；硬件版改变 I2C2 配置与 `HAL_I2C_Mem_*` 底层，上层数据结构、显示和验收保持不变。驱动本身两套都已写好，工程里实际要动的只有三处：CubeMX 配置、加入的文件、以及 `MPU6050_Init()` 传 `NULL` 还是 `&hi2c2`。

当软件版和硬件版都能显示 `ID:68`，第二到四行按左加速度、右陀螺仪排列，改变姿态时六项数据按预期变化，并且逻辑分析仪能看到指定地址读的完整序列，本章实验闭环就完成了。固定周期采样、零偏标定和姿态融合属于后续可选扩展，不是本章通过条件。
