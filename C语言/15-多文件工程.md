# 第 15 章：多文件工程与模块边界

## 本章目标

- 理解"声明放头文件、定义放源文件"的工程组织；
- 掌握 `#include` 与头文件守卫，用 `extern`/`static` 明确跨文件可见性；
- 会用两步编译（`-c` 生成 .o 再链接）和 makefile 做增量构建。

## 边界

本章是纯工程实践，不含新语法；用到的 `#ifndef`（第 13 章）、`extern`/`static`（第 03 章）都已讲过。重点是从"单文件教程代码"到"多文件真实项目"的思维转变。

## 为什么要拆文件

一个项目通常包含多个源码文件：一个含 `main()` 的主文件 + 若干"库文件"。原因：

- 职责分离：一个文件只干一类事（记录定义、存储、主流程）；
- 编译增量：只重编改动的文件（见本文"两步编译"）；
- 复用：一个 `.c` + `.h` 打包成模块，别的项目拿过去就能用。

## 基本组织：头文件 .h 放声明，源文件 .c 放定义

```c
// bar.h —— 声明（接口）
int add(int, int);

// bar.c —— 定义（实现）
#include "bar.h"
int add(int a, int b) {
  return a + b;
}

// foo.c —— 主文件
#include <stdio.h>
#include "bar.h"
int main(void) {
  printf("%d\n", add(2, 3));   // 5
  return 0;
}
```

要点：

- **bar.c 自己也 include bar.h**：让编译器核对原型与定义是否一致（改坏接口立刻报错）；
- 尖括号 vs 双引号：`<stdio.h>` 系统标准库；`"bar.h"` 用户文件，从源文件所在目录找起；
- `gcc -Iinclude/` 追加用户头文件的搜索路径；
- 依赖声明而非重复：`foo.c` 里不再手写 `int add(int, int);`，改接口只动 `bar.h`；
- 头文件里还可以放 struct 定义、typedef、宏、extern 声明（第 12/13 章内容），这些是"接口契约"。

## 头文件守卫（第 13 章的工程应用）

`a.h` 包含 `c.h`、`b.h` 也包含 `c.h`，主文件同时 include 两者时 `c.h` 会被编译两次，struct 重复定义就会报错。每个头文件必须写成:

```c
// bar.h
#ifndef BAR_H
#define BAR_H

int add(int, int);

#endif
```

守卫宏名 = 文件名大写 + `_H`（`MYHEADER_H`）。这是硬性习惯，不写守卫的头文件在真实项目里是事故隐患。

## 跨文件变量：extern 与 static

- 全局变量的定义在某个 `.c` 里，别的文件要用它，先 `extern` 声明（**不分配内存**，告诉编译器它在别处）：

```c
extern int myVar;        // 我在别的文件里定义过了
extern int a[];          // extern 数组可不写长度
```

`extern` 声明可以写在源文件里，也可以放进头文件由多个文件共享。

- 反过来，想**禁止**其他文件使用本文件的全局变量，用 `static`（文件私有）：

```c
static int foo = 3;      // 只在本文件可见，别的文件引用会报错
```

工程纪律：**尽量少用跨文件全局变量**；模块之间通过函数接口通信，变量用 `static` 锁在文件内（第 03 章讲过 static 的两副面孔：文件私有 + 函数内持久）。

## 两步编译与链接

一次性编译 `gcc -o foo foo.c bar.c` 每次都全量重编。真实项目这么做：先各自编译成**对象文件**，再链接：

```bash
$ gcc -c foo.c     # 生成 foo.o（只检查语法，不链接）
$ gcc -c bar.c     # 生成 bar.o
$ gcc -o foo foo.o bar.o   # 链接成可执行文件
```

- `.o` 是编译中间产物，不是可执行文件；
- **只重编改动的文件**，没动的继续用旧 .o，最后重新链接一次——链接比编译快得多；
- `main` 符号必须恰好存在一次（一个可执行文件只能有一个 main）；
- 链接时找不到函数定义 → linker error（如忘了把 bar.c 放进来）。

## make：增量构建自动化

make 读取当前目录的 `makefile`（或 `Makefile`），里面是**构建规则**：目标、依赖、生成命令。

```makefile
foo: foo.o bar.o
	gcc -o foo foo.o bar.o

foo.o: bar.h foo.c
	gcc -c foo.c

bar.o: bar.h bar.c
	gcc -c bar.c
```

规则格式：第一行 `目标: 依赖项`，第二行（或几行）以 **Tab** 缩进的生成命令（不能用空格！）。

使用：

```bash
$ make            # 执行第一条规则的构建（惯例：最终可执行文件放第一条）
$ make foo.o      # 只构建指定目标
```

make 的核心机制是**时间戳**：比较目标和依赖的修改时间，依赖没变过就不重做。所以上例只改 `foo.c` 时 `make` 只重编 `foo.o`，`bar.o` 保持原样然后用 `foo.o bar.o` 重新链接。

Makefile 进阶项（变量、模式规则、自动变量 `$@`/`$^`）用到再查；初学者掌握上面的三段式就够支撑日常项目。

## 本章小结

头文件描述接口，源文件提供实现；`static` 控制文件内可见性，`extern` 声明外部定义。编译、链接和 Makefile 共同组成可维护的构建流程。
