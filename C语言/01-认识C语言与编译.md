# 第 01 章：认识 C 语言与编译过程

## 本章目标

- 了解 C 语言的来历、特点和主要版本；
- 理解源代码如何通过编译器变成可执行程序；
- 能独立编译并运行自己的第一个 C 源文件。

## 边界

本章只建立全局视角。语句怎么写、变量和数据类型是什么，从下一章开始分别学习。读完本章，你不必理解示例中每一行的含义，只要知道它"如何被编译、如何运行"即可。

## 历史：C 语言从哪里来

==C 语言最初是作为 Unix 系统的开发工具发明的。==

1969 年，美国贝尔实验室的肯·汤普森（Ken Thompson）与丹尼斯·里奇（Dennis Ritchie）一起开发了 Unix 操作系统。当时的 Unix 用汇编语言编写，无法移植到其他计算机，他们决定改用高级语言重写。但当时的高级语言满足不了需求，汤普森便在 BCPL 的基础上发明了 B 语言。

1972 年，丹尼斯·里奇和布莱恩·柯林汉（Brian Kernighan）在 B 语言的基础上重新设计了一种新语言，取代 B 语言，因此称为 C 语言。

1973 年，整个 Unix 系统都用 C 语言重写。此后这门语言快速流传，广泛用于操作系统和系统软件的开发。1988 年，美国国家标准协会（ANSI）正式将 C 语言标准化。

几十年过去，C 语言依然是最广泛使用的系统编程语言之一，Unix 和 Linux 至今仍然以 C 语言开发。

## C 语言的特点

C 语言能长盛不衰，源于几个鲜明特点。

**（1）接近底层。** C 语言能直接操作硬件、管理内存、与操作系统对话，非常适合需要与硬件交互、有极高性能要求的程序。

**（2）可移植性好。** 它的原始设计目标就是移植 Unix 到不同计算机架构，因此 C 程序可以相对简单地移植到各种硬件和操作系统。汽车、照相机、家用电器等嵌入式设备的底层系统大多用 C 编写，靠的也是这一条。

**（3）语法简单。** C 的语法规则不算多，几乎没有语法糖——如果两个语法能做几乎相同的事，C 往往只保留一种。它也不提供"类"（class）之类的高级数据结构，复杂的数据结构都要自己构造。

**（4）灵活性高。** C 对程序员的限制很少，它的哲学是"信任程序员，不要妨碍他们做事"。它让你自己管理内存，不提供自动清理，也不做类型检查、数组负索引检查、指针越界检查等保护。对高手是自由，对新手则容易犯错、不好调试。

这些特点综合起来，让 C 能写出充分发挥硬件潜力的高性能程序，编译器实现也相对容易。同时，C++、Java、C#、JavaScript 等流行语言都以 C 为基础，学好 C 有助于理解它们。

## C 语言的版本

**K&R C**：1978 年里奇和柯林汉合著《C 编程语言》，在无正式标准前这本书即是事实标准，以作者姓氏简称为 K&R C。

**ANSI C（C89 / C90）**：1989 年 ANSI 制定标准，1990 年 ISO 通过，又称 C89 或 C90。

**C95**：1995 年对 C89 的补充，加入多字节字符和宽字符支持。

**C99**：1999 年第一次大型修订，加入 `//` 注释等特性，是目前使用最广的版本之一。

**C11**：2011 年修订，加入线程库、原子操作、静态断言等特性；Unicode 文本处理仍主要依赖编码和本地化库。

**C17**：2018 年发布，只修补 C11 缺陷，无新功能。

**C23**：较新的语言修订，加入了一批语法和标准库改进。不同编译器对 C23 的支持程度不同，本教程主线统一按 C17 编译，C23 只作为扩展阅读。

## 编译：从文本到可执行程序

C 是编译型语言：==源码是纯文本文件，本身不能执行，必须由编译器翻译成二进制指令==，这个过程叫编译阶段（编译时），与运行阶段（运行时）相区分。

最常见的编译器是 GCC（自由软件基金会推出）。Linux 和 Mac 可直接安装，Windows 可以安装 MinGW 或使用 MSYS2。不想装编译器，也有在线编译工具，例如 CodingGround（tutorialspoint）和 OnlineGDB（onlinegdb.com）。

### Hello World：第一个 C 程序

C 源文件通常以 `.c` 结尾。下面是最简单的 C 程序 `hello.c`：

```c
#include <stdio.h>

int main(void) {
  printf("Hello World\n");
  return 0;
}
```

这个程序唯一的作用，就是在屏幕上显示 "Hello World"。现在不解释各行的含义（下一章会逐步说明），只演示编译运行的流程。

在命令行执行：

```bash
$ gcc hello.c
```

`$` 是命令提示符，你需要输入的是 `$` 后面的部分。编译后默认生成 `a.out`（Windows 平台为 `a.exe`），执行它：

> 说明：本书的命令行示例统一基于 bash（Linux/macOS 终端，Windows 下请用 MSYS2 或 Git Bash），第 16 章的命令行练习同理。

```bash
$ ./a.out
Hello World
```

`-o` 参数可以指定产物文件名：

```bash
$ gcc -o hello hello.c
$ ./hello
Hello World
```

`-std=` 参数指定按哪个标准编译，注意它用 `=` 连接，且 `=` 前后不能有空格：

```bash
$ gcc -std=c99 hello.c
```

### 本书的编译约定

之后的示例统一使用严格警告模式编译，把 `main.c` 换成实际源文件名：

```bash
gcc -std=c17 -Wall -Wextra -Wpedantic -O0 -g main.c -o app.exe
./app.exe
```

编译阶段没有任何输出才是正常状态。出现警告时，先理解并修正警告再运行程序——不要把"生成了可执行文件"当成"程序已经正确"。

## 本章小结

C 源文件需要经过编译和链接才能运行。先学会用统一命令编译一个最小程序，再逐章增加语法和库函数。

## 自查与练习

1. 用自己的编译器，把上面三个命令依次执行一遍，确认三种方式的产物都能运行。
2. 如果不写 `-o`，编译产物叫什么名字？在 Windows 上呢？
3. `gcc -std=c17 main.c` 和 `gcc -std=c99 main.c` 的区别是什么？
