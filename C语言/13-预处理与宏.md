# 第 13 章：预处理、宏与条件编译

## 本章目标

- 理解预处理发生在编译之前、以 `#` 开头；
- 掌握 `#define` 对象宏与带参宏，知道宏的坑（原样替换）与对应纪律；
- 掌握 `#include` 与头文件守卫；
- 用 `#if`/`#ifdef` 系列做条件编译，读懂预定义宏。

## 边界

宏能做的事很多，但**默认优先用函数和命名常量**；本章侧重"能读懂前人代码 + 会写简单宏"。带参宏若需要类型安全、可调试、可嵌套，一律用函数。

## 预处理器：编译前的文本加工

编译第一步是预处理：清理注释、把多行语句合成逻辑行，然后执行所有 `#` 开头的指令。指令规则：

- 以 `#` 开头、放在行首（前面可以有空格；`#` 与指令间一般不空格）；
- 每条指令一行（行尾反斜杠 `\` 可折行）；**结尾不需要分号**；
- 可以出现在文件任何位置，通常集中放在文件头部。

## #define：对象宏

```c
#define MAX 100
```

将源码中**独立成词的** `MAX` 原样替换成 `100`。规则：

- 宏名遵守标识符规则，不能含空格；
- **原样替换**：`"MAX"`（字符串里）和 `MAX_SIZE`（标识符一部分）都不替换；
- 可多重替换（宏里套宏）；同名重复定义且内容相同则合法，不同则报错；
- 想重定义时先 `#undef`：

```c
#define LIMIT 400
#undef LIMIT
#define LIMIT 500   // 重新定义
```

主要价值：命名常量（数组容量、配置值），改一处全部生效（第 04 章讲过的 `#define BUFSIZE 1024` 模式）。

## 带参数的宏：函数式宏与人字形的坑

```c
#define SQUARE(X) X*X
```

注意 `SQUARE` 与 `(` 之间**不能有空格**。用法看着像函数，其实是原样替换——这是最大的坑：

```c
printf("%d\n", SQUARE(3 + 4));   // 输出 19，不是 49！
// 替换为 3 + 4*3 + 4
```

**纪律：参数和整个宏体都加括号**：

```c
#define SQUARE(X) ((X) * (X))
#define MAX(x, y) ((x) > (y) ? (x) : (y))
#define IS_EVEN(n) ((n) % 2 == 0)
```

其他要点：

- 宏参数可以是空的：`#define getchar() getc(stdin)`；
- 宏体过长用 `\` 折行，必要时用 `{ }` 创造块作用域；
- 宏不涉及类型，**任何类型都可以用**；每处使用都是代码展开，省去了函数调用的开销；
- 但副作用是灾难：`MAX(x++, y)` 会把 `x++` 执行两次。

**用函数还是宏？** 默认用函数（类型安全、可调试、只执行一次）。宏只在明知需求（如性能热点、必须处理多类型）时用。至少你必须是"读得懂宏"的人——老代码里很常见。

### # 与 ## 运算符

在宏体里，参数前加 `#` 把参数转成字符串字面量：

```c
#define STR(x) #x
printf("%s\n", STR(3.14159));   // 输出 3.14159（字符串）

#define XNAME(n) "x"#n
printf("%s\n", XNAME(4));       // 输出 x4
```

`##` 把参数与标识符"粘合"成新标识符，用于批量生成名字：

```c
#define MK_ID(n) i##n
int MK_ID(1), MK_ID(2);         // 成为 int i1, i2;
```

不定参数用 `...`，展开时用 `__VA_ARGS__` 代指多余参数：

```c
#define X(a, b, ...) (10*(a) + 20*(b)), __VA_ARGS__
X(5, 4, 3.14, "Hi!", 12)
// 展开为 (10*(5) + 20*(4)), 3.14, "Hi!", 12
```

`...` 只能放在参数列表**尾部**。

## #include：加载其他文件

```c
#include <foo.h>   // 尖括号：系统/标准库头文件
#include "foo.h"   // 双引号：用户自己的头文件（先找当前目录）
```

- 双引号形式可以写路径：`#include "include/util.h"`；gcc 用 `-I目录` 追加搜索路径；
- 最常用于加载头文件（`.h`，多文件工程详见第 15 章）；
- 多次包含同一头文件合法，但**可能造成重复定义**——这就是头文件守卫存在的理由（见下）。

## 头文件守卫：防止重复加载

```c
// myheader.h
#ifndef MYHEADER_H
#define MYHEADER_H

// ... 真正的声明内容 ...

#endif
```

原理：第一次加载时宏未定义 → 定义它 + 加载内容；之后再加载直接跳过。宏名惯例：文件名大写 + `_H`。守卫缺失时，同一定义出现两次（如 struct 定义）会编译报错。

## 条件编译：#if 家族

**`#if 表达式`**：表达式非 0 才编译内部代码，可配 `#else`、`#elif`：

```c
#define FOO 1

#if FOO
  printf("defined\n");
#else
  printf("not defined\n");
#endif
```

- 未定义的宏在 `#if` 里等同于 0；
- `#if 0 ... #endif` 是经典"注释大段代码"手法（嵌套结构也能关）。

**`#ifdef` / `#ifndef`**：判断宏是否定义过（不看值）；`defined` 运算符可组合多重判断：

```c
#ifdef MAVIS        // 等价于 #if defined MAVIS
  #include "foo.h"
#else
  #include "bar.h"
#endif

#if defined IBMPC
  #include "ibmpc.h"
#elif defined MAC
  #include "mac.h"
#else
  #error 不支持该平台
#endif
```

**典型用途**：

```c
#define DEBUG 1

#if DEBUG
  printf("value of i: %d\n", i);    // 调试开关
#endif
```

`gcc -DDEBUG=1 foo.c` 可以在命令行定义宏，不编译时就不带 `-D`，反复切换调试/发布模式。

## 其他指令

- `#error 消息`：让预处理器报错并终止编译（常用于版本/平台检查）：
  `#if __STDC_VERSION__ != 201112L \n #error Not C11 \n #endif`
- `#pragma`：修改编译器属性（如 `#pragma warning(disable: XXX)`，移植性差，慎用）；
- `#line 300 "newname"`：重设 `__LINE__`/`__FILE__`（编译生成代码工具用，日常不碰）。

## 预定义宏

| 宏 | 含义 |
|---|---|
| `__DATE__` / `__TIME__` | 编译日期 / 时间（字符串） |
| `__FILE__` / `__LINE__` | 当前文件名 / 行号 |
| `__func__` | 当前函数名（只能在函数内用） |
| `__STDC__` | 1 表示遵循 C 标准 |
| `__STDC_VERSION__` | 版本号：C99 `199901L`、C11 `201112L`、C17 `201710L` |

打印示例：`printf("%s %d\n", __FILE__, __LINE__);`——这是编写调试信息和断言的基础设施。
