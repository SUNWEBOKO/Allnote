# 第 6 章 定时器 TIM 与电机驱动

## 本章闭环

定时器（Timer，TIM）的本质是一个由时钟或外部边沿驱动的计数器。`PSC`、`CNT`、`ARR` 组成时基；捕获比较通道和主从触发电路则围绕同一个计数器扩展出定时中断、外部脉冲计数、PWM、输入捕获、PWMI 和编码器接口。

```text
内部时钟 / 外部边沿
          |
          v
     PSC -> CNT <-> ARR
             |
             +-> 更新事件：周期任务、溢出扩展
             +-> CNT 与 CCR 比较：输出 PWM
             +-> 输入边沿锁存 CNT 到 CCR：测周期、脉宽、占空比
             +-> A/B 正交边沿控制 CNT 加减：位置、方向、速度
```

## 1. 定时器与时基

### 1.1 为什么需要定时器

只要有频率稳定的脉冲，统计脉冲个数就能测量时间。若计数频率为 $f_{CNT}$，计数了 $N$ 个脉冲，则经过的时间为：

$$
t=\frac{N}{f_{CNT}}
$$

软件延时依赖 CPU 执行指令，期间难以处理其他任务，也会受编译优化、中断和主频变化影响。硬件定时器由独立计数电路工作，CPU 只需配置参数，并在事件发生后读取状态或响应中断，因此更准确，也不会一直占用处理器。

“定时器”这个名称容易让人只想到延时。实际上，只要把输入时钟换成传感器脉冲，它就变成事件计数器；把 `CNT` 与 `CCR` 比较，它就能输出 PWM；在外部边沿到来时把 `CNT` 保存到 `CCR`，它又变成时间测量单元。

### 1.2 STM32F103 的定时器资源

STM32F1 定时器按硬件能力分为三类：

| 类型 | 典型编号 | 主要能力 |
| --- | --- | --- |
| 基本定时器 | TIM6、TIM7 | 时基、更新中断、触发 DAC |
| 通用定时器 | TIM2~TIM5 | 时基、内外时钟、捕获比较、主从触发、编码器 |
| 高级定时器 | TIM1、TIM8 | 通用功能，另有互补输出、死区、刹车输入和重复计数器 |

课程所用 STM32F103C8T6 只有 TIM1~TIM4：TIM1 是高级定时器，TIM2~TIM4 是通用定时器，没有 TIM6/TIM7。高级、通用定时器都包含基本时基，因此可把 TIM4 当作“基本定时器”使用。

高级定时器的互补输出、死区和刹车适合直接控制半桥、三相桥等功率级。本章使用 TB6612 驱动直流电机，功率换向由驱动芯片完成，不配置 TIM1 的互补输出。STM32F103 的 TIM1 重复计数器 `RCR` 为 8 位，范围是 `0~255`，不要误当成普通 16 位计数器。

### 1.3 时基单元：PSC、CNT、ARR

时基单元由三个核心寄存器构成：

- `PSC`（Prescaler）：预分频器。寄存器从 0 数到 `PSC`，实际分频系数为 `PSC+1`。
- `CNT`（Counter）：主计数器。每收到一个计数时钟就加一或减一。
- `ARR`（Auto-Reload Register）：自动重装寄存器，决定计数边界。

最常用的边沿对齐、向上计数过程如下：

```text
CNT: 0 -> 1 -> 2 -> ... -> ARR -> 0 -> ...
                              |
                              +-> 产生更新事件 UEV
```

计数器从 0 到 `ARR` 一共经历 `ARR+1` 个计数，因此：

$$
f_{CNT}=\frac{f_{TIM}}{PSC+1}
$$

$$
f_{update}=\frac{f_{TIM}}{(PSC+1)(ARR+1)}
$$

$$
T_{update}=\frac{(PSC+1)(ARR+1)}{f_{TIM}}
$$

式中：

- $f_{TIM}$：送入定时器的时钟频率，单位 Hz；
- $f_{CNT}$：主计数器递增或递减的频率；
- $f_{update}$：更新事件频率；
- $T_{update}$：一次完整计数周期。

两个“`+1`”都来自硬件从 0 开始计数。CubeMX 中若希望 7200 分频，应填写 `Prescaler = 7199`；若希望一个周期包含 10000 个计数，应填写 `Counter Period = 9999`。

### 1.4 计数模式与更新事件

通用和高级定时器支持三类计数方式：

| 模式 | `CNT` 变化 | 一个周期的特点 |
| --- | --- | --- |
| 向上计数 | `0 -> ARR -> 0` | 最常用，公式最直观 |
| 向下计数 | `ARR -> 0 -> ARR` | 比较逻辑与向上计数不同 |
| 中央对齐 | `0 -> ARR -> 0` 往返 | PWM 边沿关于周期中心对称，频率公式需考虑往返 |

本章参数计算默认使用向上计数。更新事件（Update Event，UEV）不只表示自然溢出，还可能由软件设置 `EGR.UG`、从模式 Reset 等事件产生。UEV 可以完成：

- 让 `CNT` 回到起始值；
- 把预装载值传给影子寄存器；
- 置位更新标志 `UIF`；
- 在允许时产生更新中断；
- 通过 `TRGO` 触发其他外设。

因此，“出现更新中断”不一定意味着 `CNT` 自然数到了 `ARR`。涉及从模式或软件更新时，还要结合触发标志和配置判断来源。

### 1.5 定时器时钟与 APB 倍频

课程工程通常使用 8 MHz 外部晶振，经 PLL 9 倍频得到 72 MHz：

```text
SYSCLK = 72 MHz
HCLK   = 72 MHz
PCLK2  = 72 MHz -> TIM1CLK = 72 MHz
PCLK1  = 36 MHz -> APB1 分频不为 1，TIM2~TIM4CLK = 2 x PCLK1 = 72 MHz
```

通用规则是：

$$
f_{TIM}=
\begin{cases}
f_{PCLK}, & APB\text{ 预分频}=1 \\
2f_{PCLK}, & APB\text{ 预分频}\ne1
\end{cases}
$$

所以 TIM2~TIM4 挂在 36 MHz 的 APB1 上，不代表定时器只得到 36 MHz。CubeMX 时钟树中的 `APB1 Timer clocks` 才是应代入公式的值。

若工程未启用外部晶振和 PLL，系统可能仍以 8 MHz 运行。按 72 MHz 计算的周期会慢约 9 倍。发现所有定时、串口或 PWM 参数同时异常时，应先检查时钟树，而不是分别改每个外设参数。

### 1.6 位宽与最长周期

STM32F103C8T6 本章使用的 `PSC`、`CNT`、`ARR` 都按 16 位资源考虑。最大分频和向上计数周期均为 65536 个时钟。若 $f_{TIM}=72\ \mathrm{MHz}$：

$$
T_{max}=\frac{65536\times65536}{72\times10^6}\approx59.65\ \mathrm{s}
$$

需要更长周期时，通常让定时器生成较短而稳定的基准周期，再由软件累计。例如定时器每 100 ms 中断一次，软件计满 600 次得到 1 min。也可让一个定时器的 `TRGO` 作为另一个定时器的触发输入实现级联，但入门工程优先采用软件累计，配置更直观。

晶振本身有频率误差，温度也会造成漂移。定时器只能准确统计它收到的时钟，不能消除时钟源误差；长期日历时间应使用 RTC、校准或外部授时。

### 1.7 预装载、影子寄存器与生效时刻

`PSC` 真正参与分频的是影子寄存器。软件写入新 `PSC` 后，通常要等下一次 UEV 才装入影子寄存器。这样可避免一个周期前后两段采用不同的分频值。

`ARR` 是否延迟生效由 `ARPE` 控制，对应 CubeMX 的 `Auto-reload preload`：

- `Disable`：软件写入 `ARR` 后直接改变计数边界；
- `Enable`：新值先进入预装载寄存器，在下一次 UEV 时统一生效。

`CCR` 也可启用预装载。PWM 运行时建议让新的占空比在周期边界生效，防止当前周期突然被截短或拉长。

若未启用 ARR 预装载，并在 `CNT` 已经大于新 `ARR` 时把周期调小，当前周期可能错过新的比较边界，直到计数器自然回绕后才恢复正常。运行中动态改频率时，应启用预装载，或在可控时刻写入参数并产生一次更新事件。

HAL 常用宏如下：

| 任务 | HAL 宏 |
| --- | --- |
| 读取/设置 `CNT` | `__HAL_TIM_GET_COUNTER()`、`__HAL_TIM_SET_COUNTER()` |
| 读取/设置 `ARR` | `__HAL_TIM_GET_AUTORELOAD()`、`__HAL_TIM_SET_AUTORELOAD()` |
| 设置 `PSC` | `__HAL_TIM_SET_PRESCALER()` |
| 产生更新事件 | `__HAL_TIM_GENERATE_EVENT(..., TIM_EVENTSOURCE_UPDATE)` |
| 读取/清除标志 | `__HAL_TIM_GET_FLAG()`、`__HAL_TIM_CLEAR_FLAG()` |

直接改 `PSC/ARR` 后，要明确希望“立即重启一个新周期”还是“在下个自然周期生效”。不要为了让参数生效无条件产生 UEV，因为 UEV 还可能置位 `UIF` 并影响中断逻辑。

### 1.8 CubeMX、HAL 与中断调用链

CubeMX 中把 TIM4 的 `Clock Source` 设为 `Internal Clock` 后，参数会进入 `MX_TIM4_Init()`：

```c
htim4.Instance = TIM4;
htim4.Init.Prescaler = 7199;
htim4.Init.CounterMode = TIM_COUNTERMODE_UP;
htim4.Init.Period = 9999;
htim4.Init.ClockDivision = TIM_CLOCKDIVISION_DIV1;
htim4.Init.AutoReloadPreload = TIM_AUTORELOAD_PRELOAD_ENABLE;
HAL_TIM_Base_Init(&htim4);
```

这段代码只完成初始化，不等于计数器已经运行。HAL 把“初始化”和“启动方式”分开：

| 目标 | 启动接口 |
| --- | --- |
| 只计数，程序轮询 | `HAL_TIM_Base_Start()` |
| 计数并响应更新中断 | `HAL_TIM_Base_Start_IT()` |
| 计数并用 DMA 传输更新数据 | `HAL_TIM_Base_Start_DMA()` |

更新中断的完整链路是：

```text
CNT 溢出/UEV
 -> SR.UIF = 1
 -> DIER.UIE 允许更新中断
 -> NVIC
 -> TIM4_IRQHandler()
 -> HAL_TIM_IRQHandler(&htim4)
 -> HAL 清标志
 -> HAL_TIM_PeriodElapsedCallback(&htim4)
```

CubeMX 必须在 `NVIC Settings` 中勾选 TIM4 全局中断。若 IRQHandler 中没有调用 `HAL_TIM_IRQHandler()`，HAL 回调不会执行；若只调用 `HAL_TIM_Base_Start()`，则 `DIER.UIE` 没有开启，也不会进入回调。

### 1.9 实验 6-1：1 s 定时中断

目标是让 TIM4 每 1 s 产生一次更新中断。取 $f_{TIM4}=72\ \mathrm{MHz}$：

$$
PSC=7200-1,\qquad ARR=10000-1
$$

于是：

$$
f_{CNT}=\frac{72\ \mathrm{MHz}}{7200}=10\ \mathrm{kHz}
$$

$$
T_{update}=\frac{10000}{10\ \mathrm{kHz}}=1\ \mathrm{s}
$$

CubeMX 配置：

| 项目 | 值 |
| --- | --- |
| TIM4 Clock Source | Internal Clock |
| Prescaler | `7199` |
| Counter Mode | Up |
| Counter Period | `9999` |
| Auto-reload preload | Enable |
| NVIC | TIM4 global interrupt Enable |

启动前清除初始化阶段可能留下的 `UIF`，可避免刚启动就多执行一次回调：

```c
volatile uint32_t tim4_seconds = 0U;

static void Timer4_Start(void)
{
    __HAL_TIM_CLEAR_FLAG(&htim4, TIM_FLAG_UPDATE);
    HAL_TIM_Base_Start_IT(&htim4);
}

void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim)
{
    if (htim->Instance == TIM4)
    {
        ++tim4_seconds;
    }
}
```

`tim4_seconds` 同时被中断和主程序访问，必须声明为 `volatile`。中断中只更新计数、置标志或搬运少量数据；OLED 刷屏、格式化字符串、阻塞串口发送等耗时操作放到主循环。若主循环和中断共用同一串口 DMA/IT 缓冲区，还要处理“上次发送未完成”的并发问题。

正常现象是 `tim4_seconds` 每秒加一。若启动后立刻加一，检查启动前是否清除了 `TIM_FLAG_UPDATE`；若周期慢约 9 倍，检查系统是否仍运行在 8 MHz；若完全不回调，沿“启动接口 -> UIF/UIE -> NVIC -> IRQHandler -> HAL 回调”逐级排查。

## 2. 外部时钟与从模式

### 2.1 外部信号进入定时器的路径

通用/高级定时器可以不使用内部时钟，而让 GPIO 上的有效边沿驱动 `CNT`。相关输入包括：

- `TI1~TI4`：四个捕获比较通道对应的外部输入；
- `ETR`（External Trigger）：独立外部触发输入；
- `ITR0~ITR3`：来自其他定时器 `TRGO` 的内部触发输入。

输入不会直接送到计数器，而要经过同步、数字滤波、边沿选择和触发源选择：

```text
GPIO/TIx -> 输入滤波 -> 极性/边沿检测 -> TIxFPx ----+
                                                       |
ETR -> 极性 -> 预分频 -> 输入滤波 -> ETRF -----------+-> TRGI
                                                       |
其他定时器 TRGO -> ITRx ------------------------------+
```

`TRGI` 只是“当前被选中的触发输入”。触发后执行什么动作，由从模式控制器的 `SMS` 配置决定。

### 2.2 外部时钟模式 1 与模式 2

两种外部时钟模式都能让外部边沿驱动 `CNT`，区别在于数据路径：

| 模式 | 输入路径 | 可选来源 | 特点 |
| --- | --- | --- | --- |
| External Clock Mode 1 | `TRGI -> 从模式控制器 -> CNT` | TI1FP1、TI2FP2、TI1_ED、ETR、ITRx | 来源丰富，但占用从模式控制器 |
| External Clock Mode 2 | `ETRF -> 触发控制器 -> CNT` | 仅 ETR | 路径独立，可与 Reset/Gated/Trigger 从模式同时使用 |

CubeMX 中：

- 模式 2：`Clock Source = ETR2`；
- 模式 1：关闭普通 Clock Source，选择 `Slave Mode = External Clock Mode 1`，再选择 `Trigger Source`。

STM32F103C8T6 的 TIM2_ETR 在 PA0。由于封装引脚限制，并非每个定时器的 ETR 都被引出；配置前要核对芯片数据手册和 CubeMX 引脚图。

`TI1 Edge Detector`（TI1_ED）对 TI1 的双边沿产生脉冲，因此同样的黑白交替距离可能得到 TI1FP1 单边沿计数的两倍。选择边沿后必须重新定义“一个物理标记对应多少个计数”。

### 2.3 极性、外部预分频与数字滤波

外部输入配置通常包含三个参数：

- `Polarity`：决定使用上升沿还是通过反相等效使用下降沿；
- `Prescaler`：ETR 可按 1、2、4、8 个有效边沿产生一次计数；
- `Filter`：要求输入在若干次采样中保持稳定，才承认一次电平变化。

数字滤波不是简单的平均值处理，也不是“填 15 一定最好”。滤波越强，越能抑制窄毛刺和机械抖动，但确认边沿所需时间更长，允许的最高输入频率也更低。采样频率由 `fDTS` 和滤波参数共同决定，而 `fDTS` 又受定时器时钟与 `Clock Division` 影响。高速编码器或高频外部时钟应按参考手册计算带宽，不能照搬低速光电开关的 `Filter=15`。

课程传送带使用的红外反射模块在黑白边缘附近可能反复翻转。此时应先调节模块比较阈值、改善安装距离和信号完整性，再使用适当数字滤波；滤波不能修复严重的光学抖动或接线干扰。

### 2.4 从模式控制器

从模式决定 `TRGI` 到来后如何控制定时器：

| 从模式 | `TRGI` 的作用 | 典型用途 |
| --- | --- | --- |
| External Clock Mode 1 | 每个有效触发沿让 `CNT` 计数 | 外部事件计数、定时器级联 |
| Reset | 有效触发沿复位 `CNT` 并产生更新事件 | 自动测周期、边沿同步 |
| Gated | 触发输入有效期间允许计数，无效期间暂停 | 测高电平宽度、窗口计数 |
| Trigger | 第一个有效触发沿启动计数，之后不会由同类触发停止 | 事件启动、定时器同步 |

Reset 模式会产生 UEV，因此可能触发更新中断，并把预装载值装入影子寄存器。若要区分“ARR 自然溢出”和“从模式复位”，可结合触发标志 `TIM_FLAG_TRIGGER` 判断，并在使用后清除：

```c
if (__HAL_TIM_GET_FLAG(&htim2, TIM_FLAG_TRIGGER) != RESET)
{
    __HAL_TIM_CLEAR_FLAG(&htim2, TIM_FLAG_TRIGGER);
    /* 本次更新与 TRGI 触发有关 */
}
```

Gated 模式只暂停或继续计数，不会在门控边沿自动清零 `CNT`。Trigger 模式只负责启动，不负责停止；若希望“每次触发只运行一个周期”，可再启用 One Pulse Mode，让定时器到达 `ARR` 后自动停止。

### 2.5 HAL 配置与启动

外部时钟和从模式的底层配置由 CubeMX 写入 `MX_TIMx_Init()`，常见 HAL 结构如下：

```c
TIM_ClockConfigTypeDef clockSourceConfig = {0};
TIM_SlaveConfigTypeDef slaveConfig = {0};

clockSourceConfig.ClockSource = TIM_CLOCKSOURCE_ETRMODE2;
clockSourceConfig.ClockPolarity = TIM_CLOCKPOLARITY_NONINVERTED;
clockSourceConfig.ClockPrescaler = TIM_CLOCKPRESCALER_DIV1;
clockSourceConfig.ClockFilter = 15;
HAL_TIM_ConfigClockSource(&htim2, &clockSourceConfig);

/* 使用模式 1 或 Reset/Gated/Trigger 时配置 slaveConfig */
slaveConfig.SlaveMode = TIM_SLAVEMODE_RESET;
slaveConfig.InputTrigger = TIM_TS_TI1FP1;
slaveConfig.TriggerPolarity = TIM_TRIGGERPOLARITY_RISING;
slaveConfig.TriggerPrescaler = TIM_TRIGGERPRESCALER_DIV1;
slaveConfig.TriggerFilter = 15;
HAL_TIM_SlaveConfigSynchro(&htim2, &slaveConfig);
```

应用层仍使用 `HAL_TIM_Base_Start()` 或 `HAL_TIM_Base_Start_IT()` 启动，因为外部时钟只改变“谁提供计数边沿”，没有改变 `CNT` 属于时基单元这一事实。

### 2.6 实验 6-2：传送带计数、距离与速度

红外反射模块的 DO 接 TIM2_ETR/PA0。传送带边缘均匀布置黑白条纹，每经过一个有效边沿，`CNT` 加一。

CubeMX 关键配置：

| 项目 | 值 |
| --- | --- |
| TIM2 Clock Source | ETR2 |
| Prescaler | `0` |
| Counter Period | `65535` |
| Clock Polarity | Non Inverted |
| Clock Prescaler | DIV1 |
| Clock Filter | 根据实测设置，低速抖动信号可从 `15` 开始验证 |

启动与读取：

```c
static void ConveyorCounter_Start(void)
{
    __HAL_TIM_SET_COUNTER(&htim2, 0U);
    HAL_TIM_Base_Start(&htim2);
}

static uint16_t ConveyorCounter_Read(void)
{
    return (uint16_t)__HAL_TIM_GET_COUNTER(&htim2);
}
```

设每个物理标记间距为 $L$，每个标记产生 $k$ 个有效计数，累计计数为 $N$，则传送距离：

$$
s=\frac{N}{k}L
$$

固定闸门时间 $T_g$ 内计数增量为 $\Delta N$，则平均速度：

$$
v=\frac{\Delta N}{kT_g}L
$$

例如每 100 ms 用另一个定时器读取一次 `CNT`，不要清零外部计数器，而是做 16 位模差：

```c
static uint16_t previous_count = 0U;

static uint16_t Conveyor_GetDelta(void)
{
    uint16_t current = (uint16_t)__HAL_TIM_GET_COUNTER(&htim2);
    uint16_t delta = (uint16_t)(current - previous_count);
    previous_count = current;
    return delta;
}
```

无符号模差允许 `CNT` 在两次采样间跨过一次 65535 回绕，但要求真实增量小于 65536。若需要长期累计总距离，可开启更新中断扩展高位计数，或在每次模差后把增量累加到 32/64 位软件变量。

正常现象是每经过一个规定边沿，计数按预期增加。若一格增加几十次，先观察 DO 波形和阈值，再调整滤波；若数值恰好翻倍，检查是否选择了 TI1_ED 双边沿；若高速时少计，减弱滤波并核对外部输入最高频率。

### 2.7 实验 6-3：观察三种控制型从模式

用 TIM2 内部时钟产生 1 kHz 计数，`ARR=4999`，正常 5 s 更新一次；PA0/TI1 提供触发信号。

Reset 模式下，每个有效上升沿使 `CNT` 重新从 0 开始。Gated 模式下，有效电平期间 `CNT` 增加，无效电平期间保持原值。Trigger 模式下，启动后 `CNT` 先保持 0，第一个有效边沿到来后开始计数，后续边沿不会让它停止。

验收时不要只看更新回调，应同时周期性读取 `CNT`：

```c
uint16_t count = (uint16_t)__HAL_TIM_GET_COUNTER(&htim2);
uint8_t triggered =
    (__HAL_TIM_GET_FLAG(&htim2, TIM_FLAG_TRIGGER) != RESET);

if (triggered != 0U)
{
    __HAL_TIM_CLEAR_FLAG(&htim2, TIM_FLAG_TRIGGER);
}
```

这三个模式的区别是“复位、门控、启动”，不是三种新的计数时钟。Reset/Gated/Trigger 下仍需为定时器配置内部时钟或 ETR 模式 2；否则 `TRGI` 只能控制状态，却没有时钟可供 `CNT` 计数。

## 3. 输出比较、PWM、舵机与直流电机

### 3.1 输出比较如何生成波形

输出比较（Output Compare，OC）不断比较 `CNT` 与捕获比较寄存器 `CCR`，再根据选定模式控制通道参考输出 `OCxREF`。最终输出级还能选择极性，所以“有效电平”不一定等于 GPIO 高电平。

常见模式：

| 模式 | 比较单元行为 | 用途 |
| --- | --- | --- |
| Frozen | 不因匹配改变输出 | 保持当前状态 |
| Active/Inactive on match | 匹配时置有效/无效 | 定时改变电平 |
| Toggle on match | 匹配时翻转 | 输出固定 50% 方波 |
| Forced active/inactive | 忽略比较结果强制状态 | 调试或故障控制 |
| PWM mode 1/2 | 按 `CNT` 与 `CCR` 的大小连续决定输出 | 可调频率、占空比 PWM |

同一定时器的 CH1~CH4 共享 `PSC/CNT/ARR`，所以频率相同且周期同步；每个通道有独立 `CCRx`，占空比可分别调整。同一通道的 `CCR` 和引脚由输入捕获与输出比较共用，不能同时既输入捕获又输出 PWM。

### 3.2 PWM 参数与边界

PWM（Pulse Width Modulation，脉冲宽度调制）是一种周期固定、有效电平持续时间可调的数字波形。三个基本参数是：

- 频率：$f=1/T$；
- 占空比：$D=T_{ON}/T$；
- 分辨率：占空比最小可调步距。

在“边沿对齐、向上计数、PWM mode 1、有效电平为高”条件下：

```text
CNT < CCR  -> 输出有效（高）
CNT >= CCR -> 输出无效（低）
```

因此：

$$
f_{PWM}=\frac{f_{TIM}}{(PSC+1)(ARR+1)}
$$

$$
D=\frac{CCR}{ARR+1}
$$

$$
\Delta D=\frac{1}{ARR+1}
$$

例如 `ARR=99` 时，一个周期有 100 个计数，占空比分辨率为 1%；`CCR=30` 时，`CNT=0~29` 共 30 个计数输出高电平，占空比为 30%。

边界要单独理解：

- `CCR=0`：0%；
- `CCR=ARR`：占空比为 $ARR/(ARR+1)$，不是严格 100%；
- `CCR=ARR+1`：整个周期都满足 `CNT<CCR`，在寄存器能写下该值时可得到严格 100%。

PWM mode 2 会把有效与无效关系反过来；`Polarity=Low` 又会在最终输出级反相。分析波形时要同时核对计数模式、PWM mode 和输出极性。

PWM 的平均电压近似为 $D\cdot V_{HIGH}$，前提是负载或后级具有足够的低通/惯性特征。舵机并不按平均电压工作，而是把高电平脉宽解释为位置命令；不能把所有 PWM 应用都理解成“模拟电压”。

### 3.3 CubeMX 与 HAL 配置链

PWM 配置顺序：

```text
选择 TIMx 内部时钟
 -> 设置 PSC、ARR、计数模式
 -> 选择 PWM Generation CHx
 -> 设置 PWM mode、Pulse(CCR)、Polarity、Fast Mode
 -> CubeMX 配置复用输出 GPIO
 -> HAL_TIM_PWM_Start()
 -> __HAL_TIM_SET_COMPARE() 动态修改占空比
```

CubeMX 生成的通道配置类似：

```c
TIM_OC_InitTypeDef channelConfig = {0};

channelConfig.OCMode = TIM_OCMODE_PWM1;
channelConfig.Pulse = 0;
channelConfig.OCPolarity = TIM_OCPOLARITY_HIGH;
channelConfig.OCFastMode = TIM_OCFAST_DISABLE;
HAL_TIM_PWM_ConfigChannel(&htim3, &channelConfig, TIM_CHANNEL_1);
```

运行时接口：

| 任务 | HAL 接口 |
| --- | --- |
| 启动/停止 PWM | `HAL_TIM_PWM_Start()`、`HAL_TIM_PWM_Stop()` |
| 中断/DMA 方式 | `HAL_TIM_PWM_Start_IT()`、`HAL_TIM_PWM_Start_DMA()` |
| 改比较值 | `__HAL_TIM_SET_COMPARE()` |
| 读比较值 | `__HAL_TIM_GET_COMPARE()` |

`Pulse` 和 `__HAL_TIM_SET_COMPARE()` 的单位是计数值，不是百分比。只有 `ARR+1=100` 时，`CCR` 的数值才恰好与百分数相同。

### 3.4 实验 6-4：PWM 呼吸灯

课程三色 LED 的 PA6 对应 TIM3_CH1。取 $f_{TIM3}=72\ \mathrm{MHz}$、`PSC=71`、`ARR=99`：

$$
f_{PWM}=\frac{72\ \mathrm{MHz}}{72\times100}=10\ \mathrm{kHz}
$$

CubeMX 将 TIM3_CH1 配为 `PWM Generation CH1`、PWM mode 1、High polarity，PA6 会自动配置为复用推挽输出。

```c
static void BreathingLed_RunOnce(void)
{
    uint16_t compare;

    HAL_TIM_PWM_Start(&htim3, TIM_CHANNEL_1);

    for (compare = 0U; compare <= 100U; ++compare)
    {
        __HAL_TIM_SET_COMPARE(&htim3, TIM_CHANNEL_1, compare);
        HAL_Delay(10U);
    }

    for (compare = 100U; compare > 0U; --compare)
    {
        __HAL_TIM_SET_COMPARE(
            &htim3,
            TIM_CHANNEL_1,
            compare - 1U
        );
        HAL_Delay(10U);
    }
}
```

若 LED 为低电平点亮，占空比与视觉亮度方向会相反，可改输出极性或写入 `100-compare`。人眼感知亮度不是线性的，即使占空比线性变化，视觉上也未必匀速变亮；需要更自然效果时可使用 Gamma 查表，但这不改变 PWM 硬件原理。

### 3.5 舵机的闭环机构与控制脉宽

常见 SG90/SJ90 舵机内部包含直流电机、减速齿轮、电位器和控制板。控制板比较“输入脉宽代表的目标角度”与“电位器反馈的当前角度”，再决定电机旋转方向。因此舵机本身是一个封装好的位置伺服系统，STM32 只负责发送位置命令。

课程舵机使用约 50 Hz，即 20 ms 周期的控制信号。常见映射为：

| 高电平时间 | 占 20 ms 的比例 | 典型角度 |
| --- | --- | --- |
| 0.5 ms | 2.5% | 0° |
| 1.5 ms | 7.5% | 90° |
| 2.5 ms | 12.5% | 180° |

具体安全脉宽和实际角度应以舵机规格书及实测为准。机械结构可能在到达理论 0°/180° 前就碰到限位，继续施加命令会堵转、发热并拉低电源。

课程板上的舵机信号 PB8 对应 TIM4_CH3。可按字幕参数配置：

| 项目 | 值 |
| --- | --- |
| TIM4_CH3 | PWM Generation CH3 |
| Prescaler | `719`，计数频率 100 kHz |
| Counter Period | `2000`（按课程字幕） |
| PWM Mode / Polarity | PWM mode 1 / High |

此时一个计数为 $10\ \mu s$，`CCR=50~250` 对应 $0.5~2.5\ \mathrm{ms}$。严格按 `ARR+1` 计算，字幕中的 `ARR=2000` 会得到约 $49.975\ \mathrm{Hz}$，对舵机控制没有实际影响；若要精确得到 50 Hz，可把 `ARR` 改为 `1999`。也可设 `PSC=71`、`ARR=19999`，让一个计数等于 $1\ \mu s$，计算更直观，但占用更多 ARR 范围。

### 3.6 实验 6-5：编码器旋钮控制舵机

课程板旋转编码器 A/B 相接 TIM1_CH1/CH2，舵机接 TIM4_CH3。数据链为：

```text
旋转编码器 A/B -> TIM1 Encoder -> CNT 限幅
                                  -> 角度/脉宽映射
                                  -> TIM4_CH3 CCR -> 舵机
```

字幕按“一个机械脉冲得到两个计数”的口径，把半圈旋转对应为 20 个计数。若在 CubeMX 中改成 TI12 四倍频，同一机械转角对应的计数会改变，`SERVO_COUNT_MAX` 也必须按实际解码倍频同步调整。

先启动两个外设：

```c
#define SERVO_COUNT_MAX 20
#define SERVO_CCR_MIN   50U
#define SERVO_CCR_MAX   250U

static void Servo_Start(void)
{
    __HAL_TIM_SET_COUNTER(&htim1, 0U);
    HAL_TIM_Encoder_Start(&htim1, TIM_CHANNEL_ALL);
    HAL_TIM_PWM_Start(&htim4, TIM_CHANNEL_3);
}
```

读取时先按有符号值解释零点附近的回绕，再限幅并同步写回 `CNT`：

```c
static int16_t Servo_ReadLimitedCount(void)
{
    int16_t count = (int16_t)__HAL_TIM_GET_COUNTER(&htim1);

    if (count < 0)
    {
        count = 0;
        __HAL_TIM_SET_COUNTER(&htim1, 0U);
    }
    else if (count > SERVO_COUNT_MAX)
    {
        count = SERVO_COUNT_MAX;
        __HAL_TIM_SET_COUNTER(&htim1, SERVO_COUNT_MAX);
    }

    return count;
}

static void Servo_UpdateFromEncoder(void)
{
    int16_t count = Servo_ReadLimitedCount();
    uint32_t pulse =
        SERVO_CCR_MIN +
        ((uint32_t)count * (SERVO_CCR_MAX - SERVO_CCR_MIN))
        / SERVO_COUNT_MAX;

    __HAL_TIM_SET_COMPARE(&htim4, TIM_CHANNEL_3, pulse);
}
```

先乘后除可保留整数精度；若先计算 `count / SERVO_COUNT_MAX`，绝大多数结果会因整数除法变成 0。程序初次启动前最好先写入中位脉宽，再启用 PWM，减少舵机突然撞向端点。

舵机应由合适的 5 V 电源供电，不能从 GPIO 取电；STM32、电源和舵机必须共地。舵机动作导致系统复位或 OLED 闪烁，通常是电源瞬态能力、布线压降或去耦问题，不是 PWM 公式问题。

### 3.7 为什么 GPIO 不能直接驱动直流电机

小直流电机启动和堵转电流通常远高于 GPIO 的承受能力。电机绕组是感性负载，关断、换向或外力转动时会产生反电动势。GPIO 直接连接电机既无法提供足够电流，也可能因电压尖峰损坏 MCU。

H 桥驱动器用功率晶体管承担电机电流，并通过两组桥臂改变电机两端极性，实现正转、反转、短刹车和高阻滑行。PWM 控制的是桥臂导通时间，因此改变的是平均驱动力；实际转速还受供电、电机反电动势、负载和摩擦影响。

课程字幕使用 DRV8833，但本章电机实验按实际驱动目录 `E:\ProjectStm\驱动库\TB1622` 中的 TB6612FNG HAL 驱动编写，不复制课程的 DRV8833 双 PWM 与衰减模式代码。

### 3.8 TB6612FNG 状态与实际驱动约定

TB6612 有 A/B 两路 H 桥。以 A 路为例，`AIN1/AIN2` 决定方向，`PWMA` 是高有效 PWM，`STBY=1` 时芯片才工作。

| IN1 | IN2 | PWM | 输出状态 |
| :---: | :---: | :---: | --- |
| 1 | 0 | 1 | 正转方向导通 |
| 0 | 1 | 1 | 反转方向导通 |
| 任意 | 任意 | 0 | 短刹车 |
| 1 | 1 | 0/1 | 短刹车 |
| 0 | 0 | 1 | 高阻停止，即滑行 |
| 任意 | 任意 | 任意，且 `STBY=0` | 待机，高阻 |

本机驱动的行为已在 `tb6612.c` 中固定：

- `TB6612_Forward()/Backward()` 先把 PWM 拉低，再改变方向脚，最后写入目标占空比；
- `TB6612_Brake()` 进入短刹车状态；
- `TB6612_Coast()` 把两方向脚拉低，并保持 PWM 为高，得到高阻滑行；
- `Forward/Backward(speed=0)` 的 PWM 始终为低，因此表现为短刹车，不等于 `Coast()`；
- 驱动不修改 `PSC/ARR`，PWM 频率完全由 CubeMX 决定。

驱动把 `speed=0~100` 映射到当前 `ARR+1`：

$$
CCR\approx\frac{speed}{100}(ARR+1)
$$

这只是占空比百分数，不是 r/min。需要恒速时，必须增加编码器反馈和 PID 等闭环控制。

### 3.9 TB6612 的 CubeMX 与硬件配置

以驱动默认的 TIM3_CH1/CH2 为例，配置 20 kHz PWM：

| 项目 | 值 |
| --- | --- |
| TIM3_CH1 / CH2 | PWM Generation |
| Prescaler | `0` |
| Counter Period | `3599` |
| PWM Mode | PWM mode 1 |
| Polarity | High |
| AIN1/AIN2/BIN1/BIN2 | GPIO Output Push-Pull，初始低 |
| STBY | 硬件拉高，或配置 GPIO 输出并在应用层置高 |

$$
f_{PWM}=\frac{72\ \mathrm{MHz}}{(0+1)(3599+1)}
=20\ \mathrm{kHz}
$$

`tb6612.h` 中的映射必须与 CubeMX 一致：

```c
#define AIN1_GPIO_Port TB6612_AIN1_GPIO_Port
#define AIN2_GPIO_Port TB6612_AIN2_GPIO_Port
#define AIN1_Pin       TB6612_AIN1_Pin
#define AIN2_Pin       TB6612_AIN2_Pin

#define PWMA_TIM         &htim3
#define PWMA_TIM_CHANNEL TIM_CHANNEL_1
#define PWMB_TIM         &htim3
#define PWMB_TIM_CHANNEL TIM_CHANNEL_2
```

硬件连接：

```text
STM32 TIM3_CH1 -> PWMA         A01/A02 -> 电机 A
STM32 GPIO     -> AIN1/AIN2
STM32 GPIO/上拉 -> STBY

VM  -> 电机电源
VCC -> 逻辑电源
GND -> STM32、电机电源、TB6612 共地
```

`STBY` 没有包含在当前驱动的公共接口里，必须由模块硬件上拉或应用层 GPIO 保证为高。电机电源旁应按模块要求布置去耦，业务层应避免高速下瞬间正反转。

### 3.10 实验 6-6：编码器旋钮控制 TB6612

沿用课程字幕的交互：用编码器 `CNT` 的中点表示停车，`0~19` 映射为反转，`20` 停车，`21~40` 映射为正转。启动时先把计数器置于中点，防止上电立即全速反转。

```c
#define MOTOR_CONTROL_MID 20
#define MOTOR_CONTROL_MAX 40

static void MotorControl_Start(void)
{
    TB6612_Init(ONLY_A);
    __HAL_TIM_SET_COUNTER(&htim1, MOTOR_CONTROL_MID);
    HAL_TIM_Encoder_Start(&htim1, TIM_CHANNEL_ALL);
    TB6612_Coast(ONLY_A);
}

static int16_t MotorControl_ReadKnob(void)
{
    int16_t count = (int16_t)__HAL_TIM_GET_COUNTER(&htim1);

    if (count < 0)
    {
        count = 0;
        __HAL_TIM_SET_COUNTER(&htim1, 0U);
    }
    else if (count > MOTOR_CONTROL_MAX)
    {
        count = MOTOR_CONTROL_MAX;
        __HAL_TIM_SET_COUNTER(&htim1, MOTOR_CONTROL_MAX);
    }

    return count;
}

static void MotorControl_Update(void)
{
    int16_t count = MotorControl_ReadKnob();

    if (count < MOTOR_CONTROL_MID)
    {
        uint8_t speed = (uint8_t)(
            (MOTOR_CONTROL_MID - count) * 100
            / MOTOR_CONTROL_MID
        );
        TB6612_Backward(ONLY_A, speed);
    }
    else if (count > MOTOR_CONTROL_MID)
    {
        uint8_t speed = (uint8_t)(
            (count - MOTOR_CONTROL_MID) * 100
            / (MOTOR_CONTROL_MAX - MOTOR_CONTROL_MID)
        );
        TB6612_Forward(ONLY_A, speed);
    }
    else
    {
        TB6612_Coast(ONLY_A);
    }
}
```

这里用 TIM1 读取旋钮编码器；TB6612 的 PWM 定时器由 `tb6612.h` 中的 `PWMA_TIM/PWMB_TIM` 决定。若实际旋转方向与界面定义相反，可交换 A/B、电机两根线或对调 Forward/Backward 的调用，但只能选一种方式统一方向口径。

若希望旋钮回到中点时快速停住，把 `Coast()` 改为 `Brake()`；两者的机械效果和电流衰减不同。电机从静止到很低占空比时可能不转，这是静摩擦和启动转矩造成的死区，不应通过伪造“速度已经达到”来掩盖。可在应用层标定最小启动占空比，但要与实际测速闭环区分。

## 4. 输入捕获、PWMI 与超声波测距

### 4.1 输入捕获解决什么问题

轮询 GPIO 再由软件启动/读取定时器，会把循环延迟、中断延迟和指令执行时间带入测量。输入捕获（Input Capture，IC）在指定边沿到来的硬件时刻，把当前 `CNT` 复制到 `CCR`。程序晚一点读取，得到的仍是边沿发生时的计数值。

```text
GPIO/TIx -> 滤波 -> 极性选择 -> 输入预分频
         -> 边沿到来时 CCRx <- CNT
         -> 置位 CCxIF
         -> 可选捕获中断/DMA
```

输出比较与输入捕获共用 `CCR`：

- 输出比较：软件先写 `CCR`，硬件比较 `CNT` 与 `CCR`；
- 输入捕获：外部边沿到来时，硬件把 `CNT` 写入 `CCR`。

### 4.2 测频法与测周法

测量频率有两种基本方法。

测频法（M 法）在固定闸门时间 $T_g$ 内统计待测边沿数 $N$：

$$
f_x=\frac{N}{T_g}
$$

它适合高频信号。闸门越长，分辨率越高，但结果更新越慢。

测周法（T 法）在相邻同类边沿之间，用已知计数频率 $f_c$ 统计计数值 $N$：

$$
T_x=\frac{N}{f_c},\qquad f_x=\frac{f_c}{N}
$$

它适合低频信号。$N$ 越大，相对量化误差越小；输入频率过低时，`CNT` 可能在下一个边沿到来前溢出。

令两种方法的计数规模近似相同，可得到误差意义上的中界频率：

$$
f_m=\sqrt{\frac{f_c}{T_g}}
$$

实际选择还要考虑刷新速度、抖动、计数器位宽和输入滤波带宽。

### 4.3 直接捕获、间接捕获与通道配对

TI1/TI2 和 TI3/TI4 分别组成通道对。以信号从 TI1 引入为例：

- CH1 选择 `Direct Input`：TI1FP1 捕获到 CCR1；
- CH2 选择 `Indirect Input`：同一 TI1 信号交叉捕获到 CCR2。

这样一根信号线就能用两个 `CCR` 分别记录上升沿和下降沿，不需要接到两个 GPIO。一个通道本身通常只配置一种捕获极性；“一个通道双边沿”若芯片/HAL 配置不直接支持，可用两个通道配对或在中断中切换极性。

输入捕获参数：

| CubeMX/HAL 参数 | 作用 |
| --- | --- |
| Polarity | 捕获上升沿、下降沿或支持的双边沿 |
| Selection | Direct TI 或 Indirect TI |
| Prescaler | 每 1、2、4、8 个有效边沿捕获一次 |
| Filter | 数字滤波强度 |

输入预分频发生在捕获通道前，只改变“每几个边沿保存一次”，不会改变 `CNT` 的计数频率。数字滤波越强，抗毛刺能力越好，但延迟和带宽限制越明显。

### 4.4 Slave Reset 自动测周期

单次捕获只得到某个边沿的时间戳。若希望每次 CCR1 直接表示“刚结束的一个周期”，可让同一个输入边沿同时完成捕获与复位：

```text
TI1 上升沿
  +-> CCR1 <- CNT，保存上一周期
  +-> TRGI = TI1FP1
      -> Slave Reset
      -> CNT = 0，开始下一周期
```

硬件自动重复该过程，CPU 只需读取 CCR1。CubeMX 中通常配置 CH1 Direct Input、Rising，`Slave Mode = Reset Mode`，`Trigger Source = TI1FP1`。

### 4.5 PWMI 同时测频率和占空比

PWMI（PWM Input）用两个通道观察同一输入：

- CH1：直接输入、上升沿捕获，CCR1 保存整个周期；
- CH2：间接输入、下降沿捕获，CCR2 保存高电平宽度；
- TI1FP1：作为 Reset 触发，在每个上升沿清零 `CNT`。

若定时器计数频率为 $f_c$：

$$
f_x=\frac{f_c}{CCR1}
$$

$$
D=\frac{CCR2}{CCR1}\times100\%
$$

计算前必须检查 `CCR1!=0`。读取时先把两个寄存器缓存到局部变量，再计算，减少两次读取跨过新捕获事件造成的不一致。

### 4.6 HAL 配置、启动与回调

输入捕获配置链：

```text
配置 TIM 内部时钟、PSC、ARR
 -> 配置 IC 通道的极性、直连/间接、预分频、滤波
 -> 需要自动测周时配置 Slave Reset 与 TRGI
 -> 需要回调时在 NVIC 中开启捕获比较中断
 -> HAL_TIM_IC_Start() / HAL_TIM_IC_Start_IT()
 -> HAL_TIM_ReadCapturedValue()
```

启动两个通道：

```c
HAL_TIM_IC_Start(&htim3, TIM_CHANNEL_1);
HAL_TIM_IC_Start(&htim3, TIM_CHANNEL_2);
```

捕获中断回调必须同时判断定时器实例和活动通道。`htim->Channel` 使用 `HAL_TIM_ACTIVE_CHANNEL_x`，不是 `TIM_CHANNEL_x`：

```c
volatile uint32_t capture_period = 0U;
volatile uint8_t capture_ready = 0U;

void HAL_TIM_IC_CaptureCallback(TIM_HandleTypeDef *htim)
{
    if ((htim->Instance == TIM3) &&
        (htim->Channel == HAL_TIM_ACTIVE_CHANNEL_1))
    {
        capture_period =
            HAL_TIM_ReadCapturedValue(htim, TIM_CHANNEL_1);
        capture_ready = 1U;
    }
}
```

HAL 的 `TIMx_IRQHandler() -> HAL_TIM_IRQHandler()` 会判断 `CCxIF`、中断允许位并清除相应标志，再调用此回调。不要在回调里再次长时间轮询输入。

### 4.7 实验 6-7：输入捕获和 PWMI

用 TIM2_CH1 输出已知 PWM，再用导线接到 TIM3_CH1。TIM3 取 `PSC=71`、`ARR=65535`，计数频率为 1 MHz，一个计数等于 $1\ \mu s$。

单通道测周期时，CH1 配置 Direct Input、Rising，并用 TI1FP1 触发 Slave Reset：

```c
static uint32_t InputCapture_GetFrequency(void)
{
    uint32_t period =
        HAL_TIM_ReadCapturedValue(&htim3, TIM_CHANNEL_1);

    if (period == 0U)
    {
        return 0U;
    }

    return 1000000UL / period;
}
```

PWMI 再启用 CH2 间接下降沿捕获：

```c
typedef struct
{
    uint32_t frequency_hz;
    uint32_t duty_percent;
} PwmMeasurement;

static PwmMeasurement PWMI_Read(void)
{
    PwmMeasurement result = {0U, 0U};
    uint32_t period =
        HAL_TIM_ReadCapturedValue(&htim3, TIM_CHANNEL_1);
    uint32_t high =
        HAL_TIM_ReadCapturedValue(&htim3, TIM_CHANNEL_2);

    if (period != 0U)
    {
        result.frequency_hz = 1000000UL / period;
        result.duty_percent = high * 100UL / period;
    }

    return result;
}
```

当 $f_c=1\ \mathrm{MHz}$、`ARR=65535` 时，不溢出的理论最低频率约为：

$$
f_{min}=\frac{10^6}{65536}\approx15.26\ \mathrm{Hz}
$$

测周量化误差量级约为 $1/N$。若希望误差约不高于 1%，应尽量让周期计数 $N\ge100$；在 1 MHz 计数下，对应频率不高于约 10 kHz。

输入停止后 CCR 会保留最后一次值，不会自动清零。应用层必须记录最后捕获时刻，超过合理周期仍未更新就报告 0 Hz 或超时，不能继续显示旧频率。

### 4.8 HC-SR04 的测距时序

HC-SR04 类模块有四个引脚：

- `VCC/GND`：模块供电；
- `TRIG`：STM32 输出触发脉冲；
- `ECHO`：模块输出回波高电平。

一次测量：

```text
STM32: TRIG ____|‾‾约10us‾‾|________________
模块 : ECHO __________|‾‾‾‾往返时间 t‾‾‾‾|____
```

`ECHO` 高电平时间 $t$ 表示声波往返时间。取室温附近声速 $v\approx343\ \mathrm{m/s}$：

$$
d=\frac{vt}{2}
$$

若 $t$ 的单位是 $\mu s$：

$$
d\approx\frac{t_{\mu s}}{58.3}\ \mathrm{cm}
$$

声速随温度、湿度变化；障碍物角度、吸声材料、模块盲区和视场内更近物体都会影响结果。超声波测距得到的是声束范围内最先形成有效回波的目标，不一定是正前方指定物体。

### 4.9 实验 6-8：输入捕获实现超声波测距

按字幕中的资源映射：

| 信号 | 引脚/资源 | 配置 |
| --- | --- | --- |
| TRIG | PA11 | GPIO Output Push-Pull |
| ECHO | PA10 / TIM1_CH3 | CH3 Direct Input，Rising |
| ECHO 下降沿 | TIM1_CH4 | CH4 Indirect Input，Falling |

TIM1 配置 `PSC=71`、`ARR=65535`，得到 1 MHz 计数。CH3 启动普通捕获，CH4 启动捕获中断：

```c
volatile uint32_t echo_pulse_us = 0U;
volatile uint8_t echo_ready = 0U;

static void Ultrasonic_CaptureStart(void)
{
    HAL_TIM_IC_Start(&htim1, TIM_CHANNEL_3);
    HAL_TIM_IC_Start_IT(&htim1, TIM_CHANNEL_4);
}

void HAL_TIM_IC_CaptureCallback(TIM_HandleTypeDef *htim)
{
    if ((htim->Instance == TIM1) &&
        (htim->Channel == HAL_TIM_ACTIVE_CHANNEL_4))
    {
        uint32_t rising =
            HAL_TIM_ReadCapturedValue(htim, TIM_CHANNEL_3);
        uint32_t falling =
            HAL_TIM_ReadCapturedValue(htim, TIM_CHANNEL_4);
        uint32_t period =
            __HAL_TIM_GET_AUTORELOAD(htim) + 1U;

        if (falling >= rising)
        {
            echo_pulse_us = falling - rising;
        }
        else
        {
            echo_pulse_us = period - rising + falling;
        }

        echo_ready = 1U;
    }
}
```

触发脉冲应使用可靠的微秒延时实现。TIM1 已按 1 MHz 自由运行，可直接轮询硬件计数器；这里的空循环只等待硬件 `CNT` 前进，不依赖 CPU 执行固定条数的指令：

```c
static void Delay_us(uint16_t us)
{
    uint16_t start =
        (uint16_t)__HAL_TIM_GET_COUNTER(&htim1);

    while ((uint16_t)(
        __HAL_TIM_GET_COUNTER(&htim1) - start
    ) < us)
    {
    }
}

static void Ultrasonic_Trigger(void)
{
    echo_ready = 0U;
    __HAL_TIM_SET_COUNTER(&htim1, 0U);

    HAL_GPIO_WritePin(
        ULTRASONIC_TRIG_GPIO_Port,
        ULTRASONIC_TRIG_Pin,
        GPIO_PIN_SET
    );
    Delay_us(10U);
    HAL_GPIO_WritePin(
        ULTRASONIC_TRIG_GPIO_Port,
        ULTRASONIC_TRIG_Pin,
        GPIO_PIN_RESET
    );
}
```

空 `for` 循环会受编译优化和主频影响，不能当成可靠微秒延时。字幕为演示方便使用毫秒级 HAL_Delay 也可能触发模块，但不应作为规范触发时序。

用整数计算毫米距离：

```c
static uint32_t Ultrasonic_GetDistanceMm(void)
{
    /* 343 m/s = 0.343 mm/us，往返距离再除以 2 */
    return (echo_pulse_us * 343UL + 1000UL) / 2000UL;
}
```

工程中还必须加入超时。触发后若在模块最大回波时间内 `echo_ready` 仍为 0，应报告无回波，不能永久等待。HC-SR04 的 ECHO 常为 5 V 电平，接入 STM32 前应根据具体芯片引脚耐压和模块电路确认，必要时使用电阻分压或电平转换。

本章各实验默认是独立工程。若把输入捕获测频、超声波和其他定时器中断集成到同一项目，`HAL_TIM_IC_CaptureCallback()` 与 `HAL_TIM_PeriodElapsedCallback()` 各只能保留一个全局定义，应在其中按 `Instance` 和活动通道统一分发，不能把多个示例回调原样重复粘贴。

## 5. 编码器接口

### 5.1 增量编码器与正交信号

增量编码器输出 A、B 两相信号。理想匀速时两相相差约 90°：一个方向 A 超前 B，反向时 B 超前 A。每个边沿到来时结合另一相电平，就能判断方向。

编码器只提供相对位移，掉电后无法仅靠 A/B 相恢复绝对位置。若需要回零，可增加限位开关或 Z 相；若需要掉电保持绝对角度，应使用绝对值编码器或保存并校准位置。

用 GPIO 外部中断也能解码，但高速电机可能每秒产生大量边沿，CPU 会频繁进入中断。定时器编码器接口在硬件中完成方向判断和 `CNT` 加减，相当于“带方向的外部计数器”。

### 5.2 编码器模式与四倍频

A/B 相分别进入 CH1、CH2，经滤波和极性处理形成 TI1FP1、TI2FP2。三种编码器模式：

| 模式 | 实际计数边沿 | CubeMX/HAL 含义 |
| --- | --- | --- |
| Encoder mode TI1 | 在 TI2FP2 的两个边沿计数，方向由 TI1FP1 决定 | `TIM_ENCODERMODE_TI1` |
| Encoder mode TI2 | 在 TI1FP1 的两个边沿计数，方向由 TI2FP2 决定 | `TIM_ENCODERMODE_TI2` |
| Encoder mode TI12 | 两路的上升、下降沿都计数 | `TIM_ENCODERMODE_TI12` |

课程通常选择 TI12，一组完整正交周期得到 4 个计数，即四倍频。编码器手册中的 PPR、CPR、线数和脉冲数口径可能不同，必须确认其标称值是否已经包含四倍频和减速比。

编码器模式下的通道 Polarity 表示是否先反相输入，并不是“只在上升沿计数”。交换 A/B 或反相其中一路会改变正负方向；同时反相两路通常不改变相对方向。

不应依赖 `PSC` 给编码器计数“二分频”。编码器接口的有效计数边沿由编码器模式决定；需要降低分辨率时，应选 TI1/TI2 模式，或在应用层按明确比例换算。

### 5.3 CubeMX 与 HAL 启动

以课程板 TIM1_CH1/PA8、TIM1_CH2/PA9 为例：

| 项目 | 值 |
| --- | --- |
| Combined Channels | Encoder Mode |
| Encoder Mode | TI12 |
| Prescaler | `0` |
| Counter Period | `65535` |
| CH1/CH2 Polarity | Rising，表示不反相 |
| CH1/CH2 Filter | 按信号质量和最高速度选择 |

CubeMX 生成 `HAL_TIM_Encoder_Init()`，应用层还要启动：

```c
static void Encoder_Start(void)
{
    __HAL_TIM_SET_COUNTER(&htim1, 0U);
    HAL_TIM_Encoder_Start(&htim1, TIM_CHANNEL_ALL);
}
```

若只启动 CH1 或 CH2，另一通道可能未启用，TI12 解码无法按预期工作。编码器模式占用同一定时器的 CH1/CH2，并接管计数时钟和方向；普通内部时钟与 `CounterMode=Up/Down` 不再决定实际旋转方向。

### 5.4 位置、方向与模计数

直接读取 `CNT` 得到相对初始位置：

```c
static int16_t Encoder_GetPosition(void)
{
    return (int16_t)__HAL_TIM_GET_COUNTER(&htim1);
}
```

把 16 位无符号位模式解释为 `int16_t` 后，`65535` 自然表示 `-1`，适合处理零点附近的正反向变化。它只在关心的相对位置不超过有符号半范围时成立；长期累计位置应使用更新中断扩展高位，或周期性做连续模差并累加到 `int32_t/int64_t`。

定时器当前硬件方向也可通过 `__HAL_TIM_IS_TIM_COUNTING_DOWN()` 判断，但应用层速度符号通常直接来自有符号计数增量。

### 5.5 实验 6-9：固定闸门测速

每隔固定闸门时间 $T_g$ 读取一次增量，不清零计数器：

```c
static uint16_t previous_encoder_count = 0U;

static int16_t Encoder_GetDelta(void)
{
    uint16_t current =
        (uint16_t)__HAL_TIM_GET_COUNTER(&htim1);
    uint16_t modular_delta =
        (uint16_t)(current - previous_encoder_count);
    int16_t delta = (int16_t)modular_delta;

    previous_encoder_count = current;
    return delta;
}
```

连续模差避免了“读取后清零”之间丢失少量边沿。其前提是单个采样周期内真实增量满足：

$$
|\Delta CNT|<32768
$$

若每转一圈经过解码后产生 $C$ 个计数，闸门时间为 $T_g$ 秒：

$$
n_{r/s}=\frac{\Delta CNT}{CT_g}
$$

$$
n_{r/min}=\frac{60\Delta CNT}{CT_g}
$$

若编码器位于电机轴、输出轴前还有减速箱，$C$ 必须乘以减速比。闸门过长时低速分辨率高但刷新慢，也更容易跨过半个 16 位范围；闸门过短时刷新快，但低速下每次只有少量计数，量化波动明显。

编码器可用于两类不同任务：

- 人机输入：像课程旋钮一样，把有限 `CNT` 映射为舵机角度或电机命令；
- 运动反馈：测量电机实际位置/速度，与目标值比较形成闭环。

“编码器旋钮改变 TB6612 占空比”仍是开环调速，因为反馈的是用户旋钮，不是电机实际速度。只有编码器安装在电机或机构上并参与误差计算，才构成速度或位置闭环。

## 6. 验收与排错

### 6.1 分实验验收

| 实验 | 正常现象 | 优先检查 |
| --- | --- | --- |
| `6-1` 定时中断 | 回调严格约每 1 s 一次，启动不多触发 | 时钟树、`PSC/ARR`、UIF、NVIC、IRQHandler |
| `6-2` 传送带计数 | 每个规定边沿只增加预期次数 | PA0/ETR、极性、滤波、阈值、共地 |
| `6-3` 从模式 | Reset 清零、Gated 暂停、Trigger 启动 | TRGI、Slave Mode、计数时钟是否另有来源 |
| `6-4` 呼吸灯 | LED 平滑渐亮渐暗 | TIM3_CH1、复用输出、极性、CCR 范围 |
| `6-5` 舵机 | 旋钮在安全范围内连续控制角度 | 50 Hz、脉宽、编码器方向、5 V 供电、共地 |
| `6-6` TB6612 | 正反转和 Brake/Coast 均符合命令 | STBY、VM/VCC、方向 GPIO、PWM 通道、驱动宏 |
| `6-7` PWMI | 频率和占空比接近信号源 | 直连/间接通道、Slave Reset、CCR 对应、超时 |
| `6-8` 超声波 | 距离随物体移动变化，无回波能超时 | TRIG 脉宽、ECHO 电平、CH3/CH4、回绕计算 |
| `6-9` 编码器测速 | 正反转速度符号相反，停止后归零 | A/B 顺序、TI12、滤波、$C$ 与闸门时间 |

### 6.2 按信号链排错

遇到问题按实际数据路径逐层检查：

1. **供电、共地和接线**：舵机/电机是否独立供电并共地，TB6612 的 `VM/VCC/STBY` 是否正确，ECHO 是否满足输入电压限制。
2. **GPIO 与复用映射**：芯片型号、TIM 编号、通道、引脚是否一致；CubeMX 是否因资源冲突重映射了引脚。
3. **时钟**：外部晶振、PLL、APB 分频与 `Timer clocks` 是否符合参数计算。
4. **时基**：`PSC/ARR` 的两个“`+1`”是否正确；计数模式、预装载和 UEV 生效时刻是否符合预期。
5. **数据通路**：ETR/TIx、Direct/Indirect、TRGI、Slave Mode、PWM mode、Polarity 和 Filter 是否连成目标路径。
6. **启动和中断**：是否调用了正确的 `Start/Start_IT`；NVIC、IRQHandler、`HAL_TIM_IRQHandler()` 和回调判断是否完整。
7. **计算边界**：除零、回绕、超时、有符号范围、单位换算和整数运算顺序是否正确。
8. **应用逻辑**：中断是否过长，DMA/IT 缓冲是否被重用，开环占空比是否被误当成实际速度。

常见症状与原因：

- **启动后立即回调一次**：初始化或软件 UEV 留下了 `UIF`，启动前清标志。
- **周期固定慢一倍/快一倍**：APB 定时器倍频口径或计数模式理解错误。
- **PWM 频率正确但占空比错误**：`CCR` 被当作百分数、模式/极性反相或 `ARR+1` 漏算。
- **输入停止后仍显示旧频率/旧距离**：CCR 保留旧值，缺少超时状态。
- **编码器低速跳动、高速漏计**：输入抖动、滤波参数与速度不匹配，或 A/B 接线质量差。
- **电机占空比变化但转速不成比例**：电机是非线性机械负载，且当前控制是开环。

## 本章小结

定时器的共同主线是“选择事件来驱动、复位、比较或保存 `CNT`”。`PSC/CNT/ARR` 决定计数尺度和周期；更新事件用于周期任务与状态更新；`CNT` 和 `CCR` 比较产生 PWM；外部边沿把 `CNT` 捕获到 `CCR` 以测量时间；两路正交边沿控制 `CNT` 加减以测量位置和速度。

HAL 工程还要多看一层调用链：CubeMX 负责生成时钟、GPIO、时基、通道和 NVIC 配置；`HAL_TIM_xxx_Start()` 决定运行方式；IRQHandler 交给 `HAL_TIM_IRQHandler()` 分发；应用层在统一回调中按实例和活动通道处理结果。

掌握“时钟源 -> `PSC` -> `CNT` -> `ARR/CCR` -> 标志/中断 -> 应用结果”这条链后，就能独立配置定时中断、外部计数、从模式、PWM、舵机、TB6612 电机、输入捕获、PWMI、超声波和编码器，并能从异常现象定位到具体硬件环节。
