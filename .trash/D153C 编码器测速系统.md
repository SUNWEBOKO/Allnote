# D153C 编码器测速系统

## 0. 适用范围与学习目标

本文档讲解如何从 MG513P30 电机的霍尔编码器中提取轮胎转速。假定电机已能通过 `d153c_drive()` 正常转动，本文不涉及 PWM/H 桥驱动。读完应能：

- 解释霍尔效应与 A/B 正交信号的判向原理
- 使用 EXTI 双边沿中断实现角度测量
- 理解 M 法与 T 法的误差特性及选型依据
- 实现 T 法测速并修复三大工程缺陷
- 了解定时器编码器模式的替代方案

> 完整电机控制分为两篇：本文对应编码器测速，另一篇《D153C 电机驱动控制》对应 PWM 驱动。

## 1. 编码器物理原理

### 1.1 霍尔效应

通电导体中载流子在磁场中受洛伦兹力 $\vec{F} = q \vec{v} \times \vec{B}$ 而偏转，在导体两侧积累电荷形成横向电势差——**霍尔电压**。磁场方向反转时，霍尔电压极性随之翻转。

### 1.2 磁环与 A/B 正交信号

MG513P30 电机尾部嵌有充磁圆环，沿圆周等分为 **22 个扇区**，N/S 交替充磁，形成 **11 对磁极**。两个霍尔传感器（A 相、B 相）紧贴磁环安装，空间错开 **90° 电角度**（1/4 脉冲周期）。

磁环每转一圈，每个传感器输出 **11 个完整方波脉冲**。A/B 两路因 90° 错位呈正交关系：
- **正转**：A 相超前 B 相 90°
- **反转**：B 相超前 A 相 90°

捕获 A 相的上升沿和下降沿（双边沿），每圈共 **22 个边沿事件**。在每次边沿读取 B 相电平即可判断转向。

## 2. 角度测量：EXTI 双边沿与判向

### 2.1 引脚分配

| 信号 | 左电机 | 右电机 | 配置 |
| --- | --- | --- | --- |
| A 相 (EXTI 双边沿) | PB14 | PB3 | `GPIO_MODE_IT_RISING_FALLING`，上拉 |
| B 相 (电平读取) | PB15 | PB4 | `GPIO_MODE_INPUT`，上拉 |

> ⚠️ PB3/PB4 默认属于 JTAG 接口。CubeMX 中需将 `SYS` → `Debug` 设为 **Serial Wire** 以释放。

### 2.2 判向真值表

| A 相边沿 | B 相电平 | 转向 | 计数变化 |
| --- | --- | --- | --- |
| 上升沿 | 低电平 | 正转 | +1 |
| 上升沿 | 高电平 | 反转 | -1 |
| 下降沿 | 高电平 | 正转 | +1 |
| 下降沿 | 低电平 | 反转 | -1 |

对应 C 实现（按边沿类型分支）：
```c
int8_t new_dir;
uint8_t A = HAL_GPIO_ReadPin(port, pin_A);
uint8_t B = HAL_GPIO_ReadPin(port, pin_B);

if (A == GPIO_PIN_SET) {              // 上升沿
    new_dir = (B == GPIO_PIN_RESET) ? 1 : -1;
} else {                               // 下降沿
    new_dir = (B == GPIO_PIN_SET)   ? 1 : -1;
}
```

### 2.3 角度换算

编码器计数值 `encoder` 累计 A 相边沿净次数。换算到轮胎转角需三级：

**电机轴圈数**：$\text{encoder} / 22$（每圈 22 个边沿）

**减速比**：实测五级齿轮箱精确值 $R = 30613 / 1500 \approx 20.4087$

**轮胎圈数**：$N_{\text{wheel}} = \text{encoder} / (22 \times R)$

**轮胎转角**：
$$
\theta(^\circ) = \text{encoder} \times \frac{1500 \times 360}{22 \times 30613}
$$

| 参数 | 值 |
| --- | --- |
| 磁环边沿数/电机轴圈 | 22 |
| 减速比 | 30613/1500 ≈ 20.4087 |
| 编码器增量/输出轴圈 | $22 \times 30613/1500 \approx 449$ |

## 3. 减速比实测

厂家标称 21.3，但拆解五级齿轮箱计算得精确值 $30613/1500 \approx 20.4087$，相差约 **4%**。对角度敏感的应用不可忽略。

各级齿数：
| 级数 | 主动→从动 | 减速比 |
| --- | --- | --- |
| 第一级 | 电机轴(1) → 从动轮(12) | $1/12$ |
| 第二~四级 | 主动(22) → 从动(10) | $11/5$（每级） |
| 第五级 | 主动(23) → 输出轴(1) | $23/1$ |

$$
R = \frac{1}{12} \times \left(\frac{11}{5}\right)^3 \times \frac{23}{1} = \frac{30613}{1500}
$$

代码中推荐保留分数形式常量，避免浮点累积误差：
```c
#define ENC_TO_DEG_NUM  (1500.0f * 360.0f)
#define ENC_TO_DEG_DEN  (22.0f * 30613.0f)
```

## 4. M 法与 T 法测速对比

编码器输出的是阶梯信号，只在边沿跳变，不能直接求导，必须用数字测速算法。

| 维度 | M 法（测频） | T 法（测周） |
| --- | --- | --- |
| 原理 | 固定 $\Delta T$，统计脉冲数 $M$ | 固定 $M=1$，测脉冲宽度 $T$ |
| 公式 | $\omega = M / \Delta T$ | $\omega = 1 / T$ |
| 相对误差 | $\approx 1/M$ | $\approx \Delta t / T$ |
| 高速表现 | 好（$M$ 大，误差小） | 差（$T$ 小，误差大） |
| 低速表现 | 差（$M$ 常为 0，误差 100%） | 好（$T$ 大，误差小） |

平衡车轮胎每秒只转几转，编码器 1 ms 内的脉冲很少。**T 法在低速下误差小，自然适合；M 法在低速下不可用。**

## 5. T 法 HAL 实现：64 位微秒时钟

### 5.1 TIM2 配置

实现 T 法需要一个高精度时间基准，用 TIM2 实现微秒级计数：

| 参数 | 值 |
| --- | --- |
| 时钟源 | Internal Clock, 72 MHz |
| PSC | 71 → 1 MHz 计数频率（1 μs/计数） |
| Period | `0xFFFFFFFF`（32 位满量程） |
| 溢出周期 | $2^{32} / 10^6 \approx 4295$ 秒 ≈ 71.6 分钟 |

### 5.2 64 位时间戳

TIM2 每 1 μs 计数一次，32 位计数器约 71.6 分钟溢出一次。溢出中断中累加 64 位变量，合成永不溢出的全局时间戳：

```c
volatile uint64_t micros_64 = 0;

uint64_t get_micro_seconds(void) {
    uint32_t hi1, hi2, lo;
    do {
        hi1 = (uint32_t)(micros_64 >> 32);
        lo  = __HAL_TIM_GET_COUNTER(&htim2);
        hi2 = (uint32_t)(micros_64 >> 32);
    } while (hi1 != hi2);    // 期间若溢出中断发生则重试
    return ((uint64_t)hi2 << 32) | lo;
}

void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim) {
    if (htim->Instance == TIM2)
        micros_64 += 0x100000000ULL;
}
```

在 `main()` 中启动：`HAL_TIM_Base_Start_IT(&htim2)`。

### 5.3 EXTI 中断回调

```c
static volatile int64_t  encoder_L   = 0;
static volatile int8_t   direction_L = 1;   // ±1: 正常方向, ±2: 换向中
static volatile uint64_t T0_L        = 0;   // 最近边沿时刻
static volatile uint64_t T1_L        = 0;   // 上上次边沿时刻

void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin) {
    if (GPIO_Pin == GPIO_PIN_14) {          // 左电机 A 相
        uint64_t now = get_micro_seconds();
        T1_L = T0_L;  T0_L = now;

        uint8_t A = HAL_GPIO_ReadPin(GPIOB, GPIO_PIN_14);
        uint8_t B = HAL_GPIO_ReadPin(GPIOB, GPIO_PIN_15);
        int8_t new_dir;
        if (A == GPIO_PIN_SET) {
            new_dir = (B == GPIO_PIN_RESET) ? 1 : -1;
        } else {
            new_dir = (B == GPIO_PIN_SET)   ? 1 : -1;
        }

        if (new_dir == 1) encoder_L++; else encoder_L--;

        // 换向检测：符号变化 → 标记为 ±2
        if (direction_L * new_dir < 0)
            direction_L = (new_dir == 1) ? 2 : -2;
        else
            direction_L = new_dir;
    }
    // 右电机 (PB3) 同理
}
```

### 5.4 速度计算公式

轮胎角速度（度/秒）：
$$
\omega = \frac{\text{direction}}{T} \times \frac{1500 \times 360}{22 \times 30613}
$$

其中 $T$ 是相邻边沿时间间隔（秒），`direction` 为 +1（正转）或 -1（反转）。

## 6. 三大缺陷修复

T 法直接实现有三个典型工程缺陷，必须逐一修复。

### 6.1 停止不归零

**现象**：电机停止后速度卡在最后一个非零值。

**根因**：T 法滞后一个完整周期。电机停止后 T0/T1 不再更新，速度函数始终用最后一个完成周期计算。

**修复**：取历史周期和当前未完成时间的较大值作为预测周期：
```c
uint64_t last_period  = t0_cp - t1_cp;
uint64_t current_elap = now - t0_cp;
uint64_t T_pred = (last_period > current_elap) ? last_period : current_elap;
```
匀速时 `now - T0` 与 `T0 - T1` 基本相等，预测值等于正常周期；减速或停止时 `now - T0` 持续增大，速度平滑降至 0。

### 6.2 换向尖峰

**现象**：正反转切换时出现绝对值极大的毛刺。

**根因**：机械死区产生极窄脉冲，$T$ 极小，$\omega = 1/T$ 爆炸。

**修复**：换向时将方向标记为 `±2`（见 5.3 节），速度函数检测到 `±2` 直接返回 0，下一个正常脉冲恢复 `±1`。
```c
if (dir_cp == 2 || dir_cp == -2) return 0.0f;
```

### 6.3 随机毛刺（数据竞争）

**现象**：平稳运行时偶尔跳变到接近 0 后恢复。

**根因**：主循环读取 `T0` 时，中断更新了 `T0` 和 `T1`，主循环拿到新旧混合数据，无符号减法下溢产生天文数字。

**修复**：临界区保护——关闭中断后原子化拷贝，开启中断后用局部副本运算：
```c
__disable_irq();
int8_t   dir_cp = direction_L;
uint64_t t0_cp  = T0_L;
uint64_t t1_cp  = T1_L;
__enable_irq();
// 后续只用局部变量
```

### 6.4 优化版速度函数

```c
float app_encoder_get_speed_L(void) {
    __disable_irq();
    int8_t   dir_cp = direction_L;
    uint64_t t0_cp  = T0_L;
    uint64_t t1_cp  = T1_L;
    __enable_irq();

    if (dir_cp == 2 || dir_cp == -2) return 0.0f;
    if (t0_cp == 0 || t1_cp == 0) return 0.0f;

    uint64_t now = get_micro_seconds();
    uint64_t last_period  = t0_cp - t1_cp;
    uint64_t current_elap = now - t0_cp;
    uint64_t T_pred = (last_period > current_elap) ? last_period : current_elap;
    if (T_pred == 0) return 0.0f;

    float omega = (float)dir_cp * 1e6f / (float)T_pred;
    omega *= (1500.0f * 360.0f) / (22.0f * 30613.0f);
    return omega;
}
```

## 7. 定时器编码器模式：另一种实现

D153C 驱动库提供了不同的测速方法——使用定时器的 **编码器模式**（Encoder Mode）。

### 7.1 原理

TIM2/TIM4 配置为编码器模式，A/B 相接定时器通道。定时器硬件自动根据相位差增减计数值，上层只需固定周期调用采样函数：

```c
void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim) {
    static uint32_t div = 0;
    if (htim->Instance == TIM1) {         // 1 ms 基准中断
        if (++div >= 10) {                // 每 10 ms 采样一次
            div = 0;
            d153c_sample(D153C_MOTOR_A, 10.0f);
            d153c_sample(D153C_MOTOR_B, 10.0f);
        }
    }
}
```

定时器编码器模式下，输出轴一圈对应的计数：
$$
PPR \times MULTIPLE \times REDUCTION = 13 \times 4 \times 30 = 1560
$$

| 参数 | 数值 | 含义 |
| --- | --- | --- |
| `PPR` | 13 | 电机轴每转，编码器产生 13 个脉冲 |
| `MULTIPLE` | 4 | 编码器模式按 A/B 相四倍频计数 |
| `REDUCTION` | 30 | 减速比 30:1 |

换算为速度（r/s）：
$$
r/s = \text{delta} \times \frac{1000}{1560 \times dt_{ms}}
$$

10 ms 采样时简化为 $\text{delta} / 15.6$。

### 7.2 两套参数的口径差异

> 1560（定时器编码器模式）与 449（EXTI+T 法）的差异源于 PPR 口径不同：
> - 1560 来自"13 对磁极 × 4 倍频 × 30 减速比"，是硬件四倍频的完整计数
> - 449 来自"22 边沿/电机轴圈 × 30613/1500 减速比"，仅用 A 相双边沿，未四倍频
>
> 两套参数分别对应各自方案的计数粒度，不可混用。

### 7.3 与 EXTI + T 法对比

| 维度 | EXTI + T 法 | 定时器编码器模式 |
| --- | --- | --- |
| 硬件资源 | EXTI 线 + TIM2 时钟 | TIM2/TIM4 编码器模式 |
| 低速精度 | 高（T 法特性） | 中（依赖固定周期采样） |
| 实现复杂度 | 需手动处理缺陷修复 | 硬件自动计数，上层简单 |
| 灵活性 | 可精细控制采样策略 | 固定周期，响应滞后固定 |
| D153C 接口 | `app_encoder_get_speed()` | `d153c_sample()` + `d153c_rps()` |

两种方案均可用于速度反馈。**EXTI+T 法低速更精确，编码器模式实现更简单。**

### 7.4 为什么固定采样周期必须用硬件定时器

```c
// 错误写法：采样周期不可靠
while (1) {
    d153c_sample(D153C_MOTOR_A, 10.0f);
    HAL_Delay(10);
}
```

`HAL_Delay(10)` 只保证"至少延 10 ms"，但循环中还包括 `d153c_sample()` 和其他代码的执行耗时。最终采样间隔不稳定，算出的速度必然抖动。

对于 EXTI+T 法，采样由边沿事件驱动（每次中断记录时刻），不存在此问题。但使用定时器编码器模式时，固定周期采样是核心依赖，必须用硬件定时器保证。

## 8. 接口封装与方向符号

### 8.1 测速接口最小集

```c
void  encoder_sample(int id, float dt_ms);  // 固定周期采样
float encoder_get_rps(int id);              // 每秒转数
float encoder_get_angle(int id);            // 累计角度（度）
int32_t encoder_get_delta(int id);          // 最近周期增量
```

### 8.2 方向符号一致性

两个修正接口解决的问题不同：

```text
invert_motor   = 电机物理方向与预期相反
invert_encoder = 编码器速度符号与实际运动方向相反
```

判断方法：让电机正转（`duty > 0`），查看 `encoder_get_delta()` 正负：
- delta > 0 → 正确，无需修正
- delta < 0 → 调用 `invert_encoder` 取反

## 9. 测试验证标准

通过串口将速度数据发送到上位机（如 VOFA+），采样和发送频率解耦：

| 测试项 | 通过标准 |
| --- | --- |
| **零速归零** | 拨动轮胎后松开，速度平滑降至 0，不卡常数 |
| **过零平滑** | 快速来回拨动，波形过零点无尖峰 |
| **长期稳定** | 连续运行数分钟，无随机跳变毛刺 |
| **低速抖动** | 占空比 10% 时，速度波动 < ±15% |
| **阶跃响应** | 占空比从 0→50% 突变，速度 1 秒内稳定 |

> 采样频率建议 1 kHz（定时器中断中调用 `encoder_sample()`），串口上报使用 DMA，频率 100 Hz，避免阻塞控制环。

## 10. 易错点速查

| 现象 | 优先检查项 |
| --- | --- |
| **计数一直为 0** | 编码器 A/B 接线？共地？`SYS` → `Serial Wire` 释放了 PB3/PB4？ |
| **方向反了** | `invert_encoder` 配置错误？A/B 相接线反了？ |
| **速度不归零** | 是否用了 $T_{\text{pred}}$ 预测周期？ |
| **过零尖峰** | 是否用了 `±2` 换向屏蔽？ |
| **随机毛刺** | 速度函数中是否加了 `__disable_irq` 临界区？ |
| **数值偏大/偏小** | `PPR` / `MULTIPLE` / `REDUCTION` / `dt_ms` 参数是否正确？ |

```text
编码器计数差 delta → 除以 449（输出轴圈数）→ 除以边沿时间间隔 → r/s → 角度系数 → °/s
```

```text

```

```text

```

## 12. 小结与实践任务

### 核心结论

1. 编码器测速本质是从离散脉冲重建连续速度
2. **T 法**天然适合平衡车低速工况，M 法不适用
3. T 法三大缺陷必须修复：**停止不归零**（预测周期）、**换向尖峰**（标记屏蔽）、**随机毛刺**（临界区保护）
4. 减速比标称值不可信，实测得 $30613/1500 \approx 20.4087$
5. d153c 库的定时器编码器模式实现更简单，但低速精度略低
