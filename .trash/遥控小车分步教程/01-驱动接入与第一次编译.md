# 01 驱动接入与第一次编译

本步只确认电机驱动、蓝牙驱动和 CubeMX 生成代码能够一起编译，不让小车运动。

## 1.1 项目需要的业务驱动

最终工程只保留两组业务驱动：

```text
Core/Inc/d153c_motor.h
Core/Src/d153c_motor.c

Core/Inc/bluetooth_serial.h
Core/Src/bluetooth_serial.c
```

不再需要测速、PID、MPU6050、OLED 和字库文件。

电机驱动负责：

```text
启动 TIM3_CH1、TIM3_CH2 PWM
设置 PB12~PB15 电机方向
接收 -1000..1000 的有符号 PWM 命令
提供方向反相、滑行停止和刹车接口
```

蓝牙驱动负责：

```text
通过 USART1 单字节中断接收
识别 [ 和 ] 包围的数据包
把包内容保存到 Bluetooth_RxPacket
接收完成后置位 Bluetooth_RxFlag
```

## 1.2 CMake 业务源文件

根目录 `CMakeLists.txt` 中的业务源文件应为：

```cmake
target_sources(${CMAKE_PROJECT_NAME} PRIVATE
    Core/Src/bluetooth_serial.c
    Core/Src/d153c_motor.c
)
```

`Core/Inc` 已由 CubeMX 生成的 CMake 配置加入头文件搜索路径，不需要再次添加。

CubeMX 生成部分只应包含：

```text
main.c
gpio.c
tim.c
usart.c
stm32f1xx_it.c
stm32f1xx_hal_msp.c
```

其中 `tim.c` 只配置 TIM3，`stm32f1xx_it.c` 只保留 USART1 外设中断入口。

## 1.3 第一次编译

在项目根目录执行：

```powershell
cmake --preset Debug
cmake --build --preset Debug
```

编译成功后应生成：

```text
build/Debug/Car.elf
build/Debug/Car.map
```

## 1.4 常见编译问题

### 找不到 `d153c_motor.h`

确认文件位于：

```text
Core/Inc/d153c_motor.h
```

并确认生成的 CMake 配置包含：

```cmake
${CMAKE_CURRENT_SOURCE_DIR}/../../Core/Inc
```

### 找不到 `bluetooth_serial.h`

检查 `Core/Inc/bluetooth_serial.h` 是否存在，并重新执行配置命令：

```powershell
cmake --preset Debug
```

### `HAL_UART_RxCpltCallback` 重复定义

`bluetooth_serial.c` 已实现这个 HAL 回调，并转发给蓝牙接收状态机。不要再在 `main.c` 中定义同名函数。

### 仍然尝试编译已删除模块

如果错误中还出现：

```text
pid.c
d153c_speed_t.c
mpu6050.c
oled.c
font.c
i2c.c
```

说明 CMake 缓存仍使用旧源文件列表。重新执行：

```powershell
cmake --preset Debug
cmake --build --preset Debug
```

