# 03 蓝牙开环遥控

本步完成最终功能：手机发送摇杆包，STM32 直接计算左右轮 PWM。没有编码器反馈，也不做 PID。

控制关系为：

```text
左摇杆纵向 -> 前进、后退
右摇杆横向 -> 左转、右转
500 ms 无有效命令 -> 自动停车
```

## 3.1 蓝牙接线

| 功能 | STM32 引脚 |
|---|---|
| USART1_TX | PA9 |
| USART1_RX | PA10 |
| 波特率 | 9600 |

常见蓝牙串口模块接线：

```text
蓝牙 TXD -> STM32 PA10
蓝牙 RXD -> STM32 PA9
蓝牙 GND -> STM32 GND
蓝牙 VCC -> 按模块要求连接 3.3 V 或 5 V
```

TX 和 RX 必须交叉连接。先确认模块的电平和供电要求，不要默认所有模块的 RX 引脚都能直接承受 5 V。

## 3.2 数据包格式

蓝牙驱动以 `[` 作为开始、`]` 作为结束。手机端发送：

```text
[joystick,left_x,left_y,right_x,right_y]
```

例如：

```text
[joystick,0,100,0,0]   前进
[joystick,0,-100,0,0]  后退
[joystick,0,0,-100,0]  左转
[joystick,0,0,100,0]   右转
[joystick,0,0,0,0]     停止
```

程序会把摇杆值限制到 `-100..100`，并拒绝字段不完整或带有多余字符的数据包。无效包不会刷新失联计时。

## 3.3 控制参数

`Core/Src/main.c` 中使用：

```c
#define CAR_OPEN_DUTY             320
#define CAR_TURN_DUTY             280
#define CAR_JOYSTICK_DEAD_ZONE    8
#define CAR_COMMAND_TIMEOUT_MS    500U
```

含义如下：

| 参数 | 含义 |
|---|---|
| `CAR_OPEN_DUTY` | 摇杆满幅前进或后退时的基础 PWM |
| `CAR_TURN_DUTY` | 摇杆满幅转向时的差速 PWM |
| `CAR_JOYSTICK_DEAD_ZONE` | 回中死区，避免摇杆零点抖动 |
| `CAR_COMMAND_TIMEOUT_MS` | 失联停车时间 |

初次落地测试可以把前进和转向 PWM 调到 `250..350`。参数只决定开环输出，不代表实际转速。

## 3.4 初始化

在 `USER CODE BEGIN Includes` 中包含：

```c
#include "bluetooth_serial.h"
#include "d153c_motor.h"
#include <stdbool.h>
#include <stdio.h>
```

在 `USER CODE BEGIN 2` 中初始化：

```c
d153c_motor_init();

/* 根据第 02 步结果保留需要的反相设置 */
/* d153c_motor_invert(D153C_MOTOR_A, true); */
/* d153c_motor_invert(D153C_MOTOR_B, true); */

BluetoothSerial_Init(&huart1);
BluetoothSerial_SendString("BT ready\r\n");
car_last_command_ms = HAL_GetTick();
```

`BluetoothSerial_Init()` 会启动 USART1 单字节中断接收。不要在其他文件重复定义 `HAL_UART_RxCpltCallback()`。

## 3.5 开环差速计算

程序先应用死区，再计算：

```text
speed = left_y  * CAR_OPEN_DUTY / 100
turn  = right_x * CAR_TURN_DUTY / 100

left_duty  = speed + turn
right_duty = speed - turn
```

因此右摇杆向右时，左轮输出增加、右轮输出减少，小车向右转。混合前进和转向时，两轮会得到不同 PWM。

最终输出限制在 `-1000..1000`，与 D153C 电机驱动接口一致。

## 3.6 主循环处理

主循环中的核心逻辑为：

```c
if (Bluetooth_RxFlag != 0U)
{
  if (Car_ApplyCommand(Bluetooth_RxPacket))
  {
    car_last_command_ms = HAL_GetTick();
    car_command_active = true;
  }

  Bluetooth_RxFlag = 0U;
}

if (car_command_active &&
    ((uint32_t)(HAL_GetTick() - car_last_command_ms) >=
     CAR_COMMAND_TIMEOUT_MS))
{
  Car_Stop();
  car_command_active = false;
}
```

先解析数据，再清接收标志。标志保持为 1 时，蓝牙中断不会开始覆盖当前数据包。

超时判断采用无符号减法，即使 `HAL_GetTick()` 回绕也能正常工作。失联停车只是通信安全保护，不是闭环控制。

## 3.7 第一次测试

先把小车架起来：

1. 烧录程序并连接蓝牙。
2. 检查串口是否收到 `BT ready`。
3. 发送 `[joystick,0,0,0,0]`，两轮应停止。
4. 发送 `[joystick,0,100,0,0]`，两轮应向前转。
5. 发送 `[joystick,0,-100,0,0]`，两轮应向后转。
6. 发送 `[joystick,0,0,-100,0]`，应原地左转。
7. 发送 `[joystick,0,0,100,0]`，应原地右转。
8. 持续发送前进命令后停止发送，约 500 ms 后两轮应自动停止。

## 3.8 常见问题

### 完全收不到命令

依次检查：

1. 蓝牙模块是否已连接。
2. 双方波特率是否都是 9600。
3. PA9、PA10 是否交叉接线。
4. 手机是否发送完整方括号。
5. `BluetoothSerial_Init(&huart1)` 是否执行。
6. USART1 全局中断是否在 CubeMX 中启用。

### 收到命令但电机不动

先回到第 02 步确认电机开环测试。蓝牙链路正常不能证明电机供电、PWM 和方向线正常。

### 前后方向反了

使用：

```c
d153c_motor_invert(D153C_MOTOR_A, true);
d153c_motor_invert(D153C_MOTOR_B, true);
```

只反一侧时，仅对对应电机调用。

### 左右转方向反了

先检查 A/B 是否分别对应左轮和右轮。如果对应关系正确，再检查手机端 `right_x` 的正方向是否与文档一致；必要时把 `turn_duty` 取反。

### 小车每隔一会儿自动停止

这是 500 ms 失联保护生效。摇杆小程序需要在按住或持续操纵期间周期发送数据，建议发送周期小于 100 ms。

### 松手后仍缓慢移动

增大死区，例如：

```c
#define CAR_JOYSTICK_DEAD_ZONE 12
```

不要用过大的死区，否则低速操纵会变得生硬。

## 3.9 最终验收

最终项目应满足：

```text
手机可连续控制前进、后退和转向
摇杆回中立即停车
断开蓝牙或停止发送后 500 ms 自动停车
工程可正常编译和链接
未使用编码器、PID、MPU6050、OLED 或额外定时器
```

完成以上检查后，蓝牙开环遥控小车即实现完毕。
