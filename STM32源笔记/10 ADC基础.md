## 1. 基本原理

模拟信号是连续电压，数字系统需要离散数值参与运算。STM32F103 内置 **12-bit 逐次逼近型 ADC**。

| 参数 | 值 |
|------|-----|
| 分辨率 | 12 bit |
| 数字输出范围 | 0 ~ 4095（$2^{12} - 1$） |
| 参考电压 | 通常为 Vref（约 3.3V） |

### 1.1 逐次逼近（SAR）原理

"逐次逼近"的含义是：ADC 内部用**二分法比较**来确定输入电压的数字值。

```text
例：Vref = 3.3V，输入 = 2.1V，12-bit SAR 的工作过程：

第 1 步：猜中间值 → DAC 输出 1.65V → 比较 2.1 > 1.65 → bit11 = 1，保留上半区
第 2 步：猜 2.475V → DAC 输出 2.475V → 比较 2.1 < 2.475 → bit10 = 0，回到下半区
第 3 步：猜 2.0625V → DAC 输出 2.0625V → 比较 2.1 > 2.0625 → bit9 = 1
    ...
第 12 步：得到 12 位二进制结果
```

每个猜测周期需要一个时钟。猜的次数 = 分辨率位数。所以：
- 12-bit ADC 至少需要 12 个时钟完成一次转换
- 时钟频率越高，转换越快，但精度和稳定性会下降

STM32F103 的 ADC 时钟上限约为 **14 MHz**，单次最短转换时间约 1μs。

### 1.2 电压换算公式

$$V_{in} \approx \frac{ADC\_value}{4095} \times V_{ref}$$

示例：若 ADC 读到 2048，Vref = 3.3V，则：

$$V_{in} \approx \frac{2048}{4095} \times 3.3 \approx 1.65V$$

## 2. 逐次逼近机制

```text
输入电压 → 采样保持 → 与内部 DAC 比较（逐次二分逼近） → 输出 12 位结果
```

### 2.1 采样时间与转换时间

- **采样时间**：对输入电压采样并保持的时间，由 `SMP` 寄存器控制
- **转换时间**：完成 12 次比较所需时间，由 ADC 时钟决定

总时间 = 采样时间 + 转换时间（12 个时钟周期）。若采样时间长（如多通道时内部通道需要更长采样时间），总时间会显著增加。

## 3. 单次转换模式

```c
HAL_ADCEx_Calibration_Start(&hadc);           // 校准（上电后执行一次）
HAL_ADC_Start(&hadc);                          // 启动转换
HAL_ADC_PollForConversion(&hadc, timeout);     // 等待转换完成
uint16_t value = HAL_ADC_GetValue(&hadc);      // 读取结果
```

- 每次启动只转换一次，转换完后停
- 需要再次调用 `HAL_ADC_Start()` 才能开始下一次

---

## 4. 连续转换模式

```c
HAL_ADC_Start(&hadc);                          // 启动后持续转换
while (1)
{
    if (HAL_ADC_PollForConversion(&hadc, timeout) == HAL_OK)
    {
        uint16_t value = HAL_ADC_GetValue(&hadc);
        // 使用 value
    }
}
```

- 启动后自动连续转换
- 每次转换完成结果自动更新到 DR 寄存器
- 程序在需要时随时读取最新值

---

## 5. 上电校准

```c
HAL_ADCEx_Calibration_Start(&hadc);
```

- 校准补偿 ADC 内部的偏移误差
- 每次上电后执行一次即可，复位后需要重新校准
- 不校准可能导致测量结果整体偏移

## 7. 高频易错点

1. **ADC 时钟超限**。超过 14MHz 时转换结果可能不稳定或误差变大。

2. **上电后没有校准**。ADC 偏移误差未补偿，测量值整体偏大或偏小。

3. **参考电压不准**。Vref 不稳定时，换算结果也波动。必要时用内部 Vrefint 修正。

4. **连续模式未理解"自动更新"的含义**。DR 不断被覆盖，多通道时必须用 DMA。

5. **忘记 `HAL_ADC_GetValue()` 前等转换完成**。读到的可能是上一次的旧值。

---

## 8. 一页速记

### 核心公式
```text
V_in ≈ ADC_value / 4095 × Vref
```

### 典型流程
```text
校准 → 启动转换 → 等待完成 → 读取结果
```

### 核心 API
| 函数 | 用途 |
|------|------|
| `HAL_ADCEx_Calibration_Start()` | 上电校准 |
| `HAL_ADC_Start()` | 启动转换 |
| `HAL_ADC_PollForConversion()` | 等待完成 |
| `HAL_ADC_GetValue()` | 读取结果 |

### 最重要的一句话
> ADC 不是"把电压读成数字"，而是在精度、速度、通道数之间做权衡——采样时间、时钟频率和转换模式的选择直接影响这三个维度。
