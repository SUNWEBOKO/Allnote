# 02. GPIO 输入与按键：从轮询到非阻塞事件模型

> 本节重点：理解 GPIO 输入模式下单片机如何读取外部电平，掌握上拉电路原理与多种按键消抖方案，从简单的阻塞式控制到工程化的非阻塞事件模型，并能根据项目需求选择合适的按键逻辑实现方式。

## 1. GPIO 输入与输出的区别

| 模式 | 方向 | 本质 |
| --- | --- | --- |
| 输出 | STM32 → 外部器件 | 主动对外送出高低电平 |
| 输入 | 外部电路 → STM32 | 读取外部电路给引脚的电平 |

输出关注“引脚送出去什么”，输入关注“引脚读到什么”。

---

## 2. 上拉按键电路分析

### 2.1 电路结构

开发板 K1 按键的典型电路：

text

3.3V ──\[上拉电阻\]── PB12 ──\[按键\]── GND

### 2.2 电平状态

| 按键状态 | 电路路径 | PB12 电平 |
| --- | --- | --- |
| 松开 | 3.3V 通过上拉电阻到 PB12 | 高电平 |
| 按下 | PB12 被直接拉到 GND | 低电平 |

text

K1 松开 → PB12 = 高电平
K1 按下 → PB12 = 低电平

这种“默认高、按下变低”的结构称为 **上拉输入**。

---

## 3. 按键消抖

### 3.1 为什么需要消抖

机械按键在接通和断开的瞬间，触点会在几毫秒内多次弹跳，产生一连串高低脉冲。对单片机而言，这足以让程序误判为“按了很多次”。

text

实际按下一次：\_\_\_\_\_\_\_\_/\\/\\/\\\_/\\/\\\_\_/~~\\\_\_\_\_\_\_\_\_\_\_\_
                   按下    弹跳    稳定

### 3.2 常用消抖手段

| 方式 | 做法 | 特点 |
| --- | --- | --- |
| 硬件消抖 | 并联电容 | 开发板已集成，简单可靠 |
| 软件延时消抖 | 检测到变化后延时再确认 | 实现简单，但会阻塞主循环 |
| 状态机消抖 | 基于定时中断的采样与事件队列 | 非阻塞，适合多任务系统 |

#### 3.2.1 硬件消抖

在按键两端并联一个小电容，利用电容两端电压不能突变的特性滤除抖动。大多数开发板已在按键电路上集成电容，因此在没有特殊要求时，可以直接认为硬件消抖已足够消除绝大部分毛刺。

#### 3.2.2 软件延时消抖

最简单的软件消抖方式：检测到电平变化后，延时 20 ms 再次读取，若电平一致则确认按键动作。

c

if (HAL\_GPIO\_ReadPin(KEY\_Port, KEY\_Pin) \== GPIO\_PIN\_RESET)
{
    HAL\_Delay(20);                 // 延时 20ms，等待抖动过去
    if (HAL\_GPIO\_ReadPin(KEY\_Port, KEY\_Pin) \== GPIO\_PIN\_RESET)
    {
        // 确认按键确实按下，执行相应动作
    }
}

**阻塞问题**：`HAL_Delay(20)` 会完全占用 CPU 长达 20 ms。在这段时间内，主循环无法刷新 OLED、响应串口数据或处理其他传感器。如果主循环本来需要频繁刷新显示，任何阻塞延时都会导致明显的卡顿或数据丢失。因此，软件延时消抖只适合功能极其单一、对实时性几乎无要求的简单实验。

#### 3.2.3 状态机消抖与非阻塞事件模型

为了在多任务环境下实现可靠消抖且不阻塞主循环，通常采用 **定时中断采样 + 状态比较 + 事件队列** 的架构。这一方案将按键检测拆分为三个职责清晰的层次：

| 层级 | 函数 | 调用位置 | 职责 |
| --- | --- | --- | --- |
| 第 1 层 | `Key_GetState()` | 仅被 `Key_Tick()` 调用 | 读取 GPIO 当前电平，返回按键编号 |
| 第 2 层 | `Key_Tick()` | 定时器中断回调 | 定时采样、消抖、检测松手事件 |
| 第 3 层 | `Key_GetNum()` | 主循环 | 消费按键事件，一次消费一个 |

**第 1 层：读取硬件状态**

c

uint8\_t Key\_GetState(void)
{
    if (HAL\_GPIO\_ReadPin(GPIOB, GPIO\_PIN\_1) \== GPIO\_PIN\_RESET)  return 1;
    if (HAL\_GPIO\_ReadPin(GPIOA, GPIO\_PIN\_6) \== GPIO\_PIN\_RESET)  return 2;
    if (HAL\_GPIO\_ReadPin(GPIOA, GPIO\_PIN\_4) \== GPIO\_PIN\_RESET)  return 3;
    return 0;   // 无按键按下
}

`Key_GetState()` 只根据当前 GPIO 电平返回按键编号，不做任何延时或判断。它为上层提供纯粹的“此刻硬件状态”。

**第 2 层：定时采样与事件检测**

c

static uint8\_t count;
static uint8\_t Cur\_State, Pre\_State;
static uint8\_t Key\_Num;               // 事件缓冲区
void Key\_Tick(void)
{
    count++;
    if (count \>= 20)                  // 约 20ms 判断一次
    {
        count \= 0;
        Pre\_State \= Cur\_State;        // 记录上一次的状态
        Cur\_State \= Key\_GetState();   // 读取当前状态
        // 检测松手事件：上次有键按下 且 本次无键按下
        if (Pre\_State != 0 && Cur\_State \== 0)
        {
            Key\_Num \= Pre\_State;      // 产生一个按键事件
        }
    }
}

`Key_Tick()` 需要被一个周期为 1 ms 的定时器中断调用（见第 4 节的定时器配置）。每进入一次中断，内部计数加 1，每 20 次（即 20 ms）进行一次完整的消抖判断。20 ms 的间隔正好跨过机械触点的弹跳期，因此连续两次采样若出现 `(有键 → 无键)` 的变化，就认为发生了一次稳定、完整的“按下然后松开”动作，并把按键编号存入 `Key_Num`。

**为什么检测松手而不是按下？**  
如果检测按下事件，长按期间每一次 20 ms 采样都会被认为是一次新的按下，导致事件重复触发。而检测松手则天然保证：无论按键被按住多久，只在整个按压过程结束时产生唯一一个事件，行为更符合用户预期。

**第 3 层：消费事件**

c

uint8\_t Key\_GetNum(void)
{
    if (Key\_Num != 0)
    {
        uint8\_t temp \= Key\_Num;
        Key\_Num \= 0;            // 读取后立即清零，保证事件一次性消费
        return temp;
    }
    return 0;                   // 无事件
}

`Key_GetNum()` 在主循环中被频繁调用。有事件时，它返回按键编号并立刻将事件清除；没有事件时，它立即返回 0，不做任何等待。这种“非阻塞”特性使得按键处理可以和 OLED 刷新、串口通信等自由交替执行，互不拖累。

## 4. CubeMX 配置

| 对象 | 配置 | 说明 |
| --- | --- | --- |
| LED 引脚 | `GPIO_Output` | 推挽输出，控制小灯 |
| 按键引脚 PB12 等 | `GPIO_Input` | 普通输入，依赖外部上拉电路 |
| 定时器（用于非阻塞消抖） | 内部时钟，PSC=71，ARR=999 | 产生 1ms 更新中断，供 `Key_Tick()` 使用 |

定时器配置详解：  
当系统时钟为 72 MHz 时：
$$
f_{\text{cnt}} = \frac{72\ \mathrm{MHz}}{71 + 1} = 1\ \mathrm{MHz}
\quad (1\ \text{计数} = 1\ \mu\mathrm{s})
$$

$$
T = \frac{999 + 1}{1\ \mathrm{MHz}} = 1\ \mathrm{ms}
$$

设置预分频器 PSC = 71 使计数器时钟为 1 MHz；设置自动重装载值 ARR = 999 使定时器每 1000 个计数周期（即 1 ms）产生一次更新中断。在中断回调中调用 `Key_Tick()` 即可。

## 5. 核心读取函数

`HAL_GPIO_ReadPin()` 是最基础的 GPIO 输入读取函数：

c

if (HAL\_GPIO\_ReadPin(K1\_GPIO\_Port, K1\_Pin) \== GPIO\_PIN\_RESET)
{
    // 按键按下（低电平）
}
else
{
    // 按键松开（高电平）
}

| 返回值 | 含义 |
| --- | --- |
| `GPIO_PIN_SET` | 引脚为高电平 |
| `GPIO_PIN_RESET` | 引脚为低电平 |

无论是简单的延时消抖还是非阻塞事件模型，底层最终都是通过这个函数获取引脚电平。

## 6. 两种典型按键逻辑

### 6.1 按住亮，松开灭（电平控制型）

当前电平直接决定 LED 状态：

c

if (HAL\_GPIO\_ReadPin(K1\_GPIO\_Port, K1\_Pin) \== GPIO\_PIN\_RESET)
{
    HAL\_GPIO\_WritePin(LED\_GPIO\_Port, LED\_Pin, GPIO\_PIN\_SET);   // 按下 → 亮
}
else
{
    HAL\_GPIO\_WritePin(LED\_GPIO\_Port, LED\_Pin, GPIO\_PIN\_RESET); // 松开 → 灭
}

此逻辑不关心消抖细节，即使有抖动，LED 仅短暂闪烁，肉眼难以察觉。

### 6.2 按一次翻转一次（边沿检测型）

边沿检测型逻辑要求“每次完整按下-松开”只翻转一次 LED 状态，长按不能反复翻转。

#### 6.2.1 阻塞式边沿检测（教学版）

最简单的实现是在检测到按下后，执行动作并原地等待松手：

c

if (HAL\_GPIO\_ReadPin(K2\_GPIO\_Port, K2\_Pin) \== GPIO\_PIN\_RESET)
{
    HAL\_GPIO\_TogglePin(LED\_GPIO\_Port, LED\_Pin);                // 翻转一次
    while (HAL\_GPIO\_ReadPin(K2\_GPIO\_Port, K2\_Pin) \== GPIO\_PIN\_RESET)
    {
        // 死等松手，防止长按连翻
    }
}

这段代码在功能上是正确的，适合初学理解“边沿”与“电平”的区别。但 `while` 循环会完全阻塞主循环，在按键被按住期间，显示、通信等一切任务都会停止。因此，在 OLED 刷新、串口通信等稍复杂场景中，这种阻塞式等待将酿成严重卡顿。

#### 6.2.2 非阻塞事件驱动式边沿检测（工程推荐）

配合第 3 节中实现的非阻塞消抖模块，翻转逻辑可以改写为极其轻量的形式：

c

uint8\_t key \= Key\_GetNum();        // 尝试消费一个按键事件
if (key \== 2)                       // 假设按键2用于翻转
{
    HAL\_GPIO\_TogglePin(LED\_GPIO\_Port, LED\_Pin);
}

执行逻辑：

- `Key_Tick()` 在中断中默默完成了消抖和松手检测，并在按键松开瞬间置位 `Key_Num`。
- 主循环调用 `Key_GetNum()` 拿到事件后翻转 LED，随即继续刷新 OLED 或处理其他任务。
- 无论按键被按住多久，只产生一个事件，完全不需要 `while` 等松手循环。

这样，按键处理与显示刷新完全解耦，主循环每一轮都能全速运行，是对阻塞版本的根本性改进。

### 6.3 三种实现方式对比

| 方式 | 检测对象 | 消抖与等待方式 | 对主循环影响 | 适用场景 |
| --- | --- | --- | --- | --- |
| 电平控制型 | 当前电平 | 无需特殊消抖 | 无阻塞 | 按住亮/灭 |
| 阻塞边沿检测 | 电平变化动作 | `while` 死等松手 | **完全阻塞** | 极简实验 |
| 非阻塞事件驱动 | 松手事件 | 定时中断消抖 + `Key_GetNum()` 消费 | **无阻塞** | 含显示、通信的工程 |

## 7. 上拉与下拉的判断

| 电路类型 | 默认电平 | 触发后电平 | 典型场景 |
| --- | --- | --- | --- |
| 上拉输入 | 高电平 | 低电平（按下拉低） | 按键接 GND |
| 下拉输入 | 低电平 | 高电平（按下拉高） | 按键接 VCC |

**关键习惯**：不要靠记忆判断电平，始终对照原理图分析两种状态。

## 8. 高频易错点

1. **按键逻辑反了**。先查原理图确认是上拉还是下拉，再决定逻辑高低，不要上来就改代码。
2. **按一次翻转多次**。阻塞版本通常是没做 `while` 等待松手；非阻塞版本则检查是否误用了电平判断而非 `Key_GetNum()` 事件。
3. **阻塞消抖导致系统卡顿**。`HAL_Delay(20)` 或 `while` 循环会让主循环停止，OLED 和串口都会受到影响，务必用非阻塞方案替代。
4. **忘记启动定时器中断**。`Key_Tick()` 依赖定时器中断，若 TIM 未使能或中断回调未调用 `Key_Tick()`，将永远收不到按键事件。
5. **采样周期与消抖阈值不匹配**。例如定时器配置为 2ms 中断一次，而 `Key_Tick()` 里仍然写 `count >= 20`，消抖时长就变成了 40ms。修改定时器周期时务必同步调整阈值。
6. **在中断中调用 `Key_GetNum()`**。`Key_GetNum()` 设计为在主循环中使用；中断服务函数只应调用 `Key_Tick()`，两者不能混淆。
7. **多个地方同时消费事件**。`Key_Num` 是一次性的，如果多个任务或页面都调用 `Key_GetNum()`，只有一个能拿到事件。项目中通常只由一个统一的按键处理任务消费事件，或采用事件广播机制。

## 9. 一页速记

### 核心概念

text

GPIO 输入 = 读外部电路给引脚的电平
上拉输入：默认高，按下变低
消抖的核心思路：
  延时法   → 按下后等一会儿再确认
  状态机法 → 由定时中断周期性采样，在稳定后捕捉状态变化

### 非阻塞消抖三层职责

text

Key\_GetState()  →  读 GPIO 电平（瞬时状态）
Key\_Tick()      →  定时采样 + 消抖 + 松手检测（在中断中运行）
Key\_GetNum()    →  消费按键事件（主循环中，不阻塞）

### 核心 API

| 函数 | 用途 |
| --- | --- |
| `HAL_GPIO_ReadPin(port, pin)` | 读取引脚电平 |
| `Key_GetNum()` | 获取一次松手按键事件（无事件返回0） |

### 按键逻辑口诀

text

按住亮、松开灭        → 直接读电平
按一次翻转一次（简单版） → 检测电平变化 + while 等松手
按一次翻转一次（工程版） → 调用 Key\_GetNum() 消费事件

### 最重要的一句话

> 写按键程序时，永远先确认原理图的电路结构；在含显示、通信的系统中，务必用非阻塞事件模型替代任何形式的阻塞延时或死等。
