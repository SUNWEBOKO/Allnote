## 1. 增量式编码器基本原理

### 1.1 AB 相信号

编码器在旋转时输出两路相位差约 90° 的脉冲信号：

| 旋转方向 | A 相与 B 相相位关系 |
|----------|-------------------|
| 顺时针 | A 领先 B 约 90° |
| 逆时针 | B 领先 A 约 90° |

- **脉冲数量** → 相对角位移
- **相位先后** → 旋转方向

## 2. 软件中断方案 vs 定时器编码器模式

| 对比项 | GPIO 中断（软件方案） | 定时器编码器模式（硬件方案） |
|--------|---------------------|---------------------------|
| 实现方式 | A 相边沿触发中断，在回调中读 B 相电平 | AB 相直接接入定时器 CH1/CH2 |
| 计数方式 | 软件维护变量 | 硬件自动更新 CNT |
| 高速性能 | 差，中断频繁易丢脉冲 | 好，硬件级实时计数 |
| CPU 占用 | 高 | 极低 |
| 方向判定 | 手动判断 | 硬件自动 |

## 3. 定时器编码器模式原理

通用/高级定时器内置编码器模式，核心思想是：**用硬件实时判断 AB 相的相位关系，自动决定 CNT 的增减方向，不需要软件介入。**

### 3.1 硬件解码路径

编码器模式复用了定时器输入通道的现有路径：

```text
A 相 → CH1 → 输入滤波 → 边沿检测 → TI1FP1 ─┐
                                               ├─ 编码器逻辑 → CNT ±1
B 相 → CH2 → 输入滤波 → 边沿检测 → TI2FP2 ─┘
```

输入滤波去除机械抖动产生的毛刺，边沿检测判断有效触发沿，编码器逻辑比较两路信号的相位先后：

- A 领先 B 90°（顺时针）→ **CNT 递增**
- B 领先 A 90°（逆时针）→ **CNT 递减**

这个比较在**每个有效边沿**发生，因此硬件解码的实时性远高于软件中断方案。

### 3.2 计数精度与边沿配置

| 配置 | 每个脉冲周期的计数 | 分辨率 |
|------|-----------------|--------|
| 单沿（仅 TI1FP1 或 TI2FP2） | 1 个计数 | 1 倍 |
| 双沿（TI1FP1 + TI2FP2） | 2 个计数 | 2 倍 |
| 四倍频（双沿 × 双通道） | 4 个计数 | 4 倍 |

选择依据：需要更高分辨率时用更多边沿，但计数值变化速度也成倍增加，要和应用层的映射范围匹配。

### 3.3 与输入捕获的关系

编码器模式本质上利用了和输入捕获相同的输入路径（滤波 + 边沿检测），区别在于：

- 输入捕获：**捕获边沿时刻的 CNT 值到 CCR**
- 编码器模式：**边沿直接驱动 CNT 加减**

## 5. HAL 代码实现

### 5.1 启动编码器

```c
HAL_TIM_Encoder_Start(&htim1, TIM_CHANNEL_ALL);
```

### 5.2 读取计数

```c
int32_t count = (int32_t)__HAL_TIM_GET_COUNTER(&htim1);
```

### 5.3 常用处理

```c
// 计数映射到目标范围（如亮度 0~100）
int32_t brightness = count % 101;
if (brightness < 0) brightness = 0;

// 方向反转（交换极性或手动处理）
// 方法1: 修改 CH1 极性
// 方法2: count = -count;  // 软件取反
```

## 6. 实战功能拆解

| 功能 | 实现思路 |
|------|----------|
| 旋钮调节亮度 | 读取 `CNT` → 映射到 `0~100` → 写入 PWM CCR |
| OLED 显示 | I2C 驱动 OLED，实时显示计数值或进度条 |
| 旋钮按键切换 | 检测编码器按键按下 → 切换 PWM 通道（灯色） |
| 通道切换 | 保存当前通道索引 → 停止旧通道 → 启动新通道 |

## 7. 高频易错点

1. **每格计数异常（翻倍/四倍）**。检查编码器模式中的边沿计数配置（单沿/双沿/双通道各沿）。

2. **方向反了**。调整 CH1 或 CH2 的输入极性即可镜像方向。

3. **计数溢出回卷**。16 位计数器最大 65535，业务层需要做限幅或 32 位扩展。

4. **亮度范围不稳**。统一计数到 PWM 的映射关系，在边界处同步回写计数器。

5. **AB 相引脚接反**。交换 A、B 输入，方向会反向。

## 8. 一页速记

### 核心概念
```text
AB 相 → 方向判定 + 脉冲计数
相位差 90° → 顺时针或逆时针
```

### 方案选择
```text
低速可软件中断 → 高速优先硬件编码器模式
```

### 核心 API
| 函数 | 用途 |
|------|------|
| `HAL_TIM_Encoder_Start(tim, CHANNEL_ALL)` | 启动编码器模式 |
| `__HAL_TIM_GET_COUNTER(tim)` | 读取当前计数值 |

### 最重要的一句话
> 编码器模式的核心不是"计数"，而是"硬件自动判定方向并完成加减计数"，把 CPU 从频繁中断中解放出来。
