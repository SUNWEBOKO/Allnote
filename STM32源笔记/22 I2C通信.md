## 1. I2C 总线概览

I2C（Inter-Integrated Circuit）是一种**同步、半双工、多主机**串行通信总线：

| 特性 | 说明 |
|------|------|
| 信号线 | `SCL`（时钟）+ `SDA`（数据） |
| 拓扑 | 总线式，多设备共享两根线 |
| 通信方式 | 主机驱动时钟，从机应答 |
| 速度 | 标准 100kHz，快速 400kHz |
| 最大设备数 | 受 7 位地址限制（理论 128 个） |

**关键：所有设备都挂在同一对 SCL/SDA 上，通过地址区分。同一时间只有一个主机控制总线。**

### 1.1 上拉电阻

```text
SCL ───[上拉电阻]─── VDD
SDA ───[上拉电阻]─── VDD
```

SCL 和 SDA 都是**开漏**输出。空闲时靠上拉电阻拉到高电平，设备通过拉低来表达信号。正因如此，多个设备可以安全地共享同一对线——谁先拉低谁就抢到总线。

### 1.2 硬件连接示意

```text
STM32(I2C1)               MPU6050              OLED
  SCL ──┬───────────────────┬───────────────────┬────
  SDA ──┴───────────────────┴───────────────────┴────
```

SCL 和 SDA 各需要一只上拉电阻（约 4.7kΩ），部分开发板已集成。

## 2. I2C 协议要素

### 2.1 空闲状态

SCL = 高电平，SDA = 高电平（上拉电阻维持）。

### 2.2 起始条件（Start Condition）

```text
SCL 为高时，SDA 从高切换到低
```

SDA 的下降沿告诉所有从机：总线开始传输了。

### 2.3 停止条件（Stop Condition）

```text
SCL 为高时，SDA 从低切换到高
```

SDA 的上升沿告诉所有从机：总线传输结束。

### 2.4 数据传输

每个时钟脉冲（SCL 跳变）传输一个数据位：

- SCL 为低时，发送方改变 SDA 电平
- SCL 为高时，接收方读取 SDA 电平
- **高位先行**（MSB first）

### 2.5 地址字节

起始条件后，主机发送的第一个字节：

```text
bit 7 ~ bit 1：7 位从机地址
bit 0：R/W（0 = 写，1 = 读）
```

**关键概念**：
- I2C 总线使用 7 位地址
- HAL 在 `I2C_Mem_Read` 等函数中需要**左移 1 位的 8 位形式**
- 例如 MPU6050 地址 `0x68` 左移后为 `0xD0`（写入）或 `0xD1`（读取）

### 2.6 ACK/NACK

每传输完一个字节，接收方在第 9 个 SCL 脉冲周期拉低 SDA 表示应答（ACK）。

| 应答 | SDA 电平 | 含义 |
|------|----------|------|
| ACK | 低 | 字节接收正常，请继续 |
| NACK | 高 | 接收异常或传输结束 |

## 3. 典型 I2C 读写序列

### 3.1 主机写一个字节到从机寄存器

```text
起始 → 从机地址+W → ACK → 寄存器地址 → ACK → 数据字节 → ACK → 停止
```

### 3.2 主机从从机读一个字节

需要先指定寄存器地址，再重新发起读取：

```text
起始 → 从机地址+W → ACK → 寄存器地址 → ACK → 停止
起始 → 从机地址+R → ACK → （主机读一字节）→ NACK → 停止
```

这个"先写寄存器地址，再读数据"的模式是最常见的 I2C 传感器/外设操作方式。

## 4. STM32 I2C 外设

### 4.1 I2C 模块特性

STM32F103 的 I2C 外设支持：

| 特性 | 说明 |
|------|------|
| 工作模式 | 主机/从机均可 |
| 速度 | 标准（100kHz）或快速（400kHz） |
| 7/10 位地址 | 均支持 |
| 事件中断 | 可配置的传输事件中断 |

### 4.2 CubeMX 配置步骤

| 步骤 | 操作 |
|------|------|
| 1 | 选择 I2C 外设（如 I2C1） |
| 2 | 模式选 `I2C` |
| 3 | 在 Parameter Settings 中设速度（100kHz 或 400kHz） |
| 4 | 在 GPIO Settings 确认 SCL/SDA 引脚 |
| 5 | 保存生成代码 |

配置要点：

| 参数 | 典型值 | 说明 |
|------|--------|------|
| Timing | `Standard Mode` | 标准 100kHz |
| Clock No Stretch | Disable | 允许从机时钟拉伸（大多数传感器需要） |
| Address | 7-bit | 从机模式才需要配 |

### 4.3 I2C 与 GPIO 的复用关系

I2C 引脚通常是**复用开漏输出**：

```text
I2C1_SCL → PB6 (AF开漏)
I2C1_SDA → PB7 (AF开漏)
```

在 CubeMX 中选中 I2C 模式后，引脚会自动配置为复用开漏，不需要手动修改。

## 5. HAL I2C API

### 5.1 最常用的两个函数

| 函数 | 用途 |
|------|------|
| `HAL_I2C_Mem_Write(hi2c, devAddr, memAddr, memAddrSize, pData, len, timeout)` | 写从机寄存器 |
| `HAL_I2C_Mem_Read(hi2c, devAddr, memAddr, memAddrSize, pData, len, timeout)` | 读从机寄存器 |

参数说明：

- `devAddr`：从机地址的 8 位形式（7 位地址左移 1 位）
- `memAddr`：从机内部的寄存器地址
- `memAddrSize`：常为 `I2C_MEMADD_SIZE_8BIT`（8 位寄存器地址）
- `pData`：数据缓冲区指针
- `len`：要传输的字节数
- `timeout`：超时时间（ms）

### 5.2 其他常用函数

| 函数 | 场景 |
|------|------|
| `HAL_I2C_Master_Transmit(hi2c, addr, data, len, timeout)` | 直接发数据，不指定寄存器地址 |
| `HAL_I2C_Master_Receive(hi2c, addr, data, len, timeout)` | 直接读数据，不指定寄存器地址 |
| `HAL_I2C_IsDeviceReady(hi2c, addr, trials, timeout)` | 检测从机是否在线（试多次） |

### 5.3 超时与错误处理

所有 HAL I2C 函数返回 `HAL_StatusTypeDef`：

| 返回值 | 含义 | 常见原因 |
|--------|------|----------|
| `HAL_OK` | 传输成功 | — |
| `HAL_ERROR` | 参数错误 | 指针为 NULL |
| `HAL_BUSY` | 总线忙 | 上次传输未完成 |
| `HAL_TIMEOUT` | 超时 | 从机无响应 / SCL 被拉低 |

**I2C 通信失败时先检查**：

1. 上拉电阻是否安装
2. SCL/SDA 引脚连接是否正确
3. 从机地址是否匹配（含左移）
4. 时钟速率是否过高

## 6. I2C vs SPI 对比

| 对比项 | I2C | SPI |
|--------|-----|-----|
| 线数 | 2（SCL + SDA） | 4（SCLK + MOSI + MISO + CS） |
| 通信方式 | 半双工 | 全双工 |
| 从机选择 | 地址 | 片选（CS）线 |
| 速度 | 100k~400kHz | 可达数 MHz~数十 MHz |
| 总线设备数 | 理论 128 个 | 受 GPIO 片选限制 |
| 适用场景 | 传感器、小屏配置、低速外设 | Flash、高速数据采集、显示刷新 |

选择建议：

- 需要多设备共享总线、引脚紧张 → **I2C**
- 需要高速数据传输 → **SPI**
- MPU6050 和 OLED 都属于低速设备，I2C 是合理选择

## 7. 高频易错点

1. **地址没有左移**。HAL 函数需要 8 位地址形式，`0x68` 要写成 `(0x68 << 1)`。

2. **I2C 引脚不是复用开漏**。CubeMX 选了 I2C 模式后就自动配好了，不要手动改成推挽输出。

3. **上拉电阻缺失**。没有上拉电阻时 SCL/SDA 电平不确定，通信完全无法工作。

4. **时钟频率过高**。400kHz 以上时需谨慎，总线上电容和走线长度都会影响信号质量。

5. **忘处理 HAL_BUSY**。I2C 总线异常挂起后，后续传输全失败。可尝试重新初始化外设或硬件复位。

6. **SCL 时钟拉伸导致超时**。某些从机在内部处理时会拉低 SCL 等待，如果 `Clock No Stretch` 关闭，主机会以为总线异常。

7. **总线锁死**。通信过程中断电或复位可能导致 SDA 被拉死。解决办法：硬件复位或时钟 SCL 脉冲恢复。

## 8. 一页速记

### I2C 信号序列
```text
写：起始 → 地址+W → ACK → 寄存器 → ACK → 数据 → ACK → 停止
读：起始 → 地址+W → ACK → 寄存器 → ACK → 停止 → 起始 → 地址+R → ACK → 数据 → NACK → 停止
```

### 配置链路
```text
CubeMX 选 I2C → 配速度 → 确认引脚 → 生成代码 → HAL 函数读写
```

### 排查顺序
```text
上拉电阻 → 引脚连接 → 地址与左移 → 时钟频率 → 总线锁死
```

### 核心 API
| 函数 | 用途 |
|------|------|
| `HAL_I2C_Mem_Write(hi2c, addr, reg, 8BIT, buf, len, tout)` | 写从机寄存器 |
| `HAL_I2C_Mem_Read(hi2c, addr, reg, 8BIT, buf, len, tout)` | 读从机寄存器 |
| `HAL_I2C_IsDeviceReady(hi2c, addr, trials, tout)` | 检测从机在线 |

### 最重要的一句话
> I2C 的核心是"地址寻址 + 开漏总线"——地址让多设备共用一对线，开漏让多设备安全争用总线，两者缺一不可。
