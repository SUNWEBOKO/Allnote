# 21. SPI 总线：Flash 读写与掉电记忆

> 本节重点：理解 SPI 四线全双工通信机制与主机配置，掌握 W25Q64 的读、写、擦除流程与驱动库设计思路。

---

## 本节核心问题

这节重点不是背 SPI 名词，而是把一条实验链路串起来：

> STM32 作为 SPI 主机，通过 W25Q64 保存 LED 状态，实现掉电记忆。

复习时抓住 5 件事：

1. SPI 的 4 根线分别做什么。
2. SPI 为什么是“时钟驱动的全双工通信”。
3. 主从两端必须匹配哪些通信参数。
4. STM32 如何把 `SPI1` 配成主机模式。
5. W25Q64 的读、写、擦除流程为什么要按固定顺序执行。

---

## 二、知识主线

SPI（Serial Peripheral Interface，串行外设接口）是一种**同步串行通信总线**，常用于 MCU 与外设之间的高速、短距离通信。

典型结构：

- **主机 Master**：通常是 STM32，负责发起通信、提供时钟、控制片选。
- **从机 Slave**：通常是 Flash、传感器、屏幕等外设，被主机选中后参与通信。

典型特点：

- 速度快，适合板级短距离连接。
- 全双工，发送和接收同时发生。
- 接线简单，但一主多从时每个从机需要独立片选。

---

## 三、核心概念

### 1. 四根信号线

| 信号线 | 方向（相对主机） | 作用 |
|---|---|---|
| `MOSI` | 主机输出 | Master Output Slave Input，主发从收 |
| `MISO` | 主机输入 | Master Input Slave Output，主收从发 |
| `SCK` | 主机输出 | Serial Clock，主机提供通信时钟 |
| `NSS/CS` | 主机输出 | 片选信号，通常低电平有效 |

一主多从时：

- `MOSI`、`MISO`、`SCK` 可以共用。
- 每个从机必须有独立 `NSS/CS`。
- 选中哪个从机，就把哪个从机的 `CS` 拉低。

### 2. 全双工本质

SPI 的关键句：**时钟一来，收发同时发生。**

因此：

- 发送数据时，主机也会同时收到数据，只是可能不用。
- 接收数据时，主机也必须发送占位数据，用来产生时钟。
- 所谓 `Receive` 并不是“主机什么都不发”。

这也是读 Flash 时必须发送 dummy byte 的根本原因。

### 3. 通信前必须对齐的参数

主从两端参数不一致，通信就会错位或无响应。

| 参数 | 复习重点 |
|---|---|
| 波特率 | 本质是 `SCK` 频率，不能超过外设和线路能力 |
| 位序 | 常见为 `MSB First`，以芯片手册为准 |
| 数据位长度 | Flash 常按字节通信，通常用 `8 bit` |
| `CPOL` | 时钟空闲时的电平：0 低、1 高 |
| `CPHA` | 在第几个时钟边沿采样：0 第一个、1 第二个 |

### 4. SPI 四种模式

`CPOL` 和 `CPHA` 组合成 4 种模式：

| 模式 | CPOL | CPHA |
|---|---:|---:|
| Mode 0 | 0 | 0 |
| Mode 1 | 0 | 1 |
| Mode 2 | 1 | 0 |
| Mode 3 | 1 | 1 |

本实验中的 W25Q64 支持 **Mode 0** 和 **Mode 3**，实验选择 **Mode 3**。

## 四、STM32 SPI1 配置

本实验中 STM32 作为主机，使用 `SPI1`。

推荐记忆配置：

- `Full Duplex Master`：全双工主机模式。
- `NSS` 使用软件控制。
- 数据位：`8 bit`。
- 位序：`MSB First`。
- 模式：`Mode 3`。
- 波特率：按 W25Q64 允许频率和板级稳定性选择分频。

常见引脚：

| STM32 引脚 | SPI 功能 |
|---|---|
| `PA5` | `SCK` |
| `PA6` | `MISO` |
| `PA7` | `MOSI` |
| `PA4` | 普通 GPIO，手动控制 `NSS/CS` |

软件片选的基本时序：

1. 通信前：拉低 `CS`。
2. 发送命令、地址或数据。
3. 通信结束：拉高 `CS`。

常用 HAL 接口：

| 函数 | 用途 | 记忆点 |
|---|---|---|
| `HAL_SPI_Transmit()` | 发命令、地址、写入数据 | 只关心发送，收到的数据丢弃 |
| `HAL_SPI_Receive()` | 接收数据 | 底层仍要发占位数据产生时钟 |
| `HAL_SPI_TransmitReceive()` | 边发边收 | 最符合 SPI 全双工本质 |

## 五、从 SPI 角度看 W25Q64 读写

### 1. 引脚对应

| W25Q64 引脚 | SPI 含义 |
|---|---|
| `DI` | `MOSI` |
| `DO` | `MISO` |
| `CLK` | `SCK` |
| `CS` | `NSS/CS` |
| `VCC` | 电源 |
| `GND` | 地 |

W25Q64 驱动本质上就是把每一次 Flash 操作拆成固定的 SPI 事务：

1. 拉低 `CS`，选中 Flash。
2. 通过 `MOSI` 发送命令码、地址或数据。
3. 需要读数据时，通过 `MISO` 接收返回值。
4. 拉高 `CS`，结束本次事务。

### 2. 容量与边界

复习只需先抓住：

- W25Q64 容量：**64 Mbit = 8 MB**。
- **页 Page = 256 Byte**，写入通常按页编程。
- **扇区 Sector = 4 KB**，擦除通常按扇区执行。
- 地址是 24 位地址，发送顺序是：高字节 -> 中字节 -> 低字节。
- Flash 不能像 RAM 一样随意覆盖，写之前通常要先擦除目标区域。

驱动里用 `W25Q64_IsValidRange()` 检查地址范围，避免读写超过 8 MB 边界。

### 3. 常用命令码与状态位

| 命令/状态 | 值 | 含义 |
|---|---|---|
| `WRITE_ENABLE` | `0x06` | 写使能，擦除/编程前必须先发 |
| `READ_STATUS_REG1` | `0x05` | 读取状态寄存器 1 |
| `PAGE_PROGRAM` | `0x02` | 页编程，写入数据 |
| `READ_DATA` | `0x03` | 从指定地址读数据 |
| `SECTOR_ERASE` | `0x20` | 擦除 4 KB 扇区 |
| `JEDEC_ID` | `0x9F` | 读取芯片 ID |
| `RELEASE_POWER_DOWN` | `0xAB` | 释放掉电模式 |
| `BUSY` 位 | `0x01` | Flash 忙，正在擦除/编程 |
| `WEL` 位 | `0x02` | 写使能锁存已置位 |

记忆重点：

- `0x06` 不是写数据，而是允许后续写/擦除。
- `0x05` 用来查忙状态，判断 Flash 能不能继续操作。
- `0x02` 只能把数据写进当前页范围，不能自动跨页。
- `0x03` 是普通读命令，读之前不用写使能。

注意：擦除和编程后都要等待 Flash 忙状态结束，再执行下一步。

## 六、驱动中的读写流程

这一部分按项目 `驱动库/W25Q64` 目录下的驱动理解。

### 1. 初始化：先确认芯片真的在线

`W25Q64_Init()` 做了 5 件事：

1. 保存 `SPI_HandleTypeDef`、`CS` 端口和 `CS` 引脚。
2. 先把 `CS` 拉高，让 Flash 处于未选中状态。
3. 发送 `0xAB`，释放掉电模式。
4. 读取 `JEDEC ID`，确认返回值是 `0xEF4017`。
5. 等待 Flash 不忙后，把 `ready` 标志置为 `1`。

复习时记住：**初始化不是只配置 SPI，还要通过读 ID 确认 Flash 可用。**

### 2. 发送地址：命令后跟 24 位地址

驱动用 `W25Q64_FillAddress()` 组织 4 字节命令：

```c
cmd[0] = opcode;
cmd[1] = address >> 16;
cmd[2] = address >> 8;
cmd[3] = address;
```

也就是：

> 命令码 -> 地址高 8 位 -> 地址中 8 位 -> 地址低 8 位

读、写、擦除只是在 `opcode` 上不同，地址发送格式相同。

### 3. 读数据：发读命令和地址，然后连续收

`W25Q64_Read()` 的流程：

1. 发送读命令 `0x03`。
2. 发送 24 位起始地址。
3. 保持 `CS` 为低，连续接收数据。
4. 接收完成后拉高 `CS`。

对应 SPI 事务：

```text
CS 拉低
MOSI: 0x03 + A23~A16 + A15~A8 + A7~A0
MISO: 连续返回 len 字节数据
CS 拉高
```

驱动细节：

- 读之前会先 `W25Q64_WaitBusy()`，确保 Flash 不忙。
- 长数据读取会按 `0xFFFF` 字节分块，因为 HAL SPI 的长度参数是 `uint16_t`。
- 读操作不需要 `WriteEnable()`。

### 4. 写使能：写/擦除前必须先打开 WEL

`W25Q64_WriteEnable()` 的流程：

1. 等待 Flash 不忙。
2. 拉低 `CS`。
3. 发送 `0x06`。
4. 拉高 `CS`。
5. 再读状态寄存器，确认 `WEL` 位已经置 1。

复习时不要把 `0x06` 当成形式步骤。没有 `WEL = 1`，后面的擦除和页编程不会生效。

### 5. 擦除：按扇区/块对齐地址

驱动支持多种擦除：

| 函数 | 命令 | 对齐大小 |
|---|---|---|
| `W25Q64_EraseSector()` | `0x20` | 4 KB |
| `W25Q64_EraseBlock32()` | `0x52` | 32 KB |
| `W25Q64_EraseBlock64()` | `0xD8` | 64 KB |
| `W25Q64_EraseChip()` | `0xC7` | 整片 |

以扇区擦除为例：

1. 地址先向下对齐到 4 KB 边界。
2. 发送写使能 `0x06`。
3. 发送擦除命令 `0x20 + 24 位地址`。
4. 等待 `BUSY` 位清零。

`W25Q64_EraseRange()` 会把起始地址向下对齐，把结束地址向上扩展到扇区边界，然后逐扇区擦除。

### 6. 写数据：只负责页编程，不自动擦除

这是驱动里最容易漏掉的一点：

> `W25Q64_Write()` 只负责跨页写入，不会自动擦除；写之前要先擦除目标扇区或目标范围。

内部流程：

1. 检查地址和长度是否越界。
2. 计算当前页还剩多少空间。
3. 把数据拆成不跨页的小块。
4. 每一块调用一次 `W25Q64_PageProgram()`。
5. 每次页编程内部都会：写使能 -> 发 `0x02 + 地址` -> 发数据 -> 等待忙结束。

页编程的 SPI 事务：

```text
CS 拉低
MOSI: 0x02 + A23~A16 + A15~A8 + A7~A0 + data...
CS 拉高
等待 BUSY 清零
```

为什么要拆页：

- W25Q64 页大小是 256 Byte。
- 页编程不能跨页边界。
- 如果地址不是页起始地址，本页可写空间会变少。

### 7. 一个完整写入闭环

如果要把 `led_state` 写到 `0x000000`，更贴近驱动的理解应是：

1. `W25Q64_EraseSector(&flash, 0x000000)`。
2. 等待驱动内部擦除完成。
3. `W25Q64_Write(&flash, 0x000000, &led_state, 1)`。
4. 驱动内部完成写使能、页编程和忙等待。

如果要读回来：

1. `W25Q64_Read(&flash, 0x000000, &led_state, 1)`。
2. 根据 `led_state` 恢复 LED。

## 七、高频易错点

1. **MOSI / MISO 接反**  
   `MOSI` 是主发从收，`MISO` 是主收从发。

2. **片选时序错误**  
   通信前拉低 `CS`，通信结束后拉高 `CS`。

3. **SPI 模式不匹配**  
   重点检查 `CPOL`、`CPHA`，本实验用 Mode 3。

4. **误以为接收时主机不用发数据**  
   SPI 接收必须靠主机发占位数据产生时钟。

5. **写 Flash 前忘记写使能**  
   没有 `0x06`，擦除和编程不会生效。

6. **写前不擦除**  
   `W25Q64_Write()` 不会自动擦除，目标区域通常要先擦除。

7. **不等待擦除/编程完成**  
   Flash 忙时继续操作，读写结果容易异常。

8. **页编程跨页**  
   W25Q64 一页是 256 Byte，页编程不能跨页，驱动会自动拆成多次 `PageProgram`。

9. **只发了 `0x06`，但没确认 `WEL`**  
   更稳的做法是发完写使能后读状态寄存器，确认 `WEL` 位已经置 1。

10. **按键不消抖**  
   一次按键可能被识别成多次切换。

11. **LED 亮灭逻辑写反**  
   板载 LED 常见低电平点亮，具体看开发板电路。

## 八、速记区

- **SPI 一句话**：主机提供时钟，用 `MOSI/MISO/SCK/CS` 完成高速同步串行通信。
- **四根线**：`MOSI` 主发从收，`MISO` 主收从发，`SCK` 主机给时钟，`CS` 拉低选中从机。
- **通信本质**：只要有时钟，发送和接收就同时发生。
- **模式判断**：`CPOL` 看空闲电平，`CPHA` 看第几个边沿采样。
- **本实验配置**：`SPI1 + Full Duplex Master + 8 bit + MSB First + Mode 3 + 软件 CS`。
- **Flash 读事务**：`CS` 拉低 -> `0x03 + 24 位地址` -> 连续接收 -> `CS` 拉高。
- **Flash 擦除事务**：写使能 -> 擦除命令 + 地址 -> 等待 `BUSY` 清零。
- **Flash 写事务**：写前先擦除；`W25Q64_Write()` 只做跨页页编程，不自动擦除。
- **实验闭环**：按钮切 LED -> 状态写 Flash -> 上电读 Flash -> 恢复 LED。
