# 23. MPU6050 / MPU6500 两种 MPU 与驱动用法

> 本节目标：分清 MPU6050 和 MPU6500 在当前驱动库里的共同点与差异，知道怎样初始化、怎样读取 raw/物理量数据，以及上层使用时最容易踩的坑。

---

## 本节核心问题

学完本节，需要能回答：

- MPU6050 和 MPU6500 都提供哪些六轴数据？这一节为什么不直接讲姿态角？
- 两套驱动在 API 风格上有哪些相同点？哪些差异必须分开记？
- `0x68/0x69` 地址、`WHO_AM_I` 和 HAL 左移地址之间是什么关系？
- raw 数据怎样换算成 `g`、`dps` 和温度？量程变化会影响哪些系数？
- 主循环、定时器任务和中断里分别更适合调用哪类读取接口？
- 当前单实例静态驱动写法有什么好处？什么时候会不够用？

## 1. 为什么这节改成一起讲

你现在驱动库里的 `MPU6050` 和 `MPU6500` 已经不是“完全不同的两套写法”，而是**接口风格几乎一致**的两套驱动：

- 都是 I2C 六轴 IMU
- 都支持自动探测 `0x68 / 0x69`
- 都提供 `Init / InitWithAddress / ReadAccelGyroRaw / ReadData`
- 都默认初始化为 `±4 g` 和 `±500 dps`
- 都是从 `0x3B` 连续读 14 字节拼出 `ax/ay/az/temp/gx/gy/gz`

所以这一节更适合讲成：

1. 两个芯片分别是什么。
2. 这两套驱动现在是怎么写的。
3. 在 STM32 工程里应该怎样使用。

把“原始数据怎样变成角度、为什么要做互补滤波”单独放到下一节，会更清楚。

---

## 2. 两个芯片先建立整体印象

MPU6050 和 MPU6500 本质上都属于六轴 IMU，内部都包含：

- 三轴加速度计：`ax`、`ay`、`az`
- 三轴陀螺仪：`gx`、`gy`、`gz`
- 温度传感器：`temp`

对上层程序来说，它们的共同任务都是：

```text
STM32 通过 I2C 访问芯片
-> 初始化寄存器
-> 读出六轴原始值
-> 再由上层做角度、滤波、控制
```

也就是说，这一节只解决“**怎么把数据读出来并正确使用驱动**”，不解决姿态解算。

---

## 3. 从你现在的驱动库看，两个芯片主要差别在哪

真正会影响你理解和使用的差别，主要只有下面这些。

| 项目 | MPU6050 | MPU6500 |
|---|---|---|
| `WHO_AM_I` 正常值 | `0x68` | `0x70` |
| 默认加速度量程 | `±4 g` | `±4 g` |
| 默认陀螺仪量程 | `±500 dps` | `±500 dps` |
| 默认采样分频 | `SMPLRT_DIV = 0x09` | `SMPLRT_DIV = 0x09` |
| 默认低通 | `CONFIG = 0x03` | `CONFIG = 0x03` |
| 额外加速度低通 | 无专门配置 | `ACCEL_CONFIG2 = 0x03` |
| 温度换算公式 | `raw / 340 + 36.53` | `raw / 333.87 + 21.0` |
| API 风格 | 与 MPU6500 基本同构 | 与 MPU6050 基本同构 |

可以先记一句：

```text
上层读法几乎一样；真正要分开的，是 WHO_AM_I、温度公式，以及 6500 多了一项加速度低通配置。
```

---

## 4. 当前驱动的总体风格

这两套驱动现在都采用**模块级单实例**写法，而不是早期那种“每个传感器一个 handle 结构体”的写法。

也就是说，驱动内部保存的是：

- 当前使用的 `I2C_HandleTypeDef *`
- 当前选中的器件地址
- 当前识别出的芯片类型
- 当前量程对应的换算系数

例如两套驱动里都有类似这样的静态变量：

```c
static I2C_HandleTypeDef *mpu_i2c = NULL;
static uint8_t mpu_address = (0x68U << 1);
static float accel_lsb_per_g = 8192.0f;
static float gyro_lsb_per_dps = 65.5f;
```

这意味着：

1. **初始化时只需要传 I2C 句柄**，不用自己先创建 handle 结构体。
2. **驱动默认按一个芯片实例来用**。
3. 如果你以后想在同一套驱动里同时挂两个同型号 MPU，这种写法就不适合直接复用，需要再改成多实例版本。

对当前课程和单板实验来说，这种写法更直接。

## 6. 初始化时到底做了什么

两套驱动的初始化主线基本一致：

1. 保存 I2C 句柄。
2. 自动探测 `0x68` 和 `0x69`。
3. 读取 `WHO_AM_I` 确认芯片身份。
4. 软复位。
5. 选择 PLL 时钟。
6. 配置低通、采样率分频、量程。

### 6.1 地址探测

`Init()` 会先探测：

```text
0x68 -> 0x69
```

如果你想明确指定地址，可以直接调用：

```c
MPU6050_InitWithAddress(&hi2c2, 0x68);
MPU6500_InitWithAddress(&hi2c2, 0x69);
```

注意这里传的是**7 位地址**：

- 正确：`0x68`、`0x69`
- 不要传：`0x68 << 1`

因为驱动内部已经会自动左移一位给 HAL。

### 6.2 身份检查

- MPU6050：读 `WHO_AM_I(0x75)` 应为 `0x68`
- MPU6500：读 `WHO_AM_I(0x75)` 应为 `0x70`

所以“地址上有设备响应”还不够，还要确认“这个设备是不是目标芯片”。

### 6.3 当前默认配置

| 配置项 | MPU6050 | MPU6500 | 作用 |
|---|---:|---:|---|
| 软复位 | `PWR_MGMT_1 = 0x80` | `PWR_MGMT_1 = 0x80` | 先复位芯片 |
| 时钟源 | `PWR_MGMT_1 = 0x01` | `PWR_MGMT_1 = 0x01` | 选 PLL 时钟 |
| 关闭待机轴 | `PWR_MGMT_2 = 0x00` | `PWR_MGMT_2 = 0x00` | 使能测量 |
| 数字低通 | `CONFIG = 0x03` | `CONFIG = 0x03` | 降低高频噪声 |
| 采样分频 | `SMPLRT_DIV = 0x09` | `SMPLRT_DIV = 0x09` | 常按约 `100 Hz` 理解 |
| 陀螺仪量程 | `±500 dps` | `±500 dps` | `65.5 LSB/(deg/s)` |
| 加速度量程 | `±4 g` | `±4 g` | `8192 LSB/g` |
| 加速度低通 | 无 | `ACCEL_CONFIG2 = 0x03` | 6500 多一步 |

所以现在这两套驱动在上层读数时，默认换算系数是一样的：

```text
加速度：8192 LSB/g
陀螺仪：65.5 LSB/(deg/s)
```

## 7. 数据结构是什么样

### 7.1 raw 结构体

两套驱动都提供了“14 字节原始数据拼好的结构体”：

```c
typedef struct
{
  int16_t accel_x;
  int16_t accel_y;
  int16_t accel_z;
  int16_t temp;
  int16_t gyro_x;
  int16_t gyro_y;
  int16_t gyro_z;
} MPUx_AccelGyroRaw;
```

这些字段还只是 raw，不是 `g`、`dps` 或摄氏度。

### 7.2 已换算物理量的结构体

```c
typedef struct
{
  float ax_g;
  float ay_g;
  float az_g;
  float temperature_c;
  float gx_dps;
  float gy_dps;
  float gz_dps;
} MPUx_Data;
```

如果你直接调用 `ReadData()`，驱动内部会按当前量程自动换算成：

- 加速度：`g`
- 温度：`℃`
- 陀螺仪：`deg/s`

这对后面做互补滤波会更方便。

## 8. 怎样读取数据

两套驱动都保留了两种使用层级。

### 8.1 方式一：读 raw，自己换算

适合：

- 想自己控制超时时间
- 想在定时器/中断里尽量缩短阻塞
- 想自己决定换算和滤波流程

#### MPU6050

```c
MPU6050_AccelGyroRaw raw;

if (MPU6050_ReadAccelGyroRaw(&raw, 100) == MPU6050_OK)
{
  float ax_g = (float)raw.accel_x / 8192.0f;
  float gy_dps = (float)raw.gyro_y / 65.5f;
}
```

#### MPU6500

```c
MPU6500_AccelGyroRaw raw;

if (MPU6500_ReadAccelGyroRaw(&raw, 100) == MPU6500_OK)
{
  float ax_g = (float)raw.accel_x / 8192.0f;
  float gy_dps = (float)raw.gyro_y / 65.5f;
}
```

### 8.2 方式二：直接读物理量

适合：

- 主循环或普通任务里读取
- 希望上层代码更短
- 后面要直接做角度、滤波、控制

#### MPU6050

```c
MPU6050_Data data;

if (MPU6050_ReadData(&data) == MPU6050_OK)
{
  // data.ax_g, data.ay_g, data.az_g
  // data.gx_dps, data.gy_dps, data.gz_dps
  // data.temperature_c
}
```

#### MPU6500

```c
MPU6500_Data data;

if (MPU6500_ReadData(&data) == MPU6500_OK)
{
  // data.ax_g, data.ay_g, data.az_g
  // data.gx_dps, data.gy_dps, data.gz_dps
  // data.temperature_c
}
```

注意：`ReadData()` 内部固定使用 `100 ms` 超时，所以**不适合直接放进高频中断**。

## 9. 两个芯片的最小使用流程

### 9.1 MPU6050

```c
if (MPU6050_Init(&hi2c2) != MPU6050_OK)
{
  // 初始化失败
}

MPU6050_Data data;
if (MPU6050_ReadData(&data) == MPU6050_OK)
{
  // 使用 data.ax_g / data.gy_dps 等
}
```

### 9.2 MPU6500

```c
if (MPU6500_Init(&hi2c2) != MPU6500_OK)
{
  // 初始化失败
}

MPU6500_Data data;
if (MPU6500_ReadData(&data) == MPU6500_OK)
{
  // 使用 data.ax_g / data.gy_dps 等
}
```

如果要指定地址：

```c
MPU6050_InitWithAddress(&hi2c2, 0x68);
MPU6500_InitWithAddress(&hi2c2, 0x68);
```

如果你在 1 ms 定时器里读 raw，可以把超时压短：

```c
MPU6500_AccelGyroRaw raw;
MPU6500_ReadAccelGyroRaw(&raw, 1);
```

MPU6050 同理。

## 10. `ReadData()` 内部到底怎样换算

### 10.1 当前默认量程下的换算

| 项目 | 默认量程 | 换算系数 |
|---|---|---:|
| 加速度 | `±4 g` | `8192 LSB/g` |
| 陀螺仪 | `±500 dps` | `65.5 LSB/(deg/s)` |

所以默认情况下：

```c
ax_g   = raw.accel_x / 8192.0f;
gy_dps = raw.gyro_y  / 65.5f;
```

### 10.2 温度公式不同

MPU6050：

```c
temperature_c = raw.temp / 340.0f + 36.53f;
```

MPU6500：

```c
temperature_c = raw.temp / 333.87f + 21.0f;
```

所以温度换算不能直接混用。

### 10.3 改量程后，`ReadData()` 会自动跟着变

只要你调用：

```c
MPU6050_SetAccelRange(...);
MPU6050_SetGyroRange(...);
```

或：

```c
MPU6500_SetAccelRange(...);
MPU6500_SetGyroRange(...);
```

驱动内部的 `accel_lsb_per_g`、`gyro_lsb_per_dps` 就会同步更新，后续 `ReadData()` 会按新量程换算。

但如果你自己在上层处理 raw，就必须同步改自己的除数。

## 11. 量程表要会查

| 加速度量程 | LSB/g | 陀螺仪量程 | LSB/(deg/s) |
|---|---:|---|---:|
| `±2 g` | `16384` | `±250 dps` | `131.0` |
| `±4 g` | `8192` | `±500 dps` | `65.5` |
| `±8 g` | `4096` | `±1000 dps` | `32.8` |
| `±16 g` | `2048` | `±2000 dps` | `16.4` |

这张表对 MPU6050 和 MPU6500 在当前驱动里都成立。

## 12. 调试时最常踩的坑

| 问题 | 原因 | 应对 |
|---|---|---|
| 初始化失败 | 地址传错，或 `AD0` 接法和实际地址不符 | 先确认是 `0x68` 还是 `0x69` |
| `InitWithAddress()` 传了 `0x68 << 1` | 驱动内部又左移了一次 | 只传 7 位地址 `0x68/0x69` |
| `WHO_AM_I` 不对 | 芯片型号认错，或读到别的设备 | 6050 应为 `0x68`，6500 应为 `0x70` |
| 上层公式比例不对 | 改了量程但没改 raw 换算系数 | 查量程表同步改除数 |
| 中断里偶尔卡顿 | `ReadData()` 内部超时太长 | 中断里优先用 `ReadAccelGyroRaw(..., 1)` |
| 温度明显不对 | 把 6050/6500 的温度公式混用了 | 按各自芯片公式换算 |
| 想同时挂两个同型号 MPU | 当前驱动是单实例静态写法 | 需要改成多实例驱动 |

## 13. 上层该怎样选读法

如果你只是想尽快拿到可用的 `g / dps` 数据，推荐：

```text
主循环 / 任务里 -> 用 ReadData()
```

如果你要自己掌控超时、做更细的实时调度，推荐：

```text
高频定时 / 中断里 -> 用 ReadAccelGyroRaw()
```

下一节讲互补滤波时，主线会优先使用 `ReadData()`，因为这样更容易把注意力放在“滤波逻辑”而不是“换算细节”上。

---

## 14. 一页速记

- MPU6050 和 MPU6500 在你当前驱动库里的 API 风格几乎一样。
- 两者都支持：自动探测 `0x68 / 0x69`、读 raw、读物理量、改量程。
- `InitWithAddress()` 传的是 **7 位地址**，不是左移后的地址。
- `WHO_AM_I`：MPU6050 是 `0x68`，MPU6500 是 `0x70`。
- 当前默认配置：`±4 g`、`±500 dps`、`SMPLRT_DIV = 0x09`、`CONFIG = 0x03`。
- 当前默认换算：`8192 LSB/g`、`65.5 LSB/(deg/s)`。
- MPU6500 比 MPU6050 多一步 `ACCEL_CONFIG2 = 0x03`。
- 温度公式不能混用：6050 是 `340 + 36.53`，6500 是 `333.87 + 21.0`。
- `ReadData()` 适合主循环；中断里更适合 `ReadAccelGyroRaw()`。
- 当前驱动是单实例静态写法，不是多实例 handle 版。
