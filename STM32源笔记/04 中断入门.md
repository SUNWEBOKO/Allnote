# 04. 中断入门：GPIO 外部中断与快速响应

> 本节重点：理解中断"打断当前任务、处理紧急事件、回来继续执行"的核心机制，掌握从轮询到外部中断的思维转变。

## 1. 什么叫中断

中断的核心机制：

> **CPU 正在执行主程序 → 紧急事件发生 → 暂停当前任务 → 跳去处理中断服务函数(ISR) → 处理完返回原位置继续执行。**

这个流程的关键在于：程序不需要主动去"查"事件有没有发生，事件自己会"通知"CPU。

```text
主程序：_________________被中断_______________恢复执行______
                            ↓
ISR:                        [紧急处理完成]
```

---

## 2. 轮询为什么会导致"按键失灵"

### 2.1 实验现象

- 红灯按固定周期闪烁（主循环有长 `HAL_Delay()`）
- 按键控制绿灯翻转
- 实际表现：按键"怎么按都不灵"

### 2.2 原因分析

```text
主循环长时间阻塞（HAL_Delay）
       ↓
按键检测窗口极短
       ↓
按键发生时程序大概率在延时中
       ↓
错过按键检测 → 看起来像失灵
```

核心问题：**轮询的检测时机完全由代码执行位置决定**，和事件发生的实际时间没有对应关系。

---

## 3. 中断 vs 轮询

| 对比项 | 轮询 | 中断 |
|--------|------|------|
| 检测时机 | 由代码执行位置决定 | 事件发生时立即触发 |
| CPU 占用 | 主循环一直占用 CPU 检查状态 | CPU 只在事件发生时短暂处理 |
| 实时性 | 差（取决于轮询频率） | 好（事件驱动） |
| 适合场景 | 频繁、可预测的事件 | 异步、偶发但需快速响应的事件 |

> 中断的核心价值不是"更高级"，而是**更及时**。

## 4. GPIO 外部中断的 CubeMX 配置

### 4.1 配置步骤

| 步骤 | 操作 |
|------|------|
| 1 | 将按键引脚（如 PB12）从 `GPIO_Input` 改为 `GPIO_EXTI12` |
| 2 | 在 GPIO 配置中确认触发边沿（上升沿/下降沿/双边沿） |
| 3 | 在 NVIC 页面勾选对应的 EXTI 中断线 |
| 4 | 保存工程并生成代码 |

### 4.2 配置变化

```text
配置前：PB12 → GPIO_Input（轮询读取）
配置后：PB12 → GPIO_EXTI12（中断触发）
```

生成代码后，工程会多出对应的中断处理框架文件。

## 5. 中断处理的代码结构

### 5.1 HAL 中断处理链路

```c
// 中断入口，HAL 自动生成
void EXTI15_10_IRQHandler(void)
{
    HAL_GPIO_EXTI_IRQHandler(PB12_Pin);  // HAL 分发
}

// 用户回调（覆盖此函数）
void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin)
{
    if (GPIO_Pin == PB12_Pin)
    {
        // 用户业务逻辑（翻转 LED、计数等）
    }
}
```

### 5.2 中断函数编写原则

| 原则 | 说明 |
|------|------|
| 尽量短小 | ISR 执行时长影响主程序响应 |
| 不放耗时操作 | 延时、打印、复杂计算不在 ISR 中执行 |
| 业务放回调 | `HAL_GPIO_EXTI_Callback()` 而不是直接改 `IRQHandler` |
| 必要时消抖 | 中断方式下按键抖动仍可能连触发 |

---

## 6. 外部中断适合的场景

| 适合 | 不适合 |
|------|--------|
| 按键触发类事件 | 主循环常规流程 |
| 外部信号边沿检测 | 高频周期性事件（用定时器轮询更合理） |
| 串口接收数据到达 | 大数据量传输（配合 DMA 更合理） |
| 偶发但需快速响应的异步事件 | 简单电平状态读取 |

---

## 7. 高频易错点

1. **中断里放 `HAL_Delay()`**。`HAL_Delay` 依赖 SysTick 中断，若中断优先级高于 SysTick，会导致死锁。

2. **中断里做大量计算或串口打印**。ISR 应尽快退出，重逻辑放主循环。

3. **忘记配置 NVIC**。GPIO 配了 EXTI 模式但没在 NVIC 页面勾选，中断不会触发。

4. **触发边沿选反**。按键是按下变低还是变高？边沿必须与实际电路一致。

5. **没有做消抖处理**。中断方式下按键抖动仍可能产生多次触发。

---

## 8. 一页速记

### 核心概念
```text
中断 = 异步事件通知机制
轮询问题：检测时机由代码位置决定，可能错过事件
中断优势：事件发生 → 立即响应
```

### 配置链路
```text
GPIO_EXTI → 配置边沿 → 勾选 NVIC → 写回调函数
```

### 代码结构
```c
// ISR 由 HAL 管理，用户只写回调：
void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin) { ... }
```

### 最重要的一句话
> 中断不是"更高级的编程技巧"，而是"让 CPU 在正确的时间做正确的事"的机制。
