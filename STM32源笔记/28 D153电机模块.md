# 28. D153 电机模块：TB6612 + MG513P30 驱动

这篇笔记按**上手顺序**来讲：先把 CubeMX 外设配好，再看电机驱动代码怎么写，最后解释测速、调车和排障。目标不是只会调用函数，而是知道每一步为什么这样配、代码背后到底在做什么。

> 本文默认沿用当前工程的约定：**TIM3 负责 PWM，TIM2 负责 A 电机编码器，TIM4 负责 B 电机编码器，TIM1 提供测速采样节拍**。如果你的工程分配不同，只需要把“外设职责”对应替换掉，原理不变。

## 知识主线

这一节其实只有一条主线：

```text
CubeMX 配外设
→ GPIO 控方向，PWM 控功率，编码器定时器负责计数
→ d153c_init() 启动这些外设
→ d153c_drive() 让电机转起来
→ d153c_sample() 在固定周期内读取增量并换算速度
→ 根据方向、增量、速度结果继续调车和排障
```

如果这条链路打通，这个模块就真正用明白了。

---

## 1. 先搞清楚你在控制什么

| 部件 | 作用 |
| --- | --- |
| **D153C / TB6612** | 电机驱动模块。负责把 MCU 的方向信号和 PWM 信号变成真正给电机的驱动电流。 |
| **MG513P30** | 带减速箱和霍尔编码器的直流减速电机。电机本体转得快，经过 **30:1** 减速后，输出轴转得更慢但力更大。 |
| **d153c 驱动库** | 对 GPIO、PWM、编码器读取做了一层封装，让你直接用函数控制两路电机。 |

系统的输入输出链路可以概括成两条：

```text
控制链路：你的代码 → d153c_drive() → IN1/IN2 + PWM → TB6612 → 电机转动
反馈链路：电机转动 → 编码器 A/B 相 → TIM 编码器计数 → d153c_sample() → delta / rps
```

所以你调这块板，本质上就是在同时处理两件事：

1. **怎么让电机按期望方向和力度转起来**
2. **怎么稳定地把“转了多少”换算成“转得多快”**

---

## 2. CubeMX 初始化应该怎么配

这一部分决定了后面的驱动代码能不能正常工作。对这个模块来说，至少要配四类资源：

- GPIO：控制方向引脚
- PWM 定时器：输出占空比
- 编码器定时器：读取 A/B 相计数
- 基准定时器：固定周期触发测速采样

### 2.1 GPIO：负责方向控制

TB6612 每路电机通常有两个方向控制引脚，例如 `IN1`、`IN2`。CubeMX 里要把它们配置为普通推挽输出。

它们的组合意义如下：

| IN1 | IN2 | 电机行为 |
| --- | --- | --- |
| 0 | 0 | 滑行停止 |
| 1 | 0 | 正转 |
| 0 | 1 | 反转 |
| 1 | 1 | 刹车 |

也就是说，**方向不是靠 PWM 本身决定的，而是靠 GPIO 的高低电平组合决定的**。PWM 只决定“给多大力”。

---

### 2.2 TIM3：负责 PWM 输出

驱动库默认使用 PWM 去控制电机功率。CubeMX 里需要：

- 打开 TIM3 的 PWM 输出通道
- 把对应通道映射到 D153C 模块的 PWM 输入脚
- 设置好预分频和自动重装值 `ARR`

当前笔记里的工程约定是：

- **TIM3 用作 PWM 定时器**
- `ARR = 3599`

驱动库内部会把 `d153c_drive()` 传入的 `-1000 ~ 1000` 占空比映射到 CCR：

$$
CCR = (ARR + 1) \times \frac{|duty|}{1000}
$$

例如 `duty = 300`，则：

$$
CCR = (3599 + 1) \times \frac{300}{1000} = 1080
$$

也就是约 30% 占空比。

> 这里用 `1000` 而不是 `100%`，只是为了方便整数比例换算。你可以把 `1000` 理解成“满功率”。

---

### 2.3 TIM2 / TIM4：负责编码器模式计数

两路电机都带编码器，所以至少要有两个定时器工作在**编码器模式**：

- **TIM2：A 电机编码器**
- **TIM4：B 电机编码器**

CubeMX 中要点：

- 选择 Encoder Mode
- 接入编码器 A/B 两相信号
- 让定时器随着编码器脉冲自动正反计数

配置好之后，定时器不会直接告诉你“速度”，它只会不断累积一个计数值。后面我们再用采样方法把这个计数差值换成转速。

---

### 2.4 TIM1：负责固定周期测速采样

测速最怕的不是公式复杂，而是**采样周期不稳**。

所以通常再拿一个基准定时器定时中断，专门负责“每隔固定时间采一次样”。当前工程的做法是：

- **TIM1 作为基础定时器**
- 定时器时钟 72 MHz
- 预分频 `PSC = 7199`，得到 10 kHz 计数频率
- 周期 `Period = 9`

于是：

$$
\frac{72\text{ MHz}}{7199 + 1} = 10\text{ kHz}
$$

再配合 `Period = 9`，就是每 10 个计数进一次中断，也就是 **1 ms 进入一次中断**。

后面如果每 10 次中断执行一次 `d153c_sample()`，就等于**每 10 ms 测一次速**。

---

### 2.5 CubeMX 生成后的初始化顺序

把外设都配好后，在 `main()` 里初始化的顺序建议固定下来：

```c
HAL_Init();
SystemClock_Config();

MX_GPIO_Init();
MX_TIM1_Init();   // 1ms 基准中断
MX_TIM2_Init();   // A 编码器
MX_TIM3_Init();   // PWM
MX_TIM4_Init();   // B 编码器

d153c_init();     // 启动 PWM 和编码器
HAL_TIM_Base_Start_IT(&htim1);
```

这个顺序的逻辑是：

1. 先把底层外设初始化好
2. 再由 `d153c_init()` 统一启动驱动相关功能
3. 最后启动测速用的中断节拍

如果你跳过了某个 `MX_TIMx_Init()`，后面的驱动函数往往不会报错，但现象会变成“电机不转”或者“编码器读数一直为 0”。

## 3. 电机驱动代码怎么写

CubeMX 只负责把硬件准备好，真正控制电机的是下面这些驱动接口。

### 3.1 最小可运行程序：先让 A 电机转起来

```c
#include "d153c.h"

int main(void)
{
    HAL_Init();
    SystemClock_Config();

    MX_GPIO_Init();
    MX_TIM3_Init();
    MX_TIM2_Init();

    d153c_init();
    d153c_drive(D153C_MOTOR_A, 300);

    while (1)
    {
    }
}
```

这段程序的意义很明确：

- `MX_GPIO_Init()`：给方向控制引脚做准备
- `MX_TIM3_Init()`：准备 PWM
- `MX_TIM2_Init()`：准备 A 电机编码器
- `d153c_init()`：真正启动驱动底层
- `d153c_drive(D153C_MOTOR_A, 300)`：让 A 电机按 30% 功率正转

对第一次上板调试来说，这个最小程序非常重要。**先确认电机能转，再谈测速和闭环。**

---

### 3.2 `d153c_drive()` 的第二个参数到底是什么

`d153c_drive(id, duty)` 的 `duty` 是一个**有符号占空比**，范围为 `-1000 ~ 1000`。

| duty | 含义 |
| --- | --- |
| `1000` | 正转，满功率 |
| `300` | 正转，约 30% 功率 |
| `0` | 滑行停止 |
| `-300` | 反转，约 30% 功率 |
| `-1000` | 反转，满功率 |

要抓住两个点：

1. **正负号决定方向**
2. **绝对值决定功率大小**

所以 `d153c_drive(A, -500)` 的意思不是“减速”，而是“反方向以 50% 功率转”。

---

### 3.3 `d153c_drive()` 背后到底做了什么

驱动库内部实际上干了两件事：

1. 根据 `duty` 正负设置 `IN1/IN2`
2. 根据 `|duty|` 计算 PWM 的 CCR 值

也就是说，`d153c_drive()` 并不是一个“黑盒神秘函数”，它只是帮你把“方向”和“功率”这两层控制打包成了一个接口。

这一点理解以后，你再看下面几个函数就会很自然：

```c
void d153c_coast(int id);
void d153c_brake(int id);
```

- `d153c_coast()`：让 IN1=0、IN2=0，电机断开靠惯性慢慢停
- `d153c_brake()`：让 IN1=1、IN2=1，电机短接刹车，停得更快

---

### 3.4 方向调反了怎么办

实际调车时，很常见的现象是：代码和硬件都在工作，但**方向定义跟你的预期不一致**。这时要分清两类问题。

#### 情况一：电机实际方向反了

你写：

```c
d153c_drive(D153C_MOTOR_A, 300);
```

你以为这是正转，但电机物理上却往反方向转。这个时候修正的是**驱动方向**：

```c
d153c_invert_motor(D153C_MOTOR_A, true);
```

它的作用是：保持你的上层代码含义不变，但在底层自动把方向翻过来。

---

#### 情况二：电机方向对了，但测速符号反了

电机看起来已经按你想要的方向转，但 `d153c_delta()` 或 `d153c_rps()` 的正负号却和实际运动方向相反。这说明问题不在电机输出，而在**编码器相位方向定义**上。

这时修正的是：

```c
d153c_invert_encoder(D153C_MOTOR_A, true);
```

它的作用是：让编码器增量和速度符号取反。

---

#### 两者怎么区分

简单记忆：

```text
invert_motor   = 电机走反了
invert_encoder = 速度符号反了
```

判断方法建议这样做：

1. 先让电机低速稳定转起来
2. 观察它的物理方向是否符合 `duty` 的正负定义
3. 再看 `d153c_delta()` 的正负是否和运动方向一致

不要一上来两个都改，不然会把问题越调越乱。

---

## 4. 编码器测速原理到底在算什么

测速这部分最容易让初学者觉得抽象，其实本质只是一个比例换算问题。

### 4.1 编码器不是直接测速度，而是测“增量”

编码器不会直接告诉你“现在是 3.2 r/s”。它给你的只是：

- 这一小段时间里，计数增加了多少
- 计数增加的方向是正还是负

所以测速必须分两步：

1. 先得到某个固定时间片内的计数差值 `delta`
2. 再把 `delta` 换算成速度

---

### 4.2 MG513P30 输出轴一圈对应多少计数

当前笔记采用的参数是：

| 参数 | 数值 | 含义 |
| --- | --- | --- |
| `PPR` | 13 | 电机本体转一圈，编码器产生 13 个脉冲 |
| `MULTIPLE` | 4 | 编码器模式下按 A/B 相四倍频计数 |
| `REDUCTION` | 30 | 减速比 30:1，电机转 30 圈，输出轴转 1 圈 |

因此输出轴转一圈对应的总计数为：

$$
13 \times 4 \times 30 = 1560
$$

这意味着：

- `delta = 1560`：输出轴转了 1 圈
- `delta = 780`：输出轴转了半圈
- `delta = 156`：输出轴转了 0.1 圈

这也是 `D153C_PPR`、`D153C_MULTIPLE`、`D153C_REDUCTION` 三个参数的物理意义。

---

### 4.3 `d153c_sample()` 的测速公式怎么来的

假设某次采样周期内，编码器增量为 `delta`，采样周期是 `dt_ms` 毫秒。

先把计数换成“输出轴转了多少圈”：

$$
\text{圈数} = \frac{delta}{1560}
$$

再除以时间，就得到每秒多少圈：

$$
r/s = \frac{delta / 1560}{dt_{ms} / 1000}
$$

整理后得到：

$$
r/s = delta \times \frac{1000}{1560 \times dt_{ms}}
$$

如果采样周期固定为 10 ms，那么：

$$
r/s = delta \times \frac{1000}{1560 \times 10} = \frac{delta}{15.6}
$$

所以在 10 ms 采样下：

| `delta` | 输出轴速度 |
| --- | --- |
| `16` | 约 `1.0 r/s` |
| `31` | 约 `2.0 r/s` |
| `78` | 约 `5.0 r/s` |
| `-16` | 约 `-1.0 r/s` |
| `0` | `0 r/s` |

测速本质上就这么简单：**固定时间内转了多少，再换算成每秒。**

---

## 5. 为什么测速一定要放进定时中断

这是实践里最关键的稳定性问题。

### 5.1 错误写法：看起来每 10 ms，实际上并不稳定

```c
while (1)
{
    d153c_sample(D153C_MOTOR_A, 10.0f);
    HAL_Delay(10);
}
```

这段代码的问题在于：`HAL_Delay(10)` 只保证“延时至少约 10 ms”，但一个循环里还有：

- `d153c_sample()` 自己的执行时间
- 其他逻辑代码的执行时间
- 中断打断带来的抖动

所以你填了 `10.0f`，并不代表它真的每 10 ms 被调用一次。这样算出来的速度一定会抖。

---

### 5.2 正确写法：用定时器中断给采样定节拍

```c
#define SAMPLE_MS  10.0f

void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim)
{
    static uint32_t divider = 0;

    if (htim->Instance == TIM1)
    {
        if (++divider >= 10)
        {
            divider = 0;
            d153c_sample(D153C_MOTOR_A, SAMPLE_MS);
            d153c_sample(D153C_MOTOR_B, SAMPLE_MS);
        }
    }
}
```

这个写法的逻辑是：

- TIM1 每 1 ms 进一次中断
- 累计 10 次后，正好过去 10 ms
- 此时再调用一次 `d153c_sample()`

这样 `dt_ms` 和真实采样间隔就一致了，计算出的速度才可信。

> 记住一句话：`d153c_sample()` 的参数不是“你希望它是多少”，而是“它真实被调用的周期是多少”。

## 6. 一套完整的上板实践流程

这一节把 CubeMX 初始化、驱动代码和测速连起来，形成一套能直接验证功能的程序。

### 6.1 完整测试程序

```c
#include "d153c.h"

#define SAMPLE_MS  10.0f

volatile bool sample_ready = false;

void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim)
{
    static uint32_t div = 0;

    if (htim->Instance == TIM1)
    {
        if (++div >= 10)
        {
            div = 0;
            d153c_sample(D153C_MOTOR_A, SAMPLE_MS);
            d153c_sample(D153C_MOTOR_B, SAMPLE_MS);

}

int main(void)
{
    HAL_Init();
    SystemClock_Config();

    MX_GPIO_Init();
    MX_TIM1_Init();
    MX_TIM2_Init();
    MX_TIM3_Init();
    MX_TIM4_Init();

    d153c_init();

    d153c_drive(D153C_MOTOR_A, 500);
    d153c_drive(D153C_MOTOR_B, -300);

    HAL_TIM_Base_Start_IT(&htim1);

    while (1)
    {
        if (sample_ready)
        {
            sample_ready = false;

            // float ra = d153c_rps(D153C_MOTOR_A);
            // float rb = d153c_rps(D153C_MOTOR_B);
            // int32_t da = d153c_delta(D153C_MOTOR_A);
            // int32_t db = d153c_delta(D153C_MOTOR_B);

            // 调试初期优先看 delta，
            // 因为它最接近编码器原始计数
        }
    }
}
```

---

### 6.2 第一次调车建议按这个顺序做

#### 第一步：先验证“能不能转”

先只关心输出，不关心测速。

```c
d153c_drive(D153C_MOTOR_A, 300);
```

如果这一步电机都不转，后面的编码器和速度就没有意义。

---

#### 第二步：再验证方向定义对不对

观察两个现象：

- `duty > 0` 时，电机实际方向是不是你定义的正方向
- 电机正转时，`d153c_delta()` 是不是正数

如果方向不一致：

- 物理方向反了 → `invert_motor`
- 速度符号反了 → `invert_encoder`

---

#### 第三步：最后再验证速度比例对不对

此时再看：

- `d153c_rps()` 的数值是否合理
- 满占空比时输出轴转速是否大致落在预期范围
- `delta` 与 `rps` 的换算是否对得上

如果速度比例明显不对，就重点排查：

- `PPR`
- `MULTIPLE`
- `REDUCTION`
- `dt_ms`

这几个参数只要错一个，速度就会整体偏大或偏小。

## 7. 常见问题与排障思路

### 7.1 电机不转

按下面顺序查：

1. 电机外部供电接了吗？通常不是只靠板上的 3.3 V / 5 V。
2. 电源电流够吗？单个电机启动电流可能达到 1~2 A。
3. TB6612 模块的 `STBY` 是否已经拉高？
4. PWM 引脚是否真的连接到了模块的 PWM 输入脚？
5. `d153c_drive()` 的 `duty` 是否非零？
6. `MX_GPIO_Init()`、`MX_TIM3_Init()`、`d153c_init()` 是否都执行了？

---

### 7.2 编码器读数一直为 0

优先查这几项：

1. 编码器 A/B 相接线是否正确
2. 编码器供电和共地是否正常
3. `MX_TIM2_Init()` / `MX_TIM4_Init()` 是否调用
4. 编码器模式是否真的在 CubeMX 中配置成功
5. `d153c_init()` 是否已经启动编码器接口

---

### 7.3 速度偏大或偏小

这通常不是“电机真有问题”，而是换算参数错了。重点检查：

1. `D153C_PPR` 是否正确（霍尔版通常为 13）
2. `D153C_MULTIPLE` 是否正确（编码器模式四倍频通常取 4）
3. `D153C_REDUCTION` 是否正确（P30 表示 30:1）
4. `d153c_sample()` 的 `dt_ms` 是否等于真实采样周期

---

## 8. API 速查

### 初始化与关闭

```c
void d153c_init(void);
void d153c_deinit(void);
```

- `d153c_init()`：启动 PWM 和编码器，并让电机初始处于安全停止状态
- `d153c_deinit()`：关闭 PWM 和编码器，停止输出

### 驱动控制

```c
void d153c_drive(int id, int16_t duty);
void d153c_coast(int id);
void d153c_brake(int id);
```

- `d153c_drive()`：设置有符号占空比，范围 `-1000 ~ 1000`
- `d153c_coast()`：滑行停止
- `d153c_brake()`：刹车停止

### 方向修正

```c
void d153c_invert_motor(int id, bool inv);
void d153c_invert_encoder(int id, bool inv);
```

- `invert_motor(true)`：修正电机物理方向与代码方向定义不一致的问题
- `invert_encoder(true)`：修正测速符号与实际运动方向不一致的问题

### 测速接口

```c
void  d153c_sample(int id, float dt_ms);
float d153c_rps(int id);
float d153c_rpm(int id);
int32_t d153c_delta(int id);
int16_t d153c_duty(int id);
```

- `d153c_sample()`：固定周期采样，`dt_ms` 必须填真实周期
- `d153c_rps()`：输出轴每秒转数
- `d153c_rpm()`：输出轴每分钟转数
- `d153c_delta()`：最近一个采样周期内的编码器增量
- `d153c_duty()`：最近一次设置的占空比

### 电机 ID

```c
#define D153C_MOTOR_A  0
#define D153C_MOTOR_B  1
```

## 9. 一页速记

### 控制链路

```text
d153c_drive(id, duty)
= 方向（IN1/IN2） + 功率（PWM）
```

- 正负号：决定方向
- 绝对值：决定功率

### 反馈链路

```text
编码器计数差 delta
→ 除以 1560，得到输出轴转了多少圈
→ 再除以采样时间，得到 r/s
```

### 调车不要混淆

```text
电机方向反了？  → invert_motor
速度符号反了？  → invert_encoder
速度比例错了？  → 查 PPR / MULTIPLE / REDUCTION / dt_ms
速度一直为 0？  → 查接线、编码器模式、定时器初始化、供电
```

### 最稳的上手顺序

```text
先让电机转
→ 再看方向
→ 再看 delta 正负
→ 最后看 rps 是否合理
```
