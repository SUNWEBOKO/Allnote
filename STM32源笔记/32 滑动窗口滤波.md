# 滑动窗口滤波：从环形缓冲区到稳健平均

## 本节核心问题

传感器、编码器、IMU、超声波测距、温度采集等系统通常会连续输出数据。真实工程里，原始数据很少是完全干净的：它可能夹杂高频抖动、电磁干扰、采样误差，甚至偶发的极端异常值。若直接使用“当前这一帧”的原始读数，控制系统可能震荡，显示结果也会跳动，后续判断还可能被单个坏点带偏。

滑动窗口滤波要解决的问题是：**在不无限保存历史数据的前提下，始终利用最近一段时间的数据，得到更稳定、更可信的当前输出。**

它可以拆成两个层次：

1. **窗口维护**：如何高效保存最近 $N$ 个数据；
2. **窗口计算**：如何从这 $N$ 个数据中算出滤波结果。

前者常用循环数组，也叫环形缓冲区；后者可以选择均值、中值、异常值剔除、四分位截尾平均等方法。

---

## 1. 滑动窗口的基本思想

设系统连续采集到一串数据：

```text
x0, x1, x2, x3, x4, ...
```

若窗口长度为 $N$，那么在时刻 $t$，滑动窗口关注的是最近 $N$ 个采样值：

$$
x(t-N+1),\ x(t-N+2),\ \dots,\ x(t)
$$

当新的数据 $x(t+1)$ 到来时：

- 最新数据 $x(t+1)$ 加入窗口；
- 最旧数据 $x(t-N+1)$ 被丢弃；
- 窗口整体向前移动一格。

也就是说，窗口始终覆盖“离当前最近的一段历史”。它不是相信单次采样，而是相信短时间内多个采样值共同呈现出的趋势。

这种方法的直觉是：如果被测信号的真实变化比噪声慢，那么短时间窗口内的正常值应该相对集中；突发噪声或异常值只会占据窗口中的少数位置。对窗口内数据做合理统计，就能降低这些坏点对输出的影响。

---

## 2. 为什么需要循环数组

最直接的想法是：从程序启动开始，把所有采样值都存起来，每次滤波时取最后 $N$ 个值。这个思路逻辑上没错，但工程上不可取。

原因有三个：

- 程序运行越久，历史数组越大；
- RAM 占用不断增长，嵌入式设备尤其吃不消；
- 实际滤波只需要最近 $N$ 个值，保存全部历史没有必要。

更合理的做法是：**只开辟 $N$ 个存储单元，新数据不断覆盖最旧的数据。**这就是循环数组的作用。

循环数组的本质是：

> 数组大小固定，写入位置循环使用。

例如窗口长度 $N=6$，数组下标为 $0 \sim 5$。写入索引 `write_idx` 初始为 0，每来一个新数据，就写入当前位置，然后让索引前进一格：

```text
写入第 1 个数据 → buffer[0]，write_idx → 1
写入第 2 个数据 → buffer[1]，write_idx → 2
写入第 3 个数据 → buffer[2]，write_idx → 3
写入第 4 个数据 → buffer[3]，write_idx → 4
写入第 5 个数据 → buffer[4]，write_idx → 5
写入第 6 个数据 → buffer[5]，write_idx → 0
写入第 7 个数据 → buffer[0]，覆盖最旧数据
```

关键在于取模：

$$
(5+1) \bmod 6 = 0
$$

所以当索引走到数组末尾后，会自动回到开头，继续覆盖旧数据。这样无论系统运行多久，窗口存储始终只占用 $N$ 个数据空间。

## 3. 环形缓冲区的 C 语言实现

下面是一个最小可用的滑动窗口存储结构：

```c
#define WINDOW_SIZE 6

float buffer[WINDOW_SIZE];  // 环形缓冲区
int write_idx = 0;          // 下一次写入的位置
int data_count = 0;         // 当前有效数据个数

void add_data(float new_data)
{
    buffer[write_idx] = new_data;

    write_idx = (write_idx + 1) % WINDOW_SIZE;

    if (data_count < WINDOW_SIZE) {
        data_count++;
    }
}
```

几个变量的意义要分清：

- `buffer[]`：固定长度的窗口缓存；
- `write_idx`：下一次新数据写入的位置；
- `data_count`：当前已有多少个有效数据。

`data_count` 很重要。系统刚启动时，窗口还没填满，如果直接把整个 `buffer` 都拿去计算，未写入位置的初始值可能被误当成有效数据，导致滤波结果偏低或失真。正确做法是：窗口未满时，只处理前 `data_count` 个有效值；窗口填满后，再处理完整的 `WINDOW_SIZE` 个值。

取模语句是循环数组的核心：

```c
write_idx = (write_idx + 1) % WINDOW_SIZE;
```

它保证 `write_idx` 永远落在合法下标 $0 \sim N-1$ 内。缺少这一步，索引会不断增大，最终访问数组边界之外的内存，在 MCU 或嵌入式系统中很容易造成难排查的异常。

## 4. 滑动窗口只是框架，滤波算法才决定输出

滑动窗口解决的是“保留哪些数据”，但真正的滤波效果取决于“如何处理这些数据”。常见策略如下。

### 4.1 均值滤波

对窗口内所有有效数据求算术平均：

$$
\bar{x}=\frac{x_1+x_2+\cdots+x_N}{N}
$$

优点是简单、计算量低，适合随机噪声较多且没有严重异常值的场景。缺点也明显：只要窗口里出现一个极端坏点，平均值就会被明显拉偏。

例如：

```text
10, 11, 12, 13, 14, 100
```

直接平均为：

$$
\frac{10+11+12+13+14+100}{6}=26.67
$$

这个结果已经远离正常值区间。

### 4.2 中值滤波

先排序，再取中间位置的值。中值对单个尖峰异常值非常鲁棒，比如一组数据大多集中在 10 到 15 附近，即使混入一个 1314，中值也不会被它大幅拉偏。

它适合抑制孤立的尖峰干扰。但如果噪声是连续的小幅随机抖动，中值的平滑效果通常不如均值；如果异常值连续出现并占据窗口较大比例，中值也会失效。

### 4.3 四分位截尾后求均值

四分位相关方法的工程思路是：先排序，去掉两端较极端的数据，只保留中间更可信的部分，再对保留数据求均值。

在很多课程或工程笔记里，这种方法会被称为“四分位距滤波”或“IQR 滤波”。严格统计学中的 IQR 还常用于构造离群值边界：

$$
[Q_1-1.5\operatorname{IQR},\ Q_3+1.5\operatorname{IQR}]
$$

而本文采用的是更直观的工程版本：**截取排序后中间约 50% 的数据求平均**。它的作用类似“截尾平均”，既能剔除极端值，又保留均值滤波的平滑性。

---

## 5. 四分位截尾平均的完整过程

假设当前窗口中有 $N$ 个有效数据。

### 第一步：排序

将窗口数据从小到大排列：

$$
y_1 \le y_2 \le \cdots \le y_N
$$

### 第二步：去掉两端数据

按比例去掉前 25% 和后 25% 的数据，只保留中间 50%。例如 $N=8$ 时，去掉最小的 2 个和最大的 2 个，保留中间 4 个。

工程实现时需要明确索引规则。一个常见写法是：

```c
start = N / 4;
end = N - N / 4;
```

然后计算排序数组中 `[start, end)` 范围内数据的平均值。这里使用的是 C 语言的 0 基下标与左闭右开区间。

### 第三步：对可信数据求平均

若保留下来的数据为：

$$
y_{start},\ y_{start+1},\ \dots,\ y_{end-1}
$$

则滤波结果为：

$$
\bar{x}_{trim}=\frac{1}{end-start}\sum_{i=start}^{end-1}y_i
$$

这种方法的鲁棒性来自排序后的“位置保护”：极大值和极小值会落在序列两端，只要异常值数量不超过被截掉的比例，它们就很难进入最终求平均的数据集。

## 6. 典型例题：异常值 1314 如何被排除

设窗口大小为 $N=8$，当前窗口内数据为：

```text
101, 99, 102, 1314, 100, 98, 103, 101
```

其中 `1314` 显然是一次异常读数。

### 6.1 直接平均的结果

若直接对全部数据求平均：

$$
\bar{x}=\frac{101+99+102+1314+100+98+103+101}{8}=252.25
$$

这个结果严重偏离正常读数区间。

### 6.2 四分位截尾平均

先排序：

```text
98, 99, 100, 101, 101, 102, 103, 1314
```

窗口长度为 8，去掉前 25% 的 2 个数据和后 25% 的 2 个数据，保留中间 4 个：

```text
100, 101, 101, 102
```

再求平均：

$$
\bar{x}_{trim}=\frac{100+101+101+102}{4}=101
$$

结果回到正常数据集的中心附近，说明极端异常值已经被有效排除。

如果换成一组更贴近小量程测量的数据：

```text
11, 12, 13, 14, 10, 15, 1314, 12
```

排序后为：

```text
10, 11, 12, 12, 13, 14, 15, 1314
```

保留中间 4 个：

```text
12, 12, 13, 14
```

滤波结果为：

$$
\frac{12+12+13+14}{4}=12.75
$$

而直接平均为：

$$
\frac{11+12+13+14+10+15+1314+12}{8}=175.125
$$

两者差异很大，正好体现出异常值剔除的意义。

## 7. 简化代码：均值与四分位截尾平均

下面代码展示的是思路，不包含具体排序函数实现。实际项目中可根据窗口大小选择冒泡排序、插入排序、快速排序，或使用库函数。

```c
float mean_filter(const float *data, int count)
{
    float sum = 0.0f;

    for (int i = 0; i < count; i++) {
        sum += data[i];
    }

    return sum / count;
}
```

四分位截尾平均需要先复制一份数据再排序，不要直接打乱环形缓冲区本身：

```c
float trimmed_mean_filter(const float *data, int count)
{
    float temp[WINDOW_SIZE];

    for (int i = 0; i < count; i++) {
        temp[i] = data[i];
    }

    sort_ascending(temp, count);  // 需要自行实现或调用排序函数

    int start = count / 4;
    int end = count - count / 4;

    float sum = 0.0f;
    int valid_count = 0;

    for (int i = start; i < end; i++) {
        sum += temp[i];
        valid_count++;
    }

    return sum / valid_count;
}
```

若窗口还没填满，应传入 `data_count`，而不是固定传入 `WINDOW_SIZE`。否则未初始化的数据会参与计算。

## 8. 工程权衡：平滑性与响应速度

滑动窗口滤波一定会带来延迟，因为它用历史数据来稳定当前输出。窗口越大，滤波越平滑，但响应越慢；窗口越小，响应越快，但抗噪能力下降。

可以这样理解：

| 窗口设置 | 优点 | 缺点 | 适合场景 |
|---|---|---|---|
| 小窗口，如 $N=3$ | 响应快、延迟小 | 平滑能力弱，抗异常能力有限 | 电机控制、快速闭环控制 |
| 中等窗口 | 平滑与实时性折中 | 需要调参 | IMU、编码器、一般传感器 |
| 大窗口，如 $N=50$ | 输出稳定、噪声抑制强 | 滞后明显，真实变化跟随慢 | 温度显示、UI 显示、慢变量测量 |

选择窗口长度时，应同时考虑：

- 采样频率；
- 信号真实变化速度；
- 噪声强度；
- 系统允许的延迟；
- MCU 的内存与计算能力。

例如温度变化通常较慢，可以接受较大的窗口；电机控制对实时性要求高，窗口过大会让控制滞后，甚至影响稳定性。

## 9. 常见误区与排查点

### 9.1 混淆“窗口存储”和“滤波算法”

滑动窗口只负责保留最近 $N$ 个数据；均值、中值、四分位截尾平均才是具体的计算策略。二者可以自由组合。

### 9.2 忘记处理窗口未满阶段

系统刚启动时，窗口可能只有 1 个、2 个或 3 个有效数据。此时不能把整个数组都拿来计算，应使用 `data_count` 控制有效数据范围。

### 9.3 省略取模导致数组越界

`(write_idx + 1) % WINDOW_SIZE` 不是可有可无的写法，而是环形缓冲区成立的关键。没有取模，索引迟早越界。

### 9.4 直接排序原始 buffer

如果直接对环形缓冲区排序，会破坏窗口数据的存储结构，后续写入与调试都可能混乱。正确方式是复制一份临时数组，再对临时数组排序。

### 9.5 认为异常值一定能被四分位方法剔除

四分位截尾平均适合处理少量孤立异常值。如果异常值连续出现，或异常值比例超过被截掉的部分，中间数据也可能被污染。此时需要结合其他限制，例如物理范围检查、最大变化率限制、连续异常计数、传感器故障判断等。

### 9.6 对所有信号使用同一种窗口大小

窗口大小必须与信号特性匹配。慢变量可以用大窗口，快变量应谨慎扩大窗口。调试时最好同时观察原始值和滤波值，看平滑程度与滞后是否满足需求。

## 10. 一页速查

| 项目 | 关键结论 |
|---|---|
| 滑动窗口 | 始终维护最近 $N$ 个采样值，新数据进入，旧数据丢弃。 |
| 循环数组 | 固定大小数组 + 写指针，通过取模实现环形覆盖。 |
| 核心代码 | `write_idx = (write_idx + 1) % WINDOW_SIZE;` |
| `data_count` | 用于处理窗口未填满阶段，避免无效数据参与计算。 |
| 均值滤波 | 简单、平滑，但容易被极端异常值拉偏。 |
| 中值滤波 | 抗孤立尖峰能力强，但对连续抖动的平滑能力有限。 |
| 四分位截尾平均 | 排序后去掉两端数据，对中间部分求均值，兼顾抗异常与平滑。 |
| 最大权衡 | 窗口越大越平滑，但响应越慢；窗口越小响应越快，但抗噪较弱。 |
| 调试建议 | 同时输出原始值与滤波值，根据噪声抑制效果和跟随延迟调整窗口。 |

## 12. 核心总结

滑动窗口滤波的本质是：**用最近一段历史数据替代单次瞬时读数，从而提高输出的稳定性和可靠性。**

实现上，循环数组负责以固定内存维护最近 $N$ 个数据；计算上，均值、中值、四分位截尾平均等策略决定滤波结果的特点。工程中最重要的不是固定套用某一种算法，而是根据信号变化速度、噪声形态、实时性要求和硬件资源，在平滑性与响应速度之间找到合适折中。
