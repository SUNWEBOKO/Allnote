# 05. 中断机制深入：EXTI、NVIC 与优先级

> 本节重点：掌握 EXTI 外部中断从 GPIO 到 ISR 的完整链路，理解 NVIC 中断优先级判定规则与实战配置。

## 1. EXTI 外部中断/事件控制器

### 1.1 EXTI 的作用

`EXTI`（External Interrupt/Event Controller）负责检测 GPIO 引脚的边沿变化，并产生中断或事件请求。

### 1.2 EXTI 中断线

STM32F1 系列共有 19 条 EXTI 线：

| 线号 | 连接对象 |
|------|----------|
| `EXTI0 ~ EXTI15` | 对应 GPIO 编号的引脚（如 `PA0/PB0/PC0` 共用 EXTI0） |
| `EXTI16` | PVD 输出 |
| `EXTI17` | RTC 闹钟 |
| `EXTI18` | USB 唤醒 |

注意：同一编号的 EXTI 线只能选择一个引脚使用（如 PA0 和 PB0 不能同时使用 EXTI0）。

---

## 2. 中断路径 vs 事件路径

| 路径 | 是否打断 CPU | 结果 | 初学重点 |
|------|-------------|------|----------|
| 中断路径 | 是 | CPU 跳转到 ISR 执行用户处理逻辑 | ✅ 重点掌握 |
| 事件路径 | 否 | 触发外设内部链路（如定时器、DMA），不产生中断 | 知道概念即可 |

---

## 3. 从 GPIO 到 ISR 的完整链路

```text
GPIO 电平变化
    ↓
EXTI 边沿检测 → 挂起位 PR 置位
    ↓
中断屏蔽寄存器 IMR 放行
    ↓
NVIC 接收中断请求
    ↓
NVIC 查向量表，找到 ISR 入口
    ↓
CPU 跳转到 IRQHandler 执行
```

### 3.1 中断向量分配

| 中断源 | 向量名称 | 说明 |
|--------|----------|------|
| EXTI0 ~ EXTI4 | `EXTI0_IRQn` ~ `EXTI4_IRQn` | 每个引脚独立向量 |
| EXTI5 ~ EXTI9 | `EXTI9_5_IRQn` | 共用向量 |
| EXTI10 ~ EXTI15 | `EXTI15_10_IRQn` | 共用向量 |

共用向量的情况下，回调中需要按 GPIO 引脚号区分中断来源：

```c
void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin)
{
    if (GPIO_Pin == GPIO_PIN_12) { /* PB12 的处理 */ }
    if (GPIO_Pin == GPIO_PIN_13) { /* PB13 的处理 */ }
}
```

## 4. 清除挂起位

### 4.1 为什么需要清挂起位

中断处理结束后，挂起位（Pending Register, PR）若不清除，NVIC 仍可能判定"中断未结束"，导致重复进入 ISR。

### 4.2 HAL 的处理方式

使用 HAL 时，中断入口调用 `HAL_GPIO_EXTI_IRQHandler()` 内部会自动完成挂起位清除，用户只需写回调函数。

### 4.3 寄存器操作

如果直接操作寄存器，流程必须是：

```c
// 1. 判断中断来源
if (EXTI->PR & EXTI_PR_PR12)
{
    // 2. 执行用户处理
    // 3. 清除挂起位（写 1 清 0）
    EXTI->PR = EXTI_PR_PR12;
}
```

**不亲手写寄存器时，只需记住：清挂起位是标准操作，HAL 已封装好。**

## 5. 中断优先级

### 5.1 两层优先级

STM32 常见中断优先级分为两层：

| 层级 | 比较优先级 | 作用 |
|------|-----------|------|
| 抢占优先级（Preempt Priority） | 先比较 | 决定是否能打断当前 ISR |
| 响应优先级（Sub Priority） | 后比较 | 同时到达的中断，谁先执行 |

**数值越小，优先级越高。**

### 5.2 判定规则

```text
同时到达的中断：
  先比抢占优先级（小者优先）
  再比响应优先级（小者优先）

ISR 执行中来了新中断：
  只看新中断的抢占优先级是否小于当前 ISR
      是 → 打断当前 ISR，执行新中断
      否 → 等待当前 ISR 完成
```

### 5.3 实战经验

- 抢占优先级决定性能关键路径（是否能打断）
- 响应优先级常作为同级中断的排序手段
- `SysTick` 优先级不能设置得太低，否则 `HAL_Delay` 会被高优先级 ISR 长时间压制

## 7. 高频易错点

1. **中断不触发**
   - GPIO 是否为 EXTI 模式？
   - NVIC 对应中断是否开启？
   - 边沿触发方式与实际电平变化是否一致？

2. **中断反复进入**
   - 挂起位是否已清除？
   - 按键抖动是否导致连触发？

3. **主循环延时异常或"卡死"**
   - 是否有高优先级长 ISR 占用了大量 CPU 时间？
   - `SysTick` 优先级是否低于某个频繁触发的中断？

4. **共用向量时未区分引脚**
   - `EXTI15_10_IRQn` 对应 PB12 和 PB13 等多个引脚，回调里必须按 `GPIO_Pin` 分流。

5. **中断中调用了 `HAL_Delay`**
   - 若中断优先级高于 SysTick，会死锁。

## 8. 一页速记

### 中断链路
```text
GPIO → EXTI 边沿检测 → PR 置位 → IMR 放行 → NVIC → ISR
```

### 中断链路排查顺序
```text
触发源 → 挂起(PR) → 屏蔽(IMR) → NVIC → 回调
```

### 优先级规则
```text
同时来：先比抢占，再比响应
打断中：只看抢占
数 值 小 = 优 先 级 高
```

### 最重要的一句话
> EXTI 负责"检测与挂起"，NVIC 负责"分发与调度"，理解这两层的分工才能快速排查中断问题。
