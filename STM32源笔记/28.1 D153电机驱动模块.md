# 28.1 D153 电机驱动模块：TB6612 + MG513P30

这一节只讲**电机驱动层**：MCU 怎样通过方向 GPIO 和 PWM 控制 TB6612，让 D153 模块上的两路 MG513P30 直流减速电机稳定转起来。

驱动层只负责下面这条链路：

```text
方向 GPIO + PWM 占空比
→ TB6612 双 H 桥
→ 电机正转 / 反转 / 滑行 / 刹车
```

测速不要混在这一层里。测速属于反馈层，分别见：

- [[28.2 D153编码器M法测速]]
- [[28.3 D153输入捕获T法测速]]

---

## 本节核心问题

学完这一节，应该能回答下面几个问题：

- D153 模块里哪些信号决定电机方向，哪些信号决定输出功率？
- 为什么 `duty` 的正负号表示方向，绝对值表示力度？
- CubeMX 里驱动层至少要配置哪些 GPIO 和 PWM 资源？
- `d153c_motor_drive(id, duty)` 的参数范围是多少？
- `d153c_motor_coast()` 和 `d153c_motor_brake()` 的区别是什么？
- 新板子第一次上电时，应该按什么顺序调车和排障？

## 1. 模块构成

| 部件 | 作用 |
| --- | --- |
| **TB6612FNG** | 双 H 桥驱动芯片，把 MCU 的方向信号和 PWM 信号变成真正驱动电机的电流。 |
| **MG513P30** | 带 30:1 减速箱和霍尔编码器的直流减速电机。驱动层只关心电机本体转动，不处理编码器测速。 |
| **d153c_motor 驱动模块** | 封装方向 GPIO、PWM 启停、占空比限幅、滑行和刹车。 |

驱动层的控制链路如下：

```text
你的代码
→ d153c_motor_drive()
→ IN1 / IN2 + PWM
→ TB6612
→ 电机转动
```

这里先抓住一句话：

```text
方向由 IN1/IN2 决定，功率由 PWM 决定。
```

---

## 2. 直流电机和 PWM 调速

直流有刷电机可以用一个集中参数等效电路理解：

$$
U_A = R_A I_A + L_A \frac{dI_A}{dt} + E
$$

其中反电动势满足：

$$
E = K_E \omega
$$

空载稳态时，电机电流较小，可近似认为：

$$
U_A \approx E = K_E \omega
$$

也就是：

$$
\omega_{\max} \approx \frac{U_A}{K_E}
$$

PWM 改变的是电机看到的等效平均电压。若电池电压为 $V_{BT}$，PWM 占空比为 $D$，则：

$$
U_{A,\text{eq}} \approx D \cdot V_{BT}
$$

所以开环下，速度上限近似随占空比增大而增大。

第一次调车必须从小占空比开始，因为：

- 刚启动时反电动势 $E = 0$，启动电流很大
- 堵转时电流持续极大，容易烧驱动芯片或拖垮电源
- 方向定义可能和预期相反，小车可能直接冲出去

## 3. TB6612 的方向状态

TB6612 每路电机通常有两个方向输入脚。方向脚决定 H 桥状态，PWM 只负责给功率。

| IN1 | IN2 | 电机行为 | 驱动接口 |
| --- | --- | --- | --- |
| 0 | 0 | 滑行停止，高阻 | `d153c_motor_coast()` |
| 1 | 0 | 正转 | `d153c_motor_drive(id, +duty)` |
| 0 | 1 | 反转 | `d153c_motor_drive(id, -duty)` |
| 1 | 1 | 短路刹车 | `d153c_motor_brake()` |

因此：

```c
d153c_motor_drive(D153C_MOTOR_A, -500);
```

含义不是“减速”，而是：

```text
A 电机反方向，50% 功率
```

如果 TB6612 模块引出了 `STBY` 引脚，还要保证它被拉高：

- `STBY = 0`：待机，不工作
- `STBY = 1`：退出待机，允许驱动

## 4. CubeMX 配置

驱动层只需要两类资源：

- GPIO：控制 `IN1`、`IN2`，必要时控制 `STBY`
- PWM 定时器：输出占空比

当前驱动库默认硬件映射在 `d153c_motor.h` 中：

```c
#define D153C_A_IN1_PORT   GPIOB
#define D153C_A_IN1_PIN    GPIO_PIN_12
#define D153C_A_IN2_PORT   GPIOB
#define D153C_A_IN2_PIN    GPIO_PIN_13
#define D153C_A_PWM_TIM    (&htim3)
#define D153C_A_PWM_CH     TIM_CHANNEL_1

#define D153C_B_IN1_PORT   GPIOB
#define D153C_B_IN1_PIN    GPIO_PIN_14
#define D153C_B_IN2_PORT   GPIOB
#define D153C_B_IN2_PIN    GPIO_PIN_15
#define D153C_B_PWM_TIM    (&htim3)
#define D153C_B_PWM_CH     TIM_CHANNEL_2
```

如果你的板子接线不同，只改这些宏，不要改驱动逻辑。

### 4.1 GPIO

方向引脚配置为普通推挽输出：

| 配置项 | 建议值 |
| --- | --- |
| Mode | `GPIO_Output` |
| Output type | `Push Pull` |
| Pull | 视硬件而定，常用 `No Pull` |
| Speed | `Low` 或 `Medium` 即可 |

初始化后不要让方向脚悬空。驱动初始化会默认进入滑行停止状态。

### 4.2 PWM

当前工程约定由 `TIM3` 输出两路 PWM。常见配置如下：

| 参数 | 值 |
| --- | --- |
| 定时器时钟 | 72 MHz |
| PSC | 71 |
| ARR | 99 |
| PWM 频率 | $72\text{ MHz} / (71 + 1) / (99 + 1) = 10\text{ kHz}$ |
| 命令范围 | `-1000 ~ 1000` |

驱动内部把 `duty` 映射到比较寄存器：

$$
CCR = (ARR + 1) \times \frac{|duty|}{1000}
$$

例如 `duty = 300` 时：

$$
CCR = (99 + 1) \times \frac{300}{1000} = 30
$$

也就是约 30% 占空比。

驱动中写入 `CCR` 前会限幅，避免 `duty` 越界导致异常输出。

## 5. 驱动 API

驱动层头文件为：

```c
#include "d153c_motor.h"
```

常用接口如下：

```c
void d153c_motor_init(void);
void d153c_motor_deinit(void);

void d153c_motor_drive(int id, int16_t duty);
void d153c_motor_coast(int id);
void d153c_motor_brake(int id);

void d153c_motor_invert(int id, bool inv);
int16_t d153c_motor_duty(int id);
```

电机编号：

```c
#define D153C_MOTOR_A  0
#define D153C_MOTOR_B  1
```

`duty` 范围为：

```text
-1000 ~ +1000
```

| duty | 含义 |
| --- | --- |
| `1000` | 正转，满功率 |
| `300` | 正转，约 30% 功率 |
| `0` | 滑行停止 |
| `-300` | 反转，约 30% 功率 |
| `-1000` | 反转，满功率 |

## 6. 最小可运行程序

```c
#include "d153c_motor.h"

int main(void)
{
    HAL_Init();
    SystemClock_Config();

    MX_GPIO_Init();
    MX_TIM3_Init();

    d153c_motor_init();

    d153c_motor_drive(D153C_MOTOR_A, 300);
    d153c_motor_drive(D153C_MOTOR_B, 300);

    while (1)
    {
    }
}
```

第一次上板时务必把车轮架空。先确认单轮能前后转，再让双轮同时转。

## 7. 方向调反了怎么办

如果你写：

```c
d153c_motor_drive(D153C_MOTOR_A, 300);
```

但 A 电机实际朝反方向转，说明电机驱动方向定义反了。此时修正：

```c
d153c_motor_invert(D153C_MOTOR_A, true);
```

不要在驱动层处理编码器测速符号。测速符号属于测速模块：

- M 法测速用 `d153c_speed_m_invert_encoder()`
- T 法测速用 `d153c_speed_t_invert()`

记法如下：

```text
电机物理方向反了 → 改 motor invert
速度反馈符号反了 → 改 speed invert
```

## 8. 上板调试流程

### 第一步：静态通电检查

- 电机外部供电是否正常
- 电源电流是否足够
- `STBY` 是否已经拉高
- MCU、电机驱动、电机编码器是否共地
- 机械上是否卡死

### 第二步：单轮前后转

```c
d153c_motor_drive(D153C_MOTOR_A, 300);
HAL_Delay(2000);
d153c_motor_drive(D153C_MOTOR_A, -300);
HAL_Delay(2000);
d153c_motor_coast(D153C_MOTOR_A);
```

通过标准：正转 2 s，反转 2 s，最后滑行停止。

### 第三步：双轮同步

```c
d153c_motor_drive(D153C_MOTOR_A, 400);
d153c_motor_drive(D153C_MOTOR_B, 400);
```

通过标准：双轮同向，整车有直线前进趋势，不是原地打转。

### 第四步：占空比阶跃

```c
for (int d = 200; d <= 1000; d += 200)
{
    d153c_motor_drive(D153C_MOTOR_A, d);
    HAL_Delay(1000);
}
d153c_motor_coast(D153C_MOTOR_A);
```

通过标准：转速随 `duty` 递增而升高，无明显突变。

### 第五步：刹车验证

```c
d153c_motor_drive(D153C_MOTOR_A, 800);
HAL_Delay(1000);
d153c_motor_brake(D153C_MOTOR_A);
```

通过标准：刹车明显比滑行停得快。

## 9. 常见故障

| 现象 | 优先检查项 |
| --- | --- |
| 电机不转 | 外部供电、`STBY`、`duty` 是否非零、PWM 是否启动、GPIO 是否初始化 |
| 只会单向转 | 某个方向引脚没配置成输出，或接线错误 |
| PWM 无效 | PWM 引脚复用映射、`HAL_TIM_PWM_Start()`、定时器通道是否正确 |
| 低占空比不动 | 电机静摩擦和负载过大，先略微提高起步占空比 |
| 发热严重 | 长时间堵转、长时间刹车、电源或机械负载异常 |

没示波器时，可以先打印定时器关键寄存器：

```c
printf("TIM3 PSC=%lu ARR=%lu CCR1=%lu CCR2=%lu\n",
       htim3.Instance->PSC,
       htim3.Instance->ARR,
       __HAL_TIM_GET_COMPARE(&htim3, TIM_CHANNEL_1),
       __HAL_TIM_GET_COMPARE(&htim3, TIM_CHANNEL_2));
```

先确认 PWM 真的写进去了，再继续怀疑电机或驱动板。

## 10. 一页速记

- D153 驱动链路：STM32 GPIO/PWM -> TB6612 -> MG513P30 电机。
- `STBY` 必须拉高，驱动芯片才会工作。
- 方向由两路 GPIO 决定，速度由 PWM 占空比决定。
- 调试顺序：静态供电 -> 单轮正反转 -> 双轮同步 -> 占空比阶跃 -> 刹车验证。
- 低占空比不转不一定是代码错，可能是电机静摩擦和负载死区。
- 没示波器时，先打印 `PSC/ARR/CCR`，确认 PWM 配置和占空比真的生效。
