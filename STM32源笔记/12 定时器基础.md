## 1. 定时器的本质

定时器不是神秘黑盒，本质是**对时钟脉冲计数**。

```text
时钟脉冲 → 预分频(PSC) → 计数器(CNT) → 计到 ARR → 更新事件
```

有稳定时钟，计到固定数量就能得到固定时间。同一硬件可扩展出输入捕获、PWM、编码器等功能。

---

## 2. STM32 定时器家族

| 类型 | 特点 | 典型用途 |
|------|------|----------|
| 基本定时器 | 只有基础定时功能，无外部 IO | 基础定时、时基 |
| 通用定时器 | 有外部 IO，支持输入捕获、输出比较、PWM | 最常用 |
| 高级定时器 | 在通用基础上增加互补输出、刹车等功能 | 电机控制 |

---

## 3. 核心量与公式

### 3.1 三个核心寄存器

| 寄存器 | 全称 | 作用 |
|--------|------|------|
| `PSC` | Prescaler | 预分频，决定计数器看到什么频率的时钟 |
| `ARR` | Auto Reload Register | 自动重装载值，决定一个计数周期的长度 |
| `CNT` | Counter | 当前计数值 |

### 3.2 定时周期公式

```text
f_cnt     = f_tim / (PSC + 1)
T_update  = (ARR + 1) / f_cnt
          = (PSC + 1) × (ARR + 1) / f_tim
```

### 3.3 示例

假设 `f_tim = 72MHz`，需要定时 1 秒：

```text
PSC = 7199  →  f_cnt = 72MHz / 7200 = 10kHz
ARR = 9999  →  T_update = 10000 / 10kHz = 1s
```

验证：
```text
(7199 + 1) × (9999 + 1) / 72,000,000 = 7200 × 10000 / 72M = 1s
```

## 4. CubeMX 配置（定时 1s）

| 步骤 | 操作 |
|------|------|
| 1 | 选择一个定时器（如 TIM4），时钟源选 `Internal Clock` |
| 2 | `Prescaler (PSC)` 设为 `7199` |
| 3 | `Counter Period (ARR)` 设为 `9999` |
| 4 | `Counter Mode` 设为 `Up`（上计数） |
| 5 | 若需中断，在 NVIC 页面勾选 TIM4 全局中断 |
| 6 | 保存生成代码 |

## 5. HAL 代码实现

### 5.1 启动定时器

```c
// 普通方式（不产生中断）
HAL_TIM_Base_Start(&htim4);

// 中断方式（产生更新中断）
HAL_TIM_Base_Start_IT(&htim4);
```

### 5.2 常用操作

| 操作 | 宏/函数 |
|------|---------|
| 读取当前计数 | `__HAL_TIM_GET_COUNTER(&htimx)` |
| 设置计数初值 | `__HAL_TIM_SET_COUNTER(&htimx, value)` |
| 修改 ARR | `__HAL_TIM_SET_AUTORELOAD(&htimx, arr)` |
| 修改 PSC | `__HAL_TIM_SET_PRESCALER(&htimx, psc)` |

### 5.3 更新中断回调

```c
void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim)
{
    if (htim->Instance == TIM4)
    {
        // 每 1 秒执行一次
        HAL_GPIO_TogglePin(LED_GPIO_Port, LED_Pin);
    }
}
```

## 6. 影子寄存器与预装载

### 6.1 为什么需要影子寄存器

如果在计数器运行过程中直接修改 PSC 或 ARR，改动可能在当前周期中途生效，导致该周期长度异常。

影子寄存器的策略：**运行时写入影子寄存器，等更新事件到来时才一次性同步到工作寄存器。**

### 6.2 预装载配置

| 配置项 | 说明 |
|--------|------|
| `Auto Reload Preload` | ARR 预装载使能，建议保持开启 |
| 关闭预装载 | 运行中减小 ARR 可能"错过"当前比较点 |

---

## 7. 高频易错点

1. **定时周期算错**。先确认 `TIMxCLK`，再核对 `PSC` 和 `ARR` 是否与公式一致。

2. **开了中断但回调不进**。检查两件事：NVIC 页面勾选了中断、`HAL_TIM_Base_Start_IT()` 代替了 `Start`。

3. **动态改参数后效果异常**。关注影子寄存器的生效时机——不是写入瞬间生效，而是下一个更新事件。

4. **PSC 和 ARR 混淆**。PSC 分频时钟频率，ARR 决定计多少下触发更新。

5. **ARR 设置为 N 但周期是 N+1 个计数**。因为计数器从 0 计到 ARR（含 0），共 `ARR + 1` 个脉冲。

## 8. 一页速记

### 核心公式
```text
定时周期 = (PSC + 1) × (ARR + 1) / f_tim
```

### 推导方法

三步确定 PSC 和 ARR：

1. **定计数频率**：PSC 决定计数器时钟
   $$f_{cnt} = \frac{f_{tim}}{PSC + 1}$$
   常用目标：1MHz（PSC=71），1μs 跳一次
2. **定定时周期**：ARR 决定计到多少产生更新
   $$T = \frac{ARR + 1}{f_{cnt}}$$
3. **反算验证**

### 常见组合（$f_{\text{tim}} = 72\ \mathrm{MHz}$）

| 目标 | 推导 | PSC | ARR | 计数器时钟 | 计数次数 |
|------|------|-----|-----|-----------|---------|
| 1s | 72MHz → 10kHz → 计 10000 次 | 7199 | 9999 | 10kHz = 100μs | 10000 次 |
| 100ms | 72MHz → 10kHz → 计 1000 次 | 7199 | 999 | 10kHz = 100μs | 1000 次 |
| 10ms | 72MHz → 100kHz → 计 1000 次 | 719 | 999 | 100kHz = 10μs | 1000 次 |
| 1ms | 72MHz → 1MHz → 计 1000 次 | 71 | 999 | 1MHz = 1μs | 1000 次 |

常见误解：ARR=9999 对应 10000 个计数（0~9999），而不是 9999 次。因为 `ARR+1` 才是总计数次数。

$$
T_{\text{period}} = \frac{(PSC + 1) \times (ARR + 1)}{f_{\text{tim}}}
= \frac{(7199+1) \times (9999+1)}{72 \times 10^6}
= \frac{7200 \times 10000}{72 \times 10^6}
= 1\ \mathrm{s}
$$

### 核心 API
| 函数 | 用途 |
|------|------|
| `HAL_TIM_Base_Start()` | 启动定时器（无中断） |
| `HAL_TIM_Base_Start_IT()` | 启动定时器（有中断） |
| `HAL_TIM_PeriodElapsedCallback()` | 更新中断回调 |

### 最重要的一句话
> 定时器核心就是 PSC 分频 + CNT 计数 + ARR 回卷，三者决定一切定时行为。
