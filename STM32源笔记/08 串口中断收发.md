# 08. 串口中断收发：从轮询到非阻塞

> 本节重点：理解串口轮询模式阻塞 CPU 的问题，掌握中断模式下的非阻塞收发机制，以及 HAL 回调函数驱动接收处理逻辑。

---

- 中断模式相比轮询模式的核心改进是什么？

- 中断接收的回调函数和数据接收流程是什么关系？
- 串口中断不触发时应该按什么顺序排查？

## 1. 轮询模式的问题

```c
// 轮询接收：CPU 被"绑死"直到收到 len 字节
HAL_UART_Receive(&huart2, rx_buf, len, HAL_MAX_DELAY);
```

- CPU 反复查询寄存器状态（可写/可读），直到发送或接收完成
- 查询期间 CPU 无法处理其他任务
- 接收长度必须预先给定，灵活性差

---

## 2. 中断模式的优势

| 对比项 | 轮询模式 | 中断模式 |
|--------|----------|----------|
| CPU 占用 | 高（忙等） | 低（仅传输时介入） |
| 阻塞性 | 阻塞 | 非阻塞 |
| 接收灵活性 | 必须提前知道长度 | 配合 HAL 状态机 |
| 主循环响应 | 被阻塞 | 可以并行处理 |

发送时：寄存器空事件触发中断，CPU 仅在"需要搬运下一字节"时介入。
接收时：数据到达触发中断，HAL 负责逐步将字节搬到缓冲区。

## 4. HAL API

| 函数 | 用途 |
|------|------|
| `HAL_UART_Transmit_IT(huart, data, len)` | 中断发送（非阻塞） |
| `HAL_UART_Receive_IT(huart, buf, len)` | 中断接收（非阻塞） |
| `HAL_UART_RxCpltCallback(huart)` | 接收完成回调 |

中断版本比轮询版本少了超时参数——调用立即返回，完成时触发回调。

### 共享变量的并发风险

中断收发模式下，**主循环和 ISR 共享同一个数据缓冲区**。这引入了并发竞争问题：

```c
// 主循环：正在读取 rx_buf
if (rx_buf[0] == 0xAA) { ... }

// 同一时刻 ISR 触发：向 rx_buf 写入新数据
void HAL_UART_RxCpltCallback(UART_HandleTypeDef *huart) {
    rx_buf[0] = new_byte;  // 可能刚好在主循环读取时被修改
}
```

**结果**：主循环读到一半的数据被中断改写，得到损坏的值。

### 三条基本保护规则

| 规则 | 说明 |
|------|------|
| 共享变量声明 `volatile` | 告诉编译器该变量可能被中断修改，禁止优化掉读取操作 |
| ISR 只写、主循环只读 | 或反之——避免读写冲突。推荐 ISR 设置标志位，主循环消费 |
| 临界区关中断保护 | 当必须主循环读、ISR 写同一变量时，在主循环读取前关中断 |

```c
volatile uint8_t new_data_flag = 0;
volatile uint8_t rx_buffer[64];

// 主循环消费
if (new_data_flag)
{
    __disable_irq();              // 关中断，防止 ISR 干扰
    uint8_t flag = new_data_flag; // 复制标志
    new_data_flag = 0;            // 清标志
    __enable_irq();               // 开中断

    if (flag) ProcessData(rx_buffer);
}

// ISR 生产（回调中）
void HAL_UART_RxCpltCallback(UART_HandleTypeDef *huart)
{
    new_data_flag = 1;
    HAL_UART_Receive_IT(&huart2, rx_buffer, RX_LEN);
}
```

**原则**：关中断的时间越短越好，只在复制共享变量的几条指令期间关闭。不要在关中断期间做耗时操作。

## 5. 中断接收的典型流程

### 5.1 初始化阶段

```c
// 主程序中启动一次接收
HAL_UART_Receive_IT(&huart2, rx_buf, RX_LEN);
```

### 5.2 回调中处理并续接

```c
void HAL_UART_RxCpltCallback(UART_HandleTypeDef *huart)
{
    if (huart->Instance == USART2)
    {
        // 1) 处理本次收到的数据
        ProcessCommand(rx_buf, RX_LEN);

        // 2) 重新启动下一轮中断接收（关键！）
        HAL_UART_Receive_IT(&huart2, rx_buf, RX_LEN);
    }
}
```

### 5.3 连续接收链

```text
初始化 HAL_UART_Receive_IT()
    ↓
数据到达 → 中断 → HAL 逐字节接收
    ↓
达到设定长度 → HAL_UART_RxCpltCallback()
    ↓
处理数据 → 再次调用 HAL_UART_Receive_IT()
    ↓
（回到等待下一帧）
```

---

## 6. 高频易错点

1. **回调中忘记重启接收**。只能收到第一帧，后续数据不再触发回调。

2. **回调函数不进**。检查 NVIC 是否开启 / `USARTx_IRQHandler` 是否调用了 `HAL_UART_IRQHandler()`。

3. **数据处理错位**。检查缓冲区长度、协议分帧方式和共享变量的并发访问。

4. **主循环中反复调用 `HAL_UART_Receive_IT`**。只需初始化调用一次，后续在回调中续接即可。

5. **回调中做耗时操作**。中断回调应尽量短小，重处理放主循环。

---

## 7. 一页速记

### 核心流程
```text
轮询：CPU 忙等，阻塞
中断：回调驱动，非阻塞
```

### 中断链路排查
```text
NVIC 开启 → IRQHandler 存在 → 调用 HAL_UART_IRQHandler → 进回调
```

### 核心 API
| 函数 | 用途 |
|------|------|
| `HAL_UART_Transmit_IT()` | 中断发送 |
| `HAL_UART_Receive_IT()` | 中断接收 |
| `HAL_UART_RxCpltCallback()` | 接收完成回调 |

### 最重要的一句话
> 中断接收的要点是"回调里续接"——回调末尾一定要再次调用 `Receive_IT`，否则只收一次。
