# 绪论：走进数学建模的大门

## 本节核心问题

这一章要解决的不是某一个具体模型，而是先建立对“数学建模”的整体认识：

- 数学建模到底是什么？
- 数学模型和数学建模有什么区别？
- 一个现实问题怎样被整理成可计算、可解释、可验证的数学问题？
- 初学者应该沿着什么主线学习建模？

姜启源先生把数学建模概括为“建立数学模型解决实际问题”。这句话抓住了本质，但对初学者来说还不够落地。更具体地说，数学建模不是把公式套到题目上，而是先理解现实问题，再用变量、假设、关系式和计算方法，把现实关系翻译成数学语言，最后把求解结果解释回现实。

## 1. 数学建模的本质

### 1.1 从现实到模型

人类认识世界常常依赖模型。模型不一定都是数学公式，也可以是图形、文字、流程图、实验装置或计算机仿真。数学模型的特殊之处在于：它用数学符号和数学关系表达现实对象，使问题能够被推导、计算、比较和检验。

![alt text](img/docs-CH0-image.png)

<center>图0.1 人类认识世界的三种模型</center>

可以把数学建模理解成一条转换链：

现实问题 -> 关键因素 -> 变量与假设 -> 数学模型 -> 求解计算 -> 结果检验 -> 现实解释

其中最重要的不是“写出复杂公式”，而是判断哪些因素必须保留，哪些因素可以暂时忽略。模型越复杂，越接近现实，但也越难求解、越难解释；模型越简单，越容易分析，但可能丢掉关键机制。建模的核心能力，就是在这两者之间取一个合适的平衡。

### 1.2 数学模型与数学建模

| 概念 | 含义 | 关注点 |
| --- | --- | --- |
| 数学模型 | 对某个现实问题的数学表达，如方程、优化模型、图模型、统计模型等。 | “写成什么数学形式？” |
| 数学建模 | 从现实问题出发，经过假设、抽象、建模、求解、检验、解释，再回到现实问题的完整过程。 | “怎样把现实问题变成可用的模型？” |

因此，数学模型是结果，数学建模是过程。只会记模型名称不等于会建模；真正的建模能力体现在能否根据问题选择变量、提出假设、设计求解路线，并说明结果在现实中意味着什么。

## 2. 建模不是“见题套公式”

不要被“数学建模”四个字劝退。它的底层仍然是解应用题，只是中学里的“小明买糖”换成了真实世界里的疫情防控、交通调度、资源分配、图像识别和投资决策。

真实问题通常有三个特点：

- 条件不完整：题目不会把所有变量、公式和数据都直接给出。
- 目标不单一：可能同时要求精度、成本、效率、稳定性或公平性。
- 方法不唯一：同一个问题可以用微分方程、优化、统计、图论或机器学习等不同方法处理。

所以，数学建模训练的不只是公式推导能力，还包括抽象问题、设计假设、调用工具、解释结果的能力。它更像一种工程化的思维方式：把复杂现实整理成可以分析和落地的结构。

## 3. 一个入门例子：SEIR 传染病模型

2020 年初，新冠疫情让传染病传播、医疗资源配置、检测策略评估等问题进入公众视野。以 SEIR 传染病模型为例，我们可以把人群分成四类：

- $S$：易感者，尚未感染但可能被感染的人。
- $E$：暴露者，已经感染但尚未表现出传染性或症状的人。
- $I$：感染者，具有传染性的人。
- $R$：康复者，康复或移出传播链的人。

若总人数为 $N$，记

$$
s(t)=\frac{S(t)}{N},\quad e(t)=\frac{E(t)}{N},\quad i(t)=\frac{I(t)}{N},\quad r(t)=\frac{R(t)}{N}
$$

则一个简化的 SEIR 模型可以写成：

$$
\begin{aligned}
\frac{ds}{dt} &= -\lambda s i,\\
\frac{de}{dt} &= \lambda s i-\delta e,\\
\frac{di}{dt} &= \delta e-\mu i,\\
\frac{dr}{dt} &= \mu i,\\
s(t)+e(t)+i(t)+r(t) &= 1.
\end{aligned}
$$

其中：

- $\lambda$ 表示感染传播强度；
- $\delta$ 表示暴露者转为感染者的速率；
- $\mu$ 表示感染者康复或移出的速率。

现在不需要完全掌握这个方程组，重点看它的建模思路：

1. 先把现实中的人群划分为几个状态；
2. 再描述状态之间如何转移；
3. 把转移关系写成微分方程；
4. 求解方程后观察疫情发展趋势；
5. 根据结果解释传播速度、峰值、干预效果等现实问题。

这说明一个模型往往不是单一知识点。教室封闭环境中的传播动画可以用元胞自动机模拟；新药试验中的数据分析需要统计检验；医疗资源安排、路径选择和调度问题又会涉及优化模型。数学建模的关键，是把现实问题整理成可表达、可计算、可解释的结构。

## 4. 好模型的判断标准

一个好的模型，既要抓住问题的主要矛盾，又不能复杂到无法求解。建模中有一个朴素原则：大道至简。

| 标准 | 具体含义 |
| --- | --- |
| 形式简洁 | 变量、假设和方程不要无谓膨胀，能解释核心问题即可。 |
| 精度到位 | 求解结果要满足实际应用或竞赛分析的精度要求。 |
| 理论清楚 | 假设、推导和适用条件要说得明白。 |
| 排除干扰 | 次要因素可以压缩或剔除，避免模型被噪声牵着走。 |
| 可解释性强 | 结果不能只给数字，还要说明现实含义。 |
| 求解方便 | 模型应当能借助 MATLAB、Python 等工具稳定求解。 |

> 注意：好模型通常不是一次写成的。建模需要反复调整假设、检验结果、修正参数；经典模型也可以在新的场景中继续改进。

## 5. 课程学习的四个层次：道、法、术、器

数学建模横跨微分方程、运筹优化、统计分析、图论、机器学习等多个方向。初学者容易困惑：内容很多，到底该先学什么？本科阶段可以先用“道、法、术、器”来组织学习。

![](img/docs-CH0-image-1.png)

<center>图0.2 数学建模的四个境界</center>

| 层次 | 学习重点 | 对应能力 |
| --- | --- | --- |
| 道 | 理解数学建模为什么存在，以及它如何连接现实与数学。 | 判断问题是否需要建模、模型服务于什么目标。 |
| 法 | 掌握常见问题的建模思路和分析框架。 | 能把问题归类，形成变量、假设和求解路线。 |
| 术 | 学习具体模型、算法和求解步骤。 | 能写出模型、推导公式、设计算法。 |
| 器 | 熟悉 MATLAB、Python 等计算工具。 | 能把模型落地实现，并处理数据、图像和结果展示。 |

这四层不是严格的先后顺序，而是互相支撑：没有“道”，容易只记公式；没有“法”，遇到新题不知道从哪里下手；没有“术”，模型无法求解；没有“器”，结果难以验证和呈现。

## 6. 本课程的两条主线

从全国大学生数学建模竞赛和常见工程问题看，问题大致可以沿两条主线展开：一条是“以模为本”，关注模型结构；另一条是“以数为本”，关注数据处理和数据驱动方法。

![](img/docs-CH0-image-2.png)

<center>图0.3 数学建模导论教程的章节逻辑</center>

### 6.1 以模为本

“以模为本”的主线强调从机制、结构和约束出发建立模型，常见内容包括：

- 解析方法与几何模型：从几何图形中抽取位置关系和数量关系，并建立方程求解。
- 微分方程与动力系统：描述连续变化过程，学习数值求解和元胞自动机等离散模拟思想。
- 规划模型：由函数极值引出线性规划、整数规划、博弈论、排队论等优化模型。
- 图论模型：研究网络结构、最短路径、TSP 等离散优化问题。
- 智能优化：在复杂搜索空间中使用遗传算法、粒子群、蚁群算法等方法寻找近似最优解。

这条线的核心问题是：现实机制或约束关系应该怎样写成数学结构？

### 6.2 以数为本

“以数为本”的主线强调数据驱动思维。随着人工智能和大数据技术的发展，越来越多的建模题目要求学生处理真实数据。基本流程通常是：

数据获取 -> 数据清洗 -> 统计描述 -> 拟合或建模 -> 评价、预测或分类 -> 结果解释

课程后半部分会依次介绍数据处理与拟合模型、权重生成与评价模型、时间序列与投资模型、机器学习与统计模型。对于图像、文本、信号等非常规数据，也会选取计算机视觉、自然语言处理和信号处理中的基础方法，帮助建立初步认识。

这条线的核心问题是：已有数据能支持什么判断、预测或决策？

## 7. 初学者的学习抓手

学完这门课，不要求立刻掌握所有模型。更重要的是形成一种判断流程：

1. 识别问题类型：这是优化、预测、评价、分类、仿真，还是机理分析？
2. 明确目标变量：最终要输出什么结果，结果怎样被评价？
3. 提出合理假设：哪些因素必须保留，哪些因素可以简化？
4. 选择模型方法：用方程、规划、统计、图论、机器学习还是组合方法？
5. 完成求解验证：用计算工具求解，并检查结果是否合理。
6. 回到现实解释：说明模型结论的现实含义、适用范围和局限。

真正入门的标志，不是见过多少模型名称，而是面对一个实际问题时，能说清楚“它属于哪类问题、应该怎样抽象、为什么这样建模、结果能说明什么”。
