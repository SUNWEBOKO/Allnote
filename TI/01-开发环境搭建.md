## 本节主线

电赛项目开发的第一步不是写复杂算法，而是搭好基础环境：能写代码、能编译、能下载、能看到现象。本节目标是搭建 CCS 创建工程、VS Code 写代码、配合 AI 辅助的工作流。

CCS 负责底层工具链（编译器、芯片支持包、烧录调试），VS Code 负责编辑体验（代码补全、语法检查、AI 辅助）。二者分工协作，不是互相替代。

最终让开发板绿色 LED 闪烁——这个简单实验能验证软件安装、工程创建、GPIO 配置、编译、下载器连接、烧录运行的整条链路。

## 1\. 开发资料包与纯英文路径

安装前先拿到课程资料包，内含工程模板、配置文件、原理图、示例代码等。保存路径必须纯英文——编译器、脚本工具和插件对中文路径支持不好，可能导致解压失败、安装异常、头文件找不到等问题，排查耗时。

## 2\. 安装 CCS

CCS 是 TI 生态的核心开发工具，提供工程创建、芯片包管理、syscfg 外设配置、编译、烧录和调试。安装步骤：
1. 压缩包复制到纯英文目录下解压
2. 安装目录建议改到非 C 盘（如 `E:\ti`），只改盘符即可
3. **记住安装路径**——后续配置 VS Code 要用
4. 组件只装 MSPM0 相关即可
5. 首次安装可能需要下载环境包，耗时取决于网络

## 3\. 安装 VS Code

安装路径可改到非 C 盘。装好后做两件事：
- **中文语言包**：扩展搜索 `Chinese`，安装简体中文包，重启生效
- **C/C++ 插件**：搜索 `C++`，安装 Microsoft 官方版

初学阶段装这两个就够了，后续按需补充。

## 4\. CCS 与 VS Code 的分工

| 工具 | 职责 |
|------|------|
| CCS | 工程创建、芯片包管理、syscfg 外设配置、编译、烧录、调试 |
| VS Code | 代码编写、补全、语法检查、AI 辅助编程 |

CCS 也能写代码，基础开发只用 CCS 完全可行。额外配 VS Code 是为了更好的编辑体验和 AI 辅助。

## 5\. 创建第一个 MSPM0G3507 工程

打开 CCS，新建工程。芯片搜索 `MSPM0G3507`，选 `empty` 空工程模板，编译器默认。工程名可自定义（如 `01LED`）。

首次创建可能需要下载环境包——由于资源在国外服务器，可能卡住，需多试几次或切换网络。**成功后后续不再重复下载**。

创建完成后右键工程 → `Rebuild`，确认空工程能编译通过。

## 6\. GPIO 点亮 LED：原理图先行

写代码前必须先看原理图。开发板 LED 与 `PA14` 相关，正极接 `PA14`，负极接 GND：
- `PA14` 高电平（$\approx 3.3\text{ V}$）→ LED 亮
- `PA14` 低电平（$\approx 0\text{ V}$）→ LED 灭

不同开发板接法不同，写程序前必须确认原理图。

## 7\. 使用 syscfg 配置 GPIO

打开 `empty.syscfg`，找到 GPIO 配置：
1. 添加 GPIO 组，命名如 `LED`
2. 选择引脚 `PA14`，引脚命名如 `LED0`
3. 方向设为 `Output`，初始值选 `Clear` 或 `Set`
4. 输出类型选标准模式
5. **按 Ctrl+S 保存**，否则配置不生效

若代码中宏名与配置不一致，回 syscfg 检查是否保存成功。

## 8\. 编译空工程验证

GPIO 配置完后先 `Rebuild`。若编译通过，说明 syscfg 正常、工程结构无误。分阶段验证是嵌入式开发的重要习惯。

## 9\. 用 VS Code 打开 CCS 工程

在 CCS 中找到工作区路径（如 `C:\Users\<用户名>\workspace_ccstheia`），在 VS Code 中打开工程文件夹。将资料包中的 `.vscode` 配置文件夹复制到工程目录中——它包含头文件路径、编译器路径等工程级配置。

## 10\. 配置 VS Code 中的 CCS 路径

修改 `.vscode` 配置文件中的路径，让 VS Code 找到三类东西：
1. CCS 的芯片头文件和驱动库
2. CCS 的编译器文件
3. 当前工程生成的配置头文件

Windows 路径建议改成正斜杠（`E:/ti/ccs/tools/compiler`）避免转义问题。

## 11\. 区分两类错误

- **CCS 编译错误**：工程无法构建，必须解决
- **VS Code IntelliSense 报错**：红色波浪线不影响 CCS 编译，但影响补全和跳转体验

若 VS Code 报找不到标准库或编译器，在配置文件中手动指定编译器路径，注意 JSON 逗号不能漏。

## 12\. LED 闪烁程序

在 `main.c` 编写：

```c
#include "ti_msp_dl_config.h"

int main(void) {
    SYSCFG_DL_init();
    while (1) {
        delay_cycles(32000000 / 8);
        DL_GPIO_clearPins(GPIO_LED_PORT, GPIO_LED_LED0_PIN);
        delay_cycles(32000000 / 8);
        DL_GPIO_setPins(GPIO_LED_PORT, GPIO_LED_LED0_PIN);
    }
}
```

关键函数：
- `SYSCFG_DL_init()` — 初始化 syscfg 配置的外设
- `delay_cycles(n)` — 空转 n 个时钟周期作为粗略延时
- `DL_GPIO_clearPins(port, pin)` / `DL_GPIO_setPins(port, pin)` — 引脚输出低/高电平

GPIO 函数需传入端口组和引脚宏，名称由 syscfg 自动生成。

## 13\. 从代码到硬件

`setPins()` → PA14 输出 $3.3\text{ V}$ → LED 亮
`clearPins()` → PA14 输出 $0\text{ V}$ → LED 灭
`delay_cycles()` 保持状态足够长时间，人眼才能看到变化。

`while(1)` 是嵌入式程序的基本结构：单片机需要持续运行，不能像 PC 程序执行完就退出。

## 14\. XDS110 下载器接线

| XDS110 | 开发板 | 作用 |
|--------|--------|------|
| `CLK` | `CLK` | 调试时钟线 |
| `SWD` | `DIO` | 调试数据线 |
| `GND` | `GND` | 公共参考地 |
| `5V` | `5V` | 给开发板供电 |

GND 必须共地——数字信号以 GND 为参考。供电建议接 5V，板载稳压电路会转换出 3.3V。接线前仔细检查，电源接反可能烧坏开发板。

## 15\. 烧录与验证

右键工程 → `Flash` 烧录。成功后绿色 LED 闪烁，说明整条链路打通。

LED 不闪则分层排查：编译通过？烧录成功？接线供电？原理图引脚和程序一致？

## 16\. AI 辅助编程（Copilot）

VS Code 扩展中搜索 `GitHub Copilot` 安装并登录即可使用。它能补全重复代码、生成注释、辅助查错。但嵌入式代码涉及真实硬件，**不能盲目信任**——电源控制、GPIO 输出、电机驱动等必须自己理解。

## 一页速记

- CCS 负责工程创建、芯片包、syscfg 配置、编译、烧录和调试；VS Code 负责代码编写和 AI 辅助
- 路径必须纯英文；安装 CCS 时记住安装目录
- 第一个工程选 MSPM0G3507 + empty 模板，空工程先 Rebuild
- LED 闪烁：配置 GPIO 为输出，while(1) 中交替 clearPins/setPins + 延时
- VS Code 红色波浪线通常路径配置问题，反斜杠改成正斜杠
- XDS110 接线：CLK-CLK、SWD-DIO、GND-GND、5V-5V
- 烧录成功后绿色 LED 闪烁，说明链路打通
