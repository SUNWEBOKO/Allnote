## 本节主线

本节学习两个后续每节都会用到的基础能力：**调试代码**（定位程序问题）和**模块化编程**（管理越来越大的代码量）。

前者解决"程序出了什么错、运行到哪一步"，后者解决"代码越写越多以后怎么管理"。

## 1\. 工程准备

基于上一节工程复制并重命名。CCS 中可以通过 `File → Import` 导入已有工程，建议勾选"复制到工作区"，避免原地导入导致路径冲突。

每节课单独保存一份工程，不要在一个工程上反复覆盖。

## 2\. 内部时钟源也能到 80 MHz

上一节用外部晶振配置到 $80\text{ MHz}$，实际上内部 $32\text{ MHz}$ 时钟源通过倍频分频也能达到 $80\text{ MHz}$。

外部晶振优势在精度更高、温漂更小；内部时钟源更简单，不依赖外部晶振电路是否可靠。对一般电赛控制题内部时钟源通常够用。

## 3\. 代码调试

调试让程序在指定位置停下来，观察执行位置、变量值和硬件现象。常用工具是**断点**。

在 CCS 中代码左侧行号附近点击设断点（红色圆点）。进入 Debug 模式后，程序运行到断点处暂停，可以查看当前状态，再继续运行或单步执行。

**断点失效**通常与编译器优化有关。编译器可能把"无意义"的代码删掉或合并，导致 C 代码某一行没有对应机器指令。

解决方法：工程属性 → Arm Compiler → 优化等级设为 `0`，保存后重新编译。

开发板最多支持三个硬件断点。设新断点前先取消不用的。

## 4\. 调试操作流程

1. 确认工程能正常编译、烧录
2. 在关键代码行设断点（如点亮/熄灭 LED 的语句前后）
3. 进入 Debug 模式，程序停在 `main()` 附近
4. 点击继续运行到第一个断点
5. 结合代码和硬件现象判断：停在"点亮"后 LED 应亮，停在"熄灭"后 LED 应灭
6. 调试完成后取消断点，让程序正常跑完

调试的本质不是点按钮，而是建立验证思路：每次只观察一小段代码，确认其是否正确。

## 5\. 模块化编程

把代码按功能拆分到不同文件中，不是所有内容都写在一个 `.c` 里。

模块化思路：一种功能 = 一组文件。如延时模块 → `delay.c` + `delay.h`；OLED → `oled.c` + `oled.h`。

- **.h 文件**（头文件）：函数声明、宏定义、接口清单。告诉其他文件"这里有这个函数可以调用"
- **.c 文件**（源文件）：函数定义、具体实现

## 6\. .h 与 .c 的关系

```c
// delay.h — 接口声明
#ifndef DELAY_H
#define DELAY_H
#include "ti_msp_dl_config.h"
void delay_ms(uint32_t ms);
#endif

// delay.c — 具体实现
#include "delay.h"
void delay_ms(uint32_t ms) {
    delay_cycles((CPUCLK_FREQ / 1000U) * ms);
}

// empty.c — 调用模块
#include "ti_msp_dl_config.h"
#include "delay.h"

int main(void) {
    SYSCFG_DL_init();
    while (1) {
        DL_GPIO_setPins(GPIO_LEDS_PORT, GPIO_LEDS_USER_LED_1_PIN);
        delay_ms(500);
        DL_GPIO_clearPins(GPIO_LEDS_PORT, GPIO_LEDS_USER_LED_1_PIN);
        delay_ms(500);
    }
}
```

头文件保护（`#ifndef` / `#define` / `#endif`）防止同一个头文件被重复包含。

**常见错误**：把 `.c` 文件 `#include` 进去（如 `#include "delay.c"`）。正确做法是包含 `.h` 文件。

## 7\. 调试与模块化的关系

模块化让调试更容易——每个功能在独立文件中，问题范围更清晰：

- 延时问题 → 先看 `delay.c`
- GPIO 控制问题 → 看主循环或 LED 模块
- OLED 显示问题 → 看 `oled.c`

写一个模块 → 编译一次 → 烧录一次 → 验证一次。不要一口气写完所有模块再统一调试。

## 一页速记

- 断点让程序停在指定行，方便观察变量和硬件现象
- 断点变灰 → 编译器优化等级设为 0 后重新编译
- 调试时只观察一小段代码，每次缩小问题范围
- 模块化：`.h` 写声明（接口），`.c` 写实现（函数体）
- `#include` 包含 `.h` 文件，不包含 `.c` 文件
- 写一个模块就验证一个，不要攒到最后一起调
